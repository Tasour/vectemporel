# E019 — Robustesse et garde-fous des planètes

Lentille `E019` du module `src/views/constellation/E019.js`, enregistrée par
`register('E019', ctx => { … })`. Fichier possédé : uniquement ce module et le
présent rapport. Lectures seules : `src/views/constellation.js`,
`src/views/constellation/registry.js`, `src/views/constellation/index.js`,
`src/views/_diagnostics.js`. Aucun fichier partagé (`registry.js`, `index.js`,
`constellation.js`, `styles.css`) n'a été modifié.

Le module ne réécrit aucun nœud produit par `constellation.js` : il audite les
boutons `.const-planet` déjà rendus, pose ses propres attributs `data-e019-*`,
ajoute un panneau préfixé `e019-` et n'invente aucune donnée historique. Toutes
les mesures sont recalculées au moment du rendu depuis le DOM et les variables
CSS posées par la vue. Une seule feuille de style est injectée, via
`ctx.css('constellation-e019', CSS)` (ligne 131). Zéro appel réseau, zéro aléa,
zéro sortie de débogage, zéro minuteur, zéro boucle d'animation, zéro observer.

## E019-01 — Recensement et socle de diagnostic

- **Preuve** : `E019.js:125-131` (gardiens `ctx` / `ctx.layout` / `ctx.viewId` puis unique appel `ctx.css`) ; `E019.js:134-173` ; helpers `unSeul()` en `E019.js:111-123` et `creer()` en `E019.js:61-67`. Le sélecteur `SELECTEUR` est défini en `E019.js:55`.
- **Solution** : lecture des planètes via `layout.querySelectorAll(SELECTEUR)`, de la géométrie du champ via `geometrie()` (`E019.js:92-96`) et de la taille de nœud via `tailleNoeud()` (`E019.js:98-100`). Création d'un unique panneau `#e019-panel` dans un enveloppeur `.e019-wrap` sans ID : le motif du tiroir de diagnostic ne peut donc pas le masquer. Le panneau porte `aria-labelledby`, un titre, une région `role="status"` et deux conteneurs vides (mesures, constats). Les attributs `data-e019-planets`, `data-e019-render` et `data-e019-mode` publient l'effectif, le numéro de rendu et le mode.
- **Impact** : un point d'entrée stable, inséré après le rendu de la vue, sans doublon ni déplacement des nœuds existants ; la lentille reste sans effet si `ctx.layout` est absent.
- **Effort** : M
- **Vérification** : après trois appels, un seul `#e019-panel` dans le document ; `data-e019-planets` égale le nombre de `.const-planet[data-const-key^="planet:"]` ; `data-e019-mode` vaut `vide` quand aucune planète n'est rendue.

## E019-02 — Garde-fou de chevauchement

- **Preuve** : `E019.js:175-196`, boucle double `for` sur le tableau `positions` (lignes 178-182) ; lecture des variables `--x` / `--y` par `proprieté()` (ligne 78) et `pourcentage()` (ligne 83) ; appel à `marquer()` (lignes 191-192, définition `E019.js:103-109`).
- **Solution** : distance euclidienne entre centres, corrigée par le rapport largeur/hauteur réel du champ (`geo.w`, `geo.h`) ; seuil `taille * 1.15 + 2` pixels. Chaque paire sous le seuil incrémente `chevauchements` et marque les deux planètes avec la classe `e019-risque`, l'attribut `data-e019-risque="1"` et le texte `Chevauchement` dans `data-e019-tag`. Le total est exposé dans `data-e019-overlaps`.
- **Impact** : une collision de disques qui était purement visuelle devient un écart mesurable, reproductible et signalable au clavier comme à la souris.
- **Effort** : S
- **Vérification** : recalculer une paire à la main depuis `--x`/`--y` et `clientWidth`/`clientHeight` ; le compteur doit coïncider ; aucun `Math.random` n'intervient dans le seuil.

## E019-03 — Garde-fou de bord d'étiquette

- **Preuve** : `E019.js:198-214` ; garde `geo.mesurable` issu de `geometrie()` (`E019.js:92-96`) ; largeur d'étiquette de 118 px héritée du CSS de `constellation.js` (demi-largeur 59 px, ligne 203).
- **Solution** : conversion des pourcentages en pixels puis test `x < 59`, `x > largeur − 59` ou `y > hauteur − taille − 16`. Les planètes en risque reçoivent `data-e019-edge="1"` et le marqueur textuel `Bord`. Quand le champ n'est pas mesurable (largeur ou hauteur nulle), le test est désactivé et l'attribut vaut `non mesure` plutôt qu'une valeur trompeuse.
- **Impact** : le débordement masqué par `overflow: hidden` du champ est détecté sans modifier la position des planètes ; le mode dégradé reste explicite.
- **Effort** : S
- **Vérification** : placer une planète à `x = 2 %` sur un champ de 640 px → `data-e019-edge="1"` et `data-e019-edges` augmenté d'une unité ; avec un champ de largeur nulle, `data-e019-edges="non mesure"`.

## E019-04 — Garde-fou de densité

- **Preuve** : `E019.js:216-224` ; `decimal()` en `E019.js:88-90` ; règle CSS réduisant l'étiquette en régime serré en `E019.js:52` (`.e019-dense .const-planet::after`).
- **Solution** : `indice = surface / nombre_de_planètes / (taille_du_nœud + 10)²`. Indice inférieur à 1 → classe `e019-dense` sur le layout, qui resserre les étiquettes de 118 à 84 px, et `data-e019-density` arrondi avec virgule décimale française. Valeur nulle explicite quand il n'y a aucune planète.
- **Impact** : un garde-fou préventif concret : la densité ne se contente pas d'être affichée, elle déclenche une adaptation visualisible du libellé.
- **Effort** : S
- **Vérification** : avec 5 planètes sur 640×420 px et des nœuds de 18 px, `data-e019-density` vaut `68,57` ; la classe `e019-dense` est absente car l'indice est supérieur à 1.

## E019-05 — Filet de sécurité d'étiquette

- **Preuve** : `E019.js:226-240` ; lecture d'attributs via `attribut()` (`E019.js:69-72`) et de texte via `texte()` (`E019.js:74-76`).
- **Solution** : si `data-label` est vide ou privé du séparateur ` · `, un libellé de repli est composé depuis `aria-label`, puis le numéro visible, puis `Repère n`. Le résultat est publié dans `data-e019-label` et, si `title` manquait, dans `title`. L'attribut source `data-label` n'est jamais écrasé ; le compteur est exposé dans `data-e019-label-fallback`.
- **Impact** : aucune planète ne reste sans libellé exploitable pour l'info-bulle ou un outil d'audit, même si la donnée d'origine est incomplète.
- **Effort** : S
- **Vérification** : supprimer `data-label` d'une planète dont l'`aria-label` est renseigné → `data-e019-label` reprend ce libellé et `data-e019-label-fallback` passe à 1 ; l'attribut d'origine reste absent.

## E019-06 — Unicité des libellés accessibles

- **Preuve** : `E019.js:242-261`, ensemble `vus` (ligne 245) et suffixage déterministe (ligne 254).
- **Solution** : deux `aria-label` identiques sont détectés ; le second reçoit le suffixe ` · repère n` indexé sur l'ordre du DOM, l'attribut `data-e019-aria-dup="1"` et le marqueur `Libelle repete`. Un `aria-label` absent est compté et marqué `Libelle absent`. Aucun libellé existant n'est supprimé. Total dans `data-e019-aria-duplicates`.
- **Impact** : la lecture d'écran peut distinguer deux repères autrement homonymes, sans modification du texte visible ni de la logique de sélection de la vue.
- **Effort** : S
- **Vérification** : dupliquer l'`aria-label` de deux planètes → une seule est suffixée, `data-e019-aria-duplicates="1"` ; après un nouveau rendu sur le même DOM, le suffixe n'est pas appliqué une seconde fois.

## E019-07 — Intégrité des clés de repère

- **Preuve** : `E019.js:263-278` ; expression régulière `CLE_FORMAT = /^planet:\d+$/` définie en `E019.js:56` ; ensemble `numeros` (ligne 266).
- **Solution** : chaque `data-const-key` doit être une forme `planet:N` et apparaître une seule fois. Toute clé mal formée ou déjà vue reçoit `data-e019-key="1"` et le marqueur `Cle irreguliere` ; le compte est publié dans `data-e019-key-issues`.
- **Impact** : la clé qui sert à la mémorisation du focus dans `constellation.js` est contrôlée : une anomalie devient visible au lieu de provoquer une restauration de focus silencieuse vers la mauvaise planète.
- **Effort** : S
- **Vérification** : remplacer une clé par `planet:x` → `data-e019-key-issues="1"` et la planète porte `data-e019-key="1"` ; avec des clés conformes, le compteur reste à 0.

## E019-08 — Activité unique et empreinte déterministe

- **Preuve** : `E019.js:280-294` ; décompte des `is-active` / `aria-current` (lignes 283-285) ; boucle FNV-1a sur les codes de caractères (lignes 288-292).
- **Solution** : une seule planète active est attendue ; si le décompte diffère (notamment zéro quand le repère actif appartient à une autre ère), l'attribut `data-e019-active-alert="1"` est posé. Par ailleurs, une empreinte FNV-1a 32 bits des couples clé/position est calculée et exposée dans `data-e019-fingerprint` sous forme hexadécimale à 8 caractères.
- **Impact** : d'un côté un état incohérent de la vue est signalé, de l'autre un témoin reproductible permet de comparer deux rendus sans journal, sans réseau et sans stockage persistant.
- **Effort** : M
- **Vérification** : deux rendus du même pays produisent la même empreinte ; retirer `is-active` de l'unique planète active fait passer `data-e019-active` à 0 et pose l'alerte ; aucun générateur aléatoire n'est utilisé.

## E019-09 — Bascule de mise en évidence

- **Preuve** : `E019.js:296-316` ; variables de module `surligner` / `rendus` en `E019.js:58-59` ; règles `.e019-highlight` en `E019.js:50-51`.
- **Solution** : un bouton `#e019-toggle` porte `aria-pressed` (bascule indépendante, donc légitime ici), `aria-controls` vers la liste des constats et un gestionnaire `onclick` unique réassigné à chaque rendu. Il applique la classe `e019-highlight` au layout, met à jour `data-e019-highlight` et annonce l'état dans la région `role="status"`. Les planètes marquées affichent alors un anneau et un badge textuel issu de `data-e019-tag` via `::before` (l'info n'est jamais portée par la seule couleur). L'état est conservé en mémoire de module entre deux rendus de la coque.
- **Impact** : l'utilisateur peut révéler ponctuellement les garde-fous sans modifier le rendu de la vue ni masquer d'information.
- **Effort** : M
- **Vérification** : `aria-pressed` passe de `false` à `true`, le texte du bouton bascule, `data-e019-highlight="true"` ; un changement de repère conserve l'état actif ; aucun `addEventListener` cumulatif n'est créé.

## E019-10 — Synthèse auditable et témoin d'unicité

- **Preuve** : `E019.js:318-374` ; tableau des dix mesures (lignes 321-338), constats par planète (lignes 340-347), légende (lignes 349-367), lecture synthétique (lignes 369-371), témoins finaux (lignes 373-374) ; liste `IDS` en `E019.js:54`.
- **Solution** : le panneau reçoit une `<dl>` de dix mesures, une `<ul>` de constats dérivés de `data-e019-tag` (avec un message explicite quand tout est conforme) et un `<details>` de légende définissant le seuil de chevauchement, le test de bord, l'indice de densité, le repli d'étiquette et l'empreinte. La région live résume les mesures. Enfin `data-e019-reduced` relaie `ctx.reducedMotion()` et `data-e019-unique` vérifie qu'aucun des huit IDs possédés n'apparaît deux fois. L'ensemble est enveloppé dans un `try/catch` tolérant (`E019.js:375-377`).
- **Impact** : chaque chiffre est défini et recalculable, l'état de la lentille est lisible par attribut, et un DOM inattendu ne peut jamais interrompre le rendu de la constellation.
- **Effort** : M
- **Vérification** : `node --check src/views/constellation/E019.js` → PASS ; recherche des motifs interdits (`console.`, `fetch`, `XMLHttpRequest`, `Math.random`, minuteurs, animation propre, `url(http`, `@import`) → 0 ligne ; `data-e019-unique="true"` après trois rendus successifs ; la légende mentionne explicitement `1,15 × la taille du nœud` et `(taille du nœud + 10 px)²`.
