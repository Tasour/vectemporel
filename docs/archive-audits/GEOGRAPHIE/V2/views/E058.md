## Thème

Offrir un aperçu global permanent de la carte GEOGRAPHIE : une minicarte qui montre tout le
domaine connu et le rectangle de la vue courante. La lentille V2 ajoute un panneau pédagogique
autonome inséré dans `.geo-panel`, un badge dans `#c3b-map`, un laboratoire canvas unique, un
rectangle de vue calculé depuis le `viewBox` réel, des repères projetés depuis les marqueurs
existants, un tableau sémantique, des mesures chiffrées référencées, une graticule, un
**radiogroupe** à choix unique, un balayage animé et une navigation clavier complète.

L'aperçu réutilise exactement le repère de la carte principale (`MAP_W = 900`, `MAP_H = 620`) :
le rectangle de vue est donc lisible directement dans les coordonnées du `viewBox`. Un clic sur
l'aperçu rejoint le repère documenté le plus proche via le **vrai gestionnaire du marqueur**, sans
réimplémenter la projection et sans déplacer fictivement un lieu. Le rendu du canvas est une
fonction déterministe de l'état, du `viewBox` et des marqueurs réels : aucune valeur n'est tirée
au hasard et aucune information n'est portée par la seule couleur (formes, tirets et libellés).

Références numériques explicites et non inventées : domaine `0…900 × 0…620` ; couverture de la
vue entière = **100 %** (référence) ; facteur de zoom de la vue entière = **×1,00** (référence) ;
graticule tous les **150** unités ; balayage de **8 s** ; pas de curseur **30** unités (**90** avec Maj).

Le contenu substantiel est du **texte sémantique réel** (`h2`, `h3`, `p`, `li`, `table`,
`fieldset role="radiogroup"`, `role="status"`) inséré dans le DOM : il reste lisible et indexable
même sans animation ni interaction. Le canvas n'est qu'une surcouche redondante.

## E058-01 — Panneau sémantique, faits sourcés et CSS isolé

- **Problème** : une feuille de styles globale pourrait déborder sur la carte ou sur les autres
  lentilles, et une injection répétée à chaque rendu dupliquerait les règles. Un panneau réduit à
  du texte généré par le canvas ne serait ni lisible ni indexable sans interaction.
- **Solution** : un unique `ctx.css(CSS_ID, CSS)` avec `CSS_ID = 'geography-v2-e058'`, dédupliqué
  par `cssOnce` du registre. Toutes les règles sont préfixées `#geography-v2-e058-*` ou
  `.geography-v2-e058-*`, avec replis `var(--…, …)` et deux media queries (`max-width:620px`,
  `prefers-reduced-motion:reduce`). Le panneau `section#geography-v2-e058-panel` porte un `h2`,
  un chapô et trois faits sourcés en paragraphes `.geography-v2-e058-fait`, tous présents dans le
  DOM avant toute animation. Le panneau est idempotent : il n'est reconstruit que s'il n'est plus
  connecté.
- **Impact** : aucune règle ne s'échappe du panneau ; le texte pédagogique est disponible
  immédiatement, sans clic ni lecture du canvas.
- **Risque** : aucun — l'injection est dédupliquée par identifiant et le panneau n'est jamais
  recréé tant qu'il reste dans le document.
- **Vérification** : une seule occurrence de `ctx.css(CSS_ID, CSS)` et un seul `register('E058', …)` ;
  l'identifiant de feuille est `geography-v2-e058` ; les trois faits sont des `<p>` portant la
  classe `geography-v2-e058-fait`.

## E058-02 — Aperçu global dans le repère réel du `viewBox`

- **Problème** : dessiner l'aperçu dans un repère arbitraire rendrait le rectangle de vue illisible
  et obligerait à réimplémenter la projection de la carte principale.
- **Solution** : le domaine de l'aperçu est exactement `0…900 × 0…620` (`OVER_W`, `OVER_H`).
  `viewGeom()` calcule une transformation conforme (un seul `scale`, centrage, marge de 12 px),
  `toPx()` et `toOv()` assurent les allers-retours coordonnées aperçu ↔ pixels CSS. Le contour du
  pays est lu dans `#c3b-map .geo-outline` puis ramené à l'aperçu : aucune géométrie n'est inventée.
- **Impact** : l'aperçu et la carte parlent la même langue ; le rectangle de vue a une signification
  immédiate en coordonnées de `viewBox`.
- **Risque** : si le SVG principal change de domaine, les constantes doivent suivre — elles sont
  documentées comme reflétant `MAP_W`/`MAP_H` de `geography.js`, et le rectangle, lui, est toujours
  lu dans l'attribut réel.
- **Vérification** : `viewGeom()` n'utilise qu'un facteur d'échelle ; `outlinePoints()` parse
  l'attribut `points` du `.geo-outline` réel ; aucun chiffre de géométrie n'est codé en dur pour le
  contour.

## E058-03 — Rectangle de vue calculé depuis le `viewBox`, repères par la forme

- **Problème** : un rectangle de vue écrit en dur deviendrait faux dès que l'utilisateur zoome ;
  distinguer les repères par la seule couleur serait inaccessible.
- **Solution** : `currentBox()` lit l'attribut `viewBox` réel de `#c3b-map .geo-svg` (avec repli
  explicite vue entière). Le rectangle est tracé en blanc tireté à `(x, y, w, h)` avec un libellé
  `vue ×facteur`, et redessiné à chaque synchronisation. Les repères se distinguent par la forme :
  losange pour le lieu actif, cercle plein dans le cadre, cercle tireté hors cadre.
- **Impact** : agrandir ou réduire la vue principale modifie immédiatement l'aperçu ; l'état d'un
  repère reste lisible en niveaux de gris.
- **Risque** : aucun — le repli vue entière est explicite et annoncé, jamais présenté comme une
  mesure du lieu.
- **Vérification** : `currentBox()` parse `viewBox` et valide quatre nombres finis avec `w > 0`,
  `h > 0` ; le dessin du losange et des cercles tiretés est dans `drawLab()`.

## E058-04 — Tableau sémantique des repères

- **Problème** : les repères dessinés sur le canvas ne sont ni sélectionnables ni indexables, et
  leur appartenance au cadre courant resterait implicite.
- **Solution** : un `<table id="geography-v2-e058-table">` liste chaque marqueur avec son libellé,
  ses coordonnées `x` et `y`, et sa présence dans le cadre (`Oui` / `Non`). Le `caption` précise le
  repère de coordonnées ; les en-têtes portent `scope="col"` et `scope="row"`. Le corps est
  reconstruit à chaque synchronisation depuis les marqueurs réels, avec un message explicite si la
  liste est vide.
- **Impact** : l'information du canvas est entièrement redondée en texte, consultable sans JS et par
  lecture d'écran.
- **Risque** : aucun — les coordonnées affichées sont celles des attributs `cx`/`cy` des anneaux
  `.geo-ring`, pas des valeurs recalculées.
- **Vérification** : `buildTable()` crée le `caption` et les quatre en-têtes `scope="col"` ;
  `updateTable()` pose `scope="row"` sur chaque libellé et gère le cas vide.

## E058-05 — Laboratoire canvas unique, déterministe, DPR ≤ 2

- **Problème** : plusieurs canvas ou un dimensionnement naïf multiplieraient les dessins par
  frame et produiraient un rendu flou sur écran haute densité.
- **Solution** : un seul `<canvas id="geography-v2-e058-canvas">` dessine le cadre, le contour, les
  repères, le rectangle de vue, le curseur et la ligne de balayage. Le dimensionnement respecte
  `DPR ≤ 2`, le contexte 2D est réinitialisé proprement à chaque frame (`setTransform`,
  `clearRect`) et la géométrie est factorisée dans `viewGeom()`. Le rendu est déterministe : il ne
  dépend que de l'état `S`, du `viewBox` et des marqueurs réels, sans aucun tirage aléatoire.
- **Impact** : une seule frame de dessin, reproductible à l'identique pour un même état ; le canvas
  reste un laboratoire, jamais le seul support d'information.
- **Risque** : la lisibilité dépend de la largeur du conteneur — la géométrie se recalcule à chaque
  rendu depuis `clientWidth`/`clientHeight`, avec des replis numériques.
- **Vérification** : un seul `getContext('2d')` dans `drawLab()` ; `Math.min(2, …)` plafonne le DPR ;
  aucune occurrence de `Math.random` dans le module.

## E058-06 — Navigation par clic vers le repère documenté le plus proche

- **Problème** : cliquer sur l'aperçu et recentrer « au point cliqué » reviendrait à inventer une
  position qui n'existe pas dans la carte.
- **Solution** : `onCanvasClick()` convertit la position du pointeur en coordonnées aperçu via
  `toOv()`, puis `selectNearest()` identifie le repère documenté le plus proche (distance
  euclidienne) et appelle `.click()` sur le vrai groupe `.geo-marker`. Le gestionnaire natif de la
  carte sélectionne alors le lieu. Le résultat est annoncé dans la région de statut avec les
  coordonnées du repère rejoint.
- **Impact** : la navigation reste ancrée sur des lieux réels ; aucun déplacement fictif ni
  réimplémentation de la projection.
- **Risque** : si aucun marqueur n'est présent, l'action est refusée avec un message explicite au
  lieu de sélectionner un point arbitraire.
- **Vérification** : `selectNearest()` teste `data.length`, calcule le minimum de distance, met à
  jour `S.cursor` et appelle `best.node.click()` ; aucun nouvel élément de carte n'est créé.

## E058-07 — Mesures chiffrées référencées + `readout` de statut

- **Problème** : afficher des pourcentages sans référence ni formule empêche le lecteur de vérifier
  les valeurs.
- **Solution** : le `readout` (`role="status" aria-live="polite"`) affiche trois grandeurs
  recalculées depuis la géométrie courante : la couverture `(w × h) / (900 × 620)` comparée à la
  référence « vue entière = 100 % », le facteur `900 / w` comparé à « vue entière = ×1,00 » et le
  nombre de repères visibles sur le total. Les valeurs sont formatées avec une virgule décimale
  et mises à jour à chaque changement de vue ou de balayage.
- **Impact** : au moins trois grandeurs chiffrées dont deux explicitement comparées à une
  référence ; le lecteur peut recalculer chaque nombre depuis sa formule.
- **Risque** : aucun — si le `viewBox` est illisible, le repli vue entière donne 100 % et ×1,00,
  cohérent avec la référence affichée.
- **Vérification** : `mesures()` calcule les trois grandeurs ; `updateReadout()` insère les
  références « 100 % » et « ×1,00 » dans le texte et pose `role="status"` / `aria-live="polite"`.

## E058-08 — `radiogroup`, bascule indépendante, motifs distincts et légende

- **Problème** : trois modes d'affichage exclusifs ne doivent pas être modélisés par des cases à
  cocher multiples, et `aria-pressed` ne doit pas être détourné pour un choix unique.
- **Solution** : un `fieldset role="radiogroup"` nommé par une `<legend>` porte trois boutons radio
  natifs (« Repères dans le cadre », « Tous les repères », « Repères hors cadre ») : c'est le choix
  unique. La graticule reste une **bascule indépendante** (`aria-pressed`) séparée. `modeMontre()`
  applique le mode au dessin ; `updateLegend()` nomme chaque motif (losange, cercle plein, cercle
  tireté, croix, rectangle tireté, graticule). Les cibles des étiquettes et des boutons mesurent
  respectivement au moins 36 px et 44 px.
- **Impact** : le modèle ARIA reflète fidèlement l'interaction ; l'information ne repose jamais sur
  la seule couleur et les zones tactiles sont confortables.
- **Risque** : aucun — les deux sémantiques (choix unique / bascule) sont séparées dans le DOM et
  dans le CSS.
- **Vérification** : `buildModeGroup()` pose `role="radiogroup"` et trois `input[type="radio"]` de
  même `name` ; `GRID_ID` porte `aria-pressed` ; le CSS fixe `min-height:36px` sur `.geography-v2-e058-choix`
  et `min-height:44px` sur les boutons.

## E058-09 — Balayage : rAF unique, pause `document.hidden` / hors écran, mouvement réduit

- **Problème** : plusieurs boucles d'animation, une animation qui tourne en arrière-plan ou un
  mouvement imposé à un utilisateur sensible dégraderaient la performance et l'accessibilité.
- **Solution** : une seule boucle `requestAnimationFrame` (`startSweep` → `tickSweep` →
  reprogrammation, annulée par `stopSweep` / `pauseLoop`) fait parcourir l'aperçu à une ligne
  verticale en huit secondes, sans aléa. `visibilitychange` arrête la boucle quand
  `document.hidden` est vrai ; un `IntersectionObserver` la met en pause hors écran et la relance
  au retour. Avec `ctx.reducedMotion()`, le balayage est affiché à son terme en une seule frame,
  sans boucle, et un écouteur de média réagit aux changements de préférence.
- **Impact** : une seule frame de balayage dessinée, aucune avancée de temps cachée, respect du
  mouvement réduit.
- **Risque** : aucun — les deux mécanismes de pause sont indépendants et idempotents, et la
  reprise est conditionnée à l'état `playing`.
- **Vérification** : une seule définition de `tickSweep` ; `document.hidden` testé dans `tickSweep`
  et `installVisibility` ; `IntersectionObserver` utilisé dans `installObserver` ; `reducedNow()`
  court-circuite la boucle dans `toggleSweep`.

## E058-10 — Clavier, recentrage réel, badge, limite falsifiable et accessibilité

- **Problème** : les actions de l'aperçu doivent avoir un équivalent clavier, le recentrage doit
  agir sur la vraie carte, et la portée du schéma doit être explicite et testable.
- **Solution** : le canvas est focalisable (`tabindex="0"`) avec un `aria-label` unique : flèches
  pour déplacer le curseur (pas de 30 unités, 90 avec Maj), `Entrée` pour rejoindre le repère le
  plus proche, `R` pour restaurer la vue entière via le vrai bouton
  `data-fk="c3b-zoom-reset"`, `G` pour basculer la graticule. Le bouton `#geography-v2-e058-reset`
  offre le même recentrage. Chaque action est annoncée dans `#geography-v2-e058-status`. Un badge
  `#geography-v2-e058-badge` est posé sur `#c3b-map` pour rappeler que l'aperçu est schématique et
  sans réseau. La section `#geography-v2-e058-limit` énonce les angles morts, et le bloc
  `#geography-v2-e058-defi` propose une affirmation falsifiable en cinq temps : prédiction →
  réglage → résultat attendu (couverture ÷4, facteur ×2) → falsification → débrief. Le focus est
  visible (`:focus-visible` et `:focus`) et `aria-pressed` reste réservé aux deux bascules.
- **Impact** : parcours clavier complet, annonces vocales, limites explicites et testables, cibles
  tactiles conformes.
- **Risque** : le défi porte sur une relation mathématique (surface ∝ `w × h`, facteur ∝ `900 / w`) ;
  sa formulation dit explicitement que la surface ne varie pas linéairement, ce qui évite
  la confusion.
- **Vérification** : `onCanvasKey()` couvre flèches, `Entrée`, `Espace`, `R`, `G` avec
  `preventDefault()` ; `resetView()` clique le vrai bouton de la carte ; `buildLimit()` produit
  une liste ordonnée de cinq `<li>` ; le CSS contient `:focus-visible` et `min-height:44px`.
