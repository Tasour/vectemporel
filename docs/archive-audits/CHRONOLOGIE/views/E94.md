Lentille : E094. Fichier possédé : `src/views/chronology/E094.js`.

## E094-01 — Nœuds préfixés `e094-` et garde d'existence (re-render safe)

- **Problème / preuve** : `register('E094', …)` n'est appelé qu'une fois, à l'import du module (`index.js:95`), mais `runEnhancements()` rejoue `apply(api)` à **chaque** rendu (`registry.js:39-42`). Un greffon qui créerait ses nœuds sans garde produirait un nouvel `#e094-audit` à chaque émission du store. La vue elle-même reconstruit son `layout` (`chronology.js:214-216`) et son stage (`chronology.js:30-31`, commentaire `shell.js:137`) ; motif déjà appliqué pour la feuille C2 (`chronology.js:97-100`) et la région live (`chronology.js:121-133`).
- **Solution** : helper `ensureNode(ctx, id, tag, cls, parent)` — `document.getElementById(id)` ; si le nœud existe déjà dans le parent courant il est réutilisé, s'il survit dans un ancien stage il est déplacé par `appendChild`, sinon il est créé. Tous les IDs sont préfixés `e094-` (`e094-audit`, `e094-bar`, `e094-toggle`, `e094-verify`, `e094-readout`, `e094-details`, `e094-rows`).
- **Impact** : aucun ID dupliqué, aucun nœud orphelin, même après une longue session de navigation entre vues.
- **Risque** : un nœud d'un stage détaché pourrait être réutilisé à tort ; la garde `node.parentNode !== parent` force le déplacement vers le stage courant, et `getElementById` ne voit pas les nœuds détachés — un nœud neuf est alors créé sans doubler le DOM vivant.
- **Effort** : M
- **Vérification** : 20 cycles `chronologie → globe → chronologie` → `document.querySelectorAll('#e094-audit').length === 1` et un seul `<section aria-label="Diagnostic d’unicité…">` dans le document.

## E094-02 — Feuille de style unique, injectée dans `<head>`

- **Problème / preuve** : `injectStyle()` (`chronology.js:32-35`, `:92`) attache `#atlas-chronologie-css` au `stage` reconstruit à chaque rendu, tandis que `injectNavStyle()` (`chronology.js:95-100`, `:116`) cible `<head>` précisément parce que celui-ci survit au `innerHTML` de la coque (commentaire `chronology.js:119-120`, `shell.js:330`). `cssOnce()` (`registry.js:13-19`) fournit déjà la garde `document.getElementById(uniqueId)`.
- **Solution** : un seul appel `ctx.css('chronology-e094', RULES)` en tête de `apply()` ; règle posée une fois, scoping par la classe `.e094-audit` et le marqueur `data-e094="on"` posé sur le layout, sans toucher `styles.css` (où vit la grille `.chronology-layout`, `styles.css:194-196`).
- **Impact** : une seule balise `<style id="chronology-e094">`, aucune règle débordant sur une autre vue.
- **Risque** : un style global pourrait écraser les boutons de la vue ; toutes les règles sont préfixées `.e094-*` et le panneau est le seul porteur du marqueur.
- **Effort** : S
- **Vérification** : `document.querySelectorAll('style#chronology-e094').length === 1` après trois rendus ; le computed style de `.atlas-chrono-tag` reste inchangé en dehors du panneau.

## E094-03 — Détection des IDs dupliqués dans le layout

- **Problème / preuve** : les IDs de la vue sont dérivés des données sans garde : `era-${item.id}` (`chronology.js:286`), `tag-btn-${tag}` (`:332`), `event-${item.id}` (`:378`), `event-btn-${item.id}` (`:387`), `aside-tag-${tag}` (`:447`), `point-${event.id}-${position}` (`:475`). Deux entités partageant le même `id`, ou un `event.tags` contenant deux fois le même thème (`chronology.js:444`), produisent des IDs identiques. `applyFocusIntent()` (`:199-205`) utilise `document.getElementById(id)` : un doublon peut focaliser le mauvais nœud.
- **Solution** : `scanDuplicates(root)` dresse un `Map<id, count>` sur `ctx.layout.querySelectorAll('[id]')`, isole les collisions et les écrit dans `data-e094-duplicates` plus trois exemples lisibles dans le readout. `focusIsSafe()` signale spécifiquement les doublons touchant les préfixes de focus (`event-btn-`, `era-`, `tag-btn-`, `aside-tag-`, `point-`) dans `data-e094-focus-safe`.
- **Impact** : anomalie de données visible et audible sans instrumentation de la console ; lien direct avec la robustesse du focus.
- **Risque** : le scan porte sur le `layout` courant et non sur tout `document`, afin de ne pas compter les IDs des autres vues ; la région live `nav-c2a-live` est dans `document.body` (`chronology.js:130`) et est donc volontairement exclue du comptage de doublons (elle est vérifiée à part en E094-04).
- **Effort** : M
- **Vérification** : injecter deux bandes d'ère avec le même `data-era-id` → `data-e094-duplicates` passe à `1`, le readout nomme l'ID en conflit et `data-e094-focus-safe="0"`.

## E094-04 — Contrôle des cibles ARIA absentes ou répétées

- **Problème / preuve** : six relations ARIA reposent sur des IDs : `aria-labelledby="atlas-chrono-title"` (`chronology.js:220`, cible `:228`), `aria-controls="atlas-chrono-events"` (`:291`, `:318`, `:335`, cible `:349`), `aria-controls="atlas-chrono-aside"` (`:389`, `:511-512`, cible `:222`), `aria-labelledby="atlas-chrono-event-title"` (`:419`, cible `:424`), `aria-labelledby="atlas-chrono-points-title"` (`:467`, cible `:463`) et la région live `NAV_LIVE_ID` (`:11`, créée `:123-131`, écrite par `navSay()` `:135-138`). Si l'une de ces cibles manque, le lecteur d'écran perd le lien sans qu'aucune erreur ne soit levée.
- **Solution** : table `ARIA_TARGETS` ; `ariaState(ctx)` compte les occurrences par `countWithId(root, id)` (comparaison textuelle de `node.id`, sans sélecteur CSS fragile) dans le `layout`, sauf `nav-c2a-live` compté dans `document`. Les cibles `atlas-chrono-event-title` et `atlas-chrono-points-title` sont marquées conditionnelles : absentes quand aucun repère n'est sélectionné (`chronology.js:416-535`), elles ne comptent pas comme orphelines dans ce cas. Résultat dans `data-e094-orphans` / `data-e094-repeated`.
- **Impact** : rupture de lien ARIA détectée au rendu suivant, sans relecture manuelle du DOM.
- **Risque** : compter une cible conditionnelle comme absente après désélection produirait un faux positif ; la présence de `.chronology-aside .aside-title` (`chronology.js:423-429`) sert de critère de sélection.
- **Effort** : M
- **Vérification** : retirer `#atlas-chrono-events` du DOM → le readout annonce « Cibles ARIA absentes : 1 » et `data-e094-orphans="1"` ; sélectionner un repère sans titre → aucun faux positif.

## E094-05 — Région live unique : le readout ne double pas `nav-c2a-live`

- **Problème / preuve** : `ensureNavLive()` (`chronology.js:121-133`) maintient `navLiveNode` au niveau module avec garde `isConnected` et `getElementById`, et `navSay()` (`:135-138`) y écrit les annonces de filtrage et d'ère (`:194`, `:301`, `:340`, `:354`). Ajouter une seconde région live concurrente ferait lire deux messages successifs pour la même action.
- **Solution** : le readout E094 est un `<p id="e094-readout" role="status" aria-live="polite" aria-atomic="true">` distinct, créé par `ensureNode`, dont le texte ne change qu'à la mesure (rendu ou clic sur « Revérifier »). Aucune annonce sur survol, aucune écriture dans `nav-c2a-live`, aucun `aria-describedby` existant modifié (cf. `M01-03`).
- **Impact** : annonces non dupliquées ; diagnostic lisible par lecteur d'écran et par test E2E.
- **Risque** : deux régions `polite` peuvent être lues à la suite ; limiter E094 aux résultats de vérification explicite écarte le bavardage. Le message reste court (borné à trois exemples de doublons).
- **Effort** : S
- **Vérification** : un seul `#e094-readout` ; après vérification, `#nav-c2a-live` conserve son contenu précédent et le texte du readout contient « Doublons d’identifiants : … ».

## E094-06 — Écouteurs posés une fois par nœud, contexte courant

- **Problème / preuve** : `runEnhancements()` (`registry.js:28-44`) reconstruit l'API puis appelle chaque `apply()` à chaque rendu ; le motif est déjà documenté dans la vue voisine (`E009.js:22-24` : garde `installed` + `latest`). Un `addEventListener` placé directement dans `apply()` empilerait les handlers. Un garde **global** serait lui-même fragile : si la coque remplace le `innerHTML` du stage (`chronology.js:119-120`, `shell.js:330`), le nœud est détruit mais le drapeau global reste vrai — les boutons deviennent muets.
- **Solution** : `bindOnce(node, role, type, handler)` pose l'écouteur et marque le **nœud** (`data-e094-bind-toggle`, `data-e094-bind-verify`). Le drapeau suit le nœud déplacé par `ensureNode`, donc un nœud neuf reçoit son écouteur et un nœud réutilisé n'en reçoit pas de second. `latest` est rafraîchi à chaque `apply()` ; le clic sur « Revérifier » appelle `refresh(latest)`, jamais un contexte périmé.
- **Impact** : un seul handler par bouton, N re-renders sans fuite ni perte de commande.
- **Risque** : un drapeau de nom unique par rôle ; deux boutons utilisent des rôles distincts (`Toggle`, `Verify`) pour ne pas s'écraser mutuellement.
- **Effort** : M
- **Vérification** : 20 re-renders puis un clic sur « Revérifier » → `data-e094-verify` passe de `0` à `1` (pas à 20) ; un clic sur le titre bascule `aria-pressed` entre `true` et `false` sans duplication.

## E094-07 — IDs dérivés de données assainis et alloués sans collision

- **Problème / preuve** : les IDs dynamiques de la vue (`chronology.js:286`, `:332`, `:378`, `:387`, `:447`, `:475`) sont interpolés sans assainissement. Un thème contenant un espace ou un `#` donne un ID que les sélecteurs CSS ne peuvent plus viser ; des tags dupliqués dans un même repère (`:444`) donnent deux `aside-tag-<tag>`. Les nœuds E094 ne doivent pas reproduire ce défaut ni écraser un ID existant.
- **Solution** : `safeKey(value)` normalise en `[A-Za-z0-9_-]` avec repli `vide` ; `uniqueId(base, used)` ajoute un suffixe `-2`, `-3` tant que `used` ou `document.getElementById` contient l'ID. Les trois lignes de détail `e094-row-…` sont d'abord retirées du conteneur, puis réallouées à chaque mesure : aucun ID figé ne peut être volé. Les IDs de `chronology.js` sont **audités**, pas modifiés (fichier non possédé).
- **Impact** : les nœuds de la lentille restent adressables de façon unique, quelles que soient les données du pays.
- **Risque** : les IDs dérivés de la vue ne peuvent pas être corrigés ici ; E094 signale la collision dans `data-e094-duplicates` mais ne renomme pas les nœuds de `chronology.js` (voir Blocages).
- **Effort** : M
- **Vérification** : forcer deux occurrences du même tag dans un repère → au moins un doublon signalé ; `document.querySelectorAll('[id^="e094-row-"]')` ne contient aucun ID répété après quatre mesures successives.

## E094-08 — Resynchronisation à chaque rendu (pays, ère, filtre)

- **Problème / preuve** : le filtre local survit aux reconstructions complètes du DOM (`chronology.js:14-16`), tout comme `focusIntent` (`:17`) et `applyFocusIntent()` (`:199-205`). Le `layout` porte `data-country-id` (`:215`) et `data-view="chronology"` (`:216`). Un greffon qui mettrait en cache le pays ou l'ère afficherait une mesure périmée après changement de sélection.
- **Solution** : `latest = ctx` à chaque `apply()` ; `data-e094-country` est réécrit depuis `layout.dataset.countryId`, `data-e094="on"` et `data-e094-reduced` à chaque rendu ; `refresh(ctx)` recalcule doublons, orphelins et nombre de nœuds à partir du stage courant, jamais depuis un cache ni depuis un nœud global.
- **Impact** : diagnostic toujours aligné sur le pays et l'ère réellement affichés.
- **Risque** : un ancien stage détaché conserve ses `data-e094-*` ; toutes les écritures visent `ctx.stage` / `ctx.layout` courants, pas `document.body`.
- **Effort** : S
- **Vérification** : changer de pays puis revenir → `data-e094-country` égal au nouveau `data-country-id`, et `data-e094-nodes` recompté sur le stage courant.

## E094-09 — Cibles tactiles, focus visible, mouvement réduit

- **Problème / preuve** : `styles.css:33` impose un `:focus-visible` à 2 px, mais la vue utilise des boutons à `min-height:30px` (`chronology.js:53-57`). La feuille de la vue neutralise déjà les transitions sous `prefers-reduced-motion` (`chronology.js:89-91`) et le registre expose `ctx.reducedMotion()` (`registry.js:33-36`) : un greffon qui ajouterait son propre écouteur `matchMedia` le dupliquerait (cf. `M01-07`, `M07-10`).
- **Solution** : CSS `min-height:36px` (visé 44 px sous 620 px) et `:focus-visible` sur `.e094-btn`, aucune transition ni animation décorative ; `ctx.layout.dataset.e094-reduced` et `panel.dataset.e094Reduced` écrits depuis `ctx.reducedMotion()` à chaque rendu, sans écouteur média propre ni boucle d'animation.
- **Impact** : commandes atteignables au doigt et au clavier, préférence de mouvement exposée dans le DOM.
- **Risque** : l'absence de `ctx.reducedMotion()` sur un contexte de test est traitée par un repli `false` ; le panneau reste fonctionnel, seul le marqueur diffère.
- **Effort** : S
- **Vérification** : mouvement réduit émulé → `data-e094-reduced="1"` ; `grep -nE 'matchMedia|requestAnimationFrame|setInterval|setTimeout' src/views/chronology/E094.js` → 0 ligne ; les deux boutons mesurent au moins 44 px en 390×844.

## E094-10 — Observabilité sans journalisation ni réseau

- **Problème / preuve** : `runEnhancements()`neutralise silencieusement une lentille défaillante et accumule ses erreurs dans `diagnostics` (`registry.js:39-43`), exposé par `viewDiagnostics()` (`:46-48`). Recourir à la console rendrait l'information invisible aux tests et au tiroir de la coque ; la vue, elle, limite ses annonces au texte visible (`chronology.js:244-256`).
- **Solution** : chaque mesure écrit le readout `role="status"` et les `data-e094-*` ; sentinelle `—` si le nœud n'est pas encore au DOM ; nombre d'exemples plafonné à trois. Zéro appel réseau, zéro `Math.random`, zéro boucle rAF, zéro timer, zéro `console.*`.
- **Impact** : diagnostic lisible par l'utilisateur, par lecteur d'écran et par E2E, sans effet de bord global.
- **Risque** : un grand nombre de doublons rendrait le texte illisible ; le résumé affiche trois identifiants puis « … », le compte exact restant dans `data-e094-duplicates`.
- **Effort** : S
- **Vérification** : `node --check src/views/chronology/E094.js` → OK ; `grep -nE 'console\.|fetch\(|XMLHttpRequest|Math\.random|requestAnimationFrame|setInterval|setTimeout' src/views/chronology/E094.js` → 0 ligne ; `/api/library` et les autres vues inchangés.

## Statut d'implémentation

Les 10 chantiers sont implémentés dans `src/views/chronology/E094.js`. Aucun fichier interdit modifié (`registry.js`, `index.js`, `SYNTHESE.md`, `README.md` et les autres `E0xx` intacts). CSS injecté une seule fois via `ctx.css('chronology-e094', …)` ; sept nœuds à ID unique préfixés `e094-` avec garde d'existence (`ensureNode`) et écouteurs liés une fois par nœud (`bindOnce`) ; un seul `register('E094', …)`. Zéro boucle rAF, zéro timer, zéro `matchMedia` propre, zéro `console.*`, zéro `Math.random`, zéro réseau. `node --check src/views/chronology/E094.js` exécuté avec succès.

## Blocages

- Aucun bloquant fonctionnel.
- E094-03 et E094-07 sont des mesures **observatoires** : la correction des IDs dérivés des données (`era-${item.id}`, `tag-btn-${tag}`, `aside-tag-${tag}`, …) exigerait d'éditer `src/views/chronology.js`, fichier non possédé. La lentille signale les collisions et protège ses propres nœuds ; elle ne renomme pas les IDs de la vue.
- La pause sur `document.hidden` et l'intersection observer restent hors périmètre (domaines M07/M08) : E094 n'ajoute ni écouteur de visibilité ni observateur, conformément à sa spécialité « IDs et re-renders ».
