# E089 — Annotations et notes personnelles sur les repères

> Lentille **E089**, vue « Chronologie ». Fichier possédé : `src/views/chronology/E089.js`.
> Lectures seules : `src/views/chronology.js`, `src/views/chronology/registry.js`,
> `src/views/chronology/index.js`, `styles.css`,
> `UNIFIED_AUDIT/MONDE/views/M07.md`, `UNIFIED_AUDIT/MONDE/views/M01.md`.
> 10 chantiers E089-01 à E089-10, **les 10 implémentés** dans le module.
> Un seul `register('E089', …)`, un seul `ctx.css('chronology-e089', …)`, IDs préfixés `e089`
> avec gardes d'existence. Zéro réseau, zéro journalisation, zéro tirage aléatoire,
> zéro boucle `requestAnimationFrame`, zéro timer, aucun fichier partagé modifié.

Le point de départ est que la vue ne produit que du contenu dérivé du store
(`src/views/chronology.js:6`) : le repère courant est décrit par ses points vérifiés
(`:461-504`) et ses actions de navigation (`:507-526`), mais aucun espace n'est réservé
à une appropriation personnelle. La lentille ajoute cet espace sans rien inventer
ni modifier dans les données.

---

## E089-01 — Aucun espace d'annotation pour le repère courant

- **Problème / preuve** : `src/views/chronology.js:416-526` construit toute la fiche du
  repère (titre, année, image, résumé, thèmes, points, navigation) sans champ libre ;
  `src/views/chronology.js:6` rappelle que chaque élément provient de `store`. Le seul
  état local de la vue est `local = { query: '', tag: null }` (`:16`), réservé au filtre.
- **Solution** : panneau `<section id="e089-panel">` ajouté à `#atlas-chrono-aside`
  (`:221-223`) après les points, avec `<h3 id="e089-heading">`, `<label>` et
  `<textarea id="e089-textarea">`. Le repère courant est identifié par
  `#atlas-chrono-events [aria-current="true"]` porteur de `data-event-id` (`:385-390`),
  avec repli sur l'id du premier point `point-<id>-<rang>` (`:475`) si le filtre masque
  la carte (`:353-374`).
- **Impact** : chaque repère devient annotable sans toucher aux points sourcés ni au
  store ; le texte saisi est clairement séparé du contenu vérifié.
- **Risque** : le panneau ne doit pas écraser les points ni les boutons « Repère
  précédent / suivant » (`:507-526`) : il est **ajouté** en fin d'aside, jamais inséré
  au milieu. Si aucun repère n'est sélectionné (`:527-535`), le textarea est désactivé
  avec un placeholder explicite plutôt que de proposer une saisie sans cible.
- **Effort** : M.
- **Vérification** : un seul `#e089-panel` dans l'aside ; le textarea porte la note du
  repère affiché ; sélectionner un autre repère recharge la bonne note ; relecture en
  1658×1150 et 390×844.

## E089-02 — Persistance locale sans réseau, avec repli mémoire

- **Problème / preuve** : `src/views/chronology.js:14-16` documente un filtre qui ne
  survit qu'aux reconstructions du DOM, et `src/views/chronology/registry.js:13-19`
  ne protège que le `<style>` via `cssOnce`. Aucun mécanisme de conservation des notes
  n'existe, et le contrat de la lentille interdit tout appel réseau.
- **Solution** : `localStorage` sous la clé `vectemporel-e089-notes`, namespace par
  `layout.dataset.countryId` (posé en `src/views/chronology.js:215`), avec hydrate
  unique sous garde module (`hydrated`) et writes à chaque frappe. Un `try/catch`
  silencieux bascule sur un objet mémoire `store` si le stockage est indisponible.
  Aucun `fetch`, aucune requête, aucun import hors `registry.js`.
- **Impact** : les notes survivent aux rendus, aux changements d'ère et aux rechargements,
  sans coût réseau et sans dépendance à un service externe.
- **Risque** : le stockage local peut lever une exception en mode privé ou sandbox ;
  le repli mémoire garde la session fonctionnelle sans signaler d'erreur à l'utilisateur.
  Les clés sont préfixées par pays pour éviter les collisions entre pays partageant
  des identifiants de repères similaires.
- **Effort** : M.
- **Vérification** : écrire une note, changer d'ère via `src/views/chronology.js:298-302`,
  recharger : la note réapparaît ; simuler un `localStorage` indisponible : aucune erreur,
  la note reste visible pour la session ; `grep` sur `fetch(` → 0 ligne.

## E089-03 — Aucun marqueur visuel des repères déjà annotés

- **Problème / preuve** : les cartes `event-card` (`:385-410`) affichent année, titre et
  sous-titre, mais aucun indicateur ne signale une note personnelle existante ; une
  information portée par la seule couleur serait de toute façon exclue.
- **Solution** : `<span class="e089-badge">` ajouté dans le bouton de carte, avec glyph
  `✎`, le mot « note » et le nombre de mots, complété par un `aria-label` dédié. Le
  parent `<li data-event-id>` reçoit `data-e089Annotated="1"` en miroir auditable.
  Le badge est un `span` non interactif : il ne crée pas de bouton imbriqué dans le
  `<button class="event-card">` et ne vole pas le clic du gestionnaire `:406-409`.
- **Impact** : les repères annotés sont repérables d'un coup d'œil dans la liste, y
  compris quand la note a été prise dans une autre ère.
- **Risque** : le badge est retiré dès que la note devient vide, pour ne pas afficher
  « 0 mot » sur une carte non annotée. Le marqueur reste dans la carte, donc il disparaît
  avec elle lors d'un filtrage (`:178-188`) : le récapitulatif E089-07 prend le relais.
- **Effort** : S.
- **Vérification** : une note de trois mots produit « ✎ note · 3 mots » ; effacer la
  note retire le badge et `data-e089Annotated` ; le focus clavier reste sur la carte.

## E089-04 — Aucune mesure chiffrée ni horodatage de la note

- **Problème / preuve** : la bande de statut (`:247-256`) ne compte que des repères et
  des rangs ; aucun volume de texte ni date de dernière écriture n'est exposé pour
  l'annotation.
- **Solution** : `#e089-count` affiche « N caractères · M mots » et `#e089-time`
  « Dernière sauvegarde : enregistrée à HH:MM. », recalculés depuis `text.length`,
  `match(/\S+/g)` et `new Date(updatedAt)`. Aucun tirage aléatoire n'intervient ;
  l'horodatage vient uniquement de l'horloge locale.
- **Impact** : information chiffrée, lisible et indexable, non portée par la couleur.
- **Risque** : une valeur `updatedAt` absente ou invalide (stockage corrompu) affiche
  « jamais enregistrée » ou « horodatage indisponible » plutôt qu'une date trompeuse.
- **Effort** : S.
- **Vérification** : saisir « un deux trois » → « 14 caractères · 3 mots » (ou le
  décompte exact du texte saisi) ; l'heure affichée correspond à la dernière frappe ;
  aucune valeur aléatoire entre deux rendus du même texte.

## E089-05 — Aucune confirmation annoncée pour l'enregistrement

- **Problème / preuve** : la vue possède une région live locale `#nav-c2a-live`
  (`:11`, `:121-138`) mais `navSay` est privé au module et ne sert qu'au filtre
  (`:190-195`) ; aucun message n'accompagne une sauvegarde de note.
- **Solution** : `#e089-status` avec `role="status"`, `aria-live="polite"` et
  `aria-atomic="true"`, calqué sur le montage de `:126-129`. Le texte est écrit
  uniquement sur action explicite : « Note enregistrée pour <repère>. », « Note
  effacée pour <repère>. » ou résultat de « Localiser ». Aucune journalisation
  navigateur n'est utilisée.
- **Impact** : confirmation audible et visible, sans bavardage au survol ni au simple
  déplacement dans la liste.
- **Risque** : une région live dupliquée annoncerait deux fois le même message après
  un re-rendu : le helper `ensure()` réutilise le nœud existant sous garde d'ID. La
  région est distincte de `#nav-c2a-live`, dont la propriété reste à `chronology.js`.
- **Effort** : M.
- **Vérification** : après une frappe, `#e089-status` contient « enregistrée pour » ;
  après effacement, « effacée pour » ; le survol d'une carte ne modifie pas le texte.

## E089-06 — Effacer une note sans perdre le fil rouge du focus

- **Problème / preuve** : les actions de l'aside (`:507-526`) pilotent uniquement la
  navigation entre repères ; la restauration de focus est centralisée dans
  `applyFocusIntent` (`:199-205`) et dépend d'un identifiant posé par les gestionnaires
  de `chronology.js`, que la lentille ne possède pas.
- **Solution** : bouton `#e089-clear` (min-height 36px) qui vide `area.value`, supprime
  la clé du stockage, rafraîchit compteur/badges/récapitulatif, annonce dans la région
  live puis replace explicitement le focus dans `#e089-textarea`. Aucun appel à `set()`
  n'est fait : le DOM n'est pas reconstruit, donc le focus n'a pas besoin d'être
  restauré par la coque.
- **Impact** : effacement réversible par simple ressaisie, sans déplacement de focus
  ni perte de contexte.
- **Risque** : le bouton est désactivé tant que la note est vide (`clear.disabled`) ;
  son gestionnaire est posé sous garde `dataset.e089Bound` pour ne pas se dupliquer si
  le même nœud est réutilisé lors d'un second passage de `runEnhancements`.
- **Effort** : S.
- **Vérification** : cliquer « Effacer cette note » → champ vide, compteur à zéro,
  badge retiré, `document.activeElement === #e089-textarea`, message dans la région live.

## E089-07 — Notes invisibles quand l'ère ou le filtre change

- **Problème / preuve** : sans filtre, la liste est ère par ère (`:235-242`) ; avec
  filtre, le périmètre devient `country.events` (`:178-188`, `:350-352`). Une note posée
  sur un repère d'une autre ère devient donc indisponible à la navigation.
- **Solution** : récapitulatif `#e089-list` qui énumère toutes les clés du pays courant
  (préfixe `<countryId>::`), avec titre du repère et nombre de mots, tri stable par clé.
  Chaque ligne porte un bouton « Localiser » qui cible `event-btn-<id>` (`:387`) via
  `getElementById`, le focalise et le fait défiler en `behavior: 'auto'`. Si la carte
  est absente du filtre, la région live l'annonce explicitement.
- **Impact** : aucune annotation n'est perdue de vue, même hors de l'ère affichée.
- **Risque** : les identifiants de repères pouvant contenir des caractères particuliers,
  la recherche utilise `getElementById` et non un sélecteur CSS construit ; le titrage
  vient des cartes présentes ou du titre de l'aside, avec repli sur l'identifiant brut.
  Le défilement est forcé en `'auto'` : aucune animation de scroll, donc pas de mouvement
  parasite même hors préférence réduite.
- **Effort** : M.
- **Vérification** : annoter un repère, changer d'ère, vérifier sa présence dans
  `#e089-list` ; « Localiser » ramène le focus sur la carte quand elle est visible et
  annonce son absence sinon.

## E089-08 — Préférence de mouvement réduit non relue par les greffons

- **Problème / preuve** : `src/views/chronology/registry.js:33-36` fournit
  `ctx.reducedMotion()`, mais aucun greffon ne le consulte dans la vue chronologie ;
  `styles.css:342-344` neutralise bien les `animation`/`transition` globalement, sans
  exposer d'état auditable pour les éléments injectés.
- **Solution** : la valeur est lue à chaque application (aucun écouteur `matchMedia`
  dupliqué) et écrite dans `layout.dataset.e089Reduced` (`'1' | '0'`). Une règle CSS
  dédiée `[data-e089-reduced="1"] .e089-badge { transition: none }` complète la
  neutralisation globale. Aucune animation ni transition n'est créée ailleurs.
- **Impact** : comportement cohérent avec la préférence système, état vérifiable dans
  le DOM par un audit ou un test E2E.
- **Risque** : le marqueur est recalculé à chaque rendu : il ne peut pas rester périmé
  après un changement de préférence suivi d'une reconstruction de la vue. Aucune boucle
  d'animation n'est introduite pour surveiller la préférence.
- **Effort** : S.
- **Vérification** : avec mouvement réduit émulé, `data-e089-reduced="1"` et la
  `transition-duration` calculée du badge à `0s` ; aucun `requestAnimationFrame` dans
  le module.

## E089-09 — Doublons d'IDs et écouteurs dupliqués au re-rendu

- **Problème / preuve** : `src/views/chronology.js:539` appelle `runEnhancements` à
  chaque rendu, et `src/views/chronology/registry.js:39-42` rejoue tous les greffons ;
  `cssOnce` (`:13-19`) ne protège que le `<style>`. Les nœuds du panneau et leurs
  écouteurs doivent donc être gardés explicitement.
- **Solution** : helper `ensure(parent, id, tag, className, text)` qui réutilise tout
  nœud `#e089-*` déjà présent dans le parent ; les contrôles portent
  `dataset.e089Bound = '1'` avant l'ajout de leur écouteur ; l'injection CSS passe par
  l'unique `ctx.css('chronology-e089', …)`. Le panneau vit dans l'aside reconstruit
  (`src/views/chronology.js:221-223`, `:537-539`) tandis que le cache de notes vit dans
  le module : séparation nette entre DOM éphémère et données persistantes.
- **Impact** : aucun ID dupliqué, aucune annonce live doublée, aucune dérive des
  écouteurs sur une longue session.
- **Risque** : un nœud détaché ne doit pas être réutilisé : `ensure()` cherche
  exclusivement dans le parent courant via `parent.querySelector`. Le `<style>` étant
  dans `<head>` (persistant) et les nœuds dans le `<stage>` (reconstruit), les deux
  gardes sont indépendants et complémentaires.
- **Effort** : M.
- **Vérification** : 20 allers-retours entre ères → un seul `#e089-panel`, un seul
  `<style id="chronology-e089">`, un seul `#e089-status` ; une frappe n'écrit qu'un
  seul message live ; `node --check src/views/chronology/E089.js` passe.

## E089-10 — Souveraineté des données et budget de la lentille

- **Problème / preuve** : le contrat de la vague interdit réseau, journalisation,
  aléa et boucle propre ; `src/views/chronology/registry.js:3-5` décrit des lentilles
  sans état partagé, neutralisées en cas d'erreur (`:39-42`). Aucun mécanisme n'empêche
  une lentille de dériver.
- **Solution** : le module n'importe que `register` depuis `registry.js`, n'appelle
  aucune API réseau, ne journalise rien, n'utilise aucun tirage aléatoire (seul
  `Date.now()` fournit l'horodatage), ne démarre ni `rAF`, ni `setTimeout`, ni
  `setInterval`, ni `IntersectionObserver`. Le texte d'introduction du panneau rappelle
  que la note reste sur l'appareil et ne modifie pas les points vérifiés.
- **Impact** : confidentialité préservée, budget de rendu inchangé (aucune frame, aucun
  timer d'arrière-plan imputable à E089), conformité au contrat de la vue.
- **Risque** : l'horodatage dépend de l'horloge locale ; ce n'est pas une source
  d'aléa, et l'affichage reste déterministe pour un même `updatedAt`. Une lentille
  défaillante serait neutralisée par le registre sans interrompre le rendu, mais les
  gardes d'existence restent nécessaires pour éviter les doublons (E089-09).
- **Effort** : S.
- **Vérification** : `grep -nE 'console\.|fetch\(|Math\.random|requestAnimationFrame|setTimeout|setInterval|XMLHttpRequest' src/views/chronology/E089.js` → 0 ligne ;
  `node --check` passe ; `viewDiagnostics()` liste une seule entrée `E089` sans
  diagnostic d'erreur après trois rendus.

## Statut d'implémentation

Les 10 chantiers sont implémentés dans `src/views/chronology/E089.js`. Aucun fichier
interdit modifié (notamment `registry.js`, `index.js`, `SYNTHESE.md`, `README.md` et les
autres lentilles E0xx). Un seul `register('E089', …)`, un seul
`ctx.css('chronology-e089', …)`, des IDs `e089-*` avec gardes d'existence, zéro réseau,
zéro journalisation, zéro tirage aléatoire, zéro boucle rAF, zéro timer. Le fichier est
déjà référencé en `src/views/chronology/index.js:90` : aucun ajout n'était nécessaire.
`node --check src/views/chronology/E089.js` exécuté avec succès avant livraison.

## Blocages

- Aucun bloquant fonctionnel.
- E089 ne peut pas appeler `selectEvent()` ni `set()` : ces fonctions sont importées
  uniquement par `src/views/chronology.js:6` et ne sont pas exposées dans `ctx`
  (`src/views/chronology/registry.js:28-37`). La lentille ne modifie donc pas l'état
  partagé : le bouton « Localiser » se contente de focaliser la carte présente et
  d'annoncer son absence si le filtre courant la masque. Un hook de navigation public
  serait nécessaire pour sauter d'ère automatiquement ; aucune contournement risqué
  n'est introduit.
- La préférence de mouvement réduit est relue à chaque rendu plutôt qu'écoutée en
  direct (`matchMedia`) : le composant n'ayant pas de boucle ni de timer, un changement
  de préférence sans reconstruction de la vue ne rafraîchit pas `data-e089-reduced`.
  Ce choix est cohérent avec le modèle M01-07/M07-08 : l'état est auditable au prochain
  rendu, sans écouteur dupliqué ni frame supplémentaire.
