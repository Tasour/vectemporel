# E090 — Liens vers les points vérifiés et navigation inter-vues (vue CHRONOLOGIE)

Lentille : E090. Fichier possédé : `src/views/chronology/E090.js`.
Lectures seules : `src/views/chronology.js`, `src/views/chronology/registry.js`, `src/views/chronology/index.js`, `styles.css`. Modèles de rapport : `UNIFIED_AUDIT/MONDE/views/M07-raf-pause.md` et `M01-ombres-eclairage.md` — les fichiers `M07.md` et `M01.md` cités dans la consigne n'existent pas dans ce dépôt.
Aucun fichier partagé modifié. CSS injecté une seule fois via `ctx.css('chronology-e090', …)`. Tous les identifiants créés sont préfixés `e090` et protégés par une garde d'existence. Aucun accès réseau, aucun générateur aléatoire, aucune journalisation, aucune boucle d'animation, aucun minuteur, aucun observateur.

## E090-01 — Index des points vérifiés : des ancres sans table des matières

- **Problème / preuve** : `src/views/chronology.js:473-476` donne à chaque point un identifiant de la forme point-event-position et `:487` y place le texte dans un paragraphe ; le titre « Points du repère (N) » est annoncé en `:462-464`. Aucun élément ne pointe vers ces ancres : l'accès aux preuves se fait par défilement. La ligne `:82` accorde `scroll-margin-block:60px` aux bandes, cartes et étiquettes, mais pas aux points.
- **Solution** : un `<nav>` identifié `e090-point-index`, inséré avant la liste des points, contient une liste d'ancres vers chaque point, libellées à partir des attributs réels `data-kind` et `data-confidence` (`:477-478`). La liste est reconstruite à chaque application pour rester synchronisée avec le repère courant.
- **Impact** : les points vérifiés deviennent adressables directement, sans modifier le rendu de la vue de base ni les données.
- **Risque** : si le repère n'a aucun point (`:468-471`), aucun index n'est créé : la garde évite un panneau vide. Le libellé « confiance non précisée » est un repli textuel, aucune valeur n'est inventée.
- **Effort** : S.
- **Vérification** : un seul `e090-point-index` présent ; autant d'ancres que de points ; `node --check` sans erreur.

## E090-02 — Aucun retour du point vers son repère

- **Problème / preuve** : `src/views/chronology.js:473-478` porte `data-point-id`, `data-kind` et `data-confidence` sur le point, mais aucun lien vers le repère. Celui-ci est pourtant adressable : la ligne `:378` fixe l'identifiant du repère sur le élément de liste.
- **Solution** : l'identifiant d'événement est extrait de l'ID du point par une expression régulière à capture avide, donc robuste aux tirets dans l'ID ; une ancre « Repère » est ajoutée à chaque point avec un `aria-label` unique. Une garde sur la classe empêche la duplication.
- **Impact** : l'aller-retour point et repère devient possible au clavier comme au pointeur.
- **Risque** : si le format des identifiants change, l'extraction échoue et le lien est silencieusement omis plutôt que de produire une casse. Aucun lien externe n'est fabriqué.
- **Effort** : S.
- **Vérification** : après trois rendus successifs, chaque point contient exactement une ancre de retour valide.

## E090-03 — Sommaire des repères absent

- **Problème / preuve** : `src/views/chronology.js:348-349` construit la liste ordonnée `#atlas-chrono-events` ; les cartes portent année, titre et sous-titre (`:392-394`), mais aucun sommaire ne permet de sauter d'un repère à l'autre.
- **Solution** : un `<nav>` identifié `e090-event-index`, inséré avant `#atlas-chrono-eras` (`:278-279`), est construit uniquement depuis les repères réellement affichés ; la carte sélectionnée reçoit `aria-current="location"`, en cohérence avec `:390`.
- **Impact** : navigation directe entre repères, avec un libellé parleur reprenant l'année réelle.
- **Risque** : en mode filtrage (`:239-242`), le périmètre passe à tous les événements du pays : le sommaire reflète exactement les repères affichés, pas seulement l'ère courante, ce qui reste cohérent avec le statut affiché en `:249-255`.
- **Effort** : M.
- **Vérification** : nombre d'ancres égal au nombre de repères affichés ; un seul `aria-current="location"` dans ce sommaire ; aucun doublon d'ID.

## E090-04 — Navigation inter-vues sans accès au routeur

- **Problème / preuve** : `ctx` n'expose que `viewId`, `stage`, `layout`, `css`, `el` et `reducedMotion` (`src/views/chronology/registry.js:28-37`). La fonction `goView` est importée seulement dans `src/views/chronology.js:6` et employée en `:273` par le bouton `#nav-c2a-back` défini en `:269-274`.
- **Solution** : un `<nav>` `e090-view-nav` contient une ancre `e090-go-globe` qui relaie le clic vers `#nav-c2a-back` par délégation DOM et annule le saut d'ancre par défaut, sans importer le magasin ; une ancre `e090-view-current` porte `aria-current="page"` et vise `#atlas-chrono-title` (`:228`) ; une note rappelle que la coque conserve les autres vues.
- **Impact** : une véritable navigation inter-vues est offerte sans couplage avec le magasin ni second propriétaire du routeur.
- **Risque** : si le bouton de retour est absent, l'ancre est marquée `aria-disabled="true"` et devient inerte — aucun repli hasardeux. L'état désactivé du bouton cible est vérifié avant le clic.
- **Effort** : M.
- **Vérification** : un clic sur `e090-go-globe` déclenche bien `goView('globe')` par le bouton existant ; absence d'import du magasin dans `E090.js`.

## E090-05 — Fil de situation C2 muet sur les points

- **Problème / preuve** : `src/views/chronology.js:142-168` construit le fil `#nav-c2a-trail` avec cinq crumbs, dont « Points du repère (N) » écrit en texte brut en `:152`, sans aucun lien.
- **Solution** : un paragraphe `e090-trail-points` est ajouté au fil avec une ancre par point vérifié. Une garde sur l'appartenance au `layout` limite l'action à la vue courante.
- **Impact** : le repère de situation devient un point d'entrée vers les preuves, au lieu d'être une simple étiquette.
- **Risque** : le fil de la coque mentionné en `:141` n'est pas modifié : E090 ajoute un contenu local sans remplacer ni réordonner les crumbs existants. Si le fil est reconstruit sans son identifiant, la garde fait sauter le chantier sans erreur.
- **Effort** : S.
- **Vérification** : autant d'ancres dans le fil que de points ; aucune duplication après re-rendu.

## E090-06 — Sources citées sans lien et sans retour

- **Problème / preuve** : `src/views/chronology.js:461` annonce « sources titrées sans lien » ; les lignes `:489-499` créent la liste des sources avec des éléments portant `data-source-id` (`:495`) et un attribut `title` d'auteurs (`:496`), mais aucune ancre.
- **Solution** : un registre local `e090-source-register` regroupe les identifiants uniques, triés de façon déterministe ; chaque entrée porte des ancres vers tous les points qui citent la source.
- **Impact** : le lien entre source et point devient navigable, sans réseau.
- **Risque** : une normalisation garantit des identifiants stables ; deux identifiants voisins pourraient entrer en collision, risque documenté.
- **Effort** : M.
- **Vérification** : autant d'entrées que d'identifiants uniques ; aucun lien externe.

## E090-07 — Aucune navigation consécutive entre points

- **Problème / preuve** : `src/views/chronology.js:506-526` gère les actions « Repère précédent » et « Repère suivant », mais aucun équivalent n'existe pour les points, alors que `:473` numérote leur position.
- **Solution** : une bande `e090-point-nav` est ajoutée dans l'en-tête de chaque point (structure décrite en `styles.css:227`) avec deux ancres vers les points voisins. Les bornes sont rendues comme des textes `aria-disabled="true"` plutôt que comme des liens morts.
- **Impact** : parcours séquentiel clavier des preuves vérifiées.
- **Risque** : si l'en-tête est absent, la bande est ajoutée directement au point ; une garde empêche la duplication. Le décompte des points est lu dans le DOM, jamais supposé.
- **Effort** : S.
- **Vérification** : le premier point porte un « précédent » indisponible, le dernier un « suivant » indisponible ; les points intermédiaires ont deux ancres valides.

## E090-08 — Aucune mesure de couverture des liens

- **Problème / preuve** : `src/views/chronology.js:247-256` affiche un statut de filtrage mais rien sur les liens profonds. La C2 dispose d'une seule région live `#nav-c2a-live` (`:121-133`) : en créer une seconde provoquerait des annonces concurrentes.
- **Solution** : un paragraphe `e090-coverage` affiche en texte ordinaire, sans attribut live, le nombre de points, d'ancres internes, de sources citées et la vue courante ; un miroir `data-e090-coverage` est posé sur le layout pour audit.
- **Impact** : mesure auditable et non portée par la seule couleur, sans bavardage vocal.
- **Risque** : le décompte est calculé depuis le DOM réel, donc il suit les changements apportés par d'autres lentilles ; c'est le comportement souhaité.
- **Effort** : S.
- **Vérification** : le miroir égale le nombre d'ancres `e090` présentes ; aucune seconde région live n'est créée.

## E090-09 — Ancres non focalisables et sans repère visuel

- **Problème / preuve** : `src/views/chronology.js:82` pose `scroll-margin-block` seulement sur les bandes, cartes et étiquettes ; les points (`:474`) et les repères (`:378`) n'ont ni `tabindex` ni style de cible atteinte.
- **Solution** : `tabIndex=-1` de façon idempotente et classe `e090-anchor-target` sur ces cibles et sur les entrées du registre ; la règle CSS associe une marge de défilement et un contour visible à l'état de cible atteinte.
- **Impact** : un lien profond déplace réellement le focus et laisse une trace visuelle explicite.
- **Risque** : `tabIndex=-1` n'ajoute pas les cibles à l'ordre de tabulation, ce qui est voulu ; la restauration de focus de la vue de base (`:199-205`, `:540`) reste inchangée.
- **Effort** : S.
- **Vérification** : après activation d'une ancre, l'élément actif porte l'ID attendu ; le contour calculé n'est pas `none`.

## E090-10 — Re-render, pannes partielles et mouvement réduit

- **Problème / preuve** : `runEnhancements` est appelé à chaque rendu (`src/views/chronology.js:539`) et la coque reconstruit le DOM (commentaire en `:95-96`) ; `registry.js:39-42` neutralise une lentille qui lève une exception.
- **Solution** : une fonction d'assurance crée chaque nœud identifié seulement s'il n'existe pas, des gardes protègent les éléments répétés, et chaque chantier est isolé : un échec local alimente `data-e090-issues` et `data-e090="partial"`, sans aucune journalisation. `ctx.reducedMotion()` (`registry.js:33-35`) pilote la classe `e090-reduced`.
- **Impact** : les dix chantiers restent indépendants ; une panne locale n'aveugle pas les autres.
- **Risque** : le miroir d'état n'est pas un rapport d'erreur complet, la journalisation étant interdite ; le diagnostic fin revient à `viewDiagnostics()` (`registry.js:46-48`).
- **Effort** : S.
- **Vérification** : `node --check` valide ; aucun terme interdit détecté ; trois rendus successifs laissent un seul exemplaire de chaque bloc `e090`.
