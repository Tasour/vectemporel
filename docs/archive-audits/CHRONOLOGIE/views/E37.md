## Chantiers

### E37-01 — Aucun énoncé historique codé en dur dans la lentille

- **Preuve** : le champ `related` est vide pour les 229 repères (constat structurant de
  `atlas-chronologie.md:7-10`) ; toute phrase historique écrite par un greffon serait une
  invention. Les libellés de `chronology.js:227,230` sont eux-mêmes dérivés du pays courant.
- **Solution** : `build()` n'émet que des libellés de schéma (« Pays (identifiant) », « Ères
  affichées », « Repères affichés », « Points du repère », « Sources citées », « Confiance
  déclarée », « Types de points », « Thèmes », « Identifiants de sources ») et des compteurs
  recomputés. Aucune chaîne de E37 ne contient de millésime, de nom de repère ni de nom de
  pays. Écritures exclusivement via `textContent`.
- **Impact** : la lentille ne peut pas introduire de fait nouveau dans la vue Chronologie.
- **Risque** : un libellé de schéma pourrait être lu comme une affirmation ; ils sont
  génériques, non datés et non attribués à un acteur.
- **Effort** : S.
- **Vérification** : relecture — aucune chaîne de E37 ne contient de date ni de nom propre ;
  `node --check src/views/chronology/E37.js`.

### E37-02 — Compteurs dérivés du DOM rendu, jamais de chiffre mémorisé

- **Preuve** : `chronology.js:214-222` construit un layout dont `data-country-id` porte
  l'identifiant réel ; `:278-307` émet une bande par ère avec `data-era-id`, `:347-413` un `<li>`
  par repère avec `data-event-id`, `data-year`, `data-importance`, `data-tags`, et `:466-503`
  un `<li class="point">` par point avec `data-kind`, `data-confidence`. Aucun de ces chiffres
  n'est exposé en texte global.
- **Solution** : `count()` et `nodeList()` interrogent `#atlas-chrono-eras .era-band`,
  `#atlas-chrono-events > li[data-event-id]` et `#atlas-chrono-aside .points > li.point`.
  Les `<li>` masqués par les filtres structurels de E04 (`item.hidden`) sont exclus : le panneau
  décrit ce qui est réellement affiché, jamais un total supposé. Le pays est affiché par son
  identifiant (`layout.dataset.countryId`), pas par un nom déduit.
- **Impact** : cinq compteurs traçables, recalculés à chaque rendu, y compris sous filtre.
- **Risque** : un filtrage textuel de la vue (`local.query`) peut afficher des repères hors ère ;
  le libellé « Repères affichés » reste exact dans les deux cas.
- **Effort** : M.
- **Vérification** : comparer les cinq compteurs du panneau avec un comptage direct des nœuds
  portant les `data-*` ci-dessus.

### E37-03 — Distribution de confiance réelle, sans catégorie fabriquée

- **Preuve** : `chronology.js:478` écrit `item.dataset.confidence = point.confidence`. Les
  valeurs réellement présentes dans le jeu (`vérifié`, `certain`, `probable`, `disputé`,
  `non documenté`, `disputed`) sont hétérogènes ; les regrouper serait interprétatif.
- **Solution** : `tally(..., 'data-confidence')` lit les seules valeurs rencontrées, les imprime
  verbatim avec leur compteur, sans traduction ni fusion, dans un ordre déterministe
  (décroissant puis `localeCompare('fr')`). État vide : « non renseignée » en italique.
- **Impact** : « probable » et « disputé » restent visibles tels quels, non convertis en
  « vrai/faux » ni en « vérifié ».
- **Risque** : vocabulaires hétérogènes ; affichés verbatim, jamais normalisés artificiellement.
- **Effort** : S.
- **Vérification** : relecture — la ligne « Confiance déclarée » égale le décompte des
  `data-confidence` des points du repère courant.

### E37-04 — Types de points réels, sans traduction ni regroupement

- **Preuve** : `chronology.js:477` expose `data-kind` sur chaque point ; la vue affiche déjà
  `point.kind` tel quel dans le badge de la fiche (`:483`). Aucune taxonomie supplémentaire
  n'est définie par la lentille.
- **Solution** : `tally(..., 'data-kind')` dérive le décompte des seules valeurs présentes, avec
  le même tri déterministe que E37-03 ; état vide « non renseignés ».
- **Impact** : densité et variété des points mesurables sans commentaire interprétatif.
- **Risque** : le terme vient du schéma du jeu de données, non d'une traduction libre.
- **Effort** : S.
- **Vérification** : comparer la ligne « Types de points » avec les `data-kind` du DOM.

### E37-05 — Sources : identifiants réels uniquement, aucune URL reconstruite

- **Preuve** : `chronology.js:489-500` résout chaque `sourceId` vers `country.sources[].title`
  et pose `data-source-id` sur le `<li>` ; fabriquer une URL à partir d'un `SRC-…` inventerait
  une référence. `README.md:5` et `verify.mjs:26` interdisent les liens externes.
- **Solution** : `sourceIds()` ne lit que `data-source-id`, jamais un titre ni une URL.
  Affichage des 3 premiers identifiants réels puis `+N` où `N` est le restant réel ; sinon
  « aucune référence renseignée ». Aucun `href`, pas même une ancre interne.
- **Impact** : traçabilité affichable sans créer de lien externe ni de citation supposée.
- **Risque** : troncature à 3 identifiants ; le solde est un compteur, pas une liste inventée.
- **Effort** : S.
- **Vérification** : relecture — seuls des `SRC-…` présents dans le dataset apparaissent ;
  aucun `href` dans E37.

### E37-06 — Thèmes réels uniquement, aucune relation causale

- **Preuve** : `chronology.js:380-383` pose `data-tags` sur les repères, `:441-459` affiche les
  thèmes du repère avec `aria-pressed`. `atlas-chronologie.md:195-216` rappelle qu'écrire
  « contemporain » ou « influence » dans le DOM serait une invention (`related` vide).
- **Solution** : `tags()` lit `data-tags` des seuls repères non masqués, déduplique et trie en
  français. Aucun attribut `data-influence`, `data-breaks-with` ni `data-contemporary` n'est
  produit ; le libellé reste « Thèmes », jamais « Relations ».
- **Impact** : aucun lien inter-repères non documenté n'est suggéré.
- **Risque** : un tag pourrait être sur-interprétée comme relation : le libellé factuel
  « Thèmes » neutralise cette lecture.
- **Effort** : S.
- **Vérification** : relecture — aucune chaîne relationnelle dans E37 ; thèmes égaux aux
  `data-tags` des repères affichés.

### E37-07 — Gardes sur données : ni `NaN`, ni `undefined`, ni `[object Object]`

- **Preuve** : `ctx.layout` peut être absent (lentille appelée hors vue) et les attributs
  `data-*` peuvent manquer sur un rendu partiel ; une concaténation directe produirait
  `undefined` ou `NaN`.
- **Solution** : `asText()` ne laisse passer qu'une chaîne ou un nombre fini ; `count()` et
  `tally()` ne comptent que des listes et des attributs présents ; `addRow()` applique
  explicitement la classe `e37-empty` quand la valeur est vide ; `node.dataset.state` vaut
  `active` ou `empty` selon le contenu réel. Toute écriture passe par `ctx.el(...).textContent`
  après `replaceChildren()`.
- **Impact** : un contexte vide ou incomplet affiche un état propre, jamais une erreur ni une
  valeur de comblement.
- **Risque** : la valeur numérique `0` est une donnée réelle et reste affichée « 0 ».
- **Effort** : M.
- **Vérification** : appeler la lentille avec un `ctx` sans `layout` — aucun nœud ajouté, aucune
  exception ; aucun `NaN`/`undefined` dans le panneau.

### E37-08 — Idempotence multi-rendus, aucun abonnement accumulé

- **Preuve** : `shell.js:137` vide le DOM à chaque `emit()` ; `chronology.js:539` relance
  `runEnhancements` à chaque rendu ; `registry.js:13-19` ne purge jamais ses tables, `:39-43`
  rejoue toutes les lentilles.
- **Solution** : `PANEL_ID = 'chronology-e37-garantie'` unique avec garde
  `document.getElementById` ; CSS via `ctx.css` (`cssOnce`) ; aucun `addEventListener`, aucun
  rappel `onHover`/`onLeave`, aucune variable de module conservant un nœud DOM. Le panneau est
  retrouvé à chaque appel et ses lignes sont reconstruites depuis le DOM courant.
- **Impact** : un seul panneau, quel que soit le nombre de rendus ; zéro écouteur fantôme.
- **Risque** : un second passage sur le même DOM (diagnostics) retrouve le panneau existant et
  ne le duplique pas.
- **Effort** : M.
- **Vérification** : rendre la vue 10× — `document.querySelectorAll('#chronology-e37-garantie')
  .length === 1` et une seule feuille `#chronology-e37`.

### E37-09 — Accessibilité : groupe statique, pas une seconde région live

- **Preuve** : `chronology.js:119-138` possède déjà `#nav-c2a-live` (`role="status"`,
  `aria-live="polite"`) et la coque expose sa propre région live (`globe.js:#globe-live`) ; un
  second live bavarderait à chaque rendu. `chronology.js:227` porte l'unique `h1` de la vue.
- **Solution** : `#chronology-e37-garantie` porte `role="group"` et un `aria-label` stable,
  jamais `role="status"`, jamais d'appel à une fonction d'annonce. Le panneau n'ajoute ni `h1`
  ni `h2`, ne modifie pas `tabindex`, ne piège pas le focus et ne détourne aucun sélecteur de
  test (`.event-card`, `#atlas-chrono-events`, `#atlas-chrono-tools`).
- **Impact** : zéro annonce redondante pour les lecteurs d'écran ; arbre de titres inchangé.
- **Risque** : le panneau est statique — l'information est dans le DOM, lue à la navigation,
  sans annonce automatique : comportement voulu.
- **Effort** : S.
- **Vérification** : relecture — aucun `aria-live`/`role=status` dans E37 ; un seul `h1` dans
  la vue.

### E37-10 — Zéro réseau, zéro aléa, mouvement réduit et budget

- **Preuve** : règle 1 de `AGENTS.md` (zéro réseau) ; `styles.css:316-317` empile les panneaux
  sous 620 px ; `chronology.js:89-91` neutralise ses transitions sous
  `prefers-reduced-motion`.
- **Solution** : aucune requête, aucun `Math.random`, aucune journalisation, aucune animation JS.
  CSS unique via `ctx.css('chronology-e37', …)`, sans transition, avec `@media
  (prefers-reduced-motion:reduce)` et un bloc `@media (max-width:620px)` qui conserve la grille
  sur 390 px. Aucun canvas, aucune boucle rAF, aucune ressource externe.
- **Impact** : la lentille ne dégrade ni le budget réseau ni la préférence de mouvement, et
  reste lisible sur mobile.
- **Risque** : aucun (aucun `transform` ni transition n'est utilisé).
- **Effort** : S.
- **Vérification** : `node --check` PASS ; recherche statique sans motif
  `console.`/`Math.random`/`fetch(`/`http`/`innerHTML`/`@import`.

## Blocages hors de mon fichier

- **A (`chronology.js`)** : les compteurs « Repères affichés » dépendent de l'attribut `hidden`
  posé par E04. Si un autre greffon masquait des repères par CSS sans `hidden`, le compteur
  resterait exact pour les nœuds du DOM mais pourrait différer du rendu visuel. E37 ne modifie
  aucun autre greffon.
- **B (`registry.js`)** : les tables de lentilles ne sont jamais purgées ; contourné localement
  par l'absence totale d'abonnement et la garde d'id (E37-08). Dette globale à porter par
  l'agent maître.
- **C (`dataset.js`)** : vocabulaires de confiance hétérogènes (`vérifié`, `certain`,
  `probable`, `disputé`, `disputed`). E37 les affiche verbatim plutôt que de forcer une
  normalisation interprétative.
