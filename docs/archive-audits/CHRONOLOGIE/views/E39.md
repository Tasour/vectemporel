# E39 — Densité de la chronologie

Lentille CHRONOLOGIE E39 — domaine : densité de l'information.
Fichier possédé : `src/views/chronology/E39.js`. Lectures seules : `src/views/chronology.js`,
`src/views/chronology/registry.js`, `styles.css`, `tests/e2e.mjs`,
`UNIFIED_AUDIT/views/atlas-chronologie.md`,
`UNIFIED_AUDIT/NAVIGATION/views/c2-orientation-atlas.md`. Aucun autre fichier modifié.
Aucune donnée historique inventée, aucun appel réseau, aucune trace de débogage,
aucune source d'aléa, aucun sélecteur de test altéré.

Thème : **rendre la densité mesurable, lisible et réglable** dans la vue chronologie.
Tous les compteurs sont recalculés depuis le DOM rendu ; les deux seuils de
« vue dense » sont des choix éditoriaux de l'interface, explicitement déclarés
comme tels (`DENSE_REPERES = 12`, `DENSE_CHARS = 6000`), jamais présentés comme
des faits historiques.

---

## E39-01 — Aucune mesure de ce qui est réellement affiché

- **Titre** : la vue dit combien de repères existent, jamais combien de contenu est effectivement dense à l'écran.
- **Preuve** : `chronology.js:247-256` affiche `Ère k/N`, `repère(s) affiché(s)` et le rang global, mais pas les points, les sources ni le volume de texte. `styles.css:205` pose une grille `repeat(auto-fill, minmax(190px,1fr))` : le nombre de cartes visibles varie avec la largeur et avec les filtres, sans retour chiffré.
- **Solution** : `<section id="e39-panel">` inséré après `#atlas-chrono-status`, avec `<p id="e39-density">` : « Densité mesurée : N repère(s) affiché(s) · P point(s) · S source(s) · X caractères visibles. » `metrics()` compte les `<li data-event-id>` non masqués, les `.point`, les `[data-source-id]` et la longueur normalisée des textes visibles.
- **Impact** : une grandeur chiffrée, recalculée à chaque rendu, remplace l'impression subjective de « beaucoup de contenu ».
- **Risque** : un filtre E04 pose `hidden` sans re-render (`E04.js:199-239`) ; la lecture est donc différée en micro-tâche sur `input`/`change`/`click` de `#atlas-chrono-main`, et `visibleEvents()` ignore les `<li hidden>`.
- **Effort** : M.
- **Vérification** : relecture — `#e39-density` contient quatre grandeurs dérivées du DOM ; aucun chiffre n'est littéral dans le module (hors seuils déclarés).

## E39-02 — Aucun réglage de la densité d'affichage

- **Titre** : les espacements de la vue sont figés, sans possibilité de resserrer la lecture.
- **Preuve** : `styles.css:195-196` fixe `.chronology-main { padding:26px 28px 34px }` et `.chronology-aside { padding:24px 22px 34px }` ; `:205` fixe `gap:9px` et `:226` `padding:10px 0` pour chaque point. Aucune commande ne permet de modifier ces valeurs.
- **Solution** : bouton `#e39-compact-toggle` « Densité compacte » dans `#atlas-chrono-tools`, avec `aria-pressed` (bascule indépendante, comme les thèmes de `chronology.js:330-341`). L'état `compact` vit dans le module ; la classe `.e39-compact` réduit uniquement les paddings, les gaps, la hauteur minimale des cartes (150 → 120 px, `styles.css:207`) et celle des images (82 → 64 px, `:214`). Aucun texte, aucun point, aucune source n'est masqué.
- **Impact** : l'utilisateur choisit sa densité sans quitter la vue ni modifier `styles.css`.
- **Risque** : coexistence avec la bascule « Lecture confort » de E01 (police agrandie) : E39 ne touche à aucune taille de police, donc les deux réglages sont cumulables sans surcharge de règle.
- **Effort** : M.
- **Vérification** : relecture — `aria-pressed` bascule, `data-e39-compact` vaut `1` ou `0` sur `.chronology-layout`, aucune règle `.e39-compact` ne porte sur `font-size` ni sur `display:none`.

## E39-03 — Grille de repères inadaptée au nombre affiché

- **Titre** : avec peu de repères, la grille étire les cartes ; avec beaucoup, la colonne minimale reste large.
- **Preuve** : `styles.css:205` impose `minmax(190px,1fr)` quoi qu'il arrive ; `E04.js:217-220` peut réduire le nombre de `<li>` visibles à un ou deux, qui s'étirent alors sur toute la largeur.
- **Solution** : en mode compact uniquement, `.e39-compact .event-list` passe à `repeat(auto-fill, minmax(150px,1fr))` avec `gap:6px` ; en mode normal, la grille d'origine reste intacte. Sous 620 px, le mode compact conserve la colonne unique prévue à `styles.css:339`.
- **Impact** : la densité de la grille suit le nombre de repères réellement affichés, sans casser le parcours E2E (`.event-card`, `tests/e2e.mjs:29`, n'est ni renommé ni retiré).
- **Risque** : `min-width:0` n'est pas réglé globalement (d'autres lentilles peuvent s'en charger) ; les titres longs restent gérés par `.event-card { overflow:hidden }` (`styles.css:207`).
- **Effort** : S.
- **Vérification** : relecture CSS — la règle de grille est préfixée `.e39-compact` et le repli mobile est documenté.

## E39-04 — Densité des ères invisible

- **Titre** : le nombre de bandes d'ères rendues n'est jamais énoncé, alors qu'il conditionne la hauteur de la page.
- **Preuve** : `chronology.js:281-305` crée une bande par ère ; `styles.css:198` leur donne `min-height:44px` et `flex:1 1 110px`, donc leur nombre commande directement le défilement. Aucun compteur d'ères n'existe dans le `<nav id="atlas-chrono-eras">`.
- **Solution** : `<p id="e39-era" class="e39-note">` ajouté en fin de nav : « Ères rendues : K bande(s) · une seule ère est développée à la fois. » `K` est compté depuis `#atlas-chrono-eras .era-band` ; la seconde partie reprend mot pour mot la lede de la vue (`chronology.js:230`).
- **Impact** : la charge verticale imputable aux ères devient lisible au bon endroit, sans ouvrir l'aide.
- **Risque** : E01 ajoute un badge textuel dans la bande courante (`E01.js:110-113`) ; E39 comptent les bandes, pas leurs enfants, donc aucun double comptage. Aucune cible interactive n'est insérée dans la nav.
- **Effort** : S.
- **Vérification** : relecture — `document.querySelectorAll('#atlas-chrono-eras .era-band').length` égale le chiffre affiché.

## E39-05 — Densité des thèmes non quantifiée

- **Titre** : la barre d'outils aligne un bouton par thème sans en donner le nombre.
- **Preuve** : `chronology.js:328-343` itère `new Set(country.events.flatMap(...tags))` et crée un `<button class="atlas-chrono-tag">` par valeur, avec `aria-pressed` et un `data-tag`. Le nombre dépend donc du pays, sans indication.
- **Solution** : `<p id="e39-tags">` dans le panneau : « Thèmes proposés : T · chaque thème reste un filtre indépendant. » `T` est compté depuis `#atlas-chrono-tools .atlas-chrono-tag[data-tag]`. Aucun bouton n'est retiré, replié ou redimensionné : la densité des thèmes est mesurée, pas tronquée.
- **Impact** : le coût visuel de la barre d'outils est connu, et le caractère indépendant des bascules est rappelé.
- **Risque** : E04 insère sa propre barre après `#atlas-chrono-tools` (`E04.js:289-294`) ; E39 ne sélectionne que les descendants de la barre d'origine, donc les contrôles E04 ne sont pas comptés.
- **Effort** : S.
- **Vérification** : relecture — le chiffre correspond au nombre de `[data-tag]` dans `#atlas-chrono-tools` ; aucun `hidden` posé sur un bouton de thème par E39.

## E39-06 — Densité de provenance non agrégée

- **Titre** : chaque point cite ses sources, mais le taux de couverture documentaire du repère reste implicite.
- **Preuve** : `chronology.js:489-500` construit un `<ul class="point-sources">` par point ; `chronology.js:466-504` liste les points sans bilan. Le lecteur doit compter manuellement les `<li data-source-id>`.
- **Solution** : `<p id="e39-provenance" class="e39-note">` ajouté en fin d'aside : « Provenance du repère : s/P point(s) sourcé(s), R référence(s) citée(s). » `P` = `.point`, `s` = points contenant au moins un `[data-source-id]`, `R` = total des `[data-source-id]` ; tout est lu dans l'aside courante.
- **Impact** : la densité documentaire devient une donnée visible et falsifiable, sans commentaire fabriqué ni lien externe.
- **Risque** : l'aside peut être vide (état sans repère, `chronology.js:527-535`) : la ligne affiche alors `0/0 point(s) sourcé(s), 0 référence(s) citée(s)`, ce qui est exact et non une erreur.
- **Effort** : S.
- **Vérification** : relecture — les trois nombres sont recalculés depuis `ctx` DOM ; aucun `href` n'est introduit.

## E39-07 — Seuil de densité et conseil contextuel falsifiable

- **Titre** : rien ne signale le passage en vue dense, alors que le nombre de cartes peut croître fortement sous l'effet d'une recherche large.
- **Preuve** : `chronology.js:178-188` élargit le périmètre de recherche à tous les repères du pays dès qu'un terme est actif ; `chronology.js:344` n'affiche qu'un compteur `N / M repères`. Le nombre de caractères affichés peut exploser sans changement de présentation.
- **Solution** : `#e39-advice` compare les grandeurs mesurées à deux seuils explicites — plus de 12 repères **ou** plus de 6 000 caractères visibles — et affiche soit « Vue dense (…) : affinez avec la recherche ou les filtres structurels. », soit « Densité modérée (…) : la liste reste lisible en une vue. ». `data-e39-dense` est posé sur le panneau pour un léger accent de couleur.
- **Impact** : un conseil actionnable, toujours accompagné des chiffres qui le justifient ; le seuil est modifiable dans le code et documenté ici.
- **Risque** : ces seuils sont des choix d'ergonomie, pas des vérités historiques : ils sont nommés `DENSE_REPERES`/`DENSE_CHARS` et commentés comme tels dans le module et ce rapport. Le conseil n'est pas une région live, donc aucun doublage vocal avec les annonces C2 (`#nav-c2a-live`, `chronology.js:119-138`).
- **Effort** : M.
- **Vérification** : relecture — le texte contient toujours les deux grandeurs ; `data-e39-dense` vaut `1` uniquement si l'une des deux conditions est vraie.

## E39-08 — Densité et cibles tactiles : aucun rétrécissement des contrôles

- **Titre** : une mise en page compacte ne doit pas dégrader l'accessibilité des boutons.
- **Preuve** : `styles.css:198` impose `min-height:44px` aux bandes d'ère ; `chronology.js:48-51` donne `min-height:36px` au champ de recherche et `:53-57` `min-height:30px` aux boutons de thème ; `:77-81` fixe `min-height:32px` au bouton de réinitialisation.
- **Solution** : la feuille E39 ne contient aucune règle `min-height` sur ces contrôles ; le bouton ajouté `#e39-compact-toggle` mesure `min-height:36px`, avec `:focus-visible` et `cursor:pointer`. Les seules hauteurs réduites sont celles de conteneurs non interactifs (`.event-card`, `img`). Le compte `aria-pressed` est réservé à la bascule compacte, indépendante des choix uniques portés par `aria-current`.
- **Impact** : densité et accessibilité ne s'excluent pas ; les sélecteurs E2E restent inchangés.
- **Risque** : un futur réglage « très compact » devrait réexaminer ce point ; E39 s'en tient au seuil 36 px.
- **Effort** : S.
- **Vérification** : relecture CSS — aucune règle `.e39-compact` ne cible `.era-band`, `.atlas-chrono-search`, `.atlas-chrono-tag` ou `.atlas-chrono-empty button`.

## E39-09 — Mobilité et mouvement réduit

- **Titre** : la densité doit rester lisible à 390 px et ne pas introduire de transition sous préférence de mouvement réduit.
- **Preuve** : `styles.css:316` passe la vue en une colonne à 1000 px, `:339` force `.event-list { grid-template-columns:1fr }` sous 620 px ; `chronology.js:83-88` n'adapte que les ères et les outils. Aucune règle ne couvre le panneau de densité.
- **Solution** : `@media (max-width:620px)` réduit les paddings du mode compact à `14px 12px`, garde la colonne unique et ajuste le bouton ; l'attribut `data-e39-reduced`, positionné depuis `ctx.reducedMotion()`, et `@media (prefers-reduced-motion:reduce)` annulent la transition du bouton. Le panneau utilise `box-sizing` hérité, `min-width:0` sur la grille et aucune position absolue : aucun débordement horizontal introduit.
- **Impact** : le panneau reste dans le flux, sous le statut, sans masquer la fiche du repère.
- **Risque** : la consultation de `matchMedia` est protégée par le wrapper `ctx.reducedMotion()` du registre (`registry.js:33-37`), donc aucun appel direct à l'API navigateur depuis la lentille.
- **Effort** : S.
- **Vérification** : relecture CSS — présence des deux media queries et de l'attribut ; aucun `position:absolute` dans la feuille E39.

## E39-10 — Idempotence et non-collision des lentilles

- **Titre** : la coque reconstruisant tout le DOM à chaque émission, une lentille mal gardée duplique nœuds et écouteurs.
- **Preuve** : `shell.js:137` fait `root.innerHTML = ''` ; `registry.js:13-19` injecte le CSS une seule fois par `cssOnce` et `:28-44` réapplique tous les greffons à chaque rendu. E01 (`E01.js:89-134`) et E04 (`E04.js:278-296`) utilisent le même motif de garde par identifiant.
- **Solution** : `ctx.css('chronology-e39', …)` une seule fois ; classe de portée `chronology-e39` et `data-e39="1"` sur `.chronology-layout` ; huit identifiants tous préfixés `e39-` et protégés par `getElementById` ; écouteurs posés uniquement sur le `main` courant, donc détruits avec lui ; aucun état module hormis le booléen `compact` ; aucune modification de nœud existant sinon l'ajout de classes et d'attributs `data-*` sur le layout.
- **Impact** : exactement un panneau, une note d'ères, une note de provenance et un bouton par rendu, sans fuite d'écouteur ni doublon de CSS.
- **Risque** : si un autre greffon supprimait `#atlas-chrono-status`, le panneau serait ajouté en tête de `main` par le repli `prepend` ; la lecture reste correcte. Aucune région `role="status"` n'est ajoutée, évitant la concurrence avec `#e04-status` et `#nav-c2a-live`.
- **Effort** : S.
- **Vérification** : relecture — `document.querySelectorAll('#e39-panel, #e39-era, #e39-provenance, #e39-compact-toggle').length === 4` ; `node --check` PASS.

## Statut d’implémentation

Les 10 chantiers sont implémentés dans `src/views/chronology/E39.js` uniquement.
Le module enregistre `register('E39', (ctx) => { … })` et consomme
`ctx.layout`, `ctx.stage`, `ctx.css`, `ctx.el`, `ctx.reducedMotion`. La feuille est
injectée par `ctx.css('chronology-e39', …)`. Aucun autre fichier du dépôt n'est
modifié par cette lentille.

## Blocages documentés

1. **Filtrage E04 sans re-render** (`E04.js:199-239`) : le compteur E39 est rafraîchi en micro-tâche après `input`/`change`/`click` sur `#atlas-chrono-main` ; aucun événement personnalisé n'est introduit.
2. **Seuils de densité** : 12 repères / 6 000 caractères sont des choix d'interface, pas des données du jeu. Ils sont exposés en constantes nommées et commentés, donc modifiables et falsifiables.
3. **Intégration** : conformément au contrat de la vague, le module est autonome ; c'est l'agent maître qui assure le câblage final du registre et rejoue les suites.
