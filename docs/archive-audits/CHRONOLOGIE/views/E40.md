# E40 — Cohérence inter-vues de la Chronologie

Lentille **E40** de la vague « Chronologie ». Fichier possédé : `src/views/chronology/E40.js`,
enregistré sous `register('E40', (ctx) => { … })`. Pièces lues en lecture seule :
`src/views/chronology.js`, `src/views/chronology/registry.js`, `src/views/chronology/index.js`,
`src/domain/store.js`, `src/data/dataset.js`, `src/app.js`, `src/ui/shell.js`,
`src/platform/keyboard.js`, `UNIFIED_AUDIT/MONDE/views/M40.md` (lentille homologue du Monde).
Aucun autre fichier modifié, aucune donnée historique inventée, zéro réseau, zéro
`Math.random`, zéro `console.*`, zéro `requestAnimationFrame`.

Contrat respecté : `ctx = { viewId, stage, layout, css(id,rules), el(tag,cls,text), reducedMotion() }`.
CSS injecté une seule fois via `ctx.css('chronology-e40', …)` ; tous les identifiants
DOM sont préfixés `chronology-e40-` ; le panneau `#chronology-e40-coherence` est un
`role="group"` sans `aria-live`, `pointer-events:none`, greffé dans `#atlas-stage`
reconstruit à chaque rendu (`shell.js:533-541`). Aucun sélecteur utilisé par les
tests n'est renommé (`.event-card`, `.era-band`, `#nav-c2a-*`, `.shell-trail`).

> **Périmètre.** La Chronologie n'est qu'une projection de l'état unique décrit
> dans `store.js` et partagé avec le Monde, le Récit, la Géographie, la
> Constellation et la Matrice des points. Le store, la coque et le routeur
> dérivent tous leurs libellés du même `DATASET` et du même `state.countryId`.
> E40 rend ces accords **falsifiables** dans un panneau visible et ne réconcilie
> aucun fichier partagé : c'est un contrôle, pas une réparation.

## E40-01 — Identité du pays : quatre miroirs, une seule vérité

- **Titre.** Le pays courant est écrit à quatre endroits ; une dérive ferait afficher la Chronologie d'un pays alors que le Récit ou le Monde en affichent un autre.
- **Preuve.** `chronology.js:208` dérive `country` de `currentCountry()` (`store.js:399-401`) ; `:215-216` grave `layout.dataset.countryId`; `:227` écrit le `h1` « Chronologie · <nom> » ; `app.js:105-127` publie `position().countryId`. `VATLAS` n'est publié qu'après le premier `mount` (`app.js:129` puis `:135`).
- **Solution.** `refresh()` lit `getSnapshot().countryId` comme source de vérité et compare le miroir du layout, le `h1` reconstruit depuis le pays courant et, quand elle est disponible, l'API publique. L'absence de `VATLAS` au premier rendu est traitée comme une **inconnue**, pas comme une divergence (`apiId === null`).
- **Impact.** Toute dérive d'identité devient lisible d'un coup d'œil dans la vue d'entrée du pays.
- **Risque.** Un `set()` entre deux rendus peut afficher une divergence transitoire ; la microtâche de E40-10 la corrige après la réflexion du hash (`store.js:252`).
- **Effort.** S.
- **Vérification.** Avec `countryId='france'` : `France · FR · aligné`. Forcer `layout.dataset.countryId='espagne'` → `divergent` (testé).

## E40-02 — Total de repères : trois inscriptions d'une même vérité

- **Titre.** Le nombre de repères du pays est recopié par la vue, le catalogue public et la situation publique ; aucune de ces copies ne peut être recalculée par le lecteur.
- **Preuve.** `chronology.js:255` écrit le rang global `i / country.events.length`, `:344` le compteur de la barre d'outils ; `app.js:98-102` expose `countries()[].events` ; `:122` expose `position().eventCount`. Le jeu porte 10 pays / 229 repères (`dataset.js:10-11`) ; la France en compte 57 (recalculé).
- **Solution.** Trois grandeurs sont recalculées depuis le store, le catalogue public et la situation publique ; l'affichage exige leur égalité. Aucun nombre n'est codé en dur dans E40. Quand l'API publique n'est pas encore disponible, la valeur est `—` et n'est pas comptée comme défaut.
- **Impact.** Une dérive future entre `meta`, `countries()` et la vue devient détectable par lecture, sans ouvrir une autre vue.
- **Risque.** comparaison d'entiers, donc sensible au format de phrase ; c'est voulu : elle porte sur les valeurs, pas sur la ponctuation.
- **Effort.** S.
- **Vérification.** `57 repères · public 57 · situation 57 · concordant` (France, harnais réel).

## E40-03 — Bande d'ère : un seul `aria-current`, cohérent avec l'état

- **Titre.** L'ère active est portée par la seule classe visuelle et par `aria-current` ; un rendu répété ou un pays fantôme pourrait laisser zéro ou plusieurs marqueurs.
- **Preuve.** `chronology.js:284-290` pose `aria-current="true"` sur la bande dont l'index égale `eraIndex` et grave `data-era-id`; `store.js:204-213` borne l'index; `:438-452` publie `selectionSnapshot().eraId`; `app.js:121` publie `eraName`.
- **Solution.** Le contrôle dénombre `.era-band.atlas-chrono-band[aria-current="true"]`, exige exactement un marqueur quand une ère est sélectionnée (zéro sinon), vérifie son `data-era-id` contre `selectionSnapshot().eraId` et son nom contre `position().eraName`. La `NodeList` est explicitement convertie avec `Array.from` (`arr()` accepte les collections array-like) — un piège qui, non corrigé, faisait afficher « 0/0 ».
- **Impact.** L'indication d'ère de la Chronologie est la même que celle du store, d'où que vienne la navigation (flèches, clic, lien profond).
- **Risque.** `→`/`↓` changent d'ère via `selectEra` (`store.js:282-297`) ; le marqueur suit la nouvelle ère au rendu suivant, sans état dupliqué.
- **Effort.** S.
- **Vérification.** `Antiquité · marqueurs 1/9 · public Antiquité · conforme`. Retirer l'attribut → `0/1 · divergent` (testé).

## E40-04 — Repère courant : carte, fiche, rang et situation publique

- **Titre.** Le repère courant est affiché quatre fois (carte active, kicker de la fiche, `h2`, situation publique) ; ces quatre inscriptions peuvent se désynchroniser sous filtre.
- **Preuve.** `chronology.js:385-390` pose `aria-current="true"` sur la carte d'index `state.eventIndex` et grave `data-event-id`; `:420` écrit `Repère i / N`; `:423-424` le `h2#atlas-chrono-event-title`; `store.js:407-409` dérive `currentEvent()`; `app.js:124` publie `eventTitle`.
- **Solution.** Un seul contrôle vérifie : l'unicité du marqueur et son `data-event-id` contre `selectionSnapshot().eventId`, le kicker contre `eventIndex + 1 / total`, le texte du `h2` contre le titre du repère et `position().eventTitle`. **Cas documenté** : sous filtre (`#atlas-chrono-status` commence par « Recherche dans les »), la carte active peut être absente de la liste — zéro marqueur est alors conforme et signalé `(filtré)`, jamais compté comme défaut (ATLAS-CHRONO-08).
- **Impact.** Le repère affiché dans la fiche est exactement celui sélectionné dans l'état partagé avec le Récit, la Géographie et la Constellation.
- **Risque.** recoupement avec E40-03 ; ici la vérification porte sur l'identité du repère, pas sur l'ère.
- **Effort.** M.
- **Vérification.** `Massalia · cartes 1/3 · fiche conforme · conforme` (France, 3 cartes dans l'ère Antiquité).

## E40-05 — Fil de situation local contre fil canonique et fil de la coque

- **Titre.** Trois fils de situation coexistent ; ils doivent raconter la même histoire sur les niveaux qu'ils partagent.
- **Preuve.** `chronology.js:142-167` construit `#nav-c2a-trail` avec cinq mâches : Monde › pays › ère › repère › « Points du repère (N) » ; `store.js:459-472` `selectionTrail()` produit les quatre premières ; `shell.js:132-142,415-443` construit `.shell-trail` depuis `position()` et ajoute le libellé de vue.
- **Solution.** `selectionTrail().map(step => step.label)` fournit la référence ; E40 compare les mâches communes du fil local et du fil de la coque, sans exiger l'égalité des niveaux propres (points, libellé de vue). Le compte des mâches est affiché pour rendre le contrôle auditable.
- **Impact.** Le fil local ne peut pas désigner un pays, une ère ou un repère différent de la coque, même après un deep link.
- **Risque.** `Monde` est le seul niveau commun sans pays sélectionné : le contrôle se limite alors à cette première mâche, comportement conforme au store.
- **Effort.** M.
- **Vérification.** `local 5 · coque 5 · 4 niveaux conformes` (testé en application réelle).

## E40-06 — Lien local : le hash est la sérialisation canonique de l'état

- **Titre.** Le lien profond est la sérialisation de l'état (`store.js:550-564`) ; s'il annonce une autre vue, un autre pays ou d'autres index, un rechargement ne restaure pas la même situation.
- **Preuve.** `store.js:550-564` `formatDeepLink()` écrit `v`, `c`, `e`, `r`, `p`, `l`, `s` ; `:633-647` `reflectHash()` grave par `replaceState` ; `:649-661` `initDeepLinks()` hydrate. **`emit` (`:251`) précède `reflectHash` (`:252`)** : pendant le rendu déclenché par `set()`, le hash est donc encore celui de l'état précédent.
- **Solution.** `refresh()` analyse `window.location.hash` avec `URLSearchParams` (standard, zéro réseau) et vérifie `v === 'chronology'`, `c === countryId`, `e === eraIndex`, `r === eventIndex`. Un abonnement `hashchange` unique et la microtâche de E40-10 rafraîchissent après la réflexion. Aucune écriture dans l'URL.
- **Impact.** Le décalage temporel du hash devient visible puis corrigé sans timer ni boucle, et la cohérence du lien est vérifiable dans la vue où l'utilisateur arrive.
- **Risque.** `replaceState` n'émet pas `hashchange` ; la microtâche après `emit` assure la convergence (signalé et testé).
- **Effort.** M.
- **Vérification.** `v=chronology · c=france · e=0 · r=0 · conforme`. Forcer `#v=globe&c=espagne&e=3&r=9` → `à restaurer` (testé).

## E40-07 — Unicité des repères de situation, sans troisième région live

- **Titre.** Ajouter une région live dans la Chronologie provoquerait des annonces redondantes avec la coque et la région locale existante.
- **Preuve.** `shell.js:121-128` crée une région `role="status" aria-live="polite"` dans `<body>` ; `chronology.js:119-133` crée `#nav-c2a-live` (unique) hors de `#app` ; `:260-268` posent `#nav-c2a-trail` et `#nav-c2a-progress`.
- **Solution.** Le panneau dénombre ces trois repères, exige exactement un de chaque, et vérifie qu'il est lui-même un `role="group"` **sans** `aria-live`. Le contrôle est visible, jamais bavard.
- **Impact.** Unicité des aides à la situation à travers les vues, sans doublon d'annonce pour les lecteurs d'écran.
- **Risque.** L'ancien panneau détaché lors d'un re-render n'est plus dans le `document`, donc pas compté ; la garde d'ID garantit un seul panneau attaché.
- **Effort.** S.
- **Vérification.** `fil 1/1 · live 1/1 · progression 1/1 · E40 sans live · conforme`.

## E40-08 — Prédicat de cohérence unique du store

- **Titre.** Le store porte déjà neuf prédicats de cohérence et un `allCoherent` ; aucune vue ne les rend visibles.
- **Preuve.** `store.js:516-542` `getDiagnostics()` expose `noUnknownStateKeys`, `indicesBounded`, `modalsExclusive`, `playingCoherent`, `previousViewCoherent`, `historyBounded`, `selectionCoherent`, `boundsModesCoherent`, `deepLinkReady` et `allCoherent`.
- **Solution.** E40 affiche `9/9 prédicats · cohérent`, ou le nombre de réussites et la **clé** du premier prédicat en échec, dans un ordre déterministe. Aucun prédicat n'est recalculé ni réécrit : E40 ne fait que refléter le contrat du store.
- **Impact.** Une incohérence d'état (index hors bornes, modales simultanées, lecture en dehors du Récit, deep link non initialisé) devient visible depuis la Chronologie.
- **Risque.** `deepLinkReady` dépend de l'amorçage automatique (`store.js:664`) ; s'il est faux, E40 le signale au lieu de le masquer.
- **Effort.** S.
- **Vérification.** `9/9 prédicats · cohérent` (testé en application réelle).

## E40-09 — Bornes partagées entre store et routeur

- **Titre.** Les mêmes index pilotent la Chronologie, le Récit, la Géographie et la Matrice des points ; store et routeur doivent annoncer les mêmes modes, index et totaux.
- **Preuve.** `store.js:28-30` `INDEX_MODES` = `event/era/place : clamp`, `point : wrap` ; `:504-513` `getBounds()` ; `keyboard.js:240-245` `VECTEMPOREL_KEYS.navigationBounds()` ; `store.js:534-538` vérifie `boundsModesCoherent`.
- **Solution.** E40 compare les quatre bornes des deux sources et vérifie que les index du snapshot égalent ceux du store. L'affichage est abrégé (`evt`, `ère`, `pt`, `lieu`) pour tenir dans le panneau ; les valeurs sont lues, jamais calculées à nouveau.
- **Impact.** Une divergence de convention de bornage entre routeur et store — qui casserait la navigation fléchée dans les vues voisines — est détectable dans la Chronologie.
- **Risque.** Si le routeur n'est pas encore publié (`VECTEMPOREL_KEYS` est défini au chargement du module `keyboard.js:202`), le contrôle se limite aux bornes du store et reste vert : une inconnue n'est pas un défaut.
- **Effort.** S.
- **Vérification.** `evt clamp 0/57 · ère clamp 0/9 · pt wrap 0/4 · lieu clamp 0/1 · conformes`.

## E40-10 — Idempotence multi-rendus et garde-fous du greffon

- **Titre.** Le registre réapplique tous les greffons à chaque `emit()` (`registry.js:39-43`) et la coque reconstruit tout le DOM (`shell.js:533`) : une implémentation naïve empilerait panneaux et abonnements.
- **Preuve.** `registry.js:13-19` `cssOnce()` garde la feuille par id ; `:39-43` n'a jamais de purge ; `app.js:130` abonne `render` au store, donc chaque `set()` redessine la scène.
- **Solution.** `latest` est remplacé à chaque appel ; `buildPanel()` est protégé par `document.getElementById(PANEL_ID)` ; l'abonnement `hashchange` est installé une seule fois ; une seule microtâche par salve (`microQueued`) rafraîchit après `emit`/publication de `VATLAS`. Tous les rappels réinterrogent le DOM courant par ID, jamais un `ctx` périmé. Le panneau affiche le nombre d'applications, de panneaux, la présence du CSS et de l'abonnement. `window.VECTEMPOREL_E40` expose `chantiers()` et `state()` en lecture seule.
- **Impact.** Un seul contrôle stable quel que soit le nombre de reconstructions, y compris après un aller-retour Récit → Chronologie ; aucune fuite de nœuds, d'écouteurs ou d'observateurs.
- **Risque.** L'état d'application survit au changement de vue ; c'est un compteur de diagnostic, sans effet sur le rendu ni sur les données.
- **Effort.** M.
- **Vérification.** Après cinq applications forcées : `panneaux 1`, `CSS 1`, `abonnement 1`, `stable`. Après navigation Récit → Chronologie en application réelle : `appliqué 2× · panneaux 1` ; `node --check` OK ; zéro `console.*`.

## Arbitrage maître attendu

Le module livré est `src/views/chronology/E40.js` (identifiant `E40`), conformément au mandat.
Or `src/views/chronology/index.js:40` importe encore le stub zero-padé `E040.js`, qui enregistre
`E040`. Tant que le maître n'a pas ajouté `import './E40.js'` (ou fusionné les deux noms), la
lentille n'est pas exécutée par le rendu réel. Le test d'intégration ci-dessous l'a donc importée
dynamiquement avant de provoquer un rendu. Aucun fichier partagé n'a été modifié pour contourner
ce point.
