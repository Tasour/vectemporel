# E16 — Gestion d'erreurs

> Hub : `UNIFIED_AUDIT/CHRONOLOGIE/` · Lentille E016 · 10 chantiers, 10 implémentés.
> Fichier possédé : `src/views/chronology/E016.js`.
> Vérification : `node --check src/views/chronology/E016.js`.

## Périmètre observé

`renderChronology(stage)` (`src/views/chronology.js`) construit quatre zones — bande de statut,
orientation C2, bandes d'ères, liste de repères et fiche latérale — puis appelle
`runEnhancements({ viewId: 'chronology', stage, layout })` en toute fin de fonction
(`chronology.js:539`). La coque reconstruisant le `stage` à chaque rendu, la lentille E016
travaille **après** la vue, sur un DOM déjà assemblé : elle ne modifie ni `chronology.js`, ni le
dataset, ni l'état partagé.

Le registre `src/views/chronology/registry.js` fournit `css(id, rules)`, `el(tag, cls, text)`
et `reducedMotion()` via `ctx`, neutralise les greffons fautifs dans un `try/catch` et conserve
leurs messages dans `viewDiagnostics()`. Le module `_diagnostics.js` masque par défaut tout
élément dont l'identifiant suit `/.*-e\d\d/` : les nœuds créés ici portent donc un attribut
`data-e16` et des identifiants sans `-e16`, afin de rester visibles et annonçables.

Les cas d'erreur réellement atteignables dans la vue sont : image locale absente
(`chronology.js:397, 434`), `formatYear()` qui recopie `String(year)` et peut afficher `NaN`,
`undefined` ou `Infinity` (`chronology.js:26`), source introuvable retombée sur son identifiant brut
(`chronology.js:493`), confiance non validée (`chronology.js:484`), références ARIA posées sur
des cibles supprimables (`chronology.js:291, 318, 335, 389, 511, 512`), et intention de focus
dont la cible a disparu (`chronology.js:199-205`).

## Les 10 chantiers

### E16-01 — Filet anti-rendu vide
- **Preuve** : `chronology.js:209` sort tôt si aucun pays n'est sélectionné ; une passe ultérieure peut aussi laisser un `stage` sans `#atlas-chrono-main`.
- **Solution** : si `ctx.layout` n'est plus dans le `stage` ou si `#atlas-chrono-main` est absent, injecter un bloc `role="note"` « Affichage indisponible » en texte français, avec renvoi vers les autres vues.
- **Impact** : aucun écran blanc silencieux ; l'information reste consultable ailleurs.
- **Risque** : faible — garde d'existence, aucune donnée inventée.
- **Effort** : faible.
- **Vérification** : `node --check`.

### E16-02 — Images en échec repliées en texte
- **Preuve** : `chronology.js:397` et `:434` posent `img.src = item.image.src` sans écoute d'erreur ; les chemins sont locaux (`public/images/...`) et peuvent manquer.
- **Solution** : écoute `error` (once) sur chaque `<img>` du stage, contrôle immédiat `complete && naturalWidth === 0`, puis remplacement par « Illustration indisponible : <alt> » ; aucun nouveau `src` n'est assigné.
- **Impact** : l'alt devient un texte lisible, sans image cassée ni tentative réseau.
- **Risque** : nul — garde anti-double-remplacement par `data-e16="image"`.
- **Effort** : moyen.
- **Vérification** : `node --check`.

### E16-03 — Années invalides explicites
- **Preuve** : `formatYear(year)` (`chronology.js:26`) renvoie `String(year)` pour toute valeur non négative : `NaN`, `undefined` et `Infinity` sont affichés tels quels dans `.event-year`, `.atlas-chrono-era-range` et `.aside-year`.
- **Solution** : détecter ces trois jetons ou un texte vide ; substituer « Année non renseignée » / « Période non renseignée », en préservant le sous-titre de `.aside-year`.
- **Impact** : aucune valeur technique fuite dans le récit ;  la plage d'ère reste lisible.
- **Risque** : nul — seules les valeurs invalides sont remplacées.
- **Effort** : faible.
- **Vérification** : `node --check`.

### E16-04 — Sources non résolues signalées
- **Preuve** : `chronology.js:493` écrit `label = source && source.title ? … : sourceId` lorsqu'aucune source du pays ne correspond.
- **Solution** : pour chaque `li[data-source-id]` dont le texte vaut exactement l'identifiant brut, ajouter « — source non référencée » en texte italique.
- **Impact** : la provenance manquante est visible, sans inventer de titre bibliographique.
- **Risque** : nul — aucune mention n'est supprimée.
- **Effort** : faible.
- **Vérification** : `node --check`.

### E16-05 — Confiance hors vocabulaire signalée
- **Preuve** : `chronology.js:484` recopie `point.confiance` sans validation ; le dataset contient six valeurs (`certain`, `probable`, `vérifié`, `disputé`, `disputed`, `non documenté`).
- **Solution** : toute valeur absente de ce jeu, ou vide, reçoit un complément « (valeur non reconnue) » / « non renseignée » et un `title`, en texte et non par la couleur seule.
- **Impact** : un niveau de confiance inattendu ne passe pas pour une donnée validée.
- **Risque** : faible — vocabulaire relevé dans `src/data/dataset.js`, aucune traduction forcée.
- **Effort** : faible.
- **Vérification** : `node --check`.

### E16-06 — Références ARIA orphelines retirées
- **Preuve** : `aria-controls` est posé aux lignes 291, 318, 335, 389, 511 et 512 ; `aria-labelledby` aux lignes 214 et 420. Une cible supprimée par une autre passe rend l'annonce morte.
- **Solution** : pour `aria-controls`, `aria-labelledby` et `aria-describedby`, filtrer les identifiants absents du document ; ne toucher qu'aux préfixes créés par `chronology.js`, afin de ne pas casser une cible introduite par une lentille postérieure.
- **Impact** : les lecteurs d'écran ne suivent plus de référence inexistante.
- **Risque** : faible — filtrage par préfixe et repli `null` si le stage est détaché.
- **Effort** : moyen.
- **Vérification** : `node --check`.

### E16-07 — Identifiants dupliqués rendus uniques
- **Preuve** : la coque et les greffons peuvent réinjecter un nœud déjà pourvu d'un `id` (`tag-btn-*`, `aside-tag-*`, `point-*`), ce qui casse `getElementById` et les `aria-*`.
- **Solution** : relevé des `id` du stage, suffixe déterministe `-secours-2`, `-secours-3`… tant que l'identifiant existe, avec marqueur `data-e16="id"`.
- **Impact** : contrat « IDs uniques » respecté même après plusieurs passes.
- **Risque** : nul — aucun aléa, aucune modification des références existantes (celles-ci pointent sur le premier nœud, valide).
- **Effort** : faible.
- **Vérification** : `node --check`.

### E16-08 — État vide du filtre explicité
- **Preuve** : `chronology.js:359` crée `#nav-c2a-empty-filter` avec un texte ; un greffon peut vider le nœud ou poser `aria-hidden`.
- **Solution** : si le texte est vide, rétablir « Aucun repère ne correspond au filtre. Modifiez la recherche ou réinitialisez le filtre. » ; retirer `aria-hidden` si présent ; ne jamais déplacer le focus.
- **Impact** : l'absence de résultat reste compréhensible et annonçable.
- **Risque** : nul — le texte d'origine est préservé s'il est intact.
- **Effort** : faible.
- **Vérification** : `node --check`.

### E16-09 — Cible de focus de secours
- **Preuve** : `applyFocusIntent()` (`chronology.js:199-205`) échoue silencieusement si `document.getElementById(id)` ne trouve plus le contrôle visé.
- **Solution** : garantir un élément `[data-fk]`, sinon le h1 `#atlas-chrono-title`, avec `tabindex="-1"` ; le focus n'est pas déplacé par la lentille.
- **Impact** : une cible d'atterrissage existe toujours pour la navigation clavier.
- **Risque** : nul — aucun vol de focus, aucune modification de `focusIntent`.
- **Effort** : faible.
- **Vérification** : `node --check`.

### E16-10 — Mode dégradé des greffons
- **Preuve** : `registry.js` neutralise les greffons fautifs et conserve `{ id, message }` dans `viewDiagnostics()` ; les lentilles E001…E015 sont appliquées avant E016.
- **Solution** : filtrer les échecs sur les identifiants présents avant `E016` dans l'ordre du registre, puis afficher un seul bloc `role="note"` « Affichage dégradé » : « Certains modules d'aide à la lecture ne sont pas disponibles (N). Les données vérifiées de la chronologie restent consultables. »
- **Impact** : la dégradation est annoncée en français, sans détail technique ni trace dans la console.
- **Risque** : faible — garde anti-doublon par `#chronology-guard-degraded`, aucun compte d'erreur future.
- **Effort** : moyen.
- **Vérification** : `node --check`.

## Bilan

- 10 / 10 chantiers implémentés dans `src/views/chronology/E016.js` ; aucun autre fichier modifié.
- Un seul `register('E016', ctx => …)` ; CSS unique `ctx.css('chronology-e16', …)` ; identifiants `chronology-guard-live`, `chronology-guard-degraded` et `chronology-guard-empty` uniques par rendu ; doublons résorbés par E16-07.
- Zéro appel à la console, zéro requête réseau, zéro `Math.random`, zéro modification de `chronology.js` ou du dataset ; français partout.
- `node --check src/views/chronology/E016.js` : OK.
