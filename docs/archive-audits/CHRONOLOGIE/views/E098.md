## E098-01 — Bloc CSS unique injecté par `ctx.css`

- **Problème / preuve** : `src/views/chronology.js:32-33` injecte son propre bloc de style dans le `stage` sous garde `document.getElementById(STYLE_ID)`, mais ce bloc s'arrête à une seule requête média (`src/views/chronology.js:83`, `@media (max-width:620px)`). `src/views/chronology/registry.js:13-19` fournit `cssOnce(uniqueId, rules)`, qui injecte dans `<head>` avec sa propre garde par identifiant. Aucun mécanisme n'existe pour l'adaptation aux grands écrans, et éditer `styles.css` est interdit à la lentille.
- **Solution** : un seul appel `ctx.css('chronology-e098', CSS)` dans `install()`. Les sélecteurs d'adaptation portent deux classes (`.e098-viewport-*`, `.e098-density-*`), donc une spécificité supérieure à `.chronology-layout` (`styles.css:194`), `.event-list` (`styles.css:205`) et à la feuille du `stage` (`src/views/chronology.js:36-91`) : aucune règle existante n'est écrasée à spécificité égale.
- **Impact** : le style de la lentille survit au `innerHTML` de la coque sans modifier un fichier partagé ; un seul `<style id="chronology-e098">` existe, même après dix rendus.
- **Risque** : la feuille du `stage` est insérée plus tard dans le document. Le risque d'écrasement est écarté par la spécificité à deux classes ; les media queries `min-width` n'existaient nulle part dans la vue, donc aucune collision de cascade.
- **Effort** : S.
- **Vérification** : `grep -c "ctx.css(" src/views/chronology/E098.js` = 1 ; un seul `<style id="chronology-e098">` dans `<head>` après trois changements d'ère ; `node --check src/views/chronology/E098.js` sans erreur.

## E098-02 — Détection du viewport par `matchMedia`, écouteurs uniques

- **Problème / preuve** : `src/views/chronology.js:83` est une règle CSS et non une détection JavaScript ; le fichier ne contient aucun `matchMedia`, `innerWidth` ni `ResizeObserver`. `src/views/chronology.js:539` appelle `runEnhancements({ viewId:'chronology', stage, layout })` à **chaque** rendu, et `src/views/chronology/registry.js:39-42` rejoue toutes les lentilles. Un écouteur installé dans `install()` sans garde se dupliquerait à chaque rendu.
- **Solution** : quatre requêtes `(min-width: 620px)`, `(min-width: 1000px)`, `(min-width: 1600px)`, `(min-width: 2200px)`, alignées sur les ruptures réelles de `styles.css:316` et `styles.css:333`. Un unique `onViewportChange` module-level est attaché sous garde `listenersInstalled` ; repli sur un seul écouteur `resize` si `window.matchMedia` est absent.
- **Impact** : la classe de viewport est connue côté JavaScript, sans sonde permanente ni boucle d'animation, et reste exacte après reconstruction du DOM.
- **Risque** : quatre requêtes déclenchent quatre appels au même handler lors d'un franchissement simultané de seuils ; `apply()` est idempotent (classes retirées puis reposées, attributs réécrits), donc l'état final est identique. Aucun `setTimeout` de debounce n'est introduit, conformément à l'interdiction de timer.
- **Effort** : M.
- **Vérification** : `grep -nE 'requestAnimationFrame|setInterval|setTimeout' src/views/chronology/E098.js` → 0 ligne ; `listenersInstalled` empêche tout second `addEventListener('change')` après dix rendus ; redimensionner de 1 500 à 2 300 px fait passer `data-e098-viewport` de `large` à `ultra-large`.

## E098-03 — Mesure de densité réelle depuis la grille rendue

- **Problème / preuve** : `styles.css:205` pose `.event-list { grid-template-columns: repeat(auto-fill, minmax(190px,1fr)); gap: 9px; }` : le nombre de colonnes est calculé par le navigateur et n'est exposé nulle part. `src/views/chronology.js:348-414` construit la liste des repères sans compteur de colonnes ; la densité réelle est donc invisible pour un audit.
- **Solution** : `measureGrid(list)` relève `list.querySelectorAll('.event-card').length` et le nombre de pistes de `window.getComputedStyle(list).gridTemplateColumns`, dans un `try/catch`. Les valeurs sont publiées dans `data-e098-cards` et `data-e098-columns` sur le layout, et reprises dans le readout.
- **Impact** : la densité est une mesure dérivée du DOM réel, pas une estimation : elle reflète le filtre courant (`src/views/chronology.js:178-188`) et la largeur effective de la colonne principale.
- **Risque** : `getComputedStyle` peut lever une exception sur un nœud déconnecté ou renvoyer `none` ; le `catch` et le garde `Number.isFinite` ramènent alors `columns` à 0, et le readout affiche « ? » plutôt qu'un chiffre trompeur. Aucune info n'est portée par la seule couleur.
- **Effort** : S.
- **Vérification** : en 1 658×1 150, `data-e098-cards` = nombre de `.event-card` et `data-e098-columns` = nombre de valeurs de `gridTemplateColumns` ; après filtrage, les deux attributs diminuent ensemble.

## E098-04 — Classes de viewport normalisées sur les ruptures existantes

- **Problème / preuve** : trois seuils coexistent sans vocabulaire commun — `styles.css:316` bascule la grille à 1 000 px, `styles.css:333-339` passe la liste en une colonne à 620 px, et `src/views/chronology.js:83` applique la même rupture de 620 px aux outils. `src/views/chronology.js:214-216` ne pose que `data-country-id` et `data-view` sur le layout.
- **Solution** : cinq classes `e098-viewport-{compact,etroit,large,tres-large,ultra-large}` et l'attribut `data-e098-viewport`, avec des libellés français explicites portant les bornes en pixels (`compact`, `étroit (620 à 999 px)`, `large (1 000 à 1 599 px)`, `très large`, `ultra-large (2 200 px et plus)`).
- **Impact** : un état de forme unique, lisible par un test E2E et annoncé en toutes lettres, aligné sur les media queries déjà présentes plutôt que sur des seuils arbitraires.
- **Risque** : un seuil CSS modifié ultérieurement dans `styles.css` désynchroniserait les libellés ; les constantes `THRESHOLDS` et `VIEWPORT_LABELS` sont regroupées en tête de module pour rendre cette dépendance explicite et localisée.
- **Effort** : S.
- **Vérification** : aux largeurs 390, 800, 1 400, 1 800 et 2 400 px, `data-e098-viewport` vaut respectivement `compact`, `etroit`, `large`, `tres-large`, `ultra-large` ; une seule classe `e098-viewport-*` est présente à la fois.

## E098-05 — Adaptation aux écrans 1 600 px et 2 200 px et plus

- **Problème / preuve** : `styles.css:194` fixe l'aside à `380px` quelle que soit la largeur, `styles.css:195` pose un padding fixe `26px 28px 34px`, et `styles.css:205` utilise `minmax(190px,1fr)`. À 2 560 px, la colonne principale mesure environ 2 180 px, soit près de dix colonnes de cartes d'environ 200 px : la mesure de lecture s'effondre. Aucune règle `@media (min-width:…)` n'existe pour la chronologie, ni dans `styles.css`, ni dans `src/views/chronology.js:83-91`.
- **Solution** : `@media (min-width:1600px)` élargit l'aside en `clamp(380px,26vw,480px)`, porte le padding à `32px 40px 44px`, passe la grille à `minmax(240px,1fr)` plafonnée à `1680px` et borne les bandes d'ère à `flex:0 1 170px` (contre `flex:1 1 116px` en `src/views/chronology.js:42`). `@media (min-width:2200px)` affine en `clamp(380px,20vw,520px)`, `minmax(270px,1fr)` et `max-width:1800px`.
- **Impact** : le nombre de colonnes plafonne au lieu de croître sans limite, les cartes gardent une largeur lisible et la fiche du repère gagne de la place sans jamais dépasser 520 px.
- **Risque** : un `clamp` trop généreux rognerait la colonne principale sur un écran 1 600 px ; la borne basse reste 380 px, donc le gain ne s'applique qu'au-delà du seuil et la grille `minmax(0,1fr)` de `styles.css:194` conserve le reste. `contain:paint` n'est pas utilisé, afin de ne pas rogner les ombres des cartes.
- **Effort** : M.
- **Vérification** : relecture visuelle en 1 658×1 150 et 2 560×1 440 ; `data-e098-columns` plafonne et `data-e098-cards` reste inchangé ; aucune règle de `styles.css` modifiée (`git diff --name-only` ne liste que les deux fichiers possédés).

## E098-06 — Readout accessible `role="status"`

- **Problème / preuve** : `src/views/chronology.js:244-256` crée une bande de statut **visible sans** `role="status"` : le commentaire précise que les annonces passent par `#nav-c2a-live` et la navigation par la région de `shell.js:73`. Aucun texte n'annonce la classe de viewport, le nombre de colonnes ni la densité choisie.
- **Solution** : un paragraphe `#e098-readout` en `role="status" aria-live="polite" aria-atomic="true"`, textuellement : « Détection du viewport : … . Densité … . N repère(s) affiché(s) sur M colonne(s). Mouvement réduit … ». Le noeud est déplacé juste après `#atlas-chrono-tools` (`src/views/chronology.js:310-345`).
- **Impact** : équivalence fonctionnelle pour les lecteurs d'écran, annonce unique et non bavarde, information chiffrée lisible en toutes lettres et non portée par la seule couleur.
- **Risque** : la région `aria-live` partagée pourrait bavarder si le readout était écrit à chaque frame ; `apply()` n'est appelé que sur rendu, transition de rupture et clic sur le bouton de densité — jamais en boucle. Aucun `fetch` n'introduit de contenu différé.
- **Effort** : M.
- **Vérification** : un seul `#e098-readout` dans le DOM ; après clic sur « Densité », le texte change et est annoncé une fois ; le texte est lisible en 390×844 sans débordement horizontal.

## E098-07 — Bouton de densité : action, ni `aria-pressed` ni radiogroupe

- **Problème / preuve** : `src/views/chronology.js:330-343` utilise `aria-pressed` pour des étiquettes indépendantes et `src/views/chronology.js:284-290` utilise `aria-current` pour le choix unique d'une ère. Le cycle « confort → compacte → dense » n'est ni une bascule indépendante ni une sélection parmi des options simultanément visibles : aucun des deux attributs ne s'applique.
- **Solution** : un `<button type="button">` unique `#e098-density-btn` dont le libellé visible porte l'état courant et l'action (« Densité : confort — cliquer pour changer »), complété par un `aria-label` français. Un seul écouteur `click`, lié sous garde `button.dataset.e098Bound` ; `onCycle()` fait tourner `MODES` et rappelle `apply()`.
- **Impact** : l'utilisateur peut fixer manuellement la densité indépendamment de la largeur, avec un contrôle de 36 px minimum, un focus visible et un équivalent clavier natif (Entrée/Espace).
- **Risque** : le mode est conservé dans une variable module-level et resynchronisé dans les classes à chaque rendu ; un rendu intervenant après un clic ne réinitialise donc pas le choix. Le bouton n'intercepte pas les flèches, laissées à la navigation de la vue.
- **Effort** : S.
- **Vérification** : trois clics successifs font passer `data-e098-density` de `confort` à `compacte`, `dense`, puis `confort` ; `aria-pressed` est absent du bouton ; après changement d'ère, `data-e098-density` conserve la dernière valeur.

## E098-08 — Mouvement réduit relu et exposé

- **Problème / preuve** : `src/views/chronology.js:89-91` neutralise les transitions des bandes, cartes et étiquettes sous `prefers-reduced-motion:reduce`, et `src/views/chronology/registry.js:33-37` expose `ctx.reducedMotion()`. Aucun greffon ne relit cette préférence pour l'adaptation de densité, et aucun état n'est auditable dans le DOM.
- **Solution** : `prefersReduced = ctx.reducedMotion || prefersReduced` puis appel à chaque `apply()` ; `data-e098-reduced` vaut `1` ou `0` ; un unique écouteur `change` sur `matchMedia('(prefers-reduced-motion: reduce)')` déclenche `onViewportChange()` ; la règle `@media (prefers-reduced-motion:reduce)` neutralise la transition du bouton.
- **Impact** : la préférence est à la fois annoncée dans le readout, exposée dans le DOM et appliquée au style, avec un seul point de lecture.
- **Risque** : un écouteur dupliqué à chaque rendu est évité par la garde `listenersInstalled` ; repli local `() => false` si `ctx.reducedMotion` est absent, sans jamais remplacer la fonction fournie par le registre.
- **Effort** : S.
- **Vérification** : avec mouvement réduit émulé, `data-e098-reduced="1"` et le readout porte « mouvement réduit actif » ; `transition-duration` calculée du bouton à `0s` ; un seul écouteur `change` enregistré.

## E098-09 — Re-render safe : IDs uniques et gardes d'existence

- **Problème / preuve** : `src/views/chronology.js:214-223` recrée `layout`, `main` et `aside` à chaque rendu, `src/views/chronology.js:210` appelle `injectStyle(stage)` dont la garde ne protège que le style, et `src/views/chronology.js:539` rejoue les greffons. `src/views/chronology/registry.js:25-31` ne garantit ni les noeuds ni les écouteurs.
- **Solution** : helper `ensureNode(id, tag, cls)` qui réutilise un noeud existant, le déplace dans le parent courant et réécrit sa classe ; IDs tous préfixés `e098` (`e098-hint`, `e098-density-btn`, `e098-readout`) ; garde `button.dataset.e098Bound` ; classes `e098-viewport-*` et `e098-density-*` retirées puis reposées à chaque `apply()` ; un seul `register('E098', install)`.
- **Impact** : aucun ID dupliqué, aucun noeud orphelin, aucun vol de focus ni de raccourci clavier sur une longue session avec changements d'ère et de pays.
- **Risque** : le `stage` et le `layout` courants deviennent déconnectés entre deux rendus ; les attributs `isConnected` sont vérifiés avant toute écriture et `currentLayout` est remplacé à chaque `install()`. Le registre neutralise silencieusement une lentille défaillante (`registry.js:39-42`) : la garde d'existence reste la première ligne de défense.
- **Effort** : M.
- **Vérification** : vingt cycles « pays → ère → pays » → un seul de chaque ID `e098-*`, un seul `<style id="chronology-e098">` ; `viewDiagnostics()` liste une seule entrée `E098` sans diagnostic d'erreur.

## E098-10 — Replis, robustesse et validation syntaxique

- **Problème / preuve** : `src/views/chronology/registry.js:28-44` construit le contexte par étalement et peut appeler la lentille avec un `ctx` partiel ; `ctx.layout` peut être absent ou déconnecté, `window.matchMedia` peut manquer, et `getComputedStyle` peut lever. Une lentille qui lèverait une exception serait neutralisée sans bruit (`registry.js:41`), rendant le défaut invisible.
- **Solution** : repli `document.querySelector('.chronology-layout')` puis retour silencieux si aucun layout ; recherche de `#atlas-chrono-main` par identifiant ; `detectClass()` bascule sur `window.innerWidth` sans `matchMedia` ; `viewportWidth()` filtre les valeurs non finies ; `try/catch` autour de `getComputedStyle` ; gardes `isConnected` sur `layout` et `liste` ; filtre `ctx.viewId` ; aucun appel réseau, aucun aléa, aucune journalisation.
- **Impact** : la lentille reste fonctionnelle dans un contexte dégradé et ne peut jamais faire échouer le rendu de base, même si son propre état est incomplet.
- **Risque** : le repli `resize` sans `matchMedia` réécrit le readout plus souvent que les requêtes média ; `apply()` reste peu coûteux (une mesure de grille) et idempotent, et aucun timer n'est ajouté pour le limiter.
- **Effort** : S.
- **Vérification** : `node --check src/views/chronology/E098.js` → aucun message ; `grep -nE 'console\.|fetch\(|XMLHttpRequest|Math\.random|requestAnimationFrame|setInterval|setTimeout'` → 0 ligne ; avec `matchMedia` simulé absent, les cinq largeurs de E098-04 donnent toujours les cinq classes attendues.

## Blocages

- Aucun bloquant fonctionnel.
- E098 ne peut pas modifier `styles.css` ni le style injecté par `src/views/chronology.js:36-91` : les media queries `min-width` sont donc portées par la feuille de la lentille, avec une spécificité à deux classes. Un futur arbitrage maître pourrait les remonter dans `styles.css:194-205` ; la lentille continuerait à fonctionner sans changement.
- E098 ne peut pas forcer la coque à conserver le focus sur `#e098-density-btn` lors d'un rendu store déclenché ailleurs : la restauration de focus appartient à `applyFocusIntent()` (`src/views/chronology.js:199-205`, appelée en `:540`). Le bouton n'est pas une cible de `focusIntent`, ce qui est le comportement correct : un rendu externe rend la main à la navigation de la vue, pas au contrôle de densité.
- Le nombre de colonnes est relevé après le rendu via `getComputedStyle` : il reflète la grille calculée, pas une prédiction. Une mesure avant layout renverrait `0`, valeur explicitement tolérée et affichée comme « ? » dans le readout.
