## E086-01 — Barre de filtres ancrée sans toucher à `chronology.js`

- **Problème / preuve** : la vue possédée construit sa liste dans `src/views/chronology.js:348-349` (`const list = el('ol', 'event-list atlas-chrono-events'); list.id = 'atlas-chrono-events';`) puis appelle les greffons en `:539` (`runEnhancements({ viewId: 'chronology', stage, layout });`). Le registre ne fournit que `{ viewId, stage, layout, css(id, rules), el(tag, cls, text), reducedMotion() }` (`registry.js:28-37`) : aucun point d'extension dédié n'existe dans la vue, et le fichier est en lecture seule pour cette lentille.
- **Solution** : `ensureBar(main, list, el, categories, onChange)` crée une `<section id="e086-bar" role="group" aria-label="Filtres E086 — type d'événement et catégories multiples">` et l'insère juste avant la liste avec `list.parentNode.insertBefore(bar, list)`. Le CSS est injecté une seule fois via `ctx.css('chronology-e086', …)` et toute règle est préfixée `.chronology-e086`. Le conteneur `.chronology-layout` reçoit la classe de portée et `data-e086="1"`.
- **Impact** : la barre apparaît entre les outils de base (`:310-345`) et la liste, sans déplacer ni réécrire un seul nœud de la vue d'origine.
- **Risque** : une insertion avant `:348` écraserait la barre d'outils de base ; l'ancrage sur `list` et non sur `tools` évite tout chevauchement. Si la liste est absente (pays sans ère), la barre est ajoutée en fin de `main` plutôt que de provoquer une erreur.
- **Effort** : S.
- **Vérification** : un seul `#e086-bar` dans le DOM après 20 re-renders ; zéro modification de `chronology.js` (`git diff` vide pour ce fichier) ; `node --check src/views/chronology/E086.js` passe.

## E086-02 — Catégories multiples (au lieu d'un thème unique)

- **Problème / preuve** : l'état local de la vue ne retient qu'un seul thème : `const local = { query: '', tag: null };` (`chronology.js:16`). Les puces de thèmes (`:328-343`) posent `aria-pressed` sur `local.tag === tag` et le clic fait `local.tag = local.tag === tag ? null : tag;` (`:337`) : sélectionner un nouveau thème désélectionne le précédent. Les thèmes réels ne sont pourtant pas rares : `allTags` est calculé sur `country.events.flatMap(item => item.tags || [])` (`:328`) et chaque carte porte `li.dataset.tags = item.tags.join(' ')` (`:383`).
- **Solution** : la lentille lit ses catégories directement sur `data-tags` des cartes présentes (`gatherCategories()`), les trie avec `localeCompare('fr')`, et crée une puce `<button aria-pressed>` par catégorie plus une puce « Toutes les catégories ». L'état est un `Set` de module (`selectedCats`) : cliquer une puce ajoute ou retire la catégorie sans toucher aux autres.
- **Impact** : l'utilisateur peut croiser plusieurs thèmes (ex. « économie » + « guerre ») là où la vue de base n'en autorisait qu'un, sans modifier le store partagé.
- **Risque** : la vue de base continuant d'appliquer son propre `local.tag` (`:333-341`), les deux filtres se cumulent ; c'est un comportement additif assumé et documenté. Les thèmes d'un pays different : `selectedCats` est élagué à chaque rendu des catégories introuvables (voir E086-08).
- **Effort** : M.
- **Vérification** : sélectionner deux puces → `layout.dataset.e086Cats` contient les deux valeurs séparées par un espace ; recliquer la première ne désélectionne pas la seconde ; la puce « Toutes » remet `selectedCats` à vide.

## E086-03 — Type d'événement en choix unique (radiogroup)

- **Problème / preuve** : les attributs posés sur chaque carte sont `eventId`, `year`, `eraId`, `importance` et `tags` (`chronology.js:379-383`) ; aucun champ explicite nommé « type » n'existe. L'importance (poids 1/2/3, `:382`) est le seul attribut discret exploitable, mais la vue ne l'utilise que comme donnée stockée : elle ne propose aucun contrôle pour filtrer dessus.
- **Solution** : un `radiogroup` (`:role="radiogroup"`, `aria-label="Type d'événement"`) regroupe quatre radios natifs `name="e086-type"` de valeurs `all`, `3`, `2`, `1`, libellés « Tous les types », « Majeur (3) », « Notable (2) », « Mineur (1) ». Le prédicat `passes()` compare `li.dataset.importance` à `selectedType`. L'absence de champ « type » est documentée dans le module et ici : l'importance sert de **proxy explicite**, aucune donnée n'est inventée.
- **Impact** : une dimension de filtrage supplémentaire, indépendante des thèmes, apparaît sans nouvelle donnée.
- **Risque** : les radios natifs groupés par `name` assurent la navigation fléchée ; le style `.e086-chip input` est rendu invisible mais reste focusable (pas de `display:none`), avec `focus-within` pour le contour. Le libellé « Majeur/Notable/Mineur » est une lecture du poids, pas une qualification historique.
- **Effort** : M.
- **Vérification** : cocher « Majeur (3) » → seules les cartes `data-importance="3"` restent visibles (`data-e086-hidden="0"`) ; `layout.dataset.e086Type === '3'` ; les flèches du clavier déplacent la sélection dans le radiogroup.

## E086-04 — Combinaison OU / ET entre catégories

- **Problème / preuve** : le filtrage de base combine recherche et thème en union simple (`filterEvents`, `chronology.js:178-188` : `if (local.tag && !(item.tags || []).includes(local.tag)) return false;`), sans notion de mode. Avec plusieurs catégories, le comportement attendu devient ambigu : « au moins une » ou « toutes » ?
- **Solution** : une bascule indépendante `#e086-mode` « Mode ET (intersection) » porte `aria-pressed` (`true` = ET actif). `passes()` applique `wanted.some(tags.includes)` en mode union (OU, valeur par défaut) et `wanted.every(tags.includes)` en mode intersection (ET), puis exige que la dimension type soit aussi satisfaite. Le bouton `#e086-reset` rétablit type `all`, catégories vides, mode OU.
- **Impact** : l'utilisateur choisit explicitement la sémantique de ses catégories multiples, avec un libellé et un `title` qui expliquent le mode courant.
- **Risque** : `aria-pressed` est ici légitime (commande indépendante) alors que le type utilise un radiogroup (choix unique) — les deux modèles ne sont pas mélangés. En mode ET avec des catégories incompatibles, le résultat peut être vide : c'est l'état E086-07 qui le prend en charge.
- **Effort** : S.
- **Vérification** : deux catégories choisies, bascule OFF → `layout.dataset.e086Mode === 'ou'` et le readout annonce « OU (union) » ; bascule ON → `'et'` et « ET (intersection) » ; « Réinitialiser » restaure `all` / vide / `ou`.

## E086-05 — Filtrage réel des cartes du DOM

- **Problème / preuve** : la liste est reconstruite à chaque rendu par `matched.forEach((item) => { … const li = el('li'); … list.appendChild(li); })` (`chronology.js:374-413`). Un greffon ne peut pas modifier `matched` (calculé en `:242` à partir du store) sans écrire dans des fichiers interdits.
- **Solution** : `apply()` parcourt `Array.from(list.children).filter(li => li.dataset.eventId)` (les seules cartes d'événement, à l'exclusion du `<li>` d'état vide de `:353-374`), pose `li.hidden = !ok` et `li.dataset.e086Hidden = ok ? '0' : '1'`, et compte `matched`/`total`. Une règle dédiée `.chronology-e086 .atlas-chrono-events>li[hidden]{display:none!important}` neutralise le `display:flex` de `styles.css` (`:60`) qui, sans cela, écraserait le `hidden` de l'agent utilisateur.
- **Impact** : le filtrage est effectif immédiatement, sans re-render, sans appel à `set()` et sans modification du store partagé.
- **Risque** : les cartes masquées restent dans le DOM (accessibles aux scripts, retirées de l'arbre d'accessibilité via `hidden`) : les catégories sont donc toujours collectables (E086-02). Le filtre s'applique en plus de tout filtre de base déjà actif, jamais à sa place.
- **Effort** : M.
- **Vérification** : après choix d'un type, le nombre de `li[data-e086-hidden="0"]` égale `layout.dataset.e086Matched` ; les cartes masquées ont `hidden` à `true` ; aucun texte d'origine n'est modifié.

## E086-06 — Readout chiffré annonçable (`role=status`)

- **Problème / preuve** : la bande de statut de la vue (`chronology.js:247-256`) décrit l'ère et le rang global mais ignore toute dimension de filtrage issue d'une lentille ; les annonces de la vue passent par `#nav-c2a-live` via `announceFilter()`/``navSay()`` (`:190-195`). Une lentille qui masquerait des cartes sans le dire rendrait le compte invisible pour un lecteur d'écran.
- **Solution** : `#e086-readout` est un `<p role="status" aria-live="polite" aria-atomic="true">` visible, texte réel : « N / T repères affichés · Type : … · Catégories : … · Mode : … ». Il est mis à jour à chaque `apply()`. Le readout n'est **pas** doublé dans la région live de la vue (`:12`, `:119-138`) : celle-ci appartient à la navigation C2, la lentille reste autonome.
- **Impact** : mesure chiffrée, lisible et annonçable ; aucune information n'est portée par la seule couleur (libellés textuels + chiffres).
- **Risque** : une `aria-live` mise à jour à chaque rendu pourrait bavarder ; les clics de la lentille ne déclenchant pas de rendu de la coque, l'annonce ne se produit que sur action explicite. Le texte est identique sur un rendu sans interaction, donc sans annonce parasite.
- **Effort** : S.
- **Vérification** : basculer le mode → `#e086-readout` contient « ET (intersection) » et l'annonce est entendue ; le texte contient toujours « / » et le nombre total ; `role="status"` et `aria-live="polite"` présents dans le DOM.

## E086-07 — État vide distinct du filtre de base

- **Problème / preuve** : la vue possède déjà deux états vides — filtre (`#nav-c2a-empty-filter`) et ère vide (`#nav-c2a-empty-era`) — construits en `chronology.js:353-374`, avec un bouton « Réinitialiser le filtre » qui ne remet que `local.query` et `local.tag` (`:364-368`). Aucun n'est déclenché par un filtre de lentille.
- **Solution** : `#e086-empty` est un `<p class="e086-empty" hidden>` ajouté dans la barre ; `apply()` l'affiche uniquement quand `total > 0 && matched === 0`, avec le texte « Aucun repère ne correspond à cette combinaison de type et de catégories. » Sa remise à zéro passe par `#e086-reset`, qui réinitialise aussi le type et le mode (contrairement au bouton de base).
- **Impact** : l'utilisateur comprend que le vide vient de la combinaison E086 et dispose d'une sortie explicite, sans confondre avec un pays sans ère.
- **Risque** : si la vue de base affiche déjà son propre état vide (aucune carte dans le DOM), `total === 0` et le message E086 reste masqué : les deux états ne se superposent pas.
- **Effort** : S.
- **Vérification** : choisir un type puis des catégories incompatibles → `#e086-empty` visible, contient « combinaison » ; cliquer « Réinitialiser les filtres » → message masqué et toutes les cartes réapparaissent.

## E086-08 — Idempotence et re-render safe

- **Problème / preuve** : `runEnhancements(ctx)` rejoue **tous** les greffons à chaque rendu (`registry.js:39-43`) et le `api` est reconstruit par étalement de `ctx` (`:29-37`) ; seul le CSS est protégé par `cssOnce()` (`:13-19`). La coque reconstruisant le `stage`, un greffon qui ne se protégerait pas dupliquerait ses nœuds et ses écouteurs. `E02.js` documente le même piège (`chrono-hierarchy`).
- **Solution** : la barre est recherchée **dans `main`** (`main.querySelector('#e086-bar')`) et réutilisée si présente ; les identifiants sont tous préfixés `e086` (`e086-bar`, `e086-type-*`, `e086-cat-*`, `e086-mode`, `e086-readout`, `e086-empty`) ; l'état (`selectedType`, `selectedCats`, `unionMode`) vit dans le module et est réaffirmé au DOM à chaque `apply()` ; les catégories disparues sont élaguées à chaque rendu.
- **Impact** : aucun ID dupliqué, aucun écouteur empilé, état visuel cohérent après un changement de pays ou d'ère.
- **Risque** : un second passage de `runEnhancements` sur le **même** DOM est neutralisé par la garde d'existence. Un pays différent change les catégories disponibles : l'élagage évite une sélection « fantôme » sans écraser le store (contrairement à `local.tag`, `chronology.js:16`).
- **Effort** : M.
- **Vérification** : 20 cycles de rendu → un seul `<style id="chronology-e086">`, un seul `#e086-bar`, un seul `#e086-readout` ; `data-e086-*` cohérents avec les `aria-pressed` ; `viewDiagnostics()` ne signale aucune erreur `E086`.

## E086-09 — Accessibilité clavier et cibles tactiles

- **Problème / preuve** : les contrôles de base sont des boutons `aria-pressed` de 30 px de haut (`.atlas-chrono-tag`, `injectStyle`, `chronology.js:53-57`) et un champ de recherche `min-height:36px` (`:47-51`) ; les puces de la fiche descendent à 24 px (`:65`). Une lentille qui ajouterait des contrôles plus petits ou sans libellé aggravereait la situation.
- **Solution** : toutes les puces et tous les boutons E086 ont `min-height:36px`, `font:inherit`, `cursor:pointer`, `:focus-visible` à `outline:2px solid var(--gold-bright)` et `:focus-within` sur les labels de radios. Radios natifs (navigation fléchée), `role="radiogroup"` et `role="group"` avec `aria-label`, `aria-controls="atlas-chrono-events"` sur chaque contrôle, `aria-label` unique sur la barre. `aria-pressed` est réservé aux bascules indépendantes (catégories, mode) ; le type relève du radiogroup.
- **Impact** : équivalence clavier complète, cibles tactiles conformes au seuil de 36 px, sémantique de groupe explicite.
- **Risque** : l'input radio masqué reste dans l'ordre de tabulation (pas de `display:none`) : c'est voulu pour le focus. Le routeur clavier global de la coque pourrait intercepter certaines touches ; les boutons et radios étant des contrôles de formulaire natifs, leur comportement précède toute navigation.
- **Effort** : M.
- **Vérification** : Tab puis flèches → sélection du type sans souris ; `getComputedStyle` des puces ≥ 36 px ; chaque contrôle possède `aria-controls` ; aucun piège de focus introduit.

## E086-10 — Mouvement réduit, budget et responsive

- **Problème / preuve** : `injectStyle` prévoit déjà un `@media (prefers-reduced-motion:reduce)` local (`chronology.js:89-91`) et `styles.css` neutralise globalement animations/transitions (`:342-345`) ; le registre expose `ctx.reducedMotion()` (`registry.js:33-36`). La grille de la vue passe en une colonne sous 620 px (`styles.css:316-317`) : une barre de filtres trop large casserait la lecture mobile.
- **Solution** : `data-e086-reduced` est posé sur `.chronology-layout` depuis `ctx.reducedMotion()` ; les transitions des puces et boutons sont neutralisées par ce marqueur **et** par une media query dédiée. Aucune animation, aucun `requestAnimationFrame`, aucun timer : `apply()` est purement événementiel. Sous 620 px, les rangées deviennent `flex-direction:column` tout en conservant `min-height:36px`. Un seul bloc CSS, préfixé et sans fuite hors de la vue.
- **Impact** : coût nul en boucle de rendu, respect de la préférence de mouvement, barre lisible sur écran étroit sans déborder la colonne.
- **Risque** : le marqueur `data-e086-reduced` doit être réévalué à chaque rendu (la préférence peut changer entre deux navigations) ; c'est fait dans le `register`. Aucune règle `!important` n'est utilisée hors du masquage des cartes `[hidden]` et de l'état vide.
- **Effort** : S.
- **Vérification** : avec mouvement réduit émulé, `data-e086-reduced="1"` et `transition-duration:0s` calculée ; `grep -nE 'requestAnimationFrame|setInterval|setTimeout' src/views/chronology/E086.js` → 0 ligne ; relecture visuelle en 1658×1150 et 390×844.

## Blocages

- **Aucun blocage fonctionnel.** La vue n'exposant pas de champ « type » explicite (`chronology.js:379-383`), E086-03 utilise l'importance (`data-importance`, `:382`) comme proxy documenté : c'est une limite de données de la vue possédée, pas un défaut de la lentille. Un champ `type` réel dans le modèle de données permettrait de remplacer ce proxy sans changer l'interface de la lentille.
- Le filtre E086 reste **additif** au filtre de base (`local.tag` / `local.query`, `chronology.js:16`, `:178-188`) : la lentille n'a pas la main sur `set({}, 'chrono-filter')` sans modifier le store, fichier hors périmètre. Le comportement est cohérent (les deux filtres se cumulent) et documenté.
- Aucune vérification E2E/visuelle n'a été rejouée par ce sous-agent (périmètre : écriture des deux fichiers possédés) ; elle est à la charge de l'agent maître, comme pour M01/M07.
