## E046-01 — `<label for>` manquant greffé sur `#atlas-chrono-search`

- **Problème / preuve** : la passe 1 crée le champ de recherche par `document.createElement('input')` (`chronology.js:313`), pose `type = 'search'` (`:314`), `id = 'atlas-chrono-search'` (`:315`), un `placeholder` (`:317`) et un `aria-label` (`:318`), puis l'ajoute aux outils (`:327`). Aucun élément `<label>` n'est créé ni associé : le nom accessible ne repose que sur `aria-label`, et le `placeholder` reste le seul indice visuel. Le modèle E049 confirme que ce champ est au cœur des interactions (`E049.js:220-225`, `E049.md:30-37`) sans jamais évoquer de libellé associé. La passe 2 hérite de ce DOM.
- **Solution** : `E046.js:226-227` repère `#atlas-chrono-tools` et `#atlas-chrono-search` ; `:232-235` crée (ou réutilise) un `<label>` de texte `LABEL_TEXT` (`:49-52`), lui pose `htmlFor = 'atlas-chrono-search'` et l'attribut `for` ; `:237` l'insère immédiatement avant le champ avec `insertBefore`. Un garde `document.getElementById(SEARCH_LABEL_ID) || …` évite tout doublon.
- **Impact** : `input.labels.length` passe à au moins 1 ; un clic sur le libellé donne le focus au champ, sans éditer `chronology.js` ni détourner son écouteur `input` (`:321-326`).
- **Risque** : si la vue passe 2 renomme `#atlas-chrono-search`, le libellé est créé mais non attaché ; l'état est alors signalé « Association incomplète » (`:284-287`) avec `data-e046-attached="0"` (`:287`), jamais masqué.
- **Effort** : S.
- **Vérification** : harnais — après rendu, `#atlas-chrono-search.labels.length ≥ 1` et `#chronology-v2-e046-search-label` précède le champ dans `#atlas-chrono-tools` ; relecture `E046.js:232-239` ↔ `chronology.js:313-327`.

## E046-02 — Audit en lecture seule de tous les champs de la vue

- **Problème / preuve** : la vue ne contient qu'un seul champ explicite (`chronology.js:313-327`) et n'expose aucun état global disant si ses contrôles de saisie sont étiquetés ; le modèle E049 mesure la charge de tabulation (`E049.js:150-169`, `E049.md:48-55`) mais pas la présence de libellés. Un audit reproductible manque.
- **Solution** : `E046.js:172-197` définit `auditChamps(root)` : sélection `input, select, textarea` (`:176-178`), pour chacun relève l'id/type, la présence d'un `<label>` via `champ.labels` (`:180`) et la source du nom accessible — « label associé », « aria-labelledby », « aria-label seul », « placeholder seul », « aucun nom » (`:181-189`). `:247-263` rend chaque relevé en `<li class="e046-row">` avec un drapeau `data-e046-ok` (`:252-253`), plafonné à 20 lignes (`:250`), avec un état vide explicite (`:261-263`).
- **Impact** : l'étiquetage de la vue devient chiffré et falsifiable via `data-e046-champs` / `data-e046-sans-label` (`:312-313`) et la métrique visible (`:310`).
- **Risque** : l'audit est un instantané reconstruit à chaque rendu ; il ne promet aucune correction des champs tiers, seulement une mesure. Les champs sans id sont affichés « (sans id) » (`:190`), ce qui est un libellé de diagnostic, pas une donnée inventée.
- **Effort** : M.
- **Vérification** : relecture `E046.js:175-197, 247-263` ; harnais — avec le seul champ de la passe 1, `data-e046-champs="1"` et `data-e046-sans-label="0"` après greffage du libellé ; aucune écriture dans les attributs des champs audités.

## E046-03 — Double attache `for` + `aria-labelledby` sur le champ

- **Problème / preuve** : `chronology.js:318` pose `aria-label` sur le champ, mais l'algorithme du nom accessible fait prévaloir `aria-label` sur un `<label for>` : greffer seulement le libellé ne le rendrait pas effectif. Le modèle E049 souligne la fragilité des noms de contrôles (`E049.js:129-134`) et l'absence de `say()` dans le registre (`E049.js:13-15`).
- **Solution** : `E046.js:241-245` pose `aria-labelledby = 'chronology-v2-e046-search-label'` sur le champ, en plus du `for` du libellé (`:234-235`) ; l'`aria-label` d'origine est conservé en repli. `:281-283` vérifie les deux attaches et `search.labels.length`, puis `:287` publie `data-e046-attached`.
- **Impact** : le libellé visible devient la source prioritaire du nom accessible, avec deux repliements cohérents (`for` et `aria-label`) si l'un venait à manquer.
- **Risque** : `aria-labelledby` écrase `aria-label` dans le nom calculé ; c'est pourquoi le texte du libellé est aligné mot pour mot sur l'`aria-label` (E046-08). Si la passe 2 change l'`aria-label`, le contrôle E046-08 signale l'écart.
- **Effort** : S.
- **Vérification** : relecture `E046.js:234-245` ↔ `chronology.js:318` ; harnais — `#atlas-chrono-search` porte `aria-labelledby="chronology-v2-e046-search-label"`, `for` du libellé égal à l'id du champ, `data-e046-attached="1"` et libellé « Association vérifiée » (`:284-285`).

## E046-04 — Libellé placé avant le champ dans l'ordre de lecture

- **Problème / preuve** : dans `chronology.js:327`, le champ est le premier enfant de `#atlas-chrono-tools`, sans aucun libellé le précédant : un lecteur d'écran linéaire rencontre la saisie avant tout intitulé. Le CSS des outils est une `flex` avec `flex-wrap` (`chronology.js:47`, `:85-88`), donc un libellé en ligne se retrouverait serré contre les puces de filtre.
- **Solution** : `E046.js:237` insère le libellé avant le champ ; `:111-117` le stylise en bloc pleine largeur (`display:block`, `flex: 1 1 100%`, `box-sizing:border-box`, marge basse de 2 px), avec une police et une couleur lisibles (`:115`). Le titre et le préambule du panneau (`:221-224`) cadrent le propos.
- **Impact** : l'ordre de lecture devient « libellé → champ → puces → compte », et le libellé occupe sa propre ligne en 390×844 comme sur grand écran.
- **Risque** : `flex: 1 1 100%` occupe une ligne entière et allonge légèrement la barre d'outils ; c'est le compromis assumé pour ne pas tasser le libellé contre les puces. Sous 620 px, la barre passe déjà en colonne (`chronology.js:86`), sans effet supplémentaire.
- **Effort** : S.
- **Vérification** : capture 1658×1150 et 390×844 — le libellé est au-dessus du champ, non tronqué ; relecture `E046.js:111-117, 237` ↔ `chronology.js:47, 85-88, 327`.

## E046-05 — Cible cliquable du libellé ≥ 24 px

- **Problème / preuve** : les puces de filtre de la passe 1 ont une hauteur minimale de 24 px (`chronology.js:66`) et le modèle E049 exige des cibles tactiles lisibles (`E049.md:93-100`), mais le champ et son environnement immédiat n'offrent aucune zone d'activation dédiée au libellé. Un simple texte de 10 px serait une cible trop petite.
- **Solution** : `E046.js:112-116` donne au libellé `min-height:24px`, `padding:4px 6px`, `box-sizing:border-box` et `cursor:pointer` ; `:118` ajoute un survol doré. Comme le libellé porte `for="atlas-chrono-search"` (`:235`), le clic sur toute cette zone active nativement le champ, sans gestionnaire de souris.
- **Impact** : la zone d'activation du libellé atteint au moins 24 px de haut et s'étend sur toute la largeur de la barre d'outils, utile au tactile comme à la souris.
- **Risque** : la hauteur réelle dépend de la police et du zoom ; `min-height` garantit le plancher mais pas une valeur fixe. Le `cursor:pointer` est un indice visuel, jamais le seul vecteur d'information (le texte du libellé reste explicite).
- **Effort** : S.
- **Vérification** : mesurer la boîte de `#chronology-v2-e046-search-label` (hauteur ≥ 24 px) ; cliquer en bordure du libellé → le champ reçoit le focus ; relecture `E046.js:112-118, 232-235`.

## E046-06 — Signal de focus sur le libellé (`:has` + `data-e046-focus`)

- **Problème / preuve** : le champ de recherche reçoit le focus à chaque frappe et la vue reconstruit le DOM en posant `focusIntent` (`chronology.js:321-325`) ; le modèle E049 documente ce chemin de focus (`E049.md:30-37`) et la restauration de la coque (`E049.md:39-46`). Aucun signal visuel ne relie le libellé à l'état de focus du champ.
- **Solution** : `E046.js:120-126` illumine le libellé (bordure dorée, fond translucide) via `#atlas-chrono-tools:has(#atlas-chrono-search:focus) #chronology-v2-e046-search-label` et via l'attribut `[data-e046-focus="1"]`. `:199-207` définit un unique écouteur `focusin` observationnel qui pose `data-e046-focus` sur le libellé et le panneau ; `:322-326` l'enregistre une seule fois sous la garde `focusBound`. Le texte `#chronology-v2-e046-focus` (`:271-272`, `:306`) explique le mécanisme.
- **Impact** : l'association champ ↔ libellé devient visible au moment précis où le champ est actif, avec un repli JS si `:has()` n'est pas pris en charge.
- **Risque** : l'écouteur `focusin` est purement observationnel — aucun `focus()`, aucun `preventDefault`, aucune écriture live (`:199-201`) — donc il ne contrarie ni le `focusIntent` de la vue ni la restauration de la coque. Si le focus quitte la fenêtre, l'attribut peut rester à `1` jusqu'au prochain `focusin` : état cosmetique, sans impact fonctionnel.
- **Effort** : M.
- **Vérification** : relecture — un seul `addEventListener('focusin'` (`E046.js:324`), zéro `focus(` / `preventDefault` ; harnais — focaliser le champ → libellé bordé d'or et `data-e046-focus="1"`, Tab vers une puce → retour à `0`.

## E046-07 — Repli « placeholder jamais seul libellé »

- **Problème / preuve** : `chronology.js:317` donne au champ un `placeholder` (« Rechercher un repère, une année, un thème… ») et `chronology.js:40, 53` le stylise en gris pâle (`--muted-2`) : un placeholder disparaît dès la saisie et son faible contraste ne constitue pas un libellé acceptable. Le modèle E049 ne corrige pas ce point (`E049.md:30-37`).
- **Solution** : `E046.js:297-303` calcule `seulPlaceholder` : le champ a un `placeholder` ET aucun `<label>` dans `champ.labels`. `:298-302` écrit un état explicite dans `#chronology-v2-e046-placeholder`, `:303` publie `data-e046-placeholder-only`, `:103-104` prévoit le repli visuel (grisé si l'état est dégradé).
- **Impact** : dès que le libellé est greffé, le message indique que le placeholder n'est plus le seul indice ; si le greffage échoue, l'alerte est visible et mesurable, jamais silencieuse.
- **Risque** : le placeholder d'origine n'est ni supprimé ni modifié ( fichier non possédé) ; il reste une aide complémentaire, ce qui est conforme à son rôle. Le contrôle repose sur `champ.labels`, donc sur la prise en charge DOM du navigateur.
- **Effort** : S.
- **Vérification** : harnais — état nominal → `data-e046-placeholder-only="0"` et libellé « n'est plus son seul indice » ; simuler l'absence de libellé → `1` et message d'alerte ; relecture `E046.js:297-303` ↔ `chronology.js:317`.

## E046-08 — Cohérence libellé visible ↔ `aria-label` d'origine

- **Problème / preuve** : `chronology.js:318` porte `aria-label = 'Rechercher parmi les repères et les points de ce pays'`. Ajouter un libellé avec un autre texte créerait deux noms concurrents : le nom calculé (via `aria-labelledby`) diverge de l'ancien `aria-label` conservé en repli, source de confusion pour les technologies d'assistance. Le modèle E049 insiste sur des libellés uniques et fidèles (`E049.js:93-104`, `E049.md:21-28`).
- **Solution** : `E046.js:49-52` définit `LABEL_TEXT` exactement égal à l'`aria-label` d'origine ; `:289-295` compare `label.textContent.trim()` à l'`aria-label` relevé sur le champ, écrit le résultat dans `#chronology-v2-e046-name` et publie `data-e046-coherent` (`:295`, `:315`).
- **Impact** : le libellé visible, le nom accessible prioritaire et le repli `aria-label` disent la même chose ; toute dérive future est signalée en texte et en attribut.
- **Risque** : si la passe 2 traduit ou reformule l'`aria-label`, le contrôle bascule à « Noms à rapprocher » (`data-e046-coherent="0"`) : la lentille signale mais ne corrige pas, la correction relevant du fichier non possédé.
- **Effort** : S.
- **Vérification** : relecture `E046.js:49-52, 289-295` ↔ `chronology.js:318` ; harnais — `data-e046-coherent="1"` et message « Nom accessible cohérent » en état nominal.

## E046-09 — Repli `prefers-reduced-motion` / `forced-colors`

- **Problème / preuve** : la coque neutralise globalement animations et transitions (`styles.css:342-344`, cité dans `E049.md:93-100`) et le registre V2 fournit `ctx.reducedMotion()` (`registry.js:33-36`), mais la passe 1 n'expose aucun état de préférence pour ses contrôles. Le survol doré introduit par E046-05 doit donc rester sans mouvement et rester lisible en couleurs forcées.
- **Solution** : `E046.js:132-136` désactive toute transition/animation du panneau et du libellé sous `prefers-reduced-motion: reduce` ; `:137-142` fournit un repli `forced-colors: active` en `Canvas`/`CanvasText` avec bordure explicite. `:305` lit `ctx.reducedMotion()`, `:307-309` écrit l'état dans `#chronology-v2-e046-motion`, `:317` publie `data-e046-reduced`.
- **Impact** : aucun mouvement parasite, contraste préservé en couleurs forcées, préférence système reportée en texte lisible.
- **Risque** : le repli `forced-colors` s'applique au panneau, au libellé, aux drapeaux et aux identifiants (`:138-140`) ; la couleur dorée disparaît alors, mais le texte des drapeaux (« label associé » / « libellé manquant ») porte l'information, jamais la teinte seule.
- **Effort** : S.
- **Vérification** : émuler `prefers-reduced-motion: reduce` → `data-e046-reduced="1"` et libellé « oui » ; forcer `forced-colors: active` → bordure `CanvasText` visible sur le libellé ; relecture `E046.js:132-142, 305-317`.

## E046-10 — Idempotence multi-rendus et unicité du greffon

- **Problème / preuve** : le registre V2 rejoue les greffons à chaque rendu (`registry.js:28-43`) et neutralise silencieusement leurs erreurs (`:39-42`) ; `cssOnce()` ne garantit que l'unicité du `<style>` (`registry.js:13-19`). Le modèle E049 documente la reconstruction du stage (`E049.md:102-109`). Sans gardes, un greffon E046 dupliquerait libellé, panneau et écouteur à chaque navigation.
- **Solution** : `E046.js:153-165` fournit `ensureNode()` avec garde d'existence et déplacement dans le parent courant ; `:232` applique la même garde au libellé ; `:34` et `:214` imposent un seul `CSS_ID` / un seul `ctx.css` ; `:322-326` un seul `focusin` sous garde module ; `:167-170` déduplique les écritures ; `:329` un seul `register('E046', install)`. `:213`, `:318` exposent `installCount` en métrique et en `data-e046-installs`.
- **Impact** : aucun doublon de libellé, de panneau ou de feuille de style après navigation aller-retour ; aucune fuite d'écouteur sur une longue session.
- **Risque** : un nœud retrouvé dans un ancien parent détaché est déplacé, jamais cloné ; ses attributs `data-e046-*` sont réécrits à chaque `install()` (`:287`, `:295`, `:303`, `:312-318`), donc jamais périmés. Le registre neutralisant une erreur, `node --check` et les gardes sont la première ligne de défense.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E046.js` → PASS ; relecture — un seul `register`, un seul `ctx.css`, un seul `addEventListener`, tous les IDs préfixés `chronology-v2-e046-` (`:34-44`) ; rejeu rendu → navigation → rendu : un seul `#chronology-v2-e046-panel`, un seul `#chronology-v2-e046-search-label`, un seul `<style id="chronology-v2-e046">`.

## Blocages / limites inter-domaines

- Le libellé est greffé à l'exécution : la vraie correction (créer le `<label>` dans la vue) relève de `chronology.js:313-327`, fichier non possédé. Si une passe 2 renumérote `#atlas-chrono-search`, l'association échoue et est signalée (`data-e046-attached="0"`), sans que la lentille puisse renommer le champ.
- `aria-labelledby` écrase `aria-label` dans le nom calculé ; l'`aria-label` d'origine est conservé en repli mais le texte du libellé doit rester aligné (E046-08). Un changement de libellé dans la vue imposerait une relecture de `LABEL_TEXT` (`E046.js:52`).
- L'audit (E046-02) est une mesure instantanée en lecture seule : il ne corrige aucun champ tiers sans libellé, il le signale seulement.
- Le signal de focus (E046-06) repose sur `:has()` avec repli par écouteur `focusin` ; si le focus quitte la fenêtre sans nouveau `focusin`, l'attribut peut rester à `1` — état purement cosmétique.
- L'écouteur `focusin` est attaché à `document` une fois pour toute la session ; il survit aux rendus et consulte `getElementById` à chaque événement (`:204`), sans jamais écrire dans une région live.
