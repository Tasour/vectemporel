## E056-01 — Détection des points sans source et mesure du taux d'omission

- **Problème / preuve** : `chronology.js:490-501` ne crée `<ul class="point-sources">` que si `point.sources` est non vide. Un point sans source est donc rendu comme un simple paragraphe (`chronology.js:488`) : l'absence est muette, aucun compteur ne la signale. Le registre V2 ne fournit pas de `say()` (`registry.js:28-37`), donc la mesure doit rester dans le DOM visible.
- **Solution** : `E056.js:192-199` parcourt les `li.point` du layout (`:194`) et retient ceux qui n'ont pas de `ul.point-sources` (`:197`). Le décompte alimente le métrique (`:269-273`), le readout (`:264-267`) et les attributs du layout (`:275-279`) ; un taux arrondi est calculé depuis `records.length / points.length` (`:270`), jamais codé en dur.
- **Impact** : le nombre d'omissions et leur part dans le repère deviennent lisibles et falsifiables, sans toucher aux données ni au rendu d'origine.
- **Risque** : seuls les points du repère affiché sont dans le DOM (l'aside est reconstruit à chaque sélection, `chronology.js:417-505`) : la mesure est locale au repère, pas globale au pays. Le libellé `E056.js:272` le dit explicitement.
- **Effort** : S.
- **Vérification** : relecture `E056.js:194,197,270,272` ↔ `chronology.js:488,490-501` ; avec un repère sans source, `data-chronology-v2-e056-omissions` suit le nombre de `li.point` sans `ul.point-sources`, et le taux est recalculé à chaque rendu.

## E056-02 — Identifiant d'omission déterministe

- **Problème / preuve** : `chronology.js:475-479` pose `data-point-id`, `data-kind` et `data-confidence` sur chaque point, mais aucun identifiant de l'absence de source n'existe. Sans clé stable, une omission ne peut être citée, retrouvée ni comparée d'un rendu à l'autre.
- **Solution** : `E056.js:130-140` fabrique `OM-E056-<pointId>` depuis `data-point-id`, avec repli déterministe sur le rang (`rang-N`) et assimilation des caractères parasites (`:131-133`). Aucun aléa, aucune graine, aucune date : la fonction est pure et reproductible. L'identifiant est affiché en texte gras (`:214`) et reporté dans `data-chronology-v2-e056-id` (`:220`).
- **Impact** : chaque omission possède une référence citables dans le drapeau, le registre et le readout.
- **Risque** : si deux points partagent le même `data-point-id`, leurs identifiants collident ; le contrat de données (`chronology.js:476`) garantit des identifiants distincts, hypothèse documentée ici. Le repli par rang reste stable tant que l'ordre DOM ne change pas.
- **Effort** : S.
- **Vérification** : `node --check` PASS ; relecture — zéro `Math.random` dans `E056.js` ; deux rendus du même repère produisent la même suite d'`OM-E056-…`.

## E056-03 — Drapeau textuel « source omise » inséré dans le point

- **Problème / preuve** : le CSS de la passe 1 distingue les pastilles de type et de confiance, mais rien ne distingue visuellement un point sans source d'un point documenté. Une information seulement portée par l'absence de `<ul>` est invisible pour la lecture linéaire (`E049.md` pose le même principe pour la couleur seule).
- **Solution** : `E056.js:201-219` insère un `<span class="chronology-v2-e056-flag">` à la fin du point, avec l'identifiant, la mention « source omise », la qualification et un lien. La feuille unique lui donne une bordure en pointillés et un motif de hachures (`:53-58`) : le sens est porté par le texte **et** par la forme, jamais par une couleur seule. La garde sur la classe (`:206`) empêche la duplication.
- **Impact** : l'omission devient perceptible dans le flux de lecture, y compris en `forced-colors` (`:97-102`) où le motif est retiré mais le texte conservé.
- **Risque** : le drapeau allonge légèrement la fiche ; c'est un compromis assumé face à un marqueur flottant qui masquerait le texte du point.
- **Effort** : M.
- **Vérification** : harnais DOM — un point sans source contient exactement un `.chronology-v2-e056-flag` ; rejeu de `apply()` sur le même DOM : toujours un seul drapeau ; capture en `forced-colors: active` : libellé lisible.

## E056-04 — Attributs miroirs d'omission portés par le point

- **Problème / preuve** : `chronology.js:475-479` expose `data-point-id`, `data-kind`, `data-confidence`, mais aucun état d'omission n'est auditable par un outil ou une lentille voisine. La passe 1 utilise le même procédé de miroir (`E049.md`, chantier E049-10) pour rendre son état vérifiable.
- **Solution** : `E056.js:220-223` écrit `data-chronology-v2-e056-id`, `-reason`, `-anchor` et `-flag="1"` sur chaque point omis. Le layout reçoit en outre les attributs agrégés `data-chronology-v2-e056(-omissions/-ids/-justified/-reduced)` (`:275-279`).
- **Impact** : l'état d'omission est observable sans lecture de texte et sans dépendre du CSS ; un contrôle automatisé peut comparer le nombre d'attributs au nombre de drapeaux.
- **Risque** : ces attributs sont écrits à chaque installation et non nettoyés à la destruction du nœud — sans conséquence, puisque la coque reconstruit le layout (`shell.js:533`, cf. `E049.md:102-104`).
- **Effort** : S.
- **Vérification** : relecture `E056.js:220-223,275-279` ; harnais — `document.querySelectorAll('[data-chronology-v2-e056-flag="1"]').length` égale le compteur du métrique.

## E056-05 — Qualification justifiée / non qualifiée en texte lisible

- **Problème / preuve** : la passe 1 prévoit un repli « omission justifiée » pour les sources (`E049.md` ne le traite pas, mais la fiche de référence `E025` porte ce vocable) ; dans la vue rendue, aucun marqueur de qualification n'est visible ni même détectable si les données n'en portent pas. Confondre « justifiée » et « oubliée » est une perte de sens.
- **Solution** : `E056.js:135-138` lit uniquement `data-omission-reason`, `data-source-omission` et `data-omission` du point, puis classe l'omission en « omission justifiée » ou « omission non qualifiée ». Le libellé est inséré dans le drapeau (`:215`), reporté dans le registre (`:253-254`) et dédupliqué dans le readout (`:267`). Le module n'invente jamais de justification.
- **Impact** : une omission délibérée et une lacune non expliquée ne sont plus confondues ; le compteur de justifiées est documenté dans le readout et l'attribut `-justified`.
- **Risque** : les attributs de justification ne sont pas émis par `chronology.js:474-480` : en l'état, toutes les omissions sont « non qualifiées ». C'est un constat honnête, pas un défaut de la lentille ; l'ajout d'un tel attribut relève du magasin de données.
- **Effort** : M.
- **Vérification** : harnais — injecter `data-omission-reason="justifiée"` sur un point sans source → libellé, `data-chronology-v2-e056-reason` et compteur passent en « justifiée » ; sans attribut, la mention « non qualifiée » apparaît.

## E056-06 — Agrégation des identifiants sur le repère courant

- **Problème / preuve** : les points sont dans l'aside (`chronology.js:467-505`) et les cartes de repères dans la frise (`chronology.js:376-413`) : rien ne relie les omissions d'un repère à sa carte, alors que `aria-current` identifie le repère consulté (`chronology.js:391`).
- **Solution** : `E056.js:171-180` retrouve la carte active, son `li[data-event-id]` et le titre du repère. Les identifiants sont reportés sur la carte et sur le `li` (`:232`, `:238`), avec un badge « N omission(s) de source » ou « Sources complètes » (`:233-236`) précédé du glyphe `◌` en CSS (`:71`).
- **Impact** : depuis la frise, on voit d'un coup d'œil si le repère sélectionné porte des omissions, et combien, sans ouvrir l'aside.
- **Risque** : si aucun repère n'est sélectionné, `findActiveEvent` renvoie un objet vide (`:175`) et le badge n'est pas créé ; le registre et le readout restent néanmoins renseignés avec « inconnu ».
- **Effort** : M.
- **Vérification** : relecture `E056.js:174,177,232,238` ↔ `chronology.js:379-384,386-391` ; harnais — changer de repère : l'ancien badge disparaît avec la carte reconstruite, le nouveau affiche le bon compte.

## E056-07 — Registre indexable des omissions (`<dl>`)

- **Problème / preuve** : les drapeaux sont dispersés dans la fiche ; sans registre, aucun texte continu ne permet de lire « identifiant → point → qualification » ni de vérifier l'ensemble des omissions d'un repère. Les contrats de la méthode Noeta et le modèle `E049.md:24` privilégient les listes sémantiques indexables.
- **Solution** : `E056.js:142-169` crée un `<section role="region" aria-labelledby>` avec un `<h2>`, un préambule, un `<div id="chronology-v2-e056-register">` et une `<dl id="chronology-v2-e056-register-list">`. Chaque omission produit un couple `<dt>OM-… — pointId</dt>` / `<dd>qualification ; repère ; point</dd>` (`:251-259`) ; le cas zéro omission est explicite (`:245-249`). `replaceChildren` (`:261`) évite l'accumulation.
- **Impact** : le registre est un contenu sémantique réel, lisible sans CSS, et cohérent avec les drapeaux insérés dans les points.
- **Risque** : le registre est reconstruit à chaque installation : les liens « Retour au point » sont recréés, mais ils pointent vers des ancrages eux-mêmes régénérés dans le même ordre (E056-08), donc jamais périmés.
- **Effort** : M.
- **Vérification** : relecture `E056.js:147-148,154-159,242,251-261` ; harnais — autant de `<dt>` que de drapeaux ; deux installations de suite ne doublent pas les entrées.

## E056-08 — Ancrage local aller-retour, sans réseau

- **Problème / preuve** : un identifiant d'omission ne sert à rien si l'on ne peut pas naviguer entre la mention et sa source. La vue expose déjà des ancres locales (`chronology.js:428-430` pose `data-fk` sur le titre) ; ouvrir une URL externe serait inutile et contraire au contrat zéro réseau.
- **Solution** : `E056.js:208-211` pose un ancrage `chronology-v2-e056-anchor-N` (préfixé, unique, `:32`, `:134`) dans le drapeau et un lien interne `(registre)` vers `#chronology-v2-e056-register`. Le registre crée le lien inverse « Retour au point » (`:255-256`). Ce sont des fragments `#` locaux : aucun `fetch`, aucun `src` distant.
- **Impact** : aller du point au registre et revenir au point se fait au clavier comme à la souris, sans quitter la vue.
- **Risque** : le défilement vers un ancrage peut être masqué par une barre fixe de la coque, non possédée ici ; le contrat de la vue pose `scroll-margin-block` sur les cartes (`chronology.js:83`), pas sur ces ancrages. Le lien reste fonctionnel, l'alignement visuel peut différer.
- **Effort** : S.
- **Vérification** : relecture — tous les `href` de `E056.js:211,256` commencent par `#` ; zéro `fetch`/`XMLHttpRequest`/`src` ; harnais — cliquer `(registre)` puis `Retour au point` ramène au `li.point` d'origine.

## E056-09 — Readout live unique, métrique et replis CSS

- **Problème / preuve** : la vue possède déjà une région live (`chronology.js:119-138`, cf. `E049.md:57-63`) ; en ajouter une deuxième produirait des annonces concurrentes. Par ailleurs, le registre fournit `ctx.reducedMotion()` (`registry.js:33-36`) sans que la vue n'expose cet état.
- **Solution** : `E056.js:161-164` crée un unique `<p role="status" aria-live="polite">`, écrit par la fonction dédupliquée `write` (`:108-110`, appel `:265-267`). Le métrique visible (`:165-166`, `:271-273`) affiche points examinés, omissions, part en pourcentage, mouvement réduit et nombre d'installations. La feuille unique prévoit un repli 620 px (`:88-93`), `prefers-reduced-motion` (`:94-96`), `forced-colors` (`:97-102`) et un anneau de focus visible sur les liens (`:66`). `ctx.reducedMotion()` est lu en `:186` et publié en `:279`.
- **Impact** : une seule annonce, non bavarde ; l'état reste lisible en 390×844, en mouvement réduit et en contraste forcé.
- **Risque** : le texte du registre n'est pas annoncé spontanément, seulement le readout récapitulatif ; c'est volontaire pour ne pas saturer la région live de la vue.
- **Effort** : M.
- **Vérification** : relecture — un seul `role="status"` et un seul `aria-live` dans `E056.js` ; zéro `animation`/`transition` non neutralisée ; émuler `prefers-reduced-motion: reduce` → `data-chronology-v2-e056-reduced="1"` et « oui » dans le métrique ; capture 390×844 sans débordement.

## E056-10 — Idempotence multi-rendus et contrat du greffon

- **Problème / preuve** : `chronology.js:540-541` appelle la passe 1 puis `runEnhancementsV2` à chaque rendu ; `registry.js:39-42` rejoue tous les greffons et isole leurs erreurs, tandis que `cssOnce` (`registry.js:13-19`) ne protège que la feuille de style. Sans gardes, un double appel du greffon duplique drapeaux et registre, et le registre neutraliserait silencieusement une exception.
- **Solution** : `E056.js:115-124` fournit `ensureNode` (réutilisation et déplacement, jamais clonage) ; `:145-146` pose un témoin `data-…-built` sur le panneau ; `:206` et `:233` gardent les drapeaux et badges ; `:261` remplace le contenu du registre ; `:108-110` déduplique les écritures. Un seul `ctx.css` (`:189`) et un seul `register` (`:282`). Aucun écouteur, aucun timer, aucune boucle, aucun aléa, aucun HTML brut : le module tient entièrement dans le contrat de la passe 2.
- **Impact** : navigation aller-retour et double application sur le même rendu laissent exactement un panneau, un registre, un drapeau par omission et une feuille `<style id="chronology-v2-e056">`.
- **Risque** : le compteur `renderCount` (`:105`, `:187`) est une mémoire module qui survit aux rendus ; il n'est qu'informatif (métrique `:273`) et ne pilote aucun comportement. Un nœud retrouvé dans un ancien parent détaché est déplacé, jamais dupliqué.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E056.js | PASS` ; relecture — un seul `register`, un seul `ctx.css`, zéro `addEventListener`, zéro `innerHTML`, zéro `console.`, zéro `setTimeout`/`setInterval`/`requestAnimationFrame`, zéro `Math.random` ; rejeu rendu → navigation → rendu : un seul `#chronology-v2-e056-panel`, un seul `<style id="chronology-v2-e056">`.

## Blocages / limites inter-domaines

- Le magasin de données (`source/data.js`) n'émet aucun attribut de justification d'omission ; la distinction « justifiée / non qualifiée » (E056-05) repose donc sur des attributs `data-omission-*` aujourd'hui absents du rendu `chronology.js:474-480`. La lentille constate et étiquette, elle ne décide pas de la justification.
- L'omission est détectée par l'absence de `<ul class="point-sources">` (`chronology.js:490-501`). Si un futur rendu change cette structure, le selector `E056.js:197` devra être relu ; c'est une dépendance de contrat assumée et documentée en tête de module (`E056.js:13-17`).
- La mesure est limitée au repère courant, seul présent dans l'aside (`chronology.js:417-505`). Une couverture globale au pays exigerait une lecture du magasin, hors périmètre de cette lentille.
- Le registre live unique (E056-09) ne remplace pas `#nav-c2a-live` (`chronology.js:119-138`) : il n'écrit pas dans la région de la vue, pour éviter les annonces concurrentes.
- Le défilement vers les ancrages (E056-08) dépend du `scroll-margin-block` global défini pour les cartes (`chronology.js:83`) et non pour ces ancrages ; un chevauchement par une barre fixe resterait à arbitrer par le maître d'œuvre de la coque.
- Le CSS est injecté après la feuille de la passe 1 ; les variables `--gold`, `--line`, `--muted` etc. sont supposées présentes (`E056.js:42-87`), comme dans le modèle `E049.js:43-91`.
