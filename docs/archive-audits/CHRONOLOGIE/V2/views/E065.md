## E065-01 — Aucun témoin visible de l'absence d'aléa dans la vue

- **Problème / preuve** : `chronology.js:208-543` construit la vue entièrement depuis le store (`state.eraIndex`, `state.eventIndex`, `:234-237`) et le filtre local (`:17`) ; pourtant aucun texte n'énonce la garantie de déterminisme. Le seul indice visible est l'aide clavier de `chronology.js:232`, qui ne dit rien du rendu. Un utilisateur ne peut donc pas vérifier que deux visites affichent la même chose.
- **Solution** : `E065.js:207-208` crée un badge `#chronology-v2-e065-badge` en texte réel — « Garantie : aucun aléa natif — toute variation provient d’une graine affichée. » — stylé en pastille via `E065.js:53-57`, et un titre `role="region"` (`E065.js:201-206`). Le panneau reste en flux normal en fin de `#atlas-chrono-main`, jamais superposé.
- **Impact** : la garantie devient lisible sans ouvrir le code ni une console, et sans modifier l'indice d'origine `chronology.js:232`.
- **Risque** : l'affirmation porte sur le greffon et sur les données qu'il lit, pas sur un audit statique de tout le dépôt. Le libellé est volontairement borné au rendu de cette vue (commentaire `E065.js:12-21`).
- **Effort** : S.
- **Vérification** : relecture `E065.js:207-208` ; rendu → le badge est présent une fois, en texte sélectionnable ; l'indice `chronology.js:232` est inchangé.

## E065-02 — Aucune graine dérivée du DOM pour un visuel éventuel

- **Problème / preuve** : la vue expose pourtant toutes les données nécessaires : `layout.dataset.countryId` (`chronology.js:215-217`), `data-era-id` / `data-start` / `data-end` sur les bandes (`:287-290`), `data-event-id` sur les cartes (`:388-389`). Rien ne les convertit en identifiant de rendu réutilisable. Le registre V2 (`registry.js:28-44`) fournit `css`, `el`, `reducedMotion`, mais aucune graine : une lentille qui voudrait un motif décoratif devrait inventer sa propre source de variation — donc recourir à une API non déterministe.
- **Solution** : `E065.js:136-143` lit uniquement ces trois marqueurs du DOM via `querySelector` en lecture seule, puis `E065.js:114-121` applique un hash FNV-1a (32 bits, sans aléa) et `E065.js:145-147` compose `e065-<hash>-<génération>`. La graine est publiée en texte (`E065.js:240`) et dans `data-e065-seed` (`:248`).
- **Impact** : toute variation du visuel est rattachée à une entrée observable (pays, ère, repère, compteur de régénération), jamais à une horloge ni à un tirage.
- **Risque** : si la vue renomme ses `data-*`, la source devient vide et le repli « contexte par défaut » (`E065.js:240`) s'active ; la graine reste déterministe mais perd sa précision. Aucune donnée n'est inventée pour compenser.
- **Effort** : M.
- **Vérification** : harnais — changer de pays puis de repère → `#chronology-v2-e065-seed` change ; revenir au même état avec le même compteur → graine identique ; relecture — zéro appel à une API non déterministe dans `E065.js:114-147`.

## E065-03 — Aucun générateur local reproductible

- **Problème / preuve** : `registry.js:28-44` délègue aux greffons la construction de leur état et neutralise silencieusement leurs erreurs (`:39-42`). Sans générateur propriétaire, la tentation est d'employer la fonction aléatoire native du moteur pour produire des hauteurs de barres ou des couleurs, ce qui rendrait le rendu non reproductible et invaliderait toute capture de référence.
- **Solution** : `E065.js:123-132` définit `makeGenerator(seed)`, un générateur à état local de type mulberry32 (incrément constant `0x6d2b79f5`, multiplications entières via `Math.imul`, normalisation sur 2³²). Il est amorcé une fois par dessin à partir du hash de la graine (`E065.js:169`). Aucun appel à une source d'aléa du moteur n'apparaît dans le module.
- **Impact** : la séquence de nombres est entièrement reproductible depuis la graine affichée ; deux rendus du même état donnent les mêmes valeurs.
- **Risque** : le générateur n'est pas cryptographique — c'est un choix assumé, il sert à un bandeau décoratif, jamais à une donnée de sécurité. Sa période et sa graine de 32 bits sont documentées dans le commentaire `E065.js:112-113`.
- **Effort** : M.
- **Vérification** : relecture de `E065.js:123-132` ; essai — appeler deux fois `makeGenerator(mêmeGraine)` dans un harnais donne la même suite de 12 valeurs ; contrôle statique : zéro occurrence d'appel aléatoire natif dans le fichier.

## E065-04 — Aucun visuel déterministe de contrôle

- **Problème / preuve** : la Chronologie n'affiche aucun motif généré : les seules images proviennent des données (`chronology.js:396-401` pour les cartes, `:433-439` pour la fiche) et les bandes d'ères sont des boutons colorés par `data` (`:294`). Il n'existe donc aucun témoin visuel permettant de constater qu'un rendu est stable.
- **Solution** : `E065.js:168-187` dessine un bandeau ordonné de `BAR_COUNT = 12` barres (`:36`) : chaque hauteur est `14 + next() * 86` arrondie (`:171-173`), posée en `style.height` et publiée dans `data-e065-value` (`:174-179`). Le bandeau est une liste `<ol>` stylée en flex (`E065.js:68-76`) et déclarée `role="img"` avec un `aria-label` complet (`E065.js:246-247`).
- **Impact** : un changement de graine se voit immédiatement, tandis qu'un simple re-render ne modifie rien — la reproductibilité devient observable à l'œil.
- **Risque** : le bandeau allonge la colonne de gauche d'environ 60 px ; c'est le compromis assumé d'un bloc en flux, préférable à un calque qui masquerait des cartes. Aucune information n'est portée par la seule couleur : la valeur de chaque barre est dans son `data-e065-value` et l'ensemble est résumé par l'`aria-label`.
- **Effort** : M.
- **Vérification** : capture avant/après navigation aller-retour → 12 barres de même hauteur ; `data-e065-value` identique ; `replaceChildren` est bien utilisé en `E065.js:180`, jamais d'écriture HTML brute.

## E065-05 — Graine non affichée à côté du visuel qu'elle commande

- **Problème / preuve** : le principe directeur du chantier est « graine affichée si visuel aléatoire » (`themes.json:72`). Un visuel déterministe mais dont la graine resterait dans une variable interne ne peut pas être audité : rien ne relie le dessin à sa cause. Aucun mécanisme de ce type n'existe dans `chronology.js:208-543`.
- **Solution** : `E065.js:240` affiche « Graine : … — source : … » dans `#chronology-v2-e065-seed` (défini `:28`, créé `:209`), et `E065.js:241` ajoute une légende `#chronology-v2-e065-caption` (`:30`, `:211`) qui relie explicitement les 12 barres à cette graine. La même graine est reprise dans l'`aria-label` du bandeau (`:247`) et dans `data-e065-seed` (`:248`).
- **Impact** : la condition « graine affichée si visuel aléatoire » est remplie au sens fort — la graine est visible, textuelle, indexable et adjacente au dessin.
- **Risque** : la chaîne de graine fait environ 24 caractères ; `overflow-wrap: anywhere` (`E065.js:47`) évite le débordement en 390×844, au prix d'un retour à la ligne sur les écrans très étroits.
- **Effort** : S.
- **Vérification** : capture 390×844 → graine et légende lisibles sans défilement horizontal ; comparer le texte de `#chronology-v2-e065-seed` à `data-e065-seed` et à la graine citée dans l'`aria-label` : les trois doivent coïncider.

## E065-06 — Aucune empreinte de stabilité entre deux rendus

- **Problème / preuve** : `chronology.js:541` relance `runEnhancementsV2` à chaque rendu et la coque reconstruit `#app` (cf. `UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:119`). Sans témoin chiffré, une dérive du dessin entre deux rendus d'un même état passerait inaperçue, d'autant que `registry.js:39-42` avale les erreurs de greffon.
- **Solution** : `E065.js:181-186` calcule une empreinte pondérée des 12 hauteurs (somme modulo 2³², en hexadécimal) et la stocke dans `data-e065-checksum`. `E065.js:234-236` compare graine et empreinte aux valeurs mémorisées (`:105-106`) et incrémente un compteur de divergences uniquement si la graine est identique et l'empreinte différente. Le résultat est affiché en `E065.js:242` et publié dans `data-e065-divergences` (`:250`).
- **Impact** : la stabilité devient une mesure falsifiable : un changement de graine est attendu, une divergence à graine constante ne l'est pas.
- **Risque** : l'empreinte n'est pas une signature cryptographique ; elle détecte une dérive du bandeau, pas une altération hostile. Le compteur est volatile (état module, `:104-110`) et repart à zéro au rechargement de la page — hypothèse explicite dans le libellé « divergences observées ».
- **Effort** : M.
- **Vérification** : relecture `E065.js:234-236` ; harnais — deux rendus sans changement d'état → `data-e065-divergences="0"` et empreinte inchangée ; régénération → nouvelle graine, empreinte différente, divergences toujours à 0.

## E065-07 — Aucun audit visible des sources de variation interdites

- **Problème / preuve** : `registry.js:28-44` n'impose aucune contrainte sur les API utilisées par les greffons et n'expose que `viewDiagnostics()` (`:46-48`), qui liste les identifiants et les erreurs. L'utilisateur n'a donc aucun moyen de savoir si un changement de rendu vient d'une donnée, d'une graine ou d'une source non déterministe.
- **Solution** : `E065.js:243` affiche un audit en texte réel dans `#chronology-v2-e065-audit` (`:32`, `:213`) : « 0 tirage natif non déterministe · 0 horodatage · 0 requête réseau · 0 minuteur ». Ce compte-rendu décrit le module lui-même, dont l'en-tête (`E065.js:16-21`) fixe les invariants ; aucun appel réseau, aucun chronomètre et aucun minuteur n'est présent dans le code.
- **Impact** : le contrat est énoncé à côté du visuel, dans le même panneau que la graine et l'empreinte, ce qui permet une vérification croisée immédiate.
- **Risque** : c'est une déclaration de conformité du greffon, pas un analyseur statique exécuté à l'exécution — les contrôles automatiques restent ceux du harnais (voir tableau final). Aucune régénération n'est déclenchée par cet audit.
- **Effort** : S.
- **Vérification** : contrôle statique — zéro occurrence des API interdites dans `E065.js` ; relecture `E065.js:243` ; le libellé reste stable après navigation aller-retour.

## E065-08 — Aucun moyen contrôlé de faire varier la graine

- **Problème / preuve** : la vue possède bien un état local mutable (`local.query`, `local.tag` en `chronology.js:17`) et un `focusIntent` (`:18`), mais aucun compteur de génération explicite : pour obtenir un nouveau motif, un greffon devrait introduire une variation opaque (horodatage ou tirage), précisément ce que le chantier interdit.
- **Solution** : `E065.js:217-227` crée un bouton `#chronology-v2-e065-regenerate` (`:33`) de type `button`, Activation native, avec un `title` explicite. Son écouteur unique, posé sous la garde `buttonBound` (`:109`, `:221-227`), incrémente `generation` (`:104`) puis redessine depuis le contexte mémorisé `currentCtx` (`:193`, `:224`). Le compteur est affiché dans le récapitulatif (`:244`) et intégré à la graine (`:146`).
- **Impact** : la seule façon de changer le visuel est une action utilisateur dont la valeur est visible ; le passage d'une graine à l'autre est reproductible (compteur 0, 1, 2…).
- **Risque** : le bouton est le seul arrêt Tab ajouté par la lentille ; il mesure 36 px de haut et passe à 44 px sous 620 px (`E065.js:77-87`), avec un anneau de focus `:focus-visible` (`:84`). `aria-pressed` n'est pas employé : il ne s'agit pas d'une bascule indépendante mais d'une action.
- **Effort** : M.
- **Vérification** : clic → `generation` passe à 1, la graine se termine par `-1`, le bandeau change et « générations : 1 » s'affiche ; clic répété → `-2` ; navigation puis retour → le compteur module reste intact et la graine est restaurée.

## E065-09 — Replis mouvement réduit / couleurs forcées absents du greffon

- **Problème / preuve** : `chronology.js:90-92` neutralise les transitions des bandes et cartes, et `registry.js:33-36` expose `reducedMotion()`, mais le registre V2 n'impose rien aux greffons : un bandeau décoratif pourrait animer ses barres et ignorer la préférence système. La passe 1 documente par ailleurs l'exigence de repli `forced-colors` (`UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:95-97`).
- **Solution** : `E065.js:89-91` impose `transition: none` et `animation: none` sur le panneau et ses descendants en `prefers-reduced-motion`, `:92-101` fournit un repli `forced-colors` (fond `Canvas`, texte `CanvasText`, barres en `CanvasText`), `:85-88` un repli 620 px. `E065.js:238` lit `ctx.reducedMotion()`, l'affiche dans le récapitulatif (`:244`) et le publie dans `data-e065-reduced` (`:251`).
- **Impact** : aucun mouvement propre au greffon, information conservée en couleurs forcées, état de préférence lisible et mesurable.
- **Risque** : la préférence est lue à chaque rendu depuis `window.matchMedia` via le registre ; un changement en cours de session sans re-rendu ne sera pas répercuté — comportement identique à celui des autres greffons V2.
- **Effort** : S.
- **Vérification** : émuler `prefers-reduced-motion: reduce` → `data-e065-reduced="1"` et « mouvement réduit : oui » ; émuler `forced-colors: active` → bordures et barres visibles ; relecture — aucune règle d'animation propre dans `E065.js:41-102`.

## E065-10 — Re-render : unicité du panneau, du CSS, de l'écouteur et de la graine

- **Problème / preuve** : `chronology.js:539-542` appelle successivement `runEnhancements` puis `runEnhancementsV2` à chaque rendu ; `registry.js:39-42` rejoue les greffons et isole leurs erreurs ; `registry.js:13-19` ne garantit que l'unicité du `<style>`. Ni les nœuds ni les écouteurs ne sont protégés. `v2/index.js:65` importe le module : le stub initial (`register('E065', () => {})`) devait être remplacé sans toucher à ce point d'entrée.
- **Solution** : `E065.js:152-160` fournit `ensureNode()` avec garde d'existence et déplacement dans le parent courant pour les dix IDs préfixées `chronology-v2-e065-` (`:25-34`) ; `:24` et `:197` imposent un seul `CSS_ID` / un seul `ctx.css` ; `:221-227` un seul écouteur de clic sous garde module ; `:254` un seul `register('E065', ctx => { … })`. Le `replaceChildren` de `:180` ne touche qu'aux barres non identifiées. Les compteurs module (`:104-110`) survivent aux rendus sans créer de nœud, et `write()` (`:162-164`) déduplique les écritures.
- **Impact** : aucun doublon de panneau, de badge, de bandeau, de bouton ou de feuille de style après navigation aller-retour ; aucune fuite d'écouteur sur une longue session ; la graine et le compteur de génération restent cohérents.
- **Risque** : un nœud retrouvé dans un ancien parent détaché est déplacé, jamais cloné ; ses `data-e065-*` sont réécrits à chaque `render()` (`:248-251`), donc jamais périmés. Le registre neutraliserait silencieusement une erreur : `node --check` et les gardes d'existence constituent la première ligne de défense.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E065.js` → PASS ; relecture — un seul `register`, un seul `ctx.css`, un seul `addEventListener`, dix IDs toutes préfixées ; rejeu rendu → navigation → rendu : un seul `#chronology-v2-e065-panel`, un seul `#chronology-v2-e065-regenerate`, un seul `<style id="chronology-v2-e065">`, `data-e065-divergences="0"`.

## Statut d'implémentation

Les dix chantiers E065-01 à E065-10 sont implémentés dans `src/views/chronology/v2/E065.js` uniquement (254 lignes). CSS injecté via `ctx.css('chronology-v2-e065', …)` (`E065.js:24`, `:197`). IDs uniques préfixées `chronology-v2-e065-` avec garde d'existence (`ensureNode`, `E065.js:152-160`). Un seul `register('E065', ctx => { render(ctx); })` (`E065.js:254`), conforme à l'import `v2/index.js:65`. La graine est dérivée du DOM (`:136-147`), le générateur est local (`:123-132`), le visuel est calculé depuis la graine (`:168-187`) et sa légende est affichée (`:240-241`, `:247`). Aucun fichier partagé modifié, aucun sélecteur de test renommé, aucune donnée inventée, aucune API non déterministe employée.

## Blocages / limites inter-domaines

- Le panneau est purement descriptif et observationnel : il ne peut pas modifier `chronology.js` (données, filtre, focus), `v2/registry.js` (contrat des greffons, diagnostic silencieux), `v2/index.js` (point d'entrée), ni la feuille globale — tous fichiers en lecture seule.
- L'audit de `E065.js:243` porte sur le comportement du greffon, pas sur une analyse statique de l'ensemble du dépôt : vérifier l'absence d'appels non déterministes ailleurs relève du harnais de qualité (lentilles E081/E082) et du maître d'œuvre.
- La source de graine (`E065.js:136-142`) dépend des `data-*` et `aria-current` posés par `chronology.js:287-290, 388-391` : un renommage de ces attributs par une autre lentille ou une refonte de la vue dégraderait la précision de la graine sans la rendre aléatoire.
- Les compteurs (génération, divergences, rendus) sont volatils, stockés dans l'état module (`E065.js:104-110`) : ils survivent aux re-rendus mais pas à un rechargement complet de la page.
- Le bandeau est décoratif et strictement déterministe ; il ne remplace ni une image de donnée (`chronology.js:396-401`, `:433-439`) ni une mesure de performance réelle (FPS, latence) — domaine des lentilles E061, E069 et E070.
- La coque reconstruisant `#app`, le panneau est réutilisé quand il est détaché puis recréé sinon ; un ordre d'insertion contraire n'est pas possible puisque `ensureNode` préserve l'ordre existant, mais le panneau reste le dernier enfant de `#atlas-chrono-main` uniquement lors de la première construction.
