## E093-01 — Aucune carte sémantique des familles dans la vue

- **Problème / preuve** : le stub initial se limitait à `register('E093', () => {});` (stub `E093.js:4`, avant remplacement) : aucun nœud n'était créé, donc aucune carte des familles n'existait dans la vue. Le thème `themes.json:103` demande pourtant une « carte illustrative ». Le modèle E049 montre la discipline attendue : un `<section role="region">` unique avec titre (`E049.js:193-195`) et une feuille CSS dédiée (`:43-91`).
- **Solution** : `E093.js:252-259` crée le `<section id="chronology-v2-e093-map" role="region" aria-labelledby="…chronology-v2-e093-title">` ; `:261-267` le titre `<h2>` et le préambule ; `:340-341` la `<ul id="chronology-v2-e093-family-list">` ; `:365` assemble l'ordre final. Le style du conteneur est en `:46-58`, les IDs en `:32-43`.
- **Impact** : la carte devient un repère sémantique unique et indexable, sans modale ni superposition, en fin de `#atlas-chrono-main`.
- **Risque** : `#atlas-chrono-main` peut ne pas exister dans une rendu intermédiaire ; `:245-248` replie alors sur `ctx.layout` puis `document.body`, garantissant la greffe.
- **Effort** : M.
- **Vérification** : relecture `:252-259, 365` ; harnais — un seul `#chronology-v2-e093-map` avec `role="region"`, un `aria-labelledby` pointant vers l'ID du `<h2>`, une seule `<ul>` de familles.

## E093-02 — Aucun signal visuel non coloré pour distinguer les familles

- **Problème / preuve** : le stub (`E093.js:4`) n'affichait rien ; aucune famille ne pouvait être distinguée, a fortiori sans couleur. Le modèle E049 rappelle l'exigence « aucune information portée par la seule couleur » (`E049.md:113`, chantier E049-09).
- **Solution** : `E093.js:299-301` donne à chaque carte un glyphe textuel (`◆ ➤ ▦ ✦ ○`, masqué aux lecteurs d'écran via `aria-hidden`) et un nom ; `:303-306` ajoute la forme en toutes lettres (« la forme et le glyphe, jamais la seule couleur ») ; `:294` pose `data-e093-forme` ; `:74-85` varie bordure et arrondi par forme (double, flèche, tirets, cercle, pointillés) ; `:265` l'énonce dans le préambule.
- **Impact** : chaque famille reste identifiable en niveaux de gris, en `forced-colors` (`:124-132`) et pour une technologie d'assistance.
- **Risque** : les glyphes Unicode dépendent de la police ; le texte de forme (`:303-306`) est le filet de sécurité, indépendant du rendu du glyphe.
- **Effort** : M.
- **Vérification** : relecture `:74-85, 294, 299-306` ; capture en niveaux de gris et `forced-colors: active` — cinq formes distinctes + cinq libellés de forme lisibles.

## E093-03 — Aucun comptage dérivé du DOM par famille

- **Problème / preuve** : le stub (`E093.js:4`) ne produisait aucun chiffre. Le domaine F exige des nombres dérivés du DOM (`themes.json:51`, E051) ; le modèle E049 mesure lui-même ses arrêts Tab en lecture seule (`E049.js:150-169`).

- **Solution** : `E093.js:121-123` neutralise transitions/animations en `prefers-reduced-motion`, `:124-132` ajoute un repli `forced-colors`, `:133-137` un repli d'impression ; `:250` lit `ctx.reducedMotion()`, `:259` publie `data-e093-reduced`, `:358-363` l'énonce en texte ; `:181-193` (`ensureNode`), `:195-197` (`write`), `:199-201` (`setData`) garants l'idempotence ; `:179, 242` comptent les installations, `:243` appelle une seule fois `ctx.css`, `:368` un seul `register`.
- **Impact** : aucun mouvement parasite, contraste préservé, aucun doublon de carte, de feuille de style ou d'ID après navigation aller-retour.
- **Risque** : le compteur d'installations est volatile (état module), mais il est réécrit en `data-e093-installs` (`:258`) à chaque rendu ; le registre neutraliserait silencieusement une erreur, d'où l'importance de `node --check` et des gardes.

## Blocages / limites inter-domaines

- Le module est purement descriptif et pédagogique : il ne modifie ni `registry.js`, ni `index.js`, ni `styles.css`, ni `src/views/chronology.js`, ni une autre lentille. L'intégration dans le point d'entrée V2 (import du module) relève du maître d'œuvre.
- Les comptages E093-03 dépendent des marqueurs `[data-family]`, `.point-family-*` ou `[data-point-family-*]` émis par la vue. Si la V2 n'en émet aucun, la carte affiche des zéros explicites : la lentille ne peut pas inventer les données de la vue sans violer le contrat.
- Les ancres E093-08 pointent vers `#atlas-chrono-main` si aucun ID de famille n'est disponible ; un ciblage plus fin exigerait une convention d'ID portée par `chronology.js`, fichier non possédé.
- Les exemples (E093-07) sont des cas d'école illustratifs et non des assertions historiques ; une validation scientifique du contenu sort du périmètre de cette lentille narration.
- Le CSS exploite les variables de thème (`--line`, `--gold`, `--ink-soft`, …) définies dans `styles.css` ; en leur absence, les replis `forced-colors` et d'impression (`:124-137`) gardent la carte lisible.
