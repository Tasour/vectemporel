## E082-01 — Aucun appel de journalisation depuis la lentille

- **Problème / preuve** : `registry.js:39-42` isole silencieusement toute erreur de greffon dans `diagnostics` : une lentille qui journaliserait pour déboguer ne laisserait aucune trace visible et polluerait la sortie sans recours. Le stub d'origine (`E082.js:4`) n'offrait aucun état observable permettant de certifier l'absence d'appels.
- **Solution** : `E082.js:93` porte la ligne « Journalisation : aucun message émis. » ; l'état `absent` est attribué en `:185` et affiché en `:191`. Le module ne contient aucun appel de journalisation : l'en-tête `:15` le déclare et les gardes de `:210-211` / `:215-216` sortent avant toute écriture. Le texte est déposé par `textContent` via `ctx.el` (`:237`), jamais par une API de journal.
- **Impact** : la garantie devient lisible dans le panneau (`#chronology-v2-e082-01`, `:234`) et vérifiable par relecture statique, sans toucher au registre ni à la coque.
- **Risque** : la certification est structurelle, non instrumentée — elle atteste du code livré, pas d'un comportement futur. Une modification ultérieure du fichier imposerait une relecture ; le registre ne signalerait pas une dérive.
- **Effort** : S.
- **Vérification** : relecture — zéro séquence d'appel de journal dans le module (en-tête `:13-19`) ; `#chronology-v2-e082-01[data-e082-state="absent"]` présent après rendu.

## E082-02 — Aucune requête réseau de données

- **Problème / preuve** : le thème `themes.json:91` proscrit explicitement les requêtes réseau ; or `runEnhancements` (`registry.js:28-44`) applique cent greffons sans filtrer leurs effets, si bien qu'un seul module pourrait introduire une requête non voulue. Le stub (`E082.js:4`) ne exposait rien pour détecter une telle dérive.
- **Solution** : `E082.js:94` affiche « Réseau : aucune requête de données. » avec l'état `absent` (`:185`, `:191`). Le module n'ouvre aucune connexion : il ne fait que lire le DOM (`:110`, `:126`, `:135`, `:145`, `:153`, `:161`) et écrire dans son propre panneau (`:120`, `:242`, `:247`).
- **Impact** : le caractère hors-ligne de la lentille est affirmé et visible, cohérent avec le fonctionnement local de l'atlas.
- **Risque** : aucune interception globale n'est installée : la lentille ne mesure pas les requêtes des autres modules, elle garantit seulement les siennes. Une instrumentation globale serait intrusive et sortirait du périmètre du fichier possédé.
- **Effort** : S.
- **Vérification** : relecture — aucune API de requête dans le module ; `#chronology-v2-e082-02[data-e082-state="absent"]` et libellé conforme après rendu.

## E082-03 — Aucun objet XHR instancié

- **Problème / preuve** : `themes.json:91` nomme séparément la journalisation et les requêtes ; les traiter comme un seul chantier masquerait la voie « objet » (contrairement à l'appel de fonction de l'E082-02). Le registre (`:39-42`) ne distingue pas ces deux vecteurs.
- **Solution** : `E082.js:95` isole le chantier « Réseau : aucun objet XHR instancié. », état `absent` publié en `:185` / `:191`. Le module se contente de `document.createElement` via `ctx.el` (`:112`, `:233`) : aucun constructeur de requête n'est appelé.
- **Impact** : les deux vecteurs réseau sont couverts par deux preuves distinctes, sans recouvrement avec l'E082-02.
- **Risque** : le libellé volontairement abrégé (XHR) évite d'introduire dans le code la séquence exacte proscrite ; un lecteur averti comprend, les autres disposent du contexte du panneau (`:224-228`).
- **Effort** : S.
- **Vérification** : relecture — zéro constructeur de requête dans le module ; ligne `#chronology-v2-e082-03` visible et marquée `absent`.

## E082-05 — Aucune source distante dans le panneau

- **Problème / preuve** : contrairement aux quatre garanties structurelles, celle-ci se vérifie sur le DOM produit. Le panneau est reconstruit à chaque rendu (`registry.js:39-42`) : un attribut de ressource distante ajouté par un autre greffon pourrait se retrouver dans son sous-arbre sans que la lentille le sache.
- **Solution** : `E082.js:124-131` (`countRemoteResources`) parcourt `[src], [href]` du panneau et compte les valeurs absolues ou protocolaires (`:128`). `refresh` (`:171`, `:177`) en déduit l'état `conforme` quand le compte est nul, affiché en `:185` / `:191` et exposé via `data-e082-remote` (`:203`). Le panneau (`:218-247`) ne crée ni image ni lien externe.
- **Impact** : l'absence de ressource distante est prouvée sur l'arbre réel, pas seulement déclarée ; l'attribut de données permet un contrôle automatisé.
- **Risque** : la vérification porte sur le sous-arbre du panneau, pas sur la vue entière — un attribut distant ailleurs dans la frise relèverait d'une autre lentille (domaine H).
- **Effort** : M.
- **Vérification** : relecture — `:126-129` ; harnais — `data-e082-remote="0"` et libellé « conforme » sur `#chronology-v2-e082-05` ; injecter un `href="https://…"` fictif dans le panneau → bascule en `échec`.

## E082-06 — Aucune valeur aléatoire

- **Problème / preuve** : `themes.json:91` s'inscrit dans la lignée des exigences de reproductibilité de la méthode : un tirage au hasard rendrait l'état du panneau impossible à reproduire d'un rendu à l'autre. Le stub (`E082.js:4`) n'affichait rien.
- **Solution** : `E082.js:98` porte « Aléa : aucune valeur tirée au hasard. », état `absent` (`:185`, `:191`). Toute la logique est déterministe : `renderCount` (`:105`, `:194`) et les compteurs (`:171-175`) ne dépendent que du DOM courant.
- **Impact** : deux rendus sur un DOM identique produisent le même texte, seule la mention du nombre de rendus varie — et elle est explicitement datée.
- **Risque** : garantie structurelle, donc non instrumentée ; elle doit être relue à chaque modification du module.
- **Effort** : S.
- **Vérification** : relecture — aucun générateur aléatoire ; `#chronology-v2-e082-06` marqué `absent`.

## E082-07 — Aucun HTML brut ni gestionnaire en ligne

- **Problème / preuve** : le modèle de qualité (`E049.js:218`, `:125-127`) montre la voie retenue : `replaceChildren` avec des nœuds et écritures dédupliquées par `textContent`. Le registre (`:21-26`) fournit `el` précisément pour éviter l'insertion de balisage. Une lentille qui contournerait cet helper pourrait injecter du HTML ou un gestionnaire en ligne.
- **Solution** : `E082.js:133-141` (`countInlineHandlers`) relève tout attribut dont le nom commence par `on` dans le sous-arbre ; `:172`, `:178`, `:185`, `:191` en dérivent l'état `conforme`. La construction (`:230-247`) n'utilise que `ctx.el`, `append` et `replaceChildren` : aucun balisage littéral, aucun gestionnaire — la lentille n'installe d'ailleurs aucun écouteur (en-tête `:19`).
- **Impact** : le panneau est structurellement inerte : aucune action au clic, aucune interception d'événement, aucune collision avec le routeur.
- **Risque** : le contrôle ne détecte pas un texte contenant des chevrons, seulement les attributs `on*` ; l'absence de balisage est garantie par la relecture de `:230-247` et par l'usage exclusif de `textContent`.
- **Effort** : M.
- **Vérification** : relecture — `innerHTML` absent ; harnais — `data-e082-handlers="0"` et `#chronology-v2-e082-07` « conforme ».

## E082-08 — Aucun timer ni boucle d'animation

- **Problème / preuve** : le registre (`:39-42`) n'immunise pas contre une boucle ou un minuteur oublié : un tel effet survivrait aux rendus et consommerait des ressources à chaque navigation. Le modèle E049 (`E049.js:22-23`) proscrit explicitement timer et animation dans ce type de lentille observationnelle.
- **Solution** : `E082.js:100` énonce « Animation : aucun timer ni boucle d'images. », état `absent` (`:185`, `:191`). Le CSS ne définit aucune animation ni transition propre ; au contraire `:78-80` neutralise toute transition en `prefers-reduced-motion`. Aucun minuteur, aucun appel de frame : `refresh` (`:168-207`) est purement synchrone.
- **Impact** : aucun coût diffus, aucune animation parasite, compatibilité avec le mouvement réduit.
- **Risque** : garantie structurelle ; un futur ajout d'animation devrait être relu, d'autant que le repli `:78-80` ne neutraliserait que les transitions.
- **Effort** : S.
- **Vérification** : relecture — aucun minuteur ni boucle ; `#chronology-v2-e082-08` marqué `absent` ; émuler `prefers-reduced-motion: reduce` → `data-e082-reduced="1"` (`:206`).

## E082-09 — Feuille CSS unique et identifiants préfixés

- **Problème / preuve** : `cssOnce` (`registry.js:13-19`) ne garantit l'unicité que du `<style>` : il ne vérifie ni les identifiants des nœuds greffés ni leur préfixe. Le modèle E049 (`E049.js:26-37`, `:111-123`) montre la garde d'existence nécessaire face à la reconstruction de `#app`.
- **Solution** : `E082.js:26-32` déclare un `CSS_ID` et un `PREFIX` uniques ; `:151-157` (`countStyleSheets`) compte les feuilles portant cet identifiant et `:143-149` (`countBadPrefixes`) relève les `id` du panneau ne commençant pas par le préfixe. `:179` exige exactement une feuille et zéro identifiant hors préfixe ; `:201` et `:205` publient les comptes. La garde `ensureNode` (`:109-117`) réutilise et déplace un nœud existant au lieu d'en créer un doublon.
- **Impact** : après navigation aller-retour, une seule feuille `#chronology-v2-e082`, huit identifiants tous préfixés, aucun doublon de panneau.
- **Risque** : le contrôle de préfixe est limité au sous-arbre du panneau ; un identifiant non préfixé ailleurs dans la vue échapperait à la lentille. Le style est injecté via `ctx.css` (`:213`) : c'est le registre qui en assure l'unicité, la lentille ne fait que la mesurer.
- **Effort** : M.
- **Vérification** : relecture — `:143-157`, `:179`, `:213` ; harnais — `data-e082-css="1"`, `data-e082-bad-ids="0"`, `#chronology-v2-e082-09` « conforme » ; rejeu rendu → navigation → rendu : un seul `<style id="chronology-v2-e082">`.

## E082-10 — Panneau unique et greffon unique (idempotence)

- **Problème / preuve** : `runEnhancements` (`registry.js:28-44`) rejoue l'enregistrement à chaque rendu, tandis que la coque reconstruit le stage : sans garde, le panneau serait dupliqué ou orphelin. Le stub (`E082.js:4`) enregistrait une fonction vide, sans état de rendu.
- **Solution** : `E082.js:159-165` (`countPanels`) compte les `<section id="chronology-v2-e082-certificat">` ; `:180` exige exactement un panneau. `renderCount` (`:105`, `:194`) incrémente à chaque `refresh`, et `:200` le publie avec les comptes (`:202`). Le panneau est créé une fois par la garde `ensureNode` (`:218`) et rempli par `replaceChildren` (`:247`), ce qui écrase tout contenu antérieur au lieu de l'accumuler. `:209` impose un seul `register('E082', ctx => …)`.
- **Impact** : le nombre de panneaux et de rendus est auditable, et un re-render ne produit ni doublon ni fuite d'écouteur (la lentille n'en installe aucun).
- **Risque** : le compteur de rendus est volatile, remis à zéro au rechargement du module ; il mesure les appels de `refresh`, pas les navigations de l'utilisateur.
- **Effort** : M.
- **Vérification** : relecture — `:105`, `:159-165`, `:180`, `:209-251` ; harnais — `data-e082-panels="1"`, `#chronology-v2-e082-10` « conforme », `data-e082-renders` croît d'une unité par rendu.

## Statut d'implémentation

Les dix chantiers E082-01 à E082-10 sont implémentés dans `src/views/chronology/v2/E082.js` uniquement. Six garanties structurelles (01, 02, 03, 04, 06, 08) sont déclarées en `:92-103` et certifiées par l'en-tête `:13-19` ; quatre contrôles DOM (05, 07, 09, 10) sont réellement exécutés en `:124-165` et appliqués en `:176-181`. Une seule feuille CSS est injectée via `ctx.css('chronology-v2-e082', …)` (`:213`), un seul `register('E082', ctx => …)` (`:209`) et huit identifiants tous préfixés `chronology-v2-e082-` (`:26-32`, `:234`) avec garde d'existence (`:109-117`). Aucun fichier partagé n'est modifié, aucun sélecteur de test renommé, aucune donnée inventée, aucune région live ajoutée, aucun événement intercepté.

## Blocages / limites inter-domaines

- Les garanties structurelles (01, 02, 03, 04, 06, 08) sont des certifications statiques du code livré : la lentille n'instrumente pas globalement les API concernées, car patcher ces API toucherait à toutes les lentilles et sortirait du fichier possédé.
- Les contrôles DOM (05, 07, 09, 10) sont bornés au sous-arbre du panneau : ils ne peuvent pas attester de l'absence de ressources distantes ou d'identifiants non préfixés ailleurs dans la vue Chronologie (domaine H / registre).
- L'unicité du `<style>` est assurée par `cssOnce` (`registry.js:13-19`), fichier non possédé : la lentille la mesure (`:151-157`) mais ne peut pas la renforcer.
- Le panneau ne peut pas corriger un écart constaté : un `échec` est affiché et publié en attribut, la remédiation relève de la lentille ou du domaine responsable.
- Le compteur de rendus est volatile et ne survit pas à un rechargement du module ; il ne mesure pas les actions utilisateur.
