## E049-01 — Préférence système lue via `ctx.reducedMotion()` et exposée en texte

- **Problème / preuve** : le contrat V2 fournit `ctx.reducedMotion()` (`E049.js:11`), mais le stub initial (`E049.js:1-4` avant remplacement) se limitait à `register('E049', () => {})` : aucun état de préférence n'était lu ni rendu. Le rapport passe 1 (`UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:95-96`) notait déjà que le registre expose cette fonction sans que la vue n'expose d'état de préférence. Le thème `themes.json:54` exige que ce respect soit effectif et vérifiable.
- **Solution** : `E049.js:245` lit `ctx.reducedMotion()` une fois par rendu (avec repli `false` si l'helper est absent), `:154-156` écrit le libellé dans `#chronology-v2-e049-preference` (`dd` créé en `:228`), et `:169` publie `data-e049-motion` à `1` ou `0` sur le panneau. L'écriture est dédupliquée par `write()` (`:140-142`) et `setData()` (`:144-146`).
- **Impact** : la préférence devient observable sans ouvrir les réglages système ni consulter la console, et sans dépendre d'un effet visuel.
- **Risque** : la valeur initiale peut être périmée si l'utilisateur change la préférence en cours de session ; E049-05 couvre précisément ce cas par l'écoute « change ». Aucune région live n'est ajoutée, conformément au choix de non-bavardage documenté en passe 1 (`UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:59-62`).
- **Effort** : S.
- **Vérification** : relecture `E049.js:245`, `:154-156`, `:169` ; harnais — préférence réduite émulée → `#chronology-v2-e049-preference` contient « oui » et `data-e049-motion="1"` ; préférence normale → « non » et `data-e049-motion="0"`.

## E049-02 — Zéro `@keyframes` et zéro animation propre dans la feuille unique

- **Problème / preuve** : le thème `themes.json:54` impose « zéro animation propre » ; le stub (`E049.js:1-4` avant remplacement) n'injectait aucune feuille et ne garantissait donc rien. Une feuille de lentille pourrait facilement glisser une animation décorative et contredire la préférence système.
- **Solution** : la feuille unique (`E049.js:44-94`) ne contient aucune règle `@keyframes` ni `animation-name`. L'audit `MOTION_AUDIT.keyframes` et `.animations` (`:104-105`) compte ces motifs dans la chaîne CSS source, et `:157` / `:170` publient le résultat (`0`) en texte et dans `data-e049-keyframes`. Les seules occurrences de `animation:` (`:77`) sont des neutralisations `none !important`, volontairement exclues du comptage (commentaire `:39-43`).
- **Impact** : le respect de la préférence est mesurable et falsifiable : si une animation propre est ajoutée, le compteur passe à `1` et le libellé change immédiatement.
- **Risque** : l'audit porte sur la chaîne CSS de ce module, pas sur les feuilles des autres lentilles ni sur `styles.css` ; un mouvement introduit ailleurs échappe à ce compteur (voir « Blocages »).
- **Effort** : S.
- **Vérification** : relecture `E049.js:44-94`, `:104-105` ; recherche textuelle — aucune occurrence de `@keyframes` ni de `animation-name:` hors compteur ; `#chronology-v2-e049-keyframes` affiche `0` et `data-e049-keyframes="0"`.

## E049-03 — Zéro transition propre : l'état ne dépend d'aucune transition CSS

- **Problème / preuve** : une transition, même courte, reste un mouvement : elle contredit une préférence « réduire ». Le passe 1 signalait des transitions neutralisées globalement (`UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:95`, `styles.css:342-344`) et le fait que la vue éteignait ses propres transitions (`:95`, `chronology.js:89-91`), mais la lentille V2 ne disposait d'aucun état propre à ce sujet (`E049.js:1-4` avant remplacement).
- **Solution** : la feuille V2 (`E049.js:45-68`) ne déclare aucune `transition-property`. Le compteur `MOTION_AUDIT.transitions` (`:106`) mesure ce motif, `E049.js:158` l'affiche dans `#chronology-v2-e049-transitions` et `:171` le publie dans `data-e049-transitions`. Le repli `:78` impose `transition: none !important` en cas de préférence réduite, sans jamais définir de transition.
- **Impact** : le panneau s'affiche instantanément dans tous les cas ; aucun changement d'état n'est animé.
- **Risque** : si une règle héritée de la coque applique une transition au panneau, seule la branche « mouvement réduit » la neutralise (`:75-81`) ; en mouvement normal, l'héritage reste sous la responsabilité de `styles.css`, fichier non possédé.
- **Effort** : S.
- **Vérification** : relecture `E049.js:45-68`, `:106`, `:158`, `:171` ; harnais — `#chronology-v2-e049-transitions` = `0`, `data-e049-transitions="0"` ; aucun `transition-property:` dans la feuille `chronology-v2-e049`.

## E049-04 — Aucune boucle rAF, aucun minuteur, aucun mouvement programmé

- **Problème / preuve** : un mouvement peut aussi venir du JavaScript : `requestAnimationFrame`, `setInterval` ou `setTimeout` en boucle. Le stub V2 (`E049.js:1-4` avant remplacement) ne démontrait rien ; le thème `themes.json:54` exige l'absence d'animation propre, y compris programmée. Le rapport passe 1 (`UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:4`) posait déjà l'interdiction de `rAF` et de timer comme invariant de la lentille.
- **Solution** : `E049.js:113-116` déclare `PROGRAMMED = { raf: 0, timers: 0, loops: 0 }` comme fait structurel ; `:160` l'écrit dans `#chronology-v2-e049-programmed` (« rAF 0 · minuteur 0 · boucle 0 ») et `:174` pose `data-e049-programmed="none"`. Le module ne contient aucun `requestAnimationFrame`, `setTimeout`, `setInterval` ni boucle d'animation (en-tête `:19-21`).
- **Impact** : aucun mouvement continu, aucune consommation CPU différée, aucun décalage entre l'état annoncé et le comportement réel.
- **Risque** : les compteurs sont des constantes vérifiées par relecture, non une introspection à l'exécution ; toute modification future du module doit les maintenir à jour — le tableau de vérification (`E049.md`, section finale) rappelle ce contrôle.
- **Effort** : S.
- **Vérification** : relecture intégrale — zéro `requestAnimationFrame`, `setTimeout`, `setInterval`, `Math.random` ; `#chronology-v2-e049-programmed` contient « aucun mouvement programmé » et `data-e049-programmed="none"`.

## E049-05 — Suivi réactif de la préférence par écoute « change », sans polling

- **Problème / preuve** : lire la préférence une seule fois au rendu laisse l'état figé si l'utilisateur bascule « réduire les animations » pendant la session. Le stub (`E049.js:1-4` avant remplacement) n'écoutait rien ; un suivi naïf par sondage introduirait un timer, contraire au thème `themes.json:54` et à l'invariant `:21`.
- **Solution** : `E049.js:184-197` (`bindMedia`) installe un unique écouteur `change` sur `window.matchMedia('(prefers-reduced-motion: reduce)')` (`:187`, `:192`), avec repli historique `addListener` (`:193`) et sortie gracieuse si `matchMedia` est absente (`:186`, `:194`). La garde `mediaBound` (`:185`, `:195`) garantit un seul abonnement. Le callback (`:188-191`) met à jour `preference` puis repeint. `:161-163` et `:177` exposent l'état du suivi.
- **Impact** : l'état suit la préférence en temps réel, sans minuteur ni scrutage périodique.
- **Risque** : `addEventListener` et `addListener` sont mutuellement exclusifs par construction (brièvement `:192-193`) ; sur un environnement ne proposant ni l'un ni l'autre, le module retombe sur la valeur initiale et l'indique explicitement — comportement dégradé mais honnête.
- **Effort** : M.
- **Vérification** : relecture `E049.js:181-197` ; harnais — émuler le basculement de la préférence → `data-e049-motion` et `#chronology-v2-e049-preference` changent sans rechargement ; rejeu `install()` → un seul abonnement (garde `:185`).

## E049-06 — Repli défensif `@media (prefers-reduced-motion: reduce)` borné au panneau

- **Problème / preuve** : même sans animation propre, un style hérité peut animer le panneau. Le passe 1 documentait une neutralisation globale dans `styles.css:342-344` (`UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:95`) ; la lentille V2 ne possède pas `styles.css` et ne peut pas la modifier. Le stub (`E049.js:1-4` avant remplacement) n'avait aucun repli.
- **Solution** : `E049.js:73-81` ajoute une règle `@media (prefers-reduced-motion: reduce)` portant uniquement sur `#chronology-v2-e049-panel` et ses descendants, avec `animation: none !important` (`:77`), `transition: none !important` (`:78`) et `scroll-behavior: auto !important` (`:79`). `MOTION_AUDIT.fallbacks` (`:109`) compte la règle ; `:164` et `:175` la publient (`data-e049-fallback`).
- **Impact** : le dispositif reste robuste même si la coque ou une autre feuille injecte un mouvement dans la zone du panneau, sans neutraliser le reste de l'application.
- **Risque** : la neutralisation est scopée au panneau par choix — elle ne protège pas la frise ni la fiche ; une protection globale relève de `styles.css` (voir « Blocages »). Les trois déclarations sont des valeurs d'arrêt, jamais des valeurs animées.
- **Effort** : S.
- **Vérification** : relecture `E049.js:73-81`, `:109`, `:164`, `:175` ; émulation `prefers-reduced-motion: reduce` → `data-e049-fallback="1"` et libellé « 1 règle de neutralisation » ; aucun mouvement visible sur le panneau.

## E049-07 — Aucune transformation, aucun défilement fluide

- **Problème / preuve** : `transform`, `translate`, `scale` ou `scroll-behavior: smooth` produisent un mouvement même sans `@keyframes` ni transition. Le thème `themes.json:54` couvre « zéro animation propre » au sens large ; le stub V2 (`E049.js:1-4` avant remplacement) ne garantissait pas leur absence.
- **Solution** : `MOTION_AUDIT.transforms` et `.smoothScroll` (`:107-108`) comptent ces motifs dans la feuille unique ; `:159` affiche « 0 transformation · 0 défilement fluide » dans `#chronology-v2-e049-transforms`, et `:172-173` publient `data-e049-transforms` et `data-e049-smooth`. Aucune règle de la feuille (`:45-93`) n'utilise ces propriétés ; le repli `:79` force au contraire `scroll-behavior: auto`.
- **Impact** : ni glissement d'entrée, ni zoom, ni défilement animé : la lecture du panneau est instantanée et stable.
- **Risque** : l'audit est textuel et sensible à la forme des déclarations ; un futur raccourci CSS ou une fonction `transform()` écrite autrement devrait être ajouté au motif de `E049.js:107` — la relecture du tableau final couvre ce point.
- **Effort** : S.
- **Vérification** : relecture `E049.js:45-93` et `:107-108` ; `#chronology-v2-e049-transforms` = « 0 transformation · 0 défilement fluide », `data-e049-transforms="0"`, `data-e049-smooth="0"`.

## E049-08 — Bilan textuel cumulé : aucune information portée par le seul mouvement

- **Problème / preuve** : indicateur d'état animé ou simple changement de teinte rendent l'information inaccessible quand le mouvement est réduit ou la couleur indisponible. Le stub (`E049.js:1-4` avant remplacement) n'affichait rien ; le passe 1 insistait sur des écritures textuelles dédupliquées et sans region live concurrente (`UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:59-62`).
- **Solution** : `E049.js:238-239` crée un paragraphe `#chronology-v2-e049-bilan` ; `:167` y écrit un récapitulatif dérivé des compteurs (`keyframes`, `transitions`, `transforms`, `rAF`, `minuteur`) et de la préférence courante. `:148-149` borne le choix : texte visible ordinaire, sans `role="status"`, sans `aria-live`, sans dépendance à un déplacement.
- **Impact** : l'état complet est lisible par lecture de l'écran, par navigation virtuelle et sur impression ; aucun bavardage sonore ajouté.
- **Risque** : le bilan n'est pas annoncé spontanément : c'est un choix délibéré pour ne pas concurrencer les trois régions live existantes du routeur, de la vue et de la coque (passe 1, `:57-62`). L'utilisateur doit naviguer jusqu'au panneau pour le lire.
- **Effort** : S.
- **Vérification** : relecture — zéro `role="status"`, zéro `aria-live` dans `E049.js` ; harnais — le bilan contient les cinq chiffres et la mention « Aucun mouvement n'est créé » en préférence normale, « Le repli système neutralise tout mouvement hérité » en préférence réduite.

## E049-09 — Couleurs forcées : état lisible par le texte et la bordure

- **Problème / preuve** : les valeurs `#chronology-v2-e049-*` sont normalement dorées (`E049.js:64`, `:53`). En `forced-colors: active` ou pour une personne ne distinguant pas cette teinte, une information portée par la seule couleur disparaît. Le passe 1 plaçait ce risque dans le domaine responsive (`UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:96`, `E077`) ; en V2 il est traité ici sous l'angle « mouvement réduit » : l'état ne doit reposer ni sur un mouvement ni sur une teinte.
- **Solution** : `E049.js:82-93` ajoute `@media (forced-colors: active)` avec `CanvasText` / `Canvas` (`:84-92`) et une bordure gauche conservée (`:86`). `MOTION_AUDIT.forced` (`:110`) compte la règle ; `:165` affiche « État porté par le texte et la bordure, pas par le mouvement ni la seule couleur » et `:176` pose `data-e049-contrast="text+border"`. Les libellés de `:154-167` doublent systématiquement l'état en mots.
- **Impact** : contraste préservé et état compréhensible en couleurs forcées, y compris si le mouvement est réduit.
- **Risque** : le repli `forced-colors` est propre au panneau ; la vue et la coque gardent leurs propres règles, non modifiées. La mesure de contraste numérique (≥ 4,5:1) reste à valider par un outil dédié — E049 ne la recalcule pas.
- **Effort** : S.
- **Vérification** : relecture `E049.js:82-93`, `:110`, `:165`, `:176` ; émulation `forced-colors: active` → bordure et texte visibles, `data-e049-contrast="text+border"` ; aucune information transmise uniquement par la couleur dorée.

## E049-10 — Idempotence multi-rendus : IDs, feuille CSS et écouteur uniques

- **Problème / preuve** : le contrat V2 impose des gardes d'existence et une seule feuille CSS. Le stub (`E049.js:1-4` avant remplacement) n'avait ni DOM ni feuille ; la coque reconstruisant le stage, un greffon naïf produirait un panneau doublon, une feuille dupliquée et un écouteur `change` supplémentaire à chaque rendu. Le passe 1 documentait le même risque pour la passe 1 (`UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:102-109`).
- **Solution** : `E049.js:130-138` (`ensureNode`) réutilise et déplace un nœud existant au lieu d'en créer un second ; `:24` et `:214` imposent un seul `CSS_ID` / `ctx.css` ; `:185` et `:195` gardent un seul abonnement `matchMedia` ; `:243` reconstruit les enfants via `replaceChildren` (`:241-243`) plutôt que `innerHTML` ; `:256` enregistre un seul `register`. `:166` et `:178` publient le compteur de rendus (`data-e049-renders`) et le libellé `#chronology-v2-e049-renders`.
- **Impact** : navigation aller-retour et rendus successifs laissent un seul panneau, une seule liste de neuf lignes, une seule feuille `chronology-v2-e049` et un seul écouteur : aucun doublon d'identifiant, aucune fuite mémoire.
- **Risque** : `ensureNode` déplace un nœud retrouvé dans un ancien parent détaché, il ne le clone pas ; ses attributs `data-e049-*` sont réécrits à chaque `paint()` (`:169-178`), donc jamais périmés. Le compteur `installs` (`:118`, `:213`) survit aux rendus mais n'est pas persistant entre rechargements de page — c'est un diagnostic de session, pas une mesure de production.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E049.js` → PASS ; relecture — un seul `register` (`:256`), un seul `ctx.css` (`:214`), un seul `matchMedia(...).addEventListener` (`:192`), douze IDs DOM tous préfixés `chronology-v2-e049-` (`:25-36`) ; rejeu rendu → navigation → rendu : un seul `#chronology-v2-e049-panel`, un seul `<style id="chronology-v2-e049">`.

## Blocages / limites inter-domaines

- L'hôte d'insertion privilégie `#atlas-chrono-main` (`E049.js:37`, `:216`) par continuité avec la passe 1 ; si la passe V2 renomme cet hôte, le repli `ctx.stage || ctx.layout` (`:216`) prend le relais. Le fichier `src/views/chronology.js` n'est pas modifié.
- `ctx.reducedMotion()` est fourni par le registre partagé : la lentille le consomme (`:245`) mais ne peut pas en corriger la source. Si l'helper renvoie une valeur erronée, l'état affiché l'est aussi ; l'écoute `matchMedia` (`:184-197`) offre un second point de vérité côté navigateur.
- La neutralisation globale des animations reste dans `styles.css` (passe 1, `UNIFIED_AUDIT/CHRONOLOGIE/views/E049.md:95`, `:342-344`) : E049 ne neutralise que son propre panneau (`:75-81`) et ne protège ni la frise ni la fiche, ni les mouvements éventuellement créés par d'autres lentilles V2.
- Les compteurs de la feuille (`:104-110`) et les compteurs de mouvement programmé (`:116`) décrivent ce module seul ; ils ne valident pas les autres feuilles CSS ni les autres modules, et exigent une relecture à chaque modification du fichier.
- L'audit `forced-colors` (`:84-92`) garantit la présence d'un repli textuel, pas une mesure de contraste chiffrée — celle-ci relève d'un outil de validation dédié (domaine E047 / H077).
- Le harnais DOM (préférence initiale, bascule « change », compteurs à zéro, déduplication, re-render) et les captures 1658×1150 / 390×844 restent à rejouer par l'agent maître ; ce rapport se limite à la preuve statique et au contrôle syntaxique.
