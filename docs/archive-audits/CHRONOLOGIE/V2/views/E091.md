## E091-01 — Kicker « Frise chronologique » non ancré ni nommé dans la vue

- **Problème / preuve** : `chronology.js:228-232` enchaîne `<h1>Chronologie · ${country.name}</h1>`, un `<p class="view-lede">` et un indice clavier de 8 px, sans jamais écrire « Frise chronologique » comme kicker situé. Les seuls `.aside-kicker` (`chronology.js:421-422`, `:530-531`) portent des compteurs (« Repère 1 / N », « Aucun repère sélectionné ») : ce sont des étiquettes d'état, pas un chapô. Le modèle E049 confirme que l'indice d'origine reste un texte minuscule non narratif (`E049.md:23`).
- **Solution** : `E091.js:201-214` définit `lireSIGNAL()` : il cherche `.view-lede`, puis `.atlas-chrono-h1`, puis `#atlas-chrono-title`, mémorise le texte réel et publie `data-v2e091-kicker="dom"` (ou `"repli"` avec `E091.js:124`). `E091.js:256-264` crée le conteneur `#chronology-v2-e091-story` (`role="region"`, `aria-labelledby`) et le paragraphe `#chronology-v2-e091-kicker` ; `:305-306` insère le bandeau juste après le chapô via `placerApres()` (`:179-185`), sans le déplacer ni l'écraser. Le libellé visible est `Kicker observé : « … »` (`:220`).
- **Impact** : le kicker existe enfin comme objet textuel nommé et daté de la lecture du DOM ; le chapô d'origine reste intact et l'insertion n'ajoute aucun arrêt Tab.
- **Risque** : si la coque masque les panneaux de lentilles, le bandeau peut être déplacé dans le tiroir de diagnostic (`E049.md:118` décrit ce mécanisme) ; le texte reste lisible et les attributs `data-v2e091-*` demeurent. Le repli `KICKER_REPLI` n'est utilisé que si aucun chapô n'est trouvé.
- **Effort** : S.
- **Vérification** : relecture `E091.js:201-214` ↔ `chronology.js:228-232` ; harnais — `data-v2e091-kicker="dom"` et un seul `#chronology-v2-e091-kicker` dont le texte contient le chapô réel ; le `<p class="view-lede">` d'origine est inchangé.

## E091-02 — Chapô descriptif sans accroche narrative

- **Problème / preuve** : `chronology.js:231` énonce un état (« Une seule ère à la fois… ») sans promesse de lecture : la phrase décrit la structure mais ne dit pas ce que le lecteur va suivre. Le modèle E049 relève que la vue est « déjà saturée d'indices textuels » (`E049.md:60`) : ajouter un indice de plus ne suffit pas, il faut un récit.
- **Solution** : `E091.js:128` porte l'accroche unique (« Une frise chronologique n'est pas une pile de dates : c'est un récit qui se parcourt… »), inscrite dans `#chronology-v2-e091-accroche` (`:266-267`) et typographiée en `:78`. L'état est publié dans `data-v2e091-accroche="1"` (`:225`).
- **Impact** : le kicker devient une promesse de lecture assumée, distincte de l'indice clavier et du statut (`chronology.js:248-257`).
- **Risque** : l'accroche est une phrase fixe, donc datée de la relecture du contrat ; elle ne prétend pas décrire un pays particulier et n'invente aucune donnée historique.
- **Effort** : S.
- **Vérification** : relecture `E091.js:128` ↔ `:266-267` ; désactiver le CSS du module → l'accroche reste lisible en texte sémantique dans `#chronology-v2-e091-story`.

## E091-03 — Les deux mots du kicker jamais expliqués

- **Problème / preuve** : le titre `chronology.js:228` et le chapô `:231` emploient « Chronologie » sans expliquer ses deux composantes. Le glossaire du domaine J est porté par la lentille E095 (`themes.json:95` : ère, repère, confiance) : la lentille E091 doit rester sur les mots du kicker uniquement pour ne pas le chevaucher.
- **Solution** : `E091.js:134-139` définit deux paires terme/définition (« Frise » = support visible, « Chronologique » = du grec *chronos*, le temps). Elles sont rendues dans une `<dl>` `#chronology-v2-e091-mots` dont chaque ligne est un couple `<dt>/<dd>` (`:269-271`, helper `:238-242`), disposé en deux colonnes en `:83-89`. Le compte est publié dans `data-v2e091-mots` (`:226`).
- **Impact** : le vocabulaire du kicker devient explicable en une lecture, sans empiéter sur le glossaire E095 ni sur l'explication « repère / point » de E092.
- **Risque** : l'étymologie de *chronologique* est un fait de langue, pas une donnée historique ; aucune autre étymologie hasardeuse n'est avancée pour « frise », dont seule la fonction de support est décrite.
- **Effort** : S.
- **Vérification** : relecture `E091.js:134-139` ↔ `:269-271` ; harnais — deux `<dt>` et deux `<dd>`, colonne de terme ramenée à 100 % sous 620 px (`:100-103`), aucune référence à « ère / repère / confiance » comme entrée de glossaire.

## E091-04 — Aucune question directrice pour ouvrir la lecture

- **Problème / preuve** : le chapô `chronology.js:231` et le statut `chronology.js:250-256` sont purement déclaratifs ; la vue ne formule nulle part la question que la frise aide à résoudre. Le modèle E049 note l'absence de synthèse et de fil narratif dans la vue (`E049.md:63`, `:117-123`).

- **Impact** : la lecture s'ouvre sur une question, ce qui donne au récit une direction sans préjuger de la réponse.
- **Risque** : la question est rhétorique et ne doit pas devenir une commande : aucun bouton, aucun `tabindex`, aucun gestionnaire n'est attaché au paragraphe.
- **Effort** : S.
- **Vérification** : relecture `E091.js:141` ↔ `:273-274` ; harnais — un seul paragraphe de question présent dans le bandeau, aucun arrêt Tab ajouté dans la vue.

## E091-05 — Lecture par ères sans arc narratif en trois temps

- **Problème / preuve** : la frise est découpée en ères (`chronology.js:282-308`) et l'aside présente tantôt la fiche, tantôt l'état vide (`chronology.js:417-419`, `:530-535`) : la structure est là, mais aucun enchaînement du type ouverture / exploration / retour n'est raconté. Le modèle E049 mesure une charge de tabulation élevée (`E049.md:48-55`), symptôme d'une lecture sans fil conducteur.
- **Solution** : `E091.js:146-152` définit trois temps rédigés d'après le chapô réel de `chronology.js:231` : ouverture (le cadre), exploration (les bandes gardent le contexte), retour (la fiche donne les points vérifiés). Ils sont rendus dans une `<ol>` `#chronology-v2-e091-arc` (`:276-278`) avec puces numérotées en `:90-91` ; le compte est publié dans `data-v2e091-arc` (`:228`).
- **Impact** : le lecteur dispose d'une progression narrative explicite qui relie les trois zones déjà présentes de la vue (kicker, bandes, fiche).
- **Risque** : ce n'est pas un mode d'emploi : aucun geste n'est prescrit, afin de laisser le micro-tutoriel au chantier E097 (`themes.json:97`). La numérotation est portée par la sémantique `<ol>` et reste lisible sans CSS.
- **Effort** : M.
- **Vérification** : relecture `E091.js:146-152` ↔ `:276-278` ↔ `chronology.js:231` ; harnais — trois `<li>` dans l'ordre, aucun verbe à l'impératif, aucun `button` créé.

## E091-06 — Registre de voix hétérogène, non stabilisé

- **Problème / preuve** : la vue mêle un chapô descriptif (`chronology.js:231`), un indice abrégé en 8 px (`:232`, styles `:39`) et des compteurs tabulaires (`:250-256`, `:59`) : le registre change d'une ligne à l'autre. Le modèle E049 cite cette hétérogénéité d'indices (`E049.md:23`, `:66-73`).
- **Solution** : `E091.js:154` fixe le registre (présent de l'indicatif, seconde personne implicite, aucune prescription de clic) dans `#chronology-v2-e091-voix` (`:280-281`), typographié en `:92-94` et publié dans `data-v2e091-voix="present-2e"` (`:229`). Aucun texte du bandeau n'emploie l'impératif ni la première personne.
- **Impact** : le récit parle d'une seule voix, ce qui le distingue des états et des commandes de la coque sans les modifier.
- **Risque** : la déclaration de registre est descriptive, pas contraignante pour les autres lentilles ; une lentille voisine pourrait introduire un autre ton. Le contrôle reste une relecture croisée.
- **Effort** : S.
- **Vérification** : relecture de toutes les constantes narratives (`E091.js:124-156`) : zéro « cliquez », zéro « appuyez », zéro `aria-keyshortcuts` ; `data-v2e091-voix` cohérent avec le libellé.

## E091-07 — Récit sans mesure réelle tirée du DOM

- **Problème / preuve** : la vue sait déjà compter — filtrage et effectifs en `chronology.js:243-256`, bandes d'ère en `:282-308`, cartes de repère en `:386-411` — mais aucun de ces nombres n'est raconté. Le modèle E049 souligne que ces éléments sont des boutons réels (`E049.md:48-55`) et que les chiffres de la vue doivent rester dérivés du DOM (`E049.md:64` sur la mesure en lecture seule).
- **Solution** : `E091.js:201-214` compte `.era-band` (`:209`) et `.event-card` (`:210`) dans le conteneur courant ; `:283-284` écrit `#chronology-v2-e091-mesure`, `:221` formule « aucun chiffre n'est inventé », et `:230-231` publie `data-v2e091-eres` / `data-v2e091-reperes`. Le style tabulaire est en `:92-94`.
- **Impact** : le récit devient falsifiable : ses deux effectifs se recalculent à chaque rendu et suivent le filtre réel de la vue.
- **Risque** : il s'agit d'un instantané ; si le filtre masque des cartes, le nombre baisse, ce qui décrit fidèlement l'affichage. Ce décompte n'est pas la « comparaison chiffrée (amplitude vs référence) » de E096 (`themes.json:96`) : aucune durée ni référence externe n'est introduite.
- **Effort** : M.
- **Vérification** : relecture `E091.js:209-210` ↔ `chronology.js:282-308, 386-411` ; harnais — `data-v2e091-eres` et `data-v2e091-reperes` égaux au nombre de bandes et de cartes effectivement présentes, sans filtre puis avec filtre.

## E091-08 — Métaphore du « fil du temps » absente

- **Problème / preuve** : le mot « frise » est une image de support, mais la vue ne la prolonge pas : `chronology.js:231` parle de bandes et de fiche, `chronology.js:46` et `:63` marquent les états par la couleur, sans fil conducteur imagé. Le modèle E049 recommande de ne pas porter l'information par le seul visuel (`E049.md:60`).
- **Solution** : `E091.js:155` porte une métaphore unique et filée (le temps est un fil, la frise la main qui le tient, les repères des nœuds), rendue dans `#chronology-v2-e091-metaphore` (`:286-287`) et publiée dans `data-v2e091-metaphore="fil"` (`:232`). La même image est reprise dans l'accroche (`:128`) et dans l'écho (`:129`).
- **Impact** : une seule image traverse le bandeau du début à la fin, ce qui donne au récit une cohérence mémorable sans ajouter de graphique ni de canvas.
- **Risque** : la métaphore est littéraire, pas factuelle ; elle ne doit pas être lue comme une affirmation sur les données. Aucun attribut `aria-hidden` n'est posé : le texte est au contraire destiné à être lu.
- **Effort** : S.
- **Vérification** : relecture `E091.js:128, 155, 129` : le mot « fil » apparaît aux trois points attendus ; harnais — un seul nœud `#chronology-v2-e091-metaphore` et `data-v2e091-metaphore="fil"`.

## E091-09 — Aucune transition entre le kicker et la frise

- **Problème / preuve** : dans `chronology.js`, le chapô (`:231`) est immédiatement suivi de l'indice clavier (`:232`), du statut (`:248-257`), du bloc d'orientation (`:261-276`) puis de la navigation d'ères (`:279-308`) : le passage du mot « chronologique » aux bandes se fait sans phrase de liaison. Le modèle E049 documente ce bloc d'orientation comme purement situationnel (`E049.md:48-55`).
- **Solution** : `E091.js:156` fournit le pont narratif (« Du mot à la frise : « chronologique » annonce l'ordre, la bande d'ère le rend visible… »), rendu dans `#chronology-v2-e091-pont` (`:289-290`) et publié dans `data-v2e091-pont="1"` (`:233`). Le bandeau lui-même est inséré à la jonction (`:305-306`).
- **Impact** : le récit relie le titre à la frise au bon endroit du DOM, sans déplacer le bloc d'orientation ni le fil d'Ariane de la vue.
- **Risque** : l'insertion pousse légèrement la navigation vers le bas ; le bandeau reste un bloc en flux de largeur limitée, donc sans recouvrement en 390×844. La règle `:100-103` replie les définitions sous 620 px.
- **Effort** : S.
- **Vérification** : relecture `E091.js:156` ↔ `:305-306` ; harnais — le bandeau est le frère suivant de `.view-lede`, et le pont est lisible avant le premier `.era-band`.

## E091-10 — Clôture sans écho du kicker ; récit non pérenne aux rendus

- **Problème / preuve** : la fiche se termine par les boutons précédent / suivant (`chronology.js:525-527`) ou par l'état vide (`:530-535`), sans retour au cadre posé par le chapô `:231`. Par ailleurs `chronology.js:541` rejoue `runEnhancementsV2` à chaque rendu, `registry.js:13-19` ne garantit que l'unicité du `<style>` et la coque reconstruit le stage (`E049.md:104`) : un bandeau naïf serait dupliqué à chaque navigation.
- **Solution** : `E091.js:129` porte l'écho de clôture, rendu dans un `<blockquote>` `#chronology-v2-e091-echo` (`:292-293`, style `:95-99`) ; `:295-296` ajoute le bilan `#chronology-v2-e091-bilan`. La pérennité est assurée par `assurerNoeud()` (`:167-176`), `placerApres()` (`:179-185`), `replaceChildren()` (`:300`), les écritures dédupliquées de `ecrire()` / `setData()` (`:187-194`), un seul `ctx.css` (`:249`) et un seul `register` fléché `ctx` (`:317`). Le nombre de rendus est publié dans `data-v2e091-rendus` (`:235`) et dans le bilan (`:222`).
- **Impact** : le récit se referme sur le kicker et reste unique, stable et non bavard après navigation aller-retour.
- **Risque** : un nœud retrouvé dans un ancien parent détaché est déplacé, jamais cloné ; ses attributs `data-v2e091-*` sont réécrits à chaque rendu (`:224-235`), donc jamais périmés. Le registre neutraliserait silencieusement une erreur de greffon (`registry.js:39-42`) : `node --check` et les gardes d'existence sont la première ligne de défense.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E091.js` → PASS ; relecture — un seul `register`, un seul `ctx.css`, treize IDs tous préfixés `chronology-v2-e091-`, zéro `innerHTML`, zéro `console.` ; rejeu rendu → navigation → rendu : un seul `#chronology-v2-e091-story`, un seul `<style id="chronology-v2-e091">`, `data-v2e091-rendus` incrémenté, un seul écho.

## Blocages / limites inter-domaines

- Le bandeau est purement narratif et observationnel : il ne peut pas réécrire le chapô de `chronology.js:231`, l'indice de `:232`, le fil d'Ariane de `:261-276` ni la navigation d'ères de `:279-308` — tous fichiers non possédés. Il les lit et s'insère après eux.
- Le registre V2 ne fournit pas de `say()` (modèle `E049.md:4`) : les douze états du bandeau sont affichés en texte visible et dédupliqués, sans `aria-live` ni `role="status"`, afin de ne pas concurrencer les régions déjà portées par la vue et la coque.
- Les chantiers du domaine J restent cloisonnés : E092 explique « repère / point », E095 porte le glossaire ère / repère / confiance, E096 la comparaison d'amplitude, E097 le micro-tutoriel, E098 le silence comme donnée, E099 l'alternative textuelle complète et E100 la synthèse de la vue. Le présent module n'empiète sur aucun d'eux ; en cas de chevauchement perçu, c'est au maître d'œuvre de trancher.
- `ctx.reducedMotion()` est disponible (`registry.js:33-36`) mais n'est pas lu ici : le bandeau ne crée aucun mouvement, donc aucun état de préférence n'a à être annoncé. Le repli CSS `prefers-reduced-motion` (`:104-110`) neutralise défensivement tout mouvement hérité.
- Les deux compteurs sont des instantanés dérivés du DOM (`:209-210`) : ils suivent le filtre courant et ne sont pas des statistiques historiques. Aucune amplitude, aucune date et aucun effectif de pays n'est calculé ici.
- Aucun test E2E n'est ajouté : les harnais décrits dans chaque section sont à rejouer par l'agent maître.
