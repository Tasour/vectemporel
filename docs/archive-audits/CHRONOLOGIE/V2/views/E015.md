## E015-01 — Compte visible mais muet pour les lecteurs d'écran

- **Problème / preuve** : la vue affiche le compte dans un simple `<span class="atlas-chrono-count">` (`chronology.js:345`, `3 / 12 repères`) et dans un `<p id="atlas-chrono-status">` (`:248-257`). Le commentaire de la vue est explicite : cette bande est « sans `role=status` » (`:245-247`) et les annonces passent par `#nav-c2a-live` (`:119-138`, `:191-196`), région partagée avec la navigation. Le compte de résultats n'a donc aucune région live qui lui appartienne : un lecteur d'écran qui filtre n'entend que le message générique de navigation, jamais « N repères affichés ».
- **Solution** : `E015.js:266-272` crée le seul `<p role="status" aria-live="polite" aria-atomic="true">` de la lentille, `#chronology-v2-e015-result-status` (`:31`), inséré dans le panneau `:268`, `:285`. Son texte est bâti par `messageFor()` (`:188-194`) puis écrit uniquement s'il diffère (`:210-214`). Aucune écriture dans `#nav-c2a-live`, `#nav-t2-live` ou la région de la coque.
- **Impact** : le compte devient annonçable par les technologies d'assistance sans détourner les annonces de navigation existantes ; le texte reste visible pour tout le monde (`:61-65`).
- **Risque** : le registre V2 n'expose pas `say()` (`registry.js:28-43`), donc la lentille ne peut pas écrire dans une région existante : c'est précisément pourquoi elle en crée une seule, dédiée. La région est reconstruite avec le stage : voir la limite inter-domaines en fin de rapport.
- **Effort** : M.
- **Vérification** : relecture — un seul `setAttribute('role', 'status')` (`:270`) et aucun `nav-c2a-live` écrit ; harnais — après filtrage, `#chronology-v2-e015-result-status` contient `Résultats : N repère(s) affiché(s) …` et `document.querySelectorAll('[role="status"]')` ne montre aucun ajout de la lentille hors ce nœud.

## E015-02 — Compte calculé dans la vue, non relu depuis le DOM rendu

- **Problème / preuve** : `filterEvents()` (`chronology.js:179-189`) calcule `matched.length` et la vue l'injecte à `:245`, `:255`, `:345`. Ce nombre n'est pas exposé au DOM sous forme de donnée : le greffon ne peut ni le lire proprement ni vérifier qu'il correspond à ce qui est réellement affiché. Une lentille qui recopierait `matched.length` inventerait une source de vérité parallèle, contrairement à l'exigence « chiffres dérivés du DOM / dataset » du domaine F voisin.
- **Solution** : `E015.js:123-130` compte les `li[data-event-id]` réellement présents dans `#atlas-chrono-events` (`:38`). Ce compte alimente le message (`:203`, `:210`) et est publié dans `data-e015-dom-count` (`:234`). La liste vide ne portant pas de `li[data-event-id]` (`chronology.js:354-374`), le compte tombe naturellement à zéro.
- **Impact** : le nombre annoncé est toujours le nombre de cartes effectivement rendues, y compris quand une autre lentille modifierait la liste ; l'écart avec le bandeau de la vue devient mesurable.
- **Risque** : si la vue changeait son marquage `data-event-id`, le compte reviendrait à `0` plutôt que de retourner un chiffre faux ; le libellé resterait cohérent avec le DOM. Le repli est documenté au commentaire `:123-125`.
- **Effort** : M.
- **Vérification** : comparer `data-e015-dom-count` au nombre de `li[data-event-id]` dans `#atlas-chrono-events` ; sans filtre, la valeur égale le nombre de cartes de l'ère ; avec filtre, elle suit `matched` (`chronology.js:183-187`).

## E015-03 — Dénominateur du ratio `N / M` non nommé ni vérifiable

- **Problème / preuve** : le bandeau `chronology.js:345` affiche `N / M repères` et `:255` répète « affiché(s) sur ${scopeEvents.length} », mais `M` change de sens selon le périmètre (`:250-254`) : nombre de repères de l'ère sans filtre, nombre total de repères du pays avec filtre (`:182`). Aucun texte n'explique ce que mesure le dénominateur, et le compte de la lentille ne peut pas le deviner.
- **Solution** : `E015.js:132-142` relit le dénominateur depuis le `<span>` (regex `(\d+)\s*\/\s*(\d+)`, `:137`) avec repli sur le bandeau (regex `/sur\s+(\d+)\s+repères?/`, `:139-140`). Le message l'intègre explicitement « sur M » (`:191`) et la valeur est exposée en `data-e015-total` (`:235`), `—` si la source manque.
- **Impact** : le ratio devient lisible et auditable ; aucun total, aucune date ni aucun pays n'est codé en dur dans la lentille.
- **Risque** : la lecture repose sur le format de texte de la vue (`N / M repères`). Si ce format change, le repli sur `#atlas-chrono-status` prend le relais ; si les deux changent, le libellé affiche `—` plutôt qu'une valeur erronée — comportement assumé et documenté `:132-134`.
- **Effort** : S.
- **Vérification** : au repos, `data-e015-total` égale le nombre de repères de l'ère ; après une recherche, il égale `country.events.length` ; le message contient toujours « sur <total> » quand la donnée existe.

## E015-04 — Périmètre du compte implicite

- **Problème / preuve** : la liste `#atlas-chrono-events` change d'`aria-label` selon le mode — `Repères filtrés de ${country.name}` contre `Repères de l'ère ${era.name}` (`chronology.js:351-353`). Le compte, lui, ne dit jamais s'il porte sur l'ère ou sur le pays. Un utilisateur qui filtre voit le total de la colonne de droite augmenter (`:182`, `:250-251`) sans que le libellé du compte le signalle.
- **Solution** : `E015.js:144-151` lit cet `aria-label` et classe le périmètre `pays` si le libellé contient « filtr » , sinon `ere`. Le résultat est dit en toutes lettres dans `#chronology-v2-e015-perimeter` (`:219-221`), ajouté au message (`:192`) et publié en `data-e015-perimeter` (`:236`).
- **Impact** : le compte est toujours situé ; la bascule de périmètre devient observable par attribut, sans modifier le filtre local de la vue.
- **Risque** : l'`aria-label` est une chaîne localisée ; le test `/filtr/i` est volontairement large et documenté `:144-146`. Aucune autre source (valeur du champ, `aria-pressed`) n'est utilisée ici pour décider du périmètre, ce qui évite deux interprétations divergentes.
- **Effort** : M.
- **Vérification** : au repos, `data-e015-perimeter="ere"` et le message se termine par « dans l'ère courante. » ; après saisie dans `#atlas-chrono-search`, `data-e015-perimeter="pays"` et « dans tout le pays. ».

## E015-05 — Zéro résultat : l'état vide ne dit pas « 0 » dans le compte

- **Problème / preuve** : sans résultat, la vue remplace la liste par un `<div id="nav-c2a-empty-filter">` avec un bouton de réinitialisation (`chronology.js:354-374`) et un message dans le bandeau (`:255`). Mais le `<span>` de compte (`:345`) affiche `0 / M` en `font-size:9px; color:var(--muted-2)` (`:59`), sans structure annonçable distincte. Le zéro existe donc visuellement, mais il n'est ni qualifié ni porté par la région de compte.
- **Solution** : `E015.js:215-217` ajoute/retrait la classe `is-empty` sur le `role="status"` selon `count === 0` ; `messageFor()` (`:188-193`) produit « Résultats : 0 repère affiché sur M … » au singulier ; `data-e015-empty` (`:237`) vaut `1`. Le CSS `:66-68` donne une bordure *dashed* et un poids normal à cet état, en plus du texte.
- **Impact** : le zéro est explicite, lisible et annonçable ; l'information n'est pas portée par la seule couleur (forme de bordure + mot « 0 » + attribut).
- **Risque** : la classe `is-empty` est combatible avec une règle externe portant sur la bordure ; le texte du message reste la source fiable, comme le rappelle le commentaire `:185-187`.
- **Effort** : M.
- **Vérification** : saisir une requête sans correspondance → `#chronology-v2-e015-result-status` contient « 0 repère affiché », porte `is-empty` et `data-e015-empty="1"` ; effacer la requête → classe retirée et attribut à `0`.

## E015-06 — Annonces concurrentes et bavardage sur chaque frappe

- **Problème / preuve** : chaque `input` sur `#atlas-chrono-search` relance `set({}, 'chrono-filter')` (`chronology.js:321-325`), donc un rendu complet (`store.js:216`, `shell.js:533`), puis `announceFilter()` écrit dans `#nav-c2a-live` (`:191-196`). Trois autres régions live existent déjà (coque, routeur, vue) : ajouter une écriture systématique dans l'une d'elles, ou une seconde région dédiée, produirait des annonces redondantes à chaque frappe.
- **Solution** : `E015.js:112-116` centralise les écritures dans `write()`, qui ne touche au texte que s'il diffère ; `:210-214` applique la même règle au `role="status"` et incrémente `updateCount` (`:94`) seulement lors d'un changement réel. La lentille n'appelle aucun `say()`, n'installe aucun écouteur (`:23-25`) et publie `data-e015-updates` (`:238`). Le message ne contient volontairement ni requête ni thème (ces derniers vivent hors de la région live, `:222-225`), ce qui évite une annonce par caractère.
- **Impact** : une seule région live supplémentaire, alimentée uniquement quand le compte, le total ou le périmètre changent ; aucun bavardage, aucune compétition avec les annonces de navigation.
- **Risque** : un changement de requête qui ne modifie pas le résultat n'est pas annoncé — c'est le comportement recherché. Le message de `announceFilter()` (`chronology.js:195`) reste seul maître de l'annonce « filtre » générique ; la lentille ne l'écrase pas.
- **Effort** : M.
- **Vérification** : relecture — zéro `nav-c2a-live`, zéro `nav-t2-live`, zéro `addEventListener` dans le module ; harnais — deux rendus sans changement de filtre laissent `data-e015-updates` invariant ; un filtre qui change le compte l'incrémente d'une unité.

## E015-07 — Recherche et thème actifs absents du compte affiché

- **Problème / preuve** : le filtre est stocké dans `local.query` et `local.tag` (`chronology.js:17`). Il est reflété dans les contrôles — `#atlas-chrono-search` (`:313-320`), les `#tag-btn-<tag>` (`:330-343`) et les `#aside-tag-<tag>` (`:445-456`) — mais nulle part à côté du compte : `chronology.js:345` affiche seulement un ratio. Un lecteur qui revient sur la vue ne voit pas *pourquoi* le compte est tel qu'il est.
- **Solution** : `E015.js:153-170` relit la valeur du champ et les `[data-tag][aria-pressed="true"]` des deux conteneurs, en dédupliquant un même thème présent deux fois. Le résultat est affiché dans `#chronology-v2-e015-filter` (`:222-225`) et exposé en `data-e015-query` / `data-e015-tag` (`:239-240`). Ces lignes restent **hors** de la région live (E015-06).
- **Impact** : le compte est accompagné de la cause du filtrage, sans invention de données ni modification des boutons `aria-pressed` de la vue.
- **Risque** : la requête est insérée par `textContent` via `ctx.el` (`:268`, `:283-285`) : aucun balisage brut ne peut traverser la lentille, même si l'utilisateur saisit `<…>`. La chaîne est trimmée (`:159`) pour ne pas afficher d'espace parasite.
- **Effort** : M.
- **Vérification** : saisir `paix` → `data-e015-query="paix"` et le libellé contient `« paix »` ; activer un thème → `data-e015-tag` contient le thème, une seule fois malgré les deux commandes ; `#chronology-v2-e015-result-status` reste inchangé si le compte ne bouge pas.

## E015-08 — Rang du repère courant non relié à la liste affichée

- **Problème / preuve** : le bandeau de la vue donne « rang global X/Y » (`chronology.js:256`) et la progression donne le rang dans l'ère (`:264-269`), tandis que la liste affichée peut être réduite au pays entier par le filtre (`:182`). Trois rangs coexistent sans que le compte dise lequel il accompanie : l'utilisateur peut croire que `3 / 12` et « repère 3/229 » désignent la même chose.
- **Solution** : `E015.js:172-183` compte les `.event-card` rendues et repère celle qui porte `aria-current="true"` (posé par `chronology.js:391`). Le rang est affiché dans `#chronology-v2-e015-current` avec la mention « dans la liste affichée » (`:226-228`) et publié en `data-e015-current` (`:241`).
- **Impact** : le rang affiché est explicitement relatif au résultat filtré ; la confusion avec le rang global est levée par le libellé, sans toucher à `#nav-c2a-progress`.
- **Risque** : si aucune carte n'est courante (état vide ou sélection hors filtre), le libellé dit « aucun dans la liste affichée » et l'attribut vaut `0/N` (`:178`, `:227`) plutôt qu'un rang inventé.
- **Effort** : S.
- **Vérification** : sélectionner une carte → `data-e015-current` vaut `rang/nombre de cartes` ; filtrer de façon à exclure la carte courante → `0/N` et libellé « aucun » ; le rang global de la vue reste inchangé.

## E015-09 — Lisibilité du compte : mesure, mouvement réduit, contraste, papier

- **Problème / preuve** : le compte d'origine est un texte de 9 px en `var(--muted-2)` (`chronology.js:59`) ; la grille passe en une colonne sous 1000 px et la recherche en pleine largeur sous 620 px (`:84-89`). Le registre fournit `ctx.reducedMotion()` (`registry.js:33-36`) mais la vue n'expose aucun état de préférence pour son compte. Un bandeau de compte trop fin, animé ou dépendant de la seule couleur serait illisible en 390×844 et en mode contraste forcé.
- **Solution** : `E015.js:44-91` injecte une seule feuille avec `font-variant-numeric: tabular-nums` (`:54`), une hauteur minimale (`:61`), un repli 620 px (`:74-77`), l'annulation de toute transition en `prefers-reduced-motion` (`:78-80`), un repli `forced-colors` (`:81-85`) et un repli d'impression (`:86-89`). `:208` lit `ctx.reducedMotion()`, publié en `data-e015-reduced` (`:242`) et répété dans la ligne d'audit (`:229-231`).
- **Impact** : chiffres alignés, compte non tronqué sur mobile, contraste préservé dans les modes système, aucun mouvement parasite, sortie papier propre.
- **Risque** : le panneau allonge la colonne principale et repousse la fin de la liste ; c'est un compromis assumé face à un bandeau absolu qui masquerait des cartes. Aucune animation n'est créée, donc aucun timer ni boucle rAF n'est nécessaire.
- **Effort** : M.
- **Vérification** : émuler `prefers-reduced-motion: reduce` → `data-e015-reduced="1"` et « oui » dans l'audit ; capture 390×844 → le compte reste lisible et `#chronology-v2-e015-panel` ne déborde pas ; relecture du CSS : aucun `transition` non neutralisé, aucune `url(` distante.

## E015-10 — Re-rendus : unicité de l'id, de la feuille de style et du greffon

- **Problème / preuve** : `chronology.js:541` appelle `runEnhancementsV2({ viewId, stage, layout })` à chaque rendu ; `registry.js:28-43` rejoue les greffons et neutralise silencieusement leurs erreurs (`:39-42`). `registry.js:13-19` ne garantit que l'unicité du `<style>` ; ni les nœuds ni les compteurs ne sont protégés. `shell.js:533` détruit le stage précédent, et `_diagnostics.js:69-78` marque tout nœud dont l'id satisfait `/^(e\d{2,3}[-_ ]|.*-e\d{2,3})/i` **si son parent est `body`, `stage` ou `layout`** — un panneau directement greffé dans le layout serait donc masqué par `display:none !important`.
- **Solution** : `E015.js:97-110` fournit `ensureNode()` avec garde d'existence et déplacement dans le parent courant ; `:28-35` et `:250` imposent un seul identifiant CSS et un seul `ctx.css` ; `:253-259` greffe le panneau dans `.chronology-main` (parent ni `body`, ni `stage`, ni `layout`) pour échapper au marquage ; `:93-95` et `:251` maintiennent les compteurs module ; `:285` utilise `replaceChildren` ; `:290-292` unique `register`.
- **Impact** : aucun doublon de panneau, de `role="status"` ou de feuille de style après navigation aller-retour ; le panneau reste visible même avec le tiroir de diagnostics ouvert, et hérite de l'`inert` des modales de la coque.
- **Risque** : un nœud retrouvé dans un ancien parent détaché est déplacé, jamais cloné ; ses attributs `data-e015-*` sont réécrits à chaque `refresh()` (`:233-243`), donc jamais périmés. Le registre neutralisant les erreurs (`:39-42`), `node --check` et les gardes d'existence constituent la première ligne de défense.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E015.js` → PASS ; relecture — un seul `register`, un seul `ctx.css`, huit ids tous préfixés `chronology-v2-e015-` (`:28-35`) ; rejeu rendu → navigation → rendu : un seul `#chronology-v2-e015-panel`, un seul `#chronology-v2-e015-result-status`, un seul `<style id="chronology-v2-e015">`, `viewDiagnostics().diagnostics` vide.

## Blocages / limites inter-domaines

- La région `role="status"` est reconstruite avec le stage à chaque rendu (`shell.js:533`). Son texte est réécrit de façon déterministe, mais la portée durable de l'annonce relève de E041 (« région live unique ») et de E019 (« annonce sans bavardage ») : la lentille ne crée pas de conteneur persistant hors de `#app` pour ne pas doubler les régions existantes ni être happée par `_diagnostics.js:69-78`.
- Le dénominateur est lu depuis le texte de `chronology.js:345` / `:255` : si la vue change son format, le repli puis le libellé `—` prennent le relais, mais la correction du format relève de la vue, fichier non possédé.
- Le périmètre dépend de l'`aria-label` de `chronology.js:351-353` ; une localisation qui retirerait le radical « filtr » imposerait une relecture de `E015.js:144-151`.
- Le thème est dédupliqué entre les deux commandes `aria-pressed` de `chronology.js:330-343` et `:445-456` ; supprimer cette duplication relève de la passe 1 / d'une lentille dédiée, pas de ce module.
- Le rang affiché est volontairement relatif à la liste filtrée. Le rang global de `chronology.js:256` n'est pas modifié ; sa mise en cohérence avec le compte relève d'une arbitrage maître.
- L'état du panneau (compteurs, dernier message) est volatile : il est recalculé à chaque rendu, comme le prescrit le contrat de greffon.
