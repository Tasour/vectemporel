# M35 — Couverture et points d'audit (domaine D : données & sémantique)

Lentille M35. Fichier possédé : `src/views/monde/M35.js`. Lectures seules :
`src/data/dataset.js`, `POINT_REGISTRY.md`, `src/views/globe.js`,
`src/views/monde/registry.js`, `src/views/monde/M13.js`,
`src/views/monde/M31.js`, `src/views/monde/M34.js`, `src/views/monde/M36.js`,
`source/audits/*/coverage-matrix.csv`. Un seul fichier modifié, aucun
sélecteur de test touché. Zéro réseau, zéro aléa, zéro journalisation,
aucune donnée historique inventée.

Relevés à la lecture (jamais saisis dans le module) : 845 points dans
`country.points` (somme des dix pays = `meta.validatedPoints`), 14 domaines
distincts, 5 échelles, 20 valeurs de `datePrecision`, 168 points de confiance
« non documenté », 80 points citant au moins un identifiant `OM-*`
(52 `OM-*` seuls + 28 références mixtes `SRC-*`/`OM-*`). Le chiffre
« 784 cellules de couverture vérifiées » (`globe.js:373`) correspond à la somme
des lignes des dix `coverage-matrix.csv` ; il n'est pas présent dans le dataset
et n'est donc jamais recalculé ni affiché par la lentille.

## Chantiers

### M35-01 — Une seule source de vérité : les points reçus dans le contexte

- **Preuve** : `globe.js:433-441` construit `mondeCtx` avec `countries: DATASET.countries` et `selected`, puis `registry.js:51-57` transmet ces champs au greffon. La coque ne transmet pas `meta` (constatdéjà établi en M31-03) : `dataset.js:11-13` porte `points: 1746` et `validatedPoints: 845`, mais ces chiffres ne sont pas accessibles au greffon. `globe.js:373` insère une phrase figée (« 784 cellules… ») non recalculée.
- **Solution** : `compute()` lit exclusivement `country.points`, `country.eras` et `ctx.selected` ; aucune phrase historique, aucune date ni total recopié. Toutes les écritures passent par `textContent`.
- **Impact** : la lentille ne peut réintroduire ni le « 784 » figé ni un total périmé ; elle reste un miroir exact du jeu de données reçu.
- **Effort** : S.
- **Vérification** : relecture — aucun littéral `784`, `845`, `1746`, `14` ou `229` dans `M35.js` ; la somme des points affichée est recalculée par itération sur `ctx.countries`.

### M35-02 — Panneau unique et CSS injecté une seule fois

- **Preuve** : `cssOnce()` (`registry.js:25-31`) garde l'injection par identifiant ; `runMondeEnhancements()` est rappelé à chaque rendu (`globe.js:442`) tandis que `.globe-scene` est recréée (`globe.js:317`).
- **Solution** : garde `getElementById(PANEL_ID)` + `isConnected` + `parentElement === ctx.scene` ; `ctx.css('monde-m35', CSS)` appelé à chaque passage (idempotent par construction).
- **Impact** : un seul `#monde-m35-coverage` et une seule feuille `#monde-m35`, quel que soit le nombre de rendus.
- **Effort** : S.
- **Vérification** : rendre le globe 10× → `document.querySelectorAll('#monde-m35-coverage').length === 1` et `document.getElementById('monde-m35') !== null`.

### M35-03 — Total des points d'audit dérivé, jamais codé en dur

- **Preuve** : `POINT_REGISTRY.md` annonce « 845 points fusionnés » ; les tableaux `country.points` commencent en `dataset.js:4585` et leur somme sur les dix pays donne exactement 845, soit `meta.validatedPoints`.
- **Solution** : `stats.points = points.length`, construit en une passe sur le périmètre ; la phrase « Points d’audit : N » et le miroir `data-m35-points` utilisent cette valeur calculée.
- **Impact** : si un point est ajouté ou retiré lors d'une régénération du dataset, le panneau suit sans modification de code.
- **Effort** : S.
- **Vérification** : vue d'ensemble → 845 ; pays sélectionné → le compte exact du pays (France 140, Japon 74…) ; somme des dix comptes individuels = compte agrégé.

### M35-04 — Couverture par domaines, sans le « /14 » figé

- **Preuve** : `globe.js:131` et `M13.js:55` écrivent `${domains}/14 domaines` avec un dénominateur littéral ; `dataset.js` porte 14 valeurs distinctes de `points[].domain`, mais ce nombre peut changer.
- **Solution** : `domains` est un dictionnaire construit depuis les `point.domain` réellement présents ; `stats.domainCount = Object.keys(domains).length`. Le détail affiche les domaines et leurs comptes tels quels, bornés à trois entrées plus le reste compté.
- **Impact** : aucun dénominateur faux ; les libellés de domaine affichés sont exactement ceux du dataset.
- **Effort** : S.
- **Vérification** : France → 14 domaines dérivés ; aucun texte « /14 » n'apparaît dans le module ; la somme des comptes du dictionnaire égale le total des points du périmètre.

### M35-05 — Couverture par ères : trous détectés, jamais comblés

- **Preuve** : `country.eras` (`dataset.js:130-203`) porte les ères ; chaque point de `country.points` porte un `eraId` réel (`dataset.js:4587`). Les dix pays couvrent aujourd'hui toutes leurs ères, mais rien ne garantit que ce soit toujours vrai.
- **Solution** : `compute()` compare l'ensemble des `eraId` des points aux identifiants d'ères du périmètre ; la ligne « Ères couvertes : X/Y » est calculée, et les ères manquantes sont nommées depuis `era.name` (repli sur `era.id`) sans créer de point factice.
- **Impact** : un trou de couverture devient visible immédiatement, sans être masqué par un texte générique.
- **Effort** : M.
- **Vérification** : vue d'ensemble → 56/56 ères couvertes ;France → 9/9 ; aucune ère manquante n'est affichée si le comptage est complet ; le nom affiché pour une ère manquante est identique à `era.name` du dataset.

### M35-06 — Couverture par échelle (scale), valeurs verbatim

- **Preuve** : les points portent `scale` (`dataset.js:4590` et suivants) avec cinq valeurs observées : `national`, `transnational`, `imperial`, `regional`, `local`. Aucune de ces valeurs n'est traduite ou fusionnée ailleurs dans la vue Monde.
- **Solution** : histogramme `Object.create(null)` rempli en une passe ; `pairs()` trie par compte décroissant puis par `localeCompare('fr')` pour un ordre déterministe.
- **Impact** : les échelles sous-représentées restent mesurables (par exemple `local`, la plus rare dans le relevé) sans intermétation.
- **Effort** : S.
- **Vérification** : la somme des comptes de la ligne « Échelles » égale `stats.points` ; relecture — seules les cinq valeurs présentes dans le dataset apparaissent.

### M35-07 — Précision de date : aucune catégorie fabriquée

- **Preuve** : `datePrecision` contient 20 valeurs distinctes, dont des codes courts (`year`, `interval`, `day`, `approximate`, `range`, `month`) et des phrases longues présentes dans le dataset (par exemple « intervalle de l'ère ; fait non daté », `dataset.js:4698` et suivants).
- **Solution** : l'histogramme est rendu verbatim, limité à trois valeurs plus « + N autre(s) » ; aucun regroupement du type « daté / non daté » n'est introduit, aucune normalisation n'est appliquée.
- **Impact** : le vocabulaire du schéma est préservé ; la lentille ne transforme pas une précision déclarée en certitude.
- **Effort** : S.
- **Vérification** : chaque valeur affichée est un sous-ensemble exact des `datePrecision` observés ; le complément « + N autre(s) » reprend le nombre de valeurs non affichées.

### M35-08 — Absences documentées : provenance négative, pas donnée manquante

- **Preuve** : 168 points portent `confidence: "non documenté"` (`dataset.js:4698`) et 80 points citent un identifiant `OM-*` ; les justifications renvoient aux cellules « vide justifié » des `coverage-matrix.csv`. Ce sont des absences tracées, pas des oublis à corriger par la lentille.
- **Solution** : deux compteurs distincts — un sur la valeur déclarée `non documenté`, un sur la présence d'une référence `OM-*` dans `point.sources` — affichés sur la même ligne mais jamais additionnés ni confondus. Aucun contenu d'omission n'est rédigé, aucune URL n'est reconstruite.
- **Impact** : la couverture négative devient un indicateur auditable sans inventer le fait qu'elle conserve.
- **Effort** : M.
- **Vérification** : vue d'ensemble → 168 et 80 ; chaque compte est borné par `stats.points` ; relecture — aucun texte d'omission nouveau n'apparaît dans le module.

### M35-09 — Statut des points : « validated » tel quel, sans assimilation

- **Preuve** : `status: "validated"` est porté par les 845 points (`dataset.js:4623`, `:4663`, …) ; les points de repère utilisent un autre vocabulaire (`confidence: "vérifié"`, `dataset.js:230`) et un autre corpus.
- **Solution** : `pairs(statuses)` imprime les valeurs de `point.status` sans traduction ; le texte évite « points vérifiés » et parle uniquement de « points d'audit ».
- **Impact** : aucun statut de validation n'est surenchéri ; la distinction entre les deux corpus de points est maintenue.
- **Effort** : S.
- **Vérification** : ligne « statut : validated 845 » en vue d'ensemble ; « validated 140 » pour la France ; le miroir `data-m35-status` reprend la même valeur.

### M35-10 — Miroir auditable, survols frais et zéro effet de bord

- **Preuve** : `notifyMondeHover()` / `notifyMondeLeave()` (`registry.js:70-75`) alimentent les callbacks ; `registry.js:46-50` purge puis réenregistre les tableaux à chaque rendu, comme documenté en M34-07. `#globe-live` (`globe.js:71-85`) est déjà la région live canonique (M20).
- **Solution** : callbacks réenregistrés à chaque appel du greffon (aucune garde module), lecture systématique de `latest`, survol prioritaire puis retour à `ctx.selected` ; miroirs `data-m35-*` sur `ctx.host` (portée, points, domaines, ères, omissions, statut) ; panneau `role="group"` sans `aria-live` pour ne pas doubler l'annonce ; CSS neutralisé sous `prefers-reduced-motion`.
- **Impact** : état vérifiable sans instrumentation, déterministe, accessible, sans annonce redondante ni fuite d'écouteur.
- **Effort** : M.
- **Vérification** : survol A → B → sortie restaure le pays sélectionné ; `document.getElementById('globe-canvas').dataset.m35Points === '845'` en vue d'ensemble ; `grep -E 'fetch|Math.random|console\.|innerHTML|https?://' src/views/monde/M35.js` → aucune ligne ; `node --check src/views/monde/M35.js` → OK.

## Contraintes relevées hors de mon fichier

- **`globe.js:373`** : le sous-titre « 784 cellules de couverture vérifiées » n'est pas recalculé depuis le dataset ; il correspond en réalité à la somme des lignes des dix fichiers `coverage-matrix.csv`, non transmises à la vue. M35 ne le réutilise pas. Correctif éventuel hors de mon fichier.
- **`globe.js:131` et `M13.js:55`** : le dénominateur « /14 domaines » est codé en dur. M35 affiche un nombre dérivé et ne propage pas cette valeur.
- **`registry.js:46-50`** : la purge des callbacks à chaque rendu est le comportement attendu ; une garde « abonné une fois » ferait perdre les abonnements M35 dès le second rendu.
