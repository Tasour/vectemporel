# M25 — Navigation par flèches (domaine C : ergonomie & interaction)

Lentille : M25. Fichier possédé : `src/views/monde/M25.js`.
Lectures seules : `src/views/globe.js`, `src/views/monde/registry.js`,
`src/platform/keyboard.js`, `src/domain/store.js`, `src/views/monde/M05.js`,
`src/views/monde/M13.js`, `UNIFIED_AUDIT/MONDE/README.md`.
Aucun fichier partagé modifié, aucun réseau, aucun `Math.random`, aucun `console.*`.
**Aucun écouteur `keydown` ajouté** : la lentille est un observateur des flèches, pas un troisième propriétaire.

---

## M25-01 — Zéro écouteur clavier dupliqué : observation par `onHover` / `onLeave`

- Preuve : `globe.js:202-230` détient `onHostKeyDown` (flèches + Home/End + Entrée sur l'hôte) et `globe.js:233-245` détient `onChoicesKeyDown` (flèches sur la liste). Le routeur global `keyboard.js:169` rend la main explicitement sur `state.view === 'globe'`. `M05.js:288` attache un `keydown` à l'hôte pour `+`/`-`/PageUp/PageDown, et `M13.js:186` un `keydown` document pour Échap. Ajouter un cinquième handler de flèches provoquerait des parcours concurrents et des annonces triples.
- Solution : `M25.js` ne contient aucun `addEventListener('keydown', …)`. Il s'abonne une seule fois aux callbacks du registre `ctx.onHover` / `ctx.onLeave` (registry.js:50-52), déjà alimentés par `highlight()` (globe.js:186-200) à chaque flèche sur l'hôte et à chaque `focus` sur un bouton pays (globe.js:419).
- Impact : les trois propriétaires existants restent seuls ; M25 se contente de lire le résultat de leur navigation.
- Risque : un `onHover` issu de la souris (engine `onHover`, globe.js:449-457) ressemble à une flèche. M25 ne prétend pas distinguer l'origine : il enregistre une transition de curseur, pas une frappe, et le compteur `steps` est documenté comme « transitions observées ».
- Effort : S
- Vérification : `grep -n 'keydown' src/views/monde/M25.js` ne renvoie aucune ligne ; `VECTEMPOREL_M25.diag().subscribed === true` après un rendu.

## M25-02 — Curseur dérivé, jamais écrit dans le store

- Preuve : `store.js:40-63` ne possède aucun index de survol ou de curseur ; `hoverIndex` (globe.js:20) est une variable module privée. Écrire dans `state` créerait un quatrième propriétaire et réveillerait les abonnés à chaque flèche.
- Solution : un index `cursor` module, résolu depuis le payload `{ country, code }` par identité d'objet, puis par `country.id`, puis par `code`, dans `ctx.countries`. Aucun appel à `set()`, aucune mutation de `ctx.state`.
- Impact : la navigation par flèches reste locale et sans effet de bord sur l'état partagé, le fil d'Ariane ou les deep links.
- Risque : un pays du payload absent de `ctx.countries` doit être ignoré plutôt que de créer un index invalide ; la résolution en trois temps échoue alors proprement (`-1`).
- Effort : S
- Vérification : après trois flèches, `VECTEMPOREL_M25.cursor().index` suit l'index mis en évidence et `state.revision` est inchangé.

## M25-03 — Readout visuel d'ordinal, sans troisième annonce live

- Preuve : `globe.js:199` annonce déjà « Pays N sur 10 … Entrée pour ouvrir » via `say()`, et `M13.js:234` annonce un aperçu enrichi dès que le focus est dans l'hôte ou un bouton pays. Un nœud `aria-live` supplémentaire produirait une voix triple.
- Solution : `#monde-m25-cursor` est visible mais `aria-hidden="true"`. Son texte porte l'ordinal `NN/10` et le nom du pays : l'information n'est jamais portée par la seule couleur. Le rail (M25-04) est également `aria-hidden`.
- Impact : une seule voix, un seul canal live ; les utilisateurs voyants disposent d'un repère de position permanent pendant le parcours.
- Risque : le readout paraît « muet » aux lecteurs d'écran ; c'est volontaire, l'information est déjà vocalisée par les deux canaux existants, documentés dans ce chantier.
- Effort : S
- Vérification : le nombre de nœuds `[aria-live]` est identique avant et après installation de M25 ; le texte du readout contient bien `NN/10` et le nom.

## M25-04 — Rail de pips numérotés, reconstruit seulement si le compte change

- Preuve : `globe.js:379-381` affiche un total (« 10 pays · … ») mais aucune position courante ; le survol ne laisse aucun repère visuel ordinal sur la scène.
- Solution : `#monde-m25-rail` reçoit une pastille par pays, numérotée de `01` à `NN`, avec `data-m25-pip`. Le rail n'est reconstruit que si `childElementCount !== total` ; sinon seules les classes et `data-m25-state` (`current`/`past`/`next`/`idle`) sont basculées, sans allocation en boucle.
- Impact : lecture immédiate de la progression dans une grille de dix pays, sans modifier `.globe-country` ni `#globe-choices`.
- Risque : un changement de jeu de données entre deux rendus doit recalculer les pastilles ; la comparaison de compte couvre ce cas, y compris le passage à zéro pays.
- Effort : M
- Vérification : dix pastilles pour dix pays ; après navigation, exactement une porte `.is-current` et son numéro égale l'ordinal du readout.

## M25-05 — Équivalents pointeur ◀ / ▶ des flèches, sans réimplémenter le parcours

- Preuve : `globe.js:415-418` attache le clic des boutons pays à `reveal.reveal(..., selectCountry)` (ouverture), tandis que `globe.js:419` attache leur `focus` à `highlight(index)` (mise en évidence). Un greffon qui rappellerait `selectCountry` ouvrirait la chronologie au lieu de déplacer le curseur.
- Solution : deux boutons `#monde-m25-prev` / `#monde-m25-next` (≥ 36 px, `aria-label` explicites, pas d'`aria-pressed` : ce ne sont pas des bascules) focalisent le bouton pays dont `data-index` vise la cible, avec `focus({ preventScroll: true })`. Le `focus` existant déclenche `highlight()`, donc l'annonce et le drapeau restent ceux de `globe.js`. Parcours déterministe modulo le nombre de pays, sans aléa.
- Impact : équivalent tactile/souris des flèches gauche/droite, sans duplication du parcours ni appel direct à `selectCountry`.
- Risque : la liste est triée par nom dans le DOM (globe.js:395) alors que `data-index` est l'index du jeu de données. La sélection se fait donc par `data-index`, jamais par position dans le DOM. Si la liste n'est pas rendue, M25 replie sur son curseur local et annonce via `say()` (globe.js n'ayant alors rien annoncé).
- Effort : M
- Vérification : clic sur ▶ depuis le pays 3 (index 2) → `document.activeElement.dataset.index === '3'` (mod 10), `host.dataset.m25Index === '3'`, la vue reste `globe`.

## M25-06 — Synchronisation du `tabindex` roving entre sphère et liste

- Preuve : `globe.js:403` pose `tabIndex = 0` sur le pays sélectionné au rendu ; `lastFocusIndex` (globe.js:21, 387-391) n'est mis à jour que par un `focusin` sur la liste. Après des flèches sur la sphère, un `Tab` ramène donc à l'ancien pays, pas à celui visé.
- Solution : dès qu'un curseur est connu, M25 aligne `tabIndex = 0` sur le bouton du curseur et `-1` sur les autres ; tant qu'aucun curseur n'est établi, il retombe sur le pays sélectionné, exactement comme `globe.js:403`. Il pose `data-m25-cursor="true"` sur la cible mais n'écrit **ni** `aria-current` (réservé à la sélection, globe.js:414) **ni** les sélecteurs utilisés par les tests.
- Impact : continuité du parcours clavier entre les deux surfaces, sans confondre « sélectionné » et « visé par les flèches ».
- Risque : un survol pointeur alors que le focus est dans la liste déplace le `tabindex` ; c'est le comportement attendu d'un roving aligné sur la cible courante, et le focus réel n'est pas modifié.
- Effort : M
- Vérification : flèches sur l'hôte jusqu'au pays 7 puis `Tab` → focus sur `button[data-index="6"]` ; `aria-current="true"` reste sur le pays sélectionné.

## M25-07 — Miroir d'état `data-m25-*` auditable sur l'hôte

- Preuve : `hoverIndex` est privé (globe.js:20) et aucun attribut DOM ne publie la position courante ; un test E2E ne peut vérifier les flèches qu'en lisant le texte du readout.
- Solution : M25 maintient sur l'hôte stable (`#globe-canvas`) `data-m25-nav` (`ready`/`cursor`/`idle`/`empty`), `data-m25-index`, `data-m25-total`, `data-m25-steps`, `data-m25-wraps`, `data-m25-leaves` et `data-m25-last` (`next`/`prev`). Le rebouclage n'est compté que sur une transition entre extrémités avec focus clavier, pour ne pas compter un survol souris.
- Impact : état de navigation lisible par un audit sans instrumenter `globe.js`.
- Risque : `steps` compte des transitions de curseur, pas des frappes ; le libellé du diagnostic le précise. Un `onLeave` n'efface pas le curseur (contrairement à M13) : il incrémente seulement `leaves`, la mémoire de navigation étant utile au retour.
- Effort : M
- Vérification : curseur déjà établi sur le pays 1, dix flèchesdroites sur l'hôte → `data-m25-steps` progresse de 10 et `data-m25-wraps === '1'`.

## M25-08 — Idempotence : un seul jeu de nœuds, un seul abonnement

- Preuve : `runMondeEnhancements()` est rejoué à chaque rendu (globe.js:442) ; `readyCallbacks` / `hoverCallbacks` s'accumulent dans le registre (registry.js:50-52) et la coque remplace le `innerHTML` de la scène.
- Solution : garde module `subscribed` pour les callbacks, CSS injecté une fois via `ctx.css('monde-m25', …)`, IDs uniques avec garde `isConnected`, et marqueur `data-m25-bound` posé sur les deux boutons. Les pointeurs de nœuds sont toujours relus par `getElementById` (jamais mémorisés), comme dans M13, afin qu'un callback accumulé ne mette jamais à jour un nœud détaché.
- Impact : trois rendus produisent trois `install()` mais un seul panneau, un seul abonnement et deux seuls boutons.
- Risque : un panneau détaché lors d'un re-render est recréé et ses boutons re-liés grâce au marqueur par nœud ; le compteur `installs` rend cette activité visible.
- Effort : S
- Vérification : trois rendus successifs → `VECTEMPOREL_M25.diag().installs === 3` et `document.querySelectorAll('#monde-m25-nav').length === 1`.

## M25-09 — Aucune boucle, aucun timer, mouvement réduit respecté

- Preuve : M07 établit que l'unique boucle rAF est détenue par le moteur ; M06 et M10 couvrent déjà `resize` et `visibilitychange`. Un greffon qui ajouterait un `requestAnimationFrame` ou un `setTimeout` réintroduirait une boucle parasite.
- Solution : M25 est purement événementiel (callbacks du registre + deux clics sur ses boutons). `ctx.reducedMotion()` est lu une seule fois à l'installation pour ajouter le suffixe « aperçu statique » au readout, sans animation propre.
- Impact : zéro frame et zéro réveil CPU imputables à la lentille ; cohérence avec les chantiers de performance de la vague.
- Risque : un futur « keep-alive » du rail casserait cette propriété ; la règle est explicite en tête de fichier et vérifiable statiquement.
- Effort : S
- Vérification : `grep -nE 'requestAnimationFrame|setInterval|setTimeout|IntersectionObserver' src/views/monde/M25.js` → 0 ligne.

## M25-10 — Repli explicite et surface de diagnostic en lecture seule

- Preuve : `DATASET.countries` peut être vide et le moteur 3D indisponible (globe.js:478-480) ; `say()` (globe.js:148-150) reste le seul canal vocal, et il est le seul que M25 est autorisé à utiliser.
- Solution : sans pays, le readout affiche « Navigation par flèches indisponible : aucun pays documenté » et `say()` l'annonce une seule fois (garde `emptyAnnounced`). `window.VECTEMPOREL_M25` expose `cursor()`, `diag()` et `chantiers()` : aucun mutateur, aucune donnée inventée.
- Impact : état vide explicite, diagnostic consultable par l'agent maître, zéro valeur fabriquée.
- Risque : l'annonce d'état vide peut être effacée par le `live.textContent = ''` de globe.js:474 au moment où le moteur devient prêt ; le readout visuel, lui, persiste et reste la source de vérité.
- Effort : S
- Vérification : `node --check src/views/monde/M25.js` OK ; `grep -nE 'console\\.|fetch\\(|XMLHttpRequest|Math.random' src/views/monde/M25.js` → 0 ligne.

## Statut d'implémentation

Les 10 chantiers sont implémentés dans `src/views/monde/M25.js`. Aucun fichier interdit modifié. CSS injecté via `ctx.css('monde-m25', …)`, nœuds à IDs uniques avec garde d'existence, un seul abonnement `onHover` / `onLeave`, zéro `keydown`, zéro boucle rAF, zéro timer, zéro `IntersectionObserver`, zéro `console.*`, zéro `Math.random`, zéro réseau. Le module s'appuie exclusivement sur `highlight()` et les callbacks du registre pour connaître la cible des flèches.

## Blocages

- Aucun bloquant. M25 ne peut pas corriger l'asymétrie `lastFocusIndex` à la source (variable privée de globe.js) : il aligne le `tabindex` DOM, ce qui rétablit le parcours `Tab` sans toucher au point d'entrée. De même, il ne peut pas étiqueter l'origine clavier/souris d'un `onHover` ; le comptage de rebouclage est donc volontairement conservateur (focus clavier requis).
