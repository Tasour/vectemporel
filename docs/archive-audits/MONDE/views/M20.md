# M20 — Annonces live du survol (domaine D : accessibilité / région live)

Lentille : M20. Fichier possédé : `src/views/monde/M20.js`.
Lectures seules : `src/views/globe.js`, `src/views/globe-reveal.js`, `src/views/monde/registry.js`, `public/globe-engine.js`, `UNIFIED_AUDIT/MONDE/views/M07-raf-pause.md`.
Aucun fichier partagé modifié, aucun réseau, aucun `Math.random`, aucun `console.*`, aucun timer, aucune seconde région `aria-live`, aucun sélecteur de test ajouté.

**Constat fondateur.** Le globe possède deux chemins de survol :
- **Clavier** — `highlight()` (globe.js) appelle `notifyMondeHover(...)` **puis** `say("… Entrée pour ouvrir.")`. Le lecteur d'écran entend un message riche.
- **Pointeur** — le callback `onHover` du moteur (globe.js) met à jour `readoutNode` (`<p class="globe-hover-readout">`, sans `role`/`aria-live`) **sans jamais appeler `say()`**. Le survol est donc muet pour l'AT.

M20 ne comble que ce second chemin, en réutilisant l'unique région live `#globe-live` (`role="status"`, `aria-live="polite"`, `aria-atomic="true"`, appendée au `<body>` pour survivre au `innerHTML` du shell — globe.js C2-06).

---

## M20-01 — Réutiliser l'unique région live partagée, pas d' second `aria-live`

- **Preuve** : `ctx.say` (registry.js + globe.js `say()`) écrit dans `#globe-live`, déjà configuré en `polite`/`atomic`. Créer un second nœud `aria-live` produirait deux files d'annonces polies concurrentes, source de bégaiement et de courses entre AT.
- **Solution** : `sayFn = ctx.say` capturé une fois ; aucun `el('p')`, aucun `setAttribute('aria-live')`, aucun `document.body.appendChild` dans M20.
- **Impact** : une seule file d'annonces, cohérente avec `globe-status` et les messages de navigation.
- **Risque** : `ctx.say` pourrait manquer dans un contexte appauvri → garde `typeof sayFn === 'function'`.
- **Effort** : S
- **Vérification** : `grep -n 'aria-live' src/views/monde/M20.js` → 0 ligne ; survols successifs → seul `#globe-live` change.

## M20-02 — Enregistrement unique des callbacks `onHover`/`onLeave`

- **Preuve** : `hoverCallbacks`/`leaveCallbacks` sont des tableaux module (registry.js:8-9) ; `notifyMondeHover()` appelle **tous** les callbacks enregistrés. `runMondeEnhancements()` est rejoué à chaque rendu du globe → sans garde, trois rendus donnent trois annonces par survol.
- **Solution** : garde module `hooksRegistered`, posée une seule fois après vérification que `ctx.onHover` et `ctx.onLeave` sont des fonctions.
- **Impact** : exactement une annonce par changement de pays, quel que soit le nombre de re-renders.
- **Risque** : la garde doit vivre au niveau module (pas dans le corps du greffon), sinon elle est réinitialisée à chaque `apply()`.
- **Effort** : S
- **Vérification** : trois rendus du globe puis un survol → `host.dataset.m20Announced` n'augmente que d'une unité.

## M20-03 — Message concis, chiffré et robuste aux données partielles

- **Preuve** : `countryMeta()` de globe.js dérive `eras`, `events`, `points` et `domains` des objets pays ; le rapport d'audit exige des grandeurs référencées. Un pays peut manquer `points` ou `domain`.
- **Solution** : `describe()` compose `Nom · année → année · N ères · N repères · N points · k/14 domaines.` avec `safeList()`, `formatYear()` (gère av. J.-C.) et `plural()`. Aucun `undefined`, aucun `NaN`.
- **Impact** : Information lisible sans voir le canvas, alignée sur les chiffres du readout visuel ; aucune information portée par la seule couleur.
- **Risque** : un libellé trop long sature la file `polite` → format borné à ~80 caractères, une seule phrase.
- **Effort** : M
- **Vérification** : survols FR et CD → le message contient « ère(s) », « repère(s) », « domaines » et une plage d'années.

## M20-04 — Dédupage par code : neutraliser le double appel de `highlight()`

- **Preuve** : `setHover()` (globe-engine.js:108) fait `if (state.hoverCode === code) return;` mais `highlight()` de globe.js appelle **aussi** `notifyMondeHover(country, code)` explicitement après `setHover()`. Le callback M20 reçoit donc deux fois le même pays sur une navigation clavier.
- **Solution** : `lastCode` module ; si `code === lastCode`, on met à jour le miroir puis on retourne sans annoncer ni incrémenter le compteur.
- **Impact** : une annonce par changement réel de pays ; pas de bégaiement perçu.
- **Risque** : `lastCode` doit être remis à `null` sur `onLeave` (M20-06), sinon un retour sur le même pays serait muet.
- **Effort** : M
- **Vérification** : focus clavier A → B → focus répété sur B → une seule annonce pour B.

## M20-05 — Annonce synchrone, sans timer de debounce : l'ordre fait gagner le clavier

- **Preuve** : dans `highlight()`, l'ordre est `notifyMondeHover(...)` **puis** `say(messageClavier)`. Un `say()` synchrone dans M20 est donc écrasé par le message clavier riche (avec « Entrée pour ouvrir ») : une seule annonce finale, la bonne. Dans le chemin pointeur (`engine.onHover`), globe.js **ne** call pas `say()` : le message M20 reste et est annoncé.
- **Solution** : `sayFn(message)` appelé directement ; aucun `setTimeout`, aucun `requestAnimationFrame`, aucun micro-task différé. Cohérent avec M07-02/M07-06 (zéro timer dans les lentilles).
- **Impact** : pas de double annonce, pas de timer parasite, préservation de l'indication clavier.
- **Risque** : si une AT lit des mutations intermédiaires (cas rare, les mutations synchrones sont normalement coalescées), elle pourrait énoncer M20 puis le message clavier ; la valeur finale reste correcte, et aucun timer n'est ajouté.
- **Effort** : M
- **Vérification** : clavier → `#globe-live` se termine par « Entrée pour ouvrir. » ; pointeur → contient le message M20.

## M20-06 — Sortie de survol : réinitialiser sans bavarder

- **Preuve** : `onPointerLeave()` fait `setHover(null)` (globe-engine.js:422-424) → `onHover(null)` → `notifyMondeLeave()` (globe.js). Le readout visuel passe à « aucun pays sous le pointeur ».
- **Solution** : `handleLeave()` remet `lastCode = null` et vide `host.dataset.m20Hover`, sans écrire dans la région live. Le compteur cumulé reste intact (audit).
- **Impact** : un retour sur le même pays est ré-annoncé ; pas de « survol terminé » superflu qui polluerait la file.
- **Risque** : ne jamais écraser ici un message de navigation précédent (ex. « Chronologie ») : M20 ne touche pas au live sur `leave`.
- **Effort** : S
- **Vérification** : survols A → sortie → A → deux annonces distinctes ; le texte live n'est pas vidé artificiellement.

## M20-07 — Silence en arrière-plan

- **Preuve** : M07 pose `data-m07-raf-phase` (`hidden`/`active`/`idle`) ; globe.js pose `data-globe-active`. Une annonce dans un onglet masqué est inutile et peut être rejouée au retour.
- **Solution** : garde `if (document.hidden) return;` **après** mise à jour de `lastCode` et du miroir. Pas de garde sur `globeActive` : le chemin mouvement réduit (`drawStaticFrame()`) laisse ce marqueur à `0` tout en restant un survol légitime (voir M20-10).
- **Impact** : zéro annonce fantôme ; aucun rattrapage au retour d'onglet.
- **Risque** : si un même pays était survolé au moment du masquage puis au retour, il ne sera pas ré-annoncé tant que le code ne change pas — comportement voulu.
- **Effort** : S
- **Vérification** : masquer l'onglet, injecter `notifyMondeHover` via le registre → `m20Announced` inchangé.

## M20-08 — Miroir d'état auditable, sans sélecteur de test

- **Preuve** : M06 et M07 exposent des `data-*` pour audit sans `console.*`. `#globe-canvas` est un ID stable (globe.js `ensure()`), pas un hook de test créé par M20.
- **Solution** : poser sur `ctx.host` `dataset.m20Hover = code` et `dataset.m20Announced = compteur cumulé`. Aucun nouvel `id`, aucune classe, aucun `data-testid`.
- **Impact** : état vérifiable par inspection DOM, sans modifier le fichier partagé.
- **Risque** : `ctx.host` peut être absent → garde `host && host.dataset`.
- **Effort** : S
- **Vérification** : après survol FR, `document.getElementById('globe-canvas').dataset.m20Hover === 'FR'`.

## M20-09 — Robustesse aux payloads partiels et codes inconnus

- **Preuve** : `notifyMondeHover(country, code)` est appelé depuis trois sites (highlight, callbacks moteur, éventuelles lentilles). Un `country` nul ou un `code` incohérent doit être traité comme une sortie, pas comme une annonce.
- **Solution** : `const code = data.code || (country && country.code) || null` ; si `!country || !code` → `handleLeave()`. `safeList()` sur toutes les collections. Aucune exception levée (le registre `safe()` avalerait silencieusement l'erreur, mais on préfère le no-op explicite).
- **Impact** : aucun « Pays undefined », aucune exception, aucune fausse annonce.
- **Risque** : un code inconnu ne doit jamais être announcé sous peine de désinformer → rejet systématique.
- **Effort** : S
- **Vérification** : appeler `notifyMondeHover(null, 'XX')` via le registre → aucun changement du live ni du compteur.

## M20-10 — Indépendance au mouvement réduit et au `reveal`

- **Preuve** : `globe-reveal.js` et `ctx.reducedMotion` (utilisé par M15 pour le zoom) ne concernent que l'animation. Une annonce est textuelle et doit rester disponible quand `prefers-reduced-motion: reduce` est actif.
- **Solution** : M20 n'appelle ni `reveal`, ni `selectCountry`, ni aucune API WAAPI/CSS ; il ne consulte pas `reducedMotion()`. Le patch de M15 sur `figure.animate` reste intact.
- **Impact** : accessibilité identique pour tous les profils, y compris AT + mouvement réduit ; aucune interférence inter-lentilles.
- **Risque** : une future lentille qui remplacerait `ctx.say` doit le faire avant M20 dans l'ordre d'enregistrement ; M20 capture `say` à l'installation.
- **Effort** : S
- **Vérification** : `reducedMotion() === true` → le survol annonce toujours ; `grep -n 'reveal' src/views/monde/M20.js` → 0 ligne d'appel.

## Blocages

- Aucun bloquant. M20 ne peut pas modifier `globe.js` pour ajouter un `say()` dans le callback `onHover` du moteur : le fichier n'est pas possédé. La lentille compense via `onHover` du registre, qui est notifié sur ce même chemin (globe.js `notifyMondeHover(country, code)`).
- M20-05 repose sur l'ordre d'appel `notifyMondeHover` → `say` dans `highlight()`. Si cet ordre venait à être inversé dans `globe.js`, le chemin clavier annoncerait deux fois ; la garde `lastCode` limiterait le doublon côté M20 mais l'indication « Entrée pour ouvrir » pourrait être remplacée. À réévaluer lors d'une refonte de `highlight()`.
