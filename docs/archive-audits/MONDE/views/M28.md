# M28 — Aide contextuelle du globe

Lentille M28 — domaine C : ergonomie & interaction.
Fichier possédé : `src/views/monde/M28.js` uniquement. L'aide de la coque (`src/ui/shell.js`, `renderHelp` / `#atlas-help`) n'est ni éditée ni doublée : M28 ajoute un panneau LOCAL et non modal, dédié à la vue Monde, avec sa propre commande. Contrat exploité : `scene`, `host`, `css`, `el`, `say`, `countries` et les signaux DOM déjà écrits par `globe.js` ; aucune dépendance vers `onReady`/`onHover`/`onLeave`, `selected` ou `state`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`. CSS injecté par `ctx.css('monde-m28', …)`.

## M28-01 — Panneau local non modal, complément de l'aide générale

- **Preuve** : `M28.js:199-210` construit une `<section role=region aria-labelledby=…>` avec un `<h2>`, un `tabIndex=-1` et un paragraphe explicite : « La touche ? ouvre l'aide générale de l'application : ce panneau la complète, il ne la remplace pas. » `M28.js:30-37` le positionne en `position:absolute; left:72px; bottom:16px; z-index:6`, `width:min(330px,46vw)`, `max-height:min(62vh,460px)` : aucun `backdrop`, aucun `role=dialog`, aucun `aria-modal`, aucun piège de focus. `M28.js:262` passe par `ctx.css(CSS_ID, CSS)` (cssOnce).
- **Solution** : conserver le panneau comme région annotée du stage, jamais comme modale. Le texte de complémentarité est écrit dans le DOM statique ; `TITLE_ID` (`M28.js:26`, `:205-207`) étiquette la région. La structure statique n'est construite qu'une fois (`:198`, `:277-284`) ; seul `.m28-context` est remplacé. `#atlas-help` et `renderHelp` ne sont jamais touchés.
- **Impact** : l'aide contextuelle n'interrompt ni le survol ni le parcours clavier du globe ; les deux aides restent disponibles avec une frontière explicite entre l'aide globale (`?`) et l'aide locale.
- **Effort** : S
- **Vérification** : relecture — aucun `role=dialog`, `aria-modal` ni `inert` ; `role=region` et `aria-labelledby` présents ; le panneau n'est pas un `<dialog>` ; `#atlas-help` absent du module.

## M28-02 — Commande dédiée, sans raccourci global ni conflit routeur

- **Preuve** : `M28.js:289-304` crée un unique `<button id=monde-m28-help-button>` de libellé visuel « i », avec `aria-label="Aide contextuelle du globe"`, `aria-controls=PANEL_ID`, `aria-expanded`, `type=button` et un `title` qui rappelle que `?` ouvre l'aide générale. Il est inséré dans `.globe-controls` s'il existe, sinon dans la scène (`:302-304`). `M28.js:14-20` pose l'invariant : aucune touche globale, `?` et Échap restent au routeur (`keyboard.js`), Échap n'étant consommé que si le panneau a le focus.
- **Solution** : la commande est un bouton natif local, sans écouteur documentaire, sans lettre réservée et sans `data-fk` susceptible de détourner la restauration de focus de la coque. `setOpen()` (`:175-189`) bascule `hidden`, `aria-expanded` et `host.dataset.m28Help`, puis rend le focus au bouton à la fermeture (`restoreFocus`).
- **Impact** : aucune régression des raccourcis de vue ; l'état d'ouverture est exposé aux technologies d'assistance (`aria-expanded`) et au CSS (signal `data-m28-help`).
- **Effort** : S
- **Vérification** : relecture — aucun `document.addEventListener`, aucune touche `?` interceptée, `aria-controls`/`aria-expanded` cohérents ; clic sur « i » puis Échap hors panneau : le routeur seul répond.

## M28-03 — Contexte calculé depuis le HUD, sans date ni total codé en dur

- **Preuve** : le commentaire `M28.js:139` l'énonce : « Aucune date ni aucun total codé en dur : tout vient du HUD ou des données. » `contextLines()` (`:140-156`) lit `#globe-status` (`data-kind`), `selectedLabel()`, le readout de survol et `reducedMotion()` ; `eventCount()` (`:111-113`) compte `country.events.length`, `selectedLabel()` (`:125-130`) compose le libellé et le nombre de repères. Aucune chaîne numérique historique n'apparaît dans le module.
- **Solution** : chaque ligne du bloc « Contexte courant » est dérivée d'un signal réel déjà présent dans la vue : sélection, survol, état du moteur, mouvement. Le greffon n'invente ni période ni chiffre ; il se contente de rendre lisible l'état courant dans le panneau.
- **Impact** : le panneau reste vrai quand le jeu de données évolue ; ses affirmations sont falsifiables par observation directe du HUD et de la liste.
- **Effort** : S
- **Vérification** : relecture — absence de millésime, de total littéral, de `DATASET` importé ; faire varier la sélection et le survol : les lignes changent sans modifier le code.

## M28-04 — Sélection résiliente à trois sources

- **Preuve** : `selectedCountry()` (`M28.js:115-123`) essaie `ctx.selected.name`, puis `host.dataset.globeSelected` résolu contre `ctx.countries` par `country.code`, puis retourne `null`. `selectedLabel()` (`:125-130`) retombe sur `.globe-country[aria-current="true"] .globe-country-name`. Le contrat du module (`:10-12`) déclare explicitement l'absence de dépendance à `ctx.selected`, `onReady`, `onHover`, `onLeave` ou `state`.
- **Solution** : hiérarchie de repli en trois niveaux, avec tolérance au `ctx` minimal : l'aide reste active même si la lentille ne reçoit aucun objet de sélection, car le DOM du globe porte déjà l'information. Le nombre de repères est calculé depuis `events` (`:111-113`), jamais supposé.
- **Impact** : pas de panneau vide ni de « Sélection : aucun pays » erroné quand la sélection est connue du seul HUD ; compatibilité avec un registre qui n'exposerait que partie du contrat.
- **Effort** : M
- **Vérification** : relecture des trois branches ; harnais DOM : (a) `ctx.selected` seul, (b) `data-globe-selected` seul, (c) `aria-current` seul, (d) aucun signal → quatre libellés corrects, dont le repli explicite « aucun pays ».

## M28-05 — Survol normalisé avec repli explicite

- **Preuve** : `hoverLabel()` (`M28.js:132-137`) lit `#globe-hover-readout`, retourne « Survol : informations indisponibles. » si le texte est vide, préfixe sinon « Survol : », et applique `withDot()` (`:97-100`) qui ajoute un point final seulement si nécessaire. Le commentaire `:139` interdit toute date codée en dur, y compris dans cette ligne.
- **Solution** : une seule fonction de normalisation (`withDot`) sert toutes les lignes de contexte ; le préfixe « Survol : » distingue l'information transitoire de la sélection ; l'absence de readout est traitée comme un état et non comme une erreur silencieuse.
- **Impact** : le panneau ne peut pas afficher une ligne vide ou sans ponctuation ; le repli dit clairement que l'information n'est pas disponible, sans inventer de pays.
- **Effort** : S
- **Vérification** : relecture de `withDot()` et `hoverLabel()` ; contrôles : texte vide → phrase de repli ; « France » → « Survol : France. » ; « Survol : Japon. » → inchangé (pas de double préfixe).

## M28-06 — États du moteur 3D et repli sur la liste

- **Preuve** : `contextLines()` (`M28.js:141-151`) branches sur `data-kind` de `#globe-status` : `ready` → « Moteur 3D prêt : la sphère répond au pointeur et au clavier. » ; `error` → « Moteur 3D indisponible : la liste des pays reste utilisable. » ; sinon (`busy`) → « Moteur 3D en chargement : la liste des pays est déjà utilisable. ». La valeur par défaut est `busy` si l'attribut manque (`:142`).
- **Solution** : trois états explicitement nommés, tous accompagnés d'une information d'usage ; le cas d'erreur n'est pas masqué et rappelle le repli DOM. Le défaut prudent (`busy`) évite d'annoncer un moteur prêt quand le signal n'existe pas encore.
- **Impact** : un utilisateur dont le WebGL échoue sait immédiatement que la liste des pays reste actionnable ; l'aide ne promet pas une interaction que le moteur ne fournit pas.
- **Effort** : S
- **Vérification** : relecture des trois branches ; harnais : `data-kind=ready|error|absent` → trois lignes distinctes, chacune se terminant par un point.

## M28-07 — Mouvement réduit détecté, texte et CSS cohérents

- **Preuve** : `reducedMotion()` (`M28.js:102-109`) interroge d'abord `ctx.reducedMotion()` dans un `try/catch`, puis `window.matchMedia('(prefers-reduced-motion: reduce)')` dans un second `try/catch`, avec repli `false`. `contextLines()` (`:152-154`) en déduit « Mouvement réduit détecté : rotation inactive, image statique. » ou « Rotation automatique active : le bouton « Rotation » la met en pause. ». La feuille (`:67-69`) neutralise les transitions sous `prefers-reduced-motion`.
- **Solution** : double source de vérité avec repli sûr, et aucune animation propre à M28 : ni rAF, ni timer, ni transition utile. Le texte décrit exactement le comportement observable de la scène.
- **Impact** : l'aide ne contredit pas le réglage système ; les utilisateurs sensibles au mouvement obtiennent une explication de l'image statique sans changer de préférence.
- **Effort** : S
- **Vérification** : relecture des deux `try/catch` ; émuler `prefers-reduced-motion: reduce` → ligne « rotation inactive » ; vérifier l'absence de `requestAnimationFrame`, `setTimeout` et de transition active dans la feuille.

## M28-08 — Annonces maîtrisées : `say()` seul, dédupliquées, Échap local

- **Preuve** : `announce()` (`M28.js:85-90`) ne parle que par `currentCtx.say()`, refuse un texte vide ou identique au dernier (`lastAnnouncement`) et exige une fonction `say`. `setOpen()` (`:175-189`) annonce ouverture/fermeture avec le premier élément de contexte ; `:172` annonce une actualisation seulement si le panneau est ouvert. `M28.js:234-239` attache Échap au panneau seul, avec `preventDefault()`, `stopPropagation()` et retour de focus au bouton ; le commentaire `:232-233` documente l'absence de conflit avec `keyboard.js:143-154`.
- **Solution** : aucun ajout de région live, aucune écriture dans `#globe-live` (M20) ni dans la coque ; déduplication par `lastAnnouncement`, remise à zéro à chaque installation (`:261`). Le focus est déplacé vers le panneau à l'ouverture (`:184`) et rendu à la commande à la fermeture (`:186`).
- **Impact** : une seule annonce par action, pas de bavardage sur les mutations de survol (`refreshContext` appelle `doAnnounce=false` depuis l'observateur), et Échap ferme le panneau sans détourner le routeur quand le focus est ailleurs.
- **Effort** : M
- **Vérification** : relecture — absence de `role=status` ajouté, un seul `say(` ; harnais : deux clics d'affilée → une seule annonce différente ? ; Échap dans le panneau → fermeture et focus sur `#monde-m28-help-button` ; Échap sur la sphère → non traité par M28.

## M28-09 — Rafraîchissement sans `innerHTML`, signature et compteurs auditables

- **Preuve** : `refreshContext()` (`M28.js:163-173`) calcule `signature = lines.join(' | ')`, sort sans rien écrire si elle est inchangée, incrémente `contextCount`, puis `contextBody.replaceChildren(...lines.map(...ctx.el('p', '', line)))`. `writeMetrics()` (`:158-161`) affiche « Ouvertures : N · Contextes affichés : N. » dans `p.m28-metrics` (`:229`, `:63`), hors région live. `openCount` est incrémenté à chaque ouverture réelle (`:181`), pas à chaque rendu.
- **Solution** : le DOM statique est construit une seule fois (`buildPanel`, `:198-240`) ; seul le bloc de contexte est remplacé, par des nœuds créés via `ctx.el`. La signature évite les écritures redondantes déclenchées par l'observateur, et les compteurs donnent une trace vérifiable du comportement du greffon.
- **Impact** : aucun `innerHTML`, aucune réinterprétation du balisage, nombre borné d'écritures DOM ; les métriques permettent de distinguer « pas de changement de contexte » de « greffon muet ».
- **Effort** : M
- **Vérification** : relecture — absence de `innerHTML`, `insertAdjacentHTML`, `outerHTML` ; rejeu : ouvrir (1 ouverture, 1 contexte), survol sans changement de signature (compteurs stables), changer de pays (contextes +1).

## M28-10 — Observateur unique ciblé, hors panneau, et greffon idempotent

- **Preuve** : `observeTargets()` (`M28.js:243-256`) déconnecte l'observateur existant avant d'en créer un seul, puis observe exactement trois cibles : `#globe-hover-readout` (`childList`, `characterData`, `subtree`), `#globe-status` (attribut `data-kind`) et `host` (attribut `data-globe-selected`). Le commentaire `:242` précise : « jamais sur le panneau (sinon boucle d'écriture) ». `install()` (`:258-316`) détecte un rendu neuf par nœud déconnecté (`:270-271`), retire un panneau/bouton mal parenté (`:272`, `:290`), réinitialise `open` et `renderedSignature` (`:308-311`) et écrit le signal `host.dataset.m28Help` (`:179`, `:314`).
- **Solution** : un seul `MutationObserver` par rendu, déconnecté puis reconnecté, ciblé sur les signaux en lecture seule ; le panneau n'est jamais observé. L'installation est idempotente : CSS unique, panneau unique, bouton unique, aucun stockage de nœud périmé ; la feuille (`:29`, `:39-40`, `:56-63`, `:64-69`) porte cibles ≥ 36 px, focus visible et repli mobile à 900 px.
- **Impact** : pas de boucle d'écriture, pas de doublon après navigation, pas de fuite d'écouteurs ; l'aide reste lisible en 390×844 et les zones tactiles restent atteignables.
- **Effort** : M
- **Vérification** : relecture — un seul `new MutationObserver`, un `disconnect()` préalable, aucune observation du panneau ; `node --check src/views/monde/M28.js` PASS ; rendu → navigation aller-retour → rendu : un seul `#monde-m28-help-button`, un seul `#monde-m28-help-panel`, état `open` remis à zéro, capture 390×844 sans débordement.

## Statut d'implémentation

Les dix chantiers M28-01 à M28-10 sont implémentés dans `src/views/monde/M28.js` uniquement. CSS injecté via `ctx.css('monde-m28', …)`. Aucune aide de la coque modifiée, aucune donnée inventée, aucun fichier partagé touché.

## Blocages / limites inter-domaines

- Échap n'est consommé que si le panneau porte le focus (`M28.js:234-239`) ; la fermeture par Échap depuis la sphère reste une affaire de routeur (`keyboard.js`), fichier non possédé.
- L'état d'ouverture est volatile : un rendu neuf de la coque (`shell.js:533`) le remet à zéro (`M28.js:268-271`, `:308-311`). Le conserver entre rendus demanderait un état partagé hors du contrat de la lentille.
- Le panneau décrit l'état du moteur via `data-kind` et les libellés du HUD ; il ne corrige pas un HUD erroné. Aucune information nouvelle n'est émise hors de `ctx.say()`.
- Le signal `host.dataset.m28Help` est écrit par M28 (`:179`, `:314`) ; toute autre lentille qui réécrirait `host.dataset` devra le préserver.
