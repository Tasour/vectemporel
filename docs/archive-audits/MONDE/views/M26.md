# M26 — Sélection courante du pays (domaine C : ergonomie & interaction)

Lentille : M26. Fichier possédé : `src/views/monde/M26.js`.
Lectures seules : `src/views/globe.js`, `src/domain/store.js`, `src/views/monde/registry.js`,
`src/views/globe-reveal.js`, `UNIFIED_AUDIT/MONDE/README.md`.
Aucun fichier partagé modifié, aucun réseau, aucun `Math.random`, aucun `console.*`,
aucun sélecteur de test créé ou modifié, zéro timer et zéro boucle `requestAnimationFrame`.

---

## M26-01 — Une seule source de vérité : `state.countryId`

- Preuve : la sélection est portée par `state.countryId` (store.js:43) et par l'unique porte
  d'écriture `set()` (store.js:216-253). `globe.js:313` ne fait que dériver `ctx.selected`
  avec `DATASET.countries.find(...)` ; `selectCountry()` (store.js:272-280) est la seule
  transition qui l'écrit. Le contrat `ctx` du registre (registry.js:7-12) donne l'état et le
  pays courant, pas un possesseur de sélection.
- Solution : `resolve(ctx)` recalcule à chaque appel la sélection depuis `ctx.state.countryId`
  et `ctx.countries`. L'état de module `local` ne conserve que des références DOM, des gardes
  d'idempotence et des identifiants déjà annoncés — jamais un pays « courant » qui pourrait
  devenir périmé.
- Impact : zéro divergence silencieuse entre l'affichage et le store, y compris après un
  retour navigateur ou une hydratation de deep link (store.js:611-631).
- Risque : copier `ctx.selected` dans une variable de module la figerait au premier rendu ;
  les rappels du registre survivant aux rendus (registry.js:50-66) écriraient alors un pays
  obsolète. La résolution systématique écarte ce risque.
- Effort : S
- Vérification : `grep -n 'Math.random\|state.countryId' src/views/monde/M26.js` → aucune
  écriture de `state`, une seule lecture, et aucun champ de sélection permanent dans `local`.

## M26-02 — Résolution par identifiant, repli déterministe sur « aucun pays »

- Preuve : `coerce('countryId')` (store.js:92-95) refuse tout identifiant absent du dataset ;
  `countryId = null` est un état légal (globe.js:376-378 affiche « Aucun pays sélectionné »).
  Résoudre par nom, code ou position serait ambigu et pourrait sélectionner le mauvais pays.
- Solution : `findIndex(c => c.id === id)` sur `ctx.countries`, avec `id` chaîne non vide.
  Pas de repli sur le premier pays, pas de valeur par défaut : identifiant introuvable ou
  vide ⇒ `country = null`, `index = -1`.
- Impact : le badge affiche exclusivement un pays réellement sélectionné ; aucun pays
  « inventé » en cas d'état corrompu.
- Risque : un `ctx.selected` périmé transmis par un rendu précédent pourrait tenter un repli ;
  le module ne l'utilise que pour l'audit M26-10, jamais pour la résolution.
- Effort : S
- Vérification : forcer `state.countryId` à une valeur inconnue puis rendre le globe → le
  badge porte « Aucun pays sélectionné » et `data-m26-selected=""`.

## M26-03 — Miroir auditable `data-m26-selected`, distinct de `data-globe-selected`

- Preuve : `globe.js:394` écrit déjà `host.dataset.globeSelected = currentCode || ''`
  (un **code** ISO). Un second greffon qui réécrirait cet attribut entrerait en conflit avec
  `syncEngine()` (globe.js:159) et casserait les attentes E2E de la vue.
- Solution : le module écrit des attributs propres sur le host réutilisé : `data-m26-selected`
  (identifiant stable), `data-m26-position` (rang 1-based), `data-m26-total`, `data-m26-coherent`.
  Le miroir existant n'est que **lu** pour l'audit.
- Impact : état de sélection observable sans instrumentation, sans console et sans toucher
  aux attributs possédés par `globe.js`.
- Risque : écrire sur `data-globe-selected` ; explicitement interdit, les noms `m26-*` sont
  réservés au greffon.
- Effort : S
- Vérification : après sélection de la France, `#globe-canvas.dataset.m26Selected === 'france'`
  et `dataset.globeSelected === 'FR'` restent tous deux vrais.

## M26-04 — Badge visuel silencieux, sans doublon de région live

- Preuve : `globe.js:73-85` possède l'unique région live `#globe-live` (hors de `#app`, pour
  survivre au `innerHTML` de la coque). Ajouter une seconde région `aria-live` annoncerait
  deux fois la même sélection. Les lentilles M14/M17 affichent déjà le survol.
- Solution : le nœud `#m26-current` est un badge **visuel** marqué `aria-hidden="true"` et
  `pointer-events:none`, fixé dans le host persistant. Il reprend la graphie exacte du nom et
  les chiffres du pays ; la parole passe par `ctx.say` (M26-05).
- Impact : zéro redondance pour les lecteurs d'écran, aucune cible cliquable parasite, aucun
  sélecteur de test modifié.
- Risque : retirer `aria-hidden` transforme le badge en doublon de `.globe-here`
  (globe.js:376-378) ; la garde est explicite dans `ensureChip()`.
- Effort : S
- Vérification : `document.getElementById('m26-current').getAttribute('aria-hidden') === 'true'`
  et le computé `pointer-events` vaut `none`.

## M26-05 — Annonce unique et dédupliquée via `ctx.say`

- Preuve : `runMondeEnhancements()` est rejoué à chaque rendu du globe (globe.js:442), donc un
  greffon naïf réannoncerait « Pays sélectionné » à chaque ouverture de modale ou changement
  de vue. `say()` (globe.js:148-150) écrit dans la région live unique.
- Solution : `announce(res)` compare l'identifiant résolu à `local.announcedId` et ne parle
  qu'au changement réel. Le message est dérivé du pays (nom + ères + repères + points), jamais
  inventé. `say` est vérifié fonction avant appel.
- Impact : une seule annonce par changement de sélection, cohérente avec `state.notice`
  (store.js:164-166, raison `'country'`).
- Risque : `ctx.say` absent dans un contexte minimal → le greffon reste muet au lieu de lever
  une erreur neutralisée par le registre.
- Effort : S
- Vérification : trois rendus successifs sans changement de `countryId` → une seule écriture
  dans `#globe-live` imputable à M26 ; changer de pays → une nouvelle annonce.

## M26-06 — Ordinal calculé depuis `countries`, aucune constante d'effectif

- Preuve : `globe.js:395` trie une copie pour l'affichage mais numérote les boutons avec
  l'index du dataset d'origine (globe.js:397, 405). `globe.js:380` affiche
  `DATASET.countries.length`. Écrire « 10 » en dur casserait l'affichage si le dataset évolue.
- Solution : `res.index + 1` et `res.total` viennent de `ctx.countries` ; le badge affiche
  « Pays N sur T » et, en cas d'absence de sélection, « Aucun pays sur T ».
- Impact : cohérence avec la numérotation des dix boutons et avec le fil de situation C2.
- Risque : utiliser l'index du tableau trié par nom donnerait un rang différent de celui des
  boutons ; `resolve()` interroge `ctx.countries` dans son ordre d'origine.
- Effort : S
- Vérification : le rang du pays affiché dans le badge égale `data-m26-position` et le
  `data-index` du bouton `aria-current="true"`.

## M26-07 — Chiffres vérifiables : ères, repères, points

- Preuve : `countryMeta()` (globe.js:124-133) et `describe()` (globe.js:117-122) comptent les
  mêmes tableaux du dataset ; `store.js:516-541` expose `getDiagnostics()` sans jamais inventer
  de valeur. Le subtitle (globe.js:373) cite 784 cellules vérifiées, chiffre global distinct.
- Solution : `count()` ne retourne que la longueur d'un tableau réel ; le badge affiche
  `N ères · N repères · N points` avec une pluralisation française (`n > 1` → pluriel).
- Impact : toute grandeur chiffrée est recalculée depuis sa source, réfutable et non portée
  par la seule couleur.
- Risque : compter les points validés (`meta.validatedPoints`) et les présenter comme les
  points du pays serait une confusion ; le module ne lit que `country.points`.
- Effort : S
- Vérification : pour la France, les trois nombres du badge correspondent à
  `country.eras.length`, `country.events.length`, `country.points.length`.

## M26-08 — Sélection stable face au survol et à la révélation

- Preuve : `notifyMondeHover/Leave` (registry.js:62-68) sont émis par `highlight()` et par le
  moteur (globe.js:193, 455) ; M17 fait suivre sa légende au survol, ce qui est son rôle. La
  sélection, elle, ne change que via `selectCountry()` (store.js:272). `reveal.isRevealing()`
  (globe-reveal.js:245) signale le zoom en cours.
- Solution : `onHover`/`onLeave` ne stockent qu'un code de survol dans une ligne secondaire
  du badge ; le nom, les chiffres et l'identifiant restent ceux de `resolve(ctx)`. Pendant la
  révélation, l'indice de survol est neutralisé pour ne pas superposer deux identités.
- Impact : compréhension claire de « ce qui est choisi » versus « ce qui est pointé », sans
  modifier le masque possédé par `globe-reveal.js`.
- Risque : appeler `selectCountry`, `reveal.hover` ou `reveal.leave` depuis ces rappels
  provoquerait une boucle de sélection ; le greffon ne fait qu'écrire son propre badge.
- Effort : M
- Vérification : survoler un pays B alors que A est sélectionné → le nom du badge reste A,
  seul le suffixe « survol : B » apparaît ; après `onLeave`, le suffixe disparaît.

## M26-09 — Idempotence : un nœud, une feuille CSS, un rappel par rendu

- Preuve : `runMondeEnhancements()` vide `readyCallbacks`, `hoverCallbacks` et
  `leaveCallbacks` au début de chaque appel (registry.js:46-50) ; `cssOnce()` (registry.js:25-31)
  déduplique la feuille par son ID. Une garde module « enregistrer une seule fois » perdrait
  donc ses rappels dès le second rendu, tandis qu'une absence de garde avec l'ancien contrat
  les dupliquerait.
- Solution : `ctx.css('monde-m26', CSS)` et un abonnement `onReady`/`onHover`/`onLeave`
  **par appel du greffon** — jamais plus, puisque le registre repart de tables vides. Le nœud
  `#m26-current` est retrouvé par `getElementById` puis rattaché au host courant ; `local.ctx`
  est rafraîchi à chaque rendu pour que les rappels lisent des références fraîches.
- Impact : zéro accumulation de callbacks, zéro rappel perdu après re-render, zéro nœud fantôme.
- Risque : le host est réutilisé par `ensure()` (globe.js:263-292) tandis que la scène est
  recréée ; rattacher le badge à la scène le perdrait à chaque rendu. Le host est donc le
  parent choisi, avec repli sur la scène si le host n'est pas connecté.
- Effort : M
- Vérification : `document.querySelectorAll('#m26-current').length === 1` et une seule entrée
  `M26` dans `mondeDiagnostics().entries`, même après trois rendus ; un `notifyMondeHover`
  après le troisième rendu met encore à jour le badge.

## M26-10 — Cohérence auditable et mouvement réduit, sans console

- Preuve : trois sources décrivent la même sélection — `state.countryId`, `ctx.selected`
  (globe.js:313), `host.dataset.globeSelected` (globe.js:394) — plus le bouton
  `aria-current="true"` (globe.js:414) possédé par la vue. Aucun moyen déclaratif ne signale
  une divergence, et tout `console.*` est interdit par la vague.
- Solution : `audit()` compare ces sources en lecture seule et écrit
  `host.dataset.m26Coherent = '1' | '0'`. Aucun attribut possédé par `globe.js` n'est écrit,
  aucun sélecteur de test n'est touché. Le CSS du badge neutralise transitions et animations
  sous `prefers-reduced-motion` ; le module ne contient ni rAF, ni timer, ni IntersectionObserver.
- Impact : divergence détectable par simple lecture de `dataset`, sans instrumentation ni
  bruit console ; conformité mouvement réduit héritée de `ctx.reducedMotion` (non nécessaire
  ici, aucun mouvement n'étant introduit).
- Risque : un contrôle de `aria-current` écrirait dans un sélecteur de test ; le module se
  limite aux `data-m26-*` et ne lit que `globeSelected` existant.
- Effort : M
- Vérification : `grep -nE 'console\.|Math\.random|setTimeout|setInterval|requestAnimationFrame|IntersectionObserver|aria-current' src/views/monde/M26.js` → 0 ligne ;
  `data-m26-coherent="1"` en fonctionnement nominal, `'0'` si l'une des trois sources diverge.

## Statut d'implémentation

Les 10 chantiers sont implémentés dans `src/views/monde/M26.js`. CSS injecté via
`ctx.css('monde-m26', …)`, nœud `#m26-current` à ID unique et garde d'existence, un `onReady`,
un `onHover` et un `onLeave` par rendu (tables vidées par le registre), zéro écriture dans le store, zéro fichier
partagé modifié, zéro réseau, zéro aléa, zéro `console.*`, zéro timer, zéro rAF.

## Blocages

- Aucun bloquant. M26 ne possède ni `selectCountry()` ni `syncEngine()` : il ne peut pas
  corriger une divergence, seulement la rendre visible via `data-m26-coherent`. Toute
  correction relève de `globe.js`/`store.js`, fichiers non possédés par cette lentille.
- L'annonce M26-05 cohabite avec `#globe-live` : en cas de survol simultané, le dernier
  message écrit gagne. C'est le contrat de la région live unique, documenté ici plutôt que
  contourné par une seconde région.
