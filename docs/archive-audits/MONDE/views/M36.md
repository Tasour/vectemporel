# M36 — Provenance des sources (domaine D : données & sémantique)

Lentille : M36. Fichier possédé : `src/views/monde/M36.js`.
Lectures seules : `src/data/dataset.js`, `source/audits/*/source-register.csv`, `source/audits/_AGENT_BRIEF.md`, `src/views/globe.js`, `src/views/monde/registry.js`, `UNIFIED_AUDIT/MONDE/SYNTHESE.md`.
Aucun fichier partagé modifié, aucun réseau, aucun `Math.random`, aucun `console.*`, aucun lien externe, aucune donnée inventée.

Chiffres de référence relevés dans `src/data/dataset.js` (généré le 2026-11-18) : 10 pays · 200 sources (`sources` par pays, 20 chacun) · fiabilité 199 `high` / 1 `medium` · indépendance 181 `independent` / 17 `primary` / 2 `same_institution` · 67 claims (32 `certain`, 16 `disputed`, 19 `probable`) · 148 omissions · 587 points d'événement sur 901 sans source · 10 audits `verdict: pending` avec `signoff` vide.

---

## M36-01 — Registre de sources local, sans lien externe

- Preuve : `meta.externalLinks = false` (dataset.js:9). Chaque pays porte un tableau `sources` (ex. `SRC-001` : *Becoming Roman*, Greg Woolf, 1998, `high`, `independent`), avec `url`/`doi` présents mais non destinés à un rendu cliquable. Le registre CSV source (`source/audits/france/source-register.csv`) contient des URL DOI/BnF qui ne doivent pas être réintroduites dans la vue.
- Solution : le greffon construit un index local `id → {type, année, auteur, titre}` à partir de `country.sources` et ne rend que des mentions textuelles dans une `<ul>` (`textContent`, jamais `innerHTML`). Aucun `<a>`, aucun `href`, aucune lecture de `s.url` ou `s.doi`.
- Impact : la provenance est lisible et vérifiable hors ligne, sans quitter l'atlas.
- Risque : une évolution future pourrait transformer la mention en lien ; la règle est explicite en tête de fichier et vérifiable par `grep 'href='`.
- Effort : S
- Vérification : `grep -nE 'href=|<a |https?://|\.url|\.doi' src/views/monde/M36.js` → 0 ligne ; les `<li>` du panneau portent uniquement id/type/année/auteur/titre.

## M36-02 — Mesure de la dette de citation

- Preuve : sur 901 points d'événement, 587 ont `sources: []` (ex. `fr-massalia-point-1`, dataset.js:230). La couverture réelle est donc lacunaire et doit être mesurée, pas présumée.
- Solution : `computeStats()` parcourt `events[].points` et compte `epCited` (au moins une source) vs `epTotal` ; la phrase « Repères appuyés : X/Y · sans source : Z » est produite depuis ces deux entiers.
- Impact : la dette documentaire devient un indicateur chiffré et auditable, distinct du nombre de sources enregistrées.
- Risque : confondre `points` (140 par pays, tous sourcés) et `events[].points` (901, majoritairement non sourcés) ; le calcul sépare explicitement les deux corpus.
- Effort : M
- Vérification : sur la France, le panneau affiche `314/901` appuyés et `587` sans source ; valeurs recalculées depuis le dataset, non codées en dur.

## M36-03 — Distribution fiabilité / indépendance en clair

- Preuve : `sources[].reliability` et `sources[].independence` sont des énumérations (`high`/`medium` ; `independent`/`primary`/`same_institution`). Les 200 sources donnent 199/1 et 181/17/2.
- Solution : deux histogrammes `Object.create(null)` construits en une passe, puis rendus en français (`élevée`, `primaire`, `même institution`…) via une table de libellés, avec repli sur la valeur brute si elle est inconnue.
- Impact : le lecteur voit immédiatement le poids et l'autonomie des appuis, sans décodage des codes anglais.
- Risque : une valeur non prévue serait affichée telle quelle plutôt que perdue ; le libellé par défaut `non renseigné` couvre les champs vides.
- Effort : S
- Vérification : le panneau France porte « fiabilité : élevée 20 · indépendance : indépendante 18 · primaire 2 » (valeurs conformes au registre France).

## M36-04 — Traçabilité des claims (sujet–prédicat–objet)

- Preuve : `country.claims` contient 67 assertions (ex. `france-claim-002`, « Rafle du Vél' d'Hiv », `SRC-008`/`SRC-009`, `certain`) avec `subject`, `predicate`, `object`, `confidence`, `sources`.
- Solution : le greffon compte les claims par pays et par niveau de confiance, et expose `Citations distinctes` (union des `sources` de claims, points et événements). Les identifiants de claims restent des mentions locales.
- Impact : le lien assertion → source est rendu visible sans modifier la structure de données.
- Risque : les mêmes SRC étant cités par plusieurs objets, la union est un `Set` ; un double comptage fausserait le total.
- Effort : M
- Vérification : sur la France, `claims sourcés : 7` et `citations distinctes : 28` (dont des identifiants `OM-*`/`PROP-*`), cohérents avec le dataset.

## M36-05 — État d'audit non signé, jamais présenté comme validé

- Preuve : `country.audit.verdict = "pending"` pour les 10 pays ; `audit.signoff = {date:"", signed_by:[]}` ; `_AGENT_BRIEF.md:40-45` prescrit `verdict: pending`, scores `null`, `signoff` vide tant qu'il n'y a pas de double lecture.
- Solution : `statusText()` lit `audit.verdict` et `signoff`, et n'ajoute « signé » que si `date` **et** `signed_by` sont non vides ; sinon « non signé ». Aucune signature ni score n'est fabriqué.
- Impact : la lentille respecte la règle de non-publication et n'induit pas le lecteur en erreur sur le statut de validation.
- Risque : un `signoff` partiellement rempli (date sans signataire) est traité comme non signé — choix conservateur et documenté.
- Effort : S
- Vérification : le panneau affiche « Audit : pending · non signé » pour chacun des 10 pays.

## M36-06 — Dettes documentaires (omissions) comme provenance négative

- Preuve : `country.omissions` recense 148 identifiants `OM-*` sur l'ensemble des pays (15 par pays, sauf Espagne 13). Le README des audits (`source/audits/README.md:41-44`) exige que les absences soient documentées.
- Solution : le greffon compte `omissions.length` et l'affiche comme « Dettes documentaires : N omission(s) », sans inventer le contenu des omissions.
- Impact : une absence tracée devient un objet de provenance au même titre qu'une source citée.
- Risque :compter les omissions comme des sources contaminerait l'histogramme ; elles restent dans une ligne distincte.
- Effort : S
- Vérification : France affiche `15 omission(s)`, Espagne `13` ; total contrôlé à 148.

## M36-07 — Détection des sources orphelines

- Preuve : une source peut être enregistrée dans `country.sources` sans être citée par un point, un claim ou un événement. Le relevé réel donne 1 cas : `SRC-002` en Espagne, 0 ailleurs.
- Solution : `orphan = sources.filter(s => s.id && !cited.has(s.id))` avec `cited` construit depuis claims + `points` + `events[].points`. Le compte est affiché, les identifiants restent des mentions locales.
- Impact : signale une incohérence de provenance (source déclarée mais non mobilisée) sans modifier le dataset.
- Risque : les identifiants `OM-*`/`PROP-*` présents dans `cited` ne sont pas des sources du registre ; ils n'affectent pas le filtre, qui ne teste que les `sources` existantes.
- Effort : M
- Vérification : sur l'Espagne, le panneau indique `sources non citées : 1` ; sur les neuf autres pays, `0`.

## M36-08 — Miroir d'état `data-m36-*` auditable sans console

- Preuve : le registre neutralise silencieusement un greffon défaillant (`registry.js:40-43`) et n'offre pas de journal ; M07 a établi le motif d'un miroir déclaratif (`data-m07-raf-phase`).
- Solution : `mirror()` écrit sur le `host` : `m36-country`, `m36-source-count`, `m36-cited`, `m36-orphan`, `m36-omissions`, `m36-verdict`. Un seul point d'écriture, aucun `console.*`.
- Impact : un test E2E ou un audit peut vérifier l'état de provenance sans instrumenter le module.
- Risque : le `host` peut être recalculé au rendu ; `hostRef` est rafraîchi à chaque appel `register` via `ctx.host.isConnected`.
- Effort : S
- Vérification : `document.getElementById('globe-canvas').dataset.m36SourceCount === '20'` sur la France, `m36Verdict === 'pending'`.

## M36-09 — Suivi du pays courant par callbacks uniques et frais

- Preuve : `globe.js:433-442` construit `ctx` avec `selected` et `countries: DATASET.countries` ; `notifyMondeHover(country, code)` alimente `onHover` avec `{country, code}` (globe.js:455, registry.js:62-64). Les tableaux de callbacks du registre survivent aux re-renders (registry.js:16-19).
- Solution : une garde module `registered` enregistre une seule fois `onHover`, `onLeave` et `onReady`. Les callbacks lisent toujours `latest` (ctx le plus récent) et `hoverCountry`, puis appellent `update()`.
- Impact : le panneau suit le survol et revient au pays sélectionné au `leave`, sans abonnement dupliqué.
- Risque : un callback enregistré lors d'un rendu précédent écrirait dans un nœud détaché ; `ensureDom()` retrouve le panneau par ID et `update()` relit `nodes` à chaque appel.
- Effort : M
- Vérification : après trois rendus du globe, `mondeDiagnostics()` liste une seule entrée `M36` ; survol puis sortie restaurent le libellé du pays sélectionné.

## M36-10 — Lisibilité sans moteur, aria et mouvement réduit

- Preuve : `ctx.onReady` n'est appelé qu'après initialisation WebGL (globe.js:465-467) ; le greffon doit donc être utile avant ce moment. M06-09 a établi le motif d'un état lisible sans moteur.
- Solution : le panneau est construit et `update()` appelé dès le premier `register`, indépendamment de `onReady`. État vide explicite (« Aucun pays actif… »), `role="status"` + `aria-live="polite"` + `aria-atomic="true"` sur la ligne de synthèse, CSS neutralisé en `prefers-reduced-motion`.
- Impact : la provenance reste consultable sans WebGL, sans JS moteur, et reste annoncée aux technologies d'assistance.
- Risque : une annonce à chaque survol pourrait être bavarde ; `aria-atomic` garantit une phrase complète et cohérente à chaque mise à jour.
- Effort : S
- Vérification : avec `window.VECTEMPOREL_GLOBE` absent, le panneau est présent et l'état vide s'affiche ; `node --check src/views/monde/M36.js` → OK.

## Statut d'implémentation

Les 10 chantiers sont implémentés dans `src/views/monde/M36.js`. CSS injecté une seule fois via `ctx.css('monde-m36', …)`, panneau `#monde-m36-provenance` à ID unique avec garde d'existence, un seul jeu de callbacks `onHover`/`onLeave`/`onReady` sous garde module, zéro `<a>`/`href`, zéro lecture de `url`/`doi`, zéro `console.*`, zéro `Math.random`, zéro timer, zéro réseau. `node --check` validé. Import contrôlé : `mondeDiagnostics()` → `{"entries":["M36"],"diagnostics":[]}`.

## Blocages

- Aucun bloquant. M36 n'écrit dans aucun fichier partagé : il ne peut pas corriger les 587 points sans source ni faire signer les audits, qui restent des décisions éditoriales. La lentille se limite à rendre ces états visibles et mesurables.
- Le rendu est volontairement borné à 6 mentions de sources (+ compte du reste) pour préserver la lisibilité du HUD ; la totalité des données reste dans le dataset et accessible via les autres vues.
