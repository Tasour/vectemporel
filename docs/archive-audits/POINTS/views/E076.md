# E076 — Responsive & mobile : safe-area insets (iPhone)

Lentille E076 — domaine H : responsive & mobile. Fichier possede : `src/views/points/E076.js` uniquement. La vue (`src/views/points.js`), la coque, `styles.css` et `index.html` ne sont ni edites ni doubles : `index.html:5` porte deja `viewport-fit=cover`, la lentille s'y appuie en lecture seule. Contrat exploite : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` — aucune dependance vers le store, les filtres ni le detail, donc aucun fichier partage touche. Zero reseau, zero alea, zero ecouteur global, zero timer, zero rAF, zero `console.*`. CSS injecte par `ctx.css('points-e076', ...)`.

## E076-01 — Portee CSS unique et ancrage idempotent sur la vue

- **Preuve** : `E076.js:18-21` declare `CSS_ID = 'points-e076'`, `SCOPE = 'points-e076'`, `NOTE_ID = 'points-e076-note'` et `REDUCED_ATTR`. La garde d'entree (`:153-154`) exige `viewId === 'points'`, un `layout` valide et les fonctions `css`/`el`. `:157` appelle `css(CSS_ID, CSS)` (cssOnce), `:158-159` pose la classe de portee et `layout.dataset.e076 = '1'`. Toutes les regles sont prefixees `.points-e076` (`:30`, `:46`, `:55`, `:66-70`, `:76-94`, `:98`).
- **Solution** : une seule feuille, une seule classe d'ancrage, un seul marqueur de donnees. L'injection passe par `cssOnce` du registre : un second passage sur le meme DOM ne cree pas de second `<style>`. La garde `viewId` empeche toute fuite vers les autres vues.
- **Impact** : la lentille est confinee a la matrice des points ; aucun selecteur nu ne peut atteindre les filtres, la coque ou une autre lentille. Non destructif : aucun noeud existant n'est retire ni reecrit.
- **Effort** : S
- **Vérification** : relecture de `:153-159` ; verifier qu'aucun selecteur de `CSS` ne commence sans `.points-e076` (hors `@media`) ; appeler deux fois l'installateur → un seul `#points-e076` dans `<head>`.

## E076-02 — Chaine de repli progressive des quatre insets

- **Preuve** : `E076.js:27-43` definit, pour chaque cote, trois declarations successives : `0px` (`:31-34`), `constant(safe-area-inset-*)` (`:35-38`, iOS 11.0/11.1) puis `env(safe-area-inset-*, 0px)` (`:39-42`, iOS 11.2+). La regle gagnante est la derniere prise en charge par le moteur. Le commentaire `:28` documente this mapping.
- **Solution** : le repli est purement CSS et progressif : aucun sondeur de version iOS, aucune detection navigateur, aucune valeur codee en dur pour un appareil donne. Les variables `--points-e076-*` servent de source unique aux quatre cotes.
- **Impact** : sur un iPhone a encoche, les variables valent les insets reels ; sur un navigateur older ou desktop, elles valent `0px` et le rendu ne change pas. Aucun contenu n'est masque derriere l'encoche ni l'indicateur d'accueil.
- **Effort** : S
- **Vérification** : relecture de `:31-42` ; dans un navigateur recent, verifier que `getComputedStyle(layout).paddingTop` suit `env(safe-area-inset-top)` ; verifier qu'aucune valeur fixe (ex. `47px`) n'apparait dans le module.

## E076-03 — Inset superieur : kicker et titre hors de l'encoche

- **Preuve** : `E076.js:46-51` applique `padding-top: var(--points-e076-top)` a `.points-e076` (`:47`). Le commentaire `:23-25` etabeut que `.points-layout` n'a aucun `padding` dans `styles.css:347` : l'ajout est donc purement additif. Le kicker et le titre (`points.js:31-32`) heritent de ce decalage.
- **Solution** : la bande superieure de l'encoche / Dynamic Island est reserve par le conteneur lui-meme, sans toucher au titre ni au kicker. Aucune marge negative, aucun `position: fixed` qui pourrait se superposer.
- **Impact** : le texte « Matrice de couverture » et le compteur de points restent lisibles en portrait sur iPhone X et lateraux ; le defilement de la matrice ne remonte pas sous l'encoche.
- **Effort** : S
- **Vérification** : relecture de `:47` ; capture en 390x844 (portrait) et 844x390 (paysage) : le premier texte visible est en dessous de la zone d'encoche ; comparer avec `data-e076-top` expose sur le layout.

## E076-04 — Insets lateraux : paysage, encoche a gauche ou a droite

- **Preuve** : `E076.js:48` et `:50` appliquent `padding-right: var(--points-e076-right)` et `padding-left: var(--points-e076-left)`. La grille reste une fenetre de defilement horizontale (`styles.css:350`, `.points-grid { overflow-x: auto; }`) : l'inset lateral s'applique au conteneur, pas au contenu scrollable.
- **Solution** : les deux cotes laterales sont traitees symetriquement, ce qui couvre les deux orientations paysage (l'encoche peut etre a gauche ou a droite selon l'orientation de l'iPhone).
- **Impact** : en paysage, les cellules de la matrice et les deux regions (matrice/detail) ne passent pas sous la zone courbe de l'ecran ; le defilement horizontal reste intact.
- **Effort** : S
- **Vérification** : relecture de `:48` et `:50` ; faire pivoter en paysage : `data-e076-left` et `data-e076-right` different ; verifier que le debordement horizontal de la grille n'est pas coupe par l'inset.

## E076-05 — Inset inferieur : navigation du detail au-dessus de la barre d'accueil

- **Preuve** : `E076.js:49` applique `padding-bottom: var(--points-e076-bottom)` sur `.points-e076`. Le domaine de detail (`.points-detail`, `points.js:95-122`) contient le kicker, le titre, les sources, la justification et la navigation « Point precedent / Point suivant » : tous sont souleves par le padding du conteneur.
- **Solution** : le meme padding de conteneur qui regle le haut regle le bas ; aucune regle supplementaire ne double l'inset, ce qui evite une marge excessive et preserve le `padding: 24px 20px` de `.points-detail` (`:365` de styles.css).
- **Impact** : les boutons de navigation restent au-dessus de la home indicator et suffisamment eloignes du bord pour etre touchs sans geste ambigu.
- **Effort** : S
- **Vérification** : relecture de `:49` ; en 390x844, verifier que le bas de `.points-nav` est au-dessus de la zone d'indicateur ; comparer avec `data-e076-bottom`.

## E076-06 — Plancher mobile de 12px avec repli sans max()

- **Preuve** : `E076.js:53-73` ouvre `@media (max-width: 620px)`. Pour chaque cote, `:56-63` ecrit d'abord `calc(var(--points-e076-*) + 12px)` (repli pour les moteurs sans `max()`) puis `max(12px, var(--points-e076-*))` (valeur retenue). Le commentaire `:54` explicite le repli.
- **Solution** : sur mobile, un plancher de 12px garantit une respiration minimale meme quand l'inset vaut 0 (tablette, emulateur, navigateur sans encoche) ; le repli `calc()` assure une degradation propre sur les moteurs anciens.
- **Impact** : le contenu ne colle jamais au bord sur petit ecran, tout en restant exactement a l'inset reel sur iPhone (ou l'inset depasse 12px). Sur desktop, aucun plancher ne s'applique : aucun changement visuel.
- **Effort** : M
- **Vérification** : relecture de `:53-64` ; a 620px et moins, verifier `max()` gagne ; forcer un navigateur sans `max()` (ou lire la premiere declaration) : le repli `calc()` donne au moins 12px de marge.

## E076-07 — Couverture viewport detectee et insets mesures, notes lisibles

- **Preuve** : `viewportCover()` (`E076.js:108-112`) lit le meta viewport via `document.querySelector` et teste `viewport-fit=cover` par regex (`:111`), sans jamais ecrire. `measureInsets()` (`:116-150`) cree une sonde 0x0 `aria-hidden` avec les quatre `env()` en padding (`:120-133`), lit `getComputedStyle` (`:135`) et retire la sonde dans un `finally` (`:136`) ; `parseFloat` + `Number.isFinite` (`:137-140`) normalisent les valeurs. Les resultats sont exposes en `data-e076-cover/top/right/bottom/left` (`:165-169`) et dans une note statique (`:187-194`).
- **Solution** : aucun chiffre n'est invente : les px affiches sont mesures sur l'appareil courant. La note adapte son propos selon la couverture : avec `cover`, elle annonce les insets ; sans, elle explique qu'ils valent 0 et comment les activer.
- **Impact** : le comportement est falsifiable par observation directe du HUD DOM (`data-e076-*`) et de la note ; un developpeur voit immediatement si son environnement active ou non les safe areas.
- **Effort** : M
- **Vérification** : relecture de `:108-150` et `:163-169` ; verifier qu'aucun noeud sonde ne subsiste apres le rendu (`document.querySelectorAll('[aria-hidden="true"][style*="env("]')` vide) ; retirer temporairement `viewport-fit=cover` du meta → note de repli et `data-e076-cover="auto"`.

## E076-09 — Mouvement reduit et couleurs forcees

- **Preuve** : `E076.js:75-85` neutralise les transitions par deux voies : l'attribut `data-e076-reduced="1"` pose par JS (`:76-79`, `:173-176`) et la media query `prefers-reduced-motion` (`:80-85`). `E076.js:87-95` ajoute un repli `@media (forced-colors: active)` avec `border: 1px solid CanvasText` et `color: CanvasText` pour les memes controles.
- **Solution** : le couplage JS + CSS couvre les environnements sans `matchMedia` fiable ; le repli `forced-colors` garantit que les controles restent visibles et delimites sans dependre de la seule couleur de fond. Aucune transition propre a E076 n'est introduite ailleurs.
- **Impact** : les utilisateurs sensibles au mouvement ne voient aucune animation ajoutee par la lentille ; en mode contraste eleve, les boutons de filtre et de navigation gardent un contour explicite.
- **Effort** : S

## E076-10 — Idempotence, non-destruction et note unique

- **Preuve** : `E076.js:181-195` ne cree la note que si `layout.querySelector('#' + NOTE_ID)` est absent (`:181`), retire un noeud perime hors du layout (`:182-183`), puis l'insere apres le kicker (`:192-194`). La note est un `<p>` cree par `el()` (`:190`) avec `textContent`, jamais `innerHTML`. L'installation entiere ne pose aucun ecouteur, timer ou rAF (`:152-197`).
- **Solution** : CSS unique (cssOnce), portee unique, note unique, garde anti-doublon compatible avec un second passage sur le meme DOM. La sonde de mesure est retiree dans un `finally` (`E076.js:136`) : aucune trace hors du layout.
- **Impact** : pas de doublon apres navigation aller-retour, pas de fuite d'ecouteurs, pas de mutation des autres lentilles ni de la vue. Les autres vues sont inchangees grace a la garde `viewId`.
- **Effort** : M

## Statut d'implementation

Les dix chantiers E076-01 a E076-10 sont implementes dans `src/views/points/E076.js` uniquement. CSS injecte via `ctx.css('points-e076', ...)`. Aucun fichier partage edite, aucune valeur d'inset codee en dur, aucun ecouteur global, aucun timer ni rAF, aucune donnee inventee.

## Blocages / limites inter-domaines

- `index.html:5` porte deja `viewport-fit=cover`. La lentille se contente de le lire (`E076.js:108-112`) : si un autre domaine retirait ce reglage, les insets vaudraient 0 et la note le dirait, mais E076 ne peut pas le reecrire sans toucher a un fichier partage.
- Les insets reels dependent de l'appareil et du navigateur : `measureInsets()` (`:116-150`) les lit au moment du rendu. Un changement d'orientation apres le rendu ne declenche pas de recalcul, faute d'ecouteur (`resize`) autorise : un nouveau rendu de la vue est necessaire pour rafraichir `data-e076-*` et la note.
- Le padding est applique sur `.points-layout`, qui n'a pas de padding de base dans `styles.css:347`. Si une autre lentille ajoutait un padding sur ce meme conteneur, l'ordre d'injection CSS determinerait le resultat : E076 n'ecrit aucune valeur de padding fixe hors du plancher mobile.
- La note est statique et hors region live : elle n'annonce rien aux technologies d'assistance. C'est un choix de non-intrusion, coherent avec le fait qu'aucune information portee par la seule couleur n'est introduite.
