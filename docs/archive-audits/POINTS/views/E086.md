# E086 — Table de bord qualité & validation

Lentille E086 — domaine I : qualité & validation. Fichier possédé : `src/views/points/E086.js` uniquement. La vue `src/views/points.js`, le registre, la coque et `styles.css` ne sont ni édités ni doublés : E086 ajoute UNE table de bord locale, visible et déclarative, dans `.points-matrix`, et n'aligne aucun fichier partagé. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` (tels que fournis par `points/registry.js:28-44`). Aucune dépendance vers le store, le routeur, `say()` ou une autre lentille. Toutes les mesures affichées sont dérivées du DOM rendu par `points.js` : aucun chiffre historique, aucune donnée inventée. Zéro écouteur, zéro timer, zéro rAF, zéro observateur, zéro réseau, zéro aléa, zéro journalisation, aucune réinterprétation de balisage. CSS injecté par `ctx.css('points-e086', …)`.

## E086-01 — Ancrage unique et visible de la table de bord

- **Preuve** : `E086.js:246-255` construit une `<section role=region aria-labelledby=points-e086-title>` avec un `<h2>` unique (`points-e086-title`) ; `E086.js:89-100` la stylise sans `backdrop`, sans `role=dialog`, sans `aria-modal` et sans piège de focus. `E086.js:325` l'ancre dans `.points-matrix` (et non directement dans `layout`/`stage`/`body`) : le marqueur `_diagnostics.js:72-78` ne la capture donc pas, et la table reste visible hors mode diagnostic. `E086.js:313` passe par `ctx.css(CSS_ID, CSS)` une seule fois.
- **Solution** : une seule région annotée, complémentaire des diagnostics génériques, jamais une modale. Le titre est porté par un `h2` réel, l'identifiant de la région est préfixé `points-e086-`, et l'ancrage dans la matrice préserve la visibilité par défaut.
- **Impact** : la déclaration des dix chantiers est lisible dans la vue sans activer le tiroir « Diagnostics · 100 » ; aucune interaction avec le globe, le routeur ou la coque n'est interceptée.
- **Effort** : S
- **Vérification** : relecture — aucun `role=dialog`, `aria-modal` ni `inert` ; `role=region` et `aria-labelledby` présents ; `#points-e086-board` a pour parent `.points-matrix`, pas `body`/`stage`/`layout` ; un seul `ctx.css`.

## E086-02 — Manifeste figé, source unique des dix lignes

- **Preuve** : `E086.js:32-82` définit `CHANTIERS` par `Object.freeze`, avec exactement dix objets eux-mêmes figés (`E086-01` à `E086-10`, `:34`, `:39`, `:44`, `:49`, `:54`, `:59`, `:64`, `:69`, `:74`, `:79`). `E086.js:221-240` génère le `<tbody>` en parcourant ce manifeste ; aucun balisage de ligne n'est dupliqué ailleurs. `E086.js:208` nomme explicitement la plage « E086-01 à E086-10 » dans la légende masquée.
- **Solution** : le manifeste est l'unique source de vérité : code, objet et critère vérifiable pour chaque chantier. Toute évolution du tableau passe par une seule entrée, ce qui rend la déclaration auditable d'un coup d'œil.
- **Impact** : aucune dérive entre le texte de la table et le rapport ; le compteur `declared` est comparé à `CHANTIERS.length` (`:275`) et non à une constante divergeante.
- **Effort** : S
- **Vérification** : relecture — `Object.freeze` présent, dix objets comptés, aucun `<tr>` littéral ; contrôle DOM : `tbody > tr` = 10, codes dans l'ordre E086-01…E086-10.

## E086-03 — Table sémantique à quatre colonnes

- **Preuve** : `E086.js:207-209` crée une `<caption>` masquée par la classe `points-e086-sr` (définie `E086.js:108-112`) ; `E086.js:211-219` pose quatre `<th scope=col>` (« Chantier », « Objet », « Critère vérifiable », « État ») ; `E086.js:226-228` pose un `<th scope=row>` portant le code du chantier sur chaque ligne. `E086.js:113-125` cadre la table, ses cellules et ses en-têtes sans ressource externe.
- **Solution** : une vraie table, pas une liste de `<div>` : la relation colonne/ligne est portée par `scope`, et la légende est disponible aux technologies d'assistance tout en restant hors du flux visuel.
- **Impact** : la table de bord est parcourue ligne à ligne par lecteur d'écran ; chaque chantier est identifiable par son code, son objet, son critère et son état.
- **Effort** : S
- **Vérification** : relecture — un `caption`, quatre `th[scope=col]`, dix `th[scope=row]` ; la classe `points-e086-sr` est bien définie dans la feuille unique.

## E086-04 — État textuel par chantier, jamais par la seule couleur

- **Preuve** : `E086.js:231-237` crée un `<span class=points-e086-ok>` de texte « ✓ déclaré » et lui attache `aria-label="${code} : déclaré dans cette table de bord locale"`. `E086.js:126` ne fait qu'accentuer ce texte à la couleur dorée ; le mot « déclaré » et le cocher restent portés par le contenu textuel.
- **Solution** : l'état est redondé (glyphe + mot + libellé accessible) plutôt que codé par une couleur de fond ; aucun `aria-pressed` n'est employé, puisqu'il n'y a pas de bascule indépendante.
- **Impact** : l'information survit au daltonisme, au contraste forcé et à la conversion en niveaux de gris ; le libellé vocalisé nomme précisément le chantier concerné.
- **Effort** : S
- **Vérification** : relecture — absence d'`aria-pressed` sur les états ; dix `aria-label` distincts ; « déclaré » lisible même en désactivant la feuille CSS.

## E086-05 — Contrôle d'intégrité des ancres avant toute écriture

- **Preuve** : `E086.js:300-310` relève `.points-matrix`, `.points-grid`, `.points-title`, `.points-detail` et construit l'objet `anchors` ; `E086.js:311` retourne immédiatement si la matrice, le titre ou la grille manque. `E086.js:195-201` compose la ligne « Ancres requises : disposition ✓ · matrice ✓ · titre ✓ · grille ✓ · détail ✓. » depuis cet objet, et `E086.js:264` l'insère dans la table de bord.
- **Solution** : garde-fou en amont : la lentille ne crée ni ne modifie quoi que ce soit si le contrat DOM n'est pas rempli. Le détail est traité comme optionnel et signalé « absent » sans bloquer la déclaration.
- **Impact** : pas de panneau orphelin, pas de référence aria cassée et pas d'écriture partielle sur un rendu inattendu ou transitoire.
- **Effort** : S
- **Vérification** : relecture de la branche `return` en `:311` ; harnais DOM : (a) DOM complet → ligne d'intégrité avec cinq ✓, (b) `.points-grid` absent → aucun `#points-e086-board` créé, (c) `.points-detail` absent → table présente avec « détail absent ».

## E086-06 — Mesures entièrement recomputées depuis la matrice

- **Preuve** : `E086.js:178-191` calcule `eras`, `domains`, `cells`, `filled` et `visible` par `querySelectorAll` sur la grille et le `.view-kicker` du détail ; `E086.js:157-165` fournit `sumCells()` en repli quand le compteur du détail est illisible. `E086.js:274-278` écrit la synthèse « N ères × M domaines · F/C cellules renseignées · V point(s) dans le périmètre. » depuis ces valeurs.
- **Solution** : le domaine est déduit du nombre de cellules d'en-tête moins la colonne « Ère » (`:179-186`), le périmètre est lu sur le kicker du détail avec repli sur la somme des cellules actives. Aucun millésime ni total n'est codé en dur dans le module.
- **Impact** : la table de bord reste vraie quand le jeu de données change ; chaque chiffre est falsifiable par observation directe de la matrice et du détail.
- **Effort** : M
- **Vérification** : relecture — absence de chiffre littéral dans les chaînes de synthèse ; harnais : faire varier ères et filtres → les cinq grandeurs changent sans modifier le code ; cas sans kicker lisible → repli par somme des cellules.

## E086-07 — Résumé live annoncé une seule fois

- **Preuve** : `E086.js:257-262` crée le `<p id=points-e086-summary>` avec `role=status`, `aria-live=polite` et `aria-atomic=true` ; `E086.js:147-150` définit `setText()` qui ne touche au texte que si la valeur diffère. `E086.js:271-278` écrit le résumé APRÈS la construction de la table, une seule fois par rendu, et hors de toute région live de la coque.
- **Solution** : pas de second `say()` (le ctx de cette vue n'en expose pas), pas de région live ajoutée à `document.body`, et garde anti-écriture redondante sur le nœud. Le résumé est placé sous le titre, avant la table.
- **Impact** : une seule annonce par rendu, sans bavardage ; le compteur de chantiers affiché correspond exactement aux lignes réellement générées.
- **Effort** : S
- **Vérification** : relecture — un seul `aria-live` dans le module, un seul appel à `setText` pour le résumé ; harnais : deux rendus successifs sur le même nœud → texte identique non réécrit ; rendu neuf → une seule annonce.

## E086-08 — Traçabilité préfixée, greffage non destructif

- **Preuve** : `E086.js:225` pose `data-points-e086-step="01"…"10"` sur chaque ligne ; `E086.js:250-251` marque la région par `data-points-e086="1"` et `data-points-e086-motion` ; `E086.js:334-335` écrit `data-points-e086-declared` sur le détail et `data-points-e086-board` sur la matrice. `E086.js:282-283` affiche la note explicite : « elle ne remplace ni la validation du projet ni les diagnostics de la vue ».
- **Solution** : tous les signaux sont préfixés `points-e086-` ou `data-points-e086*` : aucune clé générique n'est occupée, aucun nœud existant n'est retiré ni réécrit. Les marqueurs sur la matrice et le détail sont des attributs de données, pas des identifiants portés par des enfants directs de `layout`.
- **Impact** : les autres lentilles peuvent lire l'état E086 sans collision ; la déclaration ne modifie ni le filtre, ni l'ère courante, ni le point sélectionné.
- **Effort** : S
- **Vérification** : relecture — aucun `remove()` visant un nœud non-E086 ; tous les identifiants du module commencent par `points-e086-` ; harnais : l'état du store (filtres, ère, index) est identique avant et après greffage.

## E086-09 — Accessibilité, repli mobile et mouvement réduit

- **Preuve** : `E086.js:131-133` impose un `:focus-visible` à deux pixels sur tout descendant focalisable ; `E086.js:134-137` replie la table en défilement horizontal sous 620 px ; `E086.js:138-140` neutralise les transitions sous `prefers-reduced-motion`. `E086.js:167-174` interroge `ctx.reducedMotion()` puis `matchMedia` avec repli sûr, et `E086.js:251` miroite le résultat dans `data-points-e086-motion`.
- **Solution** : double source de vérité (ctx + media query) avec repli prudent ; la ligne « Accessibilité » (`:265-266`) décrit exactement l'état observé, sans promettre de comportement absent.
- **Impact** : le tableau reste parcourable au clavier et lisible en 390 px de large ; les utilisateurs sensibles au mouvement ne voient aucune transition contradictoire.
- **Effort** : S
- **Vérification** : relecture des deux `try/catch` ; émuler `prefers-reduced-motion: reduce` → `data-points-e086-motion="reduce"` et ligne « mouvement réduit, transition neutralisée » ; capture 390×844 sans débordement horizontal hors de la table.

## E086-10 — Greffage idempotent et silencieux

- **Preuve** : `E086.js:315-321` réutilise le nœud par identifiant et ne retire qu'un nœud E086 mal parenté ; `E086.js:325` le branche dans la matrice avant toute construction ; `E086.js:280-281` affiche le nombre réel de tables présentes dans le document, lu par `count(document, …)`. `E086.js:313` injecte la feuille une seule fois via `cssOnce`, et `E086.js:338` enregistre un unique `register('E086', install)`.
- **Solution** : aucune closure d'état persistante hors du DOM, aucun écouteur attaché, aucun timer, aucune rAF, aucun `MutationObserver` ; `replaceChildren()` reconstruit les enfants du tableau de bord uniquement, jamais le contenu de la vue.
- **Impact** : pas de doublon après navigation, pas de fuite d'écouteurs, pas de boucle d'écriture ; le compteur d'unicité distingue « une seule table » de « greffon muet ».
- **Effort** : M
- **Vérification** : `node --check src/views/points/E086.js` → PASS ; relecture — un seul `register`, un seul `css`, zéro `addEventListener`/`setTimeout`/`requestAnimationFrame`/`MutationObserver` ; harnais : rendu → navigation aller-retour → rendu → un seul `#points-e086-board`, dix lignes, compteur « 1 table de bord E086 ».

## Statut d'implémentation

Les dix chantiers E086-01 à E086-10 sont implémentés dans `src/views/points/E086.js` uniquement. CSS injecté via `ctx.css('points-e086', …)`. Aucun fichier partagé modifié, aucune donnée inventée, aucun chiffre codé en dur, aucun écouteur ni timer. La table de bord est ancrée dans `.points-matrix` pour rester visible hors mode diagnostic.

## Blocages / limites inter-domaines

- La table de bord est **déclarative** : elle énonce les dix chantiers et leurs critères, mais elle ne remplace ni la validation du projet ni le tiroir de diagnostics générique (`src/views/_diagnostics.js`), fichier non possédé.
- L'ancrage dans `.points-matrix` est un choix délibéré : un nœud portant un identifiant `points-e086-*` attaché directement à `layout`, `stage` ou `body` serait marqué `data-points-diagnostic` au rendu suivant et masqué par défaut (`_diagnostics.js:69-78`).
- Le compteur de périmètre est lu sur `.points-detail .view-kicker` tel que produit par `points.js:96` ; si un autre greffon réécrivait ce kicker, E086 en déduirait une valeur différente. Le repli par somme des cellules actives couvre le cas illisible.
- Les marqueurs `data-points-e086-declared` et `data-points-e086-board` sont écrits sur le détail et la matrice ; toute autre lentille réécrivant ces attributs devra préserver ces clés préfixées.
