# E037 — Focus visible renforcé sur tous les contrôles

Lentille E037 — domaine D : navigation & clavier. Fichier possédé : `src/views/points/E037.js` uniquement. La vue `src/views/points.js`, le registre, le store et la coque ne sont ni édités ni doublés. Contrat exploité : `viewId`, `stage`, `layout`, `css(id, rules)`, `el(tag, cls, text)`, `reducedMotion` (tels que fournis par `points/registry.js:28-44`). Tout est dérivé du DOM rendu : aucun libellé, aucun chiffre, aucune ère codés en dur. Complémentarité : E004/E013 posent un contour `:focus-visible` simple, E035 documente les raccourcis clavier ; E037 ajoute un anneau épais et décalé (contour + double `box-shadow`), un repli `@supports`, un repère auditable sur le contrôle réellement focalisé et un panneau local non modal. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. CSS injecté par `ctx.css('points-e037', …)` (E037.js:31, :169).

## E037-01 — Une seule feuille CSS préfixée, sans ressource distante

- **Preuve** : `E037.js:31` déclare `CSS_ID = 'points-e037'`, `:32-36` préfixent la classe et l'ancre de portée (`points-e037-control`, `.points-layout[data-points-e037="1"]`), `:43-79` contient l'unique feuille ; `:169` la passe à `ctx.css(CSS_ID, CSS)`. Aucun `@import`, aucune `url(http…)`, aucun `fetch`.
- **Solution** : la feuille est unique et cadrée sur les ancres `points-e037-` ou sur les contrôles déjà rendus par `points.js`. Le sélecteur de portée exige le marqueur `data-points-e037="1"`, donc la feuille ne s'applique qu'à la vue Points greffée.
- **Impact** : aucune fuite de style hors de la vue, aucune dépendance réseau, aucun risque de collision avec les feuilles E001/E002/E004/E010/E011/E013/E018/E030/E035.
- **Effort** : S
- **Vérification** : relecture — un seul `CSS_ID`, un seul appel `ctx.css`, aucun `@import`/`url(`/`fetch` ; `node --check src/views/points/E037.js` PASS.

## E037-02 — Couverture exhaustive des contrôles, énumérée depuis le DOM

- **Preuve** : `E037.js:182-189` interroge `layout.querySelectorAll('button, select, a[href], [tabindex]:not([tabindex="-1"])')`, ajoute la classe `points-e037-control` à chaque nœud qui ne la porte pas encore et mémorise `controlsTotal` (`:189`). `:198` expose ce nombre dans `data-points-e037-controls`. `:36` définit la portée CSS sur cette même classe.
- **Solution** : la liste des contrôles n'est pas codée en dur : elle est lue sur le rendu courant (boutons d'ère `.points-era`, cellules `.points-cell`, deux `<select>`, bouton de réinitialisation, boutons `.points-nav`, et tout contrôle ajouté par une autre lentille). L'ajout de classe est purement additif et réversible.
- **Impact** : aucun contrôle n'échappe au renforcement, y compris ceux introduits par une lentille voisine ; la lentille reste vraie si la matrice ou les filtres évoluent.
- **Effort** : S
- **Vérification** : relecture — aucun sélecteur de contrôle littéral figé ; harnais DOM : comparer `controlsTotal` au nombre réel de `button`/`select` du layout, puis ajouter un bouton factice et rejouer `install()`.

## E037-03 — Anneau renforcé : contour épais, décalé, double ombre

- **Preuve** : `E037.js:44-49` pose `outline: 3px solid … !important`, `outline-offset: 3px !important` et `box-shadow: 0 0 0 1px #0b0f15, 0 0 0 4px var(--gold, #e6b96f)` sur `${SCOPE}:focus-visible`. Le commentaire `:38-42` justifie le `!important` : faire prévaloir l'anneau renforcé sur les contours de 2 px posés par E004 (`:47-49`) et E013 (`:34`), sans neutraliser leur comportement.
- **Solution** : l'anneau est une forme (contour solide + décalage + contre-cercle sombre + halo), pas une simple teinte. Le `!important` ne touche que l'état `:focus-visible` des contrôles tagués.
- **Impact** : le focus est repérable d'un coup d'œil, même sur une cellule dense de la matrice ou à proximité d'un contour concurrent ; la hiérarchie visuelle est stable d'un rendu à l'autre.
- **Effort** : S
- **Vérification** : relecture des `:44-49` ; Tab sur une cellule puis sur le bouton de réinitialisation : le même anneau de 3 px + halo apparaît sur les deux.

## E037-04 — Repli `@supports` quand `:focus-visible` est absent

- **Preuve** : `E037.js:50-57` encadre une règle `${SCOPE}:focus` identique dans `@supports not selector(:focus-visible)`. `:51` teste la prise en charge de la pseudo-classe, `:52-56` applique le même contour et le même halo.
- **Solution** : aucun JavaScript de détection de modalité n'est nécessaire : le repli est purement CSS et ne s'active que si le moteur ne connaît pas `:focus-visible`. Aucun timer, aucune boucle rAF.
- **Impact** : l'anneau renforcé reste disponible sur les moteurs plus anciens ; le comportement ne dépend d'aucun état JS volatile.
- **Effort** : S
- **Vérification** : relecture du `@supports` ; contrôle que le bloc `:focus` n'existe que dans le repli, jamais à côté de la règle `:focus-visible` (pas de double anneau en navigateur moderne).

## E037-05 — Indice jamais porté par la seule couleur

- **Preuve** : `E037.js:39-40` l'énonce explicitement ; `:45-48` combinent `outline` **solide**, `outline-offset`, `border-radius` et deux `box-shadow`. `:59-62` ajoute un `@media (forced-colors: active)` qui remplace la couleur par `CanvasText` tout en conservant le contour de 3 px.
- **Solution** : la forme (contour continu décalé + halo) suffit à elle seule ; la couleur dorée n'est qu'un renfort. Le mode couleurs forcées est traité sans perdre l'épaisseur ni le décalage.
- **Impact** : utilisateurs daltoniens, forts contrastes et mode couleurs forcées conservent un repère de focus équivalent ; conformité à l'exigence « aucune info portée par la seule couleur ».
- **Effort** : S
- **Vérification** : relecture des `:44-49` et `:58-62` ; émuler `forced-colors: active` puis Tab : le contour reste solide et décalé.

## E037-06 — Marqueur d'audit sur le contrôle réellement focalisé

- **Preuve** : `onFocusIn()` (`E037.js:123-136`) vérifie `target.matches(':focus-visible')` dans un `try/catch` (`:126-128`), pose `target.dataset.pointsE037Focus = 'true'` (`:132`) et incrémente `focusCount` (`:133`) uniquement en cas de focus clavier. `clearMarker()` (`:118-121`) nettoie le marqueur précédent ; `onFocusOut()` (`:138-140`)、`install()` (`:180`) et le commentaire `:116-117` rappellent que ce marqueur est un crochet d'audit, pas une information colorée.
- **Solution** : le repère est posé sur l'élément focalisé réel, dérivé d'un événement `focusin`, jamais deviné. Le `catch` compte prudemment comme clavier si la pseudo-classe est indisponible.
- **Impact** : une autre lentille ou un test peut vérifier l'état de focus par simple lecture de `data-points-e037-focus`, sans dépendre d'un style calculé.
- **Effort** : M
- **Vérification** : relecture des `:118-140` ; harnais : Tab sur une cellule → un seul nœud porte `data-points-e037-focus="true"` ; Tab suivant → l'ancien marqueur a disparu ; clic souris → pas de nouveau marqueur si `:focus-visible` est faux.

## E037-08 — Statut dérivé du DOM et garde anti-bavardage

- **Preuve** : `refreshStatus()` (`E037.js:108-114`) compose `${controlsTotal} contrôle(s) renforcé(s) · focus clavier observés : ${focusCount}.`, compare à `lastSignature` (`:111`) et sort sans écrire si le texte est inchangé (`:111-112`). `:110` est la seule phrase, sans millésime ni total littéral. `:189`, `:133` et `:202` alimentent les deux grandeurs depuis le DOM et les événements.
- **Solution** : signature = texte entier ; écriture unique par changement réel. Le nœud cible est `currentStatus` (`:81`, `:156`), jamais retrouvé par `getElementById` dans un rendu périmé.
- **Impact** : pas d'annonces redondantes lors des focus successifs sur le même contrôle ; le compteur reflète exactement les focus clavier observés.
- **Effort** : S
- **Vérification** : relecture des `:106-114` ; harnais : deux focus sur le même contrôle sans changement de signature → une seule écriture ; ajouter un contrôle → le total augmente sans modifier le code.

## Blocages / limites inter-domaines

- Le `!important` des `:44-46` et `:53-55` ne fait que prioriser l'anneau renforcé sur les contours E004/E013 ; il ne supprime pas ces règles. Une lentille future qui poserait elle aussi un `!important` sur `outline` pourrait reprendre la main : arbitrage à rejouer en relecture.
- `focusCount` est volatile : un rendu neuf de la coque le remet à zéro (`E037.js:178-179`) ; le conserver entre rendus demanderait un état partagé hors du contrat de la lentille.
- En l'absence de prise en charge de `:focus-visible`, le repli `:focus` (`:50-57`) affiche l'anneau aussi après un clic souris : c'est le prix d'un fallback purement CSS, sans détection de modalité JS.
- E037 n'installe aucun écouteur `keydown` : Tab / Maj+Tab / Entrée / Espace et les touches réservées restent la responsabilité du routeur et d'E035 (`points/E035.js`), fichiers non possédés.
