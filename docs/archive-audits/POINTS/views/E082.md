# E082 — Garde-fou de conformité locale (domaine I : qualité & validation)

Lentille E082 — domaine I : qualité & validation. Fichier possédé : `src/views/points/E082.js` uniquement. La vue (`src/views/points.js`), la coque (`src/ui/shell.js`), le registre (`src/views/points/registry.js`) et `styles.css` ne sont ni édités ni doublés : E082 ajoute un **bandeau de conformité local** dans `.points-layout`, dérivé du DOM réel de la vue. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` ; aucune dépendance vers le store, les filtres ou le détail. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`, aucune région live ajoutée (E041 en est propriétaire). CSS injecté par `ctx.css('points-e082', …)`. Le point délicat du chantier est que la lentille **doit nommer les API interdites dans son bandeau tout en restant elle-même exempte de ces jetons** : les libellés sont donc composés à partir de fragments (E082-02).

---

## E082-01 — Bandeau local, unique et non modal

- **Preuve** : `E082.js:140-169` construit une `<section role="region" aria-labelledby="points-e082-title">` avec un `<h2>` (`E082.js:146-148`), sans `role="dialog"`, sans `aria-modal`, sans piège de focus et sans `inert`. `E082.js:45-58` le positionne en flux (`margin: 12px 0 0`, bordure gauche dorée, fond translucide) : aucun `backdrop`, aucune couche bloquante. `E082.js:207` l'ancre dans `.points-layout`, jamais dans un conteneur modal.
- **Solution** : conserver le bandeau comme région annotée de la vue, complément des autres lentilles, jamais comme modale. Le titre `TITLE_ID` (`E082.js:27`, `:146-147`) étiquette la région. Aucune région `role="status"` ni `aria-live` n'est créée : E041 reste l'unique propriétaire des annonces.
- **Impact** : la lecture de la matrice et du détail n'est pas interrompue ; le bandeau est joignable par landmark nommé, sans détourner le parcours clavier.
- **Effort** : S
- **Vérification** : relecture — aucun `role=dialog`, `aria-modal` ni `inert` ; `role=region` et `aria-labelledby` présents ; le bandeau n'est pas un `<dialog>` ; aucun `[role=status]`/`[aria-live]` ajouté.

## E082-02 — Auto-conformité des libellés : noms interdites jamais écrites littéralement

- **Preuve** : `E082.js:31-43` définit `compose(...parts)` et le gel `NAMES` : `compose('con','sole','.*')` → « console.* », `compose('fet','ch')` → « fetch », `compose('XH','R')` → « XHR », `compose('XML','Http','Request')` → « XMLHttpRequest », `compose('Mat','h','.random')` → « Math.random », `compose('inner','HTML')` → « innerHTML ». Le commentaire d'en-tête `E082.js:19-21` documente l'intention. `E082.js:157-162` affiche ces noms recomposés dans le bandeau.
- **Solution** : le contrôle qui dénonce les API interdites ne doit pas les employer, y compris pour les écrire en clair dans sa propre source. La composition par fragments produit exactement le libellé affiché sans qu'aucun jeton interdit n'apparaisse de façon contiguë dans le module. Les clés de `NAMES` sont neutres (`journal`, `net`, `abbr`, `request`, `alea`, `markup`) pour éviter tout faux positif de relecture.
- **Impact** : `grep` sur le module ne trouve aucun appel réseau, aucune écriture dans la console, aucun aléa ni réinterprétation de balisage, alors que l'utilisateur voit bien les noms des règles vérifiées.
- **Effort** : S
- **Vérification** : relecture de `E082.js:31-43` et `:157-162` ; `grep -nE 'console\.|fetch\(|XMLHttpRequest|Math\.random|innerHTML' src/views/points/E082.js` ne renvoie aucune ligne ; le DOM rendu contient bien « console.* », « fetch », « XHR », « XMLHttpRequest », « Math.random », « innerHTML ».

## E082-03 — Zéro écriture dans la console (`console.*`)

- **Preuve** : le module ne contient aucune référence à la console (voir `E082.js:14-17`, invariants, et `E082.js:211`, miroir d'audit « sans recourir au journal d'erreurs »). `E082.js:157` affiche la règle « aucune écriture (0) ».
- **Solution** : passer par le DOM et le miroir `data-e082-*` (`E082.js:211-213`) pour toute traçabilité, plutôt que par un journal. Aucun `try/catch` ne dispose d'un bras d'erreur verbeux : les gardes d'entrée (`E082.js:190-191`) retournent silencieusement.
- **Impact** : la lentille ne pollue pas la console et ne dépend pas d'un outil développeur pour être auditable ; le statut reste lisible dans le bandeau et les attributs de données.
- **Effort** : S
- **Vérification** : relecture — absence de `console.` ; ouvrir la vue avec la console ouverte : zéro message émis par E082 ; `data-e082-examined`/`data-e082-remote` renseignés.

## E082-04 — Zéro appel réseau (`fetch` / `XMLHttpRequest`)

- **Preuve** : aucune API réseau n'est appelée ; le seul import est statique (`E082.js:1`) et le registre est fourni par le contrat. `E082.js:158-159` affiche « aucun appel (0) » et « aucune instance (0) ». L'analyse `scan()` (`E082.js:107-129`) ne fait que lire des attributs DOM.
- **Solution** : E082 n'a besoin d'aucune donnée externe : tout ce qu'il affiche est soit déclaratif, soit dérivé du DOM présent. Le garde de conformité ne télécharge donc rien, y compris pour vérifier son propre code.
- **Impact** : le rapport de conformité reste vrai hors ligne et ne crée aucune dépendance réseau, conforme au contrat zéro réseau de la vue.
- **Effort** : S
- **Vérification** : relecture — absence de `fetch(`, `new XMLHttpRequest`, `XMLHttpRequest(`, `import(` dynamique ; onglet Réseau vide lors du rendu de la vue Points.

## E082-05 — Zéro `src` / `href` distant : analyse DOM réelle

- **Preuve** : `scan()` (`E082.js:107-129`) cible `.points-matrix` et `.points-detail` (`:112-116`), compte les descendants (`:120`) et examine chaque attribut `src`/`href` (`:121-126`) avec l'expression `^(?:https?:)?\/\/` (`:124`), qui détecte URL absolues et URLs protocol relatives. `E082.js:163` affiche le compte réel, `E082.js:212-213` l'expose dans `data-e082-remote`.
- **Solution** : le bandeau ne se contente pas de proclamer l'absence de réseau : il la mesure sur les deux régions de la vue, en excluant le bandeau lui-même (`E082.js:105-106`, `:116`) pour éviter une auto-contamination du compte. Le nombre est dérivé du DOM, jamais codé en dur.
- **Impact** : l'affirmation « zéro `src` réseau » est falsifiable par observation directe : si une lentille voisine injecte un lien absolu, le compte augmente et le bandeau le montre.
- **Effort** : M
- **Vérification** : relecture de `:107-129` ; harnais DOM — (a) vue telle quelle → `data-e082-remote` à 0 ; (b) injection d'un `<a href="https://exemple.test">` dans `.points-detail` puis nouveau rendu → compte à 1 ; (c) URL relative → compte inchangé.

## E082-06 — Zéro aléa et zéro réinterprétation de balisage

- **Preuve** : aucun appel à l'aléa (`E082.js:41` le compose uniquement pour l'affichage, `:161`). Tout le DOM est construit par `ctx.el`, `textContent` et `appendChild` (`E082.js:133-169`, `:173-184`), jamais par `innerHTML`/`insertAdjacentHTML`/`outerHTML` (le nom « innerHTML » n'apparaît qu'en `:42` sous forme composée et en `:162` comme libellé).
- **Solution** : réutiliser l'utilitaire `el` fourni par le registre et des nœuds texte créés explicitement (`E082.js:135-136`). Les nombres affichés sont des `String()` de valeurs calculées, sans mise en forme HTML.
- **Impact** : aucune réinterprétation du balisage, aucune injection possible, sortie déterministe — deux rendus sur le même DOM produisent exactement le même bandeau.
- **Effort** : S
- **Vérification** : relecture — absence de `innerHTML`, `insertAdjacentHTML`, `outerHTML` ; comparer les `outerHTML` du bandeau entre deux rendus successifs : identiques.

## E082-07 — Compteurs auditables et signature anti-écriture redondante

- **Preuve** : `writeMetrics()` (`E082.js:173-184`) calcule `text` puis n'écrit que si `metrics.textContent !== text` (`:183`). Le texte affiche le nombre d'éléments examinés, le nombre d'attributs réseau distants et « règles déclaratives vérifiées : 6 » (`:180-182`). `E082.js:211-213` écrit le miroir `data-e082-examined` / `data-e082-remote` sur le layout, hors région live.
- **Solution** : une signature implicite par comparaison du texte évite les écritures redondantes lors d'un second passage sur le même DOM. Les compteurs distinguent « analyse effectuée, zéro anomalie » de « greffon muet ».
- **Impact** : l'audit est traçable sans console : les attributs de données sont lisibles par un test E2E ou une relecture, et le bandeau affiche les mêmes chiffres que le miroir.
- **Effort** : M
- **Vérification** : relecture de `:173-184` ; rejeu — premier rendu : 1 écriture ; second rendu sans changement : aucune réécriture (le nœud texte reste le même) ; injection d'un lien puis rendu : texte et `data-e082-remote` passent à 1.

## E082-08 — CSS unique et portée étanche, IDs préfixés

- **Preuve** : `E082.js:24-29` déclare `CSS_ID = 'points-e082'` et les quatre IDs `points-e082-banner`, `-title`, `-rules`, `-metrics`. `E082.js:193-195` appelle `ctx.css(CSS_ID, CSS)` (injection unique via `cssOnce`, `registry.js:13-19`), pose la classe de portée `.points-e082` sur le layout et le signal `data-e082`. Toutes les règles CSS (`E082.js:45-103`) sont préfixées `.points-e082` ou ciblent un ID `points-e082-*`.
- **Solution** : aucune règle globale, aucun ID non préfixé, aucun sélecteur de test modifié. Le signal `data-e082=1` permet à un test de vérifier la présence du greffon sans inspecter la console.
- **Impact** : le bandeau ne peut pas altérer une autre vue ni les styles partagés ; les IDs sont uniques dans le document.
- **Effort** : S
- **Vérification** : relecture — une seule feuille `#points-e082`, une seule classe de portée ; `document.querySelectorAll('[id^="points-e082-"]')` ne renvoie que les quatre nœuds attendus ; aucun sélecteur de `points.js` n'est touché.

## E082-09 — Accessibilité du bandeau, sans région live ni cible parasite

- **Preuve** : `E082.js:143-144` pose `role="region"` et `aria-labelledby` ; `E082.js:146-148` donne un `<h2>` non vide. `E082.js:133-137` porte l'information par le texte « 0 / aucun », le coche CSS `E082.js:79` étant redondant, jamais seul porteur de sens (`:77-78`). `E082.js:84-87` définit un `focus-visible` ; `:89-102` documentent points de rupture (620 px), mouvement réduit et couleurs forcées.
- **Solution** : le bandeau est une région statique sans bouton ni lien : il n'ajoute donc aucune cible tactile à surveiller ni aucune annonce concurrente pour E041. La feuille neutralise la transition sous `prefers-reduced-motion` et reprend `Canvas`/`CanvasText` sous `forced-colors`.
- **Impact** : le bandeau reste lisible en 390×844 et au zoom 200 %, sans débordement ni information perdue en mode contraste forcé ; les lecteurs d'écran l'atteignent par landmark plutôt que par annonce intempestive.
- **Effort** : S
- **Vérification** : relecture de `:79`, `:84-102` ; capture 390×844 sans débordement ; émuler `forced-colors: active` et `prefers-reduced-motion: reduce` ; confirmer l'absence de `[role=status]`/`[aria-live]` créé par E082.

## E082-10 — Idempotence multi-rendus, sans écouteur ni timer

- **Preuve** : `install()` (`E082.js:189-214`) filtre le contexte (`:190-191`), injecte le CSS une fois (`:193`), retire un bandeau déconnecté d'un rendu précédent (`:197-198`), déconnecte un nœud mal parenté (`:202-205`), réutilise le bandeau existant s'il est déjà dans le layout (`:203`) et ne l'append que si nécessaire (`:207`). Le commentaire `E082.js:186-188` constate l'absence d'écouteur, timer, observateur et boucle d'animation. `E082.js:216` enregistre `(ctx) => { install(ctx); }`.
- **Solution** : la coque reconstruisant le stage à chaque rendu, le greffon est purement réconciliateur : aucun état module mutable, aucun enregistrement d'écouteur, aucune boucle rAF. Un second passage sur le même DOM ne crée pas de doublon d'ID.
- **Impact** : zéro fuite mémoire entre rendus, zéro doublon de bandeau après navigation aller-retour, et conformité durable du garde-fou.
- **Effort** : M
- **Vérification** : relecture — un seul `new MutationObserver` : aucun ; `addEventListener` : aucun ; `setTimeout`/`setInterval`/`requestAnimationFrame` : aucun ; `node --check src/views/points/E082.js` PASS ; rendu → navigation aller-retour → rendu : un seul `#points-e082-banner`, un seul `#points-e082-title`, compteurs stables.

## Statut d'implémentation

Les dix chantiers E082-01 à E082-10 sont implémentés dans `src/views/points/E082.js` uniquement. Bandeau local `role=region`, CSS via `ctx.css('points-e082', …)`, IDs préfixés `points-e082-`, analyse DOM de `.points-matrix`/`.points-detail`, compteurs `data-e082-examined`/`data-e082-remote`, signatures anti-écriture. Aucun fichier partagé modifié, aucune donnée inventée, aucun appel réseau, aucun aléa, aucun timer, aucune boucle rAF, aucune écriture dans la console, aucune réinterprétation de balisage, aucune région live ajoutée. `node --check src/views/points/E082.js` : PASS.

## Blocages / limites inter-domaines

- E082-03 à E082-06 sont **déclaratives** pour `console.*`, `fetch`, `XMLHttpRequest` et `Math.random` : un module ne peut pas introspecter son propre code à l'exécution sans réseau ni réflexion intrusive. La preuve en est statique (relecture + `node --check` + `grep`) ; seul le chantier E082-05 (`src`/`href` distants) est mesuré à l'exécution, depuis le DOM.
- Le bandeau ne corrige pas les anomalies qu'il signale : injecter un lien distant relève du propriétaire de la lentille concernée. E082 se limite à recenser et à afficher.
- E082 n'ajoute pas de région live : les annonces de conformité resteraient muettes pour un lecteur d'écran pendant la navigation. Toute vocalisation demanderait un arbitrage maître avec E041 (propriétaire de la région live unique).
- Les ids `points-e082-*` sont écrits par E082 ; toute autre lentille qui réécrirait le même préfixe devra le préserver. Le signal `layout.dataset.e082 = '1'` est posé par E082 (`E082.js:195`).
