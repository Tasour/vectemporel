# E055 — « disputé » jamais résolu par un silence

Lentille E055 — domaine F : sémantique & données. Fichier possédé : `src/views/points/E055.js` uniquement. La vue (`src/views/points.js`), le registre, le store et `styles.css` ne sont ni édités ni doublés. Fondement normatif : `POINT_METHODOLOGY.md` §3.6 « Le disputé reste disputé : on ne résout pas une controverse par un silence » et §3.7 « Les silences sont des données ». Le problème est réel dans le jeu de données livré : la même certitude s'écrit `disputé` (31 occurrences) **et** `disputed` (29 occurrences), et un point dont le texte dit « le bilan exact reste disputé » (`dataset.js:2904`) porte la pastille `disputed` alors qu'un point jumeau (`dataset.js:2890`) porte la pastille `vérifié` — le désaccord disparaît alors derrière une certitude apparemment tranquille. E055 n'écrit aucune donnée historique : il lit le détail rendu et rend le désaccord explicite quand il existe. Contrat exploité : `viewId`, `layout` (repli `stage`), `css`, `el`, `reducedMotion` ; le `ctx` de cette vue n'expose pas `say()`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. CSS injecté par `ctx.css('points-e055', …)` ; tous les identifiants sont préfixés `points-e055-`.

## E055-01 — Lexique bilingue du désaccord, normalisé sans aléa

- **Preuve** : `E055.js:34-40` définit `DISPUTED_FORMS = new Set(['dispute', 'disputee', 'disputed'])` et `DISPUTE_WORD = /\bdisput\w*/i`. `norm()` (`:43-49`) passe par la norme NFD et retire les diacritiques, `isDisputedForm()` (`:51-53`) compare le résultat au set, `mentionsDispute()` (`:55-57`) teste le texte libre. Le commentaire `:34-38` documente explicitement le coût d'un oubli de la variante anglaise : 29 disputes silenciées.
- **Solution** : reconnaître `disputé`, `disputée` et `disputed` comme un seul degré de certitude, et traiter la racine `disput` dans le texte ou la justification comme un second signal. La normalisation est déterministe : aucune table approximative, aucune chance, aucune dépendance à la locale du navigateur.
- **Impact** : une variante orthographique présente dans les données ne peut plus faire taire une controverse ; le greffon reste lisible quand le registre de points évolue, sans réécrire le dataset.
- **Effort** : S
- **Vérification** : relecture de `:39-57` ; harnais DOM : `confidence=disputé` puis `confidence=disputed` → deux fois `data-points-e055-state="dispute-explicite"` et un bloc visible.

## E055-02 — Lecture non destructive du détail rendu

- **Preuve** : `readDetail()` (`E055.js:80-98`) lit uniquement `.points-meta .confidence` (repli `.confidence`), `.points-point-title`, `.points-point-text`, `.points-justification`, `.points-sources` et le `.view-kicker` via `first()` (`:75-78`). Il retourne un instantané `{ raw, title, text, why, sources, hasSources, empty, perimeter }`. Le commentaire `:80-81` pose l'invariant : aucun nœud déplacé, retiré ou réécrit.
- **Solution** : observer le DOM de `points.js` plutôt que d'importer `dataset.js` ou le store. Le greffon ne devient pas une deuxième source de vérité : il commente la fiche existante sans la remplacer.
- **Impact** : compatibilité avec toutes les ères et tous les pays ; aucun couplage à la structure interne du store, aucun risque de divergence entre la donnée affichée et la donnée annoncée.
- **Effort** : S
- **Vérification** : relecture de `:75-98` — aucun `remove()`, aucun `textContent =` sur un nœud de la vue ; harnais : le titre, le texte, la justification et la ligne « Sources » d'origine restent intacts après `install()`.

## E055-03 — Désaccord explicite : la pastille dit « disputé »

- **Preuve** : `classify()` (`E055.js:105-124`) teste d'abord `isDisputedForm(info.raw)` (`:107`) ; la branche `:109-115` produit l'état `dispute-explicite` et la phrase « Désaccord non tranché — ce point reste disputé (certitude affichée : « … »). » (`:112`).
- **Solution** : conserver la valeur brute de la pastille dans le message et dans `data-points-e055-raw` (`:292`), sans la traduire ni l'arrondir. Le bloc de controverse porte le même mot que la donnée : le lecteur voit la dispute, pas seulement un code couleur.
- **Impact** : un point `disputed` n'est plus réduit à un pastille floue de 7 px (`styles.css:230`) ; la controverse est énoncée en toutes lettres dans le détail.
- **Effort** : S
- **Vérification** : relecture de `:107-115` ; harnais : `disputé` → état `dispute-explicite`, bloc non masqué, drapeau « ⚖ Désaccord non tranché… », `aria-describedby="points-e055-note"` sur la pastille.

## E055-04 — Désaccord silencieux : le texte dit « disputé », la pastille dit autre chose

- **Preuve** : la seconde branche de `classify()` (`E055.js:116-122`) déclenche l'état `dispute-silencieux` dès que `mentionsDispute(text + ' ' + why)` est vrai alors que la pastille n'est pas disputée. Le message (`:119`) nomme le conflit : « Le dossier mentionne un désaccord alors que la certitude affichée est « vérifié » : le disputé n'est pas résolu par ce silence. » Le commentaire `:100-104` cite le cas réel ; le jumeau `dataset.js:2887-2892` (texte « reste disputé », certitude `vérifié`) en est la preuve dans les données.
- **Solution** : ne pas faire confiance à la seule pastille. Quand le dossier rapporte une controverse, l'afficher même si l'étiquette de certitude semble close — c'est exactement le « silence » que l'article 3.6 interdit.
- **Impact** : une incohérence de vocabulaire dans le dataset devient un avertissement lisible au lieu d'une fausse certitude ; l'utilisateur sait que le chiffre ou la date reste contesté.
- **Effort** : M
- **Vérification** : relecture de `:108`, `:116-122` ; harnais : `confidence=vérifié` + texte « Le bilan exact reste disputé. » → état `dispute-silencieux`, bloc visible, phrasé d'avertissement.

## E055-05 — Bloc de controverse explicite, nommé et relié à la pastille

- **Preuve** : `writeNote()` (`E055.js:167-192`) construit un `<section role=note aria-labelledby=points-e055-title>` (rôle et lien posés en `:268-270`) avec un `<h4>` « Dossier de controverse » (`:176-177`), un drapeau textuel et une icône ⚖ décorative `aria-hidden` (`:190-192`). `linkConfidence()` (`:126-136`) ajoute `points-e055-note` au `aria-describedby` de la pastille **sans écraser** les jetons existants (`:131-135`) et retire seulement le sien à la fermeture.
- **Solution** : une seule région nommée, non modale, insérée avant `.points-nav` (`:286-288`) ; l'information est portée par le texte, l'icône et une bordure gauche (`:216`, `:227-228`), jamais par la couleur seule.
- **Impact** : la controverse est annoncée par les technologies d'assistance dès que le focus atteint la pastille de certitude ; le fil de lecture du détail reste intact puisque la navigation reste le dernier élément.
- **Effort** : M
- **Vérification** : relecture de `:126-136`, `:176-192`, `:268-288` ; harnais : `nextElementSibling` du bloc = `.points-nav`, `aria-describedby` présent en cas de dispute, absent sinon.

## E055-06 — La justification préservée comme dossier du désaccord

- **Preuve** : `writeNote()` (`:194-197`) ne fait que **citer** la justification lue dans le DOM : « Dossier de la controverse : … », avec repli explicite « Aucune justification enregistrée : le désaccord est signalé sans dossier écrit. » Le paragraphe porte `data-points-e055-justification="présente|absente"`. Le commentaire `:163-166` rappelle que le `.points-justification` d'origine n'est pas modifié.
- **Solution** : garder le texte source à sa place et le recontextualiser dans le bloc, avec un marqueur d'absence plutôt qu'un vide. Aucun résumé automatique, aucune invention de motif.
- **Impact** : le lecteur accède au raisonnement qui fonde le doute (ex. `dataset.js:5354` : « la date est disputée (496, 498 ou 499) ») sans perdre la citation d'origine.
- **Effort** : S
- **Vérification** : relecture de `:163-166`, `:194-197` ; harnais : justification fournie → marqueur `présente` et texte cité ; justification vide → marqueur `absente` et phrase de repli.

## E055-07 — Silence de source écrit, jamais laissé vide

- **Preuve** : `points.js` ne crée `.points-sources` que si `sources.length` est non nul. `readDetail()` (`:84`, `:93-94`) détecte cette absence via `hasSources` ; `writeNote()` (`:199-204`) affiche alors « Aucune source enregistrée pour ce point : ce silence ne tranche pas le désaccord. » et masque le paragraphe quand des sources existent. Le commentaire `:199-200` cède explicitement l'attribution d'un ID d'omission à E056.
- **Solution** : rendre le vide visible sans le remplir arbitrairement. E055 constate et énonce ; il ne fabrique ni `SRC-…` ni identifiant d'omission.
- **Impact** : l'article 3.7 est respecté à l'endroit où le risque est maximal — un point disputé sans source n'est plus un blanc muet mais une absence déclarée.
- **Effort** : S
- **Vérification** : relecture de `:93-94`, `:199-204` ; harnais : sans `.points-sources` → phrase affichée ; avec `SRC-001` → `source.hidden === true`, aucune duplication de la ligne d'origine.

## E055-08 — Chiffres dérivés du DOM, avec signature anti-rédondance

- **Preuve** : `perimeterCount()` (`:68-73`) parse le kicker réel « N point(s) dans ce périmètre » ; `silences` compte `.points-cell:not(.has-points)` (`:264`) ; `observed.size` vient du registre local (`:295`). La phrase de synthèse (`:206-207`) assemble les trois grandeurs. `signatureOf()` (`:138-142`) produit une clé déterministe et `lastSignature` (`:145`, `:278-281`) évite toute réécriture identique.
- **Solution** : aucun total codé en dur, aucun millésime inventé ; la mesure est relue à chaque rendu et n'écrase le bloc que si la signature change.
- **Impact** : le récapitulatif est falsifiable à l'écran (périmètre, cellules vides, disputes observées) et ne provoque pas de bavardage DOM sur un rendu inchangé.
- **Effort** : M
- **Vérification** : relecture de `:68-73`, `:206-207`, `:264-281` ; harnais : kicker « 2 point(s)… » + 2 cellules vides → « Périmètre : 2 point(s) · 2 cellule(s) vide(s)… » ; double `install()` → aucune réécriture, un seul bloc.

## E055-09 — Miroirs d'état auditables et registre des désaccords dédupliqués

- **Preuve** : `observed` est un `Set` de module (`:144`) alimenté seulement pour un désaccord et une signature neuve (`:265-266`). - **Impact** : l'agent maître peut vérifier d'un coup d'œil si la lentille a vu un désaccord, quelle certitude brute était affichée et combien de désaccords distincts ont été rencontrés.
- **Effort** : S

## Statut d'implémentation

Les dix chantiers E055-01 à E055-10 sont implémentés dans `src/views/points/E055.js` uniquement. CSS injecté via `ctx.css('points-e055', …)`. Aucune donnée historique inventée, aucun point modifié, aucun fichier partagé touché. Le comportement a été rejoué en harnais DOM (Chromium/Puppeteer) sur quatre cas : `disputé`, `disputed`, `vérifié` + texte « reste disputé », et point sans controverse.

## Blocages / limites inter-domaines

- Le contrat de lentille n'expose ni `dataset` ni `store` : E055 ne voit que le point courant du détail. Il ne peut donc pas dénombrer globalement les 31 `disputé` et 29 `disputed` du dataset ; il les reconnaît quand ils s'affichent. Un décompte global relève d'un outil de build, pas de cette vue.
- La détection du « silencieux » repose sur la racine `disput` dans le texte ou la justification. Une controverse formulée uniquement par « contesté », « débattu » ou « thèse discutée » avec une pastille `certain` échapperait à la règle : le lexique est volontairement strict pour éviter les faux positifs. L'élargissement doit être décidé dans la méthodologie, pas improvisé ici.
- E055 n'attribue aucun ID d'omission (E056) et ne traite pas les cellules vides de la matrice comme un objet sémantique (E057) : il ne fait que les compter comme contexte chiffré.
- `aria-describedby` est complété sur la pastille de certitude. Si une autre lentille réécrivait cet attribut en écrasant les jetons existants, le lien serait perdu ; E055 ne touche qu'au sien.
- La pastille d'origine reste en 7 px et le contraste de ses variantes relève de `styles.css` (fichier partagé, E047). E055 ajoute un bloc lisible à côté, sans corriger ce style.
- Le compteur `observed` vit dans la closure du module : il survit aux re-rendus mais pas à un rechargement complet. Aucun état partagé n'est utilisé, conformément au contrat.
