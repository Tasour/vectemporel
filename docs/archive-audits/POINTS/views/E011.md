# E011 — Filtres & périmètre : filtrage par domaine avec état visible

Lentille E011 — chantier POINTS, domaine B : filtres et périmètre. Fichier possédé : `src/views/points/E011.js` uniquement. Lectures seules (non modifiés) : `src/views/points.js`, `src/domain/store.js`, `src/views/points/registry.js`. La vue construit déjà deux selects de filtre, un bouton de réinitialisation et un kicker de périmètre (`points.js:60-93`, `:96`) : E011 s'y greffe sans rien retirer ni réécrire, en ajoutant une couche locale qui rend l'état du filtre de domaine lisible (bandeau vivant, résumé, colonne signalée, compteurs). Tout est dérivé du DOM rendu : aucun import de store, aucune écriture dans state, aucun appel à set(), selectEra() ni aucune autre fonction partagée. CSS injecté par ctx.css('points-e011', …) ; tous les identifiants sont préfixés points-e011-. Zéro réseau, zéro aléa, zéro minuteur, zéro animation, aucun journal, aucune réinterprétation de balisage.

## E011-01 — Bandeau d'état du domaine actif, exposé comme région vivante

- **Preuve** : `E011.js:25` réserve `STATUS_ID = 'points-e011-status'` ; `:38-43` lui donne un style de badge à bordure dorée ; `:259-263` crée le paragraphe via `ctx.el('p', 'points-e011-status', '')` et pose `role=status` et `aria-live=polite` ; `:135-141` compose son texte (Domaine, Famille, Ère, N point(s) affichés). Le nœud est ajouté à `.points-filters` (`:263`), jamais en remplacement d'un contrôle existant.
- **Solution** : un unique bandeau local, appendu aux filtres, annonce l'état courant du domaine. Le rôle `status` avec `aria-live=polite` rend le changement de filtre audible sans voler le focus ; le texte est construit depuis `readState()` (`:121-133`), donc toujours cohérent avec la sélection réelle.
- **Impact** : l'utilisateur voit et entend quel domaine est actif, sans ouvrir le select ni deviner le périmètre ; l'état du filtrage devient une information explicite plutôt qu'un état implicite du store.
- **Effort** : S
- **Vérification** : relecture — un seul `STATUS_ID`, une seule création de `#points-e011-status` ; contrôle DOM : le paragraphe porte `role=status` et `aria-live=polite` et son texte contient le libellé du domaine sélectionné.

## E011-02 — Compteurs dérivés du DOM, sans valeur codée en dur

- **Preuve** : `countFromKicker()` (`E011.js:110-114`) lit `.points-detail .view-kicker` et en extrait le nombre par la regex `/(\d+)\s+point/i` ; ce kicker est écrit par la vue (`points.js:96`). Le résultat alimente le bandeau (`:139`) et le résumé (`:149`). Aucun millésime ni total littéral n'apparaît dans le module : l'invariant est posé en `:108-109` et `:21`.
- **Solution** : le nombre de points du périmètre est relu depuis le texte réellement rendu ; quand le kicker est absent, la fonction retourne `null` et le bandeau affiche un tiret (`:139`, `:195`) plutôt d inventer un chiffre.
- **Impact** : les affirmations chiffrées d'E011 restent vraies quand le jeu de données évolue ; elles sont falsifiables par lecture directe du kicker de la vue.
- **Effort** : S
- **Vérification** : relecture de la regex ; harnais — kicker « 12 point(s) dans ce périmètre » donne `12` ; kicker vide donne `null` et un tiret dans le bandeau ; aucune chaîne numérique historique dans le fichier.

## E011-03 — Signalisation de la colonne de domaine dans la matrice

- **Preuve** : `markActiveColumn()` (`E011.js:164-182`) ne marque rien si le domaine vaut `*` (`:165`), sinon il repère l'index de l en-tête dont le texte égal le libellé du domaine (`:168-170`), pose `points-e011-active-head` sur cet en-tête (`:172`) et `points-e011-col-active` sur la cellule de même index de chaque ligne (`:175-181`). Le style est défini en `:54-59` ; l'appel se fait depuis `refresh()` (`:198`).
- **Solution** : l'état du filtre devient visible dans la grille elle-même, par une classe et un attribut `data-points-e011-col` posés uniquement sur les nœuds que E011 a marqués. Aucune cellule existante n'est retirée ni réordonnée.
- **Impact** : on voit d'un coup d'œil quelle colonne correspond au filtre actif, sans ouvrir le select ; le surlignage reste lisible au clavier grâce au `outline` de focus (`:60-63`).
- **Effort** : M
- **Vérification** : relecture de `:164-182` ; harnais — domaine `*` donne zéro cellule marquée ; domaine actif donne un en-tête et N cellules marquées, tous avec le même index de colonne.

## E011-04 — Résumé du périmètre inséré dans le panneau de détail

- **Preuve** : `summaryText()` (`E011.js:143-151`) distingue périmètre complet (`:144-146`) et périmètre restreint (`:147-150`) ; le paragraphe `#points-e011-summary` est créé en `:272-273` et inséré juste après le kicker du détail par `insertBefore` (`:275`), avec repli `appendChild` (`:276`).
- **Solution** : un résumé local complète le détail sans écraser le titre, le texte, les métadonnées, les familles, les sources ni la justification déjà produits par `points.js:97-114` ; l insertion est non destructive.
- **Impact** : le périmètre courant est énoncé à côté du point sélectionné, ce qui rend explicite pourquoi tel point est affiché et tel autre masqué.
- **Effort** : S
- **Vérification** : relecture de `:272-276` ; contrôle DOM : le résumé suit le kicker et précède le titre du point ; aucun nœud natif du détail n'a été supprimé.

## E011-05 — Aide associée aux deux selects sans modifier leurs écouteurs

- **Preuve** : `HELP_TEXT` (`E011.js:30-32`) explique que les deux listes filtrent la matrice et le détail et que la réinitialisation restaure le périmètre. `describeSelect()` (`:210-216`) ajoute `HELP_ID` à l'attribut `aria-describedby` existant, en préservant les identifiants déjà présents (`:212-215`) ; il est appelé pour chaque select en `:269-270`. Le paragraphe d'aide est créé en `:255-257`.
- **Solution** : l'information est portée par un attribut ARIA complémentaire, pas par un texte inclus dans le contrôle : les libellés, valeurs et gestionnaires `change` d'origine (`points.js:61-84`) restent intacts.
- **Impact** : les technologies d'assistance entendent la finalité des filtres au moment où le focus entre dans le select ; aucun doublon d identifiant, aucune perte d'une description externe préexistante.
- **Effort** : S
- **Vérification** : relecture de `:210-216` ; harnais — un select ayant déjà `aria-describedby=foo` obtient `foo points-e011-filter-help`, jamais un écrasement.

## E011-06 — Signaux de état sur le layout, observables sans JS

- **Preuve** : `refresh()` écrit `layout.dataset.pointsE011 = isDefault ? 'full' : 'filtered'` (`E011.js:199-201`) ; `install()` écrit `data-points-e011-motion` depuis `ctx.reducedMotion()` (`:278-281`) et `data-points-e011-ready=1` en fin d installation (`:285`).
- **Solution** : trois attributs `data-` exposent l'état du filtre, la préférence de mouvement et la présence du greffon. Ils sont purement additifs et servent de point d observation pour les tests et pour un CSS ultérieur éventuel.
- **Impact** : un contrôle automatisé peut affirmer l'état du périmètre sans lire le texte du bandeau ; le signal `ready` distingue un greffon actif d'un greffon neutralisé.
- **Effort** : S
- **Vérification** : relecture de `:199-201` et `:278-285` ; harnais — filtres par défaut donnent `full`, un domaine choisi donne `filtered`, `prefers-reduced-motion` donne `reduced`.

## E011-07 — Écouteurs locaux, aucun contrôle retiré, aucune touche globale

- **Preuve** : `bindControls()` (`E011.js:220-227`) n'attache que des écouteurs `change` aux deux selects et `click` au bouton de réinitialisation, trouvés dans le DOM existant (`:250-253`). Le garde-fou `node.dataset.pointsE011Bound === '1'` (`:223-225`) empêche la double liaison. Le commentaire `:218-219` documente l'absence d'écouteur documentaire et de touche réservée.
- **Solution** : aucun `document.addEventListener`, aucune interception de touche, aucun `preventDefault` sur les contrôles natifs ; les gestionnaires d'origine de `points.js` continuent de piloter le store.
- **Impact** : la navigation clavier et le routeur ne sont pas perturbés ; E011 se contente de rafraîchir son propre affichage après une action utilisateur.
- **Effort** : S
- **Vérification** : relecture — absence de `document.addEventListener` et de toute gestion de touche ; harnais — changer un select déclenche une seule actualisation E011 en plus du re-rendu normal.

## E011-08 — Compteur d'actualisations auditable et déduplication par signature

- **Preuve** : `refresh()` calcule `signature = JSON.stringify(state)`, sort sans écrire si la signature est inchangée (`:186-187`), sinon incrémente `updateCount` (`:189`) et met à jour `#points-e011-metrics` (`:192-196`). Le compteur est déclaré en `:82`.
- **Solution** : l'affichage n'est réécrit que quand l'état change réellement ; le métrique « E011 · actualisations : N · domaine : … · N point(s) » donne une trace vérifiable du comportement du greffon, hors région live.
- **Impact** : on distingue un greffon muet d'un état inchangé ; les écritures DOM restent bornées même si `refresh()` est appelé souvent.
- **Effort** : S
- **Vérification** : relecture de `:184-202` ; rejeu — deux appels sans changement donnent le même compteur, un changement de domaine l incrémente d'une unité.

## E011-09 — Réversibilité du marquage et résilience au rendu neuf

- **Preuve** : `clearMarks()` (`E011.js:154-160`) retire uniquement les classes et attributs posés par E011 sur les nœuds listés dans `marked`. `install()` détecte un rendu neuf par un nœud déconnecté (`:241-245`), appelle `stripDuplicates()` (`:246`, fonction en `:206-208`) et `clearMarks()` (`:247`) avant de reconstruire proprement.
- **Solution** : chaque installation repart d'un état propre : références périmées abandonnées, doublons éventuels supprimés, marques de la colonne effacées puis repositionnées. L opération est idempotente sur un même rendu comme après une navigation aller-retour.
- **Impact** : pas de gain de balisage, pas de cellules doublement surlignées, pas de fuite de références vers un DOM déconnecté.
- **Effort** : M
- **Vérification** : relecture de `:154-160`, `:206-208`, `:240-248` ; rejeu — rendu, navigation, rendu : un seul `#points-e011-status`, un seul `#points-e011-summary`, marques cohérentes avec le domaine courant.

## Blocages / limites inter-domaines

- E011 lit le périmètre depuis le DOM rendu (libellés des selects, kicker, ligne active). Si la vue change la structure de ces nœuds sans mise à jour de la lentille, les libellés dérivés peuvent devenir vides ; le repli est un tiret, jamais une valeur inventée (`E011.js:129`, `:139`).
- L état appliqué par E011 est volatile : un rendu neuf de la coque reconstruit le layout et remet à zéro les références et la signature (`E011.js:240-248`). Le conserver entre rendus demanderait un état partagé hors du contrat de la lentille.
- Le signal `data-points-e011` (`:199-201`) et les marques de colonne (`:164-182`) sont écrits dans le DOM : toute autre lentille qui réécrirait ces attributs ou classes devra les préserver.
- Limite falsifiable : si, après un changement de domaine, le bandeau n'affiche pas le nouveau libellé, ou si aucune colonne n'est marquée alors qu'un domaine est actif, le chantier E011-01 ou E011-03 est réfuté par l observation directe — aucun mécanisme de la lentille ne peut masquer ce résultat.
