# E090 — I. Qualité & validation : français partout

Lentille E090 — domaine I : qualité & validation. Thème : contrôle de francisation intégrale des libellés injectés (aucune chaîne anglaise, pluriels français).

Fichier possédé : `src/views/points/E090.js` uniquement. La vue (`src/views/points.js`), la coque et `styles.css` ne sont ni édités ni doublés : E090 ajoute un relevé LOCAL et non modal, dérivé des libellés déjà produits dans la vue, et signale les anglicismes et les pluriels non conformes. Il ne corrige aucun libellé. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` ; aucune dépendance vers le store, les filtres ou le détail. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. CSS injecté par `ctx.css('points-e090', …)`. Tout texte injecté par la lentille est en français et ses compteurs sont accordés selon les règles du pluriel français.

## E090-01 — CSS unique et portée ancrée sur la vue

- **Preuve** : `E090.js:25-29` définit un seul identifiant de feuille (`CSS_ID = 'points-e090'`), une classe de portée (`SCOPE = 'points-e090'`), un identifiant de panneau (`points-e090-panel`), un identifiant de titre (`points-e090-title`) et un attribut de mouvement (`data-points-e090-reduced`), tous préfixés `points-e090-`. La feuille `E090.js:34-73` ne contient que des sélecteurs préfixés `.points-e090`. `E090.js:368` passe exclusivement par `ctx.css(CSS_ID, CSS)` (qui est `cssOnce` dans `registry.js:13-19`) puis pose la classe et le marqueur sur `.points-layout` (`:369-370`). `register('E090', …)` est l'unique point d'entrée (`:405`).
- **Solution** : une seule feuille, injectée une seule fois, dont toutes les règles sont cadrées par la classe posée sur le conteneur `.points-layout` : aucune règle ne peut fuir hors de la vue Points. Le greffon est idempotent par construction (`cssOnce` + `classList.add`).
- **Impact** : aucune collision de style avec les 99 autres lentilles ni avec la coque ; un second passage sur le même DOM ne crée ni seconde feuille ni doublon de classe.
- **Effort** : S
- **Vérification** : relecture — un seul `ctx.css`, une seule `<style id=points-e090>`, tous sélecteurs préfixés ; navigation aller-retour : un seul `<style id=points-e090>` dans `<head>`.

## E090-02 — Périmètre de lecture : quatorze sélecteurs, huit familles de libellés

- **Preuve** : `ZONES` (`E090.js:75-93`) énumère quatorze sélecteurs couvrant le contrat DOM de la vue : titre (`.points-title`, `:79`), en-tête de grille (`.points-grid-row.is-head > span`, `:80`), ères (`.points-era`, `:81`), cellules avec infobulle et libellé accessible (`.points-cell`, `:82`), filtres — deux `<select>` et la réinitialisation — (`.points-filters label/option/button`, `:83-85`), les six champs du détail (`.points-point-title/-text/-meta/-families/-sources/-justification`, `:86-91`) et la navigation (`.points-nav button`, `:92`). Chaque zone porte un nom français (`:76`), seul affiché dans le relevé. `relever()` (`:215-239`) lit `textContent` (`:223`) et, pour trois zones seulement, `getAttribute` (`:226`) : aucun mutateur n'est appelé sur ces nœuds.
- **Solution** : la lecture est circonscrite aux emplacements où la vue et les lentilles voisines injectent réellement des libellés. Les attributs lus sont traduits en français dans le relevé : `title` devient « Infobulle », `aria-label` devient « Libellé accessible » (`:228`). Le relevé lui-même, frère de `.points-grid` dans `.points-matrix` (`:386-393`), est hors périmètre.
- **Impact** : le contrôle porte sur les chaînes réellement visibles ou annoncées, sans balayage excessif ni lecture du texte généré par le panneau ; aucun libellé existant n'est altéré.
- **Effort** : M
- **Vérification** : relecture de `:75-93` et `:215-239` — absence de `textContent =`, de `setAttribute` et de `appendChild` hors du panneau ; harnais DOM : injecter « filter » dans un `aria-label` de cellule puis dans un bouton de navigation → deux constats, aucun attribut modifié.

## E090-03 — Détection des anglicismes avec remplacement français

- **Preuve** : `ANGLICISMES` (`E090.js:95-128`) associe chaque jeton anglais à un remplacement français : `filter → filtre`, `reset → réinitialiser`, `next → suivant`, `previous → précédent`, `detail → détail`, `loading → chargement`, `error → erreur`, `ready → prêt`, `title → titre`, `grid → grille` (`:100-127`). Le commentaire `:95-98` énonce : « ces MOTIFS DE REPÉRAGE […] ne sont JAMAIS injectés dans le DOM ». `frontiere()` (`:184-187`) exige des frontières de mot Unicode ; `contourne()` (`:189-192`) isole la construction de l'expression régulière dans un `try/catch` ; `analyser()` (`:195-202`) n'ajoute que le remplacement au constat.
- **Solution** : le lexique sert uniquement à reconnaître une chaîne suspecte. Le relevé n'affiche jamais le jeton anglais détecté, seulement le nom français de la zone et le terme français proposé (`:256-268`) : la lentille qui exige le français s'applique aussi à son propre texte.
- **Impact** : aucun anglicisme n'est propagé par le message d'alerte lui-même ; les faux positifs par sous-chaîne sont évités (« filter » ne se confond pas avec « filters », ni « add » avec « adresse »).
- **Effort** : M
- **Vérification** : relecture de `:95-128` et `:184-202` ; harnais : « Filtres » (français) → zéro constat ; « Reset filters » → deux constats dont les remplacements sont « réinitialiser » et « filtres » ; le texte du panneau ne contient aucun jeton de la table.

## E090-04 — Pluriels français : table dédiée et rejet du « ’s » anglais

- **Preuve** : `PLURIELS` (`E090.js:130-139`) associe quinze noms du vocabulaire de la vue à leur pluriel français : `ère → ères`, `domaine → domaines`, `famille → familles`, `source → sources`, `point → points`, `filtre → filtres`, `certitude → certitudes`, `échelle → échelles`, `matrice → matrices`, `grille → grilles`, `cellule → cellules`, `ligne → lignes`, `colonne → colonnes`, `légende → légendes`, `détail → détails`. `DECLENCHEURS` (`:141`) regroupe déterminants et nombres (« les », « des », « plusieurs », `\\d+`, …). `analyser()` (`:203-209`) signale un singulier non accordé après déclencheur, sauf si le pluriel est déjà présent ; `:210-212` rejette la forme possessive anglaise `lettre + 's`.
- **Solution** : la règle est falsifiable : « 2 domaine » produit un constat proposant « domaines », tandis que « 2 domaines » n'en produit aucun. Les noms déjà terminés par `s`, `x` ou `z` sont exclus de la table (`:130-132`) pour éviter les pluriels redoublés.
- **Impact** : le contrôle couvre explicitement la deuxième exigence du thème — les pluriels français — sans imposer une règle unique à des mots irréguliers.
- **Effort** : M
- **Vérification** : relecture de `:130-141` et `:203-212` ; harnais : « 2 domaine » → constat « employer « domaines » » ; « les ères » → zéro constat ; « point's » → constat « employer « pluriel français » ».

## E090-05 — Français intégral : autocontrôle réflexif du relevé

- **Preuve** : le titre (`:324`), la note (`:327-328`), le bilan (`:247-254`), la liste des constats (`:256-268`) et la ligne de contrôle (`:286-290`) sont rédigés en français. `autocontrôle()` (`:277-284`) soumet `texte(panel)` au même `analyser()` que les libellés observés ; `ecrireEtat()` (`:292-306`) inclut le résultat dans la signature (`:295`), si bien qu'une dérive linguistique du relevé déclenche sa propre réécriture. Le message est « Autocontrôle : aucune chaîne anglaise dans ce relevé. » (`:288`).
- **Solution** : un seul détecteur sert aux libellés cibles et au texte produit par la lentille : l'exigence de francisation n'est pas seulement déclarée, elle est appliquée à la sortie du module.
- **Impact** : le remède ne peut pas introduire le défaut qu'il dénonce ; le constat d'autocontrôle est visible et vérifiable par l'utilisateur.
- **Effort** : S
- **Vérification** : relecture de `:277-290` ; harnais : lire `texte(panel)` après installation → aucune chaîne de `ANGLICISMES` n'y figure ; la ligne d'autocontrôle annonce zéro point à revoir.

## E090-06 — Signature anti-écriture et compteurs auditables

- **Preuve** : `relever()` accumule une empreinte faite des couples « emplacement = valeur » (`:219`, `:233`, `:238`). `setTexte()` (`:241-245`) ne mute un nœud que si son `textContent` diffère. `ecrireEtat()` (`:292-306`) compare la signature calculée à `lastSignature` (`:296`) : si elle est identique, il incrémente seulement `evitees` et sort (`:297-299`) ; sinon il mémorise la signature, incrémente `ecritures` et ne réécrit que le bilan, la liste et la ligne de contrôle (`:300-305`). Les trois compteurs sont déclarés à `:151-153` ; `analyses` est incrémenté à `:293`.
- **Solution** : la signature est une fonction pure des libellés lus et du résultat de l'autocontrôle. Une mutation du DOM observé ne déclenche une réécriture que si le contenu réellement affiché doit changer. Le bilan est un `<p>` ordinaire (`:329`) : aucun `role="status"`, aucun `aria-live`, aucune annonce parasite.
- **Impact** : nombre borné d'écritures DOM ; on distingue « aucune écriture nécessaire » de « greffon muet », sans bavardage à l'attention des technologies d'assistance.
- **Effort** : M
- **Vérification** : relecture de `:241-306` ; rejeu : installation (1 écriture), mutation sans changement de libellé (`evitees` +1, aucun `textContent` modifié), ajout d'un libellé anglais (`ecritures` +1, bilan mis à jour).

## E090-07 — Observateur unique, ciblé, jamais sur le relevé

- **Preuve** : `observerCibles()` (`:336-357`) déconnecte l'observateur existant avant d'en créer un seul (`:339-344`), puis observe exactement cinq cibles en lecture seule — `.points-title`, `.points-grid`, `.points-filters`, `.points-detail`, `.points-nav` (`:345-351`) — avec `{childList, characterData, subtree, attributes}` filtrés sur `class`/`value`/`aria-current`/`title`/`aria-label` (`:352-355`). Le commentaire `:336-337` précise : « JAMAIS sur le relevé (sinon boucle d'écriture) ». Le panneau, frère de ces cibles dans `.points-matrix`, n'est donc jamais observé.
- **Solution** : un seul `MutationObserver` par rendu, déconnecté puis reconnecté ; son callback appelle `rafraichir(currentCtx)` (`:344`) sans écrire directement dans les cibles observées.
- **Impact** : aucune boucle d'écriture, pas de fuite d'écouteurs entre rendus ; l'anti-redondance de E090-06 reste effective face aux mutations des lentilles voisines.
- **Effort** : M
- **Vérification** : relecture — un seul `new MutationObserver`, un `disconnect()` préalable, aucune observation du panneau ni de `.points-matrix` ; harnais : muter une cellule puis le panneau, seul le premier cas déclenche `rafraichir()`.

## E090-08 — Installation idempotente, rendu neuf et résilience au `ctx` minimal

- **Preuve** : `install()` (`:361-403`) refuse un `ctx` sans `viewId === 'points'`, sans `css` ou sans `el` (`:362-363`) et sans racine connectée (`:364-365`). `root()` (`:155-162`) retombe sur `ctx.stage.querySelector('.points-layout')` si `ctx.layout` manque. Un rendu neuf est détecté par nœud déconnecté ou changement de conteneur (`:377-378`) ; un panneau orphelin est retiré (`:380-381`), un seul panneau est réutilisé ou recréé (`:383-394`), et la signature est remise à zéro (`:401`). La garde `courant.querySelector('#' + PANEL_ID)` rend l'installation idempotente sur un second passage.
- **Solution** : une logique unique d'installation, tolérante au `ctx` partiel, qui ne laisse jamais deux panneaux ni un nœud périmé. Le mouvement réduit est lu depuis `ctx.reducedMotion()` dans un simple test de type (`:371-375`), sans dépendance au store ni aux filtres.
- **Impact** : pas de doublon après navigation aller-retour, pas de référence à un nœud détruit, comportement stable même si une autre lentille réinvoque l'installation.
- **Effort** : M
- **Vérification** : relecture des branches `:361-403` ; harnais DOM : (a) `layout` seul, (b) `stage` seul, (c) `ctx` sans racine → trois cas sans erreur ; rendu → navigation → rendu, puis double appel direct : un seul `#points-e090-panel`, signature remise à zéro.

## E090-09 — Accessibilité : région annotée, focus et préférences système

- **Preuve** : `construire()` écrit `role="region"` et `aria-labelledby="points-e090-title"` (`:320-321`) et rend la région focalisable par `tabIndex = -1` (`:322`). La feuille prévoit `:focus-visible` (`:41-43`), une neutralisation des transitions sous `prefers-reduced-motion` (`:64-66`) couplée à l'attribut `data-points-e090-reduced` posé depuis `ctx.reducedMotion()` (`:371-375`), et un repli `forced-colors` (`:67-72`). Le bilan, la liste et la ligne de contrôle portent des compteurs accordés en français (`:179-182`, `:247-254`) : aucune information n'est confiée à la seule couleur.
- **Solution** : une région correctement étiquetée, lisible au clavier, sans animation propre, dont l'information survit aux couleurs forcées. Aucune commande tactile n'est ajoutée : le relevé est purement informatif, il n'y a donc pas de cible à dimensionner.
- **Impact** : le relevé ne contredit pas la préférence de mouvement système ; les utilisateurs sensibles au mouvement et ceux en contraste élevé obtiennent la même information.
- **Effort** : S
- **Vérification** : relecture — `role=region` et `aria-labelledby` présents, aucun `aria-live` ajouté ; émuler `prefers-reduced-motion: reduce` et `forced-colors: active` : mise en page lisible, aucune animation.

## E090-10 — Non destructif, responsive et vérification d'absence d'effets de bord

- **Preuve** : la feuille prévoit un point de rupture à 620 px (`:61-63`) qui réduit police et padding du relevé ; la portée reste `.points-e090`, donc aucun débordement hors du conteneur. Le module ne modifie aucun nœud existant : il ajoute une classe, deux attributs de données et un panneau frère de la matrice (`:386-393`), et retire uniquement son propre nœud orphelin (`:380-381`). `node --check src/views/points/E090.js` passe. Aucun `fetch`/XHR, `Math.random`, `console.*`, timer ou rAF n'apparaît : les deux seules occurrences de « innerHTML » sont dans des commentaires d'interdiction (`:22`, `:316`).
- **Solution** : une lentille de validation non destructive, responsive et vérifiable, qui ne touche ni aux filtres, ni au détail, ni à la navigation de la vue. Les jetons anglais du lexique de repérage sont des données internes et ne sont jamais écrits dans le DOM.
- **Impact** : le relevé reste lisible en 390×844 ; aucune régression fonctionnelle de la matrice et aucun effet réseau ou temporel.
- **Effort** : S
- **Vérification** : relecture + `node --check` ; capture 390×844 sans débordement ; `grep` des interdits conforme.

## Statut d'implémentation

Les dix chantiers E090-01 à E090-10 sont implémentés dans `src/views/points/E090.js` uniquement. CSS injecté via `ctx.css('points-e090', …)`. Aucune vue, aucune coque, aucune feuille partagée touchée ; aucun libellé existant corrigé, aucun fichier partagé modifié.

## Blocages / limites inter-domaines

- Le relevé signale les anglicismes et les pluriels non conformes, il ne les corrige pas : la correction relève des lentilles propriétaires de chaque libellé, hors du contrat de E090.
- Le lexique de repérage couvre les anglicismes courants du domaine, pas l'ensemble de la langue anglaise ; un terme technique non listé peut échapper au contrôle. L'enrichir est une évolution locale, sans effet sur les autres lentilles.
- La table des pluriels est volontairement limitée aux quinze noms du vocabulaire de la vue ; les pluriels irréguliers ou les noms terminés par `s`, `x`, `z` sont exclus pour éviter les faux positifs.
- L'observateur cible cinq nœuds en lecture seule et jamais le panneau (E090-07) ; toute lentille qui réécrirait ces mêmes nœuds déclenchera un `rafraichir`, mais la signature anti-redondance (E090-06) absorbe les écritures inutiles.
- Le relevé est volatile : un rendu neuf de la vue remet la signature à zéro (E090-08). Les compteurs restent cumulatifs ; les conserver par vue demanderait un état partagé hors du contrat de la lentille.
