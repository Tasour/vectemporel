# E063 — Performance & rendu : MutationObserver ciblé, jamais sur la zone écrite

Lentille E063 — domaine G : performance & rendu.
Fichier possédé : `src/views/points/E063.js` uniquement. La vue (`src/views/points.js`), la coque, `styles.css` et tout fichier partagé ne sont ni édités ni doublés : E063 ajoute un relevé LOCAL et non modal dans `.points-matrix`, dérivé du DOM déjà produit par la vue. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` (tels que fournis par `points/registry.js`). Aucune dépendance vers le store, le routeur, les filtres ou une autre lentille — le relevé reste lisible avec un `ctx` minimal. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. CSS injecté par `ctx.css('points-e063', …)`.

Thèse : la vue Points est reconstruite à chaque changement d'état (`points.js:renderPoints`) ; un greffon qui observerait sa propre zone de sortie entrerait dans une boucle d'écriture. E063 démontre l'inverse : un **seul** `MutationObserver`, déconnecté puis reconnecté à chaque rendu, braqué sur trois signaux **en lecture seule** — la grille, les filtres et le titre du point — et **jamais sur le relevé que la lentille écrit**. Les compteurs affichés (signaux reçus, relevés écrits, écritures évitées, dernier signal) sont dérivés des mutations réellement observées et d'une signature calculée depuis le DOM ; aucune donnée historique n'est inventée. Le module reste distinct de E066 (signature anti-écriture) : E063 porte sur le **périmètre d'observation** et la non-récursivité, pas sur la seule déduplication.

## E063-01 — Un seul observateur, déconnecté puis reconnecté

- **Preuve** : `E063.js:78` déclare `let observer = null` (une seule variable module). `E063.js:189-191` commence `observe()` par `if (observer && typeof observer.disconnect === 'function') observer.disconnect(); observer = null;` avant toute création. `E063.js:205` construit l'unique `new MutationObserver(…)`. `E063.js:266` appelle `observe(ctx)` une fois par `install()`.
- **Solution** : une seule instance par rendu, toujours déconnectée avant d'être remplacée. Aucun `document.addEventListener`, aucun écouteur global, aucun timer, aucune boucle d'animation : le callback est exclusivement piloté par le microtask du `MutationObserver`.
- **Impact** : pas d'accumulation d'observateurs après navigation aller-retour, pas de fuite, pas de double comptage d'un même signal.
- **Effort** : S
- **Vérification** : relecture — une seule occurrence de `new MutationObserver`, un `disconnect()` préalable, aucun `addEventListener` documentaire, aucun `setTimeout`/`requestAnimationFrame` ; rendu → navigation → rendu : un seul observateur actif.

## E063-02 — Trois cibles en lecture seule

- **Preuve** : `E063.js:196-204` résout précisément `.points-grid`, `.points-filters` et `.points-detail .points-point-title` et les enregistre dans `observed = [{node, label}…]`. `E063.js:214-220` n'observe que ces trois nœuds, chacun avec ses options propres.
- **Solution** : le périmètre est volontairement étroit et nommé (`grille`, `filtres`, `titre du point`). `classify()` (`E063.js:104-112`) ne peut étiqueter un signal qu'en le rapprochant de l'une de ces trois références ; toute cible inconnue retombe sur `''` puis sur `autre` (`E063.js:211`).
- **Impact** : le relevé ne réagit qu'aux signaux de la vue qui le concernent ; il ne surveille ni la coque, ni les autres lentilles, ni le document entier.
- **Effort** : S
- **Vérification** : relecture des trois sélecteurs ; harnais DOM : modifier une classe de ligne, changer un `<select>`, remplacer le texte du titre → trois libellés distincts ; toucher le corps du document → aucun signal.

## E063-03 — La zone écrite n'est jamais observée

- **Preuve** : le commentaire d'invariant `E063.js:16-22` l'énonce explicitement ; `E063.js:33-36` et `E063.js:185-188` le rappellent : « le relevé n'est VOLONTAIREMENT pas observé : écrire dedans ne peut donc pas relancer le callback ». Les trois cibles (`E063.js:196-204`) sont toutes **hors** du panneau `#points-e063-panel` (`E063.js:27`), lequel est inséré dans `.points-matrix` (`E063.js:253-261`).
- **Solution** : le panneau est un frère de `.points-grid` / `.points-filters` dans la matrice, jamais un descendant d'une zone observée. Le titre du point seul est observé (`E063.js:220`), pas tout `.points-detail` : écrire dans le relevé ne peut remonter jusqu'à une cible.
- **Impact** : impossibilité structurelle de boucle d'écriture — la mutation produite par E063 n'est pas visible par E063. `classify()` (`E063.js:104-112`) ne connaît aucun libellé pour le relevé, ce qui rend l'exclusion vérifiable par relecture.
- **Effort** : S
- **Vérification** : relecture — `#points-e063-panel` absent de la liste `observed` ; le panneau n'est descendant ni de `.points-grid`, ni de `.points-filters`, ni du nœud titre ; observer le callback pendant 100 écritures du relevé → aucun signal supplémentaire.

## E063-04 — Budget d'attributs borné par `attributeFilter`

- **Preuve** : `E063.js:214-217` observe la grille avec `attributes: true` **uniquement** accompagné de `attributeFilter: ['class']`. Les deux autres observations (`E063.js:219-220`) n'activent pas `attributes` du tout : `childList`/`subtree` pour les filtres, `childList`/`characterData`/`subtree` pour le titre.
- **Solution** : aucun `attributes: true` sans filtre, aucun attribut `id`, `style`, `title` ou `data-*` surveillé. Seul le changement de classe de la grille (bascule `is-active` de l'ère) est utile ; le reste est ignoré.
- **Impact** : volume de mutations traitées minimisé ; le callback ne se réveille pas sur des écritures d'attributs sans rapport avec le rendu suivi.
- **Effort** : S
- **Vérification** : relecture — présence de `attributeFilter` à chaque `attributes: true` ; aucun `attributeOldValue`, aucun `attributes: true` nu ; faire varier un `title` de cellule → aucun signal, changer une classe → un signal `grille`.

## E063-05 — Compteurs dérivés des mutations réelles

- **Preuve** : `E063.js:81-84` initialise `signals`, `writes`, `avoided`, `lastSource`. `E063.js:146-152` incrémente `signals` et mémorise `lastSource` à chaque callback ; `E063.js:205-212` extrait la source de `records[i].target` via `classify()`. `E063.js:139-142` écrit « Signaux reçus : N · relevés écrits : N · évités : N. » et « Dernier signal : … · observé : … — jamais ce relevé. »
- **Solution** : toute première affichée vient d'un `MutationRecord` réel ou d'un calcul sur le DOM (`E063.js:117-129`) ; aucun millésime, aucun total ni nom de domaine codé en dur. Les compteurs sont hors région live (`E063.js:167-183`, pas de `role=status`/`aria-live`).
- **Impact** : le relevé est falsifiable — on peut déclencher un signal et vérifier que le compteur augmente d'une unité, puis vérifier qu'il reste stable sans mutation.
- **Effort** : S
- **Vérification** : relecture — absence de nombre historique littéral ; harnais : une mutation → `signals +1` ; deux mutations sans changement de signature → `avoided +2`, `writes` stable.

## E063-06 — Signature anti-redondance, sans `innerHTML`

- **Preuve** : `computeSignature()` (`E063.js:117-129`) assemble ère active, titre du point, kicker de périmètre et valeurs des deux `<select>` depuis le DOM. `refresh()` (`E063.js:153-161`) sort sans écrire quand `signature === lastSignature` et incrémente seulement `avoided`. `setText()` (`E063.js:133-137`) refuse toute écriture si le texte est déjà identique. `buildPanel()` (`E063.js:167-183`) construit tout par `ctx.el` + `textContent`.
- **Solution** : le DOM statique du relevé est bâti une seule fois ; seules deux lignes de texte sont remplacées, et uniquement quand leur contenu diffère. Aucune réinterprétation de balisage.
- **Impact** : nombre borné d'écritures même sous observation active ; aucune injection de balisage, aucun `_blank` implicite, compatibilité avec un CSP strict.
- **Effort** : M
- **Vérification** : relecture — absence de `innerHTML`, `outerHTML`, `insertAdjacentHTML` ; harnais : signature inchangée → aucun `textContent` modifié ; changement de filtre → une écriture.

## E063-07 — Détection de rendu neuf et remise à zéro

- **Preuve** : `E063.js:242` calcule `fresh = !layout || !layout.isConnected || layout !== current` ; `E063.js:245-246` retire un relevé orphelin via `document.getElementById(PANEL_ID)` ; `E063.js:268-274` remet `signals`, `writes`, `avoided`, `lastSource` et `lastSignature` à zéro sur rendu neuf.
- **Solution** : un nœud déconnecté signale une reconstruction de la vue (`points.js:renderPoints` recrée `.points-layout`). L'état volatile du relevé est réinitialisé, sans toucher aux compteurs d'un rendu encore vivant (second passage sur le même DOM).
- **Impact** : pas de compteur hérité d'une vue précédente, pas de signature périmée qui masquerait une écriture légitime au rendu suivant.
- **Effort** : S
- **Vérification** : relecture des deux branches ; harnais : rendu → changer un filtre (compteurs > 0) → nouveau rendu → compteurs à zéro, un seul relevé présent.

## E063-08 — Installation idempotente, un seul CSS et un seul panneau

- **Preuve** : `E063.js:233` appelle `ctx.css(CSS_ID, CSS)` (cssOnce) ; `E063.js:234-235` pose une portée unique et `data-e063`. `E063.js:248-262` réutilise le panneau présent, ne le recrée que s'il manque ou s'il est incomplet (`:249-252`), et le reloge sans doublon. `E063.js:74-85` garde tout l'état dans le module sans référence de nœud périmée conservée.
- **Solution** : un seul identifiant CSS, une seule classe de portée, un seul nœud `#points-e063-panel`. Le garde anti-doublon supporte un second passage sur le même DOM ; un panneau mal parenté est retiré avant réinsertion.
- **Impact** : aucune accumulation de styles ou de panneaux après re-rendu ; le greffon reste sans effet destructif sur le contenu existant de la matrice.
- **Effort** : M
- **Vérification** : relecture — une seule occurrence de `ctx.css`, un seul `PANEL_ID` ; rejeu : deux `install()` de suite sur le même layout → un seul panneau, un seul `<style id=points-e063>`.

## E063-09 — Accessibilité : région nommée, compteurs hors région live, repli mobile

- **Preuve** : `E063.js:170-172` pose `role="region"`, `aria-labelledby=points-e063-title` et `tabIndex=-1` sur le panneau, dont le titre `h3` porte l'id (`E063.js:174-176`). Les compteurs sont des `<p>` ordinaires (`E063.js:179-181`), sans `role=status`/`aria-live`. `E063.js:236-240` couplent `ctx.reducedMotion()` à l'attribut `data-e063-reduced`, relayé par la media query `E063.js:63-65`. La feuille prévoit le repli 620 px (`E063.js:60-62`), le focus visible (`E063.js:44-46`) et les couleurs forcées (`E063.js:66-71`).
- **Solution** : le relevé est une région annotée du stage, non modale : aucun `role=dialog`, aucun `aria-modal`, aucun piège de focus. Aucune information n'est portée par la seule couleur (libellés textuels des compteurs et de la source).
- **Impact** : le panneau reste lisible et navigable au clavier en 390×844 ; le mouvement réduit est respecté sans animation propre ; aucune annonce parasite dans une région live partagée.
- **Effort** : S
- **Vérification** : relecture — `role=region` et `aria-labelledby` présents, aucun `aria-live` ajouté ; émuler `prefers-reduced-motion: reduce` → attribut `data-e063-reduced=1` ; capture 390×844 sans débordement, focus visible au clavier.

## Statut d'implémentation

Les dix chantiers E063-01 à E063-10 sont implémentés dans `src/views/points/E063.js` uniquement. CSS injecté via `ctx.css('points-e063', …)`. Un seul `MutationObserver`, ciblé sur trois signaux en lecture seule, jamais sur le relevé écrit. Aucun fichier partagé touché, aucune donnée inventée.

## Blocages / limites inter-domaines

- L'observation est volontairement limitée à trois nœuds : un changement de filtre qui ne modifie pas la valeur de l'un des deux `<select>` (par exemple une action du store sans re-rendu) n'émet pas de signal E063. Ce choix est fait pour préserver le budget d'observation ; la signature est tout de même recalculée à chaque `install()`.
- Le relevé est volatile : un rendu neuf de la vue (`points.js:renderPoints`) remet les compteurs à zéro (`E063.js:268-274`). Les conserver entre rendus demanderait un état partagé hors du contrat de la lentille.
- E063 ne corrige ni le store, ni les filtres, ni le détail : il ne fait que relever des signaux déjà produits. Un `MutationObserver` non pris en charge par l'environnement (`typeof MutationObserver === 'undefined'`, `E063.js:193`) désactive silencieusement l'observation ; le relevé statique reste lisible.
- E066 observe également la grille et les filtres. Les deux lentilles disposent de panneaux distincts et d'identifiants disjoints ; E063 n'observe pas le panneau E066, et réciproquement les écritures de E063 se font dans `.points-matrix`, hors des zones observées par E066.
