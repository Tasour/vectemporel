# E099 — Alternative textuelle complète de la matrice

Lentille E099 — domaine J : pédagogie & narration. Fichier possédé : `src/views/points/E099.js` uniquement. La vue (`src/views/points.js`), le registre, le store, la coque, `styles.css` et toute autre lentille ne sont ni édités ni doublés. E099 ajoute un sous-arbre **sémantique et visible** qui restitue en texte la totalité de la matrice de couverture, afin qu'elle reste lisible et compréhensible **sans feuille de style**. Contrat exploité : `viewId`, `stage`, `layout`, `css(id, rules)`, `el(tag, cls, text)`, `reducedMotion()` (fournis par `points/registry.js:28-44`). Tout est dérivé du DOM rendu par `points.js` : `.points-title`, `.points-grid`, `.points-grid-row.is-head`, `.points-era`, `.points-cell` (`.has-points`), `.points-filters` (2 `<select>` + bouton de réinitialisation) et `.points-detail`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`. CSS injecté par `ctx.css('points-e099', …)`.

## E099-01 — Bloc sémantique visible, jamais masqué

- **Preuve** : `E099.js:249-253` crée une `<section role=region aria-labelledby=points-e099-alt-title>` avec un `tabIndex=-1` ; `:255-257` posent le `<h3>` d'intitulé, `:263-269` un `<p class="points-e099-intro">`. Le commentaire d'en-tête (`:25-27`) interdit explicitement `.sr-only`, `aria-hidden`, `hidden` et `display:none` sur l'alternative. La feuille (`:59-114`) ne contient aucune règle de masquage : elle ne fait que border, espacer et colorer le texte. `:379` insère le bloc dans `.points-matrix` (créé par `points.js:30`).
- **Solution** : le texte est porté par des éléments visibles et indexables (`<caption>`, `<th>`, `<td>`, `<p>`, `<li>`) directement dans le DOM. Aucun attribut ne le retire de l'arbre d'accessibilité. Le repli « sans CSS » est structurel : le `<table>` et les `<p>` portent seuls le sens.
- **Impact** : la matrice reste lisible et compréhensible même si la feuille de style ne charge pas ; les lecteurs d'écran et les robots d'indexation accèdent au même contenu que les utilisateurs visuels.
- **Effort** : S
- **Vérification** : relecture — absence de `.sr-only`, `aria-hidden`, `hidden`, `display:none`, `visibility:hidden` dans la feuille ; désactiver le CSS (DevTools) : le titre, le tableau et les phrases restent affichés et dans l'ordre logique.

## E099-02 — Titre, ères et domaines dérivés du DOM réel

- **Preuve** : `readMatrix()` (`E099.js:143-166`) lit `.points-title` (`:146`, provenant de `points.js:32`), l'en-tête `.points-grid-row.is-head` (`:147`, `points.js:34-37`) et les `<span>` de domaine (`:148-151`), puis les lignes `.points-grid-row:not(.is-head)` et les `.points-era` (`:155-156`, `points.js:38-43`). Aucun millésime, aucun total ni aucun nom de domaine n'est codé en dur. Le repli `domainOf()` (`:136-140`) lit le `title` posé par `points.js:48` avant d'envisager une étiquette positionnelle.
- **Solution** : chaque libellé de l'alternative est une lecture dubalisage déjà produit par la vue. Si le jeu de données change, le texte change sans modification du greffon.
- **Impact** : l'alternative ne peut pas mentir sur le contenu de la matrice ; elle reste vraie quand les ères, les domaines ou les points évoluent.
- **Effort** : S
- **Vérification** : relecture — absence de chaîne numérique historique et de `DATASET` importé ; faire varier le pays : le titre et les colonnes du tableau suivent le DOM.

## E099-03 — Équivalent tabulaire avec portées explicites

- **Preuve** : `buildAlternative()` (`E099.js:272-302`) construit un `<table>` avec `<caption>` (`:274`), un `<thead>` dont chaque `<th>` porte `scope="col"` (`:277-284`), un `<tbody>` dont chaque ligne commence par un `<th scope="row">` (`:288-300`). Le domaine de chaque cellule est aussi répété dans son `title` (`:296`). La source visuelle reste `points.js:44-55` (lignes ères × domaines).
- **Solution** : le tableau est le pendant sémantique canonique d'une grille CSS : les lecteurs d'écran reçoivent les en-têtes de ligne et de colonne, donc la relation « ère × domaine → nombre », sans dépendre de la disposition visuelle.
- **Impact** : l'information portée par la position spatiale dans la grille devient explicite et navigable cellule par cellule, y compris hors CSS.
- **Effort** : M
- **Vérification** : relecture — un seul `<caption>`, portées `col`/`row` présentes ; harnais DOM : le nombre de `<tr>` du `<tbody>` égale le nombre de `.points-grid-row:not(.is-head)`, et le nombre de `<td>` par ligne égale le nombre de domaines.

## E099-04 — Narration ère par ère en phrases complètes

- **Preuve** : `rowSentence()` (`E099.js:168-177`) produit une phrase par ère, du type « Ère X — Domaine A : 3 points ; Domaine B : aucun point. », en employant le pluriel (`:173-175`) ; `:304-308` les insère dans une `<ul class="points-e099-narrative">`. L'état est dérivé de `.has-points` et du texte de la cellule (`cellValue()`, `:129-132`, `points.js:46`).
- **Solution** : au-delà du tableau, une reformulation en langage naturel rend la matrice directement compréhensible à la lecture continue : chaque ligne énonce son ère et, pour chaque domaine, le nombre de points ou l'absence de point.
- **Impact** : la narration pédagogique transforme une grille abstraite en récit lisible, utile à l'apprentissage comme aux technologies d'assistance.
- **Effort** : S
- **Vérification** : relecture — pas de chiffre codé en dur ; harnais : une case `has-points` avec texte `2` donne « 2 points », une case sans classe donne « aucun point » ; le nombre de `<li>` égale le nombre d'ères.

## E099-05 — Restitution du point courant depuis le détail

- **Preuve** : `currentPointText()` (`E099.js:182-217`) lit `.points-point-title`, `.points-point-text`, `.points-meta`, `.points-sources` et `.points-justification` (`:186-214`, `points.js:98-111`). Il gère le cas particulier des familles : `points.js:108-109` crée un conteneur `.points-families` mais y ajoute les `<span>` comme enfants **directs** du détail ; E099 lit donc les deux emplacements (`:203-206`) et déduplique (`:207-209`).
- **Solution** : l'alternative ne se limite pas à la grille : elle enchaîne sur le point sélectionné, en reprenant mot pour mot les champs du détail, y compris le repli « Aucun point validé dans ce périmètre. » (`:187-190`, `points.js:113`).
- **Impact** : la lecture de la matrice se prolonge sans rupture dans le contenu du point, avec une fidélité au détail réel plutôt qu'à une copie approximative.
- **Effort** : M
- **Vérification** : relecture des deux sources de familles ; harnais : (a) point avec familles, sources et justification → toutes les phrases présentes ; (b) périmètre vide → phrase de repli ; (c) détail absent → repli explicite.

## E099-06 — État des filtres lu sur les contrôles réels

- **Preuve** : `filtersText()` (`E099.js:221-234`) parcourt les `<select>` de `.points-filters` (`:224-228`, `points.js:60-84`), lit leur option sélectionnée via `selectedOptions` et détecte le bouton de réinitialisation par son libellé (`:229`, `points.js:85-91`). Le résultat est inséré dans `<p class="points-e099-filters">` (`:315-318`).
- **Solution** : l'alternative explicite le périmètre courant (domaine, famille, réinitialisation possible), information que la grille visuelle ne porte pas d'elle-même. Aucun libellé de filtre n'est supposé : tout vient du DOM.
- **Impact** : un lecteur d'écran sait immédiatement pourquoi la matrice affiche tel sous-ensemble et comment revenir à l'affichage complet.
- **Effort** : S
- **Vérification** : relecture — aucune chaîne « Tous les domaines » codée en dur ; harnais : changer le domaine sélectionné → la phrase reflète la nouvelle option sans modifier le code.

## E099-07 — Liaison non destructive grille ↔ alternative

- **Preuve** : `linkGrid()` (`E099.js:335-346`) ne pose un `id` sur `.points-grid` que s'il manque (`:338-339`) et **fusionne** les identifiants de `aria-describedby` existants avec `points-e099-intro` et `points-e099-narrative` via un `Set` (`:342-345`). `buildAlternative()` ajoute un lien interne « Aller à la grille visuelle » dont le `href` est calculé depuis l'id réel (`:259-261`, `:339-340`).
- **Solution** : la grille décrit l'alternative sans écraser les relations posées par d'autres lentilles ; le lien retour permet de naviguer de l'alternative vers la grille et inversement au clavier.
- **Impact** : pas de conflit entre greffons sur `aria-describedby`, et un chemin de navigation explicite entre la vue visuelle et sa transcription textuelle.
- **Effort** : S
- **Vérification** : relecture — `aria-describedby` fusionné, pas remplacé ; harnais : préposer `aria-describedby="autre-id"` sur la grille → l'autre id survit après E099 ; clic sur le lien retour → focus ramené à la grille.

## E099-08 — Légende pédagogique de lecture

- **Preuve** : le paragraphe d'introduction (`E099.js:263-267`) énonce la règle de lecture : « chaque ligne correspond à une ère, chaque colonne à un domaine. Le chiffre indique le nombre de points validés ; la mention « aucun point » signale une case vide. » Il précise que le tableau et les phrases restituent la totalité des données « même sans feuille de style ». Les intitulés de section (`:304`, `:310`, `:315`) structurent le récit.
- **Solution** : E099 ne se contente pas de données : il apprend à les lire. La légende est du texte sémantique `<p>`, première occurrence du vocabulaire de la matrice dans le sous-arbre.
- **Impact** : un utilisateur découvrant la vue comprend comment décoder la grille avant d'entrer dans le détail — c'est le cœur du domaine pédagogie & narration.
- **Effort** : S
- **Vérification** : relecture — paragraphe dans `<p>` visible, pas de contenu généré par JS masqué ; contrôle : le texte de légende est présent dans le DOM statique après `runEnhancements`.

## E099-09 — Compteurs auditables et miroirs d'état

- **Preuve** : `metricsOf()` (`E099.js:236-244`) calcule ères, domaines, cellules, cellules remplies et vides depuis les tableaux issus du DOM ; `:320-329` les affichent dans `<p class="points-e099-metrics">`. `:383-392` écrivent six miroirs sur `layout.dataset` : `pointsE099Css`, `pointsE099Eras`, `pointsE099Domains`, `pointsE099Cells`, `pointsE099Filled` et `pointsE099Motion` (ce dernier issu de `ctx.reducedMotion()`).
- **Solution** : les compteurs sont dérivés, jamais codés en dur, et exposés dans le DOM pour l'audit. Le miroir de mouvement est le seul usage de `ctx.reducedMotion()`, sans animation ajoutée.
- **Impact** : l'agent maître peut vérifier d'un coup d'œil que l'alternative couvre bien toutes les cellules et que le réglage de mouvement a été lu.
- **Effort** : S
- **Vérification** : relecture — somme `filled + empty === cells` ; harnais : comparer `dataset.pointsE099Cells` au nombre réel de `.points-cell`, et `pointsE099Motion` à la préférence système émulée.

## E099-10 — Idempotence, non-destruction et propreté des interdits

- **Preuve** : `apply()` (`E099.js:361-393`) commence par des gardes (`:362-367`), injecte la feuille une seule fois via `ctx.css` (`:369`, `cssOnce` de `registry.js:13-19`), et `ensureSection()` (`:348-356`) retire un bloc mal parenté puis réutilise le nœud existant par identifiant. `buildAlternative()` ne fait que `replaceChildren()` **sur son propre bloc** (`:250`). `register('E099', …)` (`:395-397`) ne fait qu'appeler `apply`. Aucun `console.*`, `fetch`, `XMLHttpRequest`, `Math.random`, `innerHTML`, timer ni rAF n'apparaît dans le code (les seules occurrences sont dans les commentaires d'en-tête, `:26-29`).
- **Solution** : un seul greffon, une seule feuille, un seul bloc d'alternative par rendu ; aucun contenu de `points.js` n'est remplacé ; les nœuds périmés d'un rendu précédent sont retirés avant réinsertion.
- **Impact** : pas de doublon ni de fuite après navigation aller-retour ; aucune régression du rendu d'origine, aucune écriture destructive dans le sous-arbre d'autrui.
- **Effort** : M
- **Vérification** : `node --check src/views/points/E099.js` PASS ; relecture — un seul `new` de section, un seul `ctx.css` ; rejeu rendu → navigation → rendu : un seul `#points-e099-alt`, compteurs stables ; absence confirmée des motifs interdits par recherche textuelle.

## Statut d'implémentation

Les dix chantiers E099-01 à E099-10 sont implémentés dans `src/views/points/E099.js` uniquement. CSS injecté via `ctx.css('points-e099', …)`. Aucune vue, aucun fichier partagé, aucune autre lentille n'a été modifié. Aucune donnée historique n'est inventée, aucun chiffre n'est codé en dur.

## Blocages / limites inter-domaines

- L'alternative est reconstruite à chaque rendu de la coque : son état est volatile, comme le reste de la vue Points. La conserver entre rendus demanderait un état partagé hors du contrat de la lentille.
- E099 pose un `id` sur `.points-grid` uniquement s'il n'en a pas déjà un (`:338-339`) et fusionne `aria-describedby` (`:342-345`). Une lentille qui remplacerait afterwards l'attribut `aria-describedby` de la grille devra préserver les références `points-e099-*`.
- Les familles sont lues à la fois depuis `.points-families span` et depuis les `<span>` enfants directs du détail, pour compenser le comportement de `points.js:108-109`. Si la vue venait à remplir correctement `.points-families`, la déduplication (`:207-209`) évite le doublage.
- Le tableau alternatif duplique volontairement l'information de la grille visuelle : c'est le prix d'une transcription complète et indexable. Sa lisibilité sans CSS est structurelle, mais sa présentation (bordures, couleurs) dépend de la feuille E099.
