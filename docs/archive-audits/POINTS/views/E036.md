# E036 — Navigation entre points par j / k

Lentille E036 — domaine D : navigation & clavier. Fichier possédé : `src/views/points/E036.js` uniquement. Aucun fichier partagé n'est édité. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` (fournis par `src/views/points/registry.js:28-44`). Le routeur clavier unique (`src/platform/keyboard.js`) reste seul maître des touches réservées (`1`–`6` / `m c r g s p`, `?`, Échap, Entrée, Espace, flèches) : `j` et `k` n'appartiennent à aucune de ces familles. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`, aucune région live ajoutée. CSS injecté par `ctx.css('points-e036', …)`.

## E036-01 — Indice j / k visible et non modal dans la fiche

- **Preuve** : `E036.js:164-192` construit un `<section role=region aria-labelledby=points-e036-title>` avec un `<h4>`, deux `<kbd>` (`j`, `k`) et une phrase d'explication. `E036.js:168-169` pose `role=region` et `aria-labelledby` ; aucun `role=dialog`, aucun `aria-modal`, aucun piège de focus, aucun `inert`. `E036.js:48-76` le style sans `backdrop`, préfixé `points-e036-`, et `E036.js:228` passe par `ctx.css(CSS_ID, CSS)` (`cssOnce`, `registry.js:13-19`).
- **Solution** : l'indice est une région annotée du détail, jamais une modale. Il est inséré dans `.points-detail` (`E036.js:245-247`) et reconstruit à chaque rendu par `buildHint()` (`:166`), qui ne touche à aucun contenu existant. Les `<kbd>` sont décoratifs et ne créent aucun arrêt de tabulation supplémentaire.
- **Impact** : le raccourci est découvrable sans aide globale ; la lecture du détail et le parcours Tab ne sont pas interrompus. Aucune concurrence avec le panneau d'aide local de la lentille E035 (touches `f v b n d 0`).
- **Effort** : S
- **Vérification** : relecture — absence de `role=dialog`, `aria-modal`, `inert` ; `role=region` et `aria-labelledby` présents ; un seul `#points-e036-hint` par rendu ; aucun `backdrop`.

## E036-02 — j avance, k recule, via les boutons natifs existants

- **Preuve** : `E036.js:38-43` associe `j` à l'index `1` (« Point suivant ») et `k` à l'index `0` (« Point précédent »), c'est-à-dire l'ordre réel des boutons créés par `points.js:115-121`. `onKeyDown()` (`:197-218`) résout la touche (`:203-205`) puis active `latest.layout.querySelectorAll('.points-nav button')[spec.index]` par `button.click()` (`:207-214`).
- **Solution** : E036 ne réimplémente aucune navigation : il délègue l'action aux deux boutons natifs de `.points-nav`. `keydown` est écouté en capture sur `window` une seule fois (`:265-268`), mais l'action reste l'activation d'un contrôle réellement présent dans le DOM.
- **Impact** : le comportement clavier est strictement identique à celui de la souris ; aucun état parallèle ne peut diverger de l'interface. En cas d'absence des boutons (périmètre vide), la garde `:208` empêche toute action.
- **Effort** : S
- **Vérification** : relecture des deux entrées de `KEYS` ; harnais : `j` → même résultat qu'un clic sur « Point suivant → », `k` → même résultat que « ← Point précédent » ; aucun bouton → aucune erreur.

## E036-03 — Touches libres vérifiées à l'exécution, sans conflit routeur

- **Preuve** : `isFreeKey()` (`E036.js:88-100`) consulte la carte publique `window.VECTEMPOREL_KEYS.map` (`keyboard.js:202-203`) et refuse toute touche réservée (`RESERVED`, `:35`) ou déjà attribuée à une vue (repli `VIEW_LETTERS_FALLBACK`, `:36`, strictement identique à la map du routeur). `onKeyDown()` applique ce filtre avant toute action (`:205`) et `install()` ne marque que les touches réellement libres (`:231`, `:258-263`).
- **Solution** : `j` et `k` ne sont revendiquées que si le contrat public confirme qu'elles sont libres ; si le routeur change de cartographie, la lentille s'efface d'elle-même au lieu de détourner une touche. Aucune lettre de vue, aucune touche de commande (`?`, Échap, Entrée, Espace, flèches) n'est interceptée.
- **Impact** : aucune régression des raccourcis globaux ; l'ajout de E036 est compatible avec les autres lentilles locales (E035 notamment, qui n'utilise pas `j`/`k`).
- **Effort** : S
- **Vérification** : relecture de `isFreeKey()` ; contrôle : `VECTEMPOREL_KEYS.map` contient `1`-`6` et `m,c,r,g,s,p` mais ni `j` ni `k` ; simulation d'une map étendue contenant `j` → `data-points-e036-keys` vide et aucune navigation.

## E036-04 — Garde stricte : vue active, modale, saisie, modificateurs

- **Preuve** : `inPointsView()` (`E036.js:121-133`) exige `ctx.viewId === 'points'`, un `.points-layout` vivant dans `#atlas-stage` et, quand il est publié, `window.VATLAS.getState().view === 'points'`. `modalOpen()` (`:102-113`) interroge `VECTEMPOREL_KEYS.modalState()` avec repli DOM `[aria-modal="true"]:not([hidden])`. `isEditable()` (`:115-119`) couvre `INPUT`, `TEXTAREA`, `SELECT` et `contentEditable`. Le garde-fou est appliqué en tête de `onKeyDown()` (`:198-201`) avec `ctrlKey || metaKey || altKey`.
- **Solution** : la vue effective est vérifiée dans l'état public plutôt que dans la position du focus : après la touche `p`, le focus peut rester sur l'onglet de barre, et `j`/`k` doivent néanmoins fonctionner. Les champs de filtrage (deux `<select>` de `points.js:60-92`) et les modales restent prioritaires, exactement comme dans le routeur (`keyboard.js:126-129`, `:156-157`).
- **Impact** : saisir `j` dans un filtre ne déplace pas le point ; aucune navigation ne se déclenche pendant l'aide ou le détail ; les combinaisons navigateur (`Ctrl+J`, `Cmd+K`, `Alt+J`) ne sont pas détournées.
- **Effort** : M
- **Vérification** : relecture des trois gardes ; harnais : focus dans un `<select>` puis `j` (aucun déplacement) ; modale ouverte puis `k` (aucun déplacement) ; `Ctrl+J` (aucun déplacement) ; vue quittée puis `j` (aucun déplacement).

## E036-05 — preventDefault suffit, aucun stopPropagation ni vol de capture

- **Preuve** : `E036.js:210-212` appelle uniquement `event.preventDefault()`, avec le commentaire explicite « `keyboard.js:125` l'honore (T2-10) ». L'en-tête (`:22-23`) interdit `stopPropagation` et toute capture volée. L'écouteur est pourtant installé en capture sur `window` (`:265-267`), ce qui le fait courir avant le routeur attaché en capture sur `document` (`keyboard.js:199`).
- **Solution** : le seul contrat utilisé est le drapeau `defaultPrevented`, déjà respecté par le routeur en première ligne de son handler (`keyboard.js:125`). E036 laisse l'événement continuer vers tous les autres écouteurs ; il ne modifie ni la cible, ni la propagation.
- **Impact** : le routeur reste fonctionnel pour toutes ses touches ; les autres lentilles (E035 notamment) reçoivent le même événement. Aucun effet de bord sur la délégation d'événements de la coque.
- **Effort** : S
- **Vérification** : relecture — une seule occurrence de `preventDefault()`, aucune de `stopPropagation`/`stopImmediatePropagation` ; harnais : `j` puis `?` → l'aide globale s'ouvre toujours ; aucun autre greffon n'est privé de l'événement.

## E036-06 — Bornage et filtrage délégués, aucune écriture directe de pointIndex

- **Preuve** : le commentaire `E036.js:194-196` énonce : « Le bornage et le filtrage restent la responsabilité de `points.js:117-120` ; E036 n'écrit jamais `pointIndex` ». Les boutons natifs concernés (`points.js:119-120`) écrivent `set({ pointIndex: Math.max(0, …) })` et `set({ pointIndex: Math.min(visible.length - 1, …) })` : bornage `clamp` sur la liste filtrée `visible` construite en `points.js:23-27`.
- **Solution** : E036 active ces boutons plutôt que d'appeler `set()` ou `stepPoint()`. Il hérite ainsi du périmètre filtré (domaine × famille × ère) et des bornes `0 … visible.length - 1`, sans dupliquer le calcul de `visible` ni importer le magasin d'état.
- **Impact** : pas de débordement hors du périmètre affiché, pas de désynchronisation avec le filtre actif, aucun risque de contourner la porte d'écriture unique `set()` (`store.js:216`).
- **Effort** : S
- **Vérification** : relecture — absence de `set(`, `pointIndex`, `stepPoint` dans le module ; harnais : filtrer à 1 point puis `j` → le point reste le même ; retirer le filtre puis `j` → avance d'un cran.

## E036-07 — Miroir d'état auditable et compteurs bornés

- **Preuve** : `install()` écrit `layout.dataset.pointsE036Css`, `pointsE036Keys`, `pointsE036Motion` (`E036.js:232-235`) et, après un déplacement, `pointsE036Last` (`:254-256`). `writeMetrics()` (`:158-162`) affiche `j : N · k : N · déplacements : N` dans `#points-e036-metrics` (`:189-191`) ; `jCount`/`kCount` (`:82-83`) ne s'incrémentent que sur activation réussie (`:215-216`).
- **Solution** : ces miroirs sont dérivés du contrat réel (CSS, touches libres, préférence de mouvement, dernière touche) et servent de trace vérifiable sans journalisation. Aucune écriture dans une région live : l'annonce du point reste portée par la région live de la coque via `set(..., 'point')` (`store.js:172-173`, `shell.js:563`).
- **Impact** : un auditeur peut distinguer « touche ignorée par une garde » de « touche activée » ; aucun bavardage sonore supplémentaire n'est introduit (cf. E041 « région live unique »).
- **Effort** : S
- **Vérification** : relecture — absence de `role=status` ou `aria-live` ajouté ; rejeu : trois `j` puis deux `k` → `j : 3 · k : 2 · déplacements : 5` et `data-points-e036-last="k"`.

## E036-08 — Readout entièrement dérivé du DOM, sans chiffre codé en dur

- **Preuve** : `perimeterTotal()` (`E036.js:135-142`) lit le `.points-detail .view-kicker` produit par `points.js:96` (`${visible.length} point(s) dans ce périmètre`) et en extrait l'entier initial ; `currentTitle()` (`:144-147`) lit `.points-point-title` (`points.js:98`). `writeReadout()` (`:149-156`) compose « Point courant : … · N point(s) dans ce périmètre. » avec repli explicite « Aucun point validé dans ce périmètre. ». Le commentaire `:135-137` interdit tout millésime et total inventé.
- **Solution** : le readout est recalculé à chaque rendu sur le DOM neuf (`:252`) — y compris après le rendu asynchrone déclenché par le clic sur le bouton natif (commentaire `:249-251`). Aucune date, aucun total, aucun nom de point n'est codé en dur dans le module.
- **Impact** : l'indice reste vrai quand le jeu de données ou les filtres évoluent ; il ne promet pas de point quand le périmètre est vide, et il n'annonce jamais d'information que la vue n'affiche pas déjà.
- **Effort** : M
- **Vérification** : relecture — absence de millésime ou de total littéral ; harnais : changer de pays/filtre → le readout suit le titre et le compte affichés ; périmètre vide → phrase de repli.

## E036-09 — Idempotence multi-rendus : un écouteur, un CSS, un indice

Un seul écouteur `window` capture, une seule feuille `cssOnce`, un seul indice vivant : aucune accumulation d'écouteurs, de styles ou de doublons après navigation.
- **Impact** : pas de double activation après un aller-retour de vue, pas de fuite d'écouteurs, pas d'écriture sur un nœud périmé (toutes les écritures vérifient `isConnected`, `:150`, `:159`, `:208`).
- **Effort** : M
- **Vérification** : relecture — une seule occurrence de `addEventListener`, une seule de `ctx.css` ; rejeu : rendu → navigation Points → Chronologie → Points → `j` : un seul déplacement, un seul `#points-e036-hint`, un seul écouteur.

## Blocages / limites inter-domaines

- Le succès de `j`/`k` suppose que les boutons natifs de `.points-nav` existent (`points.js:115-122`) ; si une autre lentille les remplace ou les masque, E036 n'a plus de cible et s'abstient (garde `E036.js:208`) — fichier `points.js` non possédé.
- L'annonce du point atteint reste portée par la région live de la coque via `set(..., 'point')` (`shell.js:563`, `store.js:172-173`). E036 ne duplique pas cette annonce : toute modification de la sémantique de `buildNotice('point')` est hors de son périmètre.
- `window.VATLAS.getState()` (`app.js:149`) est utilisé en lecture seule pour confirmer la vue active ; si ce contrat public disparaît, le repli DOM (`.points-layout` dans `#atlas-stage`) reste suffisant (`E036.js:126-131`).
- L'écouteur capture unique est installé une fois pour toute la session (`E036.js:265-268`) : une lentille tierce qui appellerait `stopPropagation()` en amont pourrait empêcher `j`/`k` d'atteindre E036. Aucun tel appel n'existe dans la vague POINTS à ce jour.
