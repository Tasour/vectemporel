# E081 — Instrumentation de conformité (Qualité & validation)

Lentille E081 — domaine I : qualité & validation. Fichier possédé : `src/views/points/E081.js` uniquement. La vue (`src/views/points.js`), le registre (`src/views/points/registry.js`), le tiroir de diagnostics (`src/views/_diagnostics.js`), la coque et `styles.css` ne sont ni édités ni doublés : E081 ajoute un **rapport local d'autodiagnostic**, non modal, qui mesure ce qui est observable au rendu et déclare ce qui ne peut l'être qu'à la construction.

Contrat exploité : `viewId`, `stage`, `layout`, `css(id, rules)`, `el(tag, cls, text)`, `reducedMotion()` (fournis par `points/registry.js:28-44`). Aucune dépendance vers le store, les filtres ou le détail : le rapport reste lisible avec un `ctx` minimal. Invariants : un seul greffon, un seul CSS `points-e081`, huit ID tous préfixés `points-e081`, un seul badge live, un seul bouton, un seul panneau ; zéro réseau, zéro aléa, zéro journalisation, zéro timer, zéro rAF, zéro `innerHTML`, aucun fichier partagé touché.

Vocabulaire des résultats : **PASS** = contrôle réellement mesuré sur le DOM courant ; **DÉCLARÉ** = fait de source ou de build, vérifié par relecture et non simulé au rendu ; **INFO** = écart observé, à revoir. Le badge n'annonce jamais « PASS » pour un contrôle qu'il n'a pas exécuté.

## E081-01 — Rapport d'autodiagnostic local, non modal

- **Preuve** : `E081.js:257-268` construit une `<section role="region" aria-labelledby="points-e081-title">` avec un `<h2>`, un `tabIndex=-1` et un paragraphe explicite : « La touche ? ouvre l'aide générale de l'application : ce rapport la complète, il ne la remplace pas. » `E081.js:71-136` la stylise (`position` statique, `margin:12px 0 0`, pas de `backdrop`, pas de `role=dialog`, pas d'`aria-modal`, pas de piège de focus). `E081.js:373-376` pose le badge de synthèse, seul nœud live (`role=status`, `aria-live=polite`, `aria-atomic=true`), et `E081.js:393` place le panneau sous `.points-matrix`, pas sous `layout`.
- **Solution** : le rapport est une région annotée de la vue, ouverte à la demande par un bouton natif, jamais une modale. Le panneau et le badge sont tous deux créés avant les contrôles (`E081.js:373-394`) pour que le premier rendu mesure l'état réellement greffé. Le tiroir de diagnostics du harnais marque les nœuds dont le parent direct est `stage`/`layout`/`body` (`_diagnostics.js:69-79`) : le panneau vit donc sous `.points-matrix`, ce qui garde la commande actionnable sans toucher au fichier partagé.
- **Impact** : l'autodiagnostic n'interrompt ni la lecture de la matrice ni le parcours clavier ; le rapport complète l'aide globale avec une frontière explicite, et une seule région live évite le bavardage.
- **Effort** : M
- **Vérification** : relecture — aucun `role=dialog`, `aria-modal` ni `inert` ; `role=region` et `aria-labelledby` présents ; harnais : un seul `role=status`, panneau `hidden` au rendu, ouverture puis fermeture par Échap avec retour de focus sur le bouton.

## E081-02 — Contrôle syntaxique `node --check` déclaré, non simulé

- **Preuve** : `E081.js:209-210` porte la ligne « `node --check src/views/points/E081.js` → PASS (contrôle de build, non rejoué au rendu) ». `E081.js:21-22` énonce l'invariant : le contrôle syntaxique est un fait de build déclaré, jamais exécuté au rendu. `E081.js:276` affiche la commande littérale dans le panneau et `E081.js:399` son résultat avec le libellé « Résultat déclaré : PASS ».
- **Solution** : un navigateur ne peut pas lancer l'analyseur Node : E081 n'imite donc pas un contrôle qu'il ne fait pas. Il affiche la commande exacte, son résultat déclaré et la précision « non rejoué au rendu ». La preuve réelle est la ligne du tableau de vérification en fin de rapport, produite par l'agent maître.
- **Impact** : le rapport ne prétend pas avoir vérifié la syntaxe à l'exécution ; la frontière entre fait de build et mesure runtime reste lisible, ce qui rend l'autodiagnostic falsifiable.
- **Effort** : S
- **Vérification** : relecture — aucun appel à un analyseur, aucun `eval`, aucune chaîne « PASS » présentée comme mesurée ; commande `node --check src/views/points/E081.js` → PASS (tableau final).

## E081-03 — Zéro journalisation et zéro réseau

- **Preuve** : `E081.js:15-24` pose l'invariant (aucune journalisation, aucune requête réseau, aucun aléa, aucun timer, aucune rAF, aucun `innerHTML`). `E081.js:211-212` le rend dans le panneau comme fait **DÉCLARÉ**, avec le détail « invariant de source : aucune journalisation, aucune requête réseau, aucun aléa ». `E081.js:147-151` montre que le seul canal de sortie est le texte du badge live.
- **Solution** : E081 n'écrit nulle part ailleurs que dans son propre DOM et dans ses miroirs `data-points-e081-*` ; il n'installe aucun écouteur réseau ni documentaire, ne lit aucune ressource externe et n'appelle aucune API de hasard. Le contrôle est une déclaration de source, pas une mesure runtime, et il est étiqueté comme tel.
- **Impact** : le rapport n'ajoute aucun bruit à la console, aucune requête et aucune nondéterminisme ; les dix statuts sont reproductibles d'un rendu à l'autre.
- **Effort** : S
- **Vérification** : relecture — absence de `console.`, `fetch`, `XMLHttpRequest`, `Math.random` ; recherche : une seule occurrence de `register(` (`E081.js:350`) et une seule de `css(CSS_ID, CSS)` (`:356`) ; harnais : deux rendus produisent le même badge.

## E081-04 — Unicité des identifiants dans le document

- **Preuve** : `duplicateIds()` (`E081.js:157-169`) parcourt `document.querySelectorAll('[id]')`, construit un `Map` de comptage et collecte les ID dont le compte est supérieur à un. `E081.js:193` l'appelle à chaque rendu ; `E081.js:213-214` en déduit PASS si `duplicates.length === 0`, sinon INFO, avec le détail « N ID visités · M doublon(s) ». `E081.js:248` expose le compteur `data-points-e081-duplicates`.
- **Solution** : la mesure porte sur tout le document courant, pas seulement sur les nœuds de la lentille : un doublon introduit par une autre lentille est donc visible. Le harnais a confirmé `8 ID visités · 0 doublon(s)` au premier rendu comme au second.
- **Impact** : une régression d'identifiants, même hors de E081, devient immédiatement lisible dans le badge et le panneau, sans outil externe.
- **Effort** : M
- **Vérification** : relecture de la fonction de comptage ; harnais : `data-points-e081-duplicates="0"` après deux rendus ; cas adverse — injecter un second `#points-e081-title` doit faire passer E081-04 en INFO.

## E081-05 — Préfixe `points-e081-` sur tous les ID propres

- **Preuve** : `E081.js:31-39` déclare les sept ID d'éléments, tous préfixés ; `CSS_ID = 'points-e081'` (`:27`) complète la famille. `ownIds()` (`:173-176`) lit `[id^="points-e081"]` et `expectedIds()` (`:178-180`) construit la liste attendue de huit entrées. `E081.js:195-197` calcule `missing` et `extra`, et `:215-216` rend PASS seulement si les deux listes sont vides.
- **Solution** : le préfixe n'est pas seulement une convention de nommage : il est vérifié. Le sélecteur `[id^="points-e081"]` couvre à la fois la feuille `#points-e081` et les nœuds `#points-e081-*`, ce qui évite un faux négatif sur la feuille injectée par `cssOnce`. Aucun ID n'est posé sur un nœud d'origine de la vue.
- **Impact** : aucune collision de nommage avec E001–E080 ni E082–E100 ; la lentille peut être réappliquée sans voler d'identifiant au DOM rendu.
- **Effort** : S
- **Vérification** : relecture des huit littéraux ; harnais : `8 ID préfixés · 0 absent(s) · 0 inattendu(s)` au premier rendu ; aucun ID ajouté à `.points-title`, `.points-grid` ou `.points-detail`.

## E081-06 — Feuille CSS unique via `ctx.css('points-e081', …)`

- **Preuve** : `E081.js:27` fixe `CSS_ID = 'points-e081'` et `E081.js:71-136` contient l'unique feuille. `E081.js:356` est le seul appel à `css(CSS_ID, CSS)` ; `E081.js:198` compte les nœuds `#points-e081`, et `:217-218` rend PASS si le compte vaut exactement un. `E081.js:246` expose ce compte dans `data-points-e081-css-count`.
- **Solution** : l'injection passe par `cssOnce` du registre (`registry.js:13-19`), qui refuse un second `<style>` du même identifiant ; la feuille est donc stable quand la coque recrée `#atlas-stage`. Toutes les règles sont préfixées `#points-e081-` ou `.points-e081-`, avec cibles ≥ 36 px, focus visible, repli à 620 px, `forced-colors` et `prefers-reduced-motion`.
- **Impact** : pas de fuite de style hors de la vue Points, pas d'empilement de feuilles après navigation, aucune animation propre à la lentille.
- **Effort** : S
- **Vérification** : relecture — une seule occurrence de `css(CSS_ID, CSS)` ; harnais : `1 feuille #points-e081` après un et deux rendus ; capture 390×844 sans débordement à rejouer par l'agent maître.

## E081-07 — Clé `register('E081', …)` exacte

- **Preuve** : `E081.js:350` contient l'appel littéral `register('E081', (ctx) => {` ; c'est la seule occurrence de `register(` dans le module. `E081.js:28` déclare `REGISTER_ID = 'E081'`, `:364` écrit le miroir `data-points-e081-register` avant les contrôles, et `:204` le relit ; `:219-220` rend PASS quand les deux valeurs coïncident.

## E081-09 — Greffon non destructif, DOM d'origine intact

- **Preuve** : `ANCHORS` (`E081.js:58-66`) liste les sept repères réellement rendus par `points.js:29-126` : `.points-layout`, `.points-matrix`, `.points-title`, `.points-grid`, `.points-filters`, `.points-detail`, `.points-nav`. `E081.js:199-202` vérifie qu'ils sont tous présents et connectés ; `:223-224` rend PASS pour `7/7`. `E081.js:327-332` ne retire qu'un nœud **propre** mal parenté, jamais un nœud de la vue.
- **Solution** : la lentille se contente d'ajouter trois nœuds et des attributs `data-*` sur `layout` ; elle ne modifie ni le texte, ni les classes, ni l'ordre des nœuds existants, et ne pose aucun ID sur eux. Les noms réels du détail sont `.points-meta`, `.points-families`, `.points-sources`, `.points-justification` (`points.js:100-111`) : E081 les lit sans les renommer.
- **Impact** : le filtrage, la sélection d'ère et la navigation de la vue restent intacts ; le rapport peut être retiré sans laisser de trace fonctionnelle.
- **Effort** : S
- **Vérification** : relecture — aucun `remove()` sur un nœud d'origine, aucun `id=` posé hors de la famille `points-e081` ; harnais : `7/7 repères d’origine présents et connectés` ; rejouer les interactions de la vue après greffage.

## E081-10 — Idempotence multi-rendus

- **Preuve** : `place()` (`E081.js:327-332`) réutilise chaque nœud par identifiant et ne le recrée que s'il est absent ou déconnecté. `E081.js:359-360` remet `open` à zéro sur un rendu neuf ; `:384-387` garde un seul écouteur de clic et `:291-301` un seul écouteur d'Échap par panneau. `E081.js:225-226` vérifie `1 panneau · 1 bouton · 1 feuille` et expose `data-points-e081-checks` (`:249`).
- **Solution** : l'installation est réentrante : le CSS est idempotent par `cssOnce`, les nœuds par identifiant, le contenu par `replaceChildren` (`E081.js:258`, `:308`). Les compteurs `renderCount`/`openCount` (`:142-143`) ne mesurent que ce greffon et n'incrémentent aucun signal de la vue.
- **Impact** : navigation aller-retour et double passage sur le même DOM ne produisent ni doublon, ni fuite d'écouteur, ni faux statut ; le harnais a confirmé `8 PASS · 2 DÉCLARÉ · 0 INFO` au premier rendu comme au second, avec `1 panneau`, `1 bouton`, `1 feuille` et `0 doublon`.
- **Effort** : M
- **Vérification** : relecture — `getElementById` avant chaque création, écouteurs gardés par attribut de donnée ; harnais : deux appels du greffon sur le même `layout` → compteurs de nœuds stables, Échap dédupliqué ; suites E2E et capture 390×844 à rejouer par l'agent maître.

## Blocages / limites inter-domaines

- `node --check` est un contrôle de build : le navigateur ne peut pas le rejouer. E081 affiche la commande et son résultat **DÉCLARÉ** (`E081.js:209-210`, `:277`, `:399`) ; la preuve d'exécution reste la ligne du tableau ci-dessous, à produire par l'agent maître.
- L'absence de journalisation, de réseau et d'aléa est un invariant de source, étiqueté **DÉCLARÉ** (`E081.js:211-212`) : aucun contrôle runtime ne peut l'observer directement sans instrumenter des fichiers hors contrat.
- Le tiroir de diagnostics (`_diagnostics.js:69-79`) marque les nœuds dont le parent direct est `stage`/`layout`/`body`. E081 contourne ce marquage en parentant le panneau sous `.points-matrix` (`E081.js:389-393`), fichier non possédé : si cette règle change, la lentille devra réévaluer son point d'ancrage.
- Le contrôle d'unicité des ID (`E081.js:157-169`) mesure l'état au moment où E081 s'applique, c'est-à-dire après E001–E080 et avant E082–E100 dans l'ordre du registre : un doublon créé par une lentille postérieure ne sera pas vu au rendu courant.
- Échap n'est consommé que si le panneau porte le focus (`E081.js:293-301`) ; ailleurs, le routeur clavier (`src/platform/keyboard.js`) reste seul maître.
- L'état d'ouverture est volatile : un rendu neuf remet `open` à zéro (`E081.js:359-360`). Le conserver demanderait un état partagé hors du contrat de la lentille.
