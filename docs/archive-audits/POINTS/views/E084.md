# E084 — I. Qualité & validation : feuille CSS unique idempotente et signal de présence, sans doublon après rendus

Lentille E084 — domaine I : qualité & validation. Fichier possédé : `src/views/points/E084.js` uniquement. Aucun fichier partagé (`src/views/points.js`, `registry.js`, `styles.css`, `src/views/_diagnostics.js`) n'est édité. Le greffon exploite le contrat tel que fourni par `points/registry.js` : `viewId`, `stage`, `layout`, `css(id, rules)`, `el(tag, cls, txt)`, `reducedMotion`. Il n'ajoute aucune dépendance vers le store, le routeur ni une autre lentille, et reste actif avec un `ctx` minimal. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`.

## E084-01 — Injection CSS unique par `ctx.css('points-e084', …)`

- **Preuve** : `E084.js:26` fixe `CSS_ID = 'points-e084'` ; `:165` appelle `ctx.css(CSS_ID, CSS)` ; `:166` neutralise la lentille si `document.getElementById(CSS_ID)` est absent après injection. `registry.js:13-19` (`cssOnce`) refuse précisément une seconde injection pour un identifiant déjà présent. La feuille est définie en `:37-61`, sans `@import`, sans `url(http…)` et sans ressource externe.
- **Solution** : passer exclusivement par l'API `css` du contrat, jamais par une balise `<link>` ni une feuille écrite à la main. Le contrôle `:166` transforme un échec d'injection en neutralisation silencieuse plutôt qu'en rendu dégradé.
- **Impact** : aucune requête réseau, aucune feuille orpheline ; la feuille vit dans `<head>` et survit au remplacement du `#atlas-stage` par la coque.
- **Effort** : S
- **Vérification** : relecture de `:26`, `:37-61`, `:165-166` et de `registry.js:13-19` ; harnais : deux appels de `runEnhancements` → `document.querySelectorAll('style#points-e084').length === 1`.

## E084-02 — Garde-fou anti-doublon de la feuille

- **Preuve** : `E084.js:65-67` limite la requête à `style#points-e084` ; `:76-88` (`ensureSingleSheet`) élit le style déjà dans `<head>` (`:78`), conserve le premier et retire tous les surnuméraires (`:80-86`) ; `:168-169` consigne le nombre brut avant élagage puis appelle le garde-fou avant tout autre marquage.
- **Solution** : `cssOnce` empêche la duplication par injection, mais une copie artisanale ou une ancienne version pourrait déjà occuper le DOM. Le garde-fou garantit un unique style même dans ce cas, avec priorité à celui de `<head>`.
- **Impact** : après N rendus, la feuille reste unique ; l'écart entre `rawSheets` et `sheets` est auditable via le signal de `:186-187`.
- **Effort** : S
- **Vérification** : relecture de `:65-67` et `:76-88` ; harnais : injecter trois `style#points-e084` puis exécuter `apply` → un seul subsiste, celui du `<head>`.

## E084-03 — Signal de présence `data-points-e084="ready"`

- **Preuve** : `E084.js:28` déclare `SIGNAL = 'data-points-e084'` ; `:176` pose `layout.setAttribute(SIGNAL, 'ready')` ; `:15-16` pose l'invariant « UNE feuille, UN badge, UNE classe de portée ».

- **Impact** : l'agent maître et les autres lentilles peuvent tester la présence de E084 sans inspecter le CSS ni dépendre d'un nœud précis ; le signal est identique après un aller-retour de navigation.
- **Effort** : S

## E084-07 — Signature anti-écriture redondante

- **Impact** : nombre borné d'écritures DOM, aucun bavardage ; aucune réinterprétation de balisage (`replaceChildren` uniquement, avec des nœuds créés par `ctx.el`).

- **Impact** : rendu → navigation aller-retour → rendu : un seul style, un seul badge, aucun résidu, aucune fuite d'écouteur puisque le greffon n'en crée aucun.

## Statut d'implémentation

Les dix chantiers E084-01 à E084-10 sont implémentés dans `src/views/points/E084.js` uniquement. CSS injecté une seule fois via `ctx.css('points-e084', …)`. Un seul badge `points-e084-badge`, un seul signal `data-points-e084`, un seul jeu de compteurs d'audit. Aucun fichier partagé touché, aucune donnée inventée, aucun écouteur créé.

## Blocages / limites inter-domaines

- `cssOnce` (`registry.js:13-19`) n'expose pas de compteur d'injection : E084 déduit l'unicité par requête DOM (`E084.js:65-67`) et ne peut réélaguer un doublon qu'au rendu suivant (`:169`). Une autre lentille réécrivant `style#points-e084` entre deux rendus resterait momentanément visible.
- Le badge dépend de `ctx.el` et `ctx.css` fournis par `runEnhancements` : avec un `ctx` minimal privé de ces fonctions, la garde `:153` neutralise la lentille. C'est le comportement prévu par le contrat, pas un défaut.
- Les signaux d'audit (`:186-191`) ne sont pas persistés : un rendu neuf réinitialise `rawSheets`/`rawBadges`. Ils décrivent l'état du rendu courant, pas un historique.
- Le badge vit dans `.points-matrix` pour échapper au tiroir de diagnostic (`_diagnostics.js:69-75`). Si une autre lentille remplace entièrement `.points-matrix`, `ensureBadge` (`:94-111`) recrée le badge, mais l'ancien nœud n'est pas restauré : la lentille n'a pas vocation à gérer la structure de la matrice.
