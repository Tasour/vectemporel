# E020 — Filtres & périmètre : équivalent clavier pour chaque filtre

Lentille E020 — domaine B : filtres & périmètre. Fichier possédé : `src/views/points/E020.js` uniquement. Le module ajoute un équivalent clavier local à chacun des trois contrôles de filtrage écrits par `points.js` (`:60-93`) : deux `<select>` (domaine, famille) et le bouton « Réinitialiser les filtres ». Il n'édite aucun fichier partagé, n'écrit aucun état, n'importe pas le store et ne duplique aucune logique de filtrage : chaque raccourci délègue au comportement déjà installé sur le contrôle (`focus`, `.click()` ou `Event('change')`). Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion`. CSS injecté par `ctx.css('points-e020', …)`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`.

## E020-01 — Équivalent clavier du filtre Domaine (`Alt+D`)

- **Preuve** : `selectsOf()` (`E020.js:86-95`) identifie le `<select>` de domaine par son `aria-label="Filtrer par domaine"` (écrit en `points.js:62`), avec repli sur le premier `<select>` du groupe (`:88`). `onKeydown()` (`:159-172`) mappe `Alt+D` sur ce contrôle et lui donne le focus via `control.focus({ preventScroll: true })` (`:170`) ; la touche est consommée localement (`:162-163`).
- **Solution** : le raccourci ne modifie pas la valeur : il cible le contrôle natif, dont les flèches `←`/`→` choisissent l'option et déclenchent le `change` de `points.js:69-72`. L'équivalent clavier reproduit donc exactement le parcours souris sans court-circuiter le gestionnaire d'origine.
- **Impact** : un utilisateur clavier peut atteindre et actionner le filtre domaine sans chercher le `<select>` dans l'ordre de tabulation de la matrice.
- **Effort** : S
- **Vérification** : relecture de `:86-95` et `:159-172` ; harnais : `Alt+D` → `document.activeElement` est le premier `<select>` ; `→` → valeur changée et filtre appliqué par l'hôte.

## E020-02 — Équivalent clavier du filtre Famille (`Alt+F`)

- **Preuve** : `selectsOf()` (`:86-95`) reconnaît le second `<select>` via `aria-label="Filtrer par famille"` (`points.js:74`), avec repli sur le deuxième `<select>` (`:88`). La branche `key === 'f'` de `onKeydown()` (`:159`) sélectionne `target.family` et applique le même `focus` + annonce (`:161-171`).
- **Solution** : symétrie stricte avec E020-01 ; un seul gestionnaire sert les deux filtres, aucune duplication de code ni d'écouteur.
- **Impact** : les deux dimensions du périmètre ont le même niveau d'accès clavier ; aucun filtre n'est favorisé.
- **Effort** : S
- **Vérification** : relecture de la branche `f` ; harnais : `Alt+F` → focus sur le second `<select>` ; `Alt+D` puis `Alt+F` → focus transféré de l'un à l'autre sans erreur.

## E020-03 — Équivalent clavier de la réinitialisation (`Alt+R`)

- **Preuve** : `resetOf()` (`:99-102`) trouve le bouton dont le libellé contient « réinit » (`points.js:85`), sinon le premier bouton de `.points-filters`. La branche dédiée de `onKeydown()` (`:149-157`) appelle `reset.click()` (`:154`), ce qui exécute exactement le gestionnaire de `points.js:87-91`.
- **Solution** : activation du bouton natif plutôt que réécriture de `state.pointFilterDomain` / `pointFilterFamily` : aucune valeur d'état dupliquée dans la lentille, aucun import vers `store.js`.
- **Impact** : le raccourci reste vrai si la logique de réinitialisation de l'hôte évolue ; le bouton visuel et le raccourci produisent le même résultat.
- **Effort** : S
- **Vérification** : relecture de `:149-157` ; harnais : filtres posés sur une valeur puis `Alt+R` → les deux `<select>` reviennent à `*` et le détail affiche le périmètre complet.

## E020-04 — Parcours des options sans ouvrir la liste (`Alt+Maj+D` / `Alt+Maj+F`)

- **Preuve** : `cycle()` (`:127-137`) calcule l'index courant, choisit l'option suivante avec retour au début (`:130-132`), pose `select.value` puis émet `new Event('change', { bubbles: true })` (`:134-135`). `onKeydown()` n'appelle `cycle()` que lorsque `event.shiftKey` est vrai (`:164-168`).
- **Solution** : le filtre est changé « comme si l'utilisateur avait choisi l'option » : c'est le gestionnaire `change` de l'hôte (`points.js:69-84`) qui applique le filtre et déclenche le rendu. Aucune écriture directe dans le store.
- **Impact** : équivalent clavier complet, pas seulement un déplacement de focus : on peut balayer rapidement tous les domaines ou toutes les familles sans dérouler la liste native.
- **Effort** : M
- **Vérification** : relecture de `:127-137` ; harnais : option courante → `Alt+Maj+D` → option suivante, puis bouclage sur la première après la dernière ; une liste à une seule option ne produit aucun `change`.

## E020-05 — Anti-conflit avec le routeur clavier (modificateur `Alt` seul)

- **Preuve** : `onKeydown()` exige `event.altKey` et refuse `ctrlKey`/`metaKey` (`:144`). Le routeur `platform/keyboard.js:127` ignore explicitement toute combinaison avec `ctrlKey || metaKey || altKey` ; ses lettres nues `m/c/r/g/s/p` et chiffres `1–6` (`:160-166`) restent donc intactes, ainsi que `?`, Échap, Entrée, Espace et les flèches (`:134-196`). Le garde `event.defaultPrevented` (`:144`) respecte un gestionnaire local ayant déjà consommé la touche.
- **Solution** : aucune lettre nue réservée par la lentille ; combinaisons `Alt` (et `Alt+Maj`) uniquement. `preventDefault()` + `stopPropagation()` (`:152-153`, `:162-163`) sont posés dans le gestionnaire de la lentille, qui est en phase bulle sur `document` : le routeur, en phase capture, a déjà statué et n'est pas perturbé.
- **Impact** : aucun détournement de la navigation entre vues ni de l'aide globale ; presse-touches et lecteurs d'écran conservent leurs comportements habituels.
- **Effort** : S
- **Vérification** : relecture de `:139-163` et de `keyboard.js:123-166` ; harnais : `d`, `f`, `r` seuls ne déclenchent rien dans E020 ; `Alt+D` ne change pas de vue ; `?` et Échap répondent toujours comme avant.

## E020-06 — Découvrabilité ARIA des raccourcis sur les contrôles

- **Preuve** : `describe()` (`:232-248`) pose `aria-keyshortcuts="Alt+D Alt+Shift+D"` sur le select domaine (`:234`), `"Alt+F Alt+Shift+F"` sur le select famille (`:239`) et `"Alt+R"` sur le bouton (`:244`), avec un `title` explicite (`:235`, `:240`, `:245`) et la classe `points-e020-control` (`:236`, `:241`, `:246`).
- **Solution** : ajouts purement additifs sur des contrôles existants : ni `value`, ni `aria-label`, ni gestionnaire n'est remplacé. Les attributs sont reposés à chaque rendu, donc cohérents avec le DOM neuf.
- **Impact** : les technologies d'assistance peuvent annoncer le raccourci associé à chaque filtre ; l'information n'est pas portée par la seule couleur ni par le seul panneau d'aide.
- **Effort** : S
- **Vérification** : relecture de `:229-248` ; contrôle DOM : les trois contrôles portent `aria-keyshortcuts`, un `title` non vide et la classe de focus ; leurs `value` et `aria-label` d'origine sont inchangés.

## E020-07 — Aide locale non modale, complément de l'aide globale

- **Preuve** : `hintsOf()` (`:194-227`) construit une `<section role="region" aria-labelledby="points-e020-hints-title" tabindex="-1">` (`:199-204`) dont le paragraphe d'introduction dit explicitement : « Ces raccourcis complètent l’aide globale ouverte par « ? » : ils n’agissent que sur les filtres de cette vue. » (`:208-209`). Les cinq combinaisons sont listées en `<ul>/<li><kbd>` (`:210-216`). Aucun `role=dialog`, `aria-modal`, `inert`, piège de focus ni `backdrop`.
- **Solution** : le panneau est une région annotée du groupe de filtres, insérée en dernier enfant de `.points-filters` (`:225`) ; la feuille le fait passer à la ligne avec `flex: 1 1 100%` (`:32`), sans déplacer les contrôles existants. `#atlas-help` et `renderHelp` ne sont jamais touchés.
- **Impact** : la découverabilité des raccourcis ne bloque ni le parcours de la matrice ni l'aide globale ; la frontière entre les deux aides est explicite.
- **Effort** : M
- **Vérification** : relecture de `:192-227` et `:31-36` ; contrôle DOM : un seul `#points-e020-hints`, `role=region`, aucun `role=dialog` ; ouverture de l'aide globale par `?` toujours fonctionnelle.

## E020-08 — Annonce maîtrisée dans un status local dédupliqué

- **Preuve** : `announce()` (`:114-122`) refuse un texte vide ou identique à `lastAnnouncement` (`:116`) et n'écrit que dans le nœud `#points-e020-status` courant, à condition qu'il soit connecté (`:117-118`). Le nœud porte `role="status" aria-live="polite" aria-atomic="true"` (`:217-221`) et est masqué quand il est vide (`:51`). Les appels ne viennent que des actions clavier (`:155`, `:166-168`, `:171`), jamais d'un rendu.
- **Solution** : une seule région live locale, dédupliquée ; `lastStatus` est restauré dans un panneau neuf sans réannonce (`:217`, `:223`), ce qui évite de perdre le dernier message après un rendu tout en supprimant le bavardage.
- **Impact** : chaque action clavier produit au plus une annonce ; les changements de filtre provoqués par la souris ou par l'hôte ne génèrent aucun commentaire parasite de la part d'E020.
- **Effort** : M
- **Vérification** : relecture de `:113-122` et `:217-223` ; harnais : deux `Alt+D` consécutifs → une seule annonce ; `Alt+R` puis `Alt+R` → une seule annonce ; un rendu seul → aucun texte ajouté au status.

## E020-09 — Focus visible, cibles tactiles et mouvement réduit

- **Preuve** : la feuille pose `outline: 2px solid var(--gold-bright); outline-offset: 2px` sur `:focus-visible` des contrôles marqués et du panneau (`:52-54`), un repli à 700 px (`:55-57`) et `transition: none` sous `prefers-reduced-motion` (`:58-60`). `motionState()` (`:252-256`) lit `ctx.reducedMotion()` dans un `try/catch` avec repli `full` et expose le résultat sur `data-points-e020-motion` (`:279`). Aucune animation, aucun timer ni rAF n'existe dans le module.
- **Solution** : le respect du mouvement réduit est obtenu par construction (aucune animation propre) ; l'état observé est seulement publié pour audit. Les `<kbd>` et le panneau restent lisibles en colonne étroite grâce à `overflow-wrap: anywhere` (`:35`) et au retour à la ligne du panneau (`:32`).
- **Impact** : le focus reste percevable au clavier, les libellés ne débordent pas sur un écran étroit, et aucun mouvement parasite ne contredit le réglage système.
- **Effort** : S
- **Vérification** : relecture de `:29-61` et `:250-256` ; émuler `prefers-reduced-motion: reduce` → `data-points-e020-motion="reduced"`, aucune transition active ; capture 390×844 sans débordement du panneau.

## E020-10 — Idempotence, pureté et compatibilité multi-rendus

- **Preuve** : `ensureListener()` (`:178-183`) n'attache l'unique écouteur `keydown` qu'une fois (`listenerAttached`). `hintsOf()` (`:195-197`) supprime un panneau déconnecté ou mal parenté avant d'en créer un seul ; `ctx.css(CSS_ID, CSS)` passe par `cssOnce` du registre (`:267`, `registry.js:13-19`). Les gardes de `apply()` (`:261-266`) exigent le contrat minimal et la vue `points`. Les nœuds devenus déconnectés désactivent les raccourcis (`:151`, `:160`).
- **Solution** : un seul `register`, un seul CSS, un seul panneau, un seul status, un seul écouteur ; `current` est remplacé à chaque rendu (`:280`), jamais d'accumulation de références périmées. Le `try/catch` du `register` (`:284-287`) neutralise la lentille sans interrompre le rendu. Aucun `console.*`, `fetch`, `XMLHttpRequest`, `Math.random`, `innerHTML`, timer ni rAF.
- **Impact** : navigation aller-retour et rendus successifs ne produisent ni doublon de panneau, ni empilement d'écouteurs, ni annonce fantôme ; fichiers partagés strictement inchangés.
- **Effort** : M
- **Vérification** : relecture de `:175-183`, `:194-197`, `:258-287` ; `node --check src/views/points/E020.js` PASS ; grep des motifs interdits : aucune occurrence hors commentaires ; rendu → navigation → retour : un seul `#points-e020-hints`.

## Statut d'implémentation

Les dix chantiers E020-01 à E020-10 sont implémentés dans `src/views/points/E020.js` uniquement. CSS injecté via `ctx.css('points-e020', …)`. Aucun fichier partagé modifié, aucun état écrit, aucune logique de filtrage dupliquée.

## Blocages / limites inter-domaines

- Le routeur (`platform/keyboard.js`, fichier non possédé) réserve les lettres nues et les touches globales : E020 n'utilise donc que des combinaisons avec `Alt`; l'ajout d'un raccourci sans modificateur demanderait un arbitrage maître avec E035 (raccourcis locaux) et le routeur.
- Le cycle `Alt+Maj+D/F` repose sur l'événement `change` émis par `points.js:69-84` : si l'hôte cesse d'écouter `change` sur les `<select>`, le raccourci ciblerait encore le contrôle mais ne filtrerait plus. Aucun correctif n'est possible depuis la lentille sans écrire l'état.
- Le status local est une région live propre à E020. Si E041 (région live unique) impose une région globale, il faudra fusionner `#points-e020-status` avec le canal `say()` de la coque — hors du contrat fourni à cette lentille.
- L'état `lastStatus` est volatile et purement module-level : un rechargement complet de la page le remet à zéro. Le conserver requérait un stockage partagé hors contrat.
- Les raccourcis ne s'appliquent que lorsque la vue Points est rendue : les nœuds déconnectés désactivent le gestionnaire (`:151`, `:160`), ce qui est volontaire mais empêche un usage global hors de cette vue.
