# E014 — B. Filtres & périmètre — badge de récapitulatif du périmètre actif

Lentille E014 — domaine B : filtres & périmètre. Fichier possédé : `src/views/points/E014.js` uniquement. La vue (`src/views/points.js`), le registre, la coque et `styles.css` ne sont ni édités ni doublés : E014 ajoute un **seul badge de lecture** dans la barre `.points-filters` déjà produite par la vue. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` ; aucune dépendance vers le store, le dataset ou l'état interne de la vue. Chaque valeur affichée est dérivée du DOM réellement rendu. CSS injecté par `ctx.css('points-e014', …)`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, aucun fichier partagé touché.

## E014-01 — Badge unique ancré dans la barre de filtres, non destructif et idempotent

- **Preuve** : `E014.js:222` porte l'unique `register('E014', …)` ; `:229-232` injectent le CSS unique, posent la portée `points-e014` et le signal `data-e014=1`. `buildBadge()` (`:136-155`) construit un seul `<div id="points-e014-badge" role="group">` et l'ajoute par `filters.appendChild(badge)` (`:153`) : aucun contrôle existant n'est retiré ou remplacé. Le garde `:247-250` retire un nœud mal parenté issu d'un rendu précédent puis réutilise le badge déjà présent.
- **Solution** : ancrage dans `.points-filters` (parent direct = la barre, et non `stage`/`layout`). Ce choix écarte aussi le masquage du mode diagnostic (`_diagnostics.js:69-79` ne marque que les enfants directs de `body`, `stage` ou `layout`). Une seule feuille via `cssOnce` ; le badge est réutilisé quand le même DOM reçoit une seconde passe.
- **Impact** : les deux `<select>` et le bouton « Réinitialiser les filtres » restent intacts ; aucun doublon de badge après navigation aller-retour.
- **Effort** : S
- **Vérification** : relecture — un seul `register`, un seul `BADGE_ID`, `appendChild` sans `replaceChildren` sur les contrôles ; `node --check src/views/points/E014.js` PASS.

## E014-02 — Domaine dérivé du `<select>` réellement sélectionné, sans état importé

- **Preuve** : `selectsOf()` (`:77-86` :82) prend le premier `<select>` de `.points-filters`. `selectedLabel()` (`:90-95`) lit `select.options[select.selectedIndex].textContent` et le normalise via `collapse()` (`:72-75`). `readPerimeter()` (`:122`) retombe sur « domaine non renseigné » si le contrôle manque. Aucun import du store, aucun libellé « Tous les domaines » codé en dur dans le module : ce libellé vient de l'option produite par `points.js:63-68`.
- **Solution** : le badge reflète exactement l'option choisie par la personne, y compris la valeur par défaut `*` dont le texte est lu dans le DOM. Un contrôle absent est signalé, jamais deviné.
- **Impact** : le récapitulatif reste vrai si la liste des domaines évolue dans le jeu de données ; aucune chaîne historique à maintenir.
- **Effort** : S
- **Vérification** : relecture — absence d'import `store.js`/`dataset.js` ; harnais : changer le premier select → le libellé « Domaine » change sans toucher au code.

## E014-03 — Famille dérivée du second `<select>`, avec repli explicite

- **Preuve** : `selectsOf()` (`:83`) isole le second `<select>` de la barre. `readPerimeter()` (`:123`) applique le même mécanisme que le domaine avec le repli distinct « famille non renseignée ». La normalisation `collapse()` (`:72-75`) est partagée, ce qui évite deux variantes de-formatage.
- **Solution** : symétrie volontaire avec E014-02 : une seule fonction de lecture, deux sources, deux repli distincts. Le repli dit ce qui manque au lieu d'afficher un libellé par défaut trompeur.
- **Impact** : aucun « Toutes les familles » affiché quand le sélecteur a disparu ; les deux axes restent distinguables pour un lecteur d'écran.
- **Effort** : S
- **Vérification** : relecture des deux branches de `readPerimeter()` (`:122-123`) ; harnais : retirer le second select → « famille non renseignée », premier select inchangé.

## E014-04 — Ère courante lue depuis la ligne active de la matrice, sans millésime codé en dur

- **Preuve** : `eraLabel()` (`:99-106`) lit `.points-grid-row.is-active .points-era` (`:100`), c'est-à-dire le libellé posé par `points.js:39-43` sur la ligne de l'ère courante. - **Effort** : S

## E014-05 — Compte de points dérivé du `.view-kicker` du détail, avec accord singulier/pluriel

- **Preuve** : `countInfo()` (`:110-117`) lit `.points-detail .view-kicker` (`:111`), cible de `points.js:96` qui écrit `${visible.length} point(s) dans ce périmètre`, et en extrait l'entier par `/(\d+)\s*point/i` (`:113`). L'accord est recalculé (`:116` : `n <= 1 ? 'point' : 'points'`) ; le cas illisible donne « compte indisponible » (`:114`). La chaîne brute est conservée dans `perimeter.raw` pour la trace (`:126`).
- **Solution** : une seule grandeur chiffrée, lue à sa source et jamais recopiée en dur. Le texte brut reste consultable via le `title` du badge (`:172`), ce qui rend le chiffre auditable.
- **Impact** : zéro écart entre le compte du badge et celui du détail, y compris après filtrage ; l'accord français reste correct à 0, 1 et n.
- **Effort** : S
- **Vérification** : relecture de `:110-117` ; harnais : kicker « 1 point(s)… » → « 1 point », « 12 point(s)… » → « 12 points », kicker vide → « compte indisponible ».

## E014-06 — Récapitulatif textuel étiqueté, aucune information portée par la seule couleur

- **Preuve** : `buildBadge()` (`:136-155`) pose `role="group"` et `aria-label="Récapitulatif du périmètre actif"` (`:139-140`), un titre visible « Périmètre actif » (`:141`) et quatre axes chacun avec sa clé en texte : « Domaine : », « Famille : », « Ère : », « Points : » (`:142-152`). Les accents CSS (`:41-48`, bordure gauche dorée et valeur du compte) sont redondants avec ce texte ; `:57-62` force `Canvas`/`CanvasText` en `forced-colors`.
- **Solution** : le badge est un groupe sémantique étiqueté, pas une région live (voir blocages). Chaque axe est nommé dans le DOM visible, donc compréhensible sans couleur, sans CSS et par restitution brute.
- **Impact** : lecteur d'écran, vision déficiente et impression en niveaux de gris reçoivent la même information ; aucun axe « muet » représenté par une seule nuance.
- **Effort** : S
- **Vérification** : relecture de `:139-152` et `:57-62` ; contrôle sans CSS : les quatre libellés restent lisibles ; aucun `role=status` ajouté par E014.

## E014-07 — Signature anti-écriture redondante et compteur auditable

- **Preuve** : `signatureOf()` (`:130-132`) joint les quatre valeurs. `refresh()` (`:175-187`) sort sans écrire si la signature est inchangée (`:182`), sinon incrémente `refreshCount` (`:184`) et repeint le badge. `writeTrace()` (`:169-173`) expose `data-e014-refreshes`, `data-e014-signature` et un `title` qui contient la source brute du compte. À chaque rendu, `lastSignature` est remis à zéro (`:227`) mais le badge neuf est peint inconditionnellement (`:252-255`) : aucun vide possible.
- **Solution** : la signature évite les réécritures provoquées par les mutations en place des sources ; le compteur distingue « aucun changement de périmètre » de « greffon muet ». La trace vit dans des attributs, pas dans une journalisation.
- **Impact** : nombre borné d'écritures DOM ; comportement vérifiable par simple inspection du badge, sans instrumenter la page.
- **Effort** : M
- **Vérification** : relecture de `:175-187` ; rejeu : mutation sans changement de valeurs → compteur stable ; changement de domaine → `data-e014-refreshes` +1 et signature modifiée.

## E014-08 — Écoute `change` locale, non destructive et sans bavardage

- **Preuve** : `bindSelects()` (`:192-198`) pose un marqueur `data-e014-bound="1"` (`:194-195`) puis un unique `addEventListener('change', () => refresh())` par select (`:196`). Aucun `preventDefault`, aucun `stopPropagation` : la vue reste maîtresse de son re-rendu (`points.js:69-84`). `refresh()` n'écrit que dans le badge et ne touche aucune région live.
- **Solution** : l'écoute est locale aux deux contrôles et idempotente même si `runEnhancements` repasse sur le même DOM. Aucune annonce supplémentaire : E015 porte le `role="status"` du nombre de résultats, E13/E019 portent l'annonce des changements de filtre. Le `ctx` courant est relu via `latestCtx` (`:176`), jamais figé dans la closure de l'écouteur.
- **Impact** : retour visuel immédiat sur le badge avant le re-rendu complet, sans voler l'événement à la vue ni doubler les messages vocaux.
- **Effort** : M
- **Vérification** : relecture de `:189-198` — absence de `preventDefault`/`stopPropagation`, absence de `role=status`/`aria-live` dans le module ; harnais : deux passes `runEnhancements` sur le même DOM → un seul écouteur effectif par select.

## Blocages / limites inter-domaines

- E014 est **passif** : aucun `role="status"`, aucune région live. Le `role="status"` du nombre de résultats appartient à E015, l'annonce de changement de filtre à E013/E019. Ajouter une annonce ici provoquerait un bavardage concurrent ; la relecture de `:169-198` confirme l'absence d'écriture live.
- Le badge dépend de la structure produite par `points.js` (sélecteurs de `:61-84`, ligne active de `:39`, kicker de `:96`). L'observateur couvre les mutations en place de ces sources ; un remplacement complet sans nouvel appel à `runEnhancements` laisserait le badge afficher son dernier état jusqu'au rendu suivant.
- Le signal `layout.dataset.e014` (`:232`) et la portée `.points-e014` (`:231`) sont écrits par E014 ; toute lentille qui réécrirait `layout.dataset` ou `layout.className` en bloc devra les préserver.
- `refreshCount` est cumulatif entre rendus (closure module, `:70`) et remis à zéro au rechargement de page : il n'est pas persisté, la persistance hors du contrat de la lentille.
- Le câblage de `renderPoints` dans la coque n'a pas été observé (`shell.js:542-550` ne liste pas la vue Points). E014 s'active dès que `runEnhancements({ viewId: 'points', … })` est appelé (`points.js:126`), indépendamment du point d'entrée ; le câblage de la vue relève de l'agent maître.
