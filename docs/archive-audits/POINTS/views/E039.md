# E039 — Restauration du focus après filtrage

Lentille E039 — domaine D : navigation & clavier. Fichier possédé : `src/views/points/E039.js` uniquement. La vue `src/views/points.js`, le registre `src/views/points/registry.js`, la coque `src/ui/shell.js` et les lentilles voisines ne sont ni édités ni doublés.

Les commandes de `.points-filters` (deux `<select>` et le bouton « Réinitialiser les filtres ») et les cellules `.points-cell` appellent `set(..., 'filter')` (`points.js:52`, `:71`, `:83`, `:90`, `:49-53`). La coque recrée alors tout le DOM (`shell.js:533`, `root.innerHTML = ''`) et le nœud focalisé est détruit : le focus tombe sur `document.body` ou sur `#atlas-stage`, car `focusCandidates()` (`shell.js:223-227`) n'inclut pas les `<select>` et `findBySignature()` (`shell.js:230-238`, `:286-289`) ne peut donc pas les retrouver. E039 mémorise l'intention **avant** le re-render et la rejoue sur le contrôle équivalent du DOM neuf, après `manageFocus()` (`shell.js:562`).

Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el` (tels que fournis par `points/registry.js:28-44`). Aucune dépendance vers le store, le routeur, `ctx.say()` ou une autre lentille. Zéro réseau, zéro aléa, zéro `console.*`, zéro timer/rAF, zéro `innerHTML`, aucune région live ajoutée.

## E039-01 — Feuille CSS unique, strictement ciblée sur la vue Points

- **Preuve** : `E039.js:31` définit `CSS_ID = 'points-e039'` ; `:38-53` la feuille ne touche que `.points-filters [data-points-e039-role]`, `#points-e039-metrics` et `#points-e039-hint`, avec une seule règle `@media (prefers-reduced-motion: reduce)` (`:50-52`). `:207` passe exclusivement par `ctx.css(CSS_ID, CSS)`, c'est-à-dire `cssOnce` (`registry.js:13-19`) ; `:241` expose l'identifiant dans `filters.dataset.pointsE039Css`.
- **Solution** : une seule feuille, injectée une fois par la coque, sans effet hors de `.points-filters`. Aucune animation, aucune transition utile, aucun `!important` : le mouvement réduit est respecté par construction.
- **Impact** : le greffon n'altère ni la matrice, ni le détail, ni les autres vues ; la surcharge CSS reste nulle et le rendu 390×844 n'est pas perturbé.
- **Effort** : S
- **Vérification** : relecture — un seul `ctx.css(`, un seul `const CSS`, aucun sélecteur hors préfixe `points-e039-` / `.points-filters` ; émuler `prefers-reduced-motion: reduce` : aucune transition active.

## E039-02 — Marquage non destructif des contrôles, clé de focus durable

- **Preuve** : `mark()` (`E039.js:83-88`) écrit `data-points-e039-role` et `data-points-e039-index` sur un nœud existant et ne pose `data-fk` que si le contrôle n'en a déjà pas (`:87`). `:220-227` applique ce marquage aux deux `<select>` (`:222-223`), au bouton de réinitialisation (`:224`) et à chaque `.points-cell` (`:225-227`). Aucun contrôle natif n'est retiré, remplacé ou recréé.
- **Solution** : les attributs propres sont réécrits à chaque `install()` ; ils survivent logiquement au `innerHTML = ''` de la coque parce qu'ils sont retrouvés sur le DOM neuf. La clé `data-fk` (`:36`) est lue par `captureFocusKey()` / `findByKey()` de la coque (`shell.js:188-191`, `:240-244`) : le mécanisme natif de restauration devient lui aussi capable de retrouver les selects.
- **Impact** : le focus n'est plus perdu même quand la coque restaure seule, et les marquages de E013 (`aria-label` du bouton) et E035 (raccourcis) restent intacts.
- **Effort** : S
- **Vérification** : relecture — `setAttribute` uniquement, aucun `remove()` de contrôle natif ; harnais : après filtrage, le nouveau `<select>` porte `data-points-e039-role="domain"` et `data-fk="points-e039-domain"`.

## E039-03 — Capture synchrone de l'intention avant le re-render asynchrone

- **Preuve** : `E039.js:56` déclare `pending` dans l'état de module (donc survivant au re-render). `onFilterChange()` (`:105-110`) et `onFilterClick()` (`:112-115`) écrivent `{ role, index }` dans `pending` ; le commentaire `:103-104` documente que cette capture est synchrone, donc antérieure au `import().then(set())` de `points.js`. Les écouteurs sont liés par délégation sur `.points-filters` (`:234-237`) via `bindOnce()` (`:126-130`).
- **Solution** : le gestionnaire natif de `points.js` reste seul maître de l'état et du filtrage ; E039 ajoute un écouteur d'observation, pas un gestionnaire concurrent. L'intention est mémorisée dans la même tâche que l'événement, avant que la promesse d'import ne déclenche le rendu.
- **Impact** : aucune course entre la capture et la reconstruction ; le filtre s'applique exactement comme sans la lentille, et le focus peut être restauré sur le bon contrôle.
- **Effort** : M
- **Vérification** : relecture — aucun `preventDefault`/`stopPropagation` dans les gestionnaires E039 ; rejeu : changer le domaine au clavier → `pending` vaut `domain` avant le rendu.

## E039-04 — Restauration au sélecteur de domaine

- **Preuve** : `E039.js:222` marque le premier `<select>` de `.points-filters` avec le rôle `domain` et l'index `0` ; `:105-109` capture ce rôle sur l'événement `change` ; `:134-142` retrouve le nœud équivalent dans le DOM neuf par comparaison d'attributs ; `:177` appelle `target.focus({ preventScroll: true })`.
- **Solution** : l'équivalence est établie par rôle + index, pas par valeur de filtre ni par texte d'option (la valeur change justement pendant le filtrage). Le focus revient au même contrôle, dans le même ordre de tabulation.
- **Impact** : un utilisateur au clavier qui filtre par domaine reste immédiatement sur le sélecteur de domaine et peut enchaîner un second choix sans retouche à la souris.
- **Effort** : S
- **Vérification** : relecture des `:222` / `:105-109` / `:177` ; harnais : focus sur le 1ᵉʳ `<select>`, changer sa valeur, laisser le rendu se faire → `document.activeElement` est le nouveau 1ᵉʳ `<select>`.

## E039-05 — Restauration au bouton « Réinitialiser les filtres »

- **Preuve** : `findReset()` (`E039.js:70-79`) retrouve le bouton natif par `data-points-e039-role="reset"`, puis par le libellé `/r[eé]initialiser/i` (`:76`), avec repli sur le dernier bouton (`:78`) — même stratégie que `E013.js:61-70`. `:224` le marque, `:112-115` capture le clic, `:177` rend le focus au bouton neuf.
- **Solution** : le bouton n'est jamais dupliqué ; E039 s'appuie sur celui de `points.js:85-91` et sur le marquage déjà posé par E013. Aucun `aria-label` ni `title` n'est réécrit par E039, ce qui évite tout conflit d'étiquetage.
- **Impact** : après une réinitialisation, le focus reste sur la commande de réinitialisation plutôt que de tomber sur la scène ; l'annonce de E013 reste la seule source sonore, sans doublon.
- **Effort** : S
- **Vérification** : relecture — aucun second bouton créé, aucun `aria-label` posé par E039 ; harnais : clic (ou Entrée) sur le bouton → focus sur le bouton du DOM neuf, une seule annonce dans la live de E013.

## E039-06 — Restauration au sélecteur de famille

- **Preuve** : `E039.js:223` marque le second `<select>` avec le rôle `family` et l'index `1` ; `:105-109` accepte explicitement ce rôle au même titre que `domain` ; la recherche (`:134-142`) et le focus (`:177`) sont partagés, sans branche spécifique.
- **Solution** : le même chemin générique sert les deux selects ; seule la donnée de marquage change. Aucune valeur de famille n'est codée en dur : l'index `1` est dérivé de l'ordre réel des `<select>` dans `.points-filters`.
- **Impact** : le filtrage par famille, souvent enchaîné après le domaine, conserve lui aussi le point de tabulation de l'utilisateur.
- **Effort** : S
- **Vérification** : relecture — absence de libellé de famille littéral ; harnais : focus sur le 2ᵉ `<select>`, changer sa valeur → focus sur le nouveau 2ᵉ `<select>`, compteur « famille » incrémenté de un.

## E039-07 — Filtrage par cellule : restauration sans écouteur par cellule

- **Preuve** : le clic sur une `.points-cell` filtre par domaine (`points.js:49-53`) ; `onGridClick()` (`E039.js:119-124`) capte l'intention `cell` + index, et `bindOnce()` ne pose qu'un seul écouteur sur `.points-grid` (`:238`). `:225-227` marque chaque cellule avec son index row-major. Le commentaire `:117-118` documente explicitement le choix de la délégation.
- **Solution** : un seul écouteur couvre toute la matrice, y compris les 784 cellules du résumé de couverture ; la cible est retrouvée par son index stable dans la grille reconstruite.
- **Impact** : le filtrage depuis la matrice ne laisse pas le focus sur une cellule détruite ; le coût d'écoute reste constant quel que soit le nombre de cellules.
- **Effort** : M
- **Vérification** : relecture — un seul `addEventListener('click')` sur la grille, aucun dans la boucle de marquage ; harnais : focus sur une cellule, clic → focus sur la cellule de même index après rendu.

## E039-08 — Ciblage sûr et garde anti-vol de focus

- **Preuve** : `findTarget()` (`E039.js:134-142`) **compare** les attributs au lieu d'interpoler un sélecteur CSS : aucune donnée externe ne peut devenir un sélecteur. `restoreFocus()` (`:161-179`) vérifie `layout.isConnected` (`:164`), la présence d'une cible non désactivée (`:166`), et refuse de reprendre le focus si l'utilisateur est déjà sur un contrôle non marqué de la vue (`:170-176`). `record()` (`:149-157`) ne s'écrit que dans des `dataset` et un paragraphe de métriques, jamais dans une région live.
- **Solution** : la restauration est conditionnelle, pas autoritaire : elle agit seulement si le focus a réellement été perdu (corps, `#atlas-stage`, ou nœud déconnecté), ou si la coque a posé le focus sur un équivalent approximatif portant un attribut E039.
- **Impact** : aucun vol de focus quand l'utilisateur a quitté la vue, quand une modale est ouverte ou quand il a déjà déplacé le focus lui-même ; aucun bavardage sonore ajouté à E013/E015.
- **Effort** : M
- **Vérification** : relecture des `:164`, `:166`, `:170-176` ; harnais : (a) focus sur un bouton non marqué après filtrage → focus inchangé ; (b) navigation vers une autre vue → aucune restauration.

## E039-09 — Rejeu différé après `manageFocus`, avec garde anti-course

- **Preuve** : `E039.js:159-161` documente que la micro-tâche s'exécute après `manageFocus()` (`shell.js:562`) ; `:245-255` la planifie avec `queueMicrotask` (repli `Promise.resolve().then`, `:253`). `generation` (`:57`, incrémenté en `:208`) est capturée au moment du rejeu (`:248`) et comparée en `:162` : un rendu plus récent annule la restauration. L'usage de `queueMicrotask` est un motif déjà employé dans le dépôt (`chronology/E05.js:367` pour une restauration de focus).
- **Solution** : différer d'une micro-tâche — et non d'un timer — garantit que le rejeu intervient après la restauration synchrone de la coque, sans `setTimeout` ni rAF. La génération évite de restaurer sur un DOM périmé.
- **Impact** : le focus n'est pas écrasé par la coque, même pour les `<select>` que `findBySignature()` ne retrouve pas ; une navigation rapide ne produit pas de focus fantôme.
- **Effort** : M
- **Vérification** : relecture — absence de `setTimeout`/`setInterval`/`requestAnimationFrame` ; harnais : filtrer puis immédiatement changer de vue → `restoreFocus` sort en `:164`/`:162`, aucun focus volé.

## E039-10 — Compteurs auditables, signaux DOM, idempotence et propreté

- **Preuve** : `writeMetrics()` (`E039.js:144-147`) affiche « Focus restauré : N · domaine … · famille … · réinitialisation … · cellule … » dans `#points-e039-metrics` ; `record()` (`:149-157`) incrémente `restores`, un compteur par rôle et écrit `layout.dataset.pointsE039Last` (`:153`) ainsi que `filters.dataset.pointsE039Restores` (`:155`). `:240-243` exposent `data-points-e039=ready`, le CSS utilisé et le compteur. `ensureNodes()` (`:181-202`) retire tout nœud mal parenté puis le réinsère, sans doublon ; `bindOnce()` (`:126-130`) garantit un seul écouteur par conteneur ; `:258` enregistre exactement `register('E039', install)`.
- **Solution** : les nœuds sont des enfants de `.points-filters` (`:188`, `:200`), jamais des enfants directs de `layout` : `_diagnostics.js:69-79` ne les marque donc pas et ne les déplace pas dans le tiroir. Le compteur est un texte visible, hors région live, donc vérifiable sans instrumentation.
- **Impact** : aucune duplication après navigation aller-retour, aucune fuite d'écouteur, aucune écriture redondante dans une live region ; `node --check` passe et aucun appel interdit n'apparaît hors commentaires.
- **Effort** : M
- **Vérification** : relecture des invariants d'en-tête (`:20-28`) ; `node --check src/views/points/E039.js` → PASS ; rendu → filtrer → navigation aller-retour → rendu : un seul `#points-e039-metrics`, un seul `#points-e039-hint`, compteurs cohérents.

Les dix chantiers E039-01 à E039-10 sont implémentés dans `src/views/points/E039.js` uniquement. CSS injecté via `ctx.css('points-e039', …)`. Aucun fichier partagé modifié, aucun gestionnaire natif de filtre remplacé, aucune annonce sonore ajoutée.

## Blocages / limites inter-domaines

- E039 n'empêche pas la reconstruction du DOM par la coque (`shell.js:533`) : il rejoue le focus **après** (`E039.js:245-255`). Toute modification de l'ordre `runEnhancements` / `manageFocus` dans `shell.js` reste compatible, la micro-tâche étant différée.
- Les `<select>` ne sont pas dans `focusCandidates()` (`shell.js:223-227`) : la coque seule ne restaure pas ces contrôles par signature. E039 comble ce vide par ses attributs propres et la clé `data-fk` (`E039.js:36`, `:83-88`).
- Aucune région live n'est créée : E013 porte l'annonce de réinitialisation et E015 le nombre de résultats. E039 se limite au déplacement du focus, par choix de non-bavardage.
- L'état `pending`, `generation` et `counts` est volatile, en mémoire de module : il ne survit pas à un rechargement de page (aucune persistance demandée, hors contrat de lentille).
- Le filtrage par cellule repose sur l'ordre des `.points-cell` (`:225-227`). Si une autre lentille réordonne la grille entre le clic et le rendu, l'index pourrait viser une autre cellule ; la garde `:166` reste silencieuse si la cible n'existe plus.
- La clé `data-fk` posée sur les contrôles (`:222-224`) est lue par la coque (`shell.js:190`) : toute lentille qui réécrirait cet attribut sur les mêmes nœuds devrait le préserver.
