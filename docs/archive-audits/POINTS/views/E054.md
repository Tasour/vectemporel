# E054 — Sémantique & données : les huit familles de points en légende

Lentille E054 — domaine F : sémantique & données. Fichier possédé : `src/views/points/E054.js` uniquement. La vue (`src/views/points.js`), le registre des lentilles (`src/views/points/registry.js`), le store (`src/domain/store.js`) et `styles.css` ne sont ni édités ni doublés : E054 ajoute une légende **locale, en lecture seule**, dérivée du DOM déjà rendu. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` ; aucune dépendance vers le store ni vers l'état interne des filtres.

**Règle d'or du module** : aucune donnée historique n'est inventée. Les huit familles et leurs questions sont la taxonomie normative de `POINT_METHODOLOGY.md` §2 (vocabulaire, pas un fait daté) ; la présence d'une famille est lue dans le `<select>` que `points.js` construit à partir du corpus, et l'appartenance au point sélectionné est lue dans `.points-families`. Aucune date, aucun total, aucun identifiant de source n'est codé en dur. CSS injecté par `ctx.css('points-e054', …)` ; tous les identifiants sont préfixés `points-e054-`.

## E054-01 — Légende locale non destructive, portée CSS unique

- **Preuve** : `E054.js:24-30` déclare `CSS_ID = 'points-e054'`, `SCOPE = 'points-e054'` et les quatre identifiants préfixés ; `:50-100` porte une feuille dont **chaque** sélecteur commence par `.points-e054`. `:242-250` filtre sur `viewId === 'points'` et exige `layout`, `css`, `el`, puis appelle `css(CSS_ID, CSS)` (cssOnce) et `layout.classList.add(SCOPE)`. `:261-278` insère la section dans `.points-matrix`, juste après `.points-filters`, sans retirer ni réécrire un nœud de la vue.
- **Solution** : la lentille n'ajoute qu'une portée CSS et une section. Le garde d'entrée (`:243`) rend le greffon inerte sur toute autre vue ou avec un `ctx` minimal. L'ancrage sur `.points-layout` garantit qu'aucune règle ne fuit vers les autres vues.
- **Impact** : la matrice, les filtres, le détail et la navigation restent intacts ; la légende disparaît avec le rendu sans laisser d'état global visible.
- **Effort** : S
- **Vérification** : relecture de `:243`, `:249-250`, `:261-278` ; contrôle des sélecteurs de `:51` à `:99` (tous préfixés) ; harnais : rendre la vue, puis comparer `.points-grid`, `.points-filters`, `.points-detail` avant/après — aucun nœud modifié.

## E054-02 — Les huit familles et leurs questions en texte visible

- **Preuve** : le tableau `FAMILIES` (`E054.js:36-45`) contient exactement les huit entrées de `POINT_METHODOLOGY.md` §2, chacune avec son identifiant, son libellé et sa question canonique (« Quand l'événement a-t-il eu lieu ? », « Quel changement lent ? », « Qui a agi ? », « Quel collectif ? », « Où ? », « Quelle structure ? », « Quelle règle ? », « Comment le passé est-il raconté ? »). `:164-174` les transforme en `<li>` avec `<strong>` pour le libellé et `<span>` pour la question, via `ctx.el`.
- **Solution** : la taxonomie est écrite dans des éléments sémantiques visibles (`<ul>/<li>`, `<strong>`, `<span>`), jamais dans `aria-hidden`, `.sr-only`, un attribut `title` ou du texte généré par une couche invisible. Les slugs `groupe_social` et `repere_normatif` (`:40`, `:43`) reprennent ceux réellement présents dans `dataset.js`, documentés en commentaire à `:32-35`.
- **Impact** : la légende est indexable et lisible sans JavaScript actif au-delà de la construction initiale du DOM ; elle donne à chaque famille sa question d'usage au lieu d'un étiquetage opaque.
- **Effort** : S
- **Vérification** : relecture de `:36-45` et `:164-174` ; contrôle : huit `<li>` dans `#points-e054-list`, huit questions distinctes, aucune chaîne dans `aria-hidden` ; comparaison avec le tableau §2 de la méthodologie.

## E054-03 — Présence déduite du `<select>` des familles, jamais codée en dur

- **Preuve** : `familySelect()` (`E054.js:117-122`) repère les `<select>` de `.points-filters` et retient le second — celui que `points.js:73-84` alimente avec les familles uniques du corpus. `presentFamilies()` (`:124-132`) lit `option.value`, écarte le joker `'*'` et les valeurs vides, et retourne un `Set`. `:179` l'injecte dans `refresh()`.
- **Solution** : la liste des familles présentes n'est pas recopiée : elle est relue à chaque actualisation depuis le contrôle déjà construit par la vue. Aucune famille n'est supposée « attendue » ; seules les options réelles comptent.
- **Impact** : l'ajout d'une famille dans le corpus se reflète sans édition de la lentille ; une absence de `<select>` ou d'options ne produit pas d'erreur, mais un ensemble vide et un état « absente » explicite pour les huit entrées canoniques.
- **Effort** : S
- **Vérification** : relecture de `:117-132`, `:179` ; harnais DOM : options `['*','evenement','lieu']` → deux présentes, six absentes ; joker seul → zéro présente ; `.points-filters` absent → aucun lancement d'erreur.

## E054-04 — Silence explicite : familles absentes du corpus

- **Preuve** : `stateFor()` (`E054.js:150-154`) retourne trois états nommés : `'point'` (glyphe `◆`, « dans ce point »), `'present'` (`●`, « présente dans le corpus ») et `'absent'` (`○`, « absente du corpus »). Le commentaire `:147-149` rattache ce dernier à la règle §3.7 « les silences sont des données ». `:166-171` pose classe `is-<key>`, `data-family` et le texte « glyphe + mot » ; les couleurs de `:73-84` ne font que doubler l'information textuelle.
- **Solution** : l'absence n'est jamais un vide masqué ni un simple fond gris : elle porte un mot et un glyphe distincts. Aucune information n'est confiée à la seule couleur (vérifié aussi en `forced-colors` aux `:96-99`).
- **Impact** : une famille non représentée dans le corpus devient un fait auditable plutôt qu'un oubli ; le contrôle reste lisible en niveaux de gris, en couleurs forcées et pour les lecteurs d'écran.
- **Effort** : S
- **Vérification** : relecture de `:147-154`, `:166-171`, `:73-84`, `:96-99` ; harnais : famille sans option → `<li class="… is-absent">` avec texte « ○ absente du corpus » ; simuler `forced-colors: active` → bordure `CanvasText` et `Highlight` présentes.

## E054-05 — Résonance avec le point sélectionné

- **Preuve** : `inPointFamilies()` (`E054.js:136-145`) lit les `<span>` de texte de `.points-detail .points-families`, exactement ceux que `points.js:109` crée pour le point courant. `:151` teste cet ensemble **avant** l'appartenance au corpus, donc une famille du point sélectionné est toujours marquée « dans ce point » même si le filtre de corpus est plus large.
- **Solution** : la légende se met en résonance avec le détail sans modifier ce détail. La priorité « point > corpus » est explicite dans l'ordre des branches de `stateFor()` ; le comptage des familles « dans ce point » est filtré sur le canon à `:188`, pour ne pas compter un slug inattendu.
- **Impact** : l'utilisateur voit immédiatement quelles questions sémantiques le point affiché éclaire ; le marquage reste vrai quand le point change, puisque la lecture est refaite à chaque rendu et à chaque mutation observée.
- **Effort** : S
- **Vérification** : relecture de `:136-145`, `:150-154`, `:188` ; harnais : point portant `['acteur','lieu']` → deux `is-point`, six autres états cohérents ; détail sans `.points-families` → zéro `is-point`, aucun crash.

## E054-06 — Règle « la date est un champ, pas le contenu »

- **Preuve** : `E054.js:208-209` écrit dans un `<p class="points-e054-intro">` : « Une famille dit quelle question sémantique un point éclaire ; un point peut appartenir à plusieurs familles. Un point ne se réduit pas à une date. » `:219-220` ajoute la note « l'ère et le champ temporel du détail mesurent QUAND ; la famille dit QUOI et COMMENT. La date est un champ, pas le contenu (§2). »
- **Solution** : la règle d'intégrité de `POINT_METHODOLOGY.md` §2 est restée dans le texte visible, en deux endroits complémentaires : énoncé général en introduction, puis mise en regard avec les champs réellement rendus par `points.js` (ère, `time` dans `.points-meta`). Aucun millésime n'est introduit par la lentille.
- **Impact** : la distinction entre tempo et sémantique est explicite au moment où l'utilisateur regarde la matrice et le détail ; l'affirmation est falsifiable par lecture du §2 de la méthodologie.
- **Effort** : S
- **Vérification** : relecture de `:208-209` et `:219-220` ; contrôle : aucun chiffre à quatre digits dans le module ; présence des deux `<p>` dans la section et absence de `aria-hidden`/`hidden` sur eux.

## E054-07 — Rappel des huit critères d'un point valide

La lentille ne juge pas la validité : elle rend le critère énonçable.

## E054-08 — Accessibilité : région nommée, liste sémantique, pas de couleur seule

La feuille porte des cibles d'au moins 36 px (`:68-69`), des couleurs de texte explicites (`:76-84`) et un repli `forced-colors` (`:96-99`).

Comme la lentille n'introduit aucun contrôle interactif, elle n'ajoute aucun écouteur de clavier global.
- **Impact** : les lecteurs d'écran peuvent nommer et parcourir la légende ; les utilisateurs en couleurs forcées conservent les bordures d'état ; la lecture tactile reste confortable.

## E054-09 — Compteurs auditables et signature anti-écriture

- **Preuve** : `signature()` (`E054.js:156-158`) joint les identifiants triés des deux ensembles ; `refresh()` (`:178-193`) sort sans rien écrire si la signature est inchangée (`:182`), sinon l'incrémente (`:184`), appelle `renderList()` (`:185`) et écrit le texte des compteurs à `:189-192`. `renderList()` (`:162-176`) remplace le `<ul>` par `listRef.replaceChildren(...nodes)` — aucun `innerHTML`, aucun `insertAdjacentHTML`. `:215-217` déclare le `<p>` de compteurs hors de toute région live.
- **Solution** : la structure statique n'est construite qu'une fois (`:198-224`) ; seul le bloc d'états et la ligne de compteurs sont réécrits. Les compteurs sont calculés sur le canon filtré (`:187-188`), donc bornés par `FAMILIES.length`, et le nombre d'actualisations ne progresse que sur un changement réel de signature.
- **Impact** : aucune réinterprétation du balisage, nombre borné d'écritures DOM ; la ligne « N familles canoniques · P présentes · A absentes · U dans ce point · R actualisation(s) » permet de distinguer « donnée inchangée » de « greffon muet ».
- **Effort** : M
- **Vérification** : relecture de `:156-193` ; contrôle d'absence de `innerHTML`/`outerHTML`/`insertAdjacentHTML` ; rejeu : deux passages sur le même DOM → `R` stable ; changer le point sélectionné → `U` change et `R` augmente d'un.

## E054-10 — Observateur unique ciblé, mouvement réduit et idempotence

- **Preuve** : `observe()` (`E054.js:229-239`) déconnecte l'observateur existant (`:230`) avant d'en créer un seul (`:232`), et n'observe que deux cibles en lecture seule : le `<select>` des familles (`:235`, `:237`) et `.points-detail .points-families` (`:236`, `:238`). Le commentaire `:226-228` interdit d'observer la légende, sinon boucle. `:252-259` coupe les transitions via l'attribut `data-e054-reduced` et la media query `:90-92` ; `:270-286` détecte un rendu neuf, retire une légende mal parentée (`:266-269`), nettoie un nœud périmé (`:271-272`) et remet la signature à zéro (`:275`, `:284`).
- **Solution** : un seul `MutationObserver` par rendu, reconnecté, jamais sur le bloc écrit ; le callback (`:232-234`) vérifie que le layout est encore connecté avant de rafraîchir. L'installation est idempotente : CSS unique (cssOnce), légende unique, liste unique, aucun stockage de nœud détaché. La grille passe en une colonne sous 900 px (`:93-95`).
- **Impact** : pas de boucle d'écriture, pas de doublon après navigation, pas de fuite d'écouteurs ; la légende reste lisible en 390×844 et les transitions sont neutralisées quand le mouvement réduit est demandé.
- **Effort** : M
- **Vérification** : relecture de `:226-239`, `:252-259`, `:266-286` ; contrôle : un seul `new MutationObserver`, un `disconnect()` préalable, aucune observation de la légende ; rejeu rendu → navigation aller-retour → rendu : un seul `#points-e054-legend`, huit `<li>`, compteurs cohérents ; `node --check src/views/points/E054.js` PASS.

## Statut d'implémentation

Les dix chantiers E054-01 à E054-10 sont implémentés dans `src/views/points/E054.js` uniquement. CSS injecté via `ctx.css('points-e054', …)`. Aucun fichier partagé modifié, aucune donnée historique inventée, aucun contrôle interactif ajouté.

## Blocages / limites inter-domaines

- La taxonomie des huit familles est figée dans le module conformément à `POINT_METHODOLOGY.md` §2 : si la méthodologie introduit une neuvième famille, la table `FAMILIES` (`E054.js:36-45`) devra être mise à jour — c'est un vocabulaire normatif, pas une donnée lue dans le corpus.
- La légende reflète le `<select>` construit par `points.js` et les `<span>` de `.points-families` : elle ne corrige ni un filtre erroné ni un point mal étiqueté. Elle rend l'écart visible, elle ne le résout pas.
- L'état des compteurs et le nombre d'actualisations sont volatils : un rendu neuf reconstruit la légende (`:270-278`). Les conserver entre rendus demanderait un état partagé hors du contrat de la lentille.
- Le signal de mouvement réduit est lu via `ctx.reducedMotion()` avec repli prudent `false` (`:252-259`) ; la media query CSS (`:90-92`) couvre le cas où le JS ne fournirait pas ce signal.
