# E056 — F. Sémantique & données — omission de source explicite (ID d'omission)

Lentille E056 — domaine F : sémantique & données. Fichier possédé : `src/views/points/E056.js` uniquement. La vue (`src/views/points.js`), le store, la coque, `styles.css` et les autres lentilles ne sont ni édités ni doublés. Le défaut visé est précis : `points.js:110` n'écrit `.points-sources` **que si** `selected.sources.length` est non nul. Un point sans source produit donc un vide silencieux dans la fiche, ce qui contredit `POINT_METHODOLOGY.md` §3.7 (« les silences sont des données : `aucune source` doit être explicite, jamais un vide masqué ») et §9 (« dire "sans source" sans ID d'omission » est interdit). E056 ajoute un **registre LOCAL, non modal** dans `.points-detail` qui qualifie explicitement le statut des sources : source réelle (`SRC-…`), ID d'omission déclaré (`OM-…`) ou silence sans ID dédié. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` (tels que fournis par `points/registry.js`) ; le ctx de cette vue n'expose **pas** `say()` (`points.js:126`), donc aucune région live n'est ajoutée. CSS injecté par `ctx.css('points-e056', …)`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`, aucun fichier partagé touché.

## E056-01 — Registre local non modal, additive et sans conflit de diagnostic

- **Preuve** : `E056.js:250-267` construit une unique `<section id="points-e056-ledger" role="region" aria-labelledby="points-e056-title" tabIndex=-1>` avec un `<h3>`, un paragraphe de synthèse, une liste et un compteur ; `E056.js:294-308` le recherche par id, le reloge si son parent n'est pas le détail, et ne l'insère que dans `.points-detail` (`currentDetail.appendChild(ledger)`, `:308`). La feuille `E056.js:34-69` est injectée par `ctx.css(CSS_ID, CSS)` (`:281`). Le commentaire `:30-33` documente le choix du parent : `_diagnostics.js:69-78` ne marque que les nœuds dont le parent est `body`, `stage` ou `layout` ; le registre est enfant de `.points-detail`, il échappe donc au tiroir de diagnostic. Aucun `role=dialog`, aucun `aria-modal`, aucun piège de focus.
- **Solution** : ajout purement additif en fin de fiche, après `.points-justification` / `.points-nav` tels que rendus par `points.js:110-122`. Le registre ne remplace ni `.points-sources` ni le bouton « Réinitialiser » ; il ne supprime aucun nœud de la vue. L'en-tête `:6-10` l'énonce explicitement.
- **Impact** : la fiche reste complète et lisible ; l'omission devient visible au même endroit que la source manquante, sans modifier le rendu d'origine ni les chantiers voisins (E030 ancre de retour, E029 nav de point).
- **Effort** : M
- **Vérification** : relecture — aucun `remove()` sur un nœud de `points.js`, aucun `replaceChildren` sur le détail, parent du registre = `.points-detail` ; harnais DOM : nombre d'enfants propres à `points.js` identique avant/après, plus un seul `#points-e056-ledger`, absent du tiroir de diagnostic.

## E056-02 — Lecture défensive, zéro dépendance au store ou au jeu de données

- **Preuve** : le module n'importe que `register` (`E056.js:1`). L'en-tête `:12-14` declare : « Aucune dépendance vers le store, le routeur, le jeu de données ou une autre lentille : tout est dérivé du DOM déjà rendu par points.js. » `root()` (`:83-89`) exige un `ctx.layout` connecté, avec repli sur `ctx.stage` ; `qs()` (`:91-93`) et `text()` (`:95-97`) tolèrent un nœud absent ; `install()` sort si `.points-detail` manque (`:275-277`). `analyze()` (`:118-143`) ne lit que `.points-point-title`, `.points-sources`, `.points-justification` et `.points-meta .confidence`.
- **Solution** : aucune importation de `dataset.js`, `store.js` ou d'une autre lentille. Si un sélecteur disparaît lors d'une évolution de `points.js` (fichier non possédé), la lentille continue avec un libellé de repli au lieu de lever une exception neutralisée par le registre.
- **Impact** : le registre reste vrai quand le jeu de données évolue, et ne dépend d'aucun état applicatif : il décrit ce que la fiche affiche réellement.
- **Effort** : S
- **Vérification** : relecture de `:1`, `:12-14`, `:83-97`, `:275-277` ; harnais : ctx sans `layout`, puis détail sans `.points-sources`, puis sans `.points-justification` → aucune exception, libellés de repli présents.

## E056-03 — Classification des jetons de source `SRC-` / `OM-`, sans invention

- **Preuve** : `tokens()` (`E056.js:103-112`) collects les jetons par `String.match` avec déduplication via `pushUnique()` (`:99-101`) ; `analyze()` (`:127-137`) applique `/\bSRC-\d+\b/g` au texte de `.points-sources` et en déduit le tableau `real`, puis `/\bOM-\d+\b/g` pour les omissions déclarées. Le commentaire `:103-105` interdit explicitement tout ID fabriqué : seuls les jetons réellement rendus sont cités. Le mode est calculé en `:133-137` (`vide`, `source`, `omission`, `silence`).
- **Solution** : la sémantique est dérivée du texte affiché (`points.js:110` écrit `Sources : …` à partir de `selected.sources`). Un ID `OM-002` est reconnu comme une **omission documentée**, pas comme une référence bibliographique ; aucun millésime, auteur, DOI ou identifiant nouveau n'est introduit.
- **Impact** : la distinction « source réelle » / « ID d'omission » devient vérifiable par simple lecture du registre, et reste fidèle au corpus (registre `SRC-…` + fichiers `omissions.yaml`).
- **Effort** : S
- **Vérification** : relecture de `:99-112`, `:127-137` ; harnais : `Sources : SRC-001, OM-002` → 1 source réelle + 1 omission déclarée ; `Sources : OM-002` → mode `omission` ; aucun ID littéral codé en dur dans le module.

## E056-04 — Silence masqué converti en donnée explicite

- **Preuve** : `points.js:110` conditionne l'existence de `.points-sources` à `selected.sources.length`. Quand le nœud manque, `sourcesText` vaut `''` (`E056.js:125`), aucun jeton n'est trouvé (`:127-130`) et le mode devient `silence` (`:137`). `summaryOf()` (`:156-169`) écrit alors : « aucune source ni ID d'omission déclaré : le silence est rendu explicite, non masqué. » (`:168`) ; `linesOf()` (`:176-178`) ajoute la ligne « ID d'omission : aucun dans les données rendues — omission explicite sans ID dédié. »
- **Solution** : le vide n'est plus un absent silencieux mais un état nommé, affiché dans la fiche. Le message est strictement indicatif : il ne prétend pas qu'aucune histoire n'existe, seulement qu'aucune source n'est déclarée dans les données rendues.
- **Impact** : conformité avec la règle 7 de la méthodologie (§3.7) ; un lecteur voit immédiatement que l'absence de source est un constat audité, et non un oubli d'affichage.
- **Effort** : S
- **Vérification** : relecture de `:125`, `:137`, `:156-169`, `:176-178` ; harnais : retirer `.points-sources` d'une fiche → synthèse « silence explicite » et ligne « omission explicite sans ID dédié » ; remettre un `SRC-001` → retour au mode `source`.

## E056-05 — ID d'omission déclaré distingué des IDs simplement mentionnés

- **Preuve** : `analyze()` (`E056.js:129-130`) sépare `declared` (jetons `OM-` du champ Sources) de `mentioned` (jetons `OM-` de la justification, filtrés de `declared`). `linesOf()` (`:174-175`) les affiche avec deux libellés distincts : « IDs d’omission déclarés » et « IDs d’omission mentionnés dans la justification ». Le commentaire `:114-117` justifie la séparation par le cas réel d'une référence croisée erronée discutée dans la justification.
- **Solution** : ne pas confondre « la source du point est un ID d'omission » avec « la justification cite un ID d'omission à propos d'une autre ère ». Les deux informations restent visibles mais étiquetées selon leur portée exacte.
- **Impact** : aucune affirmation trompeuse sur l'appartenance d'un ID d'omission au point courant ; le registre reste falsifiable par relecture de la justification affichée.
- **Effort** : M
- **Vérification** : relecture de `:114-117`, `:129-130`, `:174-175` ; harnais : justification contenant « OM-003 concerne l'ère 3 » sans `OM-003` dans Sources → ligne « mentionnés », aucune ligne « déclarés ».

## E056-06 — Omission sans ID dédié énoncée, jamais comblée par un identifiant inventé

- **Preuve** : `explicitNoId` (`E056.js:131`) détecte dans la justification les formulations « aucun ID d'omission » / « sans ID d'omission » ; `linesOf()` (`:179-181`) affiche alors : « elle déclare explicitement l'absence d'ID d'omission dédié. » Le commentaire `:153-155` rappelle les paragraphes §3.7 et §9 de `POINT_METHODOLOGY.md`. La règle affichée en `:183` reprend « les silences sont des données : aucun vide masqué, aucune source ni ID inventé. »
- **Solution** : quand le corpus ne fournit pas d'ID d'omission (cas fréquent documenté dans `dataset.js`), la lentille **dit** qu'il n'y en a pas, au lieu d'en forger un. C'est cette explicitation — et non un identifiant fictif — qui satisfait l'interdiction de « dire sans source sans ID d'omission » : le silence est documenté, donc traité comme une donnée.
- **Impact** : aucune invention d'ID, de date, d'auteur ou de DOI ; la dette documentaire reste une dette visible, prête à être instruite par les agents d'ère.
- **Effort** : S
- **Vérification** : relecture de `:131`, `:153-155`, `:179-183` ; contrôle : aucun motif de génération d'ID (pas de compteur converti en `OM-…`, pas de `Math.random`) ; harnais : justification avec « aucun ID d'omission dédié » → ligne dédiée et aucun jeton `OM-` affiché.

## E056-07 — Signature anti-écriture redondante et compteurs auditables

- **Preuve** : `signatureOf()` (`E056.js:145-151`) compose la signature depuis le mode, le titre, les jetons, l'absence d'ID, la certitude, le texte des sources et la justification. `refresh()` (`:213-224`) calcule la signature, sort sans écrire si elle est identique à `lastSignature` (`:219`), sinon incrémente `writes` (et `silences` pour les modes `silence`/`omission`, `:222`) avant de rendre. `writeMetrics()` (`:187-191`) affiche « Écritures du registre : N · Silences rendus explicites : M. » avec garde `textContent` (`:190`).
- **Solution** : le registre n'est réécrit que lorsque son intrant change ; l'observateur (E056-08) peut donc se déclencher sans provoquer d'écriture en boucle. Les compteurs donnent une trace vérifiable hors toute région live (le ctx n'ayant pas de `say()`).
- **Impact** : nombre borné d'écritures DOM ; l'audit distingue « analyse sans changement » de « greffon muet » en comparant les compteurs avant/après une navigation de point.
- **Effort** : M
- **Vérification** : relecture de `:145-151`, `:187-191`, `:213-224` ; rejeu : ouvrir la vue (1 écriture), muter sans changer la signature (compteurs stables), changer de point (2 écritures, silences +1 si le nouveau point est un silence).

## E056-08 — Observateur unique ciblé, jamais braqué sur le registre écrit

- **Preuve** : `observe()` (`E056.js:226-248`) déconnecte l'observateur existant avant d'en créer un seul (`:229-234`), puis observe exactement quatre cibles en lecture seule : `.points-point-title`, `.points-sources`, `.points-justification`, `.points-meta` (`:235-240`). Le commentaire `:226-227` précise : « JAMAIS sur le registre (sinon boucle) ». Le callback ne fait qu'appeler `refresh(currentCtx, detail)` (`:234`).
- **Solution** : une cible par_signal de la fiche, avec `{ childList, characterData, subtree, attributes: ['class'] }` (`:241-247`) ; le registre et ses compteurs ne sont jamais observés. À chaque rendu, `install()` déconnecte puis reconnecte l'observateur sur les nouveaux nœuds (`:310`).
- **Impact** : pas de fuite d'écouteurs, pas d'auto-déclenchement ; le registre reste synchronisé avec la fiche sans risque de récursion.
- **Effort** : M
- **Vérification** : relecture — un seul `new MutationObserver`, un `disconnect()` préalable, aucune observation de `#points-e056-ledger` ni de `.points-e056-metrics` ; harnais : muter `.points-point-title` → mise à jour, muter le compteur → aucune mise à jour.

## E056-09 — Accessibilité : région nommée, libellés textuels et mouvement réduit

La feuille porte `:focus-visible` (`:43-45`), un `font-variant-numeric: tabular-nums` (`:50`, `:55`) et des libellés textuels (« Sources réelles », « IDs d’omission déclarés », « Silence explicite ») en `:173-183` : l'information n'est jamais portée par la seule couleur. `@media (prefers-reduced-motion: reduce)` neutralise la transition (`:60-62`) et `@media (forced-colors: active)` force `Canvas`/`CanvasText`/`Highlight` (`:63-68`). `install()` expose l'état via `data-e056-reduced` (`:284-288`) en interrogeant `ctx.reducedMotion()` dans un garde de type.

- **Impact** : le registre est annoncé comme région nommée, atteignable au clavier, lisible en 390×844 et sous forcage de couleurs ; le réglage système de mouvement est respecté sans contradiction.
- **Effort** : S

Un nœud déconnecté ou un détail différent signale un rendu neuf (`:290`) : `lastSignature` est remis à zéro (`:311`). Les signaux `data-e056` (`:283`) et `data-e056-reduced` (`:285`) sont préfixés. `register('E056', (ctx) => { install(ctx); })` est exact (`:315`).
- **Solution** : un seul CSS, un seul registre, un seul observateur par rendu ; aucun stockage de nœud périmé. Le module ne touche ni `.points-grid`, ni `.points-filters`, ni `.points-nav` : il ne fait qu'ajouter une région dans la fiche.
- **Impact** : pas de doublon après navigation aller-retour, pas de fuite d'écouteurs, aucune régression des 99 autres lentilles ; `node --check src/views/points/E056.js` passe.
- **Effort** : M

## Statut d'implémentation

Les dix chantiers E056-01 à E056-10 sont implémentés dans `src/views/points/E056.js` uniquement. CSS injecté via `ctx.css('points-e056', …)`. Aucun fichier partagé touché, aucun état applicatif modifié, aucun ID / millésime / auteur / DOI inventé. Le registre complète la fiche de `points.js` sans la remplacer : il explicite le statut des sources et l'omission lorsqu'aucune source n'est déclarée.

## Blocages / limites inter-domaines

- La lentille ne lit que le DOM : si `points.js` cessait d'écrire la certitude dans `.points-meta .confidence` ou la justification dans `.points-justification`, les libellés de repli s'activeraient sans erreur, mais la qualification précise serait perdue (fichier non possédé).
- Un ID d'omission mentionné dans une justification peut être une référence croisée concernant une autre ère : E056 l'étiquette « mentionné », jamais « déclaré ». Il ne tente pas de résoudre la justesse de cette référence (cela demanderait l'accès aux fichiers `omissions.yaml`, hors contrat).
- Quand aucun `OM-…` n'existe dans les données rendues, E056 énonce l'absence d'ID dédié. Attribuer un véritable ID d'omission de registre demanderait une modification de `source/audits/<pays>/omissions.yaml` et de `dataset.js`, deux fichiers non possédés.
- Le registre est volontairement non modal et sans région live : le ctx de la vue n'expose pas `say()` (`points.js:126`). Aucune annonce vocale n'est donc émise lors d'un changement de point ; l'information reste consultable dans le DOM.
