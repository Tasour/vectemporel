# E018 — B. Filtres & périmètre — combinaison domaine × famille ∩ ère cohérente

Lentille E018 du chantier POINTS (`/home/tasour/Projects/vectemporel-atlas`), en français.
Fichier possédé : `src/views/points/E018.js` uniquement. Aucun fichier partagé n'est édité : ni `src/views/points.js`, ni `src/views/points/registry.js`, ni le store, ni les données. Le contrat exploité est celui que `points.js:126` transmet à `runEnhancements` — `{ viewId, stage, layout, css, el, reducedMotion }` — plus le DOM déjà construit par `points.js:29-126` (`.points-layout`, `.points-matrix`, `.points-filters`, `.points-grid`, `.points-detail`). Le module ajoute UNE synthèse de périmètre : il rend lisible l'intersection **domaine × famille ∩ ère** et vérifie sa cohérence en croisant deux sources indépendantes déjà présentes dans le DOM — le compte du détail (`points.js:96`) et les titres des cellules de la matrice (`points.js:48`). Il ne modifie ni le texte, ni le `title`, ni les gestionnaires des contrôles d'origine. Un seul `register('E018', …)` (`E018.js:320`), un seul CSS via `ctx.css('points-e018', …)` (`E018.js:18`, `:297`), tous les identifiants préfixés `points-e018-`, zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`.

## E018-01 — Synthèse locale, non modale et non destructive

- **Preuve** : `summaryOf()` (`E018.js:207-236`) réutilise le nœud trouvé par `document.getElementById(SUMMARY_ID)` (`:208`), ne le retire que s'il est mal parenté (`:210`), sinon le crée avec `ctx.el('section', …)` (`:212`) et l'identifiant `points-e018-summary`. Il porte `role=region`, `aria-labelledby=points-e018-title`, `aria-describedby=points-e018-note` et `data-points-e018=summary` (`:214-217`). `apply()` l'ajoute dans `.points-filters`, avec repli sur `.points-matrix` (`E018.js:294-299`).
- **Solution** : aucun `dialog`, aucun `aria-modal`, aucun piège de focus, aucun `inert`. Le panneau est greffé à côté des filtres existants, sans toucher aux deux `<select>` ni au bouton de réinitialisation (`points.js:60-93`). Les paragraphes sont créés une fois (`:218-223`) ; seul leur contenu est remplacé ensuite.
- **Impact** : la lecture de la matrice et le parcours clavier des filtres restent intact ; l'information de périmètre est disponible au même endroit que les contrôles qui la produisent.
- **Effort** : S
- **Vérification** : relecture — aucun `role=dialog`, `aria-modal`, `hidden`, `inert` ; un seul `#points-e018-summary` après rendu ; les deux `<select>` et le bouton « Réinitialiser les filtres » conservent leurs attributs et gestionnaires d'origine.

## E018-02 — Combinaison domaine × famille ∩ ère lisible

- **Preuve** : `selectsOf()` (`E018.js:80-89`) identifie les deux `<select>` par leur `aria-label` (`points.js:62`, `:74`) avec repli sur leur ordre ; `dimensionLabel()` (`:117-121`) traduit `'*'` en « tous les domaines » / « toutes les familles ». `render()` (`:265-272`) écrit `domaine « X » × famille « Y » ∩ ère « Z »`.
- **Solution** : les trois dimensions sont affichées explicitement en texte visible, dans l'ordre de la formule du thème. Aucune valeur n'est codée en dur : tout provient de `.value` des selects et du libellé de l'ère active. Le `×` et le `∩` sont doublés d'une paraphrase dans la note `points-e018-note` (`:224-227`) pour ne pas dépendre d'un symbole.
- **Impact** : la personne qui lit peut vérifier d'un coup d'œil le périmètre réellement appliqué, y compris quand un filtre est neutre (`*`).
- **Effort** : S
- **Vérification** : relecture — aucun libellé de domaine, de famille ou d'ère littéral dans le module ; harnais : `(domaine=D, famille=*, ère=E)` puis `(domaine=*, famille=F, ère=E)` → deux phrases distinctes, chacune avec les trois dimensions.

## E018-03 — Cohérence dérivée du DOM, sans donnée inventée

- **Preuve** : `detailCountOf()` (`E018.js:152-156`) lit le premier entier du kicker `.points-detail > .view-kicker` écrit à `points.js:96` ; `cellTotalOf()` (`:130-149`) additionne les `N` des `title` de cellules (`points.js:48`). `verdictOf()` (`:161-175`) confronte les deux : `détail > cellule` → `incoherent`, `détail = 0` → `vide`, signal absent → `partiel` ou `inconnu`, sinon `coherent`.
- **Solution** : deux sources indépendantes sont comparées, aucune n'est remplacée par une supputation. Quand un domaine est sélectionné, seule la cellule `(ère active, domaine)` est lue ; sans domaine, toutes les cellules de la ligne sont additionnées. Le texte dit explicitement que la cellule ignore la famille.
- **Impact** : l'assertion est falsifiable — faire varier un filtre ou l'ère change le verdict ; une incohérence réelle entre le détail et la matrice devient visible au lieu d'être silencieuse.
- **Effort** : M
- **Vérification** : relecture — absence de nombre historique codé en dur ; harnais : détail 3 / cellule 5 → `coherent` ; détail 4 / cellule 2 → `incoherent` ; détail 0 → `vide` ; titre de cellule absent → `partiel`.

## E018-04 — Ère active résiliente à trois sources

- **Preuve** : `eraOf()` (`E018.js:97-114`) cherche d'abord la ligne `.points-grid-row.is-active` (écrite par `points.js:39`), puis `.points-era[aria-current="true"]`, puis la première ligne ; le nom vient du texte du bouton `.points-era`, sinon reste vide et s'affiche « ère non déterminée » (`:269`).
- **Solution** : hiérarchie de repli, sans appel au store et sans supposition de millésime. La même fonction fournit le nom pour le texte et la ligne pour le marquage des cellules, ce qui garantit qu'une seule ère est désignée.
- **Impact** : pas de verdict erroné quand la classe `is-active` manque ou quand plusieurs lignes sont actives : le premier signal valide est utilisé, l'absence totale est annoncée.
- **Effort** : S
- **Vérification** : relecture des trois branches ; harnais : (a) `.is-active` seul, (b) `aria-current` seul, (c) aucune marque avec au moins une ligne, (d) aucune ligne → quatre comportements corrects, dont « ère non déterminée ».

## E018-05 — Marquage de cellule non destructif et idempotent

- **Preuve** : `markCells()` (`E018.js:179-204`) efface d'abord `data-points-e018-match`, `data-points-e018-state` et la classe `.points-e018-match` (`:180-184`), puis pose ces attributs sur la cellule `(ère, domaine)` (`:195-200`) et `data-points-e018-era` sur le bouton d'ère (`:203`). La feuille ne change que `border-style` et le focus (`:51`, `:47-50`).
- **Solution** : seuls des attributs `data-*` et une classe sont ajoutés ; `textContent`, `title`, `type` et le gestionnaire `click` de la cellule (`points.js:46-53`) ne sont jamais écrits. Le nettoyage préalable rend la passe idempotente sur un même DOM.
- **Impact** : la matrice reste parfaitement utilisable ; le repère visuel ne porte aucune information qui n'existe pas déjà en texte dans le panneau.
- **Effort** : S
- **Vérification** : relecture — aucune écriture de `textContent`/`title`/`onclick` sur `.points-cell` ; rejeu de la passe deux fois de suite → une seule cellule marquée, aucun doublon d'attribut.

## E018-06 — Rafraîchissement par écouteurs non destructifs

- **Preuve** : `bindOnce()` (`E018.js:241-246`) pose l'écouteur en phase capture (`true`, `:244`) et marque l'élément `data-points-e018-bound=1` (`:245`). `apply()` (`:313-317`) l'applique aux deux selects (`change`), au bouton de réinitialisation et aux boutons `.points-era` / `.points-cell` (`click`).
- **Solution** : aucun `preventDefault`, aucun `stopPropagation`, aucun retrait de gestionnaire : les handlers de `points.js:69-90`, `:42` et `:49-53` continuent d'agir. Le marqueur `dataset` empêche d'empiler des écouteurs si le registre repasse sur le même DOM ; un rendu neuf reconstruit des nœuds sans marqueur.
- **Impact** : la synthèse réagit immédiatement au geste, puis est recalculée à neuf au rendu suivant déclenché par la vue — les deux passes convergent vers le même état.
- **Effort** : M
- **Vérification** : relecture — absence de `preventDefault`, `stopPropagation`, `removeEventListener` ; harnais : changer le domaine, la famille, cliquer « Réinitialiser » et une cellule → quatre rafraîchissements, un seul écouteur par contrôle.

## E018-07 — Signature anti-écriture redondante et compteurs auditables

- **Preuve** : `render()` (`E018.js:250-285`) construit la signature `domaine|famille|ère|détail|cellule|verdict` (`:251-255`), sort si elle est inchangée (`:255`), incrémente `writes` (`:257`) et remplace les paragraphes par `replaceChildren` (`:265`, `:278`). `E018.js:64-65` déclare les deux variables ; `:231-232` les remettent à zéro à la création d'un panneau neuf ; le compteur s'affiche en `:284`.
- **Solution** : aucune écriture DOM inutile, aucun `innerHTML`/`insertAdjacentHTML`/`outerHTML` ; le compteur « Actualisations du périmètre : N » permet de distinguer « rien n'a changé » de « greffon muet ».
- **Impact** : nombre borné d'écritures, comportement traçable, compatibilité avec les lentilles de performance (E066, E067) sans les modifier.
- **Effort** : S
- **Vérification** : relecture — les trois appels d'écriture sont conditionnels à la signature ; harnais : deux clics sans changement de signature → compteur stable ; changer l'ère → compteur +1.

## Statut d'implémentation

Les dix chantiers E018-01 à E018-10 sont implémentés dans `src/views/points/E018.js` uniquement. CSS injecté via `ctx.css('points-e018', …)`. Aucun contrôle d'origine n'est modifié, aucune valeur n'est inventée, aucun fichier partagé n'est touché.

## Blocages / limites inter-domaines

- La matrice ne code pas la famille dans ses cellules : le contrôle croisé porte sur `domaine ∩ ère`, tandis que le compte du détail porte sur `domaine ∩ famille ∩ ère`. Le module le dit explicitement dans la note SR et dans le libellé « cellule ère × domaine » ; il ne peut pas vérifier la famille au niveau de la cellule sans toucher au store (`points.js:21-25`), fichier non possédé.
- `writes` et `signature` sont des variables de module, pas un état partagé : un rendu neuf crée un panneau neuf et remet les compteurs à zéro. Conserver un historique entre vues demanderait un contrat hors lentille.
- Le verdict dépend du kicker et des `title` écrits par `points.js` : si une lentille postérieure réécrit ces nœuds, E018 lit la nouvelle valeur sans la corriger. Aucune information n'est émise hors du panneau local.
- Le panneau est ajouté dans `.points-filters` ; si une lentille postérieure vide ce conteneur, le panneau disparaît avec lui. Aucun observateur n'est posé sur ce conteneur, pour éviter une boucle d'écriture.
