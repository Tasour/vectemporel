# E097 — Pédagogie & narration : micro-tutoriel de lecture de la matrice

Lentille E097 — domaine J : pédagogie & narration (théorie & transmission).
Fichier possédé : `src/views/points/E097.js` uniquement. La vue (`src/views/points.js`), la coque et `styles.css` ne sont ni édités ni doublés : E097 ajoute un panneau LOCAL et non modal, accroché à `.points-matrix`, qui **apprend à lire** la matrice — lignes = ères, colonnes = domaines, cellules = croisements. Il ne fait que LIRE le DOM produit par `points.js:29-125` ; le greffon d'aide de la coque (`?` / `#atlas-help`) n'est ni touché ni doublé. Contrairement à E096 (couverture chiffrée), E097 porte sur la **lecture des axes et du symbolisme**, pas sur un score.

Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` ; aucune dépendance vers le store, les filtres ou le détail : le tutoriel reste vrai avec un `ctx` minimal. CSS injecté par `ctx.css('points-e097', …)` (`:30`, `:412`). Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. Aucune structure codée en dur : ni nombre d'ères, ni nombre de domaines, ni millésime, ni total littéral.

## E097-01 — Panneau local non modal, complément de la matrice

- **Preuve** : `E097.js:429-446` crée une unique `<section role="region" aria-labelledby="points-e097-title">` dont le `<h2>` porte `tabIndex=-1` (`:354-357`), et l'ancre dans `.points-matrix` (`:446`). Le CSS (`:56-62`) le pose en bloc documentaire ordinaire, avec `border-left` et fond discret : aucun `backdrop`, aucun `role=dialog`, aucun `aria-modal`, aucun piège de focus. Le commentaire d'en-tête (`:7-10`) documente explicitement la frontière avec l'aide de la coque, non modifiée.
- **Solution** : conserver le panneau comme note pédagogique de la vue, jamais comme modale. La structure statique est construite une seule fois (`buildPanel`, `:349-390`) ; seules les zones variables sont remplacées (`:294-303`). `#atlas-help` et le raccourci `?` ne sont jamais évoqués dans le code, seulement dans le commentaire de délimitation.
- **Impact** : le tutoriel n'interrompt ni le défilement de la grille ni le parcours clavier ; il ne remplace pas l'aide globale et n'empiète sur aucune autre lentille.
- **Effort** : S
- **Vérification** : relecture — aucun `role=dialog`, `aria-modal` ni `inert` ; `role=region` et `aria-labelledby` présents (`:351-352`) ; le panneau n'est pas un `<dialog>` ; il est bien fils de `.points-matrix`.

## E097-03 — Micro-tutoriel en trois temps, texte sémantique

- **Preuve** : `stepContent()` (`:191-231`) enchaîne trois étapes — « Les lignes portent les ères » (`:195-206`), « Les colonnes portent les domaines » (`:207-218`), « Les cellules croisent ère et domaine » (`:219-230`). Chaque étape : une définition, une observation chiffrée lue dans le DOM, un conseil d'usage. Le texte est écrit dans un `<h3>` et des `<p>` créés par `ctx.el` (`:297-300`), visibles et indexables sans JS.

- **Impact** : le panneau reste lisible et compréhensible avec JavaScript désactivé (les définitions statiques du glossaire demeurent, `:329-344`) ; la couche pédagogique ne remplace jamais la matrice.
- **Effort** : M
- **Vérification** : relecture — trois branches dans `stepContent()` ; un `<h3>` et trois `<p>` par étape (`:298-299`) ; contrôle : désactiver JS → la matrice d'origine reste intacte.

## E097-04 — Navigation native entre étapes, accessible au clavier

- **Preuve** : `buildPanel()` (`:377-387`) crée deux `<button type="button">` natifs (« ← Étape précédente », « Étape suivante → »), chacun avec un `aria-label` distinct, attachés **une seule fois** aux handlers `setStep(step ± 1)` (`:381`, `:385`). `setStep()` (`:314-317`) borne l'index entre 0 et `STEP_LABELS.length - 1` ; `render()` (`:305-306`) pose `disabled` aux deux extrémités.
- **Solution** : aucun gestionnaire documentaire, aucune touche réservée, aucun `tabindex` positif : la navigation repose sur des boutons standards. Les libellés visuels et les `aria-label` restent cohérents avec l'action réelle.
- **Impact** : parcours clavier complet sans conflit avec le routeur ; l'état de la commande (bouton actif/inactif aux bornes) est exposé aux technologies d'assistance via `disabled`.
- **Effort** : S
- **Vérification** : relecture — deux boutons, deux `addEventListener('click')` (`:381`, `:385`), bornage (`:315`) ; harnais : clic « suivant » trois fois → reste à l'étape 3, « précédent » désactivé en étape 1, « suivant » désactivé en étape 3.

## E097-05 — Mise en évidence non destructive et réversible

- **Preuve** : `applyHighlight()` (`:265-281`) commence par `clearHighlight()` (`:257-260`) qui retire **uniquement ses trois classes** (`e097-hl-era`, `-domain`, `-cell`, `:41-43`) des nœuds précédemment marqués, puis ajoute la classe de l'étape courante sur les bonnes cibles : boutons-ères (`:268`), en-têtes de domaines (`:271`), cellules (`:274`). Aucun `title`, aucun attribut, aucun écouteur natif de `points.js` n'est modifié.
- **Solution** : la surbrillance est purement CSS (`outline` + fond discret, `:101-108`) et strictement réversible. Les nœuds marqués sont suivis dans `highlighted` (`:141`) ; le retrait précède toujours l'ajout, ce qui interdit l'accumulation de classes entre étapes.
- **Impact** : le changement d'étape ne laisse aucune trace sur la matrice ; les gestionnaires de `points.js` (clic ère, clic cellule, filtres) restent opérationnels ; la classe `is-active` d'E001 et les marques des autres lentilles sont préservées.
- **Effort** : M
- **Vérification** : relecture — un seul `clearHighlight()`, seules les classes préfixées `e097-hl-` sont écrites/retirées ; harnais : étapes 1→2→3 → à chaque fois un seul jeu de classes présentes dans la grille, retour en étape 1 sans résidu.

## E097-07 — Mesures référencées : trois grandeurs et une comparaison falsifiable

- **Preuve** : `buildReadout()` (`:235-248`) affiche quatre grandeurs dérivées du DOM : ères, domaines, cellules observées, cellules avec un nombre (`:247`). La **référence** est explicite et calculée : `ères × domaines = cellules attendues` (`:179`, `:239`), comparée au total observé (`:243`) avec un écart signé énoncé (`:244-246`). Repli « indisponible » quand la grille manque (`:240-242`).
- **Solution** : la référence n'est pas un chiffre mémorisé mais le produit des deux axes lus sur la matrice. L'écart se lit `expected − total` ; s'il est nul, la phrase l'affirme (« aucun écart : la grille est complète »), sinon elle donne la magnitude absolue. Le lecteur peut reconstruire le calcul lui-même.
- **Impact** : la comparaison est pédagogiquement honnête et falsifiable — une grille incomplète donne un écart non nul, visible immédiatement ; aucune information n'est portée par la seule couleur (chiffres tabulaires, `:61`).
- **Effort** : S
- **Vérification** : relecture de `:236-247` ; harnais : grille absente → « indisponible » ; grille à E ères × D domaines complète → « référence E×D, aucun écart » ; retirer une cellule → « écart : 1 cellule(s) ».

## E097-08 — Région live unique, déduplication et accessibilité

- **Preuve** : le seul `role="status"` du module est créé une fois dans `buildPanel()` (`:365-371`), avec `aria-live="polite"` et `aria-atomic="true"`. `render()` ne fait que mettre à jour son `textContent` (`:301`), et uniquement quand la signature change (`:294`, garde définie en `:253-255`). Le panneau porte `role=region` + `aria-labelledby` (`:351-352`) ; un bloc `forced-colors` (`:122-129`) garantit bordures et texte explicites.
- **Solution** : une seule région live locale, dédupliquée par `signatureOf()` (étape + quatre grandeurs + titre) : ni bavardage à chaque `MutationObserver`, ni annonce en double. Le ctx POINTS n'expose pas `say()` (`src/views/points/registry.js`) : E097 n'écrit donc dans aucune région live de la coque.
- **Impact** : les lecteurs d'écran entendent l'étape et les grandeurs une fois par changement réel ; les cibles tactiles restent ≥ 36 px (`:78-83`, `:89-92`) et le focus reste visible (`:84-86`, `:93-95`).
- **Effort** : M
- **Vérification** : relecture — un seul `setAttribute('role', 'status')` dans tout le fichier ; style de focus présent ; contrôle : deux rendus sans changement → aucune réécriture de la live (signature inchangée).

## E097-09 — Mouvement réduit détecté, aucune animation propre

- **Solution** : double source de vérité (sonde JS + media query) avec repli sûr. Le greffon n'a pas d'animation qui lui soit propre : la surbrillance est un simple changement de classe, sans mouvement.
- **Impact** : le tutoriel ne contredit pas la préférence système ; les utilisateurs sensibles au mouvement voient les mêmes informations, sans fondu.
- **Effort** : S

## Blocages / limites inter-domaines

- Le tutoriel décrit la structure de la **matrice affichée** (`E097.js:156-181`). Il ne valide ni le contenu des points ni les chiffres globaux documentés ailleurs (`COVERAGE_POINTS.md`, fichier non possédé) : E097 ne recopie aucun total externe, il ne fait que lire ères, domaines et cellules présents dans le DOM.
- Le ctx POINTS n'expose pas `say()` (`src/views/points/registry.js`) : l'annonce passe par le `<p role=status>` local (`:365-371`), région propre au module.
- La référence « ères × domaines = cellules attendues » (`:179`, `:243`) est une attente de **complétude structurelle** de la grille : un écart non nul signale une case manquante dans le rendu, pas une erreur historique. E097 ne corrige pas la matrice, il la rend lisible.
- L'état d'étape est volatil : `points.js:126` relance `runEnhancements` à chaque rendu. Le composant module conserve l'index courant (`:134`) entre rendus, mais une navigation complète (rechargement) le remet à zéro : une historisation demanderait un état partagé hors du contrat de la lentille.
- Si la vue ne produit aucun `.points-grid` (ctx minimal), le panneau affiche les replis « indisponible » (`:202`, `:214`, `:241`) : c'est un comportement explicite, pas une panne.
