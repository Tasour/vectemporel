# E068 — Performance et sobriété

> Lentille V2 E068 de la vue Récit, focalisée sur la performance et la sobriété. Fichiers possédés : `src/views/recit/v2/E068.js` et `UNIFIED_AUDIT/RECIT/V2/views/E068.md`. **Statut : 10/10 chantiers implémentés** (`E068-01` à `E068-10`). Contrat respecté : un seul `register('E068', …)`, une seule feuille `css('recit-v2-e068', …)`, classes `recit-v2-e068-*`, identifiants `v2-e068-*` uniques (jamais les ids `e068-*` de la passe 1, qui partage le même DOM), aucune journalisation, aucune requête, aucune source d'aléa. Chaque chiffre affiché est dérivé du DOM réel (`.view-kicker`, `#c3a-status`, `.recit-thread-item`, `#recit-point-title`, `.recit-media`) ou d'un signal d'environnement effectivement consulté (`reducedMotion()`). La passe 1 optimisait le rendu (containment, `content-visibility`, décodage d'image, mode sobre, chiffres tabulaires, `text-wrap`) ; la V2 mesure et rend lisible ce coût, sans reprendre aucun de ces chantiers.

Pièces lues pour le diagnostic : `src/views/recit/v2/registry.js` (`register`, `cssOnce`, `el`, `runEnhancements`), `src/views/recit/E068.js` et `UNIFIED_AUDIT/RECIT/views/E068.md` (modèle de la passe 1), `src/views/recit/v2/E003.js` et son rapport (référence de structure V2), `src/views/recit.js` (construction du DOM : `.recit-layout/.recit-media/.recit-body`, `.recit-progress`, `.view-kicker`, `#recit-point-title`, `#recit-context`, `.recit-timing`, `#c3a-tools`, `#c3a-status`, `#c3a-thread`, `.recit-actions`, `.recit-legend`, `.recit-trace`), `src/views/_diagnostics.js` (tiroir `data-recitv2-diagnostic`, marquage des ids `-e068`). Jeu de données : 901 points, statut « N point(s) affiché(s) sur T », fil de boutons `.recit-thread-item`.

Nature du greffon : strictement additif. Aucun texte existant, aucun attribut utile et aucun gestionnaire d'origine n'est remplacé. Toutes les opérations sont enveloppées dans `safe()` et le point d'entrée dans un `try/catch` global : un repère absent ne produit jamais d'exception. Sans JavaScript, la vue Récit reste intégralement lisible.

## E068-01 — Jauge de charge du fil

- **Problème** : `#c3a-status` énonce « N point(s) affiché(s) sur T » en prose, sans synthèse visuelle du taux de couverture du repère après filtrage.
- **Solution** : `lireTotaux()` extrait les affichés par `/(\d+)\s*point\(s\)\s*affiché\(s\)\s*sur\s*(\d+)/` sur `#c3a-status` (repli `.c3a-status`) et le total par `/Étape\s+(\d+)\s*\/\s*(\d+)/` sur `.view-kicker` ; `pct = Math.round(affiches / total * 100)`. `#v2-e068-jauge` contient le texte « Fil : A / T point(s) · P % affichés » et une piste `.recit-v2-e068-jauge-piste` (`aria-hidden="true"`) dont l'enfant `.recit-v2-e068-jauge-rempli` reçoit `style.width = pct + '%'`. Insertion après le statut via `poser()` → `insererApres()`, qui refuse tout id déjà présent.
- **Impact** : le coût de rendu du fil est lisible d'un coup d'œil, sans recomposer le ratio ni changer de vue.
- **Risque** : kicker ou statut absent : `lireTotaux()` retombe sur le total du statut puis sur `0`, et le pourcentage vaut `0` sans exception. L'information n'est jamais portée par la seule couleur : le texte chiffré reste lisible, y compris en mouvement réduit (E068-08 annule la transition de la jauge).
- **Vérification** : `#v2-e068-jauge` unique ; `pct` recalculé depuis les deux expressions régulières ; `node --check` OK.

## E068-02 — Récapitulatif de sobriété en phrase

- **Problème** : les signaux de sobriété (mouvement, présence d'image, complexité, volume de texte) sont éparpillés entre la coque, le DOM et l'environnement, sans phrase unique qui les restitue.
- **Solution** : `#v2-e068-recap` (`role="status"`, `aria-live="polite"`) assemble « Profil sobriété : mouvement réduit/complet · image présente (N)/absente · X nœuds de base · C caractères de texte. » Les valeurs proviennent de `reducedMotion()`, de `profilImage()`, du comptage `layout.querySelectorAll('*')` et de `volumeTexte()`. Insertion après la jauge par la chaîne `chainer()`.
- **Impact** : un résumé audible et lisible nomme explicitement l'état réel de la vue, utile après un changement de point ou de préférence système.
- **Risque** : aucun état n'est supposé — l'absence d'image est une observation du DOM, pas une hypothèse. Si la jauge n'a pas pu être insérée, `poser()` repose le récapitulatif en tête de `.recit-body` ; la garde d'id évite le doublon.
- **Vérification** : `#v2-e068-recap` unique, libellés cohérents avec les quatre sources ; `node --check` OK.

## E068-03 — Coût structurel : nœuds de base

- **Problème** : la vue expose des centaines de boutons de fil, mais aucun indicateur ne dit combien de nœuds la coque a réellement disposés pour le point courant.
- **Solution** : `safe(() => layout.querySelectorAll('*').length)` est calculé une fois, avant toute insertion V2. `#v2-e068-noeuds` écrit « Complexité de base : X nœuds dans la vue, avant cet enrichissement V2. », inséré après `.view-kicker` avec repli sur `.recit-body`.
- **Impact** : l'apprenant dispose d'une mesure honnête de la complexité d'origine, distincte du coût ajouté par le tableau de bord V2 lui-même.
- **Risque** : le nombre est volontairement figé avant insertion : le message le dit explicitement, ce qui évite de présenter un chiffre qui s'augmenterait de ses propres notes. Un `querySelectorAll` indisponible donne `0` via `safe()`, sans erreur.
- **Vérification** : `#v2-e068-noeuds` unique ; valeur égale au comptage réel au moment du rendu ; `node --check` OK.

## E068-04 — Volume de texte du point courant

- **Problème** : `.recit-timing` annonce une durée estimée en secondes, mais rien ne chiffre le volume réel de texte du point (titre + chapeau) qui sera disposé et peint.
- **Solution** : `volumeTexte()` concatène le `textContent` de `#recit-point-title` (repli `.recit-title`) et de `#recit-context`, normalise les espaces, puis compte les caractères et les mots. `#v2-e068-volume` écrit « Volume du point : C caractères · M mots (titre et chapeau). », inséré après `.recit-timing`.
- **Impact** : le coût typographique est explicite sans réécrire ni tronquer une seule phrase du récit.
- **Risque** : `#recit-context` n'existe qu'au premier point : la fonction compositionne alors le seul titre, sans valeur inventée. Si le titre manque aussi, les deux compteurs valent `0`.
- **Vérification** : `#v2-e068-volume` unique ; C et M recalculés depuis le `textContent` des deux nœuds ; `node --check` OK.

## E068-05 — Avertissement de fil chargé

- **Problème** : sur un repère qui expose beaucoup de points, chaque résultat affiché est un bouton disposé et peint ; aucun signal n'alerte quand leur nombre devient élevé.
- **Solution** : si `totaux.affiches >= SEUIL_FIL` (seuil interne de budget de rendu, jamais affiché), `#v2-e068-avertissement` est inséré dans la chaîne après le récapitulatif : « Fil chargé : N point(s) affiché(s), autant de boutons disposés et peints. La recherche et les filtres réduisent ce coût. » Le seuil est une convention de code ; seul N, lu dans `#c3a-status`, est écrit dans le DOM.
- **Impact** : l'utilisateur comprend pourquoi le fil devient coûteux et sait qu'un filtrage réduit le travail du navigateur.
- **Risque** : le seuil n'est présenté ni comme une mesure ni comme un fait : aucun chiffre fabriqué n'est affiché. Si le statut est illisible, `affiches` vaut `0` et la branche reste inactive — la vue est inchangée.
- **Vérification** : `#v2-e068-avertissement` présent uniquement au-delà du seuil ; N identique au compte du statut ; `node --check` OK.

## E068-06 — Statut image et coût réseau évité

- **Problème** : la coque affiche « Aucune image vérifiée pour ce repère » dans `.media-empty`, mais aucun texte ne relie cette absence à l'absence de transfert d'image.
- **Solution** : `profilImage()` compte les `<img>` dans `.recit-media` et détecte `.media-empty`. `#v2-e068-image` écrit « Aucune image pour ce repère : aucun octet d’image demandé. » ou « Image : I élément(s) image présent(s) dans ce repère. », inséré après `#v2-e068-volume`.
- **Impact** : le coût réseau est explicité de façon véridique, sans annoncer d'octets non mesurables localement.
- **Risque** : aucun `src`, `alt` ou `loading` n'est modifié — la V2 ne touche pas aux attributs gérés par la passe 1. En l'absence de `.recit-media`, `nombre` vaut `0` et le message « aucune image » est affiché par défaut, conforme au DOM observé.
- **Vérification** : `#v2-e068-image` unique ; I égal au nombre réel d'`<img>` ; `img.src`/`img.alt` intacts ; `node --check` OK.

## E068-07 — Levier de densité compacte

- **Problème** : réduire la surface peinte suppose de faire tenir plus de contenu par écran ; la passe 1 propose un « mode sobre » qui neutralise les effets, mais aucun levier ne agit sur les espacements.
- **Solution** : `#v2-e068-compact` (`button type="button"`, `.recit-v2-e068-bouton`, `min-height:36px`, `:focus-visible`, `aria-pressed`) est inséré en tête de `.recit-actions` s'il n'existe pas. Son clic inverse la variable de module `compact`, met à jour l'état ARIA et le libellé (« Densité : compacte/normale ») et bascule `recit-v2-e068-compact` sur la racine. La feuille réduit alors les marges de `.c3a-tools`, le `gap` de `.recit-thread-list`, et les marges de `.recit-thread` et `.recit-legend`, sans toucher à la taille des cibles tactiles existantes. L'état survit aux reconstructions du DOM par la coque.
- **Impact** : un levier réel et réversible diminue le défilement et donc la surface à peindre, sans masquer la moindre phrase.
- **Risque** : `aria-pressed` n'est utilisé que pour cette bascule indépendante, jamais pour un choix unique. Le bouton n'est créé que si `.recit-actions` et `el` existent ; les gardes `getElementById` et `actions.querySelector('#v2-e068-compact')` empêchent tout doublon. Aucune règle ne réduit une hauteur minimale de bouton ni ne pose `display:none`.
- **Vérification** : un seul `#v2-e068-compact` par rendu ; `aria-pressed` suit l'état ; la racine porte ou non `recit-v2-e068-compact` ; cible ≥ 36 px ; `node --check` OK.

## E068-08 — Mouvement réduit appliqué aux artefacts V2

- **Problème** : la media query globale et la passe 1 neutralisent les animations de la coque, mais la jauge introduite par la V2 possède sa propre transition de largeur, qui doit obéir à la même préférence.
- **Solution** : `reducedMotion()` (fourni par le registre) est appelé dans le point d'entrée ; la racine reçoit `recit-v2-e068-sans-mouvement` et `data-v2-e068-mouvement="reduit"` (sinon `"plein"`). La feuille annule `transition` et `animation` sur `.recit-v2-e068-jauge-rempli` via cette classe **et** via une media query `prefers-reduced-motion:reduce` autonome.
- **Impact** : la préférence de sobriété de mouvement est honorée de façon redondante et cohérente pour les seuls éléments mobiles créés par la V2.
- **Risque** : `reducedMotion()` est évalué sans effet de bord ; un moteur qui ne fournit pas `matchMedia` renvoie `false` et la media query agit seule. Aucun timer ni gestionnaire n'est installé ; la jauge reste lisible dans tous les cas.
- **Vérification** : avec la préférence active, la racine porte la classe et l'attribut, et `getComputedStyle` de la jauge ne montre aucune transition ; `node --check` OK.

## E068-09 — Rang du point courant dans le fil

- **Problème** : le kicker donne « Étape i / n » du repère, mais pas la position du point affiché parmi les boutons réellement présents dans `#c3a-thread` après filtrage.
- **Solution** : `rangCourant(items)` cherche dans les `.recit-thread-item` l'attribut `aria-current="step"` ou la classe `is-current`. `#v2-e068-rang` écrit « Point courant : rang r / N · N bouton(s) dans le fil. », ou « hors du fil affiché » si aucun item n'est courant, inséré après l'avertissement ou le récapitulatif.
- **Impact** : l'apprenant situe le point lu dans le sous-ensemble filtré, ce qui rend la navigation prévisible.
- **Risque** : l'absence d'item courant est une observation du DOM, pas une supposition : le message « hors du fil affiché » est alors affiché. Le rang est dérivé de l'ordre réel des boutons, jamais d'une hypothèse sur le jeu de données.
- **Vérification** : `#v2-e068-rang` unique ; r = index + 1 dans la liste réelle des items ; `node --check` OK.

## E068-10 — Panneau de synthèse V2 (tiroir diagnostic)

- **Problème** : les neuf mesures ci-dessus vivent dans des notes éparses ; aucun tiroir ne les regroupe pour un contrôle rapide de la sobriété de la vue.
- **Solution** : `ajouterPanneau()` retire d'abord tout panneau `#v2-e068-diagnostic` résiduel (le DOM étant reconstruit à chaque rendu), puis crée une `<section data-recitv2-diagnostic>` avec un `<h2>` et neuf `<p>` identifiés `v2-e068-diag-*` : nœuds de base, points affichés, couverture, volume, image, mouvement, densité, rang et bilan. Chaque ligne est alimentée par `ecrire()` depuis les valeurs déjà calculées, le bilan récapitulant `noeuds`, `items.length`, `volume.caracteres` et le mouvement.
- **Impact** : un diagnostic consolidé, factuel et dérivé du DOM, permet de vérifier en un coup d'œil l'effet des neuf autres chantiers.
- **Risque** : le marquage `data-recitv2-diagnostic` fait entrer le panneau dans le tiroir `_diagnostics.js` : il est masqué par défaut, donc jamais confondu avec le contenu du récit. Le texte de synthèse n'est pas porté par une couleur seule. Aucune ligne n'est inventée : toutes les valeurs sont relues au rendu.
- **Vérification** : panneau unique, neuf `<p>` renseignés ; `node --check` OK ; aucun fichier partagé modifié.
