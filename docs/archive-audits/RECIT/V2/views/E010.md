# E010 — Registre de lecture des données affichées (V2)

> Lentille V2 E010 — vue Récit (`src/views/recit/v2/E010.js`). Thème repris de la passe 1 : données, traçabilité et provenance. Contexte : la passe 1 traite déjà la fiche de provenance, le signal de présence/absence de source, les puces `SRC`, le tableau de bord du jeu, la répartition par type et certitude, la signature du fil, le glossaire, la méta-provenance et le vérificateur de chaîne. La V2 propose donc **dix chantiers neufs et distincts**, tous dérivés du DOM réellement affiché et regroupés dans un « registre de lecture » visible. Statut : **10/10 chantiers implémentés** (E010-01 à E010-10).
> Contrat respecté : un seul `register('E010', …)`, un seul `css('recit-v2-e010', …)` regroupant toutes les règles, classes préfixées `recit-v2-e010-`, ids DOM préfixés `v2-e010-` et uniques (aucun id `e010-` de la passe 1 n'est réutilisé sur le DOM partagé), zéro réseau/console/aléa, enrichissement non destructif avec gardes d'existence et `try/catch` global.
>
> Vérification exécutée : outre `node --check`, la lentille a été chargée dans Chromium headless (hors de l'arbre du projet) sur un DOM factice reproduisant `.recit-layout/.recit-media/.recit-body/.c3a-status/#c3a-search/.recit-thread/.recit-trace/.recit-legend`, puis appliquée **trois fois de suite** dans trois scénarios (traçabilité cohérente, point sans source, références divergentes). Aucune erreur JavaScript, aucun id dupliqué, aucun nœud marqué `data-recit-diagnostic`.

## E010-01 — Échelle du repère relue dans la recherche

- **Problème** : le nombre total de points du repère n'est jamais affiché en clair ; il n'existe que dans l'attribut `aria-label` du champ `#c3a-search` (« Rechercher parmi les N points de ce repère »), donc invisible pour un lecteur visuel.
- **Solution** : `<li id="v2-e010-echelle" class="recit-v2-e010-readout recit-v2-e010-item recit-v2-e010-echelle">` dans le registre. Le nombre est extrait de `search.getAttribute('aria-label')` par `/(\d+)\s+points?\s+de\s+ce\s+repère/i` et converti avec `parseInt(…, 10)` ; texte « Échelle du repère : N point(s) dans le jeu de données local. », repli « non déterminée » sans chiffre.
- **Impact** : échelle chiffrée visible et indexable dans un `<li>` du flux, sans toucher au champ de recherche.
- **Risque** : si l'aria-label change de forme, aucun nombre n'est inventé — le repli reste textuel. L'attribut du champ est lu, jamais réécrit.
- **Vérification** : un seul `#v2-e010-echelle` ; avec l'aria-label « … les 6 points … », le texte affiche 6 ; aucun `href` ni `src` introduit.

## E010-02 — Couverture du fil chiffrée

- **Problème** : `#c3a-status` annonce « N point(s) affiché(s) sur M » mais ne calcule pas la proportion ; le lecteur doit la reconstituer mentalement à chaque filtrage.
- **Solution** : regex `/(\d+)\s+point\(s\)\s+affiché\(s\)\s+sur\s+(\d+)/i` sur `statut.textContent`, puis `Math.round((affiches / totalRepere) * 100)` avec garde `totalRepere > 0`. `<li id="v2-e010-couverture">` affiche « Fil affiché : N point(s) sur M (X % du repère). », ou « proportion non déterminée » si le statut est illisible.
- **Impact** : proportion lisible, recalculée depuis le DOM à chaque rendu, donc toujours synchronisée avec les filtres C3.
- **Risque** : le contenu de `#c3a-status` n'est pas modifié (lecture seule) ; le pourcentage est arrondi à l'unité et suivi du signe `%`, jamais porté par la couleur seule.
- **Vérification** : le cas testé « 2 affiché(s) sur 6 » donne `round(2/6×100) = 33` → « (33 % du repère) » ; un seul nœud après trois rendus.

## E010-03 — Sélection active relue sur les filtres

- **Problème** : les critères C3 sont dispersés entre la valeur de `#c3a-search` et les boutons `.c3a-filter[aria-pressed="true"]` des groupes « Type » et « Certitude » ; aucun récapitulatif textuel ne les rassemble.
- **Solution** : lecture de `search.value` et des `.c3a-group[role="group"]` ; pour chaque groupe, le bouton pressé est relevé via `.c3a-filter[aria-pressed="true"]`, les libellés « Tous les types » / « Toutes » étant écartés par `/^Tous\b|^Toutes\b/i`. `<li id="v2-e010-filtres">` affiche « Sélection active : recherche « q » · Type = récit · Certitude = Vérifié. », ou « Aucun filtre actif sur ce repère. »
- **Impact** : état exact de la sélection rendu lisible, y compris pour un lecteur d'écran, sans reconstitution manuelle.
- **Risque** : `aria-pressed` est lu mais jamais écrit ; la lentille ne détourne donc pas l'attribut des boutons existants (ce n'est pas une bascule qu'elle possède) et n'écrase aucun `aria-*`.
- **Vérification** : dans le scénario testé (bouton « Toutes » pressé pour le type, « Vérifié » pour la certitude), le texte vaut « Sélection active : Certitude = Vérifié. » ; un seul nœud.

## E010-04 — Décompte des références déclarées du point courant

- **Problème** : le nombre de références n'apparaît que dans le `<summary>` replié de `.recit-trace` ; pour un point sans source, `.recit-sources` ne le chiffre pas à zéro.
- **Solution** : regex `/(\d+)\s+référence\(s\)/i` sur le texte du `<summary>` ; `<li id="v2-e010-refs">` affiche « Références du point : N déclarée(s) dans la traçabilité. ». En l'absence de `.recit-trace` mais présence de `.recit-sources`, le texte est « aucune référence déclarée » (zéro explicite) ; sinon « état non déterminé ».
- **Impact** : décompte visible même lorsque le `<details>` est fermé, et zéro explicite pour un point non sourcé.
- **Risque** : le `<summary>` et le paragraphe d'origine ne sont pas modifiés ; aucun identifiant n'est fabriqué quand la traçabilité manque.
- **Vérification** : « Traçabilité · 2 référence(s) locale(s) » → « 2 déclarée(s) » ; scénario sans source → « aucune référence déclarée ».

## E010-05 — Contrôle de cohérence des références

- **Problème** : rien ne vérifie que le nombre annoncé dans le résumé correspond aux identifiants réellement listés ; une divergence (référence dupliquée ou manquante) passerait inaperçue.
- **Solution** : les codes sont extraits du `<p>` de `.recit-trace` par `/SRC[- ][0-9]+/gi`, normalisés (`replace(/\s+/g, '-').toUpperCase()`) et dédupliqués par un `Set`. Leur nombre `K` est comparé au nombre `N` déclaré (chantier 04) ; `<li id="v2-e010-coherence">` affiche « Cohérence des références : N déclarée(s), K identifiant(s) distinct(s) — cohérent » ou « divergence à vérifier », avec `data-v2-e010-state="ok|divergence"`.
- **Impact** : contrôle falsifiable : 3 références déclarées pour 2 identifiants distincts signalent une divergence.
- **Risque** : l'état est porté aussi par le texte, pas seulement par la bordure CSS ; sans traçabilité, le résultat est cohérent à 0/0 ; aucun `aria-pressed` n'est employé.
- **Vérification** : cas 2 déclarés / 2 codes → « cohérent » et `data-v2-e010-state="ok"` ; cas 3 déclarés / 2 codes → « divergence à vérifier » et état `divergence`.

## E010-06 — Qualité des libellés du fil

- **Problème** : `clip()` (dans `recit.js`) tronque les libellés longs des boutons du fil à 72 caractères en ajoutant « … » ; cette perte d'information n'est signalée nulle part.
- **Solution** : comptage des `.recit-thread-item` dont `textContent` se termine par `…` via `/…\s*$/` ; `<li id="v2-e010-troncature">` affiche « Libellés du fil : K tronqué(s) sur N. », ou « aucun point affiché » si le fil est vide.
- **Impact** : la perte d'information devient une mesure lisible ; aucun libellé d'origine n'est modifié ni rallongé.
- **Risque** : une ellipse naturelle dans un texte non tronqué serait comptée — la mesure est indicative et explicitement dérivée du texte affiché ; aucune correction automatique n'est tentée.
- **Vérification** : scénario testé → « Libellés du fil : 1 tronqué(s) sur 2. » ; recalcul après chaque filtrage ; un seul nœud.

## E010-07 — Provenance de l'image du repère

- **Problème** : `.recit-media-credit` porte le crédit et la licence de l'image (et `.media-empty` le cas sans image), mais ce texte vit dans `.recit-media`, hors du corps, et est masqué sous 620 px (`display:none`).
- **Solution** : lecture via `layout.querySelector('.recit-media-credit')` — le média est un frère de `.recit-body`, non son enfant — et `layout.querySelector('.media-empty')`. `<li id="v2-e010-image">` reprend le texte du crédit (« Provenance de l'image : Crédit : … · Licence : …. »), celui de `.media-empty`, ou « non renseignée dans ce repère ».
- **Impact** : provenance de l'image rendue visible et indexable dans le registre, y compris sur petit écran.
- **Risque** : lecture seule du crédit — aucun `href` ni `src` ajouté, l'image d'origine reste intacte ; si le crédit est vide, le repli n'invente aucune valeur.
- **Vérification** : crédit « Crédit : Atelier X · Licence : CC-BY » repris tel quel ; en présence de `.media-empty`, texte « Provenance de l'image : Aucune image vérifiée pour ce repère. »

## E010-08 — Légende des symboles de certitude

- **Problème** : la passe 1 définit la certitude de façon abstraite mais ne décode pas les symboles `✓ ■ ◐ ≈` qui apparaissent dans la pastille `.recit-conf` et dans la légende.
- **Solution** : les `<p>` de `.recit-legend` sont parcourus et les paires symboles/libellés extraites par `/([✓■◐≈])\s+([A-Za-zÀ-ÿ]+)/g` ; `<li id="v2-e010-symboles">` affiche « Symboles de certitude : ✓ = Vérifié · ■ = Certain · ◐ = Probable · ≈ = Contesté. », avec repli « légende non disponible ».
- **Impact** : correspondance symbole → libellé lisible au premier usage, distincte du glossaire de la passe 1 et sans quitter la vue.
- **Risque** : les libellés sont ceux du DOM, non traduits ni réécrits (la mention « disputed » reste dans la légende d'origine) ; le contenu est un `<li>` visible, jamais un texte masqué.
- **Vérification** : quatre paires extraites de la légende réelle ; un seul `#v2-e010-symboles` ; aucun nœud ajouté à `.recit-legend`.

## E010-09 — Vérificateur de compteurs du fil

- **Problème** : les trois compteurs du fil (boutons réellement affichés, statut « N sur M », total annoncé par l'aria-label) peuvent diverger après filtrage ; aucun contrôle rejouable ne permet de les vérifier soi-même.
- **Solution** : `<div id="v2-e010-verif">` contenant un bouton `#v2-e010-verif-button` (`type="button"`, libellé « Vérifier les compteurs », `min-height:36px`, `:focus-visible`) et `<p id="v2-e010-verif-readout" role="status" aria-live="polite">`. Au clic, relecture de `#c3a-status` (N/M), du nombre de `.recit-thread-item` et de l'aria-label de `#c3a-search` (T) ; sortie « Compteurs cohérents/divergents : … Contrôle relu dans le DOM affiché. » et `data-v2-e010-count="ok|divergent"`. L'écouteur est installé une seule fois (`data-v2-e010-bound !== '1'`).
- **Impact** : contrôle falsifiable et sans réseau, distinct du vérificateur de chaîne de la passe 1 : il vérifie la cohérence interne des compteurs, pas la présence des maillons du point.
- **Risque** : le readout est remis à « non encore vérifiés » à chaque rendu, donc aucun résultat périmé après navigation ; `aria-pressed` n'est pas utilisé (commande ponctuelle) ; aucun attribut existant n'est écrasé.
- **Vérification** : cas cohérent → « Compteurs cohérents : boutons du fil 2, affichés annoncés 2, total annoncé 6, total de la recherche 6 » et `data-v2-e010-count="ok"` ; hauteur mesurée du bouton = 36 px ; écouteur unique après trois rendus.

## E010-10 — Mouvement réduit, idempotence et robustesse

- **Problème** : dix lectures insérées dans une vue reconstruite à chaque changement d'état doivent rester idempotentes, accessibles, sans mouvement indésirable ni nœuds masqués par le tiroir de diagnostics.
- **Solution** : `getOrCreate()` centralise les ids uniques, le garde anti-doublon (`document.getElementById` + contrôle du parent) et le `insertBefore` dans un `try` sans `throw` ; tous les nœuds porteurs d'un id sont déposés dans `.recit-body` ou ses enfants, jamais directement dans `stage`/`layout`, donc non marqués `data-recit-diagnostic`. `reducedMotion()` est appelé une fois par rendu et pose `data-v2-e010-motion="reduce|normal"` sur `layout` (attribut distinct de `data-e010-reduced` de la passe 1) ; le CSS annule la transition de `.recit-v2-e010-readout` sous l'attribut **et** sous `@media (prefers-reduced-motion:reduce)`. Le `try/catch` global et les gardes (`document`, `layout`, `css`, `el`, `corps`) encadrent tout le module.
- **Impact** : la lentille survit aux re-renders, respecte la préférence système, reste lisible sans JavaScript et ne perturbe ni le focus ni le tiroir de diagnostics.
- **Risque** : le `try/catch` neutralise silencieusement toute erreur sans casser la vue ; l'attribut de mouvement est posé sans écraser les autres attributs de `layout` ; le registre reste dans le flux (`<li>` visibles, pas de `aria-hidden`).
- **Vérification** : trois applications consécutives → 15 ids `v2-e010-` uniques, zéro doublon, zéro nœud `data-recit-diagnostic` ; avec préférence réduite, `data-v2-e010-motion="reduce"` et transition nulle ; sinon `normal`.
