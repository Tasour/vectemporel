# E055 — Accessibilité ARIA et lecteurs d'écran

Lentille **E055** de la vague « Récit » — module `src/views/recit/E055.js`, contrat `register('E055', ctx => { … })`, unique bloc CSS `ctx.css('recit-e055', …)`, ids DOM préfixés `e055-` et classes préfixées `recit-e055-`. **Statut : 10/10 chantiers implémentés** (E055-01 … E055-10).

Pièces lues pour le diagnostic : `src/views/recit.js` (structure `.recit-layout/.recit-media/.recit-body`, barre `.recit-progress`, kicker `.view-kicker`, `#recit-point-title`, pastille `.recit-conf`, fil `#c3a-thread`, `.recit-trace`, `.recit-sources`, `.recit-actions`, `.recit-legend`, `#atlas-recit-live`), `src/views/recit/registry.js` (`register`, `cssOnce`, `el`, `runEnhancements`), `src/views/recit/index.js` (import de `E055.js`), `src/views/_diagnostics.js` (marquage des nœuds `e\d\d`/`-e\d\d`), `UNIFIED_AUDIT/RECIT/views/E005.md` (lentille ARIA antérieure, afin d'éviter tout écrasement). Jeu de données : 901 points, `kind ∈ {récit, figure, lieu, audit}`, `confidence ∈ {vérifié, certain, probable, disputed}`, 587 points sans source.

Aucune donnée historique n'est ajoutée : les libellés diffusés sont recalculés depuis le texte réellement rendu (kicker `Étape i / n`, pastille de certitude, titre du fil, intitulés de boutons, état de `aria-pressed`) ou depuis les compteurs du DOM courant. Enrichissement strictement additif : `setOnce` ne réécrit jamais un attribut existant, `addToken` ajoute un identifiant sans effacer les autres, `idOf` réutilise un id déjà posé, `fresh` ne supprime qu'une incarnation antérieure du **même** id. Chaque chantier est isolé par `safe()` : une cible absente ne produit ni exception ni rupture visuelle. Sans JavaScript, la vue Récit reste intégralement lisible et navigable.

## E055-01

- **Problème.** Le fil est une `<ol class="recit-thread-list c3a-thread">` stylée en `list-style:none`. Même renforcée en `role="list"`/`role="listitem"` par une lentille antérieure, cette présentation prive certains lecteurs du rang ordinal : ils entendent une suite de boutons sans savoir quel point est le 3ᵉ sur 10.
- **Solution.** `chantier01()` parcourt les `<li>` de `#c3a-thread` (repli `.recit-thread-list`) et pose, via `setOnce`, `aria-posinset="rang"` et `aria-setsize="total"` sur chacun. Le total est calculé depuis `querySelectorAll('li')`, jamais codé en dur.
- **Impact.** Chaque item est énoncé avec sa position absolue (« 3 sur 10 ») dans les modes liste et parcours, y compris quand le marqueur visuel a été supprimé.
- **Risque.** Les attributs sont complémentaires de `aria-current="step"` déjà posé par la vue : aucun conflit. `setOnce` laisse intact tout `aria-posinset` antérieur. Si le fil est vide, le chantier renvoie `{ total: 0 }` sans toucher au DOM.
- **Vérification.** Sur un repère de 10 points, le 3ᵉ `<li>` porte `aria-posinset="3"` et `aria-setsize="10"` ; `getAttribute('role')` reste `listitem` ; aucun style de liste n'est modifié.

## E055-02

- **Problème.** La `<nav class="recit-thread">` porte un `aria-label` générique « Fil du repère », alors qu'un titre visible `.recit-thread-title` contient le nom réel du repère. Les deux peuvent diverger : l'utilisateur qui navigue par régions n'entend pas le libellé qu'il voit.
- **Solution.** `chantier02()` donne un id `e055-thread-title` au titre visible (via `idOf`, qui réutilise un id existant) et ajoute cet id à `aria-labelledby` de la `<nav>` via `addToken`. L'`aria-label` d'origine est conservé comme repli.
- **Impact.** Le nom de la région de navigation est exactement le titre affiché, par exemple « Fil du repère · Traités européens », sans texte inventé.
- **Risque.** Quand `aria-label` et `aria-labelledby` coexistent, ce dernier prévaut : c'est le comportement recherché, mais l'ancien libellé reste disponible si le titre visible venait à disparaître. Le chantier ne fait rien si `.recit-thread-title` est absent.
- **Vérification.** `nav[aria-labelledby]` contient `e055-thread-title`, et cet id appartient bien au `.recit-thread-title` ; `nav.getAttribute('aria-label')` vaut toujours « Fil du repère ».

## E055-03

- **Problème.** La barre `.recit-progress` porte désormais `role="progressbar"` et ses valeurs `aria-valuenow/min/max` (lentille antérieure), mais aucun nom accessible : un lecteur annonce « barre de progression, 3 sur 10 » sans dire ce qui progresse.
- **Solution.** `chantier03()` pose `role="progressbar"` si le rôle manque encore (`setOnce`), relie la barre au kicker `.view-kicker` par `aria-labelledby` (id `e055-kicker`) ou, à défaut, pose `aria-label="Progression de la lecture du récit"`, et ajoute `aria-orientation="horizontal"`.
- **Impact.** La barre est nommée par « Étape 3 / 10 · récit », texte réel du kicker : l'information de progression est comprise sans ambiguïté lors d'une navigation par widgets.
- **Risque.** `setOnce` n'écrase ni un rôle existant ni un nom déjà porté ; `addToken` préserve tout autre `aria-labelledby`. Aucune valeur ARIA n'est recalculée ici, elles restent gérées par la vue.
- **Vérification.** `.recit-progress` porte `role=progressbar`, `aria-orientation=horizontal` et `aria-labelledby=e055-kicker` ; si le kicker est retiré expérimentalement, le repli `aria-label` est présent.

## E055-04

- **Problème.** La pastille `.recit-conf` affiche un symbole (« ✓ », « ■ », « ◐ », « ≈ ») et un mot. Le symbole porta la certitude à la vue ; même nommée par une lentille antérieure, la pastille ne dit pas le niveau sur l'échelle à quatre degrés décrite dans la légende.
- **Solution.** `chantier04()` déduit le niveau du texte visible (✓ → 4/4 « vérifié », ■ → 3/4 « certain », ◐ → 2/4 « probable », ≈ → 1/4 « contesté »), crée le texte caché `e055-conf-detail` (`Niveau de certitude : …, X sur 4. Libellé visible : ….`) juste après la pastille et le relie par `aria-describedby` via `addToken`.
- **Impact.** Le degré de certitude est audible sous forme chiffrée, cohérent avec la légende, y compris pour « disputed » traduit par « contesté ».
- **Risque.** Le texte est caché par la classe `.recit-e055-sr` (1 × 1 px, hors flux) mais **non** marqué `aria-hidden` : il reste bien exposé. L'`aria-label` posé par une autre lentille n'est pas touché ; aucun chiffre n'est inventé si le symbole est inconnu (niveau 0, « non précisée »).
- **Vérification.** Sur une pastille « ■ Certain », le texte caché contient « certain, 3 sur 4 » et `chip[aria-describedby]` contient `e055-conf-detail` ; l'attribut `title` d'origine subsiste.

## E055-05

- **Problème.** Les boutons « Point précédent », « Point suivant », « Recommencer » et « Repère suivant » sont `disabled` aux extrémités du parcours. Leur état est technique : l'utilisateur entend un bouton indisponible sans savoir pourquoi, et doit deviner qu'il est au début ou à la fin du repère.
- **Solution.** `chantier05()` collecte `.recit-actions button[disabled]` et `.recit-thread-item[disabled]`, déduit la raison de l'intitulé réel (« aucun point précédent : vous êtes au début du repère », « aucun point suivant : vous êtes à la fin du repère », etc.), crée un texte caché `e055-indisponible-N` par bouton, le relie par `aria-describedby` et renforce `aria-disabled="true"` via `setOnce`.
- **Impact.** Chaque commande grisée explique son indisponibilité dans le flux accessible, sans modifier son apparence ni son comportement.
- **Risque.** Les boutons nativement `disabled` ne reçoivent pas le focus au Tab ; l'explication reste consultable en mode navigation du lecteur d'écran et n'égare pas le parcours clavier. `fresh()` garantit des ids uniques d'un rendu à l'autre ; aucun attribut `disabled` n'est retiré.
- **Vérification.** Au premier point, le bouton `data-fk="c3a-prev"` porte `aria-disabled=true` et `aria-describedby=e055-indisponible-0`, dont le texte mentionne « début du repère » ; le bouton « Point suivant » reste actif et non décrit.

## E055-06

- **Problème.** La traçabilité est une `<details class="recit-trace">` dont le contenu (identifiants de sources) n'a pas de nom propre, et le `<summary>` n'indique pas qu'il s'agit d'un repli explicable. Quand le point n'a aucune source, le `<p class="recit-sources">` est un simple paragraphe anonymous.
- **Solution.** `chantier06()` nomme les `<details>` « Traçabilité des sources du point », donne au paragraphe de contenu l'id `e055-trace-contenu` et `role="note"`, ajoute au `<summary>` le texte caché `e055-trace-indice` (« appuyez sur Entrée ou Espace pour afficher ou masquer… ») relié par `aria-describedby`, et pointe `aria-controls` vers le contenu. En absence de `<details>`, le paragraphe `.recit-sources` reçoit `role="note"` et `aria-label="Aucune source locale attachée à ce point"`.
- **Impact.** La zone de traçabilité est identifiée comme une note nommée et son mécanisme d'ouverture est explicite au clavier comme au lecteur d'écran, y compris pour les 587 points sans source du jeu de données.
- **Risque.** Le rôle natif de disclosure des `<details>` est préservé : aucun `role` n'est imposé au conteneur lui-même, seulement au paragraphe de contenu. Aucun identifiant de source n'est ajouté ou modifié.
- **Vérification.** Sur un point sourcé, `details[aria-label]`, `p#e055-trace-contenu[role=note]` et `summary[aria-controls=e055-trace-contenu]` sont présents ; sur un point non sourcé, `.recit-sources[role=note][aria-label]` est présent et aucun `<details>` n'est créé.

## E055-07

- **Problème.** `.recit-legend` est un ensemble de paragraphes. Même nommé `role="group"` par une lentille antérieure, il n'apporte aucun titre à la liste des titres du lecteur d'écran : l'aide clavier et la légende des symboles restent introuvables par navigation par titres.
- **Solution.** `chantier07()` insère en tête de la légende un `<h2 class="recit-e055-sr" id="e055-legende-titre">Aide, légende et raccourcis clavier</h2>` et ajoute cet id à `aria-labelledby` du conteneur via `addToken` (le `role="group"` est posé seulement s'il manque).
- **Impact.** La légende devient à la fois un groupe nommé et une entrée de la navigation par titres, sans déplacer ni masquer une seule ligne de texte visible.
- **Risque.** Le titre est visuellement caché mais pas retiré de l'arbre d'accessibilité. Si un `aria-label` antérieur existe, il est conservé ; `aria-labelledby` prend le pas sur lui, ce qui est le but. `fresh()` évite tout titre dupliqué après reconstruction du DOM.
- **Vérification.** La liste des titres contient « Aide, légende et raccourcis clavier » ; `.recit-legend[aria-labelledby]` contient `e055-legende-titre` ; les quatre paragraphes de légende d'origine sont toujours présents et dans le même ordre.

## E055-08

- **Problème.** Les boutons « Point précédent », « Point suivant » et « Recommencer » portent des `aria-keyshortcuts` et modifient tous le `<h1 id="recit-point-title">`, mais rien ne le déclare : un utilisateur de lecteur d'écran ne sait pas quelle zone va changer après activation.
- **Solution.** `chantier08()` réutilise l'id réel du titre (`recit-point-title`, repli `e055-point-titre` via `idOf`) et ajoute cet id à `aria-controls` des boutons repérés par `data-fk="c3a-prev"`, `c3a-next` et `c3a-restart`, via `addToken`.
- **Impact.** La cible de chaque commande de navigation est explicite : l'utilisateur sait que l'activation mettra à jour le point affiché, avant même de l'effectuer.
- **Risque.** Aucun nouvel id n'est créé dans le cas normal puisque le titre porte déjà le sien ; si le titre manque, le chantier ne pose aucun `aria-controls` orphelin. Les `aria-controls` existants sur d'autres lentilles sont préservés par `addToken`.
- **Vérification.** Trois boutons portent `aria-controls=recit-point-title` ; le bouton `data-fk="c3a-chrono"` (changement de vue) n'en reçoit pas ; aucun id `e055-*` n'est référencé qui n'existe pas.

## E055-09

- **Problème.** Le bouton `.recit-play` expose son état par `aria-pressed`, mais la manière de le changer — la touche Espace décrite dans la légende — n'est pas rattachée au bouton. L'information est loin du contrôle, au moment précis où l'utilisateur en a besoin.
- **Solution.** `chantier09()` lit `aria-pressed` du bouton, crée le texte caché `e055-lecture-raccourci` (« appuyez sur Espace pour la mettre en pause » si la lecture est active, « pour la lancer » sinon), l'insère juste après le bouton et le relie par `aria-describedby` via `addToken`.
- **Impact.** L'aide au raccourci est énoncée au moment où le bouton reçoit le focus, sans avoir à revenir à la légende en fin de récit. Ce texte complète — sans le dupliquer — le témoin d'état visible d'une autre lentille.
- **Risque.** Le libellé dépend uniquement de `aria-pressed`, déjà tenu à jour par la vue à chaque rendu : aucune bascule parallèle n'est introduite. Le texte caché n'est pas `aria-hidden`, il est bien lu comme description.
- **Vérification.** Lecture active : `play[aria-pressed=true][aria-describedby]` contient `e055-lecture-raccourci`, dont le texte mentionne « mettre en pause » ; après bascule, le nouveau texte mentionne « lancer ».

## E055-10

- **Problème.** Les neuf enrichissements ci-dessus sont silencieux par construction : rien ne permet de vérifier, sans outil externe, qu'ils ont bien été appliqués au rendu courant ni sur quelle base les libellés ont été calculés.
- **Solution.** `chantier10()` crée un `<section class="recit-e055-panel" id="e055-diagnostic">` marqué `data-recit-diagnostic`, intitulé « E055 — Accessibilité ARIA et lecteurs d'écran · mesures », avec dix paragraphes `e055-mesure-*`. Ils rapportent le rang du fil, le nom du fil, l'état de la barre, le niveau de certitude, les commandes expliquées, la traçabilité, le titre d'aide, l'état de lecture, la préférence `reducedMotion()` et le repère de jeu de données (901 points, 587 sans source). Le panneau est masqué par défaut et remonté dans le tiroir `recit-diagnostics` quand ce dernier est ouvert.
- **Impact.** Bilan falsifiable en un coup d'œil : chaque mesure est dérivée du DOM courant, donc contredifiable par simple relecture du rendu.
- **Risque.** Le panneau est `display:none` hors diagnostic et n'ajoute aucun `aria-live` : il ne provoque aucune annonce parasite. Une incarnation antérieure du même id est retirée avant recréation, ce qui évite les ids dupliqués quand le tiroir déplace le panneau. L'usage de `reducedMotion()` est purement descriptif : E055 ne crée aucune animation.
- **Vérification.** En mode diagnostic, `body.recit-diagnostics #e055-diagnostic` est visible et contient dix paragraphes `e055-mesure-*` ; hors diagnostic, il est masqué ; le nombre de régions live n'augmente pas.
