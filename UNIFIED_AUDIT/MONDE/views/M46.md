# M46 — Vérification statique du Monde

> Hub : `UNIFIED_AUDIT/MONDE/` · Domaine E (qualité & validation) · 10 chantiers, 10 implémentés.
> Fichier possédé : `src/views/monde/M46.js`. Vérification : `node --check src/views/monde/M46.js`.
> Contrat lu : `register('M46', ctx => {…})` ; `ctx = { scene, host, countries, css, el, … }`
> (`src/views/monde/registry.js:6-12`, `:21-23`, `:33-38`).

## Périmètre observé

La vue Monde est reconstruite à chaque `renderGlobe()` (`globe.js:310`), puis les 50
lentilles sont appliquées sur le DOM frais (`globe.js:442` → `registry.js:45-56`). Le
registre neutralise silencieusement un greffon fautif (`registry.js:40-43`), mais il ne
vérifie rien : aucune garantie n'existe sur la présence unique des ancres du Monde ni sur
la cohérence de leurs attributs après superposition des lentilles.

M46 est un **greffon de contrôle** : il n'écrit aucune donnée historique, ne modifie aucun
sélecteur de test (`.globe-list button`, `.globe-country`, `#globe-reveal`, `.event-card`,
…), n'émet aucun `console.*`. Il observe le DOM courant et publie un verdict déterministe
dans `#monde-m46-report` (panneau sr-only, hors `#app` donc survivant au `innerHTML` de la
coque) et dans les attributs `data-m46-*`. La preuve est dans le DOM, pas dans la console.

Ancres relevées dans `globe.js` : `#globe-canvas` (`:267-270`), `#globe-help` (`:273`,
`:278`), `#globe-status` (`:330-333`), `#globe-hover-readout` (`:335-337`), `#globe-title`
(`:370-372`), `#globe-choices` (`:383-385`), `button[data-index]` (`:402`) et `#globe-live`
créé dans `<body>` (`:71-85`, `:368`).

## Les 10 chantiers

### M46-01 — Ancres uniques attendues
- **Preuve** : les ancres ci-dessus sont créées par `globe.js` sans garantie d'unicité ; le registre cumule 50 greffons (`registry.js:54`) qui peuvent, par erreur, réinjecter un ID.
- **Solution** : table `ANCHORS` des sept ancres et de leur balise ; contrôle `document.querySelectorAll('[id="…"]').length === 1` et concordance de `tagName`.
- **Impact** : toute ancre absente, dupliquée ou détournée est détectée avant livraison.
- **Risque** : nul — lecture seule via un sélecteur d'attribut, aucun ID modifié.
- **Effort** : faible.
- **Vérification** : `node --check src/views/monde/M46.js` ; `#monde-m46-report [data-m46-check="M46-01"][data-m46-ok="1"]`.

### M46-02 — Intégrité du host
- **Preuve** : `globe.js:267-270,278` pose `id="globe-canvas"`, `tabindex=0`, `role="group"` et `aria-describedby="globe-help"`. C'est le point de contrôle C2 (c2-orientation-atlas.md).
- **Solution** : lire ces trois attributs sur `ctx.host` et exiger `role=group`, `tabindex=0`, `aria-describedby` strictement égal à `globe-help`. M46 ne réécrit aucun de ces attributs.
- **Impact** : une lentille voisine qui casserait le host est signalée sans être masquée.
- **Risque** : nul — aucune écriture sur le host.
- **Effort** : faible.
- **Vérification** : `node --check` ; détail du contrôle M46-02 dans le panneau.

### M46-03 — Titre unique
- **Preuve** : `globe.js:370-372` crée l'unique `<h1 id="globe-title">Choisir un pays</h1>` ; un second `h1` nuirait à la hiérarchie et à l'indexation.
- **Solution** : compter les `h1` dans le stage et exiger exactement un `h1`, porteur de l'ID `globe-title`.
- **Impact** : la structure de titre de la vue reste auditable et stable.
- **Risque** : le scan est limité au stage, donc un `h1` de la coque hors Monde ne génère pas de faux positif.
- **Effort** : faible.
- **Vérification** : `node --check` ; contrôle M46-03 à `1`.

### M46-04 — Liste des dix pays
- **Preuve** : `globe.js:383-385` crée `<ol id="globe-choices">` ; `:396-423` y injecte un bouton par pays avec `data-index` (`:402`), soit `countries.length` boutons.
- **Solution** : vérifier la balise `<ol>`, la présence dans le stage, le décompte `button[data-index] === countries.length`, et l'unicité + la borne `[0, N-1]` de chaque index.
- **Impact** : ni pays manquant, ni doublon d'index, ni bouton fantôme ne peuvent passer inaperçus.
- **Risque** : nul — `countries` vient du dataset réel transmis par la coque (`globe.js:434`), aucune donnée inventée.
- **Effort** : moyen.
- **Vérification** : `node --check` ; contrôle M46-04 affichant `10/10` et « index uniques et bornés ».

### M46-05 — Régions live conformes
- **Preuve** : `globe.js:76-82` crée `#globe-live` avec `role="status"`, `aria-live="polite"`, `aria-atomic="true"` ; `:330-333` fait de même pour `#globe-status` (`role=status`).
- **Solution** : exiger unicité, `role=status` et `aria-live=polite` sur ces deux nœuds. M46 n'ajoute aucune région live : son rapport est un `role="group"` silencieux, sans `aria-live`.
- **Impact** : aucun doublon d'annonce, aucune région live parasite ajoutée par la vérification.
- **Risque** : nul.
- **Effort** : faible.
- **Vérification** : `node --check` ; contrôle M46-05 à `1`.

### M46-06 — Références ARIA résolvables
- **Preuve** : `globe.js:278` pose `aria-describedby="globe-help"` ; les lentilles (ex. M13 avec `monde-m13-desc`) ajoutent des IDREF. Une référence orpheline casse l'accessibilité.
- **Solution** : parcourir les attributs `aria-describedby`, `aria-labelledby`, `aria-controls` du stage et vérifier que chaque token résout vers exactement un élément par ID.
- **Impact** : les ancres visées par l'ARIA existent et sont uniques — cœur de la règle « ancres uniques ».
- **Risque** : faible — la vérification englobe les IDREF des autres lentilles, ce qui est précisément l'objet du contrôle.
- **Effort** : moyen.
- **Vérification** : `node --check` ; contrôle M46-06 à `1`.

### M46-07 — Aucun ID dupliqué
- **Preuve** : 50 greffons injectent des nœuds à ID (`m09-contexte-badge`, `m17-legend`, `monde-m13-live`, …) ; `registry.js:50-52` accumule leurs callbacks sans dé-duplication des ID.
- **Solution** : collecter tous les `[id]` du stage, ajouter `#globe-live` (qui vit dans `<body>`) et signaler tout ID dont le compte dépasse 1, avec une liste triée déterministe.
- **Impact** : collision d'ancres entre lentilles détectée au lieu de se manifester par un `getElementById` ambigu.
- **Risque** : le rapport lui-même est hors du stage, il ne peut pas s'auto-déclarer en doublon.
- **Effort** : moyen.
- **Vérification** : `node --check` ; contrôle M46-07 à `1`.

### M46-08 — Confinement statique (zéro réseau, zéro inline)
- **Preuve** : la règle du hub (`UNIFIED_AUDIT/MONDE/README.md:57`) interdit réseau et aléas ; `globe-reveal.js` ne charge que des fichiers locaux. Une lentille pourrait glisser un `onclick` ou un `src` distant.
- **Solution** : parcourir les attributs de tous les éléments du stage ; signaler tout attribut `on*` et tout `src`/`href` commençant par `http(s)://` ou `//`. M46 lui-même n'utilise que `textContent`.
- **Impact** : la contrainte « zéro réseau » devient vérifiable statiquement sur la vue rendue.
- **Risque** : nul — lecture seule, aucune modification d'attribut.
- **Effort** : moyen.
- **Vérification** : `node --check` ; contrôle M46-08 à `1` ; `grep -E 'Math\.random|console\.|fetch\(|https?://'` sur `M46.js` vide.

### M46-09 — Rapport déterministe
- **Preuve** : un rapport qui horodaterait ses résultats rendrait la signature instable d'un rendu à l'autre (`Date.now()` est proscrit ici).
- **Solution** : table canonique `CHECK_IDS` des dix contrôles ; la signature est `id=1|id=0…`, calculée uniquement depuis les résultats dérivés du DOM, sans date ni aléa. Le contrôle vérifie que la liste produite correspond exactement à la table et que la signature est reproductible.
- **Impact** : deux rendus du même DOM donnent exactement le même rapport.
- **Risque** : nul — aucune source de non-déterminisme introduite.
- **Effort** : faible.
- **Vérification** : `node --check` ; `data-m46-signature` identique après deux rendus ; contrôle M46-09 à `1`.

### M46-10 — Nœud de rapport idempotent et autonome
- **Preuve** : `registry.js:54` rejoue les 50 greffons à chaque `renderGlobe()` ; un nœud recréé à chaque fois laisserait des doublons ou des nœuds déconnectés (cf. M13-09).
- **Solution** : un seul `#monde-m46-report` (garde `byId` + `isConnected`), sr-only, `role="group"`, `aria-label`, appendé à `<body>` ; contenu reconstruit de façon idempotente (liste vidée puis remplie), compteurs exposés en `data-m46-total/passed/failed/signature/version`. Le contrôle valide l'unicité et la cohérence des compteurs après construction. CSS unique via `ctx.css('monde-m46', …)`.
- **Impact** : navigation aller-retour sans rapport dupliqué, sans annonce parasite, sans toucher aux sélecteurs de test.
- **Risque** : nul — le panneau est hors `#app`, il ne participe pas au rendu de la coque.
- **Effort** : moyen.
- **Vérification** : `node --check` ; trois allers-retours Monde → pays → Monde : un seul `#monde-m46-report`, `data-m46-total="10"`.
