# M30 — États vides du globe (domaine C : ergonomie & interaction)

Lentille : M30. Fichier possédé : `src/views/monde/M30.js`.
Lectures seules : `src/views/globe.js`, `src/views/monde/registry.js`, `src/domain/store.js`, `UNIFIED_AUDIT/MONDE/README.md`.
Aucun fichier partagé modifié, aucun réseau, aucun `Math.random`, aucun `console.*`, aucun timer, aucune boucle `requestAnimationFrame`.

**Contrat reçu.** `register('M30', (ctx) => { … })` avec uniquement `{ scene, host, countries, state, css, el, say }`. Le greffon n'appelle donc ni `reveal`, ni `selectCountry`, ni le moteur WebGL : il observe le DOM déjà produit par `globe.js` et dérive un état vide déterministe.

**Ancrage dans `globe.js`.** La scène est recréée à chaque rendu (`const scene = el('div', 'globe-scene')`, globe.js:317) et reçoit le `host` réutilisé par `ensure()` (globe.js:263-292, 319). Le HUD porte `#globe-status` (globe.js:329-333, `data-kind` = `busy` / `error` / `ready`) et `#globe-hover-readout` (globe.js:335-337, texte initial « Survol : aucun pays sous le pointeur »). `syncEngine()` pose `host.dataset.globeActive` (globe.js:153-169). Ces signaux, avec `state.countryId` et `ctx.countries`, épuisent les faits disponibles : aucune valeur n'est inventée.

## M30-01 — Un seul panneau d'état vide, ID unique, réancré à chaque rendu

- Preuve : `runMondeEnhancements()` rejoue les greffons à chaque rendu de la coque (globe.js:442, registry.js:45-56). La scène étant un élément neuf à chaque fois, un panneau créé sans garde serait dupliqué ou laissé dans une scène détachée.
- Solution : `#monde-m30-empty` retrouvé par `document.getElementById`, créé sinon, puis déplacé dans la `ctx.scene` courante si son parent a changé. CSS unique via `ctx.css('monde-m30', …)` (registry.js:25-31). Aucun sélecteur de test modifié.
- Impact : au plus un panneau dans le document, visible ou masqué selon l'état dérivé.
- Risque : un ancien panneau détaché pourrait être réutilisé à tort ; la comparaison `node.parentNode !== ctx.scene` force le réancrage, et l'absence de `getElementById` force une recréation.
- Effort : S
- Vérification : après trois rendus successifs, `document.querySelectorAll('#monde-m30-empty').length === 1` et le nœud appartient à la scène courante.

## M30-02 — Jeu de données vide : aucun pays documenté

- Preuve : `ctx.countries` est `DATASET.countries` (globe.js:434). S'il est vide, l'orientation affiche « 0 pays » et la liste n'a aucune entrée : c'est un état vide fondamental.
- Solution : si `Array.isArray(ctx.countries)` est vrai et que sa longueur vaut 0, l'état dérivé est `no-countries`, avec un message qui ne promet aucune sélection possible.
- Impact : l'utilisateur comprend immédiatement pourquoi la liste est vide, sans croire à un défaut de chargement réseau.
- Risque : un `ctx.countries` absent (non tableau) ne doit pas être confondu avec un jeu vide ; le greffon le traite comme vide par prudence mais n'invente aucun chiffre.
- Effort : S
- Vérification : avec `countries: []`, le panneau porte `data-state="no-countries"` et son titre est « Aucun pays documenté ».

## M30-03 — Sélection périmée : identifiant présent mais introuvable

- Preuve : `state.countryId` est validé à l'écriture par `coerce()` (store.js:92-94), mais une sélection peut devenir orpheline si le jeu de données évolue ; `selectedCountry()` ne trouve alors aucun pays.
- Solution : si `state.countryId` est renseigné et qu'aucun pays de `ctx.countries` ne porte cet `id`, l'état est `stale-selection` et le message invite à choisir un pays dans la liste, sans afficher l'identifiant.
- Impact : pas de fiche vide ni de titre fantôme ; le repli est explicite et actionnable.
- Risque : comparer par `id` (et non par `code`) est obligatoire : `code` sert au picking, `id` à la sélection (store.js:272-280).
- Effort : S
- Vérification : avec `state.countryId = 'inconnu'`, le panneau porte `data-state="stale-selection"`.

## M30-04 — Canvas absent : aucune sphère affichée

- Preuve : `globe.js:249` cherche `canvas.globe-webgl` puis tout `canvas` dans le `host` ; si le moteur n'en crée pas, la scène ne contient aucune surface de rendu.
- Solution : absence de canvas dans `ctx.host` après les états bloquants → `no-canvas`, avec rappel que la liste et les flèches restent disponibles.
- Impact : l'espace laissé par la sphère n'est plus un vide incompréhensible ; il porte une explication.
- Risque : au tout premier rendu, le canvas peut ne pas encore exister alors que le moteur initialise ; l'état `busy` est testé avant (M30-06) pour ne pas afficher une fausse erreur.
- Effort : S
- Vérification : retirer le canvas du host → `data-m30-state="no-canvas"` ; le remettre → l'état change.

## M30-05 — Moteur 3D indisponible : repli guidé

- Preuve : `setStatus()` (globe.js:139-146) écrit `data-kind="error"` quand `THREE` ou le moteur manque, avec le texte réel « Moteur 3D indisponible : sélection par la liste des pays. » (globe.js:478-480).
- Solution : lire `data-kind` de `#globe-status` ; `error` donne l'état `webgl-unavailable`, dont le message renvoie vers la liste et le clavier, exactement comme le HUD, sans ajouter de cause supposée.
- Impact : un seul discours cohérent entre le HUD et le panneau, sans double annonce (le HUD annonce déjà l'erreur via `say()`).
- Risque : l'état `error` est prioritaire sur l'absence de canvas : c'est la cause, pas le symptôme, qui doit être montrée.
- Effort : S
- Vérification : forcer `data-kind="error"` sur `#globe-status` → le panneau affiche « Rendu 3D indisponible ».

## M30-06 — Chargement en cours : état transitoire non alarmant

- Preuve : avant l'initialisation, le HUD porte `data-kind="busy"` et « Chargement du globe local… » (globe.js:327-332).
- Solution : `busy` donne l'état `loading`, visible mais non annoncé : l'initialisation est brève et `setStatus()` n'annonce pas les états `busy`, éviter une succession d'annonces inutiles.
- Impact : l'utilisateur sait que le globe va apparaître et que la liste est déjà utilisable.
- Risque : un `data-kind` obsolète après la mise à jour du moteur ; le `MutationObserver` (M30-09) recalcule dès que l'attribut change.
- Effort : S
- Vérification : au premier rendu, le panneau est `data-state="loading"` ; après `onReady`, il passe à un autre état sans erreur console.

## M30-07 — Aucun pays choisi : invitation chiffrée depuis le jeu de données

- Preuve : l'orientation affiche « Aucun pays sélectionné » quand `state.countryId` est nul (globe.js:376-379), mais elle ne dit pas combien de pays sont disponibles.
- Solution : en l'absence de sélection valide et une fois le moteur prêt, l'état `no-selection` propose de choisir un pays « parmi les N documentés », où N est `ctx.countries.length`, valeur réelle du jeu de données.
- Impact : un état vide orientant vers l'action, avec une mesure vérifiable plutôt qu'une affirmation vague.
- Risque : afficher « 0 pays » serait contradictoire avec M30-02 ; cet état n'est atteint que si `countries.length > 0`.
- Effort : S
- Vérification : avec 10 pays et `countryId = null`, le message contient exactement le nombre issu de `ctx.countries.length`.

## M30-08 — Scène inactive : pause sans alarme

- Preuve : `syncEngine()` pose `host.dataset.globeActive` à `1` uniquement si `inView && !paused && state.view === 'globe'` (globe.js:153-169) ; en mouvement réduit ou hors écran, la valeur reste `0` et aucune frame n'est rendue.
- Solution : si le canvas existe mais que `globeActive !== '1'`, l'état `inactive` indique sobrement l'absence de rendu et rappelle la disponibilité de la liste.
- Impact : cohérence avec la pause réelle du moteur, sans présenter une situation normale comme une panne.
- Risque : ne jamais appeler `open()`, `close()` ni `invalidate()` : la propriété du cycle reste à `syncEngine()` (globe.js:153-169).
- Effort : S
- Vérification : passer `data-globe-active` à `0` puis `1` sur le host → l'état dérivé suit sans modifier le marqueur.

## M30-09 — Survol vide et ordre de priorité déterministe

- Preuve : `#globe-hover-readout` vaut « Survol : aucun pays sous le pointeur » tant qu'aucun pays n'est survolé (globe.js:335-337) ; ce texte change au survol piloté par `highlight()` (globe.js:185-200).
- Solution : lire ce texte et produire `no-hover` quand il est vide ou commence par « Survol : aucun ». Un unique `MutationObserver` sur `ctx.scene` (attributs `data-kind`, `data-globe-active`, `data-globe-selected`, `childList`, `characterData`, `subtree`) recalcule l'état à chaque changement, sans polling ni timer. L'ordre de priorité est figé : `no-countries` → `stale-selection` → `webgl-unavailable` → `loading` → `no-canvas` → `no-selection` → `inactive` → `no-hover` → `none`.
- Impact : un seul état affiché à la fois, reproductible, même si plusieurs conditions vides sont vraies simultanément.
- Risque : les écritures du greffon déclenchent l'observateur ; toutes les écritures sont conditionnées à une différence réelle (`dataset`, `hidden`, `textContent`), donc la boucle s'éteint après une passe.
- Effort : M
- Vérification : injecter simultanément `data-kind="error"` et un survol vide → c'est bien `webgl-unavailable` qui s'affiche ; après stabilisation, aucune mutation supplémentaire n'est générée par le greffon.

## M30-10 — Annonce live dédupliquée, miroir auditable et contraintes strictes

- Preuve : `ctx.say` écrit dans l'unique région `#globe-live` (globe.js:73-85, 148-150) ; une seconde région live annoncerait deux fois le même changement (cf. M14). Le panneau est donc un `role="group"` non live, et `say` est le seul canal d'annonce.
- Solution : annoncer uniquement lors d'un changement de clé d'état, et seulement pour les états bloquants (`no-countries`, `stale-selection`, `no-canvas`, `webgl-unavailable`, `no-selection`) ; `lastAnnounced` est réinitialisé au retour d'un état non bloquant pour permettre une nouvelle annonce. Miroir `host.dataset.m30State` et `panneau.dataset.state` pour audit. Zéro `Math.random`, zéro réseau, zéro `console.*`, zéro timer, zéro rAF.
- Impact : annonce non dupliquée, état lisible par un test sans instrumentation, aucune charge CPU en arrière-plan.
- Risque : le registre garde ses callbacks et rejoue le greffon ; le panneau et l'observateur sont réancrés (M30-01, M30-09), et l'annonce est protégée par la clé, pas par le nombre d'appels.
- Effort : M
- Vérification : `node --check src/views/monde/M30.js` passe ; `grep -nE 'console|Math.random|fetch|XMLHttpRequest|setTimeout|setInterval|requestAnimationFrame' src/views/monde/M30.js` ne renvoie aucune ligne ; deux rendus identiques ne produisent qu'une annonce.

## Statut d'implémentation

Les 10 chantiers sont implémentés dans `src/views/monde/M30.js`. Un seul panneau `#monde-m30-empty`, CSS injecté une fois via `ctx.css('monde-m30', …)`, un seul `MutationObserver` réancré sur la scène courante, une seule annonce par transition via `ctx.say`. Aucun fichier interdit modifié. Aucune donnée historique inventée : seuls `ctx.countries`, `state.countryId` et les textes/attributes réellement présents dans le DOM de `globe.js` sont lus.

## Blocages

- Aucun bloquant. M30 ne possède ni `globe.js` ni les callbacks `onHover`/`onReady` : l'observation du DOM rendu par `globe.js` est le seul chemin disponible avec le contrat reçu. C'est aussi le plus sûr : le greffon ne pilote ni le moteur WebGL, ni la sélection, ni la révélation du masque.
- Les états `loading`, `inactive` et `no-hover` sont visibles mais non annoncés (M30-10) : ce sont des situations transitoires ou nominales, et les annonces seraient redondantes avec le HUD et le live global.
