## M39-01 — Situation macro absente de la scène Monde

- **Titre** : la vue Monde ne dit ni son niveau ni la question qu'elle sert.
- **Preuve** : `globe.js:370-373` pose `<h1>Choisir un pays</h1>` puis un sous-titre figé, sans mot « Monde », sans niveau, sans `role`. La situation ne vit que dans la coque : `shell.js:132-142` (`pathParts`) et `:144-150` (`situationText`, « vue d’ensemble »). `app.js:21-28` porte pourtant `level: 1` et `role: 'Quels pays sont documentés ?'`.
- **Solution** : `p#m39-position` rend « Vous êtes ici : Monde · niveau 1 sur 6 · Quels pays sont documentés ? », dérivé de `position()` quand elle est disponible et de l'entrée `globe` de la taxonomie sinon.
- **Impact** : la question macro est lisible dans la scène, pas seulement dans la barre.
- **Risque** : doublon visuel avec `.shell-situation` ; le panneau est en fin de colonne de décision et non `aria-live`, donc aucun doublage vocal.
- **Effort** : S.
- **Vérification** : relecture — `#m39-position` contient « niveau 1 sur 6 » et le `role` exact de `app.js:22`.

## M39-02 — Catalogue figé mais invisible de la vue

- **Titre** : les six niveaux macro → micro existent dans l'API, jamais dans le rendu du globe.
- **Preuve** : `app.js:21-28` définit `VIEW_TAXONOMY` (6 entrées `{ id, label, digit, letter, level, role }`) et `:135` l'expose ; `grep taxonomy` dans `src/views/globe.js` ne renvoie aucun usage. Le README (`README.md:73-80`) documente le même tableau, mais la vue ne le reflète pas.
- **Solution** : `ol#m39-ladder` énumère les six vues : `Niveau k · libellé (chiffre/initiale) — question servie`. Libellés, raccourcis et questions sont lus dans `window.VATLAS.taxonomy`, jamais recopiés d'un autre module.
- **Impact** : le modèle mental devient une donnée lisible en navigation, sans ouvrir l'aide.
- **Risque** : divergence si une autre surface change `VIEW_TAXONOMY` sans répercuter la coque (règle `app.js:14-16`) : M39 reflète l'API, il ne l'arbitre pas.
- **Effort** : M.
- **Vérification** : relecture — six `<li>`, un seul `aria-current="location"` (M39-03).

## M39-03 — Fil local défini mais jamais appelé

- **Titre** : le fil de situation propre au globe est du code mort ; le fil réel est celui de la coque.
- **Preuve** : `globe.js:88-108` définit `buildGlobeTrail()` et le nœud `#nav-c2b-trail` avec `aria-current="location"`, mais un `grep -rn buildGlobeTrail src/` ne renvoie que la définition. Le fil effectif est `shell.js:415-443` : `aria-current="page"` (`:429`) et une destination unique pour tous les crumbs non terminaux (`:433` : racine ou `VIEW_TAXONOMY[1]`).
- **Solution** : le fil d'échelle `#m39-ladder` porte la convention `aria-current="location"` retenue en C2-07 pour les fils locaux ; ses crumbs sont du **texte réel non cliquable**, donc aucune cible ambiguë ne s'ajoute.
- **Impact** : un fil stable et adressable, complémentaire du fil global sans le dupliquer.
- **Risque** : blocage partiel — corriger le fil global exigerait `shell.js` (fichier interdit) ; documenté, non contourné.
- **Effort** : S.
- **Vérification** : `document.querySelectorAll('#m39-ladder [aria-current="location"]').length === 1`.

## M39-04 — Compteurs figés ou divergents

- **Titre** : la vue affiche des nombres en dur qui ne concordent pas avec les sources du projet.
- **Preuve** : `globe.js:373` : « Dix histoires documentées, 784 cellules de couverture vérifiées ». `README.md:110` : « 901 points ». `app.js:35` : « 845 au total ». `dataset.js` : `meta.points = 1746`, `meta.validatedPoints = 845`. - **Solution** : M39 n'écrit aucun compteur en dur. `p#m39-counts` additionne `eras`, `events` et `points` des pays reçus dans `ctx.countries` ; les chiffres sont recalculés à chaque rendu.
- **Impact** : toute affirmation chiffrée est falsifiable depuis les données, sans inventaire manauel.
- **Risque** : la divergence README (901) / API (845) / méta (1746) subsiste : M39 l'expose sans trancher, les fichiers concernés n'étant pas possédés.
- **Effort** : S.
- **Vérification** : relecture — la ligne affiche `10 pays · 56 ères · 229 repères · 845 points`, sommes vérifiables dans `dataset.js`.

## M39-05 — Vocabulaire normatif hors de portée de la vue

- **Solution** : `dl#m39-lexicon` rend les sept couples `<dt>`/`<dd>` verbatim depuis `window.VATLAS.lexicon`, dans un ordre stable (ordre des clés de l'API).

- **Risque** : la définition « point » de l'API dit 845, celle du README dit 901 (M39-04) : M39 reproduit l'API et documente l'écart.
- **Effort** : S.
- **Vérification** : relecture — sept `<dt>`, sept `<dd>`, textes identiques à `app.js:31-39`.

## M39-06 — Premier rendu avant publication de l'API publique

- **Titre** : `window.VATLAS` n'existe pas encore quand les greffons s'appliquent la première fois.
- **Preuve** : `app.js:126` appelle `mount()` avant `:132` `window.VATLAS = {…}` ; `shell.js:529` `render()` reconstruit le DOM (`:533`) et appelle `renderGlobe()` (`:540`), lequel exécute `runMondeEnhancements()` en `globe.js:442`.
- **Solution** : getters défensifs (`taxonomy()`, `lexicon()`, `version()`, `snapshot()`) lisant `window.VATLAS` avec un repli local **strictement identique** à `app.js:17-39` — même motif que `keyboard.js:18-25` pour éviter l'import circulaire.
- **Impact** : panneau correct au premier rendu comme aux suivants, sans import de `app.js` ni de `dataset.js`.
- **Risque** : le miroir de repli peut dériver si la taxonomie change ; les getters lui préfèrent toujours l'API dès qu'elle est publiée, et la dérive est détectable par relecture.
- **Effort** : M.
- **Vérification** : relecture — `window.VATLAS?.taxonomy` lu à chaque appel, repli figé `m4.2` / 6 entrées / 7 termes.

## M39-07 — Rendus répétés : unicité du panneau

- **Titre** : la coque détruit le DOM à chaque émission du store, pas les tableaux du registre.
- **Preuve** : `shell.js:533` `root.innerHTML = ''` ; `registry.js:45-63` réapplique les greffons à chaque rendu, mais purge ses callbacks (`:46-50`) et injecte le CSS une seule fois via `cssOnce` (`:25-31`).
- **Solution** : ID unique `#m39-situation`, retrait du panneau précédent avant réinsertion, CSS par `ctx.css('monde-m39', …)`, aucun écouteur, aucun état module persistant ; les rappels `onHover`/`onLeave` réinterrogent `document.getElementById` à chaque appel.
- **Impact** : exactement un panneau par rendu, aucune fuite de nœud ni d'écouteur.
- **Risque** : un rappel encore actif entre deux rendus peut écrire brièvement dans un nœud détaché ; le garde d'existence le neutralise.
- **Effort** : S.
- **Vérification** : relecture — garde `previous.remove()`, `ctx.css`, absence de `addEventListener`.

## M39-09 — Ancrage micro → macro sans doublage vocal

- **Titre** : le pays sélectionné ou survolé n'est pas relié à l'échelle dans le panneau.
- **Preuve** : `globe.js:376-378` affiche « Sélection courante » dans `.globe-here` ; `highlight()` notifie `notifyMondeHover` en `:193` et le moteur le notifie en `:455`. M17 fournit déjà une légende visuelle, M20 les annonces live.
- **Solution** : `p#m39-anchor` dérivé de `ctx.state.countryId` et `ctx.countries` (avec repli sur `ctx.selected`), mis à jour par `ctx.onHover` / `ctx.onLeave` en texte ordinaire, sans `aria-live` et sans `say()`.
- **Impact** : le lien entre le pays pointé et le niveau 1 reste lisible, sans bavardage ni doublon de légende.
- **Risque** : plusieurs rappels de rendus différents peuvent écrire dans le même nœud ; ils ne portent aucun état propre et le plus récent s'exécute en dernier, donc l'affichage converge.
- **Effort** : S.
- **Vérification** : relecture — `Ancrage : aucun pays sélectionné` au chargement sans sélection ; pays courant sinon.

## M39-10 — Placement visuel et traçabilité du modèle
