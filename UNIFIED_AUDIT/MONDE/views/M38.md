## Thèse

Le store sait déjà coder, valider et réfléchir un état dans le hash
(`store.js:544-664`, chantier T4-09), et `globe.js:433-442` transmet aux
lentilles le contexte complet (`selected`, `countries`, `state`, `say`). Mais la
vue Monde n'offre aucun geste pour **obtenir le lien d'un pays** : le bouton de
partage et son annonce étaient explicitement laissés aux surfaces `c1`/`t1`
(`t4-etat-atlas.md:136`, `c1-deeplink-poc.md:143-156`). M38 comble ce vide dans
le seul fichier de la lentille : un panneau « Lien local du pays » dérivé de la
sélection réelle, encodé par la fonction canonique du store, copiable par un
bouton accessible avec repli hors presse-papiers.

<a id="m38-01"></a>
## M38-01 — Absence de sélection : état explicite, bouton désactivé

- **Problème (preuve).** `store.js:40-63` : `countryId` vaut `null` au démarrage ;
  `globe.js:376-381` affiche alors « Aucun pays sélectionné ». Un lien « du pays »
  n'a pas de sens sans pays : le construire produirait `c=` (vide) ou un pays
  arbitraire, donc une donnée inventée.
- **Solution concrète.** Si `ctx.selected` est absent, le champ est vidé, le
  bouton reçoit `disabled = true`, et le statut porte « Aucun pays sélectionné :
  choisissez un pays pour obtenir son lien. » Aucun lien n'est fabriqué.
- **Impact sur l'évidence.** L'état vide est lisible et vocalisé ; le parcours
  « choisir un pays puis copier » reste le seul chemin vers un lien valide.
- **Risque.** Un `selected` périmé (pays retiré du `DATASET`) serait encore lié :
  on résout toujours le pays par identité dans `ctx.countries` avant d'écrire.
- **Effort.** S.
- **Vérification.** Ouvrir le globe sans sélection : champ vide, bouton grisé,
  message présent ; sélectionner un pays : le champ se remplit.

<a id="m38-02"></a>
## M38-02 — Lien dérivé de l'état réel, encodage canonique du store

- **Problème (preuve).** `store.js:550-564` définit la grille canonique
  (`v,c,e,r,p,l,s,fd,ff,d,h`) ; `store.js:566-609` la valide. Recoder une autre
  grille dans la lentille produirait des liens que `hydrateFromHash()` refuserait.
- **Solution concrète.** Construire un instantané minimal à partir de
  `selected.id` (unique identifiant du `DATASET`), avec la vue `globe` et les
  indices/initiaux déclarés par `selectCountry()` (`store.js:272-280`), puis
  appeler `formatDeepLink(snapshot)` importé du store. Le nom, le code, les ères
  et les repères ne sont jamais recopiés à la main dans l'URL.
- **Impact sur l'évidence.** Le lien collé est accepté par `parseDeepLink()` et
  restaure le pays dans la vue Monde (`v=globe&c=<id>`).
- **Risque.** Le hash réfléchi par le store (`store.js:633-647`) continue d'écrire
  l'état courant : le lien de pays est un sous-ensemble volontaire et stable de
  cet état, pas une copie de l'URL affichée à l'instant T.
- **Effort.** S.
- **Vérification.** `parseDeepLink()` sur le lien généré rend `view === 'globe'`
  et `countryId === selected.id`.

<a id="m38-03"></a>
## M38-03 — URL locale depuis `location.href`, aucun réseau

- **Problème (preuve).** `t4-etat-atlas.md:135` : la réflexion du hash est un
  `history.replaceState` local. Un lien de partage ne doit ni charger une
  ressource, ni changer de domaine, ni encoder un serveur.
- **Solution concrète.** Lire `window.location.href`, remplacer uniquement le
  fragment par le hash canonique via `URL`/`url.hash = encoded`. Repli
  déterministe en cas d'échec de `URL` : concaténer la partie avant `#` et le
  hash encodé. Aucun `fetch`, `XMLHttpRequest`, `src` distant ni `@import`.
- **Impact sur l'évidence.** Le lien est l'URL de la page courante ; il fonctionne
  aussi en `file://`, où `replaceState` peut être refusé (`store.js:640-645`).
- **Risque.** Un `location.href` vide ou hostile est cadré par le `try/catch` et
  le repli sur une base vide : aucun appel réseau n'est tenté.
- **Effort.** S.
- **Vérification.** Le lien commence par la même origine que la page ; aucune
  requête réseau n'apparaît lors de la génération ni de la copie.

<a id="m38-04"></a>
## M38-04 — Champ en lecture seule, non éditable, étiqueté

- **Problème (preuve).** `c1-deeplink-poc.md:145-156` : un lien inaccessible quand
  le presse-papiers échoue. Sans champ visible, le partage dépend entièrement du
  navigateur.
- **Solution concrète.** `<input type="text" readonly>` portant un `aria-label`
  explicite, valeur égale au lien local. Le readonly garantit que l'utilisateur
  ne peut pas modifier l'état encodé ; il peut en revanche sélectionner le texte.
- **Impact sur l'évidence.** Le lien est toujours lisible et sélectionnable, y
  compris sans javascript de copie fonctionnel.
- **Risque.** Un champ trop étroit tronque visuellement l'URL : CSS `min-width:0`
  et `flex:1` permettent le défilement horizontal sans casser la grille.
- **Effort.** S.
- **Vérification.** Le champ affiche l'URL complète ; toute tentative de saisie
  laisse la valeur inchangée.

<a id="m38-05"></a>
## M38-05 — Bouton « Copier le lien » accessible et idempotent

- **Problème (preuve).** `registry.js:45-56` : `apply` est rejoué à chaque
  `renderGlobe()` ; un attachement d'écouteur sans garde duplique les handlers sur
  un nœud réutilisé. Les sélecteurs de test (`.globe-country`, `#globe-choices`)
  sont intouchables (`MONDE/README.md:56`).
- **Solution concrète.** Bouton natif `<button type="button">`, `aria-label`
  stable, cible ≥ 36 px. Un pointeur module `boundButton` n'attache le geste que
  si le nœud diffère du précédent. Le panneau est ajouté à `.globe-list` (sinon
  au `stage`) sans modifier les nœuds existants.
- **Impact sur l'évidence.** Un clic = une seule copie ; le rendu répété ne crée
  ni doublon de panneau ni doublon d'annonce.
- **Risque.** Si la coque ne reconstruit pas le `stage`, le garde `isConnected`
  empêche de réutiliser un nœud détaché.
- **Effort.** S.
- **Vérification.** Naviguer deux fois vers le globe : un seul `#monde-m38-panel`
  dans le DOM, une seule annonce par clic.

<a id="m38-06"></a>
## M38-06 — Copie via `navigator.clipboard` avec état visible et annoncé

- **Problème (preuve).** `c1-deeplink-poc.md:145-150` : le `toast()` générique ne
  change pas l'état du bouton et n'annonce rien dans une région dédiée.
- **Solution concrète.** `navigator.clipboard.writeText(lien)` dans un `try/catch`
  avec `await` ; en succès, le bouton passe au libellé « Lien copié » (~2,4 s,
  minuteur module remis à zéro à chaque rendu) et le statut visible dit
  « Lien copié dans le presse-papiers. » ; `ctx.say()` porte la même information
  dans la région live globale de `globe.js`.
- **Impact sur l'évidence.** La confirmation est visible, textuelle (jamais la
  seule couleur) et vocalisée, sans dépendre d'un toast éphémère.
- **Risque.** Le presse-papiers est souvent refusé hors contexte sécurisé :
  l'échec bascule proprement en M38-07 au lieu de lever une exception.
- **Effort.** M.
- **Vérification.** Cliquer « Copier le lien » : le presse-papiers contient l'URL,
  le libellé change, la région live est mise à jour ; aucune erreur console.

<a id="m38-07"></a>
## M38-07 — Repli sans presse-papiers : champ focalisé et sélectionné

- **Problème (preuve).** `t4-etat-atlas.md:135` et `c1-deeplink-poc.md:153-156` :
  en `file://` ou sans API clipboard, le lien doit rester récupérable.
- **Solution concrète.** Si l'API est absente ou si `writeText` rejette, on
  focalise le champ en lecture seule, on appelle `select()`, et le statut indique
  « Presse-papiers indisponible : le lien est sélectionné, copiez-le avec Ctrl+C.
  » Aucune API dépréciée (`execCommand`) n'est utilisée.
- **Impact sur l'évidence.** Le geste de secours est explicite et clavier :
  `Ctrl+C` fonctionne dès que le champ est sélectionné.
- **Risque.** `select()` peut échouer sur un champ masqué : le panneau reste
  toujours visible quand un pays est sélectionné, donc le repli est effectif.
- **Effort.** S.
- **Vérification.** Forcer l'absence de `navigator.clipboard` : le champ reçoit le
  focus, sa sélection est non vide, le message de repli est affiché et annoncé.

<a id="m38-08"></a>
## M38-08 — RAfraîchissement à chaque rendu + annonce de restauration

- **Problème (preuve).** `globe.js:310-427` reconstruit la vue à chaque changement
  d'état ; un lien figé au premier rendu ne suit plus la sélection. Inversement,
  `store.js:611-631` hydrate le pays depuis le hash sans le dire à la vue Monde.
- **Solution concrète.** À chaque `apply`, relire `ctx.selected`, résoudre le pays
  dans `ctx.countries`, et réécrire la valeur du champ (pas de `innerHTML`, seulement
  `value`). Une fois seulement, si `parseDeepLink(location.hash)` indique
  `countryId === selected.id`, annoncer « Lien local ouvert : pays <nom>. »
  (`restoreAnnounced` garde l'unicité).
- **Impact sur l'évidence.** Le lien suit la sélection ; arriver par un lien est
  annoncé, comme le demandait T4-09/C1-10.
- **Risque.** Le hash réfléchi contient `c=<id>` même sans lien externe : le
  garde-fou évite de sur-annoncer à chaque rendu.
- **Effort.** M.
- **Vérification.** Changer de pays puis revenir au globe : le champ affiche le
  nouvel id ; un chargement avec `#v=globe&c=<id>` annonce une seule fois.

<a id="m38-09"></a>
## M38-09 — Accessibilité : `say`, libellés uniques, régions live non dupliquées

- **Problème (preuve).** `globe.js:73-85,148-150` : `say()` écrit dans `#globe-live`,
  hors de `#app` pour survivre au `innerHTML` de la coque. Créer une seconde
  région live concurrente produirait des annonces doubles.
- **Solution concrète.** Le statut visible est un `<p>` simple (pas de
  `aria-live`) ; seule `ctx.say()` vocalise. IDs uniques préfixés `monde-m38-`,
  `aria-label` distincts pour le champ et le bouton, focus visible au clavier,
  information portée par le texte du statut et du bouton.
- **Impact sur l'évidence.** Une et une seule annonce par action, cohérente avec
  les autres lentilles (M13 utilise le même schéma).
- **Risque.** `globe.js:474,483` vide parfois `#globe-live` après l'init WebGL :
  le statut visible reste, ce qui couvre le cas sans dégrader le direct.
- **Effort.** S.
- **Vérification.** Avec lecteur d'écran, une copie produit une seule phrase ;
  les libellés du champ et du bouton sont distincts et non vides.

<a id="m38-10"></a>
## M38-10 — Garde-fous : un panneau, zéro aléa, zéro console, CSS idempotent

- **Problème (preuve).** `MONDE/README.md:52-58` : une lentille ne touche qu'à son
  fichier, ne modifie aucun sélecteur de test, n'introduit ni réseau ni aléa ni
  `console.*`.
- **Solution concrète.** `ctx.css('monde-m38', …)` injecté une seule fois via
  `cssOnce` (`registry.js:25-31`) ; un seul panneau gardé par ID et `isConnected` ;
  aucun `Math.random`, aucun `console`, aucune dépendance à une heure ou à
  `performance.now()` ; le minuteur de « copié » est le seul état temporaire et
  il est borné et nettoyé.
- **Impact sur l'évidence.** La lentille est neutralisable par le registre sans
  casser le rendu ; `node --check src/views/monde/M38.js` suffit à la validation
  statique demandée par la vague.
- **Risque.** Le `import { formatDeepLink, parseDeepLink }` lit le store sans
  l'écrire : l'auto-amorçage des deep links y est déjà actif (`store.js:664`),
  aucun effet de bord supplémentaire n'est introduit.
- **Effort.** S.
- **Vérification.** `node --check` vert ; recherche de `console|Math.random|fetch`
  dans `M38.js` : 0 occurrence ; un seul `#monde-m38-panel` après plusieurs
  rendus.

   M38 se contente de les consommer.
