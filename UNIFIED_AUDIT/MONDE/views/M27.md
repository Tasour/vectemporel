## M27-01 — Aucun accès textuel direct aux dix pays

- **Problème** : la liste des pays est un simple `<ol>` de dix boutons ; aucun champ ne permet de joindre un pays par son nom, son code, une ère ou un repère.
- **Preuve** : `globe.js:369-383` construit le titre, le sous-titre, l'orientation puis `#globe-choices` ; `globe.js:396-419` y ajoute les dix boutons. Aucun `input` n'est créé dans la vue Monde, alors que la Chronologie expose une recherche locale (cf. `UNIFIED_AUDIT/NAVIGATION/views/c3-recherche-atlas.md`, C3-01).
- **Solution** : `#m27-search` (`input[type=search]`, `data-fk=m27-search`, `aria-controls=globe-choices`) inséré dans `.globe-list` juste avant la liste. L'index est construit uniquement avec les champs réels de `dataset.js` : `name` (`:18`), `code` (`:21`), `id` (`:17`), noms d'ères (`:130`) et titres de repères (`:204`). Plusieurs termes se combinent en ET ; les termes sont repliés (M27-05).
- **Impact** : « egypte », « EG », « japon », « meiji » ou « revolution » joignent immédiatement la bonne entrée ; aucun texte rédigé, aucune traduction, aucune donnée nouvelle.
- **Effort** : M
- **Vérification** : relecture de `searchText()` / `matches()` ; contrôle sur le jeu de données réel : `egypte` → EG, `EG` → EG, `japon` → JP, `meiji` → JP, `revolution` → 6 pays (FR, GB, DE, ES, CN, EG).

## M27-02 — Aucun filtre structurel pour explorer la couverture

- **Problème** : les dix pays sont toujours affichés ; rien ne permet d'isoler, par exemple, les pays dont la documentation commence avant l'an 0 ou ceux qui comptent au moins six ères.
- **Preuve** : `globe.js:396-418` parcourt tous les pays et crée un bouton pour chacun, sans critère ; `globe.js:379-381` n'affiche que des totaux agrégés et figés.
- **Solution** : un `<select id=m27-filter>` natif (`data-fk=m27-filter`, `aria-controls=globe-choices`) offre cinq critères dont la formule est portée par le code : `Tous les pays` ; `Antiquité couverte (avant l'an 0)` = `domain[0] < 0` ; `Début après 1500` = `domain[0] > 1500` ; `Au moins 6 ères` = `eras.length >= 6` ; `Au moins 90 points` = `points.length >= 90`. Les champs utilisés existent dans `dataset.js` (`:22`, `:130`, `:4585`). Les tableaux absents sont traités comme vides (`count()`), les bornes absentes comme `NaN` (`domainStart()`) : aucun pays n'est inclus par défaut.
- **Impact** : le filtre rend visible la structure de couverture réelle, sans inventer de période ni de jugement historique. Résultats calculés : antiquité 5 pays (FR, IT, CN, IN, EG) ; après 1500 : 1 (US) ; 6 ères : 4 (FR, GB, US, DE) ; 90 points : 3 (FR, GB, DE).
- **Effort** : M
- **Vérification** : relecture de la table `FILTERS` ; rejeu des cinq formules sur `DATASET.countries` ; les libellés visibles annoncent explicitement le seuil.

## M27-03 — Résultats non comptés, état vide absent

- **Problème** : après une recherche sans résultat, la liste deviendrait vide sans explication, et aucun compteur ne dirait combien de pays restent visibles.
- **Preuve** : `globe.js:379-381` affiche « 10 pays · 229 repères · 845 points » : ce sont des totaux du jeu de données, pas des résultats de filtre. Aucun `role=status` local à la liste ; la Chronologie, elle, expose compteur, état vide et réinitialisation (`c3-recherche-atlas.md`, C3-03).
- **Solution** : `#m27-status` (`role=status`, `aria-live=polite`, `aria-atomic=true`) affiche `N pays affichés sur 10 · recherche « … » · filtre : …`, avec `N` compté depuis les `<li>` non masqués. `#m27-empty` apparaît seulement si `N=0` et indique les deux sorties : Échap dans le champ ou retour à « Tous les pays ». Aucun bouton de reset n'est ajouté (contrainte M27-04) : la réinitialisation passe par Échap, déjà géré sur le champ.
- **Impact** : l'absence de résultat est explicitement attribuée aux critères, jamais à un manque de données ; le dénominateur 10 est recalculé depuis `ctx.countries.length`.
- **Effort** : S
- **Vérification** : relecture de `apply()` ; saisir `zzz` → statut `0 pays affichés sur 10` et `#m27-empty` visible ; Échap → `10 pays affichés sur 10` et état vide masqué.

## M27-04 — Filtrage sans toucher aux boutons ni aux sélecteurs de test

- **Problème** : une implémentation naïve retirerait des boutons du DOM ou réécrirait leurs libellés, ce qui casserait les tests existants et les autres lentilles.
- **Preuve** : `tests/e2e.mjs:24` exige exactement dix `.globe-list button` ; `:25-30` les parcourt pour repérer la France ; `globe.js:402` pose `data-index` sur chaque bouton et `:409` y écrit le nom. Le contrat du registre (`UNIFIED_AUDIT/MONDE/README.md`, « Règles pour les lentilles ») interdit de renommer ces sélecteurs.
- **Solution** : `apply()` ne lit que `button.dataset.index` et ne modifie que `li.hidden` sur les enfants de `#globe-choices`. Aucun bouton n'est créé, retiré, renommé ou réordonné ; aucun attribut `aria-*`, `data-index` ou `tabindex` existant n'est touché. La feuille `monde-m27` ajoute uniquement `.globe-choices li[hidden]{display:none!important}` pour garantir l'effet du masquage.
- **Impact** : les dix boutons restent présents et cliquables quand aucun filtre n'est actif ; le test E2E d'entrée conserve son dénominateur.
- **Effort** : S
- **Vérification** : `node --check` ; relecture — aucune chaîne `globe-country`, `globe-list button`, `aria-current` ou `data-index` en écriture ; E2E rejoué par l'agent maître (10 boutons comptés, clic France → chronologie).

## M27-05 — Recherche sensible à la casse et aux accents

- **Problème** : « egypte » ne trouve pas « Égypte », « etats unis » ne trouve pas « États-Unis » ; un utilisateur au clavier sans saisie accentuée est exclu.
- **Preuve** : `dataset.js:18` et suivants portent les graphies exactes `Égypte`, `États-Unis`, `Royaume-Uni` ; `globe.js:409` les recopie verbatim dans le bouton. Aucune normalisation n'existe dans la vue.
- **Solution** : `fold()` applique `normalize('NFD')`, retire les diacritiques `[\u0300-\u036f]`, passe en minuscules et rogne les espaces. La même fonction est appliquée au champ et à l'index complet ; les termes sont séparés par espaces et combinés en ET, ce qui accepte « etats unis ».
- **Impact** : l'entrée au clavier est tolérante sans altérer l'affichage des noms propres, qui reste exactement celui du dataset (aucune mise en majuscules CSS ajoutée).
- **Effort** : S
- **Vérification** : relecture de `fold()` ; contrôles réels : `egypte` → EG, `etats unis` → US, `romain` → GB, IT, EG.

## M27-06 — Rendus répétés : doublons de barre et focus perdu

- **Problème** : la coque reconstruit tout le DOM à chaque changement d'état ; une lentille qui mémorise un nœud ou réenregistre des écouteurs globalement dérive après quelques navigations.
- **Preuve** : `shell.js:533` exécute `root.innerHTML = ''` à chaque `render()` ; `globe.js:442` appelle `runMondeEnhancements` après chaque reconstruction ; `registry.js:62` réapplique les cinquante greffons. Les callbacks sont purgés à chaque passe (`registry.js:48-50`).
- **Solution** : identifiants uniques `#m27-toolbar`, `#m27-search`, `#m27-filter`, `#m27-status`, `#m27-empty`, avec garde `document.getElementById(BAR_ID)` avant insertion ; CSS via `ctx.css('monde-m27', …)` (cssOnce). L'état `local = { query, filter }` vit dans le module et survit aux rendus, mais aucun nœud n'y est conservé : toutes les fonctions réinterrogent le DOM courant. Les deux contrôles portent `data-fk=m27-search` et `data-fk=m27-filter`, clés déjà utilisées par `shell.js:240-244` pour restaurer le focus.
- **Impact** : une seule barre par rendu, recherche conservée après un aller-retour dans une autre vue, focus rendu au champ concerné par la coque.
- **Effort** : M
- **Vérification** : relecture — garde d'existence, `ctx.css`, aucun stockage de nœud, aucun `addEventListener` documentaire ; navigation Monde → Chronologie → Monde avec une recherche active : valeur conservée et focus restauré.

## M27-07 — Aucun conflit avec le routeur clavier global

- **Problème** : ajouter des boutons de filtre ou des écouteurs sur le document risquerait de détourner les raccourcis globaux (chiffres, lettres de vue, flèches, Échap, Entrée).
- **Preuve** : `keyboard.js:199` installe un écouteur de capture sur `document` ; `:59-62` déclare `editable()` et `:125` ignore les événements déjà consommés ; le contrat du routeur demande « une touche, un handler, une action ». Les flèches du globe sont gérées localement par `globe.js:202-229`.
- **Solution** : les contrôles M27 sont des éléments de formulaire natifs `INPUT` et `SELECT` : `editable()` les reconnaît et le routeur global les ignore sans qu'aucun `stopPropagation` ne soit nécessaire. Aucun `<button>` supplémentaire, donc pas de piège `Entrée`/`Espace`. Le seul écouteur clavier est attaché au champ lui-même : Échap réinitialise, Flèche bas / Flèche haut déplacent le focus vers le premier / dernier bouton de pays visible (appel de `.focus()`, sans modifier le bouton).
- **Impact** : la recherche est tapable immédiatement, les raccourcis de vue restent disponibles dès que le focus quitte le champ, et la navigation clavier mène de la recherche à la liste sans changer la sélection.
- **Effort** : S
- **Vérification** : relecture — aucun `document.addEventListener`, aucun `stopPropagation`, aucun bouton créé ; saisir `1` dans le champ ne change pas de vue, Flèche bas place le focus sur `.globe-country` visible, Entrée ouvre le pays (comportement existant).

## M27-08 — Survol d'un pays masqué : annonce et liste divergentes

- **Problème** : si la liste est filtrée sur un seul pays, la sphère et le parcours clavier peuvent encore désigner un pays masqué ; le readout et l'annonce live parlent alors d'un pays invisible dans la liste.
- **Preuve** : `onHostKeyDown()` (`globe.js:202-229`) itère `DATASET.countries`, c'est-à-dire les dix pays, sans connaître le filtre ; `highlight()` (`:186-199`) met à jour le moteur, le readout et notifie `notifyMondeHover` (`:193`), puis `say()` (`:199`). Le registre diffuse ce survol à toutes les lentilles (`registry.js:71`).
- **Solution** : M27 s'abonne à `ctx.onHover` à chaque application (les callbacks étant purgés à chaque rendu, `registry.js:48-50`). Si le pays survolé ne satisfait plus les critères courants, `reset()` efface la recherche, remet le filtre sur « Tous les pays » et rafraîchit le statut. Le filtre reste un outil de lecture, jamais un modal : le survol reprend la main et l'annonce redevient vérifiable dans la liste.
- **Impact** : toute annonce de survol correspond à un bouton visible ; aucune information supplémentaire n'est émise, le statut existant porte la correction.
- **Effort** : M
- **Vérification** : relecture de l'abonnement `ctx.onHover` ; filtrer sur Japon, survoler la France sur le globe → recherche vidée, filtre `all`, statut `10 pays affichés sur 10`.

## M27-09 — Densité, cibles tactiles et repli mobile

- **Problème** : une barre de recherche et un sélecteur mal dimensionnés écrasent la liste des pays sur mobile ou produisent un zoom automatique sur iOS.
- **Preuve** : `styles.css:163-176` donne à `.globe-list` 18 px de padding et à `.globe-choices` deux colonnes ; `:319-322` passe la vue en une colonne et la liste en une seule colonne à 1000 px. Les boutons de commande du globe mesurent 46 px (`:158-161`) ; les contrôles M27 doivent rester dans la même famille de densité.
- **Solution** : feuille `#m27-toolbar` autonome : grille deux colonnes (une seule sous 1000 px), `min-height:36px` sur les champs, `font-size:16px` pour éviter le zoom iOS, `min-width:0` pour laisser les colonnes se réduire, focus visible `outline` doré, statut et message d'état vide pleine largeur. Aucune règle ne vise `.globe-country` ou un autre sélecteur de test.
- **Impact** : la liste reste lisible et les champs atteignables en 390×844 ; l'alignement visuel suit le thème local (variables `--line`, `--line-strong`, `--gold-bright`).
- **Effort** : S
- **Vérification** : relecture CSS ; capture 390×844 rejouée par l'agent maître ; aucun débordement horizontal de `.globe-list`.

## M27-10 — Annonce unique, chiffres dérivés et propreté du greffon

- **Problème** : deux régions live concurrentes annoncent deux fois la même information, et un greffon qui borne ses chiffres en dur cesse d'être falsifiable quand le jeu de données évolue.
- **Preuve** : `globe.js:73-84` crée `#globe-live` (`role=status`, `aria-live=polite`) alimenté par `say()` (`:148-150`) ; M20 travaille sur cette région. `registry.js:40-43` neutralise silencieusement une lentille défaillante : encore faut-il ne pas en produire.
- **Solution** : M27 n'appelle jamais `say()` : son unique canal est `#m27-status`, lui-même `role=status aria-live=polite`. Tous les nombres du statut sont recalculés à chaque `apply()` depuis les `<li>` visibles et `ctx.countries.length`. Les cinq seuils de filtre sont des critères structurels documentés, pas des faits historiques. Zéro `fetch`/XHR, zéro `Math.random`, zéro `console.*`, aucun fichier partagé modifié.
- **Impact** : une seule annonce par action de filtrage, des compteurs qui suivent le dataset réel, et aucune dette de compatibilité avec les autres lentilles.
- **Effort** : S
- **Vérification** : relecture — absence de `say(`, `fetch`, `XMLHttpRequest`, `Math.random`, `console.` ; `node --check src/views/monde/M27.js` PASS ; rejeu des compteurs : 10/10 au départ, 1/10 sur Japon, 3/10 sur « Au moins 90 points ».

## Blocages / limites inter-domaines

- La navigation flèches du globe (`globe.js:202-229`) continue de parcourir les dix pays ; M27 ne la modifie pas et garantit la cohérence par réinitialisation au survol (M27-08). Une contrainte plus stricte (parcours limité aux seuls résultats) demanderait une modification de `globe.js`, fichier non possédé.
- Aucun bouton de réinitialisation n'est ajouté dans `.globe-list` pour préserver le contrat E2E de dix boutons ; la sortie d'état vide passe par Échap ou le sélecteur, et c'est documenté dans l'aide visible.
- L'état de recherche est local au module : il survit aux changements de vue mais pas à un rechargement de page. Aucun deep link n'est écrit (M38 traite des deep links pays).
