# M50 — Synthèse et dettes de la vue Monde (domaine E : qualité & validation)

Lentille : M50. Fichier possédé : `src/views/monde/M50.js`.
Lectures seules : `src/views/globe.js`, `src/views/globe-reveal.js`, `src/views/monde/registry.js`, `src/data/dataset.js`, `UNIFIED_AUDIT/MONDE/README.md`, `UNIFIED_AUDIT/MONDE/SYNTHESE.md`, `package.json`.
Aucun fichier partagé modifié, aucun réseau, aucun `Math.random`, aucun `console.*`, aucun timer, aucune boucle rAF, aucun `IntersectionObserver`, aucune région `aria-live` ajoutée, aucune donnée historique inventée.

**Constat fondateur.** Les 49 autres lentilles se partagent une seule vue (`globe.js`) et un seul registre (`registry.js`). Chacune possède son propriétaire et sa garde ; aucune ne voit l'ensemble. M50 ne possède ni moteur, masque, boucle ou voix : il **consolide les garanties déjà livrées par les autres lentilles et rend visibles les dettes structurelles** qui subsistent dans les fichiers partagés. C'est un greffon de synthèse, pas un cinquantième correcteur.

---

## M50-01 — Périmètre : une synthèse qui n'ajoute aucun propriétaire

- **Titre.** M50 se limite à son module et à son rapport ; le contrat `register(id, apply)` reste la seule porte d'entrée.
- **Preuve.** `README.md:52-58` impose un seul fichier par lentille et interdit `styles.css`, `globe.js`, `store.js`. `registry.js:21-23` n'accepte qu'un `id` chaîne et une fonction ; `globe.js:431-442` appelle `runMondeEnhancements(mondeCtx)` en fin de rendu, sans don du moteur.
- **Solution.** Un seul `register('M50', ctx => …)`, CSS via `ctx.css('monde-m50', …)`, un panneau `#monde-m50-synthese` à ID unique sous garde d'existence. Aucun import de `globe.js` (cycle), aucun appel à `selectCountry`.
- **Impact.** La vue gagne une lecture d'ensemble sans qu'aucun fichier partagé ne change de propriétaire.
- **Risque.** Un greffon de synthèse pourrait être tenté de « réparer » ce qu'il affiche ; expressément interdit : M50 est observationnel.
- **Effort.** S
- **Vérification.** `grep -n "^import\|register(" src/views/monde/M50.js` → uniquement `./registry.js` et `register('M50'` ; `node --check src/views/monde/M50.js` → PASS.

## M50-02 — Dette D-01 : registre non purgé malgré l'arbitrage annoncé

- **Titre.** Les tableaux de callbacks du registre vivent hors du rendu ; la purge annoncée par la synthèse n'est pas dans le code lu.
- **Preuve.** `registry.js:15-19` déclare `readyCallbacks`, `hoverCallbacks`, `leaveCallbacks` au niveau module ; `registry.js:62-68` pousse dans ces tableaux à chaque notification ; `runMondeEnhancements()` (`registry.js:45-56`) les parcourt sans les vider. Or `SYNTHESE.md`, arbitrage M14, annonce « corrigée en maître (`registry.js` : purge des tableaux à chaque `runMondeEnhancements`) ». Les gardes de M14 (`M14.js:212`), M20 (`M20.js:113`), M07 (`M07.js:118`) et M15 (`M15.js:154`) attestent du contournement par les lentilles.
- **Solution.** M50 n'abonne **aucun** callback `onReady`/`onHover`/`onLeave` : son panneau est reconstruit de façon idempotente à chaque `apply()`, donc il n'ajoute aucune entrée aux tableaux. La dette est affichée (`D-01`) et l'état `host.dataset.m50Renders` rend les rendus successifs comptables.
- **Impact.** Aucune duplication imputable à M50 ; dette ouverte documentée sans modification du registre (fichier non possédé).
- **Risque.** Si la purge maître est appliquée plus tard, le panneau reste vrai : il décrit une dette de conception, pas un compteur d'erreurs.
- **Effort.** S
- **Vérification.** `grep -nE 'length = 0|\.splice\(|readyCallbacks = \[\]' src/views/monde/registry.js` → 0 ligne ; trois rendus → un seul nœud `#monde-m50-synthese` et `data-m50-renders="3"`.

## M50-03 — Dette D-02 : deux chiffres de couverture dans la même vue

- **Titre.** Le sous-titre du globe et la barre de progression n'annoncent pas le même nombre de points validés.
- **Preuve.** `globe.js:373` écrit « 784 cellules de couverture vérifiées » ; `globe.js:380` affiche `DATASET.meta.validatedPoints`, soit `845` (`dataset.js:13`, dataset généré le `2026-11-18`, `dataset.js:6`). Les deux textes sont frères dans le même panneau de décision.
- **Solution.** Le panneau M50 porte `D-02` avec les deux valeurs **et leurs sources** (`globe.js:373` / `dataset.js:13`), sans arbitrer ni corriger : les deux fichiers sont en lecture seule pour cette lentille. Aucun chiffre de couverture n'est réécrit dans le module.
- **Impact.** L'incohérence devient auditable au lieu d'être invisible ; aucun chiffre n'est inventé pour trancher.
- **Risque.** Une correction future d'un des deux fichiers rendrait l'étiquette datée ; le libellé est donc explicite sur l'écart constaté, pas sur une valeur « vraie ».
- **Effort.** S
- **Vérification.** `grep -n '784' src/views/globe.js` et `grep -n 'validatedPoints' src/data/dataset.js` → les deux lignes ; le panneau contient `D-02` et les deux références de fichier.

## M50-04 — Dette D-03 : moteur unique, absent du contexte des greffons

- **Titre.** Le moteur 3D a un seul propriétaire ; le chemin nominal est `onReady`, pas `ctx`.
- **Preuve.** `registry.js:7-12` liste les clés de `ctx` : ni `engine`, ni `renderer`, ni `scene` Three.js. `globe.js:444-485` détient `engine`, l'initialise et appelle `flushMondeReady({ engine, host, selected })` (`globe.js:467`, `registry.js:58-60`). M06, M07, M09, M10 et M12 capturent tous ce payload sous garde.
- **Solution.** M50 n'importe ni `THREE`, ni `VECTEMPOREL_GLOBE`, n'appelle ni `getInfo()`, `open()` ni `close()`. Son unique lecture d'état est `host.dataset.globeActive`, marqueur déclaratif posé par `syncEngine()` (`globe.js:156`) ; aucune API du moteur n'est touchée.
- **Impact.** Zéro second propriétaire, zéro cycle d'import, zéro dérive du budget GPU.
- **Risque.** Un état `globeActive` périmé pourrait afficher une phase ancienne ; le panneau le qualifie explicitement de « miroir », et il est reconstruit à chaque rendu.
- **Effort.** S
- **Vérification.** `grep -nE 'VECTEMPOREL_GLOBE|THREE|getInfo|selectCountry' src/views/monde/M50.js` → 0 ligne ; le panneau ne lit que `host.dataset`.

## M50-05 — Dette D-04 : cycle de vie réparti entre plusieurs lentilles

- **Titre.** Une boucle rAF, un `IntersectionObserver`, une pause document et une sonde DPR : quatre propriétaires distincts, aucun doublon toléré.
- **Preuve.** `globe.js:283-290` détient l'unique `IntersectionObserver` alimentant `inView` ; `globe.js:153-169` décide `open()`/`close()` via `syncEngine()` ; `globe.js:171-183` dessine une frame statique en mouvement réduit ; `globe.js:32-36` fige `paused` sur `prefers-reduced-motion`. M07 (`visibilitychange` unique), M08 (au plus une frame d'antirebond), M06 (sonde DPR réarmée) et M10 (mouvement réduit live) se partagent le reste, chacun sous garde.
- **Solution.** Le panneau affiche les quatre garanties avec leurs propriétaires (`globe.js`, M06, M07, M08, M10). M50 n'ajoute ni `requestAnimationFrame`, ni `IntersectionObserver`, ni `setTimeout`, ni `setInterval`, ni `matchMedia`, ni `ResizeObserver`.
- **Impact.** Synthèse lisible du cycle de vie sans modifier la décision de rendu, qui reste l'apanage de `syncEngine()`.
- **Risque.** La liste des propriétaires est datée : si une lentille est réécrite, l'attribution peut changer. Elle est donc présentée comme « références des chantiers M06/M07/M08/M10 », pas comme une implication dynamique.
- **Effort.** M
- **Vérification.** `grep -nE 'requestAnimationFrame|IntersectionObserver|setTimeout|setInterval|matchMedia|ResizeObserver' src/views/monde/M50.js` → 0 ligne ; `host.dataset.m50RenderBudget="delegated"`.

## M50-06 — Dette D-05 : palette de picking figée à dix codes

- **Titre.** Le masque de révélation ne connaît que dix codes ; un onzième pays n'aurait ni découpe ni zoom.
- **Preuve.** `globe-reveal.js:11-22` fixe `PALETTE` à `FR, GB, US, DE, IT, ES, CN, IN, JP, EG` ; `globe-reveal.js:24` pointe `PICK_URL = './public/globe-pick.png'` (local) ; `maskFor()` (`globe-reveal.js:104-138`) retourne `null` sans code dans la palette, et les gardes de `hover()`/`reveal()` (`globe-reveal.js:200-201, 221`) masquent alors l'overlay silencieusement. `M11`, `M18` et `M19` (masque, exactitude, repli) sont des chantiers distincts.
- **Solution.** M50 n'appelle ni `reveal.hover()` ni `reveal.reveal()` et n'écrit pas dans `#globe-reveal` ; il affiche `D-05` avec le nombre de codes de la palette (10, source `globe-reveal.js:11-22`). Le masque reste maîtrisé par son propriétaire.
- **Impact.** Dette de couverture explicite, zéro interaction avec la transition 720 ms de M15.
- **Risque.** La palette pourrait être étendue par une lentille dédiée ; l'étiquette reste vraie comme « palette de référence des dix pays documentés » puisque `dataset.js` déclare aussi 10 pays (`dataset.js:10`).
- **Effort.** M
- **Vérification.** `grep -n 'PALETTE\|PICK_URL' src/views/globe-reveal.js` → 2 définitions ; `grep -n 'globe-reveal\|reveal\.' src/views/monde/M50.js` → 0 ligne d'écriture ; le panneau affiche « 10 codes ».

## M50-07 — Dette D-06 : voix unique et HUD purement visuel

- **Titre.** Une seule région live est annoncée ; le panneau de synthèse ne doit pas devenir une source de bruit supplémentaire.
- **Preuve.** `globe.js:71-85` crée `#globe-live` (`role="status"`, `aria-live="polite"`, `aria-atomic="true"`) hors de `#app` pour survivre au `innerHTML` du shell ; `say()` (`globe.js:148-150`) y écrit. M20 réutilise ce nœud, M13 n'annonce que via `ctx.say`, M14 marque son chip `aria-hidden="true"`.
- **Solution.** Le panneau M50 est `aria-hidden="true"` et `pointer-events:none` : cible d'audit visuel, pas d'annonce. Aucun `role="status"`, aucun `aria-live`, aucun appel à `ctx.say` au rendu. L'état est exposé sous forme d'attributs `data-m50-*` sur `host`, lisibles par un test sans instrumentation.
- **Impact.** Zéro bégaiement d'écran, zéro focus supplémentaire, aucun sélecteur de test existant modifié.
- **Risque.** Un futur besoin d'annoncer la synthèse devra passer par l'unique `#globe-live` ; M50 ne crée pas de second chemin.
- **Effort.** S
- **Vérification.** `grep -nE 'aria-live|role="status"|say\(' src/views/monde/M50.js` → 0 ligne ; le panneau porte `aria-hidden="true"`.

## M50-08 — Synthèse des données : dériver de `ctx.countries`, jamais inventer

- **Titre.** Le récapitulatif chiffré du panneau vient du domaine, pas de souvenirs ni de faits historiques.
- **Preuve.** `globe.js:433-441` passe `countries: DATASET.countries` dans `ctx` ; `countryMeta()` (`globe.js:124-133`) dérive ères, repères, points et domaines des objets pays ; `dataset.js:3-14` déclare 10 pays, 229 repères, 1746 points, 845 validés, généré le 2026-11-18.
- **Solution.** M50 calcule `pays = countries.length`, `repères = Σ country.events.length`, `points = Σ (country.points || []).length` avec `Array.isArray` et un garde sur chaque pays. Aucune date, aucun nom de pays, aucun fait historique n'est écrit en dur dans le module ; le référencement de la dette `D-02` cite les fichiers, pas une valeur choisie.
- **Impact.** Le panneau suit automatiquement le dataset ; aucune affirmation non sourcée.
- **Risque.** Un objet pays incomplet produirait `undefined` sans les gardes ; `safeList()` les neutralise en tableaux vides.
- **Effort.** M
- **Vérification.** Injecter un pays supplémentaire dans `ctx.countries` lors d'un rendu de test → le chiffre « pays » augmente d'une unité sans modifier le module ; `grep -nE 'av\. J\.-C\.|[0-9]{3}–[0-9]{3}' src/views/monde/M50.js` → 0 fait historique.

## M50-09 — Non-régression : multi-rendus, CSS injecté, IDs uniques

- **Titre.** `runMondeEnhancements()` est rejoué à chaque rendu du globe : le panneau doit rester unique.
- **Preuve.** `globe.js:442` appelle `runMondeEnhancements(mondeCtx)` à chaque `renderGlobe()` ; `registry.js:25-31` fournit `cssOnce(uniqueId, rules)` avec garde par ID ; `globe.js:71-72` rappelle que la coque est remplacée par `innerHTML` (`shell.js:330`), d'où l'usage d'un nœud `body`-persistant pour la région live.
- **Solution.** `ctx.css('monde-m50', CSS)` injecté une seule fois ; `#monde-m50-synthese` créé sous garde `getElementById` dans `ctx.scene` ; compteur module `renderCount` exposé en `data-m50-renders`. Aucun écouteur `window`/`document`, aucun sélecteur de test touché (`.globe-list button`, `.globe-country`, `#globe-reveal`, `.event-card`).
- **Impact.** Trois rendus successifs → un seul panneau, une seule feuille de style, compteur exact.
- **Risque.** Le panneau vit dans `scene`, donc il est remplacé avec la vue : c'est voulu (pas de résidu hors du globe), contrairement à `#globe-live`.
- **Effort.** S
- **Vérification.** Trois appels à `renderGlobe()` → `document.querySelectorAll('#monde-m50-synthese').length === 1` et `document.querySelectorAll('#monde-m50').length === 1` ; `host.dataset.m50Renders === '3'`.
