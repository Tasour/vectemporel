# M33 — Codes ISO et drapeaux

Lentille **M33 — Codes ISO et drapeaux**, domaine D (données & sémantique).
Fichier possédé : `src/views/monde/M33.js`. Lectures seules : `src/data/dataset.js`,
`src/domain/store.js`, `src/views/globe.js`, `src/views/globe-reveal.js`,
`src/views/monde/registry.js`. Contrat : `register('M33', (ctx) => { … })` ;
CSS via `ctx.css('monde-m33', …)` ; nœuds uniques `monde-m33-iso-status` et
`monde-m33-iso-report` protégés par garde d'existence. Aucun autre fichier
modifié, aucune donnée historique inventée, zéro réseau, zéro `Math.random`,
zéro `console.*`, zéro minuteur.

Périmètre : la *sémantique du code ISO* (identité, validation, normalisation,
jointures, norme) et sa relation au drapeau. Ne recouvre pas le sondage des SVG
locaux (M12) ni la fidélité graphique du drapeau (M18) : M33 audite le couple
**code ↔ drapeau comme données**, avant toute question de rendu.

## M33-01 — Aucune source unique de vérité pour le code ISO

- **Preuve** : le code est dupliqué dans `dataset.js` (`code: "FR"` l.21, `GB` l.9310, `US` l.16090, `DE` l.21925, `IT` l.27640, `ES` l.33140, `CN` l.38926, `IN` l.44491, `JP` l.50057, `EG` l.55045), dans `PALETTE` (`globe-reveal.js:11-22`), dans les noms de fichiers `public/flags/<code>.svg` (`globe-reveal.js:182`), dans `store.countryByCode()` (`store.js:423-425`) et dans les deep links. Rien ne construit d'index canonique : une dérive entre ces ensembles est silencieuse.
- **Solution** : au `onReady`, M33 dérive de la seule source `ctx.countries` un index figé `code → pays`, mémorisé par signature construite sur `id`, `code`, `flag` et `name`. Le nombre d'entrées est publié dans `host.dataset.m33IsoCount`.
- **Impact** : toutes les vérifications ultérieures partent du même référentiel, sans dupliquer la donnée ni écrire dans `dataset.js`.
- **Risque** : la signature évite de reconstruire l'index à chaque survol ; aucune écriture hors du host, aucun sélecteur de test touché.
- **Effort** : M.
- **Vérification** : après `onReady`, `host.dataset.m33IsoCount = 10` avec les dix pays réels ; `node --check` passe.

## M33-02 — Égalité de codes sensible à la casse et aux espaces

- **Preuve** : `store.js:424` compare `country.code === code`, et `globe.js:191,193,205,393,429` propagent le code brut du moteur. Un code arrivant en minuscules ou avec un espace (`"fr"`, `"FR "`) ne résout aucun pays, alors que la sémantique ISO est indifférente à la casse d'entrée.
- **Solution** : `normalizeCode()` (trim + majuscules) est appliqué à tout code de payload avant résolution. Le nombre de normalisations effectives est publié dans `host.dataset.m33IsoNormalized` ; `host.dataset.m33IsoCurrent` porte toujours le code canonique.
- **Impact** : un code saisi ou transmis avec une casse différente retrouve son pays sans modifier `store.js`.
- **Risque** : la normalisation n'accepte que `/^[A-Z]{2}$/` après nettoyage ; aucun code invalide n'est réparé arbitrairement ; déduplication par clé `code|id` pour ne pas gonfler le compteur.
- **Effort** : S.
- **Vérification** : avec les dix codes réels, `m33IsoNormalized = 0` ; un survol injectant `fr ` résout `FR` et porte `m33IsoCurrent = FR`.

## M33-03 — Aucune validation ISO 3166-1 alpha-2 au niveau données

- **Preuve** : nulle part dans le flux de données le code n'est validé avant d'être utilisé comme clé ; seules les lentilles M12 (`ISO2` l.15) et M18 (`validCode()` l.84-86) portent un contrôle de forme, chacune pour son usage visuel. Le jeu de données lui-même n'expose aucun état de validité.
- **Solution** : M33 classe chaque code de `ctx.countries` avec `/^[A-Z]{2}$/` ; les codes conformes alimentent l'index, les autres sont listés dans `host.dataset.m33IsoInvalid` sans jamais produire de jointure ni de chemin.
- **Impact** : une dérive de forme devient auditable avant d'atteindre le SVG ou le deep link.
- **Risque** : les dix codes réels sont tous conformes ; le garde-fou reste local et n'altère ni `globe-reveal.js` ni `store.js`.
- **Effort** : S.
- **Vérification** : `m33IsoInvalid` est vide avec le jeu réel ; un code injecté tel que `FRA` ou `f` y figure sans entrer dans l'index.

## M33-04 — Codes dupliqués ou absents non détectés

- **Preuve** : `dataset.js` déclare `"countries": 10` (meta l.10) mais aucune assertion ne garantit dix codes distincts. Un doublon ferait collisionner l'index `code → pays` et renverrait le mauvais nom ou le mauvais drapeau ; un code absent rendrait `countryByCode()` (`store.js:423-425`) muet.
- **Solution** : lors de la construction de l'index, M33 détecte les doublons (première occurrence conservée, de façon déterministe) et les pays sans code exploitable ; publication dans `host.dataset.m33IsoDuplicates` et `host.dataset.m33IsoMissing`.
- **Impact** : la perte d'identité d'un pays est visible dans le rapport au lieu de se traduire par une erreur silencieuse.
- **Risque** : aucune déduction de code depuis le nom ou le drapeau — un pays sans code reste marqué `missing` ; aucun aléa dans le choix de l'occurrence retenue.
- **Effort** : S.
- **Vérification** : avec les dix pays réels, les deux attributs sont vides ; un doublon injecté apparaît dans `m33IsoDuplicates`.

## M33-05 — Drapeau stocké en littéral, non dérivé du code

- **Preuve** : `dataset.js` porte `flag: "🇫🇷"` (l.19), `"🇬🇧"` (l.9308), `"🇺🇸"` (l.16088), etc., tandis que `code` est un champ indépendant (l.21, 9310, 16090…). `globe.js:407` affiche ce littéral tel quel : aucune vérification, au niveau données, que l'emoji correspond bien au code ISO du pays.
- **Solution** : M33 décode les deux indicateurs régionaux U+1F1E6–U+1F1FF du champ `flag` (calcul local, identique dans l'esprit à `M18.js:70-82` mais appliqué ici à *tous* les pays) et compare le résultat au code. Les divergences sont publiées dans `host.dataset.m33IsoEmojiMismatch`.
- **Impact** : une faute de frappe dans un emoji de drapeau est détectée comme incohérence de données, pas seulement lors du survol d'un pays.
- **Risque** : aucun appel réseau, aucune police téléchargée ; si l'emoji est absent ou mal formé, le pays est marqué en divergence sans valeur inventée.
- **Effort** : M.
- **Vérification** : `m33IsoEmojiMismatch` vide avec les dix drapeaux réels ; un emoji remplacé par `🇩🇰` sur `FR` produit `FR→DK`.

## M33-06 — Norme ISO non explicite (alpha-2, ni alpha-3 ni code sportif)

- **Preuve** : les codes `GB`, `DE`, `EG`, `ES`, `IN`, `CN`, `JP` sont des alpha-2 ; rien dans l'interface ne l'énonce. Un lecteur peut confondre `GB` avec `UK`, `DE` avec `DK` (Danemark), ou `EG` avec un code arbitraire. M17 (`M17-nom-legende.md:65`) signale explicitement le doublon sémantique avec M33.
- **Solution** : M33 publie `host.dataset.m33IsoStandard = "ISO 3166-1 alpha-2"` comme simple étiquette de norme (aucun code supplémentaire fabriqué) et l'intègre au libellé accessible du statut.
- **Impact** : la portée du code est explicite ; aucune ambiguïté entre normes de codification.
- **Risque** : aucune table alpha-3 n'est introduite — ce serait une donnée externe non présente dans le jeu ; l'étiquette est purement descriptive.
- **Effort** : S.
- **Vérification** : lecture de `m33IsoStandard` après `onReady` ; chaîne stable et identique pour les dix pays.

## M33-07 — Identifiant ISO moderne appliqué à des ères antiques

- **Preuve** : `dataset.js:22-25` donne à la France un domaine démarrant à `-600` ; Inde et Égypte sont dans le même cas. Un code ISO 3166-1 est un identifiant d'État contemporain : l'appliquer à une entité antique est un anachronisme sémantique.
- **Solution** : quand `country.domain[0] < 0` (donnée réelle, aucune date d'adoption inventée), M33 ajoute dans le statut accessible la mention générique « identifiant ISO moderne : l'atlas couvre aussi des époques antérieures » et pose `host.dataset.m33IsoEra = "ancienne"`. Sinon, l'attribut est supprimé.
- **Impact** : le code est lu comme repère de pays, non comme catégorie historique.
- **Risque** : formulation strictement générique, aucun fait nouveau ; aucun badge visuel qui capterait le pointeur (contrairement à M12) — seul le nœud live est enrichi.
- **Effort** : S.
- **Vérification** : survol d'un pays à domaine négatif → `m33IsoEra = "ancienne"` et mention présente ; pays récent → attribut absent.

## M33-08 — Code opaque sans libellé sémantique accessible

- **Preuve** : `globe.js:407-408` rend le drapeau emoji dans un span `aria-hidden` ; le code ISO n'apparaît comme texte nulle part dans la vue (M17 ne traite que le nom dans la légende). Un code tel que `EG` ou `DE` reste opaque pour un lecteur d'écran comme pour un lecteur occasionnel.
- **Solution** : M33 maintient un nœud `#monde-m33-iso-status` (`role="status"`, `aria-live="polite"`, `aria-atomic="true"`, visuellement masqué) mis à jour via `onHover`/`onLeave` avec « Code ISO : <code> — <nom> », le nom provenant exclusivement de `ctx.countries`.
- **Impact** : équivalent textuel du couple code/drapeau, sans toucher aux annonces de sélection de M20 ni au statut de drapeau de M12.
- **Risque** : déduplication par clé `code|id` pour éviter le bavardage ; vidage à la sortie ; aucun attribut `aria-hidden` ajouté à un porteur de sens.
- **Effort** : S.
- **Vérification** : après survol, le nœud contient le code et le nom réels ; à la sortie, il est vide.

## M33-09 — Ordre non canonique des codes

- **Preuve** : `dataset.js:15` énumère les pays dans un ordre éditorial (France, GB, US, DE, IT, ES, CN, IN, JP, Égypte) alors que `public/flags/` et `PALETTE` (`globe-reveal.js:11-22`) les classent autrement. Deux consommateurs peuvent donc lister les mêmes codes dans deux ordres différents.
- **Solution** : M33 expose `host.dataset.m33IsoOrder` : la suite triée par points de code des codes valides, dérivée de l'index unique. Aucun `Math.random`, aucun ordre dépendant du rendu.
- **Impact** : référence de tri déterministe pour tout diagnostic ou future liste de codes, sans modifier l'ordre d'affichage des boutons (possédé par `globe.js`).
- **Risque** : tri par points de code (et non `localeCompare`) pour rester indépendant de la locale du navigateur.
- **Effort** : S.
- **Vérification** : `m33IsoOrder = CN,DE,EG,ES,FR,GB,IN,IT,JP,US` avec le jeu réel ; stable entre deux rendus.

## M33-10 — Intégrité invisible hors console

- **Preuve** : `registry.js:78-80` ne consigne dans `mondeDiagnostics()` que les exceptions levées par les greffons (`safe()` l.40-43) ; une dérive de données (code invalide, doublon, emoji divergent) ne lève rien et la règle du projet interdit d'ajouter un `console.*`.
- **Solution** : M33 maintient un rapport déterministe `valid=N;invalid=…;missing=…;duplicates=…;emojiMismatch=…` publié sur `host.dataset.m33IsoReport` et répliqué dans un nœud masqué `#monde-m33-iso-report` (`aria-hidden="true"`, `hidden`), créé avec garde d'existence et republié à chaque reconstruction d'index.
- **Impact** : état du couple code/drapeau auditable par les suites E2E de l'agent maître, avec zéro erreur console.
- **Risque** : nœud hors flux et aria-hidden, aucune annonce live supplémentaire ; aucun sélecteur de test existant n'est touché.
- **Effort** : S.
- **Vérification** : lecture du dataset et du nœud après `onReady` ; chaîne reproductible, identique entre deux rendus.

## Statut d'implémentation

Les dix chantiers sont implémentés dans `src/views/monde/M33.js`. Le CSS est injecté uniquement via `ctx.css('monde-m33', …)` (une seule règle, nœuds visuellement masqués). Les éléments créés portent des IDs uniques (`monde-m33-iso-status`, `monde-m33-iso-report`) et sont protégés par garde d'existence ; les crochets du registre sont réabonnés à chaque rendu avec un jeton d'invalidation, conformément à la purge de `registry.js:48-50`.

Aucun blocage. Les fichiers `dataset.js`, `store.js`, `globe.js`, `globe-reveal.js` et les SVG n'ont pas été modifiés : l'audit est dérivé de `ctx.countries` et exposé sur le host.
