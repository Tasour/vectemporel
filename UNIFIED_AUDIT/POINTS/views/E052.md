# E052 — Aucune date codée en dur

Lentille E052 — domaine F : sémantique & données. Fichier possédé : `src/views/points/E052.js` uniquement. La vue `src/views/points.js`, le magasin `src/domain/store.js` et le jeu `src/data/dataset.js` sont lus mais jamais modifiés : E052 ajoute un panneau LOCAL de lisibilité de l'ancre temporelle dans `.points-detail`, par-dessus le DOM déjà produit. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` ; aucune import de store, aucune écriture dans `state`, aucune dépendance vers `set()` / `selectEra()`. Invariant central : aucun millésime n'est écrit dans le module ; chaque date affichée est relue dans le DOM (champ `time` de la fiche, noms d'ères de la matrice, compteurs du titre et du kicker). Zéro réseau, zéro aléa, zéro minuteur, zéro rAF, zéro journalisation. CSS injecté par `ctx.css('points-e052', …)`.

## E052-01 — Audit à l'exécution : zéro millésime littéral dans la lentille

- **Preuve** : `E052.js:44-59` regroupe dans `PROSE` toutes les phrases écrites par la lentille ; `auditLiterals()` (`:126-131`) cherche dans leur concaténation toute suite de trois ou quatre chiffres consécutifs et renvoie `0`. Le résultat est exposé deux fois : dans les métriques visibles (`:274`) et sur `root.dataset.pointsE052Literals` (`:278-281`). Le commentaire d'en-tête (`:15-20`) énonce l'invariant et nomme les seules chaînes numériques autorisées, des conventions de formatage.
- **Solution** : l'absence de date codée en dur n'est pas seulement déclarée, elle est vérifiable : toute phrase ajoutée ultérieurement dans `PROSE` contenant une année ferait passer le compteur à une valeur non nulle. L'audit porte sur les textes **écrits** par la lentille, pas sur les valeurs **lues** dans les données, afin de ne pas confondre une donnée avec une invention.
- **Impact** : l'affirmation « aucune date codée en dur » devient falsifiable par lecture du compteur, sans a priori de confiance dans le commentaire.
- **Effort** : S
- **Vérification** : relecture de `:44-59`, `:126-131` ; le compteur affiché et `data-points-e052-literals` valent `0` ; ajouter une phrase contenant une année dans `PROSE` doit les faire passer à `1`.

## E052-02 — Ancre temporelle lue dans la fiche, jamais supposée

- **Preuve** : `readPoint()` (`E052.js:146-157`) lit le titre dans `.points-point-title` (`:149`) et parcourt `.points-meta > span` (`:150-155`) pour retenir le **seul** span numérique (`:153`), avec repli sur le troisième span (`:155`) selon l'ordre rendu par `points.js` : domaine, échelle, temps, certitude. Aucune valeur temporelle n'est recopiée dans le module.
- **Solution** : la détection par forme numérique plutôt que par position fixe tolère un changement d'ordre des métadonnées ; le repli positionnel couvre le cas où le temps serait formats en texte. Le résultat est aussi publié sur `detail.dataset.pointsE052Anchor` (`:276`).
- **Impact** : si le jeu de données change d'année, le panneau suit sans modification de code ; une fiche sans temps affiche un repli explicite au lieu d'un millésime inventé.
- **Effort** : M
- **Vérification** : relecture de `:148-157` ; harnais DOM : métadonnées avec temps numérique, temps textuel, sans temps → trois lectures correctes ; comparer `data-points-e052-anchor` au span d'origine.

## E052-03 — Formatage conventionnel du signe, sans inventer d'année

- **Preuve** : `formatYear()` (`E052.js:133-144`) reçoit la chaîne lue, teste un signe optionnel puis des chiffres (`:138`), et n'ajoute que des conventions : `av. J.-C.` (`:141`), `apr. J.-C.` (`:143`), `référence` pour zéro (`:142`). Les suffixes sont définis dans `PROSE` (`:56-57`), jamais en dur dans une phrase.
- **Solution** : le nombre affiché est toujours celui du DOM ; la lentille ne fait que le ponctuer. Les conventions sont des règles de lecture, distinctes des faits historiques, et sont comptées comme hors audit par `auditLiterals()` car elles ne contiennent pas de millésime.
- **Impact** : une date négative du jeu devient lisible (« 43 av. J.-C. ») sans qu'aucun seuil ni aucune borne historique ne soit codé ; le lecteur peut remonter du suffixe à la donnée brute.
- **Effort** : S
- **Vérification** : relecture de `:135-144` ; contrôles : `-43` donne « 43 av. J.-C. », `1931` donne « 1931 apr. J.-C. », `0` donne « 0 (référence) », chaîne vide et texte libre donnent un repli.

## E052-04 — Ères relues dans leur ordre réel depuis la matrice

- **Preuve** : `erasOf()` (`E052.js:159-164`) énumère `.points-grid-row:not(.is-head)` et lit `.points-era` de chaque ligne (`:161-163`) ; `writeEras()` (`:191-198`) construit une liste ordonnée `<ol>` masquée, posée dans le panneau (`:226`) avec `aria-label` (`:227`) et une position de données par ère (`:195`).
- **Solution** : l'ordre affiché est l'ordre du DOM, pas une liste figée de noms d'ères ; le terme masqué rend la séquence disponible aux technologies d'assistance sans modifier la grille.
- **Impact** : l'ajout ou le retrait d'une ère dans le jeu se reflète immédiatement dans la lecture linéaire et dans le compteur d'ères (`:274`).
- **Effort** : S
- **Vérification** : relecture de `:160-164`, `:191-198` ; harnais : deux puis trois lignes d'ères → deux puis trois éléments de liste, comptes cohérents.

## E052-05 — Ère courante repérée par la vue, non par une date

- **Preuve** : `currentEra()` (`E052.js:166-170`) lit `.points-grid-row.is-active .points-era` (`:169`), c'est-à-dire l'état déjà posé par `points.js` via `selectEra()`. Aucune comparaison entre une année et une borne d'ère n'est effectuée. L'ère courante est marquée `aria-current` dans la liste (`:194`) et publiée sur `detail.dataset.pointsE052Era` (`:277`).
- **Solution** : la lentille se contente de relayer un signal existant ; elle ne décide pas elle-même quelle ère est courante et ne duplique pas la logique de `store.js`.
- **Impact** : pas de divergence possible entre la ligne surlignée de la matrice et l'ère annoncée dans le panneau ; changement d'ère par clic immédiatement répercuté.
- **Effort** : S
- **Vérification** : relecture de `:168-170` ; harnais : déplacer la classe `is-active` sur une autre ligne → le statut et l'attribut data suivent sans toucher au code.

## E052-06 — Compteurs dérivés du titre et du kicker rendus

- **Preuve** : `countsOf()` (`E052.js:172-178`) extrait le nombre de `.points-title` (`:175`) et celui de `.points-detail .view-kicker` (`:176`) ; ces deux valeurs alimentent la ligne de statut (`:272-273`). Le titre et le kicker sont produits par `points.js` (`:32` et `:96` du module de vue) à partir du tableau de points.
- **Solution** : la lentille n'a aucun total propre : elle relit les deux compteurs affichés et les recombine, ce qui garantit qu'ils restent égaux à ceux de la vue.
- **Impact** : le nombre de points « isolés » et le nombre de points « dans le périmètre » ne peuvent pas être contredits par un chiffre interne à E052.
- **Effort** : S
- **Vérification** : relecture de `:174-178`, `:272-273` ; harnais : modifier les deux textes sources → le statut suit ; retirer le kicker → le panneau omet la portion de périmètre sans erreur.

## E052-07 — Replis explicites quand la donnée manque ou est inhabituelle

- **Preuve** : `formatYear()` distingue quatre cas (`:137`, `:139`, `:142`, `:143`) ; `PROSE` définit « ancre temporelle non fournie » et « ancre temporelle relative » (`:54-55`). Le panneau applique les mêmes replis pour l'ère (`:266`) et le point (`:268`), et publie `absent` quand l'ancre est vide (`:276`).
- **Solution** : chaque absence est un état nommé, jamais un silence ni une valeur par défaut numérique. Une ancre sous forme de texte libre est signalée comme relative plutôt que tronquée en année.
- **Impact** : aucune ligne vide, aucun « 0 » substitué à une donnée manquante ; un défaut de données reste visible et corrigeable.
- **Effort** : S
- **Vérification** : relecture de `:137-143`, `:265-269` ; harnais : temps vide, texte libre, ère absente, titre absent → quatre libellés de repli distincts et ponctués.

## E052-08 — Statut unique, annoncé seulement quand la lecture change

- **Impact** : pas de bavardage sur un rendu identique ; le compteur d'actualisations permet de distinguer « donnée inchangée » de « greffon muet ».
- **Effort** : M
- **Vérification** : relecture de `:229-231`, `:249-274` ; rejeu : deux installations sans changement → compteur stable ; changer de point → compteur plus un et statut mis à jour.

## E052-10 — Greffon unique, idempotent, sans effet de bord

- **Impact** : pas de doublon après navigation aller-retour, pas de fuite d'écouteurs, pas de dépendance à l'ordre d'exécution des autres lentilles ; `node --check` passe.

## Statut d'implémentation

Les dix chantiers E052-01 à E052-10 sont implémentés dans `src/views/points/E052.js` uniquement. CSS injecté via `ctx.css('points-e052', …)`. Aucune date codée en dur, aucune donnée inventée, aucun fichier partagé touché.

## Blocages / limites inter-domaines

- Les bornes de dates des ères (`start` / `end` dans `dataset.js`) ne sont pas écrites dans le DOM de la vue Points : E052 ne peut donc pas vérifier qu'une ancre tombe dans son ère. Cette vérification exigerait un signal supplémentaire dans `points.js`, fichier non possédé.
- Le champ `datePrecision` du point n'est pas rendu par `points.js` ; la lentille affiche l'ancre telle quelle et ne peut pas distinguer une année d'une décennie sans données complémentaires.
- Le panneau décrit l'état lu dans le DOM ; il ne corrige pas une fiche erronée ni un kicker incohérent. Aucune information nouvelle n'est émise hors de la région live locale.
- Les attributs `data-points-e052-*` sont écrits sur `.points-detail` et sur le layout ; toute autre lentille qui réécrirait ces mêmes attributs devra les préserver.
