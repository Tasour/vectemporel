# E083 — IDs uniques préfixés points-e083-, avec repli si collision

Lentille E083 — domaine I : qualité & validation. Fichier possédé : `src/views/points/E083.js` uniquement. La vue (`src/views/points.js`), la coque, `styles.css` et les quatre-vingt-dix-neuf autres lentilles ne sont ni édités ni doublés. E083 réserve le préfixe `points-e083-`, inventorie tous les identifiants du document, détecte les doublons parmi ceux qui portent ce préfixe et applique un repli déterministe par suffixe `-r2`, `-r3`… : aucun identifiant existant n'est écrasé, aucune règle CSS ne dépend d'un identifiant, aucune collision ne peut casser l'accessibilité. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el` (fournis par `points.js:126` et `registry.js:33-41`). Aucune dépendance vers le store, les filtres (`.points-filters`, deux `<select>` et le bouton de réinitialisation, `points.js:60-93`), le détail (`.points-detail` et ses `.points-point-title/-text/-meta/-families/-sources/-justification`, `points.js:95-114`) ni la navigation (`.points-nav`, `points.js:115-122`). Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. CSS injecté par `ctx.css('points-e083', …)`.

## E083-01 — Préfixe réservé et quatre identifiants canoniques dérivés

- **Preuve** : `E083.js:24-28` déclare `CSS_ID = 'points-e083'`, `PREFIX = 'points-e083-'`, la classe `points-e083-report` et les deux clés de signal. `E083.js:31-36` dérive les quatre identifiants attendus (`points-e083-report`, `-report-title`, `-report-status`, `-report-list`) de `PREFIX` par concaténation, dans un objet gelé : aucune chaîne d'ID n'est répétée ailleurs dans le module. `E083.js:74-80` fournit les deux prédicats (`isOwned`, `isFallback`) qui reconnaissent le préfixe et le suffixe de repli.
- **Solution** : une seule source de vérité pour le préfixe ; les identifiants canoniques sont calculés, pas recopiés. Le prédicat `isOwned` (`indexOf(PREFIX) === 0`) délimite exactement le périmètre à auditer : les IDs des autres lentilles (`points-e001-…`, `points-e030-…`) sont lus mais jamais réécrits.
- **Impact** : une lentille tierce qui réutiliserait le préfixe est détectée ; une faute de frappe dans un ID ne peut pas créer un cinquième identifiant hors contrôle. Le contrôle est falsifiable : ajouter un sixième ID préfixé dans le harnais fait varier le compteur affiché.
- **Effort** : S
- **Vérification** : relecture de `E083.js:24-36` et `:74-80` ; `grep -n 'points-e083-' src/views/points/E083.js` : toutes les occurrences littérales sont dans le bloc de déclaration ou les libellés de diagnostic ; harnais : seuls les quatre identifiants attendus sont présents, aucun ID nu.

## E083-02 — CSS unique, porté par une classe et sans sélecteur d'ID

- **Preuve** : `E083.js:38-72` définit une feuille dont **toutes** les règles commencent par `.points-e083` ; aucun `#` n'apparaît dans un sélecteur. `E083.js:196-197` appelle `css(CSS_ID, CSS)` (le `cssOnce` de `registry.js:13-19`, qui refuse un second `<style id="points-e083">`) puis pose la classe de portée sur le conteneur `.points-layout` construit en `points.js:29`.
- **Solution** : le style s'ancre sur la vue réelle, pas sur les identifiants audités. Ainsi, si le repli attribue `points-e083-report-r2` au lieu de `points-e083-report`, la mise en forme reste identique : le mécanisme de correction ne peut pas se détruire lui-même.
- **Impact** : aucune fuite hors de Points, aucune dépendance invisible entre l'unicité des IDs et le rendu ; le re-rendu de la coque ne crée pas de feuille en double.
- **Effort** : S
- **Vérification** : relecture de `E083.js:38-72` ; `grep '^#'` dans le bloc CSS : aucun résultat ; harnais : rendu → navigation aller-retour → un seul `<style id="points-e083">`.

## E083-03 — Inventaire complet des IDs et détection des doublons

- **Preuve** : `E083.js:82-89` (`collectUsed`) parcourt `document.querySelectorAll('[id]')` et construit un `Set` de **tous** les identifiants présents, y compris ceux des quatre-vingt-dix-neuf autres lentilles et de la coque. `E083.js:91-102` (`collectOwned`) regroupe par valeur les seuls identifiants commençant par `PREFIX` dans une `Map` : une valeur portée par deux nœuds donne un groupe de longueur 2. `E083.js:201-202` appelle l'inventaire puis la réconciliation avant toute création de nœud.
- **Solution** : deux vues complémentaires — l'ensemble global sert à réserver un suffixe qui ne heurte rien, la carte des préfixés sert à prouver l'absence de doublon. La détection ne présume pas que le DOM de la vue est le seul présent : elle interroge le document entier.
- **Impact** : une collision avec un ID externe (coque, diagnostic, autre lentille) est traitée comme une collision interne ; le contrôle reste vrai sans supposer un ordre d'exécution des greffons.
- **Effort** : M
- **Vérification** : relecture de `E083.js:82-102` ; harnais : (a) aucun ID préfixé → 4 identifiants vérifiés, statut `ok` ; (b) un ID préfixé dupliqué injecté à la main → 5 identifiants, 5 valeurs distinctes, compteur de repli à 2.

## E083-04 — Repli déterministe par suffixe, borné et sans aléa

- **Preuve** : `E083.js:104-119` (`reserve`) essaie d'abord l'ID de base ; s'il est déjà dans `used`, il incrémente `n` depuis 2 et teste `base + '-r' + n` jusqu'à trouver une valeur libre, qu'il ajoute immédiatement à l'ensemble réservé. Aucun `Math.random`, aucun compteur aléatoire, aucune boucle sans borne (le nombre d'itérations est majoré par le nombre d'IDs du document). `E083.js:29` limite la réécriture à quatre attributs nommément déclarés.
- **Solution** : une seule fonction de repli, partagée par la réconciliation des doublons (`:134`) et l'attribution canonique (`:175`). Le suffixe est fonction de l'occupation réelle du document : même DOM entrant donne même DOM sortant.
- **Impact** : le comportement est reproductible et auditable ; un suffixe ne peut pas écraser un identifiant déjà porté, y compris un suffixe produit par un passage précédent.
- **Effort** : S
- **Vérification** : relecture de `E083.js:104-119` ; `grep -n 'Math.random' src/views/points/E083.js` : seule la mention en commentaire (`:104`) ; harnais : un porteur étranger sur `points-e083-report` → le rapport reçoit `points-e083-report-r2`, le porteur étranger garde son ID.

## E083-05 — Réconciliation des doublons sans écrasement

- **Preuve** : `E083.js:121-139` (`reconcileDuplicates`) ne traite que les groupes de longueur ≥ 2 (`:127`). Il élit pour gardien le premier nœud contenu dans la vue (`:128-131`), c'est-à-dire l'ID que `getElementById` résolvait déjà pour la lentille, puis renomme **tous les autres** via `reserve` (`:132-136`). Le gardien n'est jamais modifié ; aucun nœud n'est supprimé.
- **Solution** : résoudre l'invalidité HTML dupliqué en préservant la référence canonique, plutôt que de supprimer arbitrairement un élément ou d'attribuer de nouveaux IDs à tout le monde. L'ID dupliqué d'origine continue d'exister une fois, sur le porteur de la vue.
- **Impact** : pas de perte de contenu, pas de casse des écouteurs déjà attachés par la vue sur `.points-era` et `.points-cell` (`points.js:40-55`) : E083 ne touche ni au balisage ni aux handlers, seulement à la propriété `id` des nœuds fautifs.
- **Effort** : M
- **Vérification** : relecture de `E083.js:121-139` ; harnais : deux nœuds portant `points-e083-report-title` → le premier reste `points-e083-report-title`, le second devient `points-e083-report-title-r2`, les deux nœuds restent dans le DOM.

## E083-06 — Attribution conservatrice : le repli existant survit au passage suivant

- **Preuve** : `E083.js:159-180` (`assignId`) trois branches : (1) ID canonique déjà en place et non occupé par autrui → conservation immédiate (`:166-169`) ; (2) ID en forme de repli de `base`, encore heurté par un autre porteur et résolu par `getElementById` vers ce même nœud → conservation du repli (`:170-174`) ; (3) sinon, attribution de `base` si elle est libre, ou nouveau `reserve` (`:175-179`). `E083.js:225-229` applique la fonction aux quatre nœuds du rapport.
- **Solution** : la branche (2) est la clé de l'idempotence. Sans elle, un second passage recomputerait `-r3`, `-r4`… à chaque rendu et le statut oscillerait. La branche (3) permet la consolidation inverse : dès que le porteur étranger disparaît, le rapport reprend son ID canonique.
- **Impact** : un rendu neuf sur le même DOM ne modifie aucun ID ; une collision résorbée en amont se traduit par un retour propre à l'ID canonique, sans accumulation de suffixes.
- **Effort** : M
- **Vérification** : relecture des trois branches de `E083.js:162-180` ; harnais : collision → `-r2` → second passage → toujours `-r2` ; retrait du porteur étranger → retour à `points-e083-report`.

## E083-07 — Références ARIA et « for » réécrites dans la seule portée de la vue

- **Preuve** : `E083.js:141-157` (`rewire`) ne considère que le conteneur `layout` et les descendants portant `aria-labelledby`, `aria-controls`, `aria-describedby` ou `for` (`:145-147`) ; pour chaque attribut, il ne remplace que le token exact égal à l'ancien ID (`:148-155`). `E083.js:230` appelle la réécriture pour chaque renommage. `E083.js:234-235` repose ensuite `aria-labelledby` et `aria-describedby` sur les identifiants **finaux** des nœuds, après tous les replis.
- **Solution** : double garantie — les références préexistantes dans la vue suivent le renommage, et les références du rapport sont recalculées à la fin plutôt que copiées depuis le passage précédent. Aucun attribut hors de `layout` n'est touché.
- **Impact** : le panneau reste correctement nommé et décrit même avec un ID suffixé ; une autre lentille qui porterait un `aria-controls` sur un ID préfixé hors de la vue n'est pas modifiée (limite documentée).
- **Effort** : M
- **Vérification** : relecture de `E083.js:141-157` et `:230-235` ; harnais : avec collision, `report.getAttribute('aria-labelledby')` vaut bien l'ID du titre suffixé ; aucune chaîne `document.querySelectorAll` avec portée globale dans `rewire`.

## E083-08 — Panneau de diagnostic statique, lisible et accessible

- **Preuve** : `E083.js:182-190` (`buildReport`) crée un `<section role="region">` avec un `<h3>`, un `<p>` de statut et une `<ul>` de trois `<li>`, exclusivement via `ctx.el` et `replaceChildren`. `E083.js:204-223` réutilise le panneau présent, supprime seulement un panneau E083 orphelin d'un ancien rendu, et le reconstruit uniquement si une pièce manque. `E083.js:249-256` écrit le statut et la liste en texte visible. Le panneau est inséré dans `.points-matrix` (`E083.js:209-211`), construit en `points.js:30`.
- **Solution** : le diagnostic est du DOM statique, hors région live, sans annonce intempestive et sans `innerHTML`. Les libellés (« Préfixe réservé… », « Repli : suffixe -r2, -r3… », « Les références ARIA et « for » de la vue suivent l'identifiant retenu. ») sont dans le HTML produit, donc lisibles sans JS et par les technologies d'assistance.
- **Impact** : l'état du contrôle est vérifiable à l'œil et à la lecture d'écran, sans ouvrir la console ni les outils de développement ; le panneau n'ajoute aucune modalité ni piège de focus.
- **Effort** : M
- **Vérification** : relecture de `E083.js:182-190` et `:204-223` ; `grep` : absence de `innerHTML`, `insertAdjacentHTML`, `outerHTML` ; harnais : deux passages → un seul `.points-e083-report`, un seul `role="region"`, `aria-labelledby` et `aria-describedby` résolus.

## E083-09 — Signaux observables dérivés du DOM final, donc stables

- **Preuve** : `E083.js:237-247` recomptent, après toutes les attributions, les identifiants préfixés (`ownedCount`) et ceux qui portent un suffixe `-rN` (`fallbackCount`, test `/-r\d+$/`). `E083.js:249-251` en déduit le texte de statut, et `E083.js:258-259` écrivent `data-e083-status` (`ok` / `recovered`) et `data-e083-collisions` sur `.points-layout`. Le commentaire `:237-239` documente explicitement le choix de l'état final plutôt que de la passe courante.
- **Solution** : le compteur ne mesure pas « ce que je viens de faire » mais « dans quel état est le DOM » ; un repli conservé d'un passage précédent reste compté, une consolidation le retire. Statut, texte et attributs ne peuvent donc pas se contredire.
- **Impact** : l'agent maître peut vérifier d'un coup d'œil si le préfixe est sain (`ok`, 0) ou sous repli (`recovered`, N) ; l'évolution au fil des rendus est monotone et reproductible.
- **Effort** : S
- **Vérification** : relecture de `E083.js:237-259` ; harnais : sans collision `ok/0` sur deux passes ; avec collision `recovered/1` sur deux passes ; avec un doublon injecté `recovered/2` puis à nouveau `recovered/2` ; retrait du porteur étranger → `recovered/1` (le doublon injecté reste).

## E083-10 — Contrat minimal, gardes de type et rigueur hors-ligne

- **Preuve** : `E083.js:192-197` filtre sur `viewId === 'points'`, exige `layout`, `css` et `el`, puis sort sans rien faire si le contexte est incomplet — le greffon est inoffensif avec le `ctx` minimal décrit dans l'en-tête (`:10-11`). L'en-tête (`:13-21`) énonce les invariants : un CSS, un panneau, aucun ID écrasé, aucun réseau/aléa/timer/rAF/console/innerHTML. Les media queries `:64-71` couvrent l'écran étroit (390 px) et les couleurs forcées ; la feuille ne déclare aucune transition, donc aucun mouvement à neutraliser.
- **Solution** : une seule fonction enregistrée (`register('E083', ctx => …)`, `:192`), une seule feuille, aucun écouteur global, aucun `MutationObserver` : l'audit est rejoué à chaque rendu par le registre (`registry.js:36-42`), ce qui suffit et évite toute boucle d'observation sur le panneau que la lentille écrit elle-même.
- **Impact** : E083 ne consomme aucun filet de sécurité dynamique, ne ralentit pas le rendu et ne peut pas provoquer de récursion ; `node --check` passe et les interdits sont absents du code (hors mentions en commentaire).
- **Effort** : S
- **Vérification** : `node --check src/views/points/E083.js` → PASS ; `grep -nE 'console\.|fetch\(|XMLHttpRequest|Math\.random|innerHTML|insertAdjacentHTML|outerHTML|requestAnimationFrame|setTimeout|setInterval'` → uniquement deux lignes de commentaire (`:21`, `:104`) ; un seul `register(` et un seul `css(` dans le fichier ; capture 390×844 et `forced-colors` à rejouer par l'agent maître.

## Statut d'implémentation

Les dix chantiers E083-01 à E083-10 sont implémentés dans `src/views/points/E083.js` uniquement. CSS injecté via `ctx.css('points-e083', …)`. Aucun autre fichier partagé touché, aucun identifiant d'autrui écrasé, aucune donnée inventée. Harnais DOM local : unicité, repli `-r2`, conservation du repli au second passage, réconciliation d'un doublon, consolidation après retrait du porteur étranger — tous conformes.

## Blocages / limites inter-domaines

- E083 audite le document à l'instant où le registre l'appelle. Une autre lentille exécutée **après** elle (ordre d'insertion dans `points/index.js`) et qui créerait un ID dupliqué ne sera corrigée qu'au rendu suivant. L'agent maître doit arbitrer si un greffon postérieur enfreint le préfixe.
- Le préfixe est une convention, pas une contrainte technique : E083 ne peut pas empêcher un autre module d'utiliser `points-e083-`. Il détecte et répare ; il n'impose pas.
- La réécriture des références est limitée à `.points-layout` (`E083.js:143-147`). Une référence `aria-controls` portée par un nœud extérieur à la vue (coque, panneau de diagnostic global) et pointant vers un ID renommé devra être mise à jour par son propriétaire.
- Le panneau E083 orphelin d'un ancien rendu est retiré (`E083.js:204-205`), comme le fait E001 pour sa note. Si deux `.points-layout` devaient coexister simultanément dans le document, seul celui courant conserverait le panneau ; la coque n'en rend qu'un à la fois.
- Le compteur `data-e083-collisions` mesure les IDs **en repli** dans l'état final, pas le nombre historique de collisions rencontrées depuis le chargement : un conflit résolu sans laisser de suffixe n'est pas compté.
