# E029 — Détail & fiche : point suivant / précédent dans le détail

Lentille E029 — domaine C : détail & fiche. Fichier possédé : `src/views/points/E029.js` uniquement. La vue (`src/views/points.js`), la coque, le routeur, le store, `_diagnostics.js` et `styles.css` ne sont ni édités ni doublés. E029 enrichit les **deux boutons natifs** déjà produits par `points.js:115-122` dans `.points-nav` (« ← Point précédent », « Point suivant → ») : aucun second bouton n'est créé, aucun gestionnaire natif n'est remplacé, aucun écouteur global n'est posé. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` (tels que fournis par `points/registry.js:28-44`). Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `MutationObserver`, zéro `console.*`, zéro `innerHTML`, aucune région live propre. CSS injecté par `ctx.css('points-e029', …)`. Les dix chantiers ci-dessous sont implémentés et non destructifs.

## E029-01 — Feuille CSS unique et portée possédée

- **Preuve** : `E029.js:36` déclare `CSS_ID = 'points-e029'` ; `:47-96` contient une unique chaîne CSS dont chaque sélecteur est préfixé `points-e029-` ou ancré sur un ID possédé (`#points-e029-prev`, `#points-e029-next`). `:202` appelle `ctx.css(CSS_ID, CSS)` via `cssOnce` (`registry.js:13-19`).
- **Solution** : une seule injection, réappliquée sans effet à chaque rendu. Aucun sélecteur générique, aucune règle sur une classe partagée : la portée est limitée aux nœuds créés ou marqués par la lentille.
- **Impact** : aucun style ne fuit hors du panneau de détail de la vue Points ; les autres lentilles qui stylent `.points-nav` ou `.points-detail` ne sont pas perturbées.
- **Effort** : S.
- **Vérification** : relecture de `:36`, `:47-96`, `:202` ; harnais — deux appels à `ctx.css`, un seul identifiant distinct.

## E029-02 — Repérage non destructif des deux boutons natifs

- **Preuve** : `findDetail()` (`:114-119`) part de `ctx.layout`, puis de `ctx.stage` en repli, et ne sélectionne que `.points-detail`. `findButtons()` (`:149-162`) repère les boutons dans `.points-nav` par leur libellé (`/pr[eé]c[eé]dent/i`, `/suivant/i`) avec repli positionnel (`list[0]`, `list[list.length-1]`). `:229-233` leur pose les IDs préfixés `points-e029-prev` / `points-e029-next` et des classes, sans retirer ni recréer le moindre nœud. `:262-268` n'ajoute l'écouteur que si `dataset.pointsE029Bound !== '1'`.
- **Solution** : réutilisation intégrale des commandes de `points.js:115-121`. Le garde `data-points-e029-bound` rend l'installation idempotente ; le gestionnaire natif qui appelle `set()` reste actif et intact.
- **Impact** : aucune régression fonctionnelle des boutons « précédent / suivant », aucun doublon après navigation aller-retour, aucune dépendance à un ordre de rendu d'une autre lentille.
- **Effort** : M.
- **Vérification** : relecture de `:114-119`, `:149-162`, `:229-233`, `:262-268` ; harnais — IDs uniques, un seul écouteur par bouton après deux passes sur le même DOM.

## E029-03 — Libellés accessibles stables et titre contextuel

- **Preuve** : `:234-235` posent `aria-label="Point précédent dans la fiche"` et `aria-label="Point suivant dans la fiche"`, deux libellés distincts et **constants** ; l'en-tête `:25-27` explique pourquoi : `shell.js:204-290` restaure le focus par signature incluant `aria-label`, un libellé variable casserait la restauration. `:241-242` écrivent seulement l'attribut `title` (`Point précédent — depuis <titre du DOM>`), qui ne fait pas partie de cette signature.
- **Solution** : le nom accessible est figé pour la coque, tandis que l'information contextuelle (le point affiché) vit dans l'infobulle, relue à chaque rendu depuis `.points-point-title` (`:121-123`).
- **Impact** : le focus reste sur la commande utilisée après le re-rendu déclenché par `set()` ; l'utilisateur sait au survol depuis quel point il navigue, sans qu'aucune donnée ne soit inventée.
- **Effort** : S.
- **Vérification** : relecture de `:234-242` ; harnais — libellés identiques avant et après déplacement, `title` mis à jour avec le nouveau titre, cible de focus stable.

## E029-04 — Cible de commande explicite sans id sur la vue

- **Preuve** : `:211-224` choisissent comme cible `aria-controls` le `.points-point-title` (ou le kicker en repli), enfant de `.points-detail`, auquel est posé `points-e029-target` s'il n'a pas déjà d'id. `:236-239` reportent cet id sur les deux boutons. L'en-tête `:22-24` justifie l'absence d'id sur `.points-detail` lui-même : `_diagnostics.js:69-79` masquerait tout enfant direct de layout portant un id matching `.*-eNNN`.
- **Solution** : la relation commande → fiche est déclarative, tout en restant invisible du mécanisme de diagnostic. Un `aria-label` de landmark est posé sur la fiche `:221-223` sans changer son rôle sémantique.
- **Impact** : les lecteurs d'écran peuvent annoncer quelle zone est contrôlée ; le mode diagnostic des 100 lentilles continue de fonctionner sans masquer le détail.
- **Effort** : S.
- **Vérification** : relecture de `:211-239` ; harnais — cible `points-e029-target` résolue par `getElementById`, y compris quand le titre est absent (repli sur le kicker).

## E029-05 — Détection de borne par signature, sans observateur

- **Preuve** : `:100-104` déclarent `pending`, `lastSig`, `boundaryDir` ; `:270-274` décrivent l'algorithme : le clic mémorise le titre courant (`:265-267`), le rendu suivant compare le nouveau titre à ce titre. `:278-293` : titre identique → `aria-disabled="true"` sur la direction épuisée et incrément de `boundaryCount` ; titre différent → déplacement, remise à zéro des deux bornes. `:299-306` réinitialise les bornes quand filtres ou ère changent (`perimeterSig`, `:138-145`). `:246-247` ré-applique la borne connue au bouton neuf de chaque rendu.
- **Solution** : `runEnhancements` rappelant `install()` à chaque rendu, l'état de borne est déduit d'une comparaison de texte — aucun `MutationObserver`, aucun timer, aucune lecture du store, aucun aléa. `aria-disabled` (et non `disabled`) garde le bouton dans `focusCandidates()` de `shell.js:226`.
- **Impact** : au dernier point, « Point suivant » est signalé comme sans suite ; au premier, « Point précédent » l'est aussi. Un changement de filtre lève immédiatement l'indication, qui ne peut donc pas devenir mensongère.
- **Effort** : M.
- **Vérification** : relecture de `:138-145`, `:246-247`, `:265-306` ; harnais — clic suivant avec changement de titre → déplacement ; clic suivant sans changement → `aria-disabled` sur « suivant » seulement ; clic précédent → borne levée ; changement de filtre → bornes levées.

## E029-06 — Périmètre chiffré dérivé du kicker

- **Preuve** : `perimeterCount()` (`:127-133`) extrait l'unique nombre du `.view-kicker` réel produit par `points.js:96` (« N point(s) dans ce périmètre ») et retourne `null` si le texte est absent. `:253-256` en tire la note affichée, avec un libellé de repli sans chiffre quand le kicker manque.
- **Solution** : le seul nombre de la lentille est lu dans le DOM ; aucun total, aucun millésime, aucune donnée historique n'est codé en dur.
- **Impact** : la note reste vraie quand le périmètre filtré change ; le repli explicite évite d'afficher « 0 » par défaut lorsqu'aucune information n'est disponible.
- **Effort** : S.
- **Vérification** : relecture de `:127-133`, `:253-256` ; harnais — kicker « 3 point(s) » → note « 3 point(s) » ; kicker absent → note sans nombre inventé.

## E029-07 — Statut visible de dernière action, indexable

- **Preuve** : `ensureNode()` (`:166-177`) crée un nœud unique `#points-e029-status` (classe `points-e029-status`) dans `.points-detail`, relogé sans doublon. `writeNode()` (`:179-183`) n'écrit que si la valeur change. Les trois états sont écrits en texte réel : initial (`:294-298`), déplacement (`:283-285`), borne (`:290-292`), périmètre (`:304-306`).
- **Solution** : aucun `role="status"`, aucune région live propre : la coque annonce déjà le changement de point via `store.js:172-173`. Le statut est donc un paragraphe visible, avec un rail latéral en CSS (`:74-77`) — information jamais portée par la seule couleur.
- **Impact** : l'utilisateur voit « Dernier déplacement : point suivant → <titre>. » ou « Borne atteinte : aucun point suivant… » sans double annonce vocale ; le texte est indexable, contrairement à un contenu généré dans un attribut ou un pseudo-élément.
- **Effort** : M.
- **Vérification** : relecture de `:166-183`, `:283-306` ; harnais — statut initial non vide, puis « Dernier déplacement… », puis « Borne atteinte… », puis « Périmètre actualisé… », sans nœud dupliqué.

## E029-08 — Compteurs auditables hors région live

- **Preuve** : `:103-104` maintiennent `movedCount` et `boundaryCount` ; ces compteurs sont incrémentés uniquement aux `:279` et `:287`, c'est-à-dire après une comparaison de titre. `writeMetrics()` (`:192-195`) affiche « Déplacements : N · Bornes atteintes : K. » dans `#points-e029-metrics` (`:252`), avec chiffres tabulaires (`:78-80`).
- **Solution** : la métrique n'est pas une interpolation de l'état interne supposé : elle ne bouge que lorsqu'un déplacement ou une borne a été réellement observé dans le DOM rendu. Elle est hors de toute région live, donc silencieuse pour l'AT.
- **Impact** : un relecteur peut distinguer « la commande n'a rien fait » de « la lentille est muette » ; les compteurs survivent aux rendus comme ceux de E013/E030.
- **Effort** : S.
- **Vérification** : relecture de `:103-104`, `:192-195`, `:279`, `:287` ; harnais — `Déplacements : 0 / Bornes : 0` → `1 / 0` après déplacement → `1 / 1` après borne.

## E029-09 — Focus, cibles tactiles et contraste préservés

- **Preuve** : `:48-58` impose `min-height: 44px` aux deux boutons, un `:focus-visible` avec contour de 2 px et décalage de 3 px ; `:69` rend la navigation flexible en范围 étroite, `:81-83` étend les cibles à 140 px sous 620 px de large. L'en-tête `:25-27` documente la coopération avec la restauration de focus de `shell.js:204-290` grâce aux libellés stables de E029-03.
- **Solution** : aucune touche globale, aucun `data-fk` détourné, aucun piège de focus : E029 ne fait que rendre les boutons existants conformes aux cibles tactiles et au focus visible. Le CSS ne modifie pas l'ordre de tabulation.
- **Impact** : les commandes restent atteignables au clavier et au doigt en 390×844, et le focus n'est pas volé au routeur (E035/E036 gardent la main sur les raccourcis, domaine D).
- **Effort** : S.
- **Vérification** : relecture de `:48-58`, `:69`, `:81-83` ; capture 390×844 à rejouer par l'agent maître ; harnais — libellés stables avant/après rendu.

## E029-10 — Idempotence, sobreté et conformité hors DOM

- **Preuve** : `:197-209` valident le contexte et la vue avant toute écriture ; `:166-177` et `:262-268` portent les gardes anti-doublon ; `:100-107` ne stockent que des primitives, jamais de nœud périmé. `:84-95` neutralisent les transitions sous `prefers-reduced-motion` et fournissent un repli `forced-colors` ; l'en-tête `:28-33` interdit explicitement timer, rAF, observateur, réseau, aléa, console et `innerHTML`.
- **Solution** : l'installation est purement additive et rejouable : CSS unique, deux boutons marqués une seule fois, trois nœuds de texte uniques. Aucun fichier partagé n'est modifié ; aucun appel au store, au routeur ou à une autre lentille.
- **Impact** : pas de fuite d'écouteur ni de doublon après navigation aller-retour ; le greffon reste lisible en mouvement réduit et en couleurs forcées, sans dépendre d'une seule couleur pour signifier la borne.
- **Effort** : M.
- **Vérification** : relecture de `:100-107`, `:166-177`, `:197-209`, `:262-268`, `:84-95` ; harnais — deux passes sur le même DOM → un seul nœud note/status/metrics, un seul identifiant CSS ; `node --check` PASS ; recherche de `console.`, `fetch`, `XMLHttpRequest`, `Math.random`, `innerHTML`, `requestAnimationFrame`, `setTimeout`, `MutationObserver` → aucune occurrence hors commentaire d'en-tête.

## Blocages / limites inter-domaines

- L'état de borne est inféré d'une comparaison de titres : si deux points consécutifs du périmètre portent exactement le même `subject`, un clicosts valide est interprété comme une borne atteinte. Le ctx de la vue n'expose ni `state.pointIndex` ni `visible.length` : une détection exacte demanderait un signal du store, fichier non possédé.
- Le statut visible n'est pas une région live : la coque annonce déjà le changement via `store.js:172-173`, mais cette annonce parle du repère du récit (`event.points`), pas du périmètre filtré de la vue Points. Un complément vocal spécifique nécessiterait la coque.
- Aucun raccourci clavier n'est ajouté : la navigation j/k et les raccourcis locaux relèvent des lentilles E035/E036 (domaine D), non possédées ici.
- Aucun id n'est posé sur `.points-detail` ni sur `.points-matrix` : `_diagnostics.js:69-79` masquerait un enfant direct de layout dont l'id匹配 le motif `.*-eNNN`. La cible `aria-controls` est donc portée par le titre, enfant du détail.
- `aria-disabled` n'empêche pas le gestionnaire natif de s'exécuter : au-delà de la borne, `set()` est tout de même appelé et borné par `points.js:119-120`. Le comportement reste correct, mais un rendu supplémentaire a lieu.
