# E072 — Responsive & mobile : cibles tactiles ≥ 44 px

Lentille E072 — domaine H : responsive & mobile. Fichier possédé : `src/views/points/E072.js` uniquement. La vue (`src/views/points.js`), la coque et `styles.css` ne sont ni édités ni doublés : E072 ajoute UNE portée CSS et UNE note de lecture statique, et s'appuie sur le DOM déjà rendu par la vue (`.points-layout`, `.points-matrix`, `.points-title`, `.points-grid`/`.points-grid-row`/`.points-era`/`.points-cell`, `.points-filters` — 2 selects + réinitialisation —, `.points-detail` — `.points-point-title`/`-text`/`-meta`/`-families`/`-sources`/`-justification` — et `.points-nav`). Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` (fournis par `points/registry.js:28-44`) ; aucune dépendance vers le store, les filtres ou le détail : les cibles restent élargies même avec un `ctx` minimal. Zéro écouteur global, zéro timer, zéro rAF, zéro réseau, zéro aléa, zéro `innerHTML`, zéro `console.*`. CSS injecté par `ctx.css('points-e072', …)`. Tous les identifiants sont préfixés `points-e072-`.

## E072-01 — Portée CSS unique, ancrée sur la vue Points

- **Preuve** : `E072.js:24-26` déclare `CSS_ID = 'points-e072'`, `SCOPE = 'points-e072'` et `NOTE_ID = 'points-e072-note'`. Le commentaire `E072.js:28-32` pose la portée : « toutes les règles sont préfixées par `.points-e072`, classe posée sur le conteneur `.points-layout` : aucune fuite hors de la vue Points ». La feuille est injectée une seule fois via `ctx.css(CSS_ID, CSS)` (`:160`) ; la classe est posée sur le layout à `:161`. La garde d'entrée (`:156-158`) exige `css`/`el` et rejette tout `viewId` autre que `points`.
- **Solution** : une seule feuille, injectée par `cssOnce` (le `css` du registre), avec préfixe `.points-e072-` sur les seuls nœuds créés. Aucun sélecteur nu ne peut atteindre une autre vue. Le `ctx` minimal (sans `stage`) est toléré grâce au repli `rootOf()` (`:106-110`).
- **Impact** : aucune régression visuelle hors de la vue Points ; l'enrichissement reste confiné au stage courant, y compris quand la coque recrée `#atlas-stage`.
- **Effort** : S
- **Vérification** : relecture — un seul `ctx.css(`, une seule classe de portée, aucun sélecteur global ; capture des vues voisines sans style injecté.

## E072-02 — Cibles ≥ 44 px sur la matrice (ères + cellules)

- **Preuve** : `E072.js:37-44` cible `.points-e072 .points-grid-row > button` et pose `min-height: 44px`, `min-width: 44px`, `padding: 8px 10px`. Ce sélecteur couvre exactement les boutons `.points-era` et `.points-cell` produits par `points.js:40` et `:46`, sans toucher aux en-têtes `<span>` ni aux couleurs. Le commentaire `:38-39` rappelle que les classes `is-active` / `has-points` ne sont pas modifiées.
- **Solution** : élargissement purement additif des deux familles de boutons de la grille. Aucune classe d'origine n'est retirée, aucun `title`/`aria-label`/gestionnaire de clic natif n'est réécrit : la sélection d'ère et le filtrage par domaine restent intacts.
- **Impact** : la matrice, principale zone tactile de la vue, devient actionnable au doigt sur mobile sans changer sa sémantique ni son apparence (chiffres tabulaires, cellules `has-points` conservés).
- **Effort** : S
- **Vérification** : relecture — `min-height: 44px` et `min-width: 44px` présents ; harnais DOM : mesurer `.points-era` et `.points-cell` → hauteur ≥ 44 px ; clic sur une cellule → filtre et ère inchangés dans leur comportement.

## E072-03 — Cibles ≥ 44 px sur les filtres (2 selects + reset)

Le bloc `.points-filters` de `points.js:60-93` contient bien deux `<select>` (domaine `:61`, famille `:73`) et un bouton « Réinitialiser les filtres » (`:85`) : les trois contrôles sont couverts.

- **Impact** : le filtrage tactile (choix du domaine, de la famille, remise à zéro) devient atteignable sans précision de souris, tout en préservant l'annonce de réinitialisation d'E013.
- **Effort** : S
- **Vérification** : relecture — les deux selects et le bouton sont dans le sélecteur ; harnais : hauteur ≥ 44 px pour chacun, `change`/`click` natifs toujours déclenchés.

## E072-04 — Cibles ≥ 44 px sur la navigation du détail

Le bloc `.points-nav` est produit par `points.js:115-121` avec « ← Point précédent » et « Point suivant → », et est accroché au `.points-detail` (`:122`) : les deux boutons sont couverts.

- **Impact** : la navigation avant/arrière devient tactilement fiable, en particulier dans la disposition empilée où `.points-nav` occupe le bas du détail.
- **Effort** : S
- **Vérification** : relecture — sélecteur unique couvrant les deux boutons ; harnais : hauteur ≥ 44 px, clic « suivant » → `pointIndex` inchangé dans son mécanisme.

## E072-05 — Détection du pointeur grossier, signal JS et CSS couplés

- **Preuve** : `coarsePointer()` (`E072.js:117-125`) interroge `window.matchMedia('(pointer: coarse)')` dans un `try/catch` avec repli `false`. Le résultat est écrit sur le layout à `:163-165` : `data-points-e072-coarse = '1' | '0'` ; `data-points-e072` marque le greffage (`:164`). La feuille (`:59-70`) lit ce signal via `.points-e072[data-points-e072-coarse="1"]` pour élargir les gouttières à `12px`, et applique la même logique en `@media (pointer: coarse)` avec `min-height: 48px` sur les six familles de contrôles.
- **Solution** : double source de vérité (attribut JS + media query) convergente : sur écran tactile, les cibles passent à 48 px et les espacements à 12 px ; ailleurs, la base de 44 px suffit. Le repli prudent `false` évite d'annoncer un mode tactile quand `matchMedia` est absent.
- **Impact** : les doigts disposent d'une marge de tolérance supplémentaire, sans pénaliser la densité de la matrice sur poste fixe ; l'état est auditable via l'attribut de données.
- **Effort** : M
- **Vérification** : relecture des deux `try/catch` et des deux voies CSS ; harnais : émuler `(pointer: coarse)` → attribut `'1'` et hauteurs 48 px／gouttières 12 px ; sans `matchMedia` → attribut `'0'`, hauteurs 44 px.

## E072-06 — Reflow mobile : padding Compact et absence de débordement de page

- **Preuve** : la règle de base `E072.js:35` pose `min-width: 0; max-width: 100%` sur `.points-e072`, évitant que le layout grid ne pousse la page en horizontal. Sous `@media (max-width: 620px)` (`:75`, `:82-83`), la feuille réduit les paddings de `.points-matrix` à `14px 12px 20px` et de `.points-detail` à `16px 12px`. La disposition empilée héritée de `styles.css:377-379` (matrix au-dessus, détail en dessous) reste inchangée.
- **Solution** : adaptation purement dimensionnelle aux petits écrans : marges internes resserrées pour gagner de la place utile, largeur du layout bornée à son parent. Aucune réorganisation du DOM, aucun changement de `grid-template-*` propre : E072 ne entre en conflit ni avec le repli à 1000 px de la base, ni avec les points de rupture d'E001.
- **Impact** : la vue reste lisible en 390×844 sans défilement horizontal parasite de la page, tout en conservant la hiérarchie matrice → détail.
- **Effort** : S
- **Vérification** : relecture — présence de `min-width: 0`/`max-width: 100%` et des deux paddings ; capture 390×844 : aucun `scrollWidth > clientWidth` sur `document.documentElement`.

## E072-07 — Défilement horizontal confiné à la grille

- **Preuve** : `E072.js:75-81` règle, sous 620 px, `.points-e072 .points-grid` en `overflow-x: auto`, `-webkit-overflow-scrolling: touch`, `overscroll-behavior-x: contain` et `max-height: 58vh`. Le commentaire `:72-74` documente le confinement : « le défilement horizontal reste confiné à la grille (déjà overflow-x:auto dans styles.css) ; momentum et containment évitent le piège de défilement ».
- **Solution** : la grille redevient l'unique zone de balayage horizontal ; le `overscroll-behavior-x: contain` empêche le geste de se propager à la page et le `-webkit-overflow-scrolling` restaure l'inertie sur iOS. La hauteur plafonnée à `58vh` garde le détail visible en dessous.
- **Impact** : sur mobile, parcourir les domaines de la matrice ne fait pas défiler toute la vue ; le détail reste accessible sans geste ambigu.
- **Effort** : S
- **Vérification** : relecture des quatre déclarations ; harnais mobile : balayer la grille horizontalement → `scrollLeft` de la grille varie, `window.scrollX` reste à 0.

- **Impact** : le point de focus reste perceptible au clavier comme après un appui tactile, y compris sur les cibles de 44–48 px, sans dépendre de la seule couleur de fond.
- **Effort** : S

- **Solution** : information statique écrite dans le DOM au rendu, lisible sans JavaScript actif une fois le greffon appliqué, sans `innerHTML` : le nœud est fabriqué par `ctx.el` et `textContent`. La réutilisation par identifiant garantit l'absence de doublon.
- **Impact** : l'utilisateur comprend pourquoi les cibles sont plus grandes et où se fait le défilement ; aucune annonce intempestive n'est émise aux lecteurs d'écran.
- **Effort** : S

## E072-10 — Installation idempotente et non destructive

- **Preuve** : `register('E072', …)` (`E072.js:153-175`) ne pose que des attributs de miroir : `data-points-e072`, `data-points-e072-coarse`, `data-points-e072-motion` (`:164-166`) et `data-points-e072-targets` (`:173-174`), ce dernier compté depuis le DOM réel via `queryAll()` (`:112-115`) avec le sélecteur des six familles de contrôles. Le commentaire d'en-tête `:14-21` énonce les invariants : une feuille, IDs préfixés, aucune classe/attribut/gestionnaire d'origine retiré, zéro écouteur/timer/rAF/réseau/aléa/innerHTML/console.
- **Solution** : aucun stockage de nœud périmé dans la closure, aucun `addEventListener`, aucun `setInterval`/`requestAnimationFrame` : l'installation est purement déclarative (CSS + attributs + note). Un second passage sur le même DOM est sans effet (note réutilisée, mêmes attributs réécrits).
- **Impact** : pas de doublon, pas de fuite d'écouteurs, pas de mutation du store ni des contrôles natifs ; la lentille reste inactive si le contrat CSS/el manque ou si la vue n'est pas `points`.
- **Effort** : M
- **Vérification** : relecture — absence de `addEventListener`, `setTimeout`, `setInterval`, `requestAnimationFrame`, `innerHTML`, `console.`, `Math.random`, `fetch`, `XMLHttpRequest` ; `node --check src/views/points/E072.js` PASS ; rejeu navigation : un seul `#points-e072-note`, un seul style `#points-e072`, attributs stables.

Les dix chantiers E072-01 à E072-10 sont implémentés dans `src/views/points/E072.js` uniquement. CSS injecté via `ctx.css('points-e072', …)`, tous les identifiants préfixés `points-e072-`. Aucun fichier partagé touché, aucun contrôle natif remplacé, aucune donnée inventée.

## Blocages / limites inter-domaines

- La base `styles.css:355` fixe `min-height: 34px` sur les boutons de grille et `:362`/`:375` fixent `38px` sur filtres et navigation ; E072 ne modifie pas ces fichiers et les surcharge uniquement dans sa portée `.points-e072`. Toute lentille qui retirerait la classe de portée annulerait les cibles élargies.
- Le signal `data-points-e072-coarse` dépend de `matchMedia('(pointer: coarse)')` ; les environnements sans cette requête retombent sur la base de 44 px (jamais sur une régression). L'attribut `data-points-e072-motion` est un miroir : la neutralisation effective des transitions est portée par la media query `prefers-reduced-motion`.
- Le comptage `data-points-e072-targets` reflète le DOM au moment du rendu ; il n'est pas maintenu en direct si une autre lentille insère des contrôles après E072 (ordre d'enregistrement dans `points/index.js`).
- Le confinement du défilement horizontal repose sur `overflow-x: auto` déjà présent dans `styles.css` ; si cette règle de base disparaît, E072 la rétablit sous 620 px mais pas sur écran large.
