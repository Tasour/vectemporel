# E016 — Filtres & périmètre — état vide explicite quand zéro point

Lentille E016 — chantier POINTS, domaine B : filtres et périmètre. Dix chantiers, **les 10 implémentés**. Fichier possédé : `src/views/points/E016.js` uniquement. Lectures seules (non modifiés) : `src/views/points.js`, `src/views/points/registry.js`, `src/views/points/index.js`, `src/ui/shell.js`, `styles.css`, `src/domain/store.js` et les autres lentilles E001–E100.

`renderPoints(stage)` (`points.js:16-127`) construit la matrice, les deux `<select>` de filtre et le bouton de réinitialisation (`points.js:60-93`), puis le détail avec un kicker `${visible.length} point(s) dans ce périmètre` (`points.js:96`) et, quand aucun point n'est sélectionné, un paragraphe de repli « Aucun point validé dans ce périmètre… » (`points.js:113`). E016 s'y greffe **après** le rendu, sans rien retirer ni réécrire : il ajoute une note locale dans `.points-detail` uniquement quand le périmètre affiché est vide. Tout est dérivé du DOM rendu : aucun import de store, aucune écriture dans `state`, aucun appel à `set()`, `selectEra()`, `say()` ni aucune autre fonction partagée. Le ctx de cette vue n'expose d'ailleurs pas `say()` (`points.js:126`, `points/registry.js:28-43`) : E013/E015/E019 gardent la charge des annonces et E016 **n'ajoute aucune troisième région live**. CSS injecté par `ctx.css('points-e016', …)` ; tous les identifiants sont préfixés `points-e016-`. Zéro réseau, zéro aléa, zéro minuteur, zéro rAF, zéro `console.*`, zéro `innerHTML`, aucun fichier partagé touché.

## E016-01 — Détection de l'état vide dérivée du DOM, sans chiffre codé en dur

- **Preuve** : `countFromKicker()` (`E016.js:90-95`) lit `.points-detail .view-kicker` et en extrait le nombre par `/(\d+)\s+point/i` : c'est exactement le texte écrit par `points.js:96`. `isEmptyState()` (`:107-111`) en déduit le vide si et seulement si le compte vaut zéro. L'invariant est posé en `:13-14` : aucun nombre historique ni total littéral n'apparaît dans le module.
- **Solution** : la source de vérité est le kicker réellement rendu, pas une supputation sur le store ni un compte recalculé à partir des cellules de la matrice (celles-ci affichent les counts bruts par ère/domaine et ignorent le filtre de famille). Quand le kicker est illisible, la décision bascule sur le repli E016-07.
- **Impact** : l'état vide affiché est toujours cohérent avec le périmètre que la vue a effectivement calculé ; l'affirmation est falsifiable par lecture directe du kicker.
- **Effort** : S
- **Vérification** : relecture de `:90-95` et `:107-111` ; harnais — kicker « 0 point(s) dans ce périmètre » → vide ; « 3 point(s)… » → non vide ; aucun millésime ni total codé en dur dans le fichier.

## E016-02 — Note locale `role=note`, non modale et non destructive

- **Preuve** : `buildBlock()` (`E016.js:144-157`) construit la note une seule fois par `ctx.el` : `<section role="note" aria-labelledby="points-e016-title">` avec un `<h3>` titré « État vide — aucun point affiché », le paragraphe de message et le compteur. Aucun `role=dialog`, aucun `aria-modal`, aucun `backdrop`, aucun piège de focus. L'insertion (`:249-255`) utilise `insertBefore` juste après le kicker du détail, avec repli `appendChild` ; le style est en `:30-61` et l'appel à `ctx.css(CSS_ID, CSS)` en `:213`.
- **Solution** : la note est une région annotée du détail, pas une modale. Elle reste dans le DOM en permanence et bascule seulement par l'attribut `hidden` (`:182`) : aucun nœud natif — titre, texte, métadonnées, familles, sources, justification, navigation — n'est retiré, déplacé ou réécrit.
- **Impact** : l'absence de résultat devient un bloc de lecture explicite, situé au même endroit que la fiche manquante, sans interrompre la navigation clavier ni masquer le paragraphe de repli de `points.js:113`.
- **Effort** : S
- **Vérification** : relecture de `:144-157` et `:249-255` ; contrôle DOM — un seul `role=note`, pas de `dialog` ; le titre, le texte et `.points-nav` d'origine sont toujours présents après installation.

## E016-03 — Signaux d'état observables, portés par le détail et la note

- **Preuve** : `refresh()` pose `block.dataset.pointsE016 = empty ? 'empty' : 'points'` et `detail.dataset.pointsE016 = …` (`:183-184`). La feuille (`:49-51`) colore le kicker du détail quand l'attribut vaut `empty` ; le repli `[hidden]` (`:38`) garantit la disparition effective de la note quand l'état redevient normal.
- **Solution** : deux attributs additifs, aux clés de dataset dédiées (`pointsE016`), jamais réécrits par ailleurs. Aucune information n'est portée par la seule couleur : le mot « État vide », le message et l'attribut portent le sens, la teinte dorée n'est qu'un renfort.
- **Impact** : un contrôle automatisé peut affirmer l'état sans lire le texte ; un utilisateur en couleurs forcées conserve le même contenu (`:58-60`).
- **Effort** : S
- **Vérification** : relecture de `:183-184` et `:38-51` ; harnais — vide donne `data-points-e016="empty"` sur la note et le détail ; présence de points donne `points` et `hidden` sur la note.

## E016-04 — Message adapté aux filtres actifs et à l'ère courante

- **Preuve** : `activeFilters()` (`:113-126`) parcourt les deux `<select>` de `.points-filters`, ignore les valeurs `*` et préfère le libellé de l'`<option>` sélectionnée à sa valeur brute. `activeEra()` (`:128-130`) lit `.points-grid-row.is-active .points-era`. `messageText()` (`:132-142`) compose deux variantes : vide par restriction de périmètre, ou vide par couverture encore incomplète.
- **Solution** : le message nomme les filtres réellement actifs (« Filtrer par domaine : … ; Filtrer par famille : … ») et l'ère affichée. Quand aucun filtre n'est actif, il n'invente pas de cause : il rappelle que les agents par ère travaillent encore à la couverture et qu'un silence de la matrice est une donnée.
- **Impact** : la raison de l'absence de points est explicite et oriente l'action juste — retirer une restriction si elle existe, patienter sinon — sans jamais suggérer une donnée inexistante.
- **Effort** : M
- **Vérification** : relecture de `:113-142` ; harnais — domaine `*` / famille `*` donne la variante « couverture » ; un domaine choisi donne la variante « périmètre » avec son libellé d'option et l'ère active.

## E016-05 — Aucun contrôle ni annonce dupliquée : description ARIA du bouton natif

- **Preuve** : l'invariant `:18-19` interdit toute région live et tout second bouton. `setDescription()` (`:159-168`) ajoute l'identifiant `points-e016-message` à l'`aria-describedby` du bouton de réinitialisation trouvé dans `.points-filters` (`:236`), en préservant les identifiants déjà présents et en retirant le sien quand l'état redevient normal. Le bouton lui-même reste celui de `points.js:85`, avec son gestionnaire d'origine intact.
- **Solution** : plutôt qu'un troisième `role=status` qui bavarderait avec E013, E015 et E019, la phrase d'état vide est rattachée au contrôle qui permet d'en sortir : le focus sur « Réinitialiser les filtres » fait entendre la raison du vide. L'ajout est réversible et dédupliqué (`:163-165`).
- **Impact** : les technologies d'assistance disposent du message au bon moment, sans triple annonce ni contrôle surnuméraire ; le routeur, les touches globales et les écouteurs `change` natifs ne sont pas perturbés.
- **Effort** : M
- **Vérification** : relecture de `:159-168` et `:18-19` ; absence de `role=status`, `aria-live`, `document.addEventListener` et de création de `<button>` ; harnais — un `aria-describedby` préexistant `foo` devient `foo points-e016-message`, puis revient à `foo`.

## E016-06 — Signature anti-écriture et compteur auditable hors région live

- **Preuve** : `refresh()` (`:170-193`) calcule `signature = JSON.stringify([empty, filters, activeEra(layout)])` (`:174`) et sort sans rien écrire si elle est inchangée (`:175`). `emptyCount` n'est incrémenté qu'à une transition réelle vers le vide (`:177`), et `wasEmpty` est conservé entre rendus (`:74`). Le compteur est écrit dans `#points-e016-metrics` (`:186-188`), créé hors de toute région live en `:154-156`.
- **Solution** : la garde de signature évite les réécritures provoquées par l'observateur ou par les autres lentilles qui complètent `.points-filters`. Le bloc d'écriture est encadré par `writing = true` / `finally { writing = false }` (`:180-192`), ce qui interdit toute réentrance.
- **Impact** : nombre borné d'écritures DOM, aucune annonce redondante, et une trace vérifiable (« États vides détectés : N ») qui distingue « pas de changement d'état » de « greffon muet ».
- **Effort** : M
- **Vérification** : relecture de `:170-193` ; rejeu — deux rendus successifs avec le même périmètre vide laissent le compteur à 1 ; passer à un périmètre non vide puis revenir au vide le porte à 2.

## E016-07 — Repli explicite quand le kicker est absent ou illisible

- **Preuve** : `hasFallbackText()` (`:101-105`) cherche dans les paragraphes du détail le texte de repli de `points.js:113` ; `isEmptyState()` (`:107-111`) n'en déduit le vide qu'en l'absence de `.points-point-title` (`hasPointTitle()`, `:97-99`). Lorsque le kicker fournit un nombre, ce nombre a priorité (`:108-109`).
- **Solution** : deux sources de vérité complémentaires, avec hiérarchie explicite : kicker d'abord, titre et paragraphe de repli ensuite. Si aucun signal n'est fiable, la lentille ne conclut pas au vide et laisse la vue telle quelle.
- **Impact** : pas de « état vide » erroné affiché par-dessus une fiche valide, et pas de nombre inventé pour compenser un DOM partiellement reconstruit par une autre lentille.
- **Effort** : S
- **Vérification** : relecture de `:97-111` ; harnais — (a) kicker 0 seul, (b) repli + absence de titre sans kicker, (c) titre présent avec kicker illisible, (d) aucun signal → quatre décisions conformes, dont l'abstention dans le dernier cas.

## E016-08 — Observateur unique et ciblé, jamais sur la note écrite

- **Preuve** : `observe()` (`:195-209`) déconnecte l'observateur existant (`:199`) avant d'en créer un seul (`:201`), puis observe trois cibles en lecture seule : le kicker en `childList`/`characterData`/`subtree` (`:202-204`), le détail en `childList` **sans sous-arbre** (`:205`), et la barre de filtres en `childList`/attribut `value` (`:206-208`). La note et son message ne sont jamais observés ; le commentaire `:195-197` l'énonce explicitement.
- **Solution** : l'observation couvre les changements de périmètre sans couvrir les nœuds que E016 écrit. Le garde `writing` (`:171`, `:180-192`) constitue une seconde barrière anti-boucle si une lentille postérieure venait à déplacer la note.
- **Impact** : aucune boucle d'écriture, aucune fuite d'observateur après navigation, et un rafraîchissement immédiat quand une autre lentille modifie le kicker ou les filtres en place.
- **Effort** : M
- **Vérification** : relecture — un seul `new MutationObserver`, un `disconnect()` préalable, aucun `observe()` sur `#points-e016-empty` ; harnais — modifier le texte du kicker déclenche une actualisation, modifier le message de la note n'en déclenche aucune.

## E016-09 — Mouvement réduit respecté, CSS étroit et couleurs forcées

- **Preuve** : `install()` interroge `ctx.reducedMotion()` dans un `try/catch` avec repli `false` (`:257-261`) et écrit `data-points-e016-motion="reduce|full"` sur le détail. La feuille neutralise les transitions sous `prefers-reduced-motion` (`:55-57`), prévoit un point de rupture à 700 px (`:52-54`) et un repli `forced-colors: active` (`:58-60`). Aucune animation, transition utile, rAF ou minuteur n'est introduit.
- **Solution** : la lentille n'a aucun mouvement propre : l'attribut sert de signal d'observation et le CSS reste passif. La note garde une mesure de lecture confortable (12 px / 1,55, 11 px sous 700 px) et ne modifie pas les cibles tactiles des contrôles existants.
- **Impact** : le message reste lisible à 390×844 et sous préférence de mouvement réduit, sans contradiction avec le réglage système ni débordement horizontal dans le détail.
- **Effort** : S
- **Vérification** : relecture de `:52-60` et `:257-261` ; émuler `prefers-reduced-motion: reduce` → attribut `reduce` et aucune transition calculée ; capture 390×844 sans débordement de la note.

## E016-10 — Idempotence multi-rendus, CSS unique et identifiants préfixés

- **Preuve** : `CSS_ID = 'points-e016'` (`:24`) est passé une seule fois à `ctx.css(...)` (`:213`) ; `cssOnce` (`points/registry.js:13-19`) garantit l'unicité de la feuille. Les quatre identifiants `points-e016-empty`, `-title`, `-message`, `-metrics` (`:25-28`) sont tous préfixés. `install()` détecte un rendu neuf par nœud déconnecté (`:227-228`), résorbe les doublons (`:229-231`), réutilise la note existante (`:239-248`) et ne réinitialise que la signature (`:264`) — jamais les compteurs. `register('E016', install)` apparaît une seule fois (`:268`).
- **Solution** : une seule note par rendu, références module relues depuis le DOM courant, aucun stockage de nœud périmé ; l'insertion est conditionnelle (`:249`) et le CSS est entièrement porté par les identifiants préfixés ou par le détail muni de l'attribut de données.
- **Impact** : navigation aller-retour sans doublon ni perte de message, compatibilité avec le mode diagnostic du registre, et aucun fichier partagé modifié.
- **Effort** : M
- **Vérification** : relecture — un seul `register`, un seul `ctx.css`, un seul bloc ; `node --check src/views/points/E016.js` PASS ; rejeu rendu → navigation → rendu : un seul `#points-e016-empty`, compteur préservé, état `hidden` cohérent.

## Statut d'implémentation

Les dix chantiers E016-01 à E016-10 sont implémentés dans `src/views/points/E016.js` uniquement. CSS injecté via `ctx.css('points-e016', …)`. Aucune autre lentille, aucun fichier partagé, aucune donnée ni aucun chiffre inventé. Aucun bouton ni région live dupliquée : la réinitialisation reste celle de la vue et les annonces restent à E013/E015/E019.

## Blocages / limites inter-domaines

- E016 ne pilote pas le store : il ne peut ni appliquer un filtre ni réinitialiser le périmètre à la place de l'utilisateur. Le bouton natif de `points.js:85` reste la seule action, décrite mais non modifiée dans son comportement (`E016.js:159-168`).
- L'état vide est déduit du kicker et du paragraphe de repli écrits par `points.js`; si une lentille postérieure supprimait ces deux signaux sans en fournir d'autre, E016 s'abstiendrait plutôt que d'inventer un état (`E016.js:107-111`).
- Les annonces sonores ne sont pas portées par E016 : le ctx de la vue n'expose pas `say()` et trois régions existent déjà (E013, E015, E019). Le message est donc visuel et relié au bouton par `aria-describedby`; la responsabilité de l'annonce du compte reste inter-domaines.
- Le signal `detail.dataset.pointsE016` est écrit par E016 (`E016.js:184`) ; toute lentille qui réécrirait `detail.dataset` en bloc devra le préserver.
