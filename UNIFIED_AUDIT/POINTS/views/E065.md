# E065 — G. Performance & rendu — zéro Math.random (graine affichée si visuel pseudo-aléatoire)

Lentille E065 — domaine G : performance & rendu. Fichier possédé : `src/views/points/E065.js` uniquement. La vue (`src/views/points.js`), le registre (`src/views/points/registry.js`), la coque et `styles.css` ne sont ni édités ni doublés. Contrat exploité : `viewId`, `stage`, `layout`, `css(id, rules)`, `el(tag, cls, text)`, `reducedMotion()`. Aucune dépendance vers le store, les filtres ou le détail : la lentille reste active avec un `ctx` minimal pourvu qu'il porte un `layout`. CSS injecté par `ctx.css('points-e065', …)`. Tous les identifiants sont préfixés `points-e065-`. Zéro réseau, zéro `Math.random`, zéro timer, zéro rAF, zéro `innerHTML`, zéro `console.*`, aucun fichier partagé modifié.

Le cœur du chantier est un générateur pseudo-aléatoire **déterministe** : `mulberry32` (`E065.js:91-100`) est semé par une empreinte FNV-1a du DOM rendu (`E065.js:81-88`, `:104-113`, `:155`). Le seul visuel pseudo-aléatoire ajouté — un bandeau de barres — est donc reproductible, et sa graine est **affichée en clair** dans le DOM (`E065.js:180-182`). Il ne s'agit pas de hasard : aucune source d'entropie, aucune horloge, aucun `Math.random` n'intervient.

## E065-01 — PRNG mulberry32 local, aucune graine aléatoire

- **Preuve** : `E065.js:90-100` définit `mulberry32(seed)` : `let a = seed >>> 0`, puis la suite `a = (a + 0x6d2b79f5) | 0`, `t = Math.imul(t ^ (t >>> 15), t | 1)`, `t ^= t + Math.imul(t ^ (t >>> 7), t | 61)`, retour normé `((t ^ (t >>> 14)) >>> 0) / 4294967296`. Seul `Math.imul` est utilisé, jamais `Math.random`. L'en-tête (`:14-23`) pose l'invariant « zéro Math.random : toute variation vient de mulberry32 … jamais d'une horloge ». `E065.js:141-143` injecte la feuille unique via `css(CSS_ID, CSS)` (`CSS_ID` à `:26`, feuille à `:38-67`) et ancre la portée sur `.points-layout` (`classList.add(SCOPE)` + `data-points-e065="1"`).
- **Solution** : le PRNG est une fonction locale pure du module, instanciée à chaque rendu avec la même graine quand le DOM est identique. Aucune librairie tierce n'est inlinée : l'algorithme tient en dix lignes et ne dépend que d'entiers 32 bits.
- **Impact** : le comportement est reproductible d'un rendu à l'autre et d'un environnement à l'autre ; aucun test ne peut être rendu flaky par une variation aléatoire. La contrainte « zéro Math.random » est vérifiable par simple recherche textuelle (les seules occurrences sont dans des commentaires et dans le libellé « Math.random : 0 appel »).
- **Effort** : S
- **Vérification** : relecture de `:90-100` ; recherche `Math\.random\(` dans le module → aucune occurrence d'appel ; `grep` de `Math.imul` → trois usages (`:85`, `:96`, `:97`) ; contrôle `node --check` PASS.

## E065-02 — Graine affichée en clair dans le DOM

- **Preuve** : `E065.js:180-182` crée (via `place`) le paragraphe `#points-e065-seed` (`SEED_ID` à `:29`) et écrit : `Graine : 0x<hex> (<décimal>) · mulberry32 · empreinte DOM FNV-1a.` Le formatage `seed.toString(16).toUpperCase().padStart(8, '0')` (`:181`) donne une empreinte hexadécimale stable de huit caractères. CSS dédiée à `:44-47` (chiffres tabulaires, mesure lisible).
- **Solution** : la graine n'est pas cachée dans une variable de module : elle est exposée comme texte sémantique dans un `<p>` visible, donc indexable, copiable et comparable entre deux rendus. La même valeur est aussi reportée dans `panel.dataset.pointsE065Seed` (`:207`) pour un contrôle automatisé.
- **Impact** : toute personne peut vérifier que deux rendus identiques produisent le même visuel, et qu'une modification du DOM modifie la graine de façon prévisible. La condition « graine affichée si visuel pseudo-aléatoire » est littéralement remplie.
- **Effort** : S
- **Vérification** : relecture de `:180-182` et `:207` ; harnais : lire `#points-e065-seed` avant et après un rendu identique → chaîne identique ; comparer sa partie hexadécimale à `data-points-e065-seed` du panneau → égalité.

## E065-03 — Visuel pseudo-aléatoire déterministe et borné

- **Preuve** : `E065.js:159-163` instancie `mulberry32(seed)`, tire `bars` valeurs dans un tableau `values` et compte `draws`. `E065.js:187-195` construit le bandeau `#points-e065-strip` : chaque `span.points-e065-bar` reçoit `style.height = ${Math.round(10 + value * 90)}%` et un `title` « tirage N : 0.xxx ». La hauteur est donc une fonction directe du tirage, sans couleur porteuse d'information. Le nombre de barres est `Math.min(MAX_BARS, Math.max(1, filled))` (`:157`) avec `MAX_BARS = 32` (`:33`). CSS du bandeau à `:48-55`.
- **Solution** : le bandeau est le seul élément pseudo-aléatoire de la lentille. Il est décoratif, clairement nommé comme tel, et dérivé d'un compteur réel (`filledCount`, `:115-117`) pour sa largeur et du PRNG pour sa texture. Aucun canvas n'est créé : la compétence canvas (DPR, budget par frame) reste aux lentilles E064/E069.
- **Impact** : une démonstration visible et falsifiable de l'absence de hasard, sans coût graphique ni dépendance WebGL. Le plafond de 32 barres garde le coût de rendu constant même si la matrice grossit.
- **Effort** : M
- **Vérification** : relecture de `:157`, `:159-163`, `:187-195` ; harnais : deux rendus sur le même DOM → mêmes `style.height` et mêmes `title` ; faire varier le nombre de cellules renseignées → le nombre de barres suit `min(32, filled)` ; confirmer l'absence de `document.createElement('canvas')` dans le module.

## E065-04 — Reproductibilité auto-vérifiée

- **Impact** : la propriété centrale du chantier devient observable et testable : un harnais lit `data-points-e065-repro` au lieu de devoir reconstruire la séquence.
- **Effort** : S

## E065-06 — Graine dérivée du DOM, sans date ni compteur de rendu

- **Preuve** : `fnv1a()` (`:81-88`) hash `text` avec l'offset basis `0x811c9dc5` et le facteur `0x01000193` via `Math.imul`. `domSignature()` (`:104-113`) parcourt `.points-grid-row` (`:106`), pousse le nom de l'ère lu dans `.points-era` (`:107`), puis pour chaque `.points-cell` pousse le compteur `has-points` ou `'0'` (`:108-110`) et joint le tout par `'|'` (`:112`). `E065.js:155` applique `fnv1a(domSignature(layout))`. Le commentaire `:102-103` précise : « Aucune date, aucun compteur de Rendu, aucune valeur issue du hasard ».
- **Solution** : la source de vérité est le rendu lui-même, et non un état module ou une horloge. Le hachage FNV-1a est choisi pour sa stabilité et son absence de graine secrète : deux DOM identiques donnent deux graines identiques, avec un coût linéaire en nombre de cellules.
- **Impact** : la lentille reste vraie quand le jeu de données change ; la graine évolue avec les ères, domaines et compteurs effectivement affichés. Aucun millésime n'est inventé, aucune affirmation historique n'est faite.
- **Effort** : M
- **Vérification** : relecture de `:81-88`, `:104-113`, `:153-157` ; recherche de `Date`, `Date.now`, `performance.now` dans le module → aucune occurrence ; harnais : deux DOM identiques → même graine ; ajouter une cellule `has-points` → graine différente.

Les attributs de données offrent la même information sous forme machine.
- **Impact** : la performance et la rigueur deviennent mesurables sans instrumentation externe ; un audit automatisé peut comparer `draws` au nombre attendu (`bars + 3`).

## E065-08 — Idempotence multi-rendus et anti-doublon

- **Preuve** : `place()` (`:121-130`) retire un nœud mal parenté (`:123`), ne recrée que si le nœud est absent ou déconnecté (`:124-128`), sinon le réutilise. Le panneau, la ligne de graine, le bandeau, la description et l'audit passent tous par `place` (`:175`, `:180`, `:187`, `:197`, `:200`). Le point d'entrée `register('E065', (ctx) => { try { apply(ctx); } catch { return; } })` (`:213-219`) neutralise silencieusement une structure inattendue, comme les autres lentilles du chantier. Le CSS est fédéré par `cssOnce` via `ctx.css` (`:141`).
- **Solution** : aucune variable module ne référence un nœud entre deux rendus ; l'identifiant est la seule clé de récupération. Un second passage sur le même DOM remplace le contenu par `replaceChildren` (`:195`) sans créer de doublon, sans ajouter d'écouteur.
- **Impact** : navigation aller-retour, changement de filtre ou re-render de la coque ne laissent qu'un seul `#points-e065-panel` et un seul bandeau ; aucune fuite d'écouteur ni de style.
- **Effort** : M
- **Vérification** : relecture de `:121-130`, `:141`, `:175-210`, `:213-219` ; harnais : appeler deux fois l'apply sur le même `layout` → `document.querySelectorAll('#points-e065-panel').length === 1` ; re-rendre → toujours un seul panneau, graine cohérente avec le nouveau DOM.

## E065-09 — Accessibilité du visuel et mouvement réduit

- **Preuve** : le panneau est un `<section role="group" aria-label="Signature déterministe de couverture, sans aléa">` (`:175-177`). Le bandeau porte `aria-hidden="true"` (`:188`) : sa texture n'est pas imposée aux lecteurs d'écran. Une contrepartie textuelle explicite est fournie par `#points-e065-desc` (`:197-198`) : « Bandeau décoratif … Il n'encode aucune donnée de couverture ». La ligne d'audit est une région `role="status" aria-live="polite"` (`:200-202`). Aucune information n'est portée par la seule couleur : la hauteur et le `title` de chaque barre portent la valeur. Le couplage mouvement réduit est double : attribut `data-points-e065-reduced` posé depuis `ctx.reducedMotion()` (`:145-151`) et media query neutralisant la transition (`:64-66`) ; repli mobile à 620 px (`:60-63`).
- **Solution** : visuel décoratif masqué à l'AT, sens donné par le texte, état annoncé une seule fois par la région live locale. Aucune animation n'existe dans la lentille — le CSS de mouvement réduit est une garantie, pas un correctif.
- **Impact** : la démonstration reste compréhensible sans voir le bandeau ; aucun conflit avec la région live unique d'E041 ; le rendu reste lisible en 390×844 et ne contredit pas la préférence système.
- **Effort** : M
- **Vérification** : relecture de `:145-151`, `:175-177`, `:188`, `:197-203`, `:60-66` ; contrôle : `aria-hidden="true"` présent sur le bandeau, texte équivalent présent ; émuler `prefers-reduced-motion: reduce` → attribut sur `.points-layout` et aucune transition active ; absence de `requestAnimationFrame`/`setTimeout`.

## E065-10 — Coût borné et passe de calcul unique

- **Preuve** : `MAX_BARS = 32` (`:33`) et `bars = Math.min(MAX_BARS, Math.max(1, filled))` (`:157`) bornent le nombre d'éléments créés et de tirages. Une seule passe produit `values` (`:159-163`), puis trois tirages de contrôle (`:165-172`) : `draws = bars + 3`, sans boucle d'animation. Aucun `requestAnimationFrame`, `setTimeout`, `setInterval`, `MutationObserver`, `IntersectionObserver` ni écouteur n'apparaît dans le module (`:205-210` ne fait qu'écrire quatre attributs). La feuille (`:38-67`) n'utilise aucune transition sauf neutralisation sous mouvement réduit.
- **Solution** : calcul synchrone unique par appel, stocké dans des tableaux locaux puis poussé en une seule opération `replaceChildren` (`:195`). L'empreinte DOM est parcourue une seule fois (`:104-113`), sans observation continue.
- **Impact** : coût constant et prévisible, indépendant du nombre de rendus ; aucune frame superflue, aucun timer qui survivrait à la navigation, aucune interaction avec le budget canvas des lentilles voisines.
- **Effort** : S
- **Vérification** : relecture de `:33`, `:104-113`, `:157-172`, `:195`, `:205-210` ; recherche de `requestAnimationFrame|setTimeout|setInterval|IntersectionObserver|MutationObserver|addEventListener` → aucune occurrence ; `node --check src/views/points/E065.js` → PASS.

## Blocages / limites inter-domaines

- Le bandeau est **décoratif** : il n'encode aucune donnée de couverture (`E065.js:197-198`). Toute tentation d'y lire un chiffre doit être évitée ; les chiffres réels restent dans `.points-cell` et la ligne d'audit `:203`.
- La graine dépend de la signature du DOM rendu (`:104-113`) : un changement d'ère, de filtre ou de libellé modifie la graine. C'est un comportement voulu (reproductibilité pour un même état), mais deux périmètres différents produisent deux empreintes différentes ; la comparaison n'est valable qu'à état constant.
- FNV-1a n'est pas une fonction de hachage cryptographique et mulberry32 n'est pas un PRNG cryptographique : ils servent ici à la stabilité visuelle, jamais à la sécurité. Aucune valeur secrète n'est traitée.
- `data-points-e065*` est écrit sur le panneau (`:207-210`) et `data-points-e065` / `data-points-e065-reduced` sur `.points-layout` (`:143`, `:148-150`). Toute lentille qui réécrirait ces attributs devra les préserver.
- Le plafond de 32 barres (`:33`, `:157`) est un choix de performance : au-delà, la texture serait tronquée sans perte d'information (le bandeau n'étant pas une donnée).
