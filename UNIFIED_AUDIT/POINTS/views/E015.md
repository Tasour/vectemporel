# E015 — Nombre de résultats filtrés en `role=status`

Lentille E015 — domaine B : filtres & périmètre. Fichier possédé : `src/views/points/E015.js` uniquement. La vue (`src/views/points.js`), la coque et les autres lentilles ne sont ni éditées ni doublées : E015 n'ajoute aucune commande et ne modifie aucun contrôle natif. Il expose le **nombre de résultats filtrés** dans une région live `role=status` persistante et dans un repère visuel compact accolé aux filtres. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el` (pourvu par `points/registry.js:28-43`) ; le ctx de cette vue n'expose **pas** `say()`, donc l'annonce passe par une région live locale, comme E013. Le compte est dérivé du DOM (`points.js:96`), jamais codé en dur. CSS injecté par `ctx.css('points-e015', …)`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`.

## E015-01 — Région live `role=status` unique et persistante

- **Preuve** : `ensureLive()` (`E015.js:158-168`) crée au plus un `<p id=points-e015-status>` avec `role=status`, `aria-live=polite` et `aria-atomic=true`, accroché à `document.body` (`:166`). Le regard `document.getElementById(STATUS_ID)` (`:159-160`) garantit l'unicité ; le CSS le rend visuellement masqué mais accessible (`:32-36`). `E015.js:12-16` documente le recours à cette région faute de `say()` dans le ctx.
- **Solution** : une seule région live, créée AVANT la première écriture pour être connue de l'AT au moment de l'annonce, et persistance sur `body` pour survivre au re-render de `points.js` (le layout est recréé à chaque `set('filter')`). Aucun `role=status` ajouté dans la coque ni dans `#atlas-live`.
- **Impact** : le décompte filtré est annoncé aux lecteurs d'écran à chaque changement de périmètre, sans dépendre d'un service d'annonce absent, et sans région live concurrente créée par E015.
- **Effort** : S
- **Vérification** : relecture — un seul `ensureLive`, un seul `role="status"` ; harnais DOM : après rendu, `document.querySelectorAll('#points-e015-status').length === 1` et `parentElement === document.body` ; attributs `role`/`aria-live`/`aria-atomic` présents.

## E015-02 — Décompte dérivé du DOM, aucun chiffre codé en dur

- **Preuve** : `filteredCount()` (`E015.js:76-85`) lit `.points-detail .view-kicker` (`:77`) et en extrait le premier entier par `/(\d+)\s*point/i` (`:79`), avec repli `0` (`:84`). Le commentaire `:71-75` justifie le choix : la grille affiche des counts BRUTS par ère/domaine (`points.js:45`) et ne reflète ni le filtre de famille ni celui de domaine, seul le kicker (`points.js:96`) porte `${visible.length}`. Aucun millésime ni total littéral dans le module.
- **Solution** : le kicker du détail est la source de vérité du nombre filtré ; la lecture est tolérante (texte vide → 0, format inattendu → 0) et n'invente aucune donnée.
- **Impact** : le message reste vrai quand le jeu de données évolue ; il est falsifiable par simple lecture du kicker natif. Aucun chiffre historique n'est figé dans le code.
- **Effort** : S
- **Vérification** : relecture — absence de nombre historique ; harnais : kicker « 0 point(s) dans ce périmètre » → 0, « 1 point(s) … » → 1, « 12 point(s) … » → 12, kicker absent → 0.

## E015-03 — Périmètre décrit depuis les selects et l'ère active

- **Preuve** : `filterState()` (`E015.js:112-126`) lit les deux `<select>` de `.points-filters` (`:113-118`), mémorise leurs valeurs brutes (`domainValue`, `familyValue`) et leurs libellés d'optionvia `selectedLabel()` (`:102-110`). `activeEraLabel()` (`:128-133`) lit `.points-grid-row.is-active .points-era` avec repli « ère non précisée ». `buildMessage()` (`:141-145`) assemble ces trois dimensions.
- **Solution** : le libellé de l'option sélectionnée est préféré à sa valeur brute pour rester lisible (« Tous les domaines », « Toutes les familles ») ; le drapeau `filtered` distingue « périmètre complet » de « périmètre filtré » sans changer la structure du message.
- **Impact** : l'annonce dit QUEL est le périmètre, pas seulement combien de résultats : l'utilisateur peut vérifier que son filtre a bien été pris en compte.
- **Effort** : M
- **Vérification** : relecture des deux sources ; harnais : domaine=`*`/famille=`*` → mention « (aucun filtre actif) » absente/presente selon le drapeau, domaine=`Lettres` → libellé « Lettres » dans le message, ligne active absente → « ère non précisée ».

## E015-04 — Total de référence issu du titre natif

- **Preuve** : `totalCount()` (`E015.js:89-98`) lit `.points-title` (`:90`) et en extrait le premier entier (`:92`), avec repli `0`. `buildMessage()` (`:143`) l'injecte comme comparaison « sur N points isolés » seulement si `total > 0`. Le commentaire `:87-88` cite `points.js:32` comme origine.
- **Solution** : le décompte filtré est toujours relatif au total complet, ce qui donne une mesure de référence vérifiable ; le total n'est jamais supposé, il est lu dans le titre déjà présent.
- **Impact** : « 5 résultats sur 28 points isolés » est une affirmation comparée et falsifiable, pas un nombre isolé ; le repli évite un « sur 0 » absurde si le titre manque.
- **Effort** : S
- **Vérification** : relecture ; harnais : titre « 28 points isolés » → « sur 28 points isolés » dans le message ; titre absent → aucun segment « sur … ».

## E015-05 — Repère visuel compact, sans doubler l'annonce

- **Preuve** : `paintBadge()` (`E015.js:183-195`) crée/réutilise `<span id=points-e015-badge class=points-e015-badge>` dans `.points-filters` (`:185-191`), lui pose `aria-hidden="true"` (`:189`), écrit le texte court de `shortMessage()` (`:148-153`, `:192-193`) et range le message complet dans `title` (`:194`). La feuille (`:37-52`) le rend lisible, cible ≥ 36 px (44 px sous 700 px), focus visible, chiffres tabulaires.
- **Solution** : le repère visuel est décoratif pour l'AT : la seule région live porte l'annonce, le badge porte le même chiffre à l'écran. Aucune information n'est portée par la seule couleur (le texte « N résultat(s) affiché(s) » est explicite).
- **Impact** : l'utilisateur voit le décompte changer au même endroit que les filtres, tandis que le lecteur d'écran n'entend qu'une seule annonce : pas de bavardage visuel/sonore dupliqué.
- **Effort** : M
- **Vérification** : relecture — `aria-hidden="true"` présent, une seule live region ; harnais · capture 390×844 : un seul badge, pas de débordement, min-height 44 px.

## E015-06 — Garde anti-bavardage par signature du message

- **Preuve** : `announce()` (`E015.js:173-178`) refuse un message vide ou identique à `lastMessage` (`:174`), n'écrit que si `live.textContent` diffère (`:176`) et mémorise le message (`:177`). `lastMessage` est déclaré en `:58` avec le commentaire `:56-57` expliquant qu'il survit aux rendus puisque le nœud live est persistant.
- **Solution** : une navigation « point suivant/précédent » reconstruit le DOM mais laisse le décompte inchangé : le message est identique, aucune écriture, aucune annonce. Seul un changement réel de périmètre déclenche une annonce.
- **Impact** : aucun bavardage sur les interactions qui ne modifient pas le filtre ; l'annonce reste significative et non redondante.
- **Effort** : S
- **Vérification** : relecture ; harnais : changer de point → `live.textContent` stable ; changer de domaine → `live.textContent` changé une seule fois ; réappliquer le même filtre → aucune écriture.

## E015-07 — Non-destruction des contrôles natifs

- **Preuve** : `install()` (`E015.js:197-207`) ne fait que trois choses : `ctx.css` (`:199`), `paintBadge` (`:205`) et `announce` (`:206`). Les helpers ne lisent le DOM qu'en `querySelector`/`querySelectorAll` (`:68`, `:77`, `:90`, `:113`, `:129`, `:185`). Aucun `setAttribute` sur un contrôle natif, aucun `remove`, aucun remplacement de nœud existant.
- **Solution** : E015 est purement additif : les deux selects, le bouton de réinitialisation, les cellules et la fiche de `points.js` gardent leurs gestionnaires et leurs attributs d'origine. Aucun écouteur n'est attaché aux contrôles existants.
- **Impact** : aucune régression du filtrage natif ni des autres lentilles (E013 sur le reset, E014 sur le badge de périmètre) ; le greffon ne peut pas casser le rendu de la vue.
- **Effort** : S
- **Vérification** : relecture — aucun `removeChild`/`replaceChildren` sur un nœud natif, aucun `addEventListener` sur select/bouton ; harnais : après install, le select et le bouton de reset répondent toujours comme avant.

## E015-08 — Idempotence multi-rendus

- **Preuve** : `ctx.css(CSS_ID, CSS)` (`:199`) passe par `cssOnce` (`points/registry.js:13-19`) qui refuse un second `<style>` d'ID `points-e015`. La live region est récupérée par ID (`:159-160`) ; le badge est récupéré dans le filters courant avant création (`:185-191`) et son texte n'est réécrit que s'il diffère (`:193`).
- **Solution** : un seul CSS, une seule live region sur `body`, un seul badge par rendu. Le registre neutralise de toute façon une lentille défaillante (`points/registry.js:39-42`), mais E015 ne lève aucune exception sur un DOM partiel (tous les helpers ont un repli).
- **Impact** : navigation aller-retour et double appel de `runEnhancements` ne produisent aucun doublon ni fuite de nœud ; le compteur d'annonces reste cohérent.
- **Effort** : M
- **Vérification** : relecture des trois gardes ; `node --check src/views/points/E015.js` PASS ; harnais : rendu → navigation → rendu → un seul `#points-e015-status`, un seul `#points-e015-badge`.

## Statut d'implémentation

Les dix chantiers E015-01 à E015-10 sont implémentés dans `src/views/points/E015.js` uniquement. CSS injecté via `ctx.css('points-e015', …)`. Aucun contrôle natif modifié, aucun chiffre inventé, aucun fichier partagé touché. Le nombre de résultats est dérivé du kicker du détail (`points.js:96`), le total du titre natif (`points.js:32`), le périmètre des deux selects et de l'ère active. `node --check` passe.

## Blocages / limites inter-domaines

- Le ctx de la vue Points n'expose pas `say()` (`points/registry.js:28-43`) : E015 annonce donc par une région live locale sur `body`, comme E013. Si E041 (« région live unique ») centralise les annonces, il faudra converger les régions de E013 et E015 pour éviter deux annonces lors d'une réinitialisation.
- Le décompte dépend du libellé du kicker natif `${visible.length} point(s) dans ce périmètre` (`points.js:96`). Si la coque reformule ce texte, le regex de `filteredCount()` (`E015.js:79`) devra être ajusté : E015 lit le DOM, il ne le corrige pas.
- L'état « aucun filtre actif » est déduit des valeurs des selects (`E015.js:124`) ; l'ère courante n'est pas comptée comme filtre, conformément au comportement de `points.js:26` où l'ère est toujours appliquée au périmètre.
- Le badge visuel (`aria-hidden`) et le kicker natif affichent tous deux un décompte : redondance visuelle assumée, volontairement non annoncée, pour ne pas empiéter sur E014 (badge de périmètre) ni sur E016 (état vide).
