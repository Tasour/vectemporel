# E092 — Pédagogie & narration

Lentille E092 — domaine J : pédagogie & narration.
Fichier possédé : src/views/points/E092.js uniquement. La vue (src/views/points.js), la coque, styles.css et POINT_METHODOLOGY.md ne sont ni édités ni doublés. La lentille ajoute UN panneau pédagogique local dans .points-matrix, sous le titre de la matrice, et n'altère aucun contrôle existant (filtres, cellules, navigation, fiche).

Source doctrinale citée et attribuée : POINT_METHODOLOGY.md v1.0 — définition opératoire (§1), huit familles (§2), règles d'intégrité (§3), couverture explicite (§4), hiérarchie (§5). Toute valeur historique affichée est dérivée du DOM rendu (.points-detail, .points-grid) : aucun millésime, aucun total, aucune famille n'est codé en dur, et le module n'importe ni le store ni le dataset.

Contrat exploité : viewId, layout, css, el, reducedMotion (`stage` est reçu via ctx mais n'est pas utilisé : le greffage se fait depuis `layout`). Invariants : un seul greffon, un seul CSS (ctx.css avec l'identifiant points-e092), un seul panneau (#points-e092-guide), tous les identifiants préfixés points-e092-, zéro réseau, zéro aléa, zéro timer, zéro rAF, aucune réinterprétation de balisage, aucun écouteur global, non-destruction et idempotence sur rendu neuf.

- **Impact** : l'explication est disponible dès l'ouverture de la vue (details ouvert par défaut, E092.js:312) sans masquer la matrice, sans piège de focus et sans modifier les contrôles existants.

## Statut d'implémentation

Les dix chantiers E092-01 à E092-10 sont implémentés dans `src/views/points/E092.js` uniquement. CSS injecté via `ctx.css('points-e092', …)`. Aucune vue, aucune coque, aucune feuille partagée et aucun document doctrinal n'a été modifié. Le panneau est non destructif (aucun contrôle existant déplacé ou réécrit) et idempotent (un seul `#points-e092-guide`, reconstruit à chaque rendu).

## Blocages / limites inter-domaines

- `points.js:108-109` crée le conteneur `.points-families` mais n'y déplace pas les puces : dans le rendu brut, les familles sont des `<span>` enfants directs de `.points-detail`. Le repère E092-05 dépend donc de E024 (enregistré avant E092), qui réparent ces puces dans `.points-families`. Si E024 était neutralisé, les huit familles et leurs questions resteraient affichées mais aucun repère « famille du point affiché » ne serait posé : aucun libellé erroné n'est produit. Le fichier partagé `points.js` n'est pas corrigé ici (hors périmètre de la lentille).
- Le guide est purement lecteur : il rapporte les valeurs déjà rendues dans `.points-detail` et `.points-matrix`. Il ne corrige ni une métadonnée manquante, ni une certitude erronée, ni une source absente ; il les signale par des replis explicites (`non affiché…`, `aucune source affichée…`).
- Aucune région live ni annonce n'est ajoutée : E092 écrit du texte statique visible. Si une autre lentille possède la région live de la vue, il n'y a pas de conflit d'écriture.
- Le signal `data-e092` / `data-e092-reduced` est posé sur `.points-layout` : toute lentille qui réécrirait ces attributs devra le préserver. Le greffage reste auditable par leur présence.
