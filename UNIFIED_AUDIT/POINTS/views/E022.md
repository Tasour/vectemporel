# E022 — Bloc de certitude au libellé explicite

Lentille E022 — domaine C : détail & fiche. Fichier possédé : `src/views/points/E022.js` uniquement. La vue de base (`src/views/points.js:95-114`) dépose la confiance du point sélectionné sous forme d'un badge nu, `<span class="confidence is-…">vérifié</span>, perdu dans `.points-meta` : aucun libellé explicite, aucune glose, aucun repère non coloré. E022 ne réécrit pas ce balisage et ne touche à aucun fichier partagé : il ajoute, à côté du badge d'origine, un bloc de certitude intitulé « Certitude déclarée » dont le libellé, la marque et la glose sont dérivés du seul token déjà présent dans le DOM. Contrat exploité : `ctx = { viewId, stage, layout, css, el, reducedMotion }`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. CSS injecté par `ctx.css('points-e022', …)` ; tous les identifiants sont préfixés `points-e022-`.

## E022-01 — Garde d'entrée : lentille neutre sans détail valide

- **Preuve** : `E022.js:232-235` vérifie `ctx`, `ctx.layout` via `isElement()` (`:114-116`), puis l'existence de `.points-detail` avant toute écriture ; `:233` exige `css` et `el` en fonction.
- **Solution** : un contexte incomplet, un `layout` absent ou un détail introuvable neutralise la lentille sans exception ni artefact. Aucune hypothèse sur les autres lentilles ni sur la coque.
- **Impact** : l'ajout reste purement complémentaire ; un rendu partiel ou une vue voisine ne peut pas déclencher d'erreur en cascade via le registre.
- **Effort** : S
- **Vérification** : relecture de `:232-235` ; harnais — (a) `ctx` vide, (b) `layout` sans `.points-detail`, (c) `css`/`el` manquants : trois appels sans ajout DOM ni levée d'erreur.

## E022-02 — Feuille unique, identifiant dédié, sans ressource externe

- **Preuve** : `CSS_ID = 'points-e022'` (`:23`) et l'appel unique `ctx.css(CSS_ID, CSS)` (`:238`) ; la feuille `CSS` (`:38-100`) n'utilise que des variables locales avec repli (`var(--line, …)`, `var(--gold, …)`, `var(--ink, …)`), aucun `url(http…)`, aucun `@import`. Le registre applique `cssOnce`, donc une seule feuille `<style id="points-e022">` par page.
- **Solution** : toute la mise en forme du bloc vit dans une seule chaîne CSS, injectée une fois, indépendamment du nombre de rendus. Les sélecteurs sont tous ancrés sur `#points-e022-certainty`.
- **Impact** : aucun style global modifié, aucune dépendance réseau, aucun conflit avec les feuilles des autres lentilles ; l'identifiant `cssOnce` garantit l'unicité.
- **Effort** : S
- **Vérification** : relecture de `:38-100` et `:238` ; contrôle — un seul `<style id="points-e022">` après navigation aller-retour ; absence de `url(`, `@import`, `fetch`, `XMLHttpRequest`.

## E022-03 — Bloc inséré au libellé explicite, sans toucher au badge d'origine

- **Preuve** : `buildBlock()` (`:163-186`) crée le conteneur `#points-e022-certainty` avec un titre `p.points-e022-label` portant le texte littéral « Certitude déclarée » (`:169`) ; `mount()` (`:189-215`) l'insère juste après `.points-meta` (`:207-213`) par `insertBefore`/`appendChild`, jamais à l'intérieur du badge.
- **Solution** : le badge `confidence is-…` d'origine reste en place et inchangé ; le bloc ajouté en est l'explicitation lisible. En cas de bloc déjà présent mais mal parenté, `mount()` le retire avant de le reconstruire (`:190-204`), ce qui garantit l'idempotence.
- **Impact** : la fiche gagne un intitulé sans perte d'information ni duplication ; le lecteur voit « Certitude déclarée » suivi de la valeur, au lieu d'un mot isolé dont on ignore la portée.
- **Effort** : M
- **Vérification** : relecture de `:163-215` ; harnais — le badge `.points-meta .confidence` est toujours présent après installation ; un seul `#points-e022-certainty` dans le détail après deux appels de `register`.

## E022-04 — Traduction déterministe du token et repli honnête

- **Preuve** : la table `LABELS` (`:30-36`) associe `vérifié`, `certain`, `probable`, `disputed`, `non documenté` à un libellé, une marque et une glose ; `describe()` (`:134-140`) normalise en minuscules françaises, sert l'entrée connue, puis retombe sur « Non renseignée » (`:138`) ou sur le token brut avec la mention « repris tel quel de la fiche » (`:139`).
- **Solution** : même discipline que `recit.js:8-13` — on traduit un libellé d'audit en libellé d'interface, on n'invente aucun fait historique. Un token inconnu n'est jamais rangé dans une catégorie arbitraire : il est réaffiché tel quel.
- **Impact** : le bloc reste vrai quand le jeu de données évolue ; aucune affirmation non sourcée n'est ajoutée, et la traduction de `disputed` est explicitement documentée dans la glose.
- **Effort** : S
- **Vérification** : relecture de `:30-36` et `:134-140` ; contrôles — `vérifié` → « Vérifié / ✓ », `disputed` → « Contesté / ≈ », `incertain` → libellé `incertain` non transformé, chaîne vide → « Non renseignée ».

## E022-05 — Signal non coloré : marque textuelle, mot et glose

- **Preuve** : `.points-e022-mark` (`:68-73`) porte la marque (`✓`, `■`, `◐`, `≈`, `?`, `•`) et est marqué `aria-hidden="true"` (`:176`) ; le mot lisible est porté par `wordRef` (`:177`, `:152`) et la glose par `glossRef` (`:181`, `:153`). Le `border-left` doré (`:44`) n'est qu'un renfort visuel.
- **Solution** : la certitude est portée trois fois — par un symbole, par un mot et par une phrase — jamais par la couleur seule. La marque est retirée de l'arbre d'accessibilité pour ne pas être épelée par le lecteur d'écran.
- **Impact** : le niveau de confiance reste distinguishable en grayscale, en `forced-colors` (`:92-95`) et sans CSS ; aucune information critique ne dépend de la teinte.
- **Effort** : S
- **Vérification** : relecture de `:68-73`, `:152`, `:176-177` ; contrôle — désactiver les couleurs : la marque et le mot restent lisibles ; le nœud `.points-e022-mark` porte bien `aria-hidden="true"`.

## E022-06 — Sémantique de groupe et texte indexable

- **Preuve** : `buildBlock()` pose `role="group"` et `aria-labelledby="points-e022-certainty-label"` sur le conteneur (`:166-167`) ; le titre (`:169-171`) et les deux paragraphes (`:173-182`) sont de vrais nœuds de texte créés par `ctx.el`. Un span visuellement masqué (`:174`, CSS `:80-84`) préfixe la valeur par « Pour « sujet », certitude : » (`:154`).
- **Solution** : le bloc est un groupe nommé, parcourable au lecteur d'écran, dont tout le contenu significatif est du texte réel — aucun `aria-hidden` sur le sens, aucun contenu généré uniquement par CSS. Le sujet du point est relié au bloc pour le contexte.
- **Impact** : l'intitulé et la valeur sont annonçables et reproductibles hors style ; le bloc ne dépend d'aucune région live ni d'aucune annonce parasite.
- **Effort** : M
- **Vérification** : relecture de `:166-182` ; contrôle au lecteur d'écran — le groupe est annoncé comme « Certitude déclarée, … Vérifié » ; le préfixe « Pour « … » » est bien lu et le symbole ne l'est pas.

## E022-07 — Dérivation 100 % DOM, aucune donnée codée en dur

- **Preuve** : `readSignals()` (`:124-131`) lit le token sur `.points-meta .confidence` (`:125`) et le sujet sur `.points-point-title` (`:126`) ; `paint()` écrit ces valeurs dans `data-e022-token` et `data-e022-subject` (`:155-156`). Aucun millésime, aucun total ni aucune chaîne historique n'apparaît dans le module (les seules chaînes littérales sont des libellés d'interface).
- **Solution** : la lentille se contente de rendre lisible un état déjà porté par la fiche. Le sujet n'est pas dupliqué visuellement : il est conservé comme attribut de traçabilité et dans le préfixe accessibility.
- **Impact** : le bloc suit exactement la sélection courante ; changer de point ou de filtre ne peut pas laisser une certitude périmée, et le greffon reste vrai si le jeu de données change.
- **Effort** : S
- **Vérification** : relecture de `:124-131`, `:155-156` ; contrôle — faire varier la sélection : `data-e022-token` et `data-e022-subject` changent sans modification du code ; recherche vaine de `\d{3,4}` dans le fichier hors commentaires.

## E022-08 — Rafraîchissement sans `innerHTML`, signature et compteur auditable

- **Preuve** : `paint()` (`:143-159`) n'écrit que par `textContent` et `setAttribute` ; il calcule `signature = token + '\u0000' + subject + '\u0000' + label` (`:146`), sort sans écrire si la signature est inchangée (`:147`), incrémente `updateCount` (`:149`) et l'expose dans `data-e022-updates` (`:157`).
- **Solution** : la structure statique est construite une seule fois ; seuls les textes sont remplacés. La signature évite les réécritures redondantes déclenchées par l'observateur, et le compteur fournit une trace vérifiable du comportement.
- **Impact** : aucune réinterprétation de balisage, nombre borné d'écritures DOM ; les métriques permettent de distinguer « aucun changement de certitude » de « greffon muet ».
- **Effort** : M
- **Vérification** : relecture de `:142-159` ; absence de `innerHTML`, `outerHTML`, `insertAdjacentHTML` ; rejeu — deux mutations sans changement de signature laissent `data-e022-updates` stable, un changement de token l'incrémente d'une unité.

## E022-09 — Mouvement réduit, contraste forcé et repli mobile

- **Preuve** : `motionAllowed()` (`:118-121`) interroge `ctx.reducedMotion()` dans un `try/catch` ; la classe `points-e022-motion` et l'attribut `data-e022-motion` ne sont posés que si le mouvement est autorisé (`:254-255`). La transition n'existe que sous cette classe (`:85-88`) et est neutralisée par `@media (prefers-reduced-motion: reduce)` (`:89-91`). `@media (forced-colors: active)` (`:92-95`) et `@media (max-width: 480px)` (`:96-99`) complètent la feuille.
- **Solution** : aucune animation propre inconditionnelle : la seule transition est un léger déplacement de la marque, désactivé dès que l'utilisateur demande la réduction du mouvement ou que `ctx.reducedMotion()` le signale. Le repli est sûr en cas d'erreur de la fonction.
- **Impact** : l'ajout ne contredit pas la préférence système ; le bloc reste lisible en 390 px de large et sous contraste forcé, sans débordement.
- **Effort** : S
- **Vérification** : relecture de `:118-121`, `:85-99`, `:254-255` ; contrôles — émuler `prefers-reduced-motion: reduce` → `data-e022-motion="off"` et aucune transition calculée ; capture 390×844 sans débordement du bloc.

## E022-10 — Observateur unique ciblé, idempotence et non-destruction

- **Preuve** : `watch()` (`:219-229`) déconnecte l'observateur existant (`:220`) avant d'en créer un seul (`:224`), ciblé exclusivement sur `.points-meta` (`:225-228`, appel `:261`). La cible est exactement le nœud que E022 n'écrit jamais, donc aucune boucle d'écriture. `refresh()` (`:243-258`) est l'unique chemin de réconciliation : il gère l'apparition et la disparition du token, reconstruit le bloc seulement s'il est déconnecté ou mal parenté (`:252-256`), et retire un bloc orphelin (`:247-249`).
- **Solution** : un seul `MutationObserver` par rendu, déconnecté puis reconnecté ; la garde d'idempotence de `mount()` (`:190-204`) empêche tout doublon. Le badge d'origine n'est jamais modifié. Aucun stockage de nœud périmé : le `detail` est capturé par l'installation courante.
- **Impact** : pas de fuite d'écouteurs, pas de bloc dupliqué après navigation, pas de boucle d'écriture ; la lentille reste non destructive et idempotente sur rendus successifs.
- **Effort** : M
- **Vérification** : relecture de `:190-204`, `:219-229`, `:243-261` ; un seul `new MutationObserver`, un `disconnect()` préalable, aucune observation du bloc ; `node --check src/views/points/E022.js` PASS ; rendu → navigation aller-retour → rendu : un seul `#points-e022-certainty`, badge d'origine intact, compteur cohérent.

## Statut d'implémentation

Les dix chantiers E022-01 à E022-10 sont implémentés dans `src/views/points/E022.js` uniquement. CSS injecté via `ctx.css('points-e022', …)`. Le badge de confiance d'origine est préservé ; aucune donnée historique inventée, aucun fichier partagé touché.

## Blocages / limites inter-domaines

- Les libellés de `LABELS` (`:30-36`) sont des libellés d'interface traduits du token d'audit, calqués sur `recit.js:8-13`. Si la vue de base change l'orthographe du token (`vérifié` → `vérifiée`), le repli « repris tel quel » s'active : la table devrait être alignée dans E022.js, seul fichier possédé.
- Le bloc est inséré après `.points-meta` (`:207-213`). Si une autre lentille réordonne le détail, E022 lira toujours le badge via son sélecteur de classe, mais la position visuelle du bloc suivra le nouveau `nextSibling` de `.points-meta`.
- L'observateur surveille `.points-meta`, pas le détail entier (`:225-228`). Une modification du titre seul, sans mutation de `.points-meta`, ne déclenche pas de rafraîchissement : le sujet affiché reste celui de la dernière passe. Un changement de point dans la vue recrée le DOM et repasse donc par `register`.
- Aucun `say()` n'est utilisé : le contrat de la vue Points n'expose pas de fonction d'annonce (contrairement à la vue Monde). Le bloc est annoncé par sa sémantique de groupe, sans région live supplémentaire.
