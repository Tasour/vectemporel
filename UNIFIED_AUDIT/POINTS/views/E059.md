# E059 — Échelle (local → global) représentée

Lentille E059 — domaine F : sémantique & données. Fichier possédé : `src/views/points/E059.js` uniquement. La vue (`src/views/points.js`), le store, `styles.css`, les autres lentilles et les données ne sont ni édités ni doublés. E059 ajoute une **règle d'échelle locale** dans le panneau `.points-detail` : elle lit l'échelle du point directement dans le DOM (le second `span` de `.points-meta`, écrit par `points.js:100-107`), la traduit en français et la situe sur un continuum ordonné **local → régional → national → impérial → transnational/global**. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el` (tels que fournis par `points/registry.js`). Aucune dépendance vers le dataset, le store, le routeur ou une autre lentille. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. CSS injecté par `ctx.css('points-e059', …)`.

## E059-01 — Portée CSS unique et strictement locale

- **Preuve** : `E059.js:219` appelle `ctx.css(CSS_ID, CSS)` avec `CSS_ID = 'points-e059'` (`:25`). La feuille (`:57-99`) ne contient que des sélecteurs préfixés `#points-e059-…` ou `.points-e059-…`, intention documentée en `:54-56`. Les points de rupture (`:93-95`) et le repli mouvement réduit (`:96-98`) sont dans la même feuille. Aucun sélecteur d'élément nu, aucun `!important` global, aucune règle sur `.points-layout` lui-même.
- **Solution** : une seule injection via `ctx.css('points-e059', …)` (cssOnce), tous les préfixes d'IDs et de classes réservés à la lentille. La règle vit à l'intérieur de `.points-detail`, jamais en enfant direct de `.points-layout` (où `_diagnostics.js:69-79` marquerait le nœud).
- **Impact** : aucun style ne fuit vers la matrice, les filtres ou une autre vue ; la lentille reste tolérée par le tiroir de diagnostic et par les autres greffons du détail.
- **Effort** : S
- **Vérification** : relecture — un seul appel à `ctx.css`, un seul `CSS_ID`, aucune règle non préfixée ; capture 390×844 sans débordement de la règle.

## E059-02 — Échelle lue dans le DOM, sans donnée inventée

- **Preuve** : `metaOf()` (`:109-112`) cible `.points-detail .points-meta` ; `readScale()` (`:114-131`) privilégie la position contractuelle du second span (`:120-121`, écrit par `points.js:100-107`), puis un balayage exact avec un `Set` de déduplication (`:122-129`) ; les alias sont définis en `:46-52` et l'égalité est stricte (`:127`). Le commentaire `:20-21` interdit tout chiffre de jeu de données codé en dur.
- **Solution** : le seul vocable importé est l'échelle réellement affichée. L'égalité exacte empêche le domaine `Circulations transnationales` d'être pris pour une échelle ; une échelle absente produit le repli explicite de `readingText()` (`:138-140`), jamais un silence.
- **Impact** : la règle reflète toujours le point affiché, reste vraie quand le jeu de données évolue et ne transforme aucun `probable` en `certain`.
- **Effort** : M
- **Vérification** : relecture — aucun import de `dataset.js` ni du store, aucun millésime ; harnais DOM : second span vide plus domaine transnational → repli « non renseignée », second span `national` → cran national.

## E059-03 — Règle ordonnée des cinq crans

- **Preuve** : `LADDER` (`:33-42`) est un tableau gelé, ordonné local → régional → national → impérial → global ; `renderLadder()` (`:146-159`) construit une `<ol>` dont chaque `<li>` porte un numéro dérivé de l'index (`:152-154`) et dont le contenu est remplacé par `replaceChildren` (`:158`). Le vocable `transnational` du jeu de données est ramené au cran global (`:51`).
- **Solution** : une liste sémantique ordonnée transforme un jeton brut anglais en gradient lisible, avec numérotation et libellé français. L'ordre est la convention méthodologique, pas une statistique.
- **Impact** : l'échelle devient comparable d'un point à l'autre ; le lecteur voit immédiatement si un point agit sur un site, un pays ou un empire.
- **Effort** : S
- **Vérification** : relecture — une seule `<ol>`, cinq `<li>`, clés ordonnées, aucun nombre aléatoire ; `node --check` PASS.

## Statut d'implémentation

Les dix chantiers E059-01 à E059-10 sont implémentés dans `src/views/points/E059.js` uniquement. CSS injecté via `ctx.css('points-e059', …)`. Aucune vue, aucun fichier partagé, aucune donnée et aucune autre lentille modifiés. La règle ne contient aucun chiffre de jeu de données : seul le jeton d'échelle est lu dans le DOM, le reste est une convention sémantique ordonnée.

## Blocages / limites inter-domaines

- Le détail de `points.js` n'expose qu'une seule échelle à la fois (celle du point courant). E059 ne peut donc pas produire un histogramme réel des échelles du périmètre : une telle mesure demanderait un accès aux points filtrés, hors du contrat de la lentille. Les compteurs affichés sont des rangs sur la règle, pas des effectifs.
- Le jeu de données écrit `transnational` là où la méthodologie écrit `global` : E059 les regroupe sur un même cran et affiche « transnational / global ». Une normalisation officielle du vocabulaire relève du propriétaire de `dataset.js`, fichier non possédé.
- L'état du marquage dépend de la présence du second span de `.points-meta`. Si une autre lentille réordonne ces spans, le repli par égalité exacte prend le relais ; si elle supprime l'information d'échelle, le repli « non renseignée » s'affiche — E059 n'invente rien.
- L'observateur cible `.points-meta`. Une lentille qui remplacerait ce nœud entier à chaque mutation devrait redéclencher l'installation de E059 via le rendu normal de la coque.
