# E004 — Matrice & grille : ligne de l'ère courante explicitement repérée

Lentille E004 — domaine A : matrice & grille. Fichier possédé : `src/views/points/E004.js` uniquement ; aucun fichier partagé (`points.js`, `registry.js`, `store.js`, `index.js`) n'est édité. Contrat exploité : `ctx.layout` (repli `ctx.stage`), `ctx.css`, `ctx.el` tels que fournis par `runEnhancements` (`points.js:126`). Toutes les valeurs affichées sont dérivées du DOM déjà rendu : lignes `.points-grid-row` (dont l'unique `.is-active`), en-tête de `.points-grid`, cellules `.points-cell`/`.has-points`, `.points-title` et `.points-detail`. Aucune donnée inventée, aucune cellule déplacée, aucun écouteur ajouté, aucun timer ni rAF, aucun réseau, aucun aléa, aucun `console.*`. CSS unique via `ctx.css('points-e004', …)` ; tous les identifiants préfixés `points-e004-`. Les dix chantiers sont non destructifs et idempotents : les nœuds ajoutés sont réutilisés par identifiant (`place`, `E004.js:83-94`) et une structure inattendue neutralise la lentille sans propager d'exception (`E004.js:241-247`).

## E004-01 — Matrice nommée et décrite, sans contraindre les boutons

- **Preuve** : `E004.js:124-130` pose `id=points-e004-title` sur le `.points-title` existant, `role=group` et `aria-labelledby` sur `.points-grid`, avec repli `aria-label` si le titre manque ; un paragraphe masqué `points-e004-grid-desc` est créé une fois (`:128-129`) et référencé par `aria-describedby` (`:130`). `E004.js:27`, `:110` garantissent une feuille unique `ctx.css('points-e004', …)`.
- **Solution** : la grille devient un groupe nommable sans imposer `role=grid`/`gridcell` aux boutons `.points-era` et `.points-cell` rendus par `points.js` : aucun conflit de rôle, aucune casse de la commande clavier existante. La description explicite la convention ère × domaine et le sens du repère de ligne courante.
- **Impact** : la matrice acquiert un nom et une description accessibles ; le texte ne contient aucun chiffre codé en dur.
- **Effort** : S
- **Vérification** : relecture — `role=group`, `aria-labelledby`, `aria-describedby` présents ; aucun `role=grid` ; un seul `#points-e004-grid-desc` après deux passages.

## E004-02 — Ligne de l'ère courante explicitement repérée (cœur du thème)

- **Preuve** : `E004.js:115-117` isole l'unique ligne `.is-active`; `E004.js:135-142` écrit `data-e004-current="true"` sur cette ligne seulement, `false` sur les autres, pose `aria-current="true"` sur son bouton `.points-era` et retire tout `aria-current` résiduel sur les lignes inactives (`:141`). Le repère visuel est purement CSS : `E004.js:45-46` (gras, soulignement et préfixe `▶` via `::before`).
- **Solution** : le marquage combine trois signaux redondants mais cohérents — attribut de données pour le CSS, `aria-current` pour les technologies d'assistance, style pour l'œil. Les classes d'origine `is-active` et `has-points` ne sont jamais modifiées : greffon strictement non destructif.
- **Impact** : l'ère courante est repérable immédiatement à l'écran et à la lecture ARIA ; l'unicité est garantie même si plusieurs lignes portaient `is-active` (seule la première est retenue).
- **Effort** : S
- **Vérification** : relecture — exactement un `data-e004-current="true"` et un `aria-current="true"` ; harnais : retirer/ajouter `is-active` puis rejouer → le marquage suit la ligne active sans doublon.

## E004-03 — Étiquettes contextuelles des cellules

- **Preuve** : `E004.js:113-119` dérive les domaines de la ligne d'en-tête (`.is-head > span`, première colonne écartée) et les cellules du DOM ; `E004.js:146-159` compose pour chaque `.points-cell` un `aria-label` du type « Ère ·Domaine : N points validés », ou « aucun point validé » pour une cellule sans `.has-points` (`:151-154`), et écrit `data-e004-era` / `data-e004-domain` (`:156-157`).
- **Solution** : le `title` natif de `points.js` est conservé ; l'`aria-label` ajoute le contexte ère et domaine que la grille visuelle porte par la position. Le singulier/pluriel est ajusté sur la valeur réelle `1`.
- **Impact** : une personne qui ne peut pas voir les en-têtes entend une étiquette complète ; les cellules vides sont nommées au lieu d'être lues comme un simple tiret.
- **Effort** : M
- **Vérification** : relecture — un `aria-label` par cellule, cohérent avec `data-e004-era`/`-domain` ; harnais : cellule « 1 » → « 1 point validé », cellule « · » → « aucun point validé ».

## E004-04 — Rangs ARIA et dimensions de la matrice

- **Preuve** : `E004.js:163-177` pose `aria-posinset`/`aria-setsize` sur chaque `.points-era` (rang parmi les ères, `:166-167`) et sur chaque `.points-cell` (rang parmi les domaines de sa ligne, `:170-173`) ; `:175-177` expose `data-e004-rows`, `data-e004-cols`, `data-e004-cells`. L'étiquette des ères de `:168` inclut le rang et le suffixe « (ère courante) ».
- **Solution** : les rangs sont calculés depuis l'ordre réel des nœuds rendus, jamais supposés ; aucun attribut de position existant n'est écrasé.
- **Impact** : un lecteur d'écran peut annoncer « ère 2 sur 5 » et « cellule 3 sur 7 » ; les compteurs de données permettent un contrôle automatisé.
- **Effort** : S
- **Vérification** : relecture — `aria-setsize` identique pour toutes les cellules d'une même ligne ; harnais : ajouter/retirer une ère → les rangs se recalculent.

## E004-05 — Résumé chiffré dérivé du DOM

- **Preuve** : `E004.js:179-183` crée/réutilise `#points-e004-summary` et écrit `plural(rows,…) × plural(domains,…) · filled/total cellules renseignées`, où `filled` (`:119`) compte les `.points-cell.has-points` et `total` (`:118`) toutes les cellules. Le style est en `E004.js:51`.
- **Solution** : aucun millésime ni total littéral : les trois grandeurs sont recomputées à chaque rendu depuis la matrice, avec la règle de pluriel de `:79-81`.
- **Impact** : la densité de couverture est lisible d'un coup d'œil et reste vraie quand le jeu de données évolue.
- **Effort** : S
- **Vérification** : relecture — absence de chiffre fixe ; harnais : N ères × M domaines → chaîne conforme, `filled` ≤ `total`.

## E004-06 — Légende des symboles lue sur la matrice

- **Preuve** : `E004.js:185-195` construit une `<dl>` `#points-e004-legend` : nom de l'ère courante (`:191`, issu de `activeName` en `:117`), signification d'une cellule renseignée (`:193`) et exemple réel de cellule vide (`:187`, `:195`) prélevé sur le DOM.
- **Solution** : la légende est reconstruite par `replaceChildren` (`:189`) à partir de ce qui est réellement affiché ; le symbole vide n'est pas codé en dur, il est lu sur la première cellule sans `.has-points` avec repli « · ».
- **Impact** : le sens du `▶`, du chiffre et du point médian est explicite ; aucune information n'est portée par la seule couleur.
- **Effort** : S
- **Vérification** : relecture — trois couples `<dt>/<dd>` ; harnais : aucune cellule vide → le repli « · » s'affiche sans erreur.

## E004-07 — Statut narratif de la ligne courante

- **Preuve** : `E004.js:197-207` crée/réutilise `#points-e004-status` avec `role=status` et `aria-live=polite` (`:199-200`) ; le texte (`:204`) annonce « Ère courante : <nom> · <k> domaine(s) renseigné(s) sur <total> », calculé depuis les cellules de la ligne active (`:202-203`), avec repli explicite si aucune ère n'est repérée (`:206`).
- **Solution** : un seul nœud live, mis à jour par affectation de `textContent`, sans ajout de région live concurrentielle ni annonce redondante.
- **Impact** : le changement d'ère est annoncé une fois, avec un état vérifiable, sans bavardage sur les mutations de filtres.
- **Effort** : M
- **Vérification** : relecture — un seul `role=status` ; harnais : changer d'ère → le statut suit ; retirer `is-active` → « Aucune ère courante repérée ».

## Statut d'implémentation

Les dix chantiers E004-01 à E004-10 sont implémentés dans `src/views/points/E004.js` uniquement. CSS injecté via `ctx.css('points-e004', …)`. Aucune donnée inventée, aucun fichier partagé touché, aucune structure d'origine altérée (classes, textes, boutons et navigation conservés).

## Blocages / limites inter-domaines

- Le repère visuel de la ligne courante repose sur le `::before` du bouton `.points-era` ; si une feuille tierce masquait ce pseudo-élément, le marquage ARIA (`aria-current`) et le signal `data-e004-current` restent, mais l'indice visuel disparaît. Aucun fichier CSS partagé n'a été modifié pour garantir le contraste.
- Le statut narratif est volatile : il est réécrit à chaque rendu de la coque et ne conserve pas d'historique d'annonces entre rendus.
- `E004` ne corrige pas une ère `is-active` erronée produite par `store.js` : il se contente de refléter fidèlement l'état rendu. Toute divergence de sélection relève du domaine de `points.js` / `store.js`, fichiers non possédés.
- Les identifiants `points-e004-*` sont posés sur des nœuds existants (`.points-title`, `.points-detail`) ; toute autre lentille qui réécrirait ces `id` devra les préserver.
