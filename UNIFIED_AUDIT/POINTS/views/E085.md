# E085 — Contrat d'enregistrement exact (un seul register, une seule clé, audience défensive)

Lentille E085 — domaine I : qualité & validation. Fichier possédé : `src/views/points/E085.js` uniquement. La vue (`src/views/points.js`), le registre (`src/views/points/registry.js`), la coque et les feuilles partagées ne sont ni édités ni doublés. Le thème n'est pas un simple commentaire : il est **démontré dans le module**, qui ne possède qu'une seule source de vérité pour son nom d'enregistrement, un seul appel à `register()`, et un contrôle d'audience qui échoue fermée avant tout effet de bord. Le contrat est ensuite rendu lisible dans le DOM via une note `#points-e085-contract` accrochée à `.points-matrix`, avec des grandeurs recomputées depuis la matrice réellement rendue. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`. CSS injecté par `ctx.css('points-e085', …)`.

## E085-01 — Un seul `register`, une seule clé

- **Preuve** : `E085.js:29` pose `const KEY = 'E085'`, unique occurrence littérale de la clé ; `:30` en dérive `CSS_ID = points-e085` ; `:33-37` `CONTRACT.key = KEY` ; `:39-43` les trois identifiants sont dérivés de `CSS_ID`. `:195` est le seul appel exécutable : `register(CONTRACT.key, (ctx) => { … })`. Les deux autres occurrences de `register(` (`:6`, `:193`) sont des commentaires.
- **Solution** : une clé unique, définie une fois, réutilisée par référence pour l'enregistrement, la feuille CSS et les identifiants. Aucune seconde clé, aucun second appel à `register`, aucun alias textuel du nom.
- **Impact** : le registre ne voit qu'une entrée `E085` ; un audit par comptage d'appels ou de littéraux donne le même résultat, sans interprétation.
- **Effort** : S
- **Vérification** : `grep -n "register(" src/views/points/E085.js` → une seule ligne de code (`:195`) ; `grep -n "'E085'" …` → une seule occurrence (`:29`) ; `viewDiagnostics()` lists contient `E085` une fois.

## E085-02 — Audience défensive, échec fermé

- **Preuve** : `conforms(ctx)` (`:85-91`) vérifie successivement : `ctx` est un objet, `ctx.viewId === CONTRACT.view` (`points`), `ctx.css` et `ctx.el` sont des fonctions, `ctx.layout.querySelector` existe. Le résultat est un booléen, jamais une exception. `:196` appelle ce contrôle **avant** `install()`, donc avant `ctx.css`.
- **Solution** : garde d'entrée unique et fail-closed. Toute audience autre que la vue Points, ou tout ctx incomplet, produit un retour silencieux sans création de nœud, sans injection CSS et sans écriture d'attribut.
- **Impact** : la lentille est inoffensive si elle est chargée dans un autre contexte ou avec un ctx minimal dégradé ; elle ne peut pas polluer une autre vue ni masquer une erreur de contrat.
- **Effort** : S
- **Vérification** : harnais — `ctx = null`, `viewId = 'monde'`, `css` absent, `el` absent, `layout` absent → cinq cas, zéro nœud `#points-e085-contract`, zéro feuille `#points-e085`, zéro attribut `data-points-e085`.

## E085-03 — Contrat minimal, aucune dépendance cachée

- **Preuve** : `:1` est le seul import (`register` depuis `./registry.js`) ; `:14-16` documentent le ctx exploité et l'absence de dépendance au store, au routeur, à `ctx.say()` ou aux autres lentilles. `install()` (`:154-190`) n'utilise que `ctx.css`, `ctx.el` et `ctx.layout` ; `:197-201` neutralise toute erreur inattendue sans sortie console.
- **Solution** : surface d'API minimale et fermée. Le comportement observable ne dépend que du ctx décrit et du DOM rendu par `points.js` ; un greffon voisin défaillant ou absent ne change rien.
- **Impact** : la lentille reste active avec le ctx exact fourni par `runEnhancements({ viewId, stage, layout })`, et se tait si une partie du contrat vient à manquer.
- **Effort** : S
- **Vérification** : relecture — un seul `import`, aucune référence à `state`, `set`, `say`, `store`, `router` ou à un autre identifiant de lentille ; aucun `throw` sortant du module.

## E085-04 — Greffage non destructif

- **Preuve** : `:171-173` crée une `<section>` propre et `:179` l'ajoute par `appendChild` ; `:182-188` posent uniquement des attributs `data-points-e085*` additifs sur notre nœud, sur `layout` et sur `matrix`. Le seul `remove()` (`:161`) vise notre propre nœud lorsqu'il est mal parenté. `:126` (`section.replaceChildren()`) ne touche qu'au contenu de notre section.
- **Solution** : ajout à la fin de `.points-matrix`, sans déplacement ni suppression d'un nœud de `points.js`, sans réécriture des classes `is-active` / `has-points`, sans altération des selects, du détail ou de la navigation.
- **Impact** : les gestionnaires natifs (ères, cellules, filtres, point précédent/suivant) restent intacts ; les lentilles voisines qui lisent la matrice ne voient aucune structure modifiée.
- **Effort** : S
- **Vérification** : relecture — aucun `innerHTML`, `outerHTML` ou `insertAdjacentHTML` ; aucun `remove()` hors nœud possédé ; comparer le nombre d'enfants de `.points-matrix` avant/après greffage (+1 exactement).

## E085-05 — Idempotence sur un DOM inchangé

- **Preuve** : `:160` recherche le nœud par identifiant ; `:169-178` le réutilise s'il existe et le reconstruit seulement s'il lui manque son readout ; `:179` ne l'attache que s'il n'est pas déjà au bon endroit ; `:113-120` n'écrit le readout que si sa signature change.
- **Solution** : identifiant stable + réutilisation + écriture conditionnelle. Deux passages de `install()` sur le même DOM produisent exactement le même arbre et le même texte.
- **Impact** : pas de doublon de note, pas de bavardage dans la région live, pas d'incrémentation artificielle du compteur de greffage lors d'un second passage.
- **Effort** : S
- **Vérification** : harnais — appeler deux fois l'installation sur le même `layout` → `document.querySelectorAll('#points-e085-contract').length === 1`, `data-points-e085-grafts === '1'`, texte du readout inchangé.

## E085-07 — Mesures dérivées et référencées

- **Preuve** : `numbers()` (`:95-104`) compte les lignes d'ère (`:97`), les domaines depuis l'en-tête moins la colonne « Ère » (`:98-101`), les cellules (`:102`) et calcule la référence `expected = eras * domains` (`:103`). `metricsText()` (`:106-111`) les assemble ; `paintMetrics()` (`:113-120`) n'écrit que sur changement de signature. Le readout est `role=status aria-live=polite` (`:144-147`).
- **Solution** : aucune valeur historique codée en dur : ères, domaines, cellules et référence sont relus sur la matrice à chaque rendu. L'écart entre `cellules` et `eras × domaines` reste observable sans conjecture.
- **Impact** : la note reste vraie si le jeu de données évolue ; elle fournit au moins trois grandeurs chiffrées dont une comparée à une référence calculée.
- **Effort** : M
- **Vérification** : harnais — pour une matrice de 4 ères × 5 domaines et 20 cellules, le readout annonce `Ères : 4 · domaines : 5 · cellules : 20 (référence 4×5 = 20)` ; retirer une cellule → l'écart apparaît sans modification du code.

- **Impact** : la démonstration du contrat est lisible au clavier et aux technologies d'assistance, y compris en 390×844 et en mode contraste forcé.
- **Effort** : M

## E085-10 — Cycle de vie et audibilité du greffage

- **Preuve** : `:151-153` documentent la détection de rendu neuf ; `:163-167` teste `root.isConnected`, remet le compteur et la signature à zéro ; `:169` récupère le nœud encore présent, `:179` le reloge sans doublon ; `:181-185` incrémente `graftCount` une seule fois et l'expose avec la clé et la vue dans `data-points-e085-*` ; `:187-188` marquent `layout` et `matrix`.
- **Solution** : un nœud déconnecté signale un rendu neuf, ce qui réinitialise l'état volatile et recompte exactement un greffage. La feuille CSS reste unique grâce à cssOnce, indépendamment du nombre de rendus.
- **Impact** : navigation aller-retour sans doublon ni nœud fantôme ; le compteur `data-points-e085-grafts` permet de distinguer « premier greffage », « second passage idempotent » et « rendu neuf ».
- **Effort** : M
- **Vérification** : scénario — rendu initial (1 greffage) → second appel sur le même DOM (toujours 1) → navigation puis nouveau rendu (2) ; un seul `#points-e085-contract`, une seule feuille `#points-e085`, compteur et readout cohérents à chaque étape.

## Statut d'implémentation

Les dix chantiers E085-01 à E085-10 sont implémentés dans `src/views/points/E085.js` uniquement. Une seule clé (`E085`), un seul appel à `register()`, une seule feuille `points-e085`, une seule note `#points-e085-contract`. Aucun fichier partagé touché, aucune donnée inventée, aucun écouteur global.

## Blocages / limites inter-domaines

- Le registre (`src/views/points/registry.js`) enregistre les lentilles sans garantir l'unicité des clés : E085 garantit la sienne par construction (`:29`, `:195`), mais un doublon introduit dans un autre fichier ne peut pas être détecté depuis cette lentille.
- Le compteur de greffage est dérivé de `root.isConnected` : si un outil externe déplace la note hors du document sans la détruire, le greffage suivant est compté comme neuf. C'est un choix de robustesse, pas une fuite d'état partagé.
- La note décrit le contrat d'enregistrement d'E085 ; elle ne valide pas les autres lentilles. L'audit transversal des 100 clés reste hors du périmètre de ce module.
- Aucune information n'est émise hors de la note locale : pas de région live globale, pas d'appel à `ctx.say()` (non fourni par la vue Points).
