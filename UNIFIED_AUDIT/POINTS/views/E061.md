# E061 — Boucle rAF unique (ou nulle) et pause sur `document.hidden`

Lentille E061 — domaine G : performance & rendu.
Fichier possédé : `src/views/points/E061.js` uniquement. La vue (`src/views/points.js`), la coque (`src/ui/shell.js`), le registre (`src/views/points/registry.js`) et les feuilles partagées ne sont ni édités ni doublés. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` ; aucune dépendance vers le store, les filtres, le détail ou les autres lentilles.

La vue « points » est une matrice DOM statique (aucun canvas, aucune animation) : c'est la branche « rAF nulle » de la règle qui s'applique. Le greffon ne possède aucune boucle, n'a rien à relancer au retour d'onglet, et se contente d'observer `document.hidden` pour publier un état auditable. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro observateur, zéro `console.*`. CSS injecté par `ctx.css('points-e061', …)`.

## E061-01 — Garde de contexte, CSS unique préfixé et portée ancrée

- **Preuve** : `E061.js:144-146` exige `viewId === 'points'`, un `layout` et les fonctions `css`/`el`. `css(CSS_ID, CSS)` (`:149`) avec `CSS_ID = 'points-e061'` (`:24`) passe par `cssOnce` (`registry.js:13-19`) : une seule feuille `<style id="points-e061">`. `layout.classList.add(SCOPE)` (`:25`, `:150`) préfixe chaque règle de la feuille (`:29-60`) ; le readout porte `READOUT_ID = 'points-e061-status'` (`:26`), aucun ID non préfixé.
- **Solution** : la lentille ne s'active que sur la vue cible et avec le contrat minimal ; toute règle CSS est sous `.points-e061`, tout nœud ajouté porte un ID `points-e061-*`. Une feuille, une portée, un readout par rendu.
- **Impact** : aucun style ne fuit hors de la vue Points ; aucune collision d'ID avec les autres lentilles E001–E100 ; l'activation est sans effet sur les autres vues.
- **Effort** : S
- **Vérification** : relecture — un seul appel `css(`, toutes les règles préfixées `.points-e061`, seul l'ID `points-e061-status` est créé ; deux passages sur le même `layout` ne dupliquent ni la feuille ni le nœud.

## E061-02 — Branche « rAF nulle » : aucune boucle dans le greffon

- **Preuve** : le commentaire `E061.js:10-13` pose explicitement la branche : « la vue « points » est une matrice DOM statique […] le greffon ne possède aucune boucle requestAnimationFrame ». `now()` (`:72-78`) est une lecture ponctuelle de `performance.now()`, pas un appel planifié. L'unique occurrence textuelle de `requestAnimationFrame` (`:12`) est dans l'en-tête, aucune en code. `points.js:29-126` produit uniquement des nœuds DOM (`div`, `button`, `select`, `p`).
- **Solution** : le greffon est purement événementiel (`install` + `visibilitychange`) ; il ne crée, ne possède et ne relance aucun `requestAnimationFrame`. Aucun canvas, aucun `getInfo()`, aucune horloge de moteur à réarmer.
- **Impact** : zéro frame imputable à la lentille, budget GPU/CPU inchangé ; la règle « une seule boucle rAF (ou nulle) » est respectée sous sa forme la plus forte.
- **Effort** : S
- **Vérification** : `grep -n requestAnimationFrame src/views/points/E061.js` → 1 seule ligne, en commentaire (`:12`), zéro appel ; `node --check` PASS.

## E061-03 — Aucun timer d'arrière-plan

- **Preuve** : aucun `setTimeout`, `setInterval` ni `requestIdleCallback` dans le module, y compris dans l'en-tête qui se limite à « zéro timer » (`:20`). Les deux seuls points d'écriture sont `install()` (`:155`) et `handleVisibility()` (`:119`) via `paint()` (`:96-103`), tous deux discrets.
- **Solution** : aucune fonction n'est planifiée ; l'horloge `now()` ne fait que lire le temps au moment d'une transition déjà observée. Le texte du readout précise « aucune frame demandée, aucune écriture de la grille » pendant le masquage (`:86`).
- **Impact** : aucun réveil CPU en arrière-plan imputable au greffon, cohérent avec l'absence de boucle.
- **Effort** : S
- **Vérification** : `grep -nE 'setTimeout|setInterval|requestIdleCallback'` hors commentaires → 0 ligne ; masquer l'onglet 2 s → aucun changement de DOM après la transition initiale.

## E061-04 — Écouteur `visibilitychange` unique sous garde module

- **Preuve** : `visibilityHooked = false` (`:62`) et le bloc `if (!visibilityHooked)` (`:159-164`) contiennent le seul `document.addEventListener('visibilitychange', handleVisibility)` (`:162`). L'état de garde survit au `root.innerHTML = ''` de la coque (`shell.js:533`) qui recrée le stage à chaque rendu.
- **Solution** : un seul listener enregistré pour toute la session, même si `install()` est rejoué à chaque rendu de la vue. Le handler n'appelle aucune API de vue et ne modifie aucun nœud de `points.js` : il ne fait que mettre à jour compteurs, attribut et readout.
- **Impact** : pas de duplication d'écouteurs ni d'appels redondants après navigation aller-retour ; la pause suit exactement l'état réel du document.
- **Effort** : S
- **Vérification** : relecture — un seul `addEventListener` dans le module ; trois rendus successifs → un seul handler actif (aucune progression anormale des compteurs).

## E061-05 — Miroir d'état `data-e061-visibility` auditable

- **Preuve** : `VISIBILITY_ATTR = 'data-e061-visibility'` (`:27`) ; `paint()` écrit `layoutRef.setAttribute(VISIBILITY_ATTR, phase)` (`:98`) avec `phase = lastPhase || phaseNow()` (`:97`) ; `phaseNow()` (`:80-82`) lit `document.hidden`, repli `visible` si `document` est absent. Aucune écriture en boucle : `paint()` n'est appelée que depuis `install()` et `handleVisibility()`.
- **Solution** : un marqueur déclaratif `visible`/`hidden` posé sur `.points-layout`, dérivé de `document.hidden` seul, sans instrumentation de la coque ni de la vue.
- **Impact** : état de pause lisible par un test E2E ou un audit sans `console.*` ; le signal est stable entre deux transitions.
- **Effort** : S
- **Vérification** : après `install`, `layout.dataset.e061Visibility === (document.hidden ? 'hidden' : 'visible')` ; basculer `document.hidden` → valeur mise à jour sans re-rendu de la vue.

## E061-06 — Compteurs de reprise traçables, sans sonde périodique

- **Preuve** : `hiddenCount`, `resumeCount`, `hiddenSince`, `lastHiddenMs` (`:64-67`) ne sont modifiés que dans `handleVisibility()` (`:107-120`). La garde `if (phase === lastPhase) return` (`:109`) déduplique les évènements redondants ; l'incrément a lieu une seule fois par transition (`:111`, `:114`) et la durée de pause est calculée à la reprise (`:115`) à partir de `now()` (`:72-78`), qui ne planifie rien.
- **Solution** : des compteurs discrets prouvent que le travail se limite aux transitions visibilité, et non au temps écoulé. Aucun échantillonnage périodique, aucun keep-alive.
- **Impact** : distinction vérifiable entre « aucun changement » et « greffon muet » ; la mesure de pause reste falsifiable par un harnais qui bascule `document.hidden`.
- **Effort** : M
- **Vérification** : N bascules `visible → hidden → visible` → readout `Masquages : N` et `Reprises : N` ; un second évènement `visibilitychange` sans changement de phase laisse les compteurs inchangés.

## Blocages / limites inter-domaines

- La pause est observatoire : la vue « points » n'ayant aucune boucle rAF, il n'existe rien à suspendre côté moteur. E061 ne peut pas modifier `points.js` ni `shell.js` (fichiers non possédés) pour introduire une boucle — et n'a pas à le faire.
- `performance.now()` peut être absent ou borné à zéro selon l'environnement : la durée de pause est alors omise du readout (`:88-91`) plutôt que remplacée par un chiffre trompeur ; les compteurs de transitions restent exacts.
- Le miroir d'état dérive de `document.hidden` seul : une vue masquée par `IntersectionObserver` alors que l'onglet reste visible n'est pas signalée. La présence dans la vue relève de la coque et d'autres lentilles, hors du contrat de E061.
- Si une autre lentille reconstruit `.points-matrix` avec `replaceChildren`, le readout peut être retiré ; le prochain `install()` le recrée (E061-09). Aucun nœud appartenant à autrui n'est supprimé.
