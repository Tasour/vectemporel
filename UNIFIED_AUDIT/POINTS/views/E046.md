# E046 — Selects avec label associé

Lentille E046 du chantier POINTS, domaine E : accessibilité & ARIA. Fichier possédé : `src/views/points/E046.js` uniquement. La vue `src/views/points.js`, le registre, `styles.css` et les autres lentilles ne sont ni édités ni doublés : E046 enrichit le DOM déjà produit par `renderPoints` (`points.js:60-93`, `:124-126`) sans reconstruire la grille ni réenregistrer les écouteurs des filtres.

Contrat exploité : `viewId`, `stage`, `layout`, `css(id, rules)`, `el(tag, cls, text)`, `reducedMotion` (`registry.js:29-37`). Aucune dépendance au store, aux filtres ou au jeu de données : chaque libellé est dérivé de l'aria-label réellement posé par `points.js:62` et `:74`, avec un repli structurel — jamais d'une donnée historique codée en dur. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. CSS unique injecté par `ctx.css('points-e046', …)` (`registry.js:13-19`), cadré par le signal `data-e046` posé sur `.points-filters` (`E046.js:148`).

État initial audité : les deux `<select>` de `points.js:61-84` portent un aria-label (Filtrer par domaine, Filtrer par famille) mais aucun `<label for>` ni `id` : le nom accessible existe, mais le contrôle n'a ni étiquette visible associée ni cible de clic label. E046 comble cette lacune sans effacer l'aria-label, que E024, E093, E094 et E095 continuent de lire, et sans toucher au bouton de réinitialisation.

## E046-01 — Association native label/for pour chaque select de filtre

- **Preuve** : `ensureLabel` (`E046.js:109-126`) crée un `<label class=points-e046-label>` par `ctx.el` (`:115`), lui donne un `for` via `label.htmlFor = selectId` (`:119`) et l'insère immédiatement avant son select avec `filters.insertBefore(label, select)` (`:118`). Le couple est complété par `data-e046-for` sur l'étiquette (`:121`) et `data-e046-label-id` sur le select (`:124`). Les selects sont découverts dans `.points-filters` (`:166-169`), exactement là où `points.js:60-93` les a rendus.
- **Solution** : une étiquette native, une par filtre, placée juste avant son contrôle dans l'ordre de lecture. Le clic sur l'étiquette donne le focus au select ; l'aria-label préexistant est conservé tel quel, si bien que le nom accessible reste stable pour les technologies d'assistance.
- **Impact** : un utilisateur qui clique sur le mot « domaine » ou « famille » active le bon filtre ; l'étiquette visible et le nom accessible coïncident, ce qui lève l'ambiguïté entre les deux selects.
- **Effort** : S
- **Vérification** : relecture de `:109-126` ; harnais DOM : chaque select possède exactement un label dont le `for` égale son `id`, et ce label précède immédiatement le select ; clic sur le label → `document.activeElement` est le select.

## E046-02 — Identifiants préfixés et déterministes

- **Preuve** : les constantes `LABEL_PREFIX` et `SELECT_PREFIX` (`:31-32`) valent `points-e046-label-` et `points-e046-select-` ; `ensureSelectId` (`:96-103`) reprend un `id` existant ou en crée un par index, et l'identifiant du label est construit à `:111`. Le commentaire d'invariant (`:18-19`) impose des identifiants préfixés et déterministes, sans tirage aléatoire ; la liste `keepIds` (`:173`) est dérivée du même index.
- **Solution** : une seule règle de nommage pour les deux familles d'identifiants, calculée depuis la position du select dans `.points-filters`. Aucun compteur global, aucune date, aucune graine aléatoire.
- **Impact** : les références `for`/`id` sont stables d'un rendu à l'autre, ce qui permet à E083 de vérifier leur intégrité et évite les collisions avec les identifiants des autres lentilles.
- **Effort** : S
- **Vérification** : relecture de `:31-32`, `:96-103`, `:111`, `:173` ; contrôle : tous les `id` créés commencent par `points-e046-` ; deux rendus successifs produisent les mêmes identifiants ; recherche de `Math.random` dans le module → aucune occurrence.

## E046-03 — Libellé dérivé de l'aria-label réel, sans donnée inventée

- **Preuve** : `labelFrom` (`:86-92`) lit d'abord `aria-label` du select (`:87-88`), c'est-à-dire les chaînes posées par `points.js:62` et `:74`. Le repli lit un `title` déjà présent (`:89-90`, par exemple celui que E095 pose sur l'ancre domaine), puis numérote structurellement un filtre inattendu (`:91`). L'en-tête (`:13-14`) affirme l'absence de donnée historique codée en dur.
- **Solution** : le texte visible de l'étiquette est une lecture du contrôle, pas une traduction ou une invention. Le repli final ne nomme pas un contenu historique, il identifie seulement un champ.
- **Impact** : si un jeu de données change de domaines ou de familles, le libellé reste correct ; si l'aria-label est temporairement absent, l'étiquette ne devient pas vide.
- **Effort** : S
- **Vérification** : relecture de `:83-92` ; harnais : aria-label présent → texte identique ; aria-label absent et title présent → premier segment du title ; ni l'un ni l'autre → `Filtre 1` / `Filtre 2`.

## E046-04 — Non-destruction des contrôles existants

- **Preuve** : le commentaire `:105-108` énonce la règle ; `ensureLabel` n'écrit sur le select que `data-e046-labelled` (`:123`), `data-e046-label-id` (`:124`) et, seulement à la création, l'attribut `id` (`:97-101`). Aucune écriture vers `aria-label`, `title`, `className`, `value`, `options` ou `addEventListener` n'existe dans le module. La feuille est cadrée par `.points-filters[data-e046]` (`:40-69`) et ne réécrit pas `display:flex` de `styles.css:361` (commentaire `:35-38`).
- **Solution** : l'étiquette est ajoutée à côté du contrôle, jamais à sa place. Les écouteurs `change` de `points.js:69-84` et le bouton de réinitialisation de `points.js:85-91` restent attachés au même nœud.
- **Impact** : le filtrage fonctionne exactement comme avant E046 ; les lentilles qui relisent l'aria-label des selects (E024, E093, E094, E095) voient la valeur d'origine.
- **Effort** : S
- **Vérification** : recherche de `aria-label =`, `title =`, `className =`, `.value =` et `addEventListener` dans E046.js → aucune occurrence sur les selects ; harnais : avant/après, mêmes options, même valeur sélectionnée, même comportement au changement.

## E046-05 — Idempotence : réutilisation, garde et retrait des orphelins

- **Preuve** : l'invariant `:22-23` pose la garde et la réutilisation ; `ensureLabel` retrouve l'étiquette par `document.getElementById(labelId)` (`:112`), la retire si elle est mal parentée (`:113`), ne la recrée que si elle est absente ou déconnectée (`:114-117`) et ne la déplace que si nécessaire (`:118`). `dropOrphans` (`:130-134`) supprime les étiquettes dont l'identifiant n'est plus dans `keepIds` (`:173-174`).
- **Solution** : trois mécanismes complémentaires — identification par id, repositionnement conditionnel, nettoyage des restes d'un rendu précédent. Les attributs `for` et les marqueurs sont réappliqués à chaque passe, donc l'état converge.
- **Impact** : navigation aller-retour sans doublon d'étiquettes, sans référence périmée et sans accumulation de nœuds invisibles.
- **Effort** : M
- **Vérification** : harnais : deux appels successifs sur le même DOM → deux labels au total, mêmes identifiants, même texte ; insérer une étiquette obsolète puis revérifier → elle est retirée.

## E046-06 — Structure de `.points-filters` préservée

- **Preuve** : le point d'ancrage est trouvé par `layout.querySelector('.points-filters')` (`:166`) avec repli `ctx.stage` (`:164`) ; les selects sont énumérés sans les déplacer (`:169`) ; l'insertion se fait avant chaque select (`:118`) et n'altère ni l'ordre relatif des deux selects ni la position du bouton de réinitialisation rendu en `points.js:92`. Le module n'appelle jamais `append`, `replaceChildren` ni `removeChild` sur un nœud de la vue.
- **Solution** : les étiquettes deviennent des frères des contrôles dans le conteneur flex existant. Aucun groupe enveloppant n'est introduit, ce qui éviterait de réparent les selects et de casser les sélecteurs descendants utilisés par E031, E095, E099 et E100.
- **Impact** : la disposition de `styles.css:361` reste celle de la vue ; le bouton « Réinitialiser les filtres » reste le troisième enfant utile du conteneur.
- **Effort** : S
- **Vérification** : relecture de `:118`, `:164-176` ; harnais : ordre final label, select, label, select, bouton ; le nombre de selects et de boutons est inchangé ; capture 390×844 à rejouer pour vérifier le repli mobile.

## E046-07 — Cibles tactiles et focus visible

- **Preuve** : la feuille donne `min-height: 24px` au label (`:43`) et confirme `min-height: 38px` au select (`:50`, valeur déjà portée par `styles.css:362`, donc non réduite). Le focus du select est cerné par un contour de 2 px (`:51-54`) et l'état `:focus-within` du label par un pointillé (`:55-58`). Le repli mobile (`:59-61`) donne `flex-basis: 100%` au libellé pour éviter qu'il soit coupé.
- **Solution** : aucune nouvelle mise en page globale ; des repères de focus et une hauteur minimale suffisante, portés uniquement par le signal `data-e046`.
- **Impact** : au clavier, le contrôle actif est identifiable ; sur écran étroit, le libellé occupe sa propre ligne et le select reste atteignable au doigt.
- **Effort** : S
- **Vérification** : relecture de `:40-61` ; contrôle : `min-height` ≥ 36 px ; navigation Tab jusqu'aux deux selects → contour visible ; bascule à 390 px → libellé sur sa ligne, pas de débordement horizontal.

## E046-08 — Trace auditable de l'état des filtres

- **Preuve** : `refreshState` (`:147-159`) pose `data-e046` et `data-e046-selects` sur le conteneur (`:148-149`) et sur la vue (`:156-157`), puis `data-e046-value` et `data-e046-choice` sur chaque select (`:151-152`). `selectedText` (`:136-143`) lit l'option sélectionnée depuis `selectedIndex`/`selectedOptions`, avec repli sur `value`. Le commentaire `:145-146` précise qu'aucune région live n'est alimentée.
- **Solution** : les marqueurs sont dérivés de l'état réel des selects, recalculés à chaque rendu, jamais mémorisés dans une variable de module.
- **Impact** : un audit peut vérifier d'un coup d'œil combien de filtres ont été étiquetés et quelle valeur était active, sans inspecter le store ni écouter d'événement.
- **Effort** : S
- **Vérification** : relecture de `:136-159` ; harnais : changer la valeur d'un select puis relancer l'installation → les deux marqueurs suivent la nouvelle valeur ; recherche de `role=status` ou `aria-live` dans le module → aucune occurrence.

## E046-09 — Préférences système et absence de mouvement propre

- **Preuve** : la feuille neutralise toute transition sous `prefers-reduced-motion` (`:62-65`) et bascule couleurs/contour sous `forced-colors` (`:66-69`). Le commentaire `:35-38` indique qu'aucune transition n'est introduite et l'invariant `:26` interdit tout mouvement propre.
- **Solution** : E046 est purement statique : ni rAF, ni timer, ni animation. Les règles média ne font que neutraliser d'éventuelles transitions héritées et garantir la lisibilité du libellé en couleurs forcées.
- **Impact** : le libellé reste visible en contraste forcé, et l'ajout d'étiquettes n'introduit aucun mouvement pour les utilisateurs sensibles.
- **Effort** : S
- **Vérification** : relecture de `:62-69` ; émuler `prefers-reduced-motion: reduce` et `forced-colors: active` → aucune transition, libellé et contour toujours visibles ; recherche de `requestAnimationFrame`, `setTimeout`, `setInterval` → aucune occurrence.

## E046-10 — Conformité statique et point d'entrée unique

- **Preuve** : `register('E046', (ctx) => { … })` est unique et signé `ctx` (`:161-177`). Les gardes (`:162-170`) neutralisent un contexte incomplet, une autre vue ou une structure inattendue sans propager d'erreur. Le CSS passe par `ctx.css(CSS_ID, CSS)` (`:172`), c'est-à-dire `cssOnce` (`registry.js:13-19`). Les invariants complets sont énoncés en `:16-26`.
- **Solution** : une seule passe synchrone et locale par rendu, sans écouteur global, sans état module mutable et sans fichier partagé modifié.
- **Impact** : la lentille est neutralisée proprement si la structure change, et elle ne perturbe ni le rendu ni les 99 autres greffons.
- **Effort** : S

## Blocages / limites inter-domaines

- Les selects rendus par `points.js:61-84` n'ont pas d'`id` à l'origine : E046 en crée un (`:96-103`) pour pouvoir poser le `for`. Si une autre lentille devait réécrire l'`id` d'un select après E046, l'association deviendrait caduque ; les lentilles concernées devraient préserver `data-e046-labelled` et l'identifiant référencé par `data-e046-label-id`.
- L'aria-label est volontairement conservé (`:105-108`) : selon l'algorithme de nom accessible, il continue de primer sur le label natif. Comme les deux textes sont identiques par construction (`:86-88`), aucune divergence n'est introduite, mais E046 ne remplace pas l'aria-label par un `aria-labelledby`.
- Le libellé est calculé au rendu : aucun `MutationObserver` propre n'est installé, pour éviter une boucle d'écriture. Un changement d'aria-label opéré après le rendu par une autre lentille ne sera reflété qu'au rendu suivant.
- Le signal `layout.dataset.e046` (`:156-157`) et `filters.dataset.e046` (`:148`) sont écrits par E046 ; toute lentille qui réécrirait ces attributs devra les préserver.
- Un harnais DOM local (stubs Node, 11 contrôles) a été exécuté et passe intégralement ; la capture navigateur 390×844 et les suites E2E restent à rejouer par l'agent maître, ce module n'ayant pas été monté dans un navigateur lors de cette passe.
