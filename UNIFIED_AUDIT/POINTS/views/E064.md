# E064 — DPR ≤ 2 si canvas, snapshots déterministes et zéro réseau

Lentille E064 — domaine G : performance & rendu. Fichier possédé : `src/views/points/E064.js` uniquement. La vue (`src/views/points.js`), le registre (`registry.js`), la coque et `styles.css` ne sont ni édités ni doublés. Contrat exploité : `viewId`, `layout`, `css`, `el` ; `ctx.reducedMotion` est volontairement inutilisé car il n'existe aucune animation à neutraliser (`E064.js:18-19`). CSS injecté une seule fois par `ctx.css('points-e064', …)` (`E064.js:103`) ; tous les identifiants sont préfixés `points-e064-` (`E064.js:26-28`). Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`.

**Fait fondateur.** La vue Points est exclusivement DOM/CSS : elle ne contient aucun `<canvas>` et n'en réclame aucun (`src/views/points.js:29-126`). Le plafond DPR ≤ 2 est donc traité comme une **garde défensive dormante**, jamais comme une contrainte violée : E064 constate l'absence de canvas, expose le plafond, et ne crée jamais de surface de dessin. Le « snapshot » est une signature déterministe dérivée du DOM réel (titre, ère active, deux filtres, couverture, point sélectionné, périmètre), sans date, sans matériel, sans hasard et sans requête.

## E064-01 — Vue DOM-only : zéro canvas créé, état audité

- **Preuve** : l'en-tête `E064.js:10-16` documente le fait fondateur. `E064.js:107-109` interroge `layout.querySelectorAll('canvas')` et écrit le compteur dans `layout.dataset.e064Canvas` (valeur `0` dans la vue actuelle) ; aucune instruction `document.createElement('canvas')` ni aucun appel à `getContext` n'apparaît.
- **Solution** : plutôt que d'improviser une surface de dessin pour « illustrer » le plafond, la lentille constate l'absence de canvas et la rend vérifiable par un attribut de données. Le thème « DPR ≤ 2 si canvas » est ainsi respecté par construction : la condition « si canvas » est fausse.
- **Impact** : aucun coût GPU, aucune allocation de bitmap, aucun risque de dépassement de budget mémoire sur mobile ; l'audit peut lire `data-e064-canvas="0"` sans instrumenter le navigateur.
- **Effort** : S
- **Vérification** : relecture de `E064.js:107-109` et de `src/views/points.js:29-126` ; contrôle DOM : `document.querySelectorAll('canvas').length === 0` après rendu ; harnais avec un canvas injecté : le compteur passe à `1` et la garde E064-03 s'active.

## E064-02 — Plafond de densité codé en dur et exposé

- **Preuve** : `DPR_CAP = 2` est une constante unique (`E064.js:28`). `clampDpr()` (`E064.js:45-51`) borne toute valeur avec `Math.min(2, Math.max(1, n))` et retombe sur `1` pour une entrée absente ou non finie. `E064.js:111-113` expose `layout.dataset.e064DprCap = String(DPR_CAP)`.
- **Solution** : le plafond est une décision de code, pas une observation matérielle. La valeur réelle de `devicePixelRatio` n'est jamais écrite dans le contenu ni dans le snapshot : seul le bornage est documenté dans le DOM.
- **Impact** : le contrat « DPR ≤ 2 » reste vrai sur un écran 3× comme sur un écran 1× ; l'affichage ne change pas avec le matériel, ce qui rend les captures reproductibles.
- **Effort** : S
- **Vérification** : relecture de `E064.js:28`, `45-51`, `111-113` ; contrôle : `data-e064-dpr-cap="2"` ; harnais `clampDpr(3) === 2`, `clampDpr(0.5) === 1`, `clampDpr(NaN) === 1`.

## E064-03 — Garde canvas défensive, dormante et non destructive

- **Preuve** : `capCanvasDpr()` (`E064.js:53-71`) vérifie d'abord `getContext`, lit les dimensions CSS via `getBoundingClientRect()` (repli `clientWidth`/`clientHeight`), calcule `width`/`height` avec `Math.round(css × clampDpr(devicePixelRatio))` et n'écrit `canvas.width`/`canvas.height` que si la valeur diffère. `E064.js:109` l'appelle sur la liste de l'E064-01, vide ici.
- **Solution** : une seule fonction pure et réutilisable, prête à borner un canvas futur ou injecté par une autre lentille, mais qui ne crée rien, ne touche à aucun nœud existant en l'absence de canvas et reste sans effet sur le rendu courant.
- **Impact** : si un canvas apparaît un jour dans cette vue, le plafond DPR ≤ 2 s'applique automatiquement sans modifier ce module ; entre-temps, le coût d'exécution est une boucle sur zéro élément.
- **Effort** : M
- **Vérification** : relecture de `E064.js:53-71`, `109` ; harnais avec un canvas 300×150 CSS sous `devicePixelRatio = 3` : la réserve devient 600×300 (DPR effectif 2), pas 900×450 ; sans canvas : aucune écriture.

## E064-04 — Signature de snapshot dérivée du DOM seul

- **Preuve** : `snapshotParts()` (`E064.js:73-95`) lit `.points-title`, `.points-grid-row.is-active .points-era`, les deux `select` de `.points-filters`, `.points-point-title`, le compteur de `.points-cell.has-points` et le kicker de `.points-detail`. `E064.js:116-117` assemble ces sept champs en signature stockée dans `data-e064-signature`.
- **Solution** : le snapshot n'est pas une capture d'écran : c'est une liste de paires `clé=valeur` entièrement reconstruite depuis les nœuds déjà présents. Aucune donnée n'est inventée, aucune date n'est ajoutée, aucun état interne n'est lu.
- **Impact** : l'instantané reste exact quand le jeu de données évolue ; il peut être comparé avant/après une action (filtre, changement d'ère, navigation entre points) pour vérifier que la vue a réellement changé.
- **Effort** : M
- **Vérification** : relecture de `E064.js:73-95`, `116-117` ; harnais : changer la valeur du select « domaine » puis `set()` → la sous-chaîne `domaine=` change ; sans action, deux appels donnent la même signature.

## E064-05 — Instantané lisible, écrit par `textContent`

- **Preuve** : la feuille locale `.points-e064-snapshot` (`E064.js:30-43`) reste dans la portée du paragraphe, avec `font-variant-numeric: tabular-nums` et un repli `forced-colors`. `E064.js:118` compose le texte en français, `E064.js:128-135` crée le paragraphe via `el('p', 'points-e064-snapshot', text)` et l'insère après `.points-title` dans `.points-matrix`, et `E064.js:140` ne réécrit que si `textContent` diffère.
- **Solution** : un unique paragraphe statique, visible et indexable, sert de face lisible de la signature. Toute mise à jour passe par `textContent` ; aucun `innerHTML`, `outerHTML` ou `insertAdjacentHTML` n'est utilisé.
- **Impact** : l'information est consultable sans outil de développement, y compris en couleurs forcées ; aucune réinterprétation du balisage et aucune injection ne sont possibles.
- **Effort** : S
- **Vérification** : relecture de `E064.js:30-43`, `118`, `128-140` ; contrôle : un seul `#points-e064-snapshot` après rendu ; changement de filtre → une seule mutation de texte.

## E064-06 — Zéro réseau : snapshot entièrement local

- **Preuve** : le commentaire `E064.js:73-75` interdit explicitement toute requête dans la signature ; le corps de `register()` (`E064.js:97-142`) ne contient ni `fetch`, ni `XMLHttpRequest`, ni `import()` dynamique, ni création d'image, ni `src` distant. Les seules lectures sont des requêtes DOM (`E064.js:77-84`, `107`, `123`).
- **Solution** : le snapshot ne consulte aucune ressource externe : tout ce qu'il affiche est déjà dans le DOM produit par `points.js`. Aucune sonde, aucun ping, aucune police ou image distante n'est introduite.
- **Impact** : la lentille fonctionne hors ligne, sans latence réseau et sans fuite de données ; le rendu reste déterministe même si le réseau est indisponible.
- **Effort** : S
- **Vérification** : relecture — absence de `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `http://`, `https://` et `@import` ; capture du trafic réseau pendant le rendu : zéro requête supplémentaire.

## E064-07 — Zéro aléa, zéro horodatage : reproductibilité

- **Preuve** : `E064.js:73-75` proscrit date et hasard ; `E064.js:82-94` ne compte que des nœuds et ne lit que des `textContent`/`value` ; aucun `Math.random`, `Date.now`, `performance.now` ou `new Date()` n'apparaît (`E064.js:1-142`). La seule valeur matérielle, `devicePixelRatio`, est confinée à la garde dormante E064-03 et n'entre jamais dans le snapshot.
- **Solution** : la signature est une fonction pure du DOM : mêmes nœuds → mêmes champs → même texte. Aucune graine n'est nécessaire puisqu'aucun tirage n'est effectué.
- **Impact** : deux captures du même état sont bit à bit identiques ; les tests de non-régression peuvent comparer `data-e064-signature` sans tolérance ni normalisation.
- **Effort** : S
- **Vérification** : relecture — absence de `Math.random`, `Date`, `performance` ; harnais : deux rendus successifs du même DOM → `data-e064-signature` identique.

## E064-08 — Coût borné : aucune boucle d'animation, une écriture conditionnelle

- **Preuve** : l'en-tête `E064.js:21-23` fixe l'absence de timer et de rAF ; le calcul est synchrone dans `register()` (`E064.js:105-140`). `E064.js:137-140` compare `textContent` avant d'écrire, et `E064.js:117` n'écrit l'attribut de signature qu'une fois par passage.
- **Solution** : aucun `requestAnimationFrame`, `setTimeout` ni `setInterval` : le snapshot se met à jour au même moment que le rendu de la vue, sans boucle perpétuelle ni nouvelle tâche différée. Le travail est proportionnel au nombre de cellules déjà présentes, donc constant pour une vue donnée.
- **Impact** : pas de frame supplémentaire, pas de réveil CPU en arrière-plan, pas de dérive de latence ; le coût reste mesurable et plafonné par la taille du DOM existant.
- **Effort** : S
- **Vérification** : relecture — absence de `requestAnimationFrame`, `setTimeout`, `setInterval` ; harnais MutationObserver sur `#points-e064-snapshot` : appel sans changement de filtre → zéro mutation de texte.

## E064-09 — Non destructif : aucun nœud de la vue modifié

- **Preuve** : `E064.js:120-127` ne retire qu'un paragraphe portant **notre propre** identifiant et situé hors du layout courant ; `E064.js:128-135` ajoute un paragraphe dans `.points-matrix` sans remplacer ni déplacer `.points-title`, `.points-grid`, `.points-filters`, `.points-detail` ou `.points-nav`. Aucun `replaceChildren`, `remove` ou `textContent` ne vise un nœud de la vue.
- **Solution** : la lentille se contente de trois attributs `data-e064-*` et d'un paragraphe annoté. Les deux `select`, le bouton de réinitialisation, les boutons de cellule et la navigation restent strictement tels que `points.js` les a construits.
- **Impact** : aucune régression fonctionnelle pour les autres lentilles (filtres, grille, détail, clavier) ; E064 peut être activé ou désactivé sans changer le comportement de la vue.
- **Effort** : S
- **Vérification** : relecture de `E064.js:120-135` ; harnais : avant/après installation, comparer les `outerHTML` de `.points-grid`, `.points-filters`, `.points-detail` et `.points-nav` — seuls les attributs `data-e064-*` du layout diffèrent.

## E064-10 — Idempotence et contrat de lentille exact

- **Preuve** : l'enregistrement est exactement `register('E064', (ctx) => { … })` (`E064.js:97`, fermé en `:142`). `ctx.css(CSS_ID, CSS)` (`E064.js:103`) passe par `cssOnce` du registre ; le garde `document.getElementById(SNAPSHOT_ID)` (`E064.js:123-140`) garantit un seul paragraphe par rendu ; les identifiants `points-e064` / `points-e064-snapshot` sont déclarés en `E064.js:26-28`.
- **Solution** : un seul CSS, un seul paragraphe, une seule signature, aucune variable module muante conservée d'un rendu à l'autre. Un second passage sur le même DOM (navigation aller-retour) réutilise les nœuds existants et ne crée aucun doublon.
- **Impact** : pas de feuille de style dupliquée, pas de paragraphe fantôme, pas de fuite d'écouteur ; la lentille se comporte identiquement au premier et au centième rendu.
- **Effort** : M
- **Vérification** : relecture de `E064.js:26-28`, `97-142` ; `node --check src/views/points/E064.js` → PASS ; harnais rendu → navigation aller-retour → rendu : un seul `#points-e064-snapshot`, une seule feuille `#points-e064`, signature stable.

## Statut d'implémentation

Les dix chantiers E064-01 à E064-10 sont implémentés dans `src/views/points/E064.js` uniquement. CSS injecté via `ctx.css('points-e064', …)`. Aucun canvas n'est créé : le plafond DPR ≤ 2 est porté par une constante, une fonction de bornage et une garde dormante. Le snapshot est une signature DOM déterministe, sans réseau ni aléa. Aucun fichier partagé n'a été touché.

## Blocages / limites inter-domaines

- La vue Points ne possède aucun canvas (`src/views/points.js:29-126`) : la garde E064-03 ne peut être observée en action que via un harnais qui injecte un canvas. Le comportement par défaut reste « zéro canvas », ce qui est le résultat attendu du thème.
- `devicePixelRatio` n'est lu que dans la garde E064-03 et n'est jamais affiché : afficher la densité réelle rendrait les captures non reproductibles, ce qui contredirait E064-07. Toute lentille qui souhaiterait une lecture matérielle doit la garder hors du snapshot.
- Le snapshot est calculé au rendu, pas observé en continu : un changement de DOM sans nouveau rendu de la coque ne le met pas à jour. L'observation continue relève du contrat de la lentille E063 (MutationObserver ciblé), fichier non possédé.
- L'anti-écriture redondante (E064-05/E064-08) est une technique locale au service de la reproductibilité ; le contrat global de signature est porté par E066, et l'idempotence multi-rendus par E068, tous deux hors de ce module.
