# E058 — Noms historiques conservés avec leur époque

Lentille E058 — domaine F : sémantique & données.
Fichier possédé : `src/views/points/E058.js` uniquement. La vue (`src/views/points.js`), la coque, les autres lentilles et `styles.css` ne sont ni édités ni doublés. La lentille ajoute UN encadré non modal dans `.points-detail`, avec une charte de lecture et l'ancrage explicite du point courant : ère, ancrage temporel, noms et variantes conservés tels quels. Tout est dérivé du DOM rendu (`.points-grid-row.is-active .points-era`, `.points-meta`, `.points-point-title`, `.points-point-text`) : aucun nom, aucun millésime, aucune ère codés en dur. Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro écouteur global, zéro `console.*`, zéro `innerHTML`. CSS injecté par `ctx.css('points-e058', …)`, identifiants préfixés `points-e058-`.

## E058-01 — Charte statique des noms historiques, énoncée avant toute détection

- **Preuve** : `E058.js:189-191` crée une `<section role="region" aria-labelledby="points-e058-heading">` ; `:193-195` pose le `<h4 id="points-e058-heading">Noms historiques et leur ère</h4>`. `:197-200` ajoute un paragraphe `.points-e058-charte` dont le texte est fixe : « un nom d’époque est conservé tel que la source le donne — il n’est ni modernisé ni traduit. Une variante entre parenthèses est un nom historique, pas une correction… ». `:202-211` ajoute la liste de définitions d'ancrage. Aucun `role="dialog"`, aucun `aria-modal`, aucun `inert`.
- **Solution** : la charte est écrite dans le DOM statique une seule fois (`buildPanel`), avant même que le point courant soit analysé. Elle pose la règle de conservation (pas de modernisation, pas de traduction, pas de correction d'une variante), puis la fiche d'ancrage vient l'illustrer. L'encadré reste une région annotée du détail, jamais une modale.
- **Impact** : le lecteur sait d'abord comment lire les noms, puis voit la règle appliquée au point affiché ; l'information n'est pas portée par la seule couleur (libellés `dt` explicites + bordure gauche).
- **Effort** : S
- **Vérification** : relecture de `:189-211` — `role="region"` et `aria-labelledby` présents, aucun attribut de modale ; la charte est visible sans point sélectionné ; harnais : ouvrir une fiche sans nom entre parenthèses → la charte reste affichée.

- **Effort** : S

## E058-03 — Ancrage temporel lu dans `.points-meta`, sans date inventée

- **Impact** : l'encadré ne peut pas afficher de millésime absent de la fiche ; les ères sans ancrage chiffré restent honnêtes (« non affiché ») au lieu d'être complétées par une borne inventée.
- **Effort** : S

## E058-04 — Détection des noms conservés, avec filtre strict des groupes numériques

- **Preuve** : `isNameLike()` (`E058.js:116-123`) exige au moins deux lettres et autant de lettres que de chiffres, et écarte les bornes (`jusqu'`, `vers`, `environ`, `siècle`, `année`, `date`, `ans`). `detectNames()` (`:132-161`) n'interroge que deux nœuds : `.points-point-title` (`:142`) et `.points-point-text` (`:143`). `:147-152` relève les groupes entre parenthèses ; `:153-158` relève les noms propres introduits par `ancien/ancienne/anciens/anciennes/autrefois/jadis/alors` suivis d'une majuscule.
- **Solution** : deux motifs suffisants et vérifiables, tous deux en lecture seule. `add()` (`:135-140`) déduplique en préservant l'ordre d'apparition et mémorise la source (`titre` ou `texte`). Le filtre empêche qu'un intervalle comme `(1897–1904)` ou `(jusqu'en 1911)` devienne un « nom historique » fabriqué.
- **Impact** : les seuls noms listés sont ceux réellement écrits dans la fiche ; un chiffre ou une borne de date n'est jamais requalifié en nom, ce qui rend l'affirmation falsifiable par relecture du texte source.
- **Effort** : M
- **Vérification** : relecture de `:116-161` ; harnais : `Kolkata (Calcutta) — … (jusqu'en 1911)` → un seul élément `Calcutta`, le groupe daté écarté ; `(1911)` et `(env. 1250)` → zéro élément ; doublon titre/texte → une seule occurrence.

## E058-05 — Chaque variante étiquetée avec son ère et conservée verbatim

- **Preuve** : `fillPanel()` (`E058.js:223-249`) reconstruit seulement `#points-e058-variants` par `replaceChildren()` (`:233`). Quand il existe des noms, `:238-244` crée une `<ul>` de `<li>` dont le texte est `` `« ${name.value} » — conservé tel quel · ère : ${era}${suffix} · relevé dans le ${name.source}.` `` (`:242`), avec `suffix = ' · ancrage : ' + time` (`:240`). Quand il n'y en a pas, `:235-236` affiche « Aucune variante détectée : le nom du point est conservé tel quel avec son ère. »
- **Solution** : la chaîne du nom est copiée exactement depuis le DOM source (`txt()` à `:101-105`, `add()` à `:135-140`) : ni correction orthographique, ni traduction, ni mise à jour anachronique. L'ère et l'ancrage sont ajoutés autour, jamais à l'intérieur du nom.
- **Impact** : un nom d'époque reste lisible avec le contexte qui l'explique ; le lecteur peut comparer la variante affichée au texte original de la fiche et constater qu'elle est identique.
- **Effort** : S
- **Vérification** : relecture de `:233-245` ; harnais : comparer `textContent` du `<li>` et le segment du texte source — la sous-chaîne `« … »` doit être strictement identique ; changer d'ère → l'étiquette `ère :` change, la variante reste la même.

## E058-06 — Aucune date ni aucun nom codé en dur

- **Preuve** : l'en-tête (`E058.js:10-15`) déclare : « Toutes les valeurs affichées sont DÉRIVÉES DU DOM… Aucun nom, aucune date, aucun millésime n'est codé en dur ». Les seules fonctions de lecture sont `eraOf()` (`:167-172`), `timeOf()` (`:177-187`) et `detectNames()` (`:132-161`), toutes basées sur `querySelector` / `textContent`. Les tokens numériques visibles dans le fichier (`:113` « 1911 », « 1897–1904 », `:127` « Calcutta ») sont des exemples dans des commentaires d'intention et ne sont jamais écrits dans le DOM.
- **Solution** : le module ne possède aucun tableau de noms, aucune table d'ères, aucune constante de millésime. Les seules chaînes littérales écrites sont la charte, les libellés d'interface et les messages de repli.
- **Impact** : la lentille reste vraie si le jeu de données change de pays ou d'époque ; aucune affirmation historique n'est ajoutée au corpus, la règle de non-invention est préservée.
- **Effort** : S
- **Vérification** : relecture — absence d'import de `DATASET`, de table d'ères, de millésime dans une chaîne écrite au DOM ; `grep` des nombres dans les `textContent` : seuls les comptages de variantes (`:247`) et l'ancrage lu (`:231`, `:240`) peuvent en produire.

## Blocages / limites inter-domaines

- L'ère affichée est celle de la ligne active de la matrice (contrat de filtrage de `points.js`) ; si la vue change d'ère sans mettre à jour `.is-active`, E058 suit le DOM et peut afficher « ère non précisée ». Corriger le signal d'ère relève de la vue, fichier non possédé.
- La détection repose sur deux motifs syntaxiques (parenthèses et qualificatifs d'époque suivis d'une majuscule). Un nom historique attesté dans la prose sans ces marqueurs n'est pas listé : la lentille ne l'invente pas, elle se contente de ne pas le modifier. Étendre la détection demanderait une table de noms partagée, hors contrat.
- L'ancrage temporel est lu dans le 3ᵉ `<span>` de `.points-meta` ; si `points.js` réordonne ces spans, le repli numérique peut changer de source. Le format de la métadonnée appartient à la vue.
- L'encadré est inséré avant `.points-nav` ; une autre lentille qui réordonnerait le détail pourrait changer sa position, sans en altérer le contenu.
