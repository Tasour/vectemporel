# E025 — C. Détail & fiche — sources avec repli « omission justifiée »

Lentille E025 — domaine C : détail & fiche. Fichier possédé : `src/views/points/E025.js` uniquement ; aucun fichier partagé n'est édité. Le module lit le DOM construit par `src/views/points.js:95-114` et ajoute **une seule zone** `#points-e025-sources` dans `.points-detail` : liste structurée des sources déclarées quand elles existent, repli explicite « omission justifiée » quand la fiche n'en cite aucune.

Contrat exploité : `viewId`, `stage`, `layout`, `css`, `el`, `reducedMotion` (registry.js:28-44). Toutes les valeurs affichées sont dérivées de `.points-sources`, `.points-justification` et `.points-meta .confidence` : aucune source, aucune date, aucun identifiant n'est inventé. La feuille est injectée par `ctx.css('points-e025', …)` (E025.js:288) ; tous les identifiants sont préfixés `points-e025-` (E025.js:26-28). Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`.

Fait de données vérifié : `dataset.js:4695-4699` stocke `"sources": ["OM-002"]` avec `confidence: "non documenté"` pour une cellule « vide justifié ». Un tel jeton est une **référence d'omission**, pas une citation : la lentille le classe à part (E025.js:121-127, :163-180). Le rapport M35 (`UNIFIED_AUDIT/MONDE/views/M35.md:80`) relève 168 points `non documenté` et 80 points citant un `OM-*`.

## E025-01 — Zone unique insérée dans le détail, sans destruction

- **Preuve** : `E025.js:283-291` — `apply()` exige un `ctx.layout` et un `.points-detail` dotés de `querySelector`/`insertBefore`, puis `place(ctx, ZONE_ID, 'section', 'points-e025-zone', detail)` ; `E025.js:293-295` oriente la zone avant `.points-justification` (ou `.points-nav` en repli). La fiche d'origine (`points.js:95-122`) n'est ni déplacée ni retirée : seule la ligne plate est masquée (`E025.js:269-274`).
- **Solution** : la zone est créée au plus une fois par détail, réutilisée par identifiant, et placée dans l'ordre de lecture naturel du détail. Un `ctx` incomplet neutralise la lentille sans interrompre le rendu (`E025.js:311-314`).
- **Impact** : le détail reste lisible et complet ; la nouvelle zone s'ajoute comme encadré de fiche, jamais comme panneau modal ni comme replacement du contenu existant.
- **Effort** : S
- **Vérification** : relecture de `E025.js:283-314` ; harnais DOM — un seul `#points-e025-sources` après rendu, situé entre `.points-meta`/`.points-families` et `.points-justification` ; aucun nœud de `points.js` supprimé.

## E025-02 — Sources présentes : liste sémantique dérivée du DOM

- **Preuve** : `E025.js:111-119` — `sourceTokens()` retire le préfixe `Sources :` écrit par `points.js:110` et sépare sur la virgule ; `E025.js:163-171` construit le modèle ; `E025.js:200-218` rend `<ul class="points-e025-list">` avec un `<li><cite class="points-e025-cite">` par référence. Aucun nom de source n'apparaît en dur dans le module.
- **Solution** : la ligne plate « Sources : A, B » est convertie en liste citée, chaque jeton conservé tel quel ; un compteur textuel « N référence(s) citée(s) » est recalculé depuis la liste.
- **Impact** : les références deviennent des entités citables et discernables par les technologies d'assistance au lieu d'une chaîne plate ; le modèle suit le jeu de données sans réédition du code.
- **Effort** : S
- **Vérification** : harnais — « Sources : SRC-001, SRC-002 » produit exactement deux `<cite>` (`SRC-001`, `SRC-002`) et le libellé « 2 référence(s) citée(s) » ; relecture — absence de tableau de sources littéral.

## E025-03 — En-tête nommé, groupe ARIA, jamais de modale

- **Preuve** : `E025.js:262-265` crée `<h3 id="points-e025-title">` (« Sources de ce point » / « Sources · omission justifiée ») ; `E025.js:297-301` pose `role="group"` et `aria-labelledby="points-e025-title"` sur la zone ; la feuille `E025.js:41-47` stylise le titre sans `backdrop`, sans `position:fixed` et sans piège de focus.
- **Solution** : la zone est un groupe nommé par son propre titre, pas un `<dialog>`, pas un `role=dialog`, pas d'`aria-modal`. Aucun gestionnaire de clavier, aucune touche réservée, aucun `data-fk`.
- **Impact** : le parcours clavier de la fiche et du détail reste intact ; l'en-tête donne un repère de lecture sans interrompre le fil.
- **Effort** : S
- **Vérification** : relecture — aucun `role=dialog`, `aria-modal`, `inert` ni écouteur documentaire ; le titre porte bien l'ID référencé par `aria-labelledby`.

## E025-04 — Repli « omission justifiée » quand aucune citation n'est présente

- **Preuve** : `E025.js:121-127` — `isOmissionToken()` reconnaît `/^OM-\d+$/i` ; `E025.js:166-180` sépare `citations` et `storedRefs` et pose `hasSources = citations.length > 0` ; `E025.js:227-233` rend le badge de nature et la phrase « Aucune source citée pour ce point : l'absence est documentée, pas masquée. » ; `E025.js:275-276` choisit la branche.
- **Solution** : trois cas réels sont couverts — sources citées, aucun `.points-sources`, ligne ne contenant qu'un `OM-*`. Dans les deux derniers, le repli dit explicitement que l'absence est tracée ; il ne promet pas une source inexistante. Le cas `dataset.js:4695-4699` est traité comme omission, pas comme citation.
- **Impact** : un point « vide justifié » n'est plus affiché comme s'il reposait sur une source `OM-002` ; la couverture négative devient lisible au même endroit que les sources positives.
- **Effort** : M
- **Vérification** : harnais — (a) `Sources : SRC-001` → branche citations ; (b) aucun `.points-sources` → branche omission ; (c) `Sources : OM-002` avec certitude `non documenté` → branche omission et `OM-002` listé comme référence d'omission, jamais dans un `<cite>`.

## E025-05 — Le motif est lu sur la justification, jamais érigé en source

- **Preuve** : `E025.js:129-135` — `omissionKind()` classe « omission documentée », « case vide justifiée », « dette documentée » ou « absence de source déclarée » depuis le texte réel ; `E025.js:155-161` — `excerpt()` garde la première phrase (plafond 240 caractères) ; `E025.js:234-240` la rend précédée de « Motif : ».
- **Solution** : la justification sert d'explication de l'absence ; elle n'est jamais transformée en `<cite>`, en URL ni en référence bibliographique. Le texte intégral reste dans `.points-justification` (E026 le mettra en citation), la zone n'en montre qu'un extrait documentaire.
- **Impact** : aucun texte d'omission nouveau n'est rédigé par la lentille ; le motif affiché est falsifiable par lecture de la fiche d'origine.
- **Effort** : S
- **Vérification** : relecture — aucun `<cite>` créé dans `renderOmission()` (`E025.js:227-255`) ; harnais — justification « Cellule « vide justifié » … » → badge « case vide justifiée » et motif tronqué à la première phrase.

## E025-06 — Identifiants d'omission surfacés depuis deux signaux, dédupliqués

- **Preuve** : `E025.js:137-146` — `omissionIds()` extrait `/OM-\d+/g` et déduplique via un objet `Object.create(null)` ; `E025.js:169-171` fusionne la justification et les jetons `OM-*` de la ligne « Sources » ; `E025.js:241-250` rend « Référence d'omission : …. » ou, à défaut, « Aucun identifiant d'omission dédié n'est associé à cette case. ».
- **Solution** : l'identifiant n'est jamais codé en dur ; il est lu là où le jeu de données le place réellement. Le cas sans identifiant dédié est nommé, pas laissé vide.
- **Impact** : un auditeur peut relier la fiche à `omissions.yaml` sans quitter le détail ; l'absence d'identifiant est elle-même une information.
- **Effort** : S
- **Vérification** : harnais — justification contenant `OM-002` deux fois → une seule occurrence affichée ; justification sans `OM-*` → phrase de repli ; recoupement avec `M35.md:80` (80 points porteurs d'un `OM-*`).

## E025-07 — Certitude « non documenté » distincte de l'absence de source

- **Preuve** : `E025.js:148-151` — `confidenceOf()` lit `.points-meta .confidence` tel que rendu par `points.js:105` ; `E025.js:251-254` ajoute « Certitude « non documenté » : l'absence de source est attendue et tracée ; ce point n'est pas présenté comme une citation. » uniquement si le badge le dit.
- **Solution** : deux signaux indépendants — présence de citations et valeur de certitude — sont affichés sans être additionnés ni confondus, sur le modèle de `M35.md:81`. Aucun changement de certitude n'est opéré.
- **Impact** : un point `non documenté` n'est pas lu comme une lacune de la lentille mais comme un état déclaré du corpus ; un point « certain » sans source ne reçoit pas ce commentaire.
- **Effort** : S
- **Vérification** : harnais — badge `non documenté` → ligne supplémentaire ; badge `certain` → ligne absente ; relecture — aucune modification de `.confidence` ni de sa classe `is-*`.

## E025-08 — Accessibilité : états textuels, contraste, focus, zéro région live

- **Preuve** : chaque état porte un libellé (`E025.js:203`, `:231`, `:244`, `:248`) ; la feuille `E025.js:62` donne un focus visible sur `.points-nav button`, `:63-65` un repli ≤ 700 px, `:66-71` `prefers-contrast`/`forced-colors`, `:72-74` neutralisation sous `prefers-reduced-motion`. Aucun `role="status"` ni `aria-live` n'est ajouté (`E025.js:297-301`).
- **Solution** : l'information ne repose jamais sur la seule couleur (badge de nature + texte, libellé « Sources déclarées » / « omission justifiée »). Aucune région live concurrente n'est créée : E041 reste l'unique source d'annonces. Aucune animation propre n'existe, donc `reducedMotion` est respecté par construction.
- **Impact** : la zone reste lisible en 390×844, en contraste forcé et avec mouvement réduit ; les lecteurs d'écran obtiennent un groupe nommé sans bavardage.
- **Effort** : M
- **Vérification** : relecture — absence de `role=status`, `aria-live`, `role=dialog`, `aria-modal` ; émulation `forced-colors: active` et `prefers-reduced-motion: reduce` → bordure CanvasText, aucune transition.

## E025-09 — Signature par nœud et écriture conditionnelle

- **Preuve** : `E025.js:183-196` — `signatureOf()` joint état, citations, références stockées, justification, nature, identifiants et certitude ; `E025.js:303-308` — sortie sans écriture si `zone.dataset.pointsE025Sig === sig` et que le corps existe, sinon signature posée puis `render()` ; `E025.js:77` compteur `writes`, `:261` `replaceChildren()`, `:277-278` métrique visible.
- **Solution** : la signature est stockée sur le nœud lui-même : elle disparaît avec lui au rendu neuf, ce qui supprime tout état module périmé. Le corps est reconstruit par `replaceChildren` et nœuds `ctx.el`, jamais par `innerHTML`.
- **Impact** : aucune écriture redondante sur un DOM inchangé ; la métrique « actualisations de la zone : N » distingue « modèle inchangé » de « greffon muet ».
- **Effort** : M
- **Vérification** : rejeu — 1re passe `writes=1`, 2e passe sur le même DOM `writes` stable, changement de point `writes+1`, rendu neuf `writes=0` ; relecture — aucun `innerHTML`, `outerHTML`, `insertAdjacentHTML`.

## E025-10 — Idempotent multi-rendus, CSS unique, périmètre strict

- **Preuve** : `E025.js:91-95` — `put()` ne réécrit qu'une valeur différente ; `E025.js:97-109` — `place()` retire un nœud mal parenté, recrée un nœud déconnecté et remet le compteur à zéro ; `E025.js:26-28` + `:288` — un seul `CSS_ID` passé à `ctx.css` (cssOnce) ; `E025.js:311-314` — un seul `register('E025', …)` avec `try/catch`. Seul `.points-sources` est masqué (`E025.js:271-274`) ; `.points-point-title`, `.points-point-text`, `.points-meta`, `.points-families`, `.points-justification` et `.points-nav` ne sont jamais modifiés.
- **Solution** : les attributs, la zone et la feuille sont tous réutilisés par identifiant ; la lentille tolère un second passage de `runEnhancements` sur le même DOM et un rendu neuf. Aucun écouteur, aucun timer, aucune rAF n'est accumulé.
- **Impact** : pas de doublon après navigation aller-retour, pas de fuite, pas d'interférence avec les autres lentilles du domaine C (E021–E024, E026–E030).
- **Effort** : M
- **Vérification** : `node --check src/views/points/E025.js` → PASS ; navigation aller-retour → un seul `#points-e025-sources` et une seule feuille `#points-e025` ; `grep` des interdits (`console.`, `fetch`, `XMLHttpRequest`, `Math.random`, `innerHTML`, `requestAnimationFrame`, `setTimeout`, `setInterval`) → aucune occurrence active.

## Statut d'implémentation

Les dix chantiers E025-01 à E025-10 sont implémentés dans `src/views/points/E025.js` uniquement. CSS injecté via `ctx.css('points-e025', …)`. Un seul `register('E025', ctx => {…})`. La ligne plate `.points-sources` est masquée de façon réversible, jamais supprimée, et son contenu est intégralement reclassé (citations d'un côté, références d'omission de l'autre). Aucun fichier partagé touché, aucune donnée inventée.

## Blocages / limites inter-domaines

- Le masquage de `.points-sources` passe par l'attribut `hidden` plus une règle CSS dédiée (`E025.js:34`, `:271-274`) : une autre lentille qui voudrait lire la visibilité de cette ligne devrait lire la zone `#points-e025-sources`. Aucune autre lentille du domaine C ne porte sur `.points-sources` (themes.json:24-33).
- Le motif affiché est un extrait de première phrase plafonné à 240 caractères (`E025.js:155-161`) : le texte intégral reste dans `.points-justification`, dont la mise en citation relève d'E026 (themes.json:26). L'extrait est purement documentaire et n'altère aucun chiffre.
- Aucune annonce de région live n'est émise lors du changement de source : E041 conserve l'unique région live. Le changement est donc perceptible à la lecture du détail, pas par une annonce automatique.
- Le compteur `writes` est volatile et remis à zéro sur nœud neuf (`E025.js:77`, `:106`) : le conserver entre rendus exigerait un état partagé hors du contrat de la lentille.
- La reconnaissance des références d'omission repose sur le motif `/^OM-\d+$/i` (`E025.js:125`) : un identifiant de forme différente serait traité comme une citation. Le motif est celui observé dans `dataset.js:4696` et `M35.md:80`.
