# E019 — Filtres & périmètre : annonce de changement de filtre sans bavardage

Lentille E019 — domaine B : filtres & périmètre. Fichier possédé : `src/views/points/E019.js` uniquement. Aucun fichier partagé n'est édité. Les deux `<select>` et le bouton « Réinitialiser les filtres » de `points.js` ne sont ni remplacés ni modifiés dans leur comportement : E019 ajoute des attributs d'accessibilité, un écouteur par select et une région live LOCALE. Le bouton de réinitialisation appartient à E013 ; E019 reste volontairement muet sur ce geste pour ne pas doubler l'annonce. Le ctx de la vue (`viewId, stage, layout, css, el, reducedMotion`, `points/registry.js:28-44`) n'expose pas `say()` : l'annonce passe donc par un `<p role=status aria-live=polite>` persistant, accroché à `document.body` pour survivre au re-render déclenché par `set()`. Contrat exploité : `.points-filters` (2 selects) et `.points-detail` (compteur de périmètre). Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`, zéro `MutationObserver`. CSS injecté par `ctx.css('points-e019', …)`, tous les identifiants préfixés `points-e019-`.

## E019-01 — Feuille CSS unique, ciblée et sans effet hors de la vue Points

- **Preuve** : `E019.js:32-51` définit une feuille unique `CSS` ; `E019.js:159` la passe à `ctx.css(CSS_ID, CSS)`, donc `cssOnce` (`registry.js:13-19`) ne l'injecte qu'une fois. Tout sélecteur est soit sous `.points-layout`, soit `#points-e019-live` (`E019.js:36,40,46,49`) ; `CSS_ID = 'points-e019'` et `LIVE_ID = 'points-e019-live'` (`:29-30`).
- **Solution** : une seule feuille, identifiant stable, périmétrage strict à la vue Points. Aucun style global, aucun `@import`, aucune URL distante.
- **Impact** : pas de collision de styles avec les autres lentilles ni avec le reste de l'application ; la feuille survit aux rendus successifs sans duplication.
- **Effort** : S
- **Vérification** : relecture — un seul `const CSS`, un seul appel `ctx.css(CSS_ID, CSS)` ; aucun sélecteur hors `.points-layout` / `#points-e019-live`.

## E019-02 — Annonce au changement de filtre de domaine

- **Preuve** : `selectsOf()` (`E019.js:96-103`) lit les `<select>` de `.points-filters` dans l'ordre où `points.js:92` les a attachés ; l'index 0 est le domaine (`E019.js:165-167`, `kinds = ['domaine','famille']`). L'écouteur `change` (`E019.js:172-175`) appelle `onFilterChange('domaine', …)` (`:135-143`) qui mémorise le libellé de l'option choisie ; l'annonce est diffusée au rendu suivant par `:183-185`. Le gestionnaire natif de `points.js:69-72` reste actif.
- **Solution** : greffon purement additif — aucun `preventDefault`, aucune modification de `state`, aucun remplacement du `<select>`. Le changement est capté au moment où l'utilisateur le fait, puis annoncé une fois le DOM recalculé.
- **Impact** : un lecteur d'écran apprend immédiatement quel domaine est désormais affiché, sans que le comportement du filtre change pour les autres utilisateurs.
- **Effort** : S
- **Vérification** : relecture de `:165-175` et `:135-143` ; harnais — sélectionner « Physique » dans le premier select : une seule annonce, libellé conforme à l'option réelle.

## E019-03 — Région live locale, unique et créée avant la première écriture

- **Preuve** : `ensureLive()` (`E019.js:59-77`) cherche `#points-e019-live`, le réutilise s'il est connecté, sinon le crée (`<p role=status aria-live=polite aria-atomic=true>`, `:69-74`) et l'attache à `document.body`. `install()` l'appelle à `:163`, avant toute annonce possible. Une région déconnectée est retirée puis recréée (`:68`), sans doublon d'identifiant.
- **Solution** : région persistante sur `body` plutôt que dans le layout : le re-render de `renderPoints` remplace le layout (`points.js:124-126`), pas cette région. Aucune écriture dans une région live d'une autre lentille (`points-e013-live`, `points-e035-live`) ni dans la coque.
- **Impact** : la première annonce n'est pas perdue faute de région live présente ; aucune région concurrente n'est modifiée.
- **Effort** : S
- **Vérification** : relecture de `:62-77` ; harnais — avant tout changement, `document.querySelectorAll('#points-e019-live').length === 1` ; après plusieurs rendus, toujours 1.

## E019-04 — Annonce au changement de filtre de famille

- **Preuve** : le même écouteur couvre le second select, identifié `kind = 'famille'` (`E019.js:165-167`, index 1). `onFilterChange()` (`:135-143`) enregistre `kind` et le libellé de l'option ; `buildMessage()` (`:123-129`) produit « Filtre famille : <libellé>. … ». Aucune liste de familles n'est codée en dur.
- **Solution** : symétrie totale avec le domaine, sans second mécanisme : un seul type d'écouteur, une seule file d'annonce (`pending`), une seule région live.
- **Impact** : le périmètre par famille est annoncé avec la même économie de parole que le domaine ; pas de bavardage propre à cette dimension.
- **Effort** : S
- **Vérification** : relecture de `:165-175` ; harnais — sélectionner une famille : message « Filtre famille : … », une seule écriture dans la live.

## E019-05 — Déduplication et anti-bavardage

- **Preuve** : `announce()` (`E019.js:79-88`) refuse une chaîne vide, une phrase identique à `lastAnnouncement` (`:82`) et une région absente ou déconnectée (`:84`). Les invariants d'en-tête (`:20-26`) interdisent toute annonce au rendu et sur le bouton de réinitialisation. `pending` est vidé après usage (`:189`), ce qui empêche rejouer une annonce si `install()` repasse sur le même DOM (`:181-190`).
- **Solution** : une seule annonce par changement réel, différée au rendu qui suit `set()` ; garde de dédup stable entre les rendus (`:56`), contrairement aux compteurs de rendu. Le bouton « Réinitialiser » est volontairement laissé à E013 (`:9-10`).
- **Impact** : ni bavardage sur les rendus sans changement de filtre, ni double annonce sur la réinitialisation, ni répétition d'une phrase identique.
- **Effort** : M
- **Vérification** : relecture de `:79-88` et `:181-190` ; harnais — deux clics successifs sans changement de valeur (le second ne déclenche pas `change`) : une seule annonce ; changement puis réinitialisation : annonce E019 puis annonce E013, jamais deux fois la même.

## E019-06 — Libellé annoncé depuis l'option réellement sélectionnée

- **Preuve** : `optionLabel()` (`E019.js:105-111`) lit `select.options[select.selectedIndex]` et prend `textContent` (repli `label`). `onFilterChange()` l'appelle à `:139` au moment de l'événement, quand le DOM reflète encore le choix de l'utilisateur.
- **Solution** : aucune table de libellés, aucun `value` traduit en dur : la source de vérité est l'`<option>` que le navigateur expose. Le champ `value` est mémorisé (`:139`) pour traçabilité mais n'est pas interprété.
- **Impact** : l'annonce reste correcte si un domaine ou une famille est ajouté, renommé ou retiré du jeu de données.
- **Effort** : S
- **Vérification** : relecture de `:105-111` ; harnais — changer le libellé d'une option dans le harnais : l'annonce suit sans modification du module.

## E019-07 — Compteur du périmètre lu dans le détail réel

- **Preuve** : `scopeCount()` (`E019.js:113-121`) lit `.points-detail` et extrait `(\d+) point(s) dans ce périmètre` du texte affiché par `points.js:96`. `install()` l'appelle après re-render (`:184`) : le nombre est donc celui du nouveau périmètre, pas l'ancien. Le résultat est aussi exposé en miroir auditable `data-points-e019-count` (`:187`).
- **Solution** : aucun recalcul de la logique de filtrage de `points.js` : la lentille se contente de relire le compteur que la vue a déjà calculé. Repli explicite si le libellé change : message sans nombre (`:128`).
- **Impact** : le chiffre annoncé est falsifiable par lecture directe du détail ; aucune statistique inventée ni périmée n'est énoncée.
- **Effort** : S
- **Vérification** : relecture de `:113-121` et `:184-187` ; harnais — filtrer puis lire simultanément la live et le `.view-kicker` : les nombres coïncident.

## E019-08 — Accessibilité : live polie, cibles tactiles et focus visible

- **Preuve** : la région porte `role=status`, `aria-live=polite` et `aria-atomic=true` (`E019.js:71-73`). La feuille (`:36-50`) impose `min-height: 36px` aux selects, `44px` sous 620 px, un `outline` `:focus-visible`, et neutralise transitions/animations sous `prefers-reduced-motion`. Les selects conservent leur `aria-label` natif (`points.js:62,74`) ; E019 n'ajoute un `title` que s'il est absent (`:169-171`).
- **Solution** : annonce polie et atomique (pas d'interruption, phrase entière relue), cibles conformes, focus visible, mouvement réduit respecté, aucun attribut natif écrasé.
- **Impact** : compatible lecteur d'écran et navigation clavier, y compris en 390×844 ; aucune information portée par la seule couleur.
- **Effort** : S
- **Vérification** : relecture de `:40-50` et `:71-73` ; contrôle — `getComputedStyle` des selects ≥ 36 px, émulation `prefers-reduced-motion: reduce` sans transition active.

## E019-09 — Message court, composé depuis le DOM, avec repli véridifiable

- **Preuve** : `buildMessage()` (`E019.js:123-129`) ne produit qu'une phrase courte : `Filtre <kind> : <libellé>.` suivie, si disponible, de `<n> point(s) dans ce périmètre.`, sinon de `Périmètre actualisé.` Le compteur d'annonces est écrit en miroir dans `data-points-e019-announced` (`:188`), hors région live.
- **Solution** : une seule phrase informative, jamais un commentaire sur l'action elle-même (« j'ai filtré… ») ; le repli dit seulement ce qui est observable, sans inventer de nombre.
- **Impact** : annonce compréhensible en une écoute, sans bavardage ni sur-annotation ; trace auditable du nombre réel d'annonces.
- **Effort** : S
- **Vérification** : relecture de `:123-129` ; harnais — compteur absent (détail sans chiffre) : message de repli, jamais un `0` fabriqué.

## E019-10 — Greffon idempotent, non destructif, résilient au rendu neuf

- **Preuve** : `install()` (`:156-192`) garde un seul appel CSS (`:159`), une seule région live (`:163`), un écouteur par nœud grâce au marqueur `data-points-e019-bound` testé à `:172` puis posé à `:173`. Aucun nœud natif n'est supprimé ; les signaux DOM sont préfixés (`data-points-e019*`, `:142,149,186-188`). `register('E019', install)` n'apparaît qu'une fois (`:194`). Le ctx est relu à chaque passage (`:158`) et `pending` est remis à zéro après diffusion (`:189`).
- **Solution** : même DOM, aucun doublon d'écouteur ; rendu neuf (coque recréant le stage), nouveaux selects → nouveaux écouteurs, région live conservée sur `body`, `lastAnnouncement` stable pour éviter la répétition.
- **Impact** : pas de fuite d'écouteurs ni d'annonces fantômes après navigation aller-retour ; comportement vérifiable par attributs de diagnostic sans `console.*`.
- **Effort** : M
- **Vérification** : relecture de `:156-194` ; harnais — rendu → aller-retour → rendu : un seul `#points-e019-live`, un seul écouteur par select, `data-points-e019-announced` cohérent avec le nombre de changements.

## Statut d'implémentation

Les dix chantiers E019-01 à E019-10 sont implémentés dans `src/views/points/E019.js` uniquement. CSS injecté via `ctx.css('points-e019', …)`. Aucun fichier partagé touché, aucun comportement natif de `points.js` modifié, aucun doublage de l'annonce de réinitialisation d'E013.

## Blocages / limites inter-domaines

- Le ctx de la vue Points n'expose pas `say()` (`points/registry.js:28-44`) : E019 utilise sa propre région live sur `document.body`. Toute lentille qui réécrirait `body` devra préserver `#points-e019-live`.
- L'annonce est différée au rendu qui suit `set()` ; elle suppose le re-render assuré par `subscribe(render)` (`app.js:130`). Si un hôte ne re-rendait pas, le `pending` resterait en attente — comportement à rejouer dans le harnais.
- Le bouton « Réinitialiser les filtres » est délibérément muet côté E019 pour éviter une double annonce avec E013 ; sa couverture est donc hors périmètre de cette lentille.
- Le compteur dépend du libellé exact écrit par `points.js:96` (`N point(s) dans ce périmètre`). Si ce libellé changeait, le repli « Périmètre actualisé. » s'activerait sans chiffre.
- Le choix d'identifier les selects par leur position (0 = domaine, 1 = famille) suit l'ordre d'attachement de `points.js:92`. Un changement de cet ordre inversionnait les libellés `kind` — à surveiller si la vue est réordonnée.
