# E045 — Cellules étiquetées (ère, domaine, compte)

Lentille E045 du chantier POINTS, domaine E : accessibilité & ARIA. Fichier possédé : `src/views/points/E045.js` uniquement. La vue `src/views/points.js`, la coque, `styles.css` et les autres lentilles ne sont ni édités ni doublés : E045 enrichit le DOM déjà produit par `renderPoints` (`points.js:29-126`) sans le reconstruire.

Contrat exploité : `viewId`, `layout`, `css`, `el`, `reducedMotion` (`registry.js:29-37`). Aucune dépendance vers le store, les filtres ou le détail : chaque étiquette est dérivée du DOM réel — texte visible de la cellule (`points.js:46`), `title` (`points.js:48`), boutons d'ère (`points.js:40`), en-têtes de colonne (`points.js:35-36`). Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`. CSS unique injecté par `ctx.css('points-e045', …)` (`registry.js:13-19`). Les rôles de grille restent la compétence d'E044 (`themes.json:49`) : E045 pose uniquement des rôles d'en-tête là où aucun rôle n'existe.

## E045-01 — Étiquette ARIA complète par cellule : ère · domaine · compte

- **Preuve** : `E045.js:163-168` compose `base = ${eraName} · ${domain} : ${countWord(count)} (${state})` puis l'écrit dans `aria-label` via `setAttr` (`:68-70`), avec un point final ajouté par `withDot` (`:63-66`). L'ère vient du bouton `.points-era` (`:140-141`), le domaine des en-têtes de colonne (`:121-125`, `:155-156`), le compte de `countOf` (`:49-54`). Le garde `contextualLabel` (`:91-94`) préserve une étiquette déjà contextuelle posée par E003.
- **Solution** : une seule étiquette nomme les trois dimensions demandées ; aucun chiffre ni nom n'est codé en dur, tout est lu dans le DOM rendu. Le texte visible (`count` ou `·`) et le `title` restent intacts.
- **Impact** : un lecteur d'écran annonce « Antiquité · Droit : 3 points (cellule renseignée). » au lieu d'un « 3 » orphelin ; la cellule devient compréhensible hors du contexte visuel de la grille.
- **Effort** : M
- **Vérification** : relecture de `:163-168` ; harnais DOM : une cellule `3` avec `title` « Antiquité · Droit · 3 point(s) » donne une étiquette contenant ère, domaine, « 3 points » et « cellule renseignée » ; rejeu sur le même nœud → aucune seconde écriture (`setAttr` compare avant d'écrire).

## E045-02 — Cellules vides explicitement nommées, le « · » visuel conservé

- **Preuve** : `countOf` (`:49-54`) teste d'abord le texte (/^\\d+$/) puis le `title` (/(\\d+)\\s*point/i) ; le signe `·` (`points.js:46`) et un `title` absent retombent sur `0`, jamais sur `1`. `countWord(0)` renvoie « aucun point » (`:58-61`) et l'état devient « cellule vide » (`:161`).
- **Solution** : l'absence de point est un état nommé, pas un blanc. Le signe intermédiaire reste affiché pour les voyants ; seule l'étiquette accessible le traduit.
- **Impact** : une cellule vide ne peut plus être confondue avec une cellule dont le compte n'aurait pas été chargé, ni annoncée comme « point » par défaut.
- **Effort** : S
- **Vérification** : relecture de `:49-54`, `:58-61`, `:161` ; harnais : texte `·` avec et sans `title` → deux fois « aucun point (cellule vide) » ; texte `0` → même étiquette.

## E045-03 — Boutons d'ère étiquetés avec le total de leur ligne

- **Preuve** : `:144-145` calcule `total` en sommant `countOf` sur toutes les cellules de la ligne ; `:149-152` pose sur `.points-era` l'étiquette `Ère <nom> : <compte> dans cette ligne de la matrice`. Le libellé visible du bouton (`points.js:40`) n'est pas modifié.
- **Solution** : le nom de l'ère est complété par une grandeur dérivée, recalculée à chaque rendu depuis les cellules réelles ; aucun total historique n'est importé.
- **Impact** : parcourir les boutons d'ère au clavier donne déjà une mesure de couverture par ligne, sans ouvrir chaque cellule.
- **Effort** : S
- **Vérification** : relecture de `:144-152` ; harnais : une ère de trois cellules (2, 0, 1) → étiquette « 3 points dans cette ligne de la matrice » ; changer une cellule → l'étiquette suit sans modifier le code.

## E045-04 — En-têtes associés par identifiants préfixés et `aria-describedby`

- **Preuve** : `:22-25` déclare `HEAD_PREFIX = 'points-e045-head-'` et `ERA_PREFIX = 'points-e045-era-'` ; `:130-135` attribue un `id` préfixé à chaque `<span>` d'en-tête et `:172-174` ajoute cet identifiant ainsi que celui du bouton d'ère à l'`aria-describedby` de la cellule. `describe` (`:80-87`) lit les identifiants existants, évite les doublons et ne les écrase pas.
- **Solution** : les noms d'en-tête sont des cibles adressables, rattachées à chaque cellule comme descriptions complémentaires — sans déplacer ni renommer les nœuds de la vue.
- **Impact** : même si l'étiquette principale est tronquée par une technologie d'assistance, l'ère et le domaine restent disponibles via la description.
- **Effort** : M
- **Vérification** : relecture de `:80-87`, `:130-135`, `:172-174` ; contrôle : tous les `id` commencent par `points-e045-` ; une cellule portant déjà `aria-describedby="autre"` conserve `autre` puis reçoit les deux identifiants.

## E045-05 — Rôles d'en-tête complémentaires, non destructifs

- **Preuve** : `ensureRole` (`:74-76`) ne pose `role="columnheader"` que si l'attribut `role` est absent ; `:133` l'applique aux `<span>` de la ligne d'en-tête. Le commentaire d'en-tête (`:18-19`) réserve explicitement `role=grid`/`row`/`gridcell` à E044.
- **Solution** : E045 n'entre pas en conflit avec la sémantique de grille d'E044 : si E044 a déjà posé un rôle, il est conservé ; sinon les en-têtes de colonne seuls gagnent un rôle sémantique adapté à leur nature de `<span>`.
- **Impact** : pas de double attribution de rôles, pas de régression des boutons `.points-cell` dont la sémantique de bouton reste inchangée.
- **Effort** : S
- **Vérification** : relecture de `:18-19`, `:74-76`, `:130-135` ; harnais : en-tête sans rôle → `columnheader` ; en-tête avec `role="gridcell"` préexistant → rôle inchangé.

## E045-06 — Accord du compte en français, sans « point(s) » brut

- **Preuve** : `countWord` (`:56-61`) renvoie « aucun point », « 1 point » ou `${count} points` ; `withDot` (`:63-66`) ponctue une seule fois. Le « point(s) » du `title` natif (`points.js:48`) n'est jamais recopié dans une étiquette.
- **Solution** : une seule fonction de mise en forme sert les cellules (`:165`) et les boutons d'ère (`:151`) : zéro accord bancal du type « 1 points » ou « aucun points ».
- **Impact** : les annonces sont grammaticalement correctes à tous les compteurs, y compris zéro et un.
- **Effort** : S
- **Vérification** : relecture de `:56-66` ; contrôle des trois cas : 0 → « aucun point », 1 → « 1 point », 12 → « 12 points » ; aucun « point(s) » dans le module.

## E045-07 — Légende statique de lecture des étiquettes

- **Preuve** : `legendInto` (`:96-104`) crée un `<p class="points-e045-legend">` avec `ctx.el` et l'identifiant `points-e045-legend`, inséré avant `.points-filters` quand il existe (`:100-102`). La garde `!layout.querySelector('#…')` (`:184`) empêche le doublon ; un exemplaire orphelin d'un rendu précédent est retiré (`:185-186`).
- **Solution** : la convention ère · domaine · compte et le sens du signe `·` sont expliqués une fois, en texte visible, hors région live et sans chiffre codé en dur.
- **Impact** : les utilisateurs comprennent pourquoi le compte est absent d'une cellule ; la légende reste lisible sans CSS et n'ajoute aucune annonce concurrente.
- **Effort** : S
- **Vérification** : relecture de `:96-104`, `:178-188` ; rendu → nouveau rendu : un seul `#points-e045-legend` ; lecture sans feuille de style : le paragraphe reste dans le flux.

## E045-08 — Unicité des étiquettes, désambiguïsation par position

- **Preuve** : `used = new Set()` (`:137`) ; `:165-167` compare `base` aux étiquettes déjà vues et n'ajoute « — ligne N, colonne M » qu'en cas de collision réelle, avant d'enregistrer la base.
- **Solution** : la désambiguïsation est conditionnelle : aucune position n'est ajoutée quand ère + domaine suffisent à distinguer les cellules, ce qui évite un bruit inutile dans les annonces.
- **Impact** : deux ères homonymes ou deux domaines homonymes ne produisent pas deux étiquettes identiques ; chaque cellule reste adressable de façon unique pour un lecteur d'écran.
- **Effort** : M
- **Vérification** : relecture de `:137`, `:165-167` ; harnais : jeu normal → aucune mention de ligne/colonne ; jeu dupliqué → seules les cellules en collision reçoivent le suffixe de position.

## E045-09 — État de présence dit en toutes lettres, `title` préservé

- **Preuve** : `:159-161` dérive `state` du compte (`cellule renseignée` / `cellule vide`) et l'injecte dans l'étiquette (`:165`). Aucune écriture vers `cell.title` n'existe dans le module ; la classe `has-points` de `points.js:46` n'est ni lue pour colorer ni retirée.
- **Solution** : l'information portée par la couleur de fond est doublée par un mot dans l'étiquette accessible, tandis que le `title` natif reste la source de repli du compte (`:52`) et n'est pas écrasé.
- **Impact** : en `forced-colors` ou sans CSS, la distinction « avec points / sans point » demeure ; les deux canaux (visuel et accessible) restent cohérents.
- **Effort** : S
- **Vérification** : relecture de `:52`, `:159-165` ; recherche de `cell.title =` dans E045.js → aucune occurrence ; bascule des couleurs forcées → l'état reste énoncé.

## E045-10 — Idempotence, non-destruction et conformité statique

- **Preuve** : `:106-114` filtre sur `viewId === 'points'`, injecte le CSS par `cssOnce` et pose une seule classe de portée ; `setAttr` (`:68-70`) évite les écritures redondantes ; `:184-188` garantit une seule légende. Le module ne contient aucun `addEventListener` global, aucun `innerHTML`, aucun `Math.random`, `fetch`, `XMLHttpRequest`, `console.` ni timer/rAF (vérification textuelle ci-dessous).
- **Solution** : une seule passe synchrone et locale par rendu ; les nœuds de la vue sont lus et annotés, jamais remplacés ; les étiquettes existantes déjà contextuelles sont préservées (`:89-94`, `:149`).
- **Impact** : navigation aller-retour sans doublon d'identifiants ni de légende, pas de fuite d'écouteurs, aucune dépendance à un état module mutable, compatibilité avec E003/E044/E049.
- **Effort** : M
- **Vérification** : `node --check src/views/points/E045.js` → PASS ; recherche des interdits → aucune occurrence ; deux appels successifs sur le même DOM → mêmes `id`, même légende unique, aucun `aria-label` réécrit à l'identique ; capture 390×844 à rejouer par l'agent maître.

## Statut d'implémentation

Les dix chantiers E045-01 à E045-10 sont implémentés dans `src/views/points/E045.js` uniquement. CSS unique via `ctx.css('points-e045', …)`. Aucun fichier partagé touché, aucune donnée inventée, aucun rôle préexistant écrasé, aucun nœud de la vue supprimé.

## Blocages / limites inter-domaines

- La sémantique complète de grille (`role=grid`/`row`/`gridcell`) relève d'E044 (`themes.json:49`) : E045 ne la pose pas et se contente de rôles d'en-tête de colonne en l'absence d'attribution préalable (`E045.js:74-76`, `:133`). Si E044 n'est pas implémenté, la grille reste navigateur-native (boutons tabulables), ce qui est conforme à l'état initial de `points.js`.
- L'étiquette dépend du `title` et du texte produit par `points.js:46-48` : si une autre lentille modifie ces sources sans mettre à jour les étiquettes, E045 recalcule au rendu suivant, pas immédiatement (aucun `MutationObserver` propre, pour éviter une boucle d'écriture).
- La légende est statique et non localisée autrement qu'en français : l'ajout d'une locale demanderait de modifier ce module, seul fichier possédé.
- Le signal `layout.dataset.e045 = '1'` (`:114`) est écrit par E045 ; toute lentille qui réécrirait `layout.dataset` doit le préserver.
