# E033 — Navigation & clavier : Entrée / Espace activent une cellule

Lentille E033 — domaine D : navigation & clavier. Fichier possédé : `src/views/points/E033.js` uniquement (242 lignes). Ni `src/views/points.js` (qui crée les cellules), ni `src/platform/keyboard.js` (routeur clavier unique), ni le store, ni la coque ne sont édités. Contrat exploité : `viewId`, `stage`, `layout`, `css(id,rules)`, `el(tag,cls,text)`, `reducedMotion` (fournis par `points/registry.js:28-44`). Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro `console.*`, zéro `innerHTML`, aucune donnée historique inventée. CSS injecté par `ctx.css('points-e033', …)` (cssOnce, `registry.js:13-19`). Tous les identifiants sont préfixés `points-e033-`.

Le constat de départ est important pour l'honnêteté du rapport : `points.js:46` crée les cellules comme des `<button>` natifs, et le navigateur synthétise déjà leur `click` sous Entrée (keydown) et Espace (keyup) ; le routeur (`keyboard.js:131-132`) laisse passer ces touches car `isControl()` inclut `BUTTON`. E033 ne « réinvente » donc pas l'activation native : il la **garantit explicitement**, la **documente** (ARIA + indice visible), fournit un **repli** pour une cellule devenue non native (ex. `div role=gridcell` après E044 — un rôle ARIA ne produit aucun clic), et le tout **sans double déclenchement** ni modification des gestionnaires `click` existants.

## E033-01 — Écouteur clavier délégué unique sur la matrice

- **Preuve** : l'invariant d'en-tête `E033.js:16-17` pose « un seul écouteur keydown DÉLÉGUÉ, attaché à `.points-grid` (jamais un par cellule) ». L'état module ne retient qu'une seule référence de grille écoutée, `currentGrid` (`E033.js:78`). Le gestionnaire `onGridKeyDown` (`E033.js:129-159`) est une référence de fonction stable, attachée une seule fois par rendu (`E033.js:228-230`) et détachée de l'ancienne grille (`E033.js:227`).
- **Solution** : délégation sur le conteneur `.points-grid` plutôt qu'un `addEventListener` par cellule. Le coût est constant quel que soit le nombre de cellules (784 au maximum), et l'écouteur suit le cycle de vie du nœud rendu.
- **Impact** : aucun écouteur multiplié, aucune fuite sur les nombreux rendus que provoquent les filtres ; le parcours clavier de la matrice reste fluide.
- **Effort** : S
- **Vérification** : relecture — un seul `addEventListener('keydown', …)` dans le module (`:229`) et un seul `removeEventListener` (`:227`) ; aucun `addEventListener` dans une boucle sur les cellules.

## E033-02 — Ciblage cellule / ère par `closest`, sans toucher aux filtres

- **Preuve** : `CELL_SELECTOR = '.points-cell, .points-era'` (`E033.js:40`) et `targetCell()` (`:91-95`) utilisent `node.closest(CELL_SELECTOR)`. Le garde `E033.js:136-137` exige que la cellule trouvée appartienne bien à `currentGrid`. Les sélecteurs de `points.js` sont respectés : `.points-cell` (`:46`), `.points-era` (`:40`) ; les `<select>`, le bouton « Réinitialiser les filtres » et `.points-nav` (`:60-93`, `:115-122`) ne correspondent pas au sélecteur.
- **Solution** : résolution au moment de l'appui, sur l'élément réellement focalisé ; un éventuel nœud enfant remonte à la cellule, mais aucun contrôle hors matrice ne peut être activé par E033.
- **Impact** : la frappe dans un `<select>` (recherche d'option native) et les boutons de navigation restent strictement sous la responsabilité du navigateur et du routeur.
- **Effort** : S
- **Vérification** : relecture du sélecteur ; harnais : focus sur `select` + Entrée/Espace → aucun compteur E033 incrémenté ; focus sur `.points-cell` + Entrée → compteur +1 ; focus sur `.points-era` + Entrée → compteur +1.

## E033-03 — Reconnaissance de Entrée, Espace et du repli `Spacebar`

- **Preuve** : constantes `ENTER = 'Enter'`, `SPACE = ' '`, `SPACE_LEGACY = 'Spacebar'` (`E033.js:42-44`) et `isActivationKey()` (`:87-89`). Le gestionnaire filtre d'abord la touche (`:134`) puis distingue Entrée des deux variantes d'Espace via `isEnter` (`:139`). Les modificateurs `Ctrl/Meta/Alt` sont rejetés (`:133`), alignés sur `keyboard.js:127`.
- **Solution** : une seule fonction de normalisation, pas de comparaison éparpillée ; le repli `Spacebar` couvre les moteurs anciens (IE/Edge legacy) sans coût.
- **Impact** : l'activation clavier fonctionne avec la touche Espace quelle que soit la valeur `event.key` rapportée, sans detourner les combinaisons navigateur.
- **Effort** : S
- **Vérification** : relecture de `isActivationKey()` et de la garde modificateurs ; harnais : `key=' '` et `key='Spacebar'` → même traitement ; `key='Enter'` → traitement Entrée ; `key='a'` → aucun effet.

## E033-04 — Aucun double déclenchement sur un bouton natif

- **Preuve** : commentaire `E033.js:101-103` et `nativeModes()` (`:104-112`) : `button`/`summary` → `{enter:true, space:true}`, `a[href]` → `{enter:true, space:false}`, champs de formulaire → natifs. La branche de non-ingérence est `E033.js:143-149` : si le mode natif couvre la touche, on écrit les métriques puis on `return` **sans appeler `click()` ni `preventDefault()`**. Le routeur (`keyboard.js:131-132`) quitte déjà son handler pour les contrôles (`isControl` inclut `BUTTON`, `keyboard.js:66-73`), donc aucun `toggleDetail()` parasite.
- **Solution** : distinguer le mode d'activation natif du mode « à synthétiser ». Sur un `<button>`, le navigateur émet seul le `click` (Entrée en keydown, Espace en keyup) : E033 s'abstient, ce qui évite le double `set()`/`selectEra()`.
- **Impact** : une seule sélection d'ère / un seul filtrage par appui ; le comportement natif des boutons reste intact pour les technologies d'assistance.
- **Effort** : M
- **Vérification** : relecture de `nativeModes()` et de la branche `:143-149` ; harnais : un appui Entrée sur une cellule `<button>` déclenche exactement un `click` (un seul passage dans le handler de `points.js:49-53`) ; le compteur « Clics synthétisés » reste à 0.

## E033-05 — Repli explicite pour une cellule non native

- **Preuve** : branche `E033.js:151-158`. Quand `nativeModes()` renvoie `{enter:false, space:false}` (cas d'un `<div role="gridcell" tabindex="0">`, rôle ARIA sans activation native), E033 appelle `cell.click()` (`:154-156`), incrémente `syntheticCount` (`:156`) et neutralise le défilement d'Espace par `event.preventDefault()` (`:153`). Le commentaire `:151-152` documente ce choix.
- **Solution** : converger vers le **même** `click` que la souris, donc vers les mêmes gestionnaires de `points.js`, au lieu de réimplémenter `selectEra`/filtrage. `preventDefault()` n'est posé que sur Espace, là où un `div` ferait défiler la page.
- **Impact** : si une lentille de grille (E044) convertit les cellules en `role=gridcell`, l'activation clavier ne régresse pas ; le geste clavier et le geste souris restent équivalents.
- **Effort** : M
- **Vérification** : relecture de la branche de repli ; harnais : remplacer une cellule par `<div role=gridcell tabindex=0>` avec le même handler `click` → Entrée et Espace appellent le handler une fois chacun, sans défilement ; « Clics synthétisés » passe à 2.

## E033-06 — Non destructif : gestionnaires `click` et nœuds préservés

- **Preuve** : invariants `E033.js:25-33` (« préservation intégrale des gestionnaires click existants », « les nœuds de points.js ne sont jamais retirés ni réécrits »). Aucun `removeEventListener` sur une cellule, aucun `replaceChildren` sur la grille, aucune modification de `title`, `textContent` ou `className` des cellules. Seuls des attributs absents sont ajoutés : `aria-keyshortcuts` (`:182`) et `aria-describedby` (`:186`), tous deux gardés par `hasAttribute`.
- **Solution** : E033 est un greffon purement additif sur la couche clavier. Il n'écrit aucune logique métier : l'activation, qu'elle soit native ou synthétisée, finit toujours dans le `click` existant de `points.js`.
- **Impact** : aucune régression des filtres, de la sélection d'ère ou de la navigation entre points ; coexistence sans conflit avec E031–E032 (tabulation / flèches) et E044 (sémantique de grille).
- **Effort** : S
- **Vérification** : relecture — absence de `removeEventListener` hors grille, absence d'écriture de `textContent`/`className` sur `.points-cell` ; rejeu : clic souris et appui clavier produisent le même état de l'URL/du store.

## E033-07 — Compteurs auditables dérivés du DOM rendu

- **Preuve** : `writeMetrics()` (`E033.js:114-123`) affiche « Activations clavier : N · Clics synthétisés : N. » dans `p.points-e033-metrics` (créé en `:220-223`, rempli en `:117`), et écrit les miroirs `layout.dataset.pointsE033Activations` / `pointsE033Synthetic` (`:120-121`). Les compteurs sont incrémentés sur une intention réelle (`:141`) et sur un clic effectivement synthétisé (`:156`), jamais à chaque rendu. Le nombre de cellules est lu dans le DOM (`:180`, `:213`).
- **Solution** : aucune valeur historique codée en dur ; tout est recalculé depuis l'événement clavier et le DOM courant. Les métriques sont hors région live, donc sans annonce bavarde (E041 reste maître des annonces).
- **Impact** : on distingue « greffon muet » de « aucune activation tentée » ; la trace est vérifiable dans le DOM, sans `console.*` ni instrumentation réseau.
- **Effort** : M
- **Vérification** : relecture de `writeMetrics()` ; rejeu : trois appuis sur une cellule native → « Activations clavier : 3 · Clics synthétisés : 0. » ; un appui sur une cellule div → « 4 · 1. »

## E033-08 — Découvrabilité ARIA et indice visible

- **Preuve** : `ensureHint()` (`E033.js:161-174`) crée un unique `<p id=points-e033-hint>` de texte « Clavier : tabulez jusqu'à une cellule, puis Entrée ou Espace pour l'activer. » dans `.points-matrix`. `markCells()` (`:176-189`) pose `aria-keyshortcuts="Enter Space"` sur les cellules/ères qui n'en ont pas (`:182`) et relie la grille à l'indice par `aria-describedby` (`:185-187`). La feuille (`:60-62`) renforce le `:focus-visible` des cellules.
- **Solution** : rendre l'activation explicite aux lecteurs d'écran (ARIA) et aux utilisateurs sighted (indice), sans nouvelle touche réservée ni écouteur supplémentaire. Tous les ajouts sont conditionnels : aucun attribut existant n'est écrasé.
- **Impact** : l'action clavier est documentée au point d'usage ; le focus reste visible sur la cellule activée, ce qui confirme visuellement l'activation.
- **Effort** : S
- **Vérification** : relecture de `ensureHint()` / `markCells()` ; relecture ARIA — `aria-keyshortcuts="Enter Space"` valide, `aria-describedby` pointe vers un id existant, aucun `aria-label` dupliqué ; capture 390×844 sans débordement.

- **Impact** : l'aspect reste lisible en 390×844 et sous préférences de mouvement/contraste renforcées, sans fuite de style hors de la vue Points.

## E033-10 — Idempotence multi-rendus et garde-fous d'exécution

- **Preuve** : `apply()` (`E033.js:191-234`) garde `viewId === 'points'` (`:193`), un `layout` connecté (`:194-197`) et un `ctx` minimal (`:192`). Un rendu neuf change de `.points-grid` : l'ancien écouteur est détaché (`:227`), le nouveau attaché (`:228-231`), et l'indice/les métriques mal parentés sont déplacés sans duplication (`:165-166`, `:216-223`). Les miroirs `pointsE033` / `pointsE033Render` (`:204-205`) exposent l'état. `register('E033', …)` (`:236-242`) enveloppe l'appel dans un `try/catch` : une lentille défaillante est neutralisée sans interrompre le rendu (contrat `registry.js:39-43`).
- **Solution** : une seule feuille, un seul indice, un seul bloc de métriques et un seul écouteur délégué par rendu, avec détachement explicite ; la référence de handler reste stable d'un rendu à l'autre.
- **Impact** : pas de doublon après navigation, pas de fuite d'écouteur, pas d'exception remontée au registre ; le module reste robuste même avec un `ctx` partiel.
- **Effort** : M
- **Vérification** : `node --check src/views/points/E033.js` PASS ; relecture — un seul `addEventListener`, zéro `MutationObserver`/rAF/timer ; rendu → changement de filtre → rendu : un seul `#points-e033-hint`, un seul `#points-e033-metrics`, un seul écouteur, compteurs cohérents.

## Blocages / limites inter-domaines

- Sur les cellules `<button>` natives (cas actuel de `points.js:46`), l'activation est déjà produite par le navigateur : E033 ne synthétise aucun clic et se limite à garantir, documenter et mesurer. Le repli `cell.click()` ne s'active que si une autre lentille (ex. E044) retire la sémantique de bouton natif.
- Le routeur (`keyboard.js`) reste maître de Entrée/Espace hors contrôle : E033 s'appuie sur le fait qu'il ignore ces touches quand la cible est un contrôle (`keyboard.js:131-132`, `isControl` inclut `BUTTON` et tout `[tabindex]≠-1`). Si ce contrat changeait, la branche de repli devrait être réévaluée.
- Aucune annonce live n'est émise par E033 : les changements d'ère/filtre sont déjà annoncés par le store et E041. Ajouter une région live propre provoquerait des annonces doubles — E033 s'en abstient volontairement.
- Les miroirs `layout.dataset.pointsE033*` et les attributs `aria-keyshortcuts` / `aria-describedby` sont écrits par E033 ; toute autre lentille réécrivant ces mêmes attributs devra les préserver (les ajouts sont conditionnels, donc sans écrasement d'un attribut déjà présent).
- La grille `.points-grid` est produite par `points.js` : si son sélecteur changeait, le ciblage (`E033.js:40`, `:210`) devrait être mis à jour ; le greffon n'échouerait pas (garde `:137`), il deviendrait simplement muet.
