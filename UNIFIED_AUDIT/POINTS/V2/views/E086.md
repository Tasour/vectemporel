## E086-01 — Contrat d'entrée du greffon non vérifié : échec silencieux possible

- **Problème / preuve** : `points/v2/registry.js:28-37` fabrique l'API passée aux greffons (`css`, `el`, `reducedMotion`) en étalant `ctx`, puis `:39-42` applique chaque greffon dans un `try/catch` qui neutralise les erreurs (`:41`). Rien ne garantit en amont que `viewId`, `stage` et `layout` existent ni que les helpers soient des fonctions. Le stub initial (quatre lignes utiles) n'exerçait aucun contrôle : un greffon présupposant le contrat pouvait être neutralisé sans que l'utilisateur ne voie rien.
- **Solution** : `E086.js:179-185` vérifie `viewId === 'pointsv2'`, la présence de `stage` et `layout`, et le type des trois helpers ; `:208` publie le résultat ; `:231-236` ajoute des gardes défensives avant tout travail et ne compte le rendu que lorsque le contrat est exploitable. Le filtre strict sur `'pointsv2'` (`:232`) distingue la V2 de la passe 1, qui filtrait sur `'points'`.
- **Impact** : une dérive du contrat devient visible dans le panneau au lieu d'être absorbée par le registre, sans modifier `registry.js`.
- **Risque** : le contrôle décrit le contrat courant, il ne le répare pas. Si le registre change de nom de helper, la ligne passe en « À VÉRIFIER » et la relecture du module est nécessaire.
- **Effort** : S.
- **Vérification** : harnais — rendu nominal : ligne 01 « CONFORME », `data-points-v2-e086-ok="10"` ; rendu avec `stage` absent : ligne 01 « À VÉRIFIER », `data-points-v2-e086-warn ≥ 1`. `node --check` inchangé (PASS).

## E086-02 — Aucune mesure du nombre réel de feuilles CSS du greffon

- **Problème / preuve** : `points/v2/registry.js:13-19` (`cssOnce`) protège l'insertion d'une feuille par son identifiant, et `:39-42` rejoue les greffons à chaque rendu. Le registre garantit l'unicité du `<style>` mais n'expose aucun compteur : une seconde feuille portant le même identifiant, introduite ailleurs, resterait invisible. Le stub initial n'injectait aucune feuille.
- **Solution** : `E086.js:34` fixe `CSS_ID = 'points-v2-e086'`, `:69-133` définit l'unique chaîne CSS, `:240` est le seul appel d'injection ; `:187` compte les `<style id="points-v2-e086">` réels, `:209` écrit la ligne, `:286` publie `data-points-v2-e086-css-count`, `:217` rappelle le compte dans le contrôle d'idempotence. Aucun identifiant de la passe 1 (`points-e086`) n'est réutilisé.
- **Impact** : l'unicité de la feuille devient une mesure observable et non une hypothèse sur le comportement du registre.
- **Risque** : le comptage porte sur le document entier ; une feuille homonyme injectée par un autre acteur déclencherait une alerte légitime mais hors du périmètre de cette lentille.
- **Effort** : S.
- **Vérification** : harnais — `1 feuille « points-v2-e086 » dans le document`, `data-points-v2-e086-css-count="1"` ; relecture : une seule occurrence de l'appel d'injection (`E086.js:240`), un seul `CSS_ID` (`:34`).

## E086-03 — Identifiants du greffon : unicité non contrôlée après re-render

- **Problème / preuve** : `points/v2/registry.js:21-26` crée les nœuds sans identifiant, `:39-42` rejoue les greffons, et `_diagnostics.js:81-103` déplace les panneaux dans un tiroir puis les restitue. Sans garde, deux rendus pouvaient laisser coexister deux nœuds portant le même ID, avec des sélecteurs CSS ambigus et un `getElementById` qui n'en voit qu'un.
- **Solution** : `E086.js:38-49` énumère seize identifiants possédés (six de structure, dix de ligne) ; `:140-148` fournit `ensureNode` avec réutilisation par `getElementById` et déplacement dans le parent courant, jamais de clonage ; `:188` vérifie que chaque ID apparaît exactement une fois, `:210` l'écrit, `:245` et `:262` utilisent la garde pour le panneau et les lignes. `panel.replaceChildren` (`:268`) et `list.replaceChildren` (`:269`) reconstruisent uniquement le panneau possédé.
- **Impact** : aucun doublon d'ID après navigation aller-retour ; le CSS reste adressable sans ambiguïté.
- **Risque** : un nœud retrouvé est déplacé, jamais cloné (`E086.js:146`) ; ses attributs sont réécrits à chaque rendu (`:283-290`), donc jamais périmés. Le contrôle couvre uniquement les seize ID possédés, pas ceux du reste de la vue.
- **Effort** : M.
- **Vérification** : harnais — `16/16 identifiants uniques` au premier rendu ; deux rendus successifs → un seul `#points-v2-e086-audit`, un seul `<style id="points-v2-e086">` ; relecture : aucune concaténation d'ID ailleurs que dans `OWNED_IDS` (`:49`).

## E086-04 — Espace de noms des identifiants : préfixation non prouvée

- **Problème / preuve** : `points/v2/registry.js:9-11` accepte n'importe quelle chaîne comme identifiant de greffon et `:21-26` n'impose aucun préfixe aux nœuds créés. Le risque n'est pas ici la duplication (chantier 03) mais la collision avec un ID générique d'une autre lentille, avec la passe 1 (`points-e086-*`) ou avec un ID de la coque : un ID `check-01` non qualifié pourrait être retrouvé par un greffon voisin.
- **Solution** : `E086.js:36` déclare `PREFIX = 'points-v2-e086-'` ; `:47-48` en dérive les dix ID de ligne, `:38-44` porte le préfixe sur les six ID de structure ; `:189` teste la préfixation de chaque ID, `:211` publie `16/16 identifiants préfixés points-v2-e086-` ; les sélecteurs CSS sont tous ancrés sur `.points-v2-e086` (`:69-133`). Les attributs de suivi sont eux aussi préfixés `data-points-v2-e086-*` (`:154-157`), distincts des `data-points-e086*` de la passe 1.
- **Impact** : l'appartenance de chaque nœud à la lentille V2 est explicite et vérifiable, sans toucher au registre ni écraser la passe 1.
- **Risque** : le test est statique sur la liste déclarée (`:49`) ; un futur nœud créé sans passer par `CHECK_IDS` ou `OWNED_IDS` échapperait au contrôle — d'où la consigne de dériver tout nouvel ID du `PREFIX`.
- **Effort** : S.
- **Vérification** : relecture — zéro ID littéral non préfixé dans `E086.js` ; harnais — ligne 04 « CONFORME · 16/16 identifiants préfixés points-v2-e086- ».

## E086-05 — Feuille CSS injectée sans filtre d'hygiène

- **Problème / preuve** : `points/v2/registry.js:13-19` recopie `rules` textuellement dans `style.textContent` (`:17`) sans filtrer son contenu. Une priorité forcée, un import distant, une URL réseau ou un panneau à position fixe dans la feuille d'une lentille auraient franchi ce point sans contrôle, alors que le cahier des charges V2 impose zéro réseau et un bloc en flux.
- **Solution** : `E086.js:69-133` est une feuille sans directive interdite, en blocs en flux, dont **chaque** sélecteur commence par `.points-v2-e086` (y compris dans les `@media` `:124`, `:127`, `:130`), avec replis `620px` (`:124-126`), `prefers-reduced-motion` (`:127-129`) et `forced-colors` (`:130-136`) ; `:190-191` applique à cette même chaîne `CSS` un filtre sur les directives proscrites (`!important`, `@import`, `url(http…)`, `position: fixed`) ; `:212` publie le résultat ; `:66-68` documente l'intention.
- **Impact** : la règle d'hygiène est autovérifiée au moment de l'injection, pas seulement relue à la main, et la portée CSS ne peut pas fuir hors de la vue Points ni recouvrir la feuille `points-e086` de la passe 1.
- **Risque** : le filtre ne porte que sur la chaîne possédée ; il ne contrôle ni `styles.css` ni les feuilles des autres lentilles. Un motif légitime ressemblant à une URL distante dans une future règle exigerait de réviser le filtre.
- **Effort** : M.
- **Vérification** : relecture croisée `E086.js:69-133` ↔ filtre `:190-191` ; harnais — ligne 05 « aucune priorité forcée, import, URL distante ou position fixe » ; recherche de motifs distants dans la feuille injectée : aucun résultat.

## E086-06 — Ressources actives distantes non détectées

- **Problème / preuve** : `points/v2/registry.js:28-37` fournit les helpers sans inspecter le document, et `:39-42` ne vérifie rien après coup. La passe 1 (`UNIFIED_AUDIT/POINTS/views/E086.md:3`) pose l'invariant « zéro réseau » comme exigence de qualité, mais aucun mécanisme ne signale une ressource active distante apparue dans le DOM au fil des rendus.
- **Solution** : `E086.js:195-199` assemble les sélecteurs d'images, scripts, iframes et feuilles de style distantes à partir des schémas ; `:213` écrit le nombre trouvé. Les schémas sont assemblés (`:195`) plutôt qu'écrits littéralement, pour ne pas introduire d'URL distante dans le module lui-même. Le module ne contient aucun appel réseau : ni `fetch`, ni `XMLHttpRequest`, ni `src` distant.
- **Impact** : toute dérive « zéro réseau » devient mesurable dans le panneau sans intercepter la charge d'une page.
- **Risque** : seules les ressources *actives* chargées par le navigateur sont comptées ; un simple lien de citation `href` externe, autorisé par ailleurs, n'est pas un chargement et n'est donc pas signalé. Le contrôle est instantané, pas continu : aucun observateur n'est installé.
- **Effort** : M.
- **Vérification** : harnais — ligne 06 « 0 ressource active distante dans le document » ; contrôle statique du module : zéro appel réseau, zéro `XHR`, zéro URL distante littérale.

## E086-07 — Structure sémantique (main / h1) non vérifiée

- **Problème / preuve** : `points/v2/registry.js:28-37` transmet `layout` sans garantir la présence d'un `<main>` unique ni d'un `<h1>` ; `:21-26` peut créer n'importe quelle balise. Une lentille qui ajouterait un second `<main>` ou un titre de niveau 1 concurrent dégraderait l'indexation et l'ordre de lecture, sans qu'aucun contrôle du registre ne le signale.
- **Solution** : `E086.js:201-202` compte `<main>` et `<h1>` dans le document, `:214` publie le résultat ; `:249` crée volontairement un `<h2>` pour le titre du panneau et `:255` une liste ordonnée, afin de ne pas concurrencer le titre principal ; `:246-247` relie le panneau à ce titre par `aria-labelledby`. Le panneau est un `role="region"` (`:246`), jamais une modale.
- **Impact** : la structure sémantique de la vue devient auditable et le panneau ne l'altère pas.
- **Risque** : le comptage est global au document. Si une autre lentille introduit un second `<main>`, l'alerte est juste mais sa correction relève du maître d'œuvre, pas de cette lentille. Le module n'écrit dans aucune région live, conformément au choix de silence au montage.
- **Effort** : S.
- **Vérification** : harnais — ligne 07 « 1 élément &lt;main&gt; · 1 titre(s) &lt;h1&gt; » ; relecture — un seul `make('h2', …)` (`:249`), aucun `role="status"` ni `aria-live` dans le module.

## E086-08 — État des contrôles non garanti hors couleur seule

- **Problème / preuve** : le CSS du panneau distingue les états par la couleur de bordure et de texte (`E086.js:94-98`, `:109-113`), ce qui ne suffit pas : sans marqueur textuel et sans forme distincte, un daltonien ou une technologie d'assistance ne peut pas distinguer « CONFORME » de « À VÉRIFIER ». La passe 1 pose la même exigence (« état textuel, jamais la seule couleur », `UNIFIED_AUDIT/POINTS/views/E086.md:29-35`).
- **Solution** : `E086.js:169-175` centralise l'écriture : `appliquer` pose toujours `data-points-v2-e086-state` et le libellé `[v] CONFORME` ou `[!] À VÉRIFIER` ensemble ; `:221-228` (`secondePasse`) relit le DOM *après* écriture et vérifie les dix lignes ; `:271-277` applique les neuf premiers contrôles, puis recalcule et réapplique le huitième. Le CSS ajoute bordure pleine contre bordure en pointillés (`:94-98`) et soulignement pointillé (`:109-113`), avec repli `forced-colors` (`:130-136`) et focus visible (`:117-119`).
- **Impact** : l'état de chaque contrôle est lisible par le texte, par la forme et par l'attribut, sans dépendre de la teinte.
- **Risque** : le contrôle est auto-référentiel par construction : il garantit la cohérence interne du panneau, pas le contraste mesuré des couleurs — celui-ci reste à auditer par un outil dédié (limite inter-domaines).
- **Effort** : M.
- **Vérification** : harnais — ligne 08 « 10/10 lignes avec état textuel et marqueur », dix `data-points-v2-e086-state` présents ; relecture — l'ordre `:271-277` garantit que `secondePasse` s'exécute après la première écriture.

## E086-09 — Préférence de mouvement réduit non publiée

- **Problème / preuve** : `points/v2/registry.js:33-36` expose `reducedMotion` via `matchMedia` dans un `try/catch`, mais ni le registre ni le stub initial ne publient l'état de la préférence. La passe 1 traite le même sujet (`UNIFIED_AUDIT/POINTS/views/E086.md:69-75`) et exige un miroir d'état de mouvement.
- **Solution** : `E086.js:203-204` lit le helper et exige la présence du repli CSS ; `:127-129` neutralise l'unique transition du panneau en `prefers-reduced-motion` ; `:216` décrit l'état dans la ligne, `:281` le répète dans le bilan, `:290` publie `data-points-v2-e086-reduced`. Aucune animation n'est créée ailleurs ; le panneau reste silencieux au montage.
- **Impact** : la préférence est traçable et le peu de mouvement introduit par la lentille est neutralisé.
- **Risque** : si `matchMedia` lève une exception, le registre renvoie `false` (`registry.js:35`) : la ligne indique « mouvement réduit : non » alors que le réglage système peut être actif. Ce repli est hérité du contrat, non modifiable ici.
- **Effort** : S.
- **Vérification** : relecture — une seule `transition` dans la feuille (`:115`), neutralisée (`:128`) ; harnais — `data-points-v2-e086-reduced="0"` avec le helper à `false`, bascule à `true` → libellé « oui » et ligne 09 toujours conforme.

## E086-10 — Idempotence multi-rendus non démontrée

- **Problème / preuve** : `points/v2/registry.js:39-42` rejoue tous les greffons à chaque rendu et `:13-19` ne protège que l'unicité du style ; `_diagnostics.js:81-103` déplace et restitue les panneaux. Le stub initial, sans nœud ni état, ne pouvait pas prouver qu'il restait un seul panneau après navigation.
- **Solution** : `E086.js:135` maintient un compteur de rendus module ; `:231-239` borne l'entrée, `:239` l'incrémente ; `:245` réutilise le panneau via `ensureNode` ; `:268-269` remplace les enfants plutôt que de les accumuler ; `:205` et `:217` comparent panneaux, feuilles et rendus ; `:283-285` publient `data-points-v2-e086-renders`, `data-points-v2-e086-ok` et `data-points-v2-e086-warn`. L'ancrage dans `.points-matrix` (`:244`) empêche le marquage diagnostic du panneau au rendu suivant.
- **Impact** : un rendu répété ne crée ni doublon de panneau, ni fuite de nœud, et le bilan reste exact ; le panneau reste visible hors mode diagnostic.
- **Risque** : le compteur survit aux rendus mais est réinitialisé au rechargement complet de la page ; c'est le comportement attendu d'un greffon sans état persistant. Le registre neutraliserait silencieusement une erreur (`registry.js:41`) : `node --check` et le harnais restent la première ligne de défense, d'où le `try/catch` local (`:295-298`).
- **Effort** : M.
- **Vérification** : harnais — deux exécutions du greffon → un seul panneau, une seule feuille, `data-points-v2-e086-renders="2"` et `rendus : 2 · panneaux : 1 · feuilles : 1` ; `node --check src/views/points/v2/E086.js` → PASS.

## Blocages / limites inter-domaines

- `points/v2/registry.js` (`:9-11`, `:13-19`, `:28-42`) et `index.js` ne sont pas modifiables : la lentille ne peut pas durcir le contrat d'entrée, filtrer les feuilles CSS des autres greffons ni empêcher le `try/catch` qui neutralise silencieusement une erreur.
- Les contrôles E086-06 et E086-07 sont des instantanés : sans observateur ni timer, ils ne détectent pas une ressource distante ou un second `<main>` apparu entre deux rendus. Une surveillance continue relèverait d'une lentille dédiée du domaine G.
- E086-08 valide la cohérence interne du panneau, pas le contraste réel des couleurs ni le rendu sous `forced-colors` : la mesure de contraste relève du domaine E (E047) et la relecture visuelle des captures du domaine H.
- Le contrôle de structure (E086-07) porte sur le document entier : une anomalie causée par une autre lentille serait signalée ici mais ne pourrait pas être corrigée dans ce module.
- Le repli de `reducedMotion` (`registry.js:33-36`) renvoie `false` si `matchMedia` échoue ; la lentille ne peut pas distinguer ce cas d'une préférence réellement absente.
- La passe 1 (`points-e086-*`, `data-points-e086*`) et la V2 (`points-v2-e086-*`, `data-points-v2-e086-*`) coexistent sans collision ; la V2 n'écrit aucun de ces identifiants sur les enfants directs de `.points-layout`, pour échapper au marquage `_diagnostics.js:69-78`.
- Aucune synthèse n'est produite : ce rapport ne fait que documenter ses dix chantiers, conformément à la consigne de périmètre.
