# E052 — Aucune date codée en dur (passe V2, vue Points)

Lentille E052 — domaine F : sémantique & données, passe V2 de la vue Points. Thème unique : « aucune date codée en dur », décliné en dix chantiers non chevauchants, E052-01 à E052-10, tous observables dans le DOM rendu ou dans la feuille de style injectée. Fichier possédé : `src/views/points/v2/E052.js` uniquement (module `E052`, identifiant de registre `E052`, déjà importé par `src/views/points/v2/index.js:52`). Lectures seules : `src/views/points/E052.js` et `UNIFIED_AUDIT/POINTS/views/E052.md` (passe 1), `src/views/points.js` (DOM rendu), `src/views/points/v2/registry.js` (contrat `ctx`). La passe 1, la vue, les autres lentilles, les registres et le CSS global ne sont ni édités ni doublés.

Contrat respecté : module ESM avec un seul `import { register } from './registry.js';` (`E052.js:1`) et un seul `register('E052', (ctx) => { … });` (`E052.js:551`) ; `ctx = { viewId:'pointsv2', stage, layout }` enrichi de `css` / `el` / `reducedMotion` (`v2/registry.js:28-37`) ; une seule feuille `ctx.css('points-v2-e052', …)` (`E052.js:35`, `:486`). Tous les IDs DOM sont préfixés `points-v2-e052-` (`:38-52`) avec garde d'existence `assurerNoeud` (`:144-153`) ; tous les sélecteurs CSS commencent par `.points-v2-e052` (`:66-125`, hors at-rules `@media`). Toute création de nœud passe par `ctx.el` (`:472-477`) : zéro réinterprétation de balisage. Zéro journalisation, zéro appel réseau, zéro aléa, zéro minuteur, zéro boucle d'animation, zéro écouteur. Français partout (commentaires, libellés, valeurs de dataset).

Le principe directeur : **aucun millésime littéral ne traverse le module**. Chaque nombre est lu dans le DOM produit par `points.js` (`.points-title`, `.view-kicker`, `.points-meta > span`, `.points-cell.has-points`, `.points-era`) ou dérivé par calcul. Les seules constantes numériques du fichier sont la graine de hachage `5381`, la mention normative « ISO 8601 » dans deux commentaires, et des valeurs de mise en forme CSS (tailles, opacités) — aucune n'est une année. Quand la donnée manque, le panneau le declare explicitement au lieu d'en inventer une.

## E052-01 — Porteuses de date et de nombre recensées depuis le DOM

- **Problème / preuve** : `points.js:33` rend le total dans `.points-title`, `:97` le périmètre dans `.view-kicker`, `:105` le `time` du point comme 3e span de `.points-meta`, et `:47` un compte par case `.points-cell.has-points`. Ces sources coexistent sans vue d'ensemble : rien n'atteste que chaque nombre affiché remonte au DOM et qu'aucun n'a été écrit « en dur » par un greffon. Le registre V2 réjoue les greffons à chaque rendu (`registry.js:39-42`), ce qui rend le recensement nécessaire.
- **Solution** : `lire()` (`E052.js:216-243`) collecte les cinq familles ; `chantierInventaire()` (`:244-263`) écrit une liste visible ventilée (titre, kicker, champ `time`, cases, ères) et publie `data-e052-porteuses` et `data-e052-annees` (`:261-262`). Le greffon ne produit aucun nombre propre.
- **Impact** : le nombre exact de porteuses devient lisible et falsifiable avant toute intervention ; le panneau ne revendique aucune valeur qui ne soit pas dans le DOM.
- **Risque** : le recensement dépend des sélecteurs de `points.js` ; une refonte des classes `points-cell` / `points-meta` le rendrait muet. Le panneau afficherait alors zéro — signal attendu, pas une valeur de repli.
- **Effort** : M.
- **Vérification** : relecture `E052.js:216-263` ↔ `points.js:33, 47, 97, 105` ; harnais — comparer `data-e052-porteuses` au nombre réel de millésimes + compteurs + cases et `data-e052-annees` au nombre de millésimes extraits de l'ancre.

## E052-02 — Provenance déclarée de chaque valeur

- **Problème / preuve** : un nombre peut être « correct » visuellement sans que son origine soit vérifiable. La passe 1 publie seulement `data-points-e052-anchor` sur `.points-detail` : elle n'étiquette pas chaque nœud source. Un greffon pourrait recopier un millésime observé puis le figer sans que rien ne le distingue d'une valeur dérivée.
- **Solution** : `chantierProvenance()` (`E052.js:265-287`) étiquette chaque nœud : `data-e052-source` vaut `.points-meta > span:nth-child(3)` pour le champ temps, `.points-title` pour le total, `.points-detail .view-kicker` pour le périmètre et `.points-cell.has-points` pour les cases (`:266-271`). Une légende visible mappe chaque source à son rôle (`:272-279`) et `data-e052-etiquetes` est publié (`:285-286`).
- **Impact** : chaque valeur du panneau peut être remontée à son sélecteur d'origine ; l'absence de source devient détectable plutôt que silencieuse.
- **Risque** : les écritures `dataset` touchent des nœuds appartenant à la vue, mais n'en modifient ni le texte ni le comportement ; aucun sélecteur de test n'est renommé.
- **Effort** : M.
- **Vérification** : relecture — zéro millésime littéral dans le module ; harnais — le 3e span porte `data-e052-source="…nth-child(3)"`, le titre et le kicker portent leur sélecteur, chaque case porte `data-e052-source=".points-cell.has-points"`.

## E052-03 — Forme brute → forme lisible dérivée du signe

- **Problème / preuve** : les `time` du jeu sont tantôt simples (`1603`), négatifs (`-753`), tantôt des intervalles (`962/1517`, `1492-1610`). Un greffon qui réimplémenterait le formatage pourrait être tenté d'ancrer l'affichage sur une année de référence écrite en dur — exactement l'erreur E052.
- **Solution** : `anneesDe()` (`E052.js:160-179`) isole les composantes d'une ancre en distinguant le signe négatif en tête de composante du tiret d'intervalle ; `formatAnnee()` (`:181-186`) ne dépend que du signe de sa valeur. `chantierFormat()` (`:288-309`) annote le span de `data-e052-brut` et `data-e052-forme` (`:291-292`) et affiche la dérivation « brut → forme » (`:295-299`), avec un libellé explicite quand il n'y a rien à formater (`:300-303`).
- **Impact** : la chaîne `valeur DOM → forme lisible` est documentée en place ; changer le `time` du point change immédiatement la forme affichée, sans seuil ni borne codé.
- **Risque** : un tiret entre deux nombres est interprété comme intervalle, un signe négatif uniquement en tête de composante ; cette convention est documentée et ne fabrique aucune borne absente du DOM. L'échantillon visuel est plafonné à huit formes (`:295`) mais le compteur porte sur toutes les années lues.
- **Effort** : S.
- **Vérification** : relecture `E052.js:160-186, 288-309` ; harnais — une ancre `-753` donne « 753 av. J.-C. », `1492-1610` donne deux formes positives, une ancre vide donne le libellé de repli ; modifier `data-e052-brut` puis vérifier que `data-e052-forme` suit.

## E052-04 — Ordre d'affichage des ères lu dans la matrice

- **Problème / preuve** : `points.js:39-58` énumère les ères dans l'ordre du jeu (`country.eras.forEach`). Un greffon qui voudrait « aider » en inscrivant un ordre figé de noms d'ères introduirait des données implicites : l'ordre deviendrait une donnée codée en dur.
- **Solution** : `chantierOrdre()` (`E052.js:310-328`) rend une `<ol>` dont chaque rang est recalculé depuis la position réelle du `.points-era` dans la matrice (`:313-317`), marque l'ère affichée par `aria-current` implicite dans le texte (`:315`) et publie `data-e052-position` par ère (`:316`) et `data-e052-ordonnees` (`:326`).
- **Impact** : l'ordre visible est une fonction du DOM, jamais une assertion ; l'ajout ou le retrait d'une ère se reflète immédiatement dans la liste et le compteur.
- **Risque** : l'ère courante est relue via `.points-grid-row.is-active`, signal déjà posé par la vue : la lentille ne décide pas elle-même quelle ère est affichée et ne duplique pas la logique du magasin.
- **Effort** : M.
- **Vérification** : relecture `E052.js:310-328` ↔ `points.js:39-58` ; harnais — deux puis trois lignes d'ères donnent deux puis trois `<li>`, rangs renumérotés, `data-e052-ordonnees` cohérent.

## E052-05 — Échelle des millésimes calculée par soustraction

- **Problème / preuve** : les bornes d'une ancre sont des valeurs dérivées ; écrire « 118 ans » en dur dans un panneau serait une durée déguisée en mesure. La passe 1 affiche l'ancre mais ne calcule aucune amplitude.
- **Solution** : `chantierEchelle()` (`E052.js:329-349`) calcule `min` et `max` par `Math.min` / `Math.max` sur les années lues (`:332-333`), affiche l'amplitude `max - min` et les écarts consécutifs (`:334-337`), et publie `data-e052-amplitude` (`:345-346`). Aucune durée n'est littérale.
- **Impact** : toute grandeur temporelle affichée est une soustraction de valeurs DOM, retracable et recalculable.
- **Risque** : un écart négatif est possible si l'ordre des composantes de l'ancre est décroissant ; il est affiché tel quel, sans correction arbitraire — le panneau décrit, il ne réécrit pas la donnée.
- **Effort** : M.
- **Vérification** : relecture `E052.js:329-349` ; harnais — recalculer l'amplitude à la main depuis l'ancre et la comparer au texte et à `data-e052-amplitude`.

## E052-06 — Horodatages `<time datetime>` dérivés de l'ancre

- **Problème / preuve** : `points.js:105` rend le temps dans un `<span>` : c'est un texte lisible par l'humain, mais pas une date machine. Sans `datetime`, un outil ne peut pas distinguer une année calculée d'un millésime saisi à la main.
- **Solution** : `isoAnnee()` (`E052.js:188-193`) convertit chaque année lue en année astronomique ISO 8601 (année 1 av. J.-C. = `0000`). `chantierMachine()` (`:350-378`) crée ou réutilise un `<time class="e052-time">` par composante de l'ancre (`:356-360`), pose `dateTime = isoAnnee(n)` (`:361`), le marque `data-e052-source` (`:362`) et en synchronise le texte via `ecrire()` (`:363`).
- **Impact** : la date devient lisible par machine **et** par l'humain, les deux depuis la même source ; aucun `datetime` n'est écrit en dur.
- **Risque** : l'ajout d'un `<time>` dans le span de métadonnée est un effet DOM sur un nœud de la vue ; il est gardé par `querySelector('.e052-time')` (`:356`), donc idempotent, et ne modifie ni le titre ni les gestionnaires de la vue.
- **Effort** : S.
- **Vérification** : relecture `E052.js:188-193, 350-378` ; harnais — chaque `<time>` porte un `datetime` cohérent avec l'ancre lue, et un second rendu ne crée pas de doublon.

## E052-07 — Années orphelines signalées, jamais complétées

- **Problème / preuve** : c'est le cas falsifiable du thème. Si un texte du détail contient un millésime à quatre chiffres sans source dans le DOM, la vue ne le signale pas : l'information semble fiable alors qu'elle n'a pas de source. Une lentille « charitable » pourrait inventer la donnée manquante — exactement l'erreur E052 interdite.
- **Solution** : `chantierOrphelins()` (`E052.js:379-404`) construit l'ensemble des années légitimes depuis l'ancre lue (`:380`), parcourt les nœuds texte du détail via `textes()` (`:195-214`) pour repérer les motifs à quatre chiffres sans source (`:383-389`), publie `data-e052-orphelins` à `1` ou `0` (`:401-402`) et affiche le signalement ou l'absence explicite d'orpheline (`:394-398`). Deux états CSS distincts sont prévus (`:95-97`).
- **Impact** : une date sans source est visiblement signalée au lieu d'être réparée par supposition ; zéro orpheline devient une mesure positive.
- **Risque** : le périmètre est volontairement limité au texte du détail (`:382`) ; un millésime dans la matrice ou un titre hors détail échappe à la détection, choix documenté pour ne pas confondre compteurs de matrix et années.
- **Effort** : M.
- **Vérification** : relecture — aucune écriture de `time` dans le module ; harnais — injecter un millésime à quatre chiffres sans source dans le détail → `data-e052-orphelins = "1"` et texte de signalement ; le retirer → retour à `"0"`.

## E052-08 — Cohérence des compteurs rendus, jugée sans correction

- **Problème / preuve** : `points.js:33` annonce le total dans le titre, `:47` pose un compte par case, `:97` annonce le périmètre dans le kicker. Rien dans la vue ne vérifie que le totalannoncé égale la somme des cases, ni que le périmètre égale la somme des cases de l'ère affichée : une incohérence de données se propagerait silencieusement, et un greffon qui « corrigerait » le nombre introduirait une valeur codée en dur.
- **Solution** : `chantierCoherence()` (`E052.js:405-430`) compare le total du titre à `donnees.sommeCellules` et le périmètre du détail à `donnees.sommeCellulesActives` (`:409-424`), publie `data-e052-coherent` à `oui` / `non` (`:427`) et `data-e052-incoherents` (`:428`), et liste chaque écart en texte (`:417-419`). Le panneau rappelle explicitement que les bornes d'ère ne sont pas rendues et qu'aucune appartenance d'ancre n'est affirmée (`:425`) — une limite déjà notée en passe 1, ici rendue visible.
- **Impact** : la qualité des compteurs est auditable sans les modifier ; le jugement porte sur les seules valeurs du DOM.
- **Risque** : un périmètre non fourni est compté comme « non jugeable », pas comme incohérent (`:412-414`) : c'est un choix de rigueur, documenté dans la légende.
- **Effort** : M.
- **Vérification** : relecture — aucune valeur de compteur écrite en dur ; harnais — modifier une case → `data-e052-coherence = "non"`, compteur incohérent incrémenté, ligne visible ajoutée ; retirer le kicker → mention « non fourni », aucun jugement.

## E052-09 — Empreinte déterministe des valeurs lues

- **Problème / preuve** : pour démontrer qu'aucune valeur n'est figée, il faut une synthèse qui bouge quand la donnée bouge. Un horodatage (issu d'une horloge) ne conviendrait pas : il varierait sans que les données changent et introduirait une date non dérivée du DOM.
- **Solution** : `empreinteDonnees()` (`E052.js:432-445`) concatène millésimes, compteurs, noms d'ères et textes de cases lus (`:433-439`) et applique un hachage déterministe de type djb2 avec graine fixe `GRAINE_HASH = 5381` (`:57`, `:440-443`). `chantierSignature()` (`:447-455`) affiche l'empreinte, la stocke dans `data-e052-signature` (`:453`) et la répète dans la métrique (`:536`). Aucune horloge, aucun aléa.
- **Impact** : l'empreinte est une preuve de dérivation — elle change si et seulement si une donnée change — et fournit un point de comparaison stable entre rendus.
- **Risque** : le hachage est une signature de convenance, pas un condensé cryptographique ; une collision théorique est sans conséquence, l'empreinte servant de repère visuel et non de garantie d'intégrité.
- **Effort** : S.
- **Vérification** : relecture — zéro horloge, zéro aléa, une seule graine constante ; harnais — deux jeux identiques → empreinte identique ; modifier un millésime ou une case → empreinte différente.

## E052-10 — Recalcul à chaque rendu : aucune valeur en cache

- **Problème / preuve** : la coque reconstruit le stage à chaque rendu et `registry.js:39-42` rejoue les greffons. Un greffon qui mémoriserait le premier millésime lu et le réafficherait ensuite produirait une date codée en dur par comportement, même sans littéral dans le code. `index.js:52` importe bien `./E052.js`, donc le stub initial devait être remplacé sans changer ce point d'entrée.
- **Solution** : `install()` relit systématiquement le DOM (`E052.js:483`) et recalcule l'empreinte (`:484`) avant toute écriture. `chantierFraicheur()` (`:457-469`) compare à `signaturePrecedente` (`:460-462`), incrémente `rendus` (`:459`) et publie `data-e052-rendus` / `data-e052-change` / `data-e052-stable` (`:465-467`). L'idempotence est assurée par `assurerNoeud()` (`:144-153`) et le remontage unique du panneau (`:531`) ; la garde `viewId` (`:482`) limite l'effet à `pointsv2` ; `ctx.reducedMotion()` est lu une fois sans animation propre (`:545-546`, `:118-120`). Écritures dédupliquées via `ecrire()` (`:134-136`) et `setData()` (`:138-142`).
- **Impact** : après navigation aller-retour, un seul panneau subsiste et ses valeurs sont celles du DOM courant ; l'état « depuis combien de rendus / modifié ou non » est auditable.
- **Risque** : les compteurs module (`rendus`, `signaturePrecedente`, `:59-60`) survivent aux rendus par conception ; ils ne créent aucun nœud et sont réécrits à chaque passage, donc jamais périmés. Un `<style id="points-v2-e052">` unique est garanti par `cssOnce` (`registry.js:13-19`).
- **Effort** : M.
- **Vérification** : `node --check src/views/points/v2/E052.js` → PASS ; relecture — un seul `register` (`:551`), un seul `ctx.css` (`:486`), quatorze IDs tous préfixés `points-v2-e052-` (`:38-52`) ; rejeu rendu → navigation → rendu : un seul `#points-v2-e052-panel`, `data-e052-rendus` incrémenté, `data-e052-stable = "1"` à données inchangées.

## Blocages / limites inter-domaines

- La vue n'étant ni possédée ni éditable, la découverte des porteuses de date repose sur les sélecteurs `.points-title`, `.view-kicker`, `.points-meta > span` et `.points-cell.has-points` (`E052.js:216-243`). Une refonte de ces marqueurs par le maître d'œuvre rendrait le recensement muet ; le panneau afficherait zéro plutôt qu'une valeur de repli — comportement conforme, mais à réévaluer lors d'une telle refonte.
- Les bornes de dates des ères (`start` / `end` dans `dataset.js`) ne sont pas rendues dans le DOM de la vue Points : E052 V2 ne peut donc pas vérifier qu'une ancre tombe dans son ère. Le chantier 08 rend cette limite explicite au lieu de la masquer ; la vérification exigerait un signal supplémentaire dans `points.js`, fichier non possédé.
- Le champ `datePrecision` du point n'est pas rendu non plus : la lentille affiche l'ancre telle quelle et ne distingue pas une année d'une décennie sans données complémentaires.
- Le panneau décrit l'état lu dans le DOM ; il ne corrige ni une fiche erronée, ni un kicker incohérent, ni un compte de case. Aucune information nouvelle n'est émise : la V2 n'ajoute aucune région live et n'écrit dans aucune de la passe 1.
- Le registre neutralise silencieusement une lentille défaillante (`registry.js:39-42`) : `node --check` et les gardes d'existence sont la première ligne de défense ; un harnais navigateur reste nécessaire pour valider les effets DOM.
- L'échantillon visuel est plafonné (huit formes en E052-03) pour la lisibilité ; les compteurs de dataset portent, eux, sur la totalité des valeurs lues.
- Le chemin d'import `../_diagnostics.js` des registres V2 est identique dans tous les domaines et antérieur à cette lentille : un éventuel échec de résolution de ce module partagé est hors du périmètre de E052 et n'a pas été modifié ici.
