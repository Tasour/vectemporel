## E004-01 — Matrice nommée et décrite, sans contraindre les boutons

La feuille unique est injectée en `:131` (`ctx.css(CSS_ID, CSS)`), `CSS_ID = 'points-v2-e004'` en `:36`.
2. **Solution** : la grille devient un groupe nommable sans imposer `role="grid"`/`gridcell` aux boutons `.points-era` et `.points-cell` rendus par `points.js` : aucun conflit de rôle, aucune casse de la commande clavier existante. Le titre n'est pas contraint à un id V2 si la passe 1 en a déjà un : la relation ARIA reste valide des deux côtés.
3. **Impact** : la matrice acquiert un nom et une description accessibles ; le texte ne contient aucun chiffre codé en dur.
4. **Effort** : S
5. **Vérification** : relecture — `role="group"`, `aria-labelledby`, `aria-describedby` présents, aucun `role="grid"`, un seul `#points-v2-e004-grid-desc` après deux passages ; harnais — retirer l'id du titre puis rejouer → le repli `points-v2-e004-name` est posé et référencé.

## E004-02 — Ligne de l'ère courante explicitement repérée (cœur du thème)

2. **Solution** : trois signaux redondants mais cohérents — attribut de données V2 (`data-v2-e004-current`, distinct du `data-e004-current` de la passe 1), `aria-current` pour les technologies d'assistance, style pour l'œil. 3. **Impact** : l'ère courante est repérable immédiatement à l'écran et à la lecture ARIA ; l'unicité est garantie même si plusieurs lignes portaient `is-active` (seule la première est retenue).

## Blocages / limites inter-domaines

- **Coexistence des identifiants** : `.points-title` et `.points-detail` reçoivent un id V2 (`points-v2-e004-name` / `points-v2-e004-detail`) uniquement s'ils n'en ont pas déjà un. La passe 1 posant `points-e004-title` / `points-e004-detail` avant la V2 (`points.js:127` puis `:128`), la V2 réutilise ces id plutôt que de les écraser : le préfixe `points-v2-e004-` ne s'applique donc qu'aux nœud **créés** par la V2, pas aux deux nœuds partagés. Toute lentille future qui réécrirait ces id devra les préserver.
- **Repère visuel** : le marquage de la ligne courante repose sur le `::before` du bouton `.points-era` ; si une feuille tierce masquait ce pseudo-élément, `aria-current` et `data-v2-e004-current` restent mais l'indice visuel disparaît. Aucun fichier CSS partagé n'a été modifié.
- **Cascade des pseudo-éléments** : la passe 1 et la V2 définissent toutes deux un `::before` sur `.points-era` de la ligne courante avec le même glyphe `▶` ; la feuille V2, injectée après, prévaut. Le rendu reste identique, sans doublon visible (un élément n'a qu'un seul `::before`).
- **Statut volatile** : le statut narratif est réécrit à chaque rendu de la coque et ne conserve pas d'historique d'annonces entre rendus.
- **Fidélité à l'état rendu** : E004 V2 ne corrige pas une ère `is-active` erronée produite par `store.js` ; il reflète l'état rendu. Toute divergence de sélection relève de `points.js` / `store.js`, fichiers non possédés.
- **Portée du diagnostic** : le module `_diagnostics.js` marque les nœuds dont l'id correspond à `.*-e\d{2,3}` lorsque leur parent direct est `body`, `stage` ou `layout`. Les nœuds V2 sont des enfants de `.points-matrix` (petits-enfants de `layout`) : ils ne sont donc pas déplacés dans le tiroir de diagnostic. Comportement identique à la passe 1, sans modification du module partagé.
