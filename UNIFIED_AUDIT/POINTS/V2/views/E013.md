# E013 (V2) — Réinitialisation des filtres (bouton + annonce)

Lentille POINTS E013 — passe 2 (V2) — domaine B : filtres & périmètre. Fichier possédé : `src/views/points/v2/E013.js` uniquement. Aucun fichier de la passe 1 (`src/views/points/E013.js`) ni aucun fichier partagé (vue `points.js`, coque, `styles.css`, `registry.js`, `index.js`) n'est modifié. Le bouton natif de `points.js` (`clear`, « Réinitialiser les filtres », `points.js:86-92`) n'est ni remplacé ni modifié dans son comportement : E013 V2 ajoute des attributs d'accessibilité **additifs**, **un** écouteur d'annonce, **une** note statique et une région live **locale distincte**. Contrat exploité : `viewId` (`'pointsv2'`), `stage`, `layout`, `css`, `el`, `reducedMotion`. Le `ctx` de cette vue n'expose pas `say()` (`points.js:128` appelle `runEnhancementsV2` sans lui), donc l'annonce passe par un `<p role=status aria-live=polite>` préfixé, accroché à `document.body` pour survivre au re-render déclenché par `set()`. Zéro réseau, zéro aléa, zéro timer, zéro rAF, zéro écouteur global, zéro `console.*`, zéro `innerHTML`. CSS injecté par `ctx.css('points-v2-e013', …)`.

Différence contractuelle V2 : `points.js:128` appelle `runEnhancementsV2({ viewId: 'pointsv2', stage, layout })` alors que la passe 1 cible `'points'` (`points.js:127`). La lentille filtre donc sur `'pointsv2'` (`v2/E013.js:120`). Tous les identifiants (`points-v2-e013-*`), classes et signaux (`data-points-v2-e013-*`, clés `pointsV2E013*`) sont distincts de ceux de la passe 1 (`points-e013-*`, `data-points-e013*`) afin de ne pas écraser ses marqueurs sur le DOM partagé. Le message V2 est enrichi du nom de l'ère lu dans le DOM, sans chiffre littéral.

## E013-01 — Repérage non destructif du bouton natif (V2)

- **Preuve** : `v2/E013.js:116-128` définit `rootOf()` : filtre sur `viewId === 'pointsv2'` (`:120`), ancrage sur `layout` puis repli sur le `.points-layout` de `stage` (`:121-126`). `findReset()` (`:130-143`) cherche d'abord le marqueur `[data-points-v2-e013-bound]` (`:136`), sinon parcourt les `button` de `.points-filters` et reconnaît le bouton natif à son libellé `/r[eé]initialiser/i` (`:140`), avec repli sur le dernier bouton (`:142`). `apply()` (`:266-275`) obtient `.points-filters` puis le bouton et sort s'ils manquent. Aucun `ctx.el('button')` ni `append` de bouton dans le module.
- **Solution** : réutiliser le bouton existant au lieu d'en créer un second, sans dépendre de l'id posé par la passe 1. Le marqueur V2 permet de le retrouver au rendu suivant même si le libellé change.
- **Impact** : le gestionnaire natif de `points.js` (mise à `state.pointFilterDomain/Family = '*'` puis `set(..., 'filter')`) reste le seul à réinitialiser les filtres : aucun doublon de commande, aucune régression fonctionnelle, coexistence avec la passe 1.
- **Effort** : S
- **Vérification** : relecture — absence de création de bouton ; harnais DOM : un seul `button` « Réinitialiser les filtres » dans `.points-filters` avant et après `apply()`, un seul gestionnaire natif actif, un seul marqueur `data-points-v2-e013-bound`.

## E013-06 — Deux messages distincts et véridifiables (V2)

## Blocages / limites inter-domaines

- La passe 2 cible `viewId: 'pointsv2'` (`points.js:128`) tandis que la passe 1 cible `'points'` (`points.js:127`) : les deux lentilles E013 s'appliquent au même DOM et écoutent le même bouton. E013 V2 n'écrit ni dans `#points-e013-live`, ni dans les signaux `data-points-e013*` de la passe 1. **Deux régions live coexistent donc** et deux phrases distinctes peuvent être lues à chaque clic ; à coordonner par l'agent maître (une arbitration consistant à ne garder qu'une seule annonce par clic reste de sa compétence, E013 V2 n'écrivant dans aucune région d'autrui).
- La réinitialisation native ne touche que le domaine et la famille (`points.js:88-89`) ; l'ère reste active. La note statique (`:246`) et le message (`:193`) le disent explicitement, mais E013 V2 ne modifie pas `state` : une réinitialisation incluant l'ère relève de `points.js`, fichier non possédé.
- Le re-render est asynchrone (`import()` dynamique, `points.js:91`) : l'annonce est écrite **avant** lui, dans une région hors `stage`, pour ne pas être perdue. Le message reflète donc l'état d'avant clic lu dans le DOM, pas le résultat après re-render — c'est un choix de vérité, pas une approximation.
- Le décompte somme les cellules `has-points` de la ligne d'ère active ; si une autre lentille (ex. E008 tri, E007 défilement) altère la structure de `.points-grid`, le sélecteur `:177` reste valide mais doit être rejoué en harnais.
- La note `points-v2-e013-hint` est insérée dans `.points-filters` (conteneur flex, `styles.css:361`) avec `flex-basis: 100%` : une lentille qui réorganiserait ce conteneur peut modifier son placement visuel, sans effet sur l'accessibilité (le texte reste dans le DOM et référencé par `aria-describedby`).
- Aucun fichier partagé modifié : `points.js`, `index.js`, `registry.js`, `styles.css` et la passe 1 sont intacts.
