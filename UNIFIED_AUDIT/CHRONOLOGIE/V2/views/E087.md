## E087-01 — Aucune surface de preuve auditable dans la vue

- **Problème / preuve** : la vue expose des indices textuels dispersés (indice clavier 8 px en `chronology.js:231`, cf. `E049.md:23`) et le modèle E049 décrit un panneau purement descriptif (`E049.js:193-218`, `E049.md:24`) sans qu'aucun endroit ne rende la lentille elle-même vérifiable. Le thème E087 exige des preuves avec numéros de ligne ; aucun texte de la vue ne porte de telle référence.
- **Solution** : `E087.js:298-300` crée un `<section role="region" aria-labelledby="…">` (`#chronology-v2-e087-panel`) dans `#atlas-chrono-main` (constante `HOST_ID`, `:36`), sous garde `ensureNode`. Le titre `:302` et le préambule `:304` bornent le périmètre : le panneau décrit, il n'altère ni la frise ni le détail. Le greffon est greffé en `:288-348`, une seule fois enregistré en `:350`.
- **Impact** : la preuve devient consultable sur place, sans ouvrir le rapport ni lancer un outil externe ; le panneau reste en flux normal et n'ajoute aucun arrêt Tab hormis son bouton.
- **Risque** : le panneau allonge la colonne de gauche et repousse la fin de la liste ; c'est un compromis assumé, cohérent avec le choix du modèle E049 (`E049.md:98`) d'un bloc en flux plutôt qu'un panneau absolu qui masquerait des cartes.
- **Effort** : M.
- **Vérification** : relecture `E087.js:288-300` ↔ `:302-304` ; harnais — un seul `#chronology-v2-e087-panel`, `role="region"`, `aria-labelledby` pointant sur `#chronology-v2-e087-title` ; la frise et la fiche restent inchangées.

## E087-02 — Contrat ESM (import / register / feuille) non matérialisé

- **Problème / preuve** : le contrat est imposé au greffon — un import de `register`, un seul `register('E087', …)`, une seule feuille CSS — mais le registre ne l'expose pas : `cssOnce` ne garantit que l'unicité du `<style>` (`registry.js:13-19`, relevé `E049.md:104`) et `runEnhancements` rejoue indistinctement les entrées (`:39-42`). - **Solution** : `E087.js:46-48` déclare `CONTRAT` (`imports: 1`, `registres: 1`, `feuilles: 1`) comme faits de relecture ; `:212` les affiche en texte dans `#chronology-v2-e087-contract`, avec `data-e087-contract` en `:222`. - **Impact** : le respect du contrat devient lisible et falsifiable par simple lecture du panneau, sans modifier le registre ni le point d'entrée `index.js:87`.
- **Risque** : les valeurs sont des faits structuraux déclarés, vérifiés par relecture et non calculés à l'exécution : une modification future du module imposerait de relire `E087.js:48` et la ligne d'état `:212`. Aucune valeur n'est inventée ni dérivée d'une source externe.
- **Effort** : S.
- **Vérification** : relecture croisée `E087.js:1`, `:48`, `:212`, `:222`, `:293`, `:350` — un import, un register, un css ; `data-e087-contract="1"` ; aucune autre occurrence de `register('E087'`.

## E087-03 — IDs du module non dénombrés, préfixe non vérifié

- **Problème / preuve** : `registry.js:13-19` ne protège que la feuille de style ; ni les nœuds ni leurs IDs ne sont contrôlés (`E049.md:104`). Sur un re-render, la coque détruit le stage (`E049.md:41`) : sans inventaire, un ID oublié ou mal préfixé passerait inaperçu.
- **Solution** : `E087.js:41-44` dresse `OWNED_IDS` (12 identifiants) ; `:159-164` calcule `IDS_AUDIT` — total, nombre d'IDs commençant par `PREFIX` (`:37`) et cardinal d'un `Set` pour l'unicité — et `:213` affiche le résultat dans `#chronology-v2-e087-ids` avec `data-e087-ids` (`:223`). La garde `ensureNode` (`:178-186`) réutilise tout nœud déjà present dans le document.
- **Impact** : le préfixe et l'unicité sont vérifiés à l'exécution, et le compte affiché dérive de la liste réelle plutôt que d'une constante recopiée.
- **Risque** : l'audit porte sur les IDs du module, pas sur ceux de la vue ; un ID ajouté ultérieurement devra être inscrit dans `OWNED_IDS` pour être compté. Le préfixe est contrôlé par `startsWith`, donc un ID conforme mais inattendu ne serait pas signalé nommément.
- **Effort** : S.
- **Vérification** : relecture `E087.js:37`, `:41-44`, `:159-164`, `:213`, `:223` ; harnais — `data-e087-ids="12"`, texte « 12 IDs, 12 préfixés, 12 uniques » ; double rendu → aucun ID en doublon dans `#atlas-chrono-main`.

## E087-04 — Feuille CSS non mesurée depuis sa chaîne source

- **Problème / preuve** : `ctx.css` (`registry.js:13-19`) injecte une feuille sans la décrire ; le modèle E049 relève que la vue diffuse de nombreuses valeurs en pixels (`E049.md:95`, relevé sur `chronology.js:39,45,56,64`), mais aucune métrique de la feuille injectée n'est exposée dans le DOM.
- **Solution** : `E087.js:78-146` définit l'unique chaîne `CSS` ; `:148-157` dérive `CSS_AUDIT` (règles comptées sur `\{`, replis sur `@media`, déclarations sur `;`) via `occurrences` (`:148-150`) ; `:214` affiche le résultat dans `#chronology-v2-e087-css` avec `data-e087-css` (`:224`). Aucun chiffre n'est codé en dur dans le libellé.
- **Impact** : la complexité de la feuille devient mesurable et reproductible ; le contrôle peut être rejoué sur toute modification du CSS du greffon.
- **Risque** : le comptage par expression régulière mesure des occurrences textuelles, pas l'application effective des règles par le navigateur ; il ne garantit pas le rendu, seulement la taille de la source. Les `@media` sont comptés comme des blocs, pas comme des conditions évaluées.
- **Effort** : M.
- **Vérification** : relecture `E087.js:78-157`, `:214`, `:224` ; comparer `data-e087-css` au nombre réel de blocs `{` de la chaîne `CSS` ; un seul `<style id="chronology-v2-e087">` dans `<head>` après deux rendus.

## E087-05 — Attestation d'absence des API interdites

- **Problème / preuve** : le registre neutralise silencieusement tout greffon défaillant (`registry.js:39-42`, `E049.md:104`) : une lentille pourrait invoquer une API interdite — journalisation, réseau, aléa, balisage brut, minuteur, boucle — sans que l'échec soit visible dans la vue. Le modèle E049 consigne les mêmes invariants (`E049.md:4`, `:20`).
- **Solution** : `E087.js:50-59` déclare `INTERDITS`, un compteur à zéro par famille, vérifiable par relecture du fichier entier ; `:215` l'affiche en six postes dans `#chronology-v2-e087-forbidden` et `:225` publie la somme dans `data-e087-forbidden`. - **Impact** : l'absence des interdits devient une affirmation explicite et contrôlable, alignée sur le contrat de la passe V2.
- **Risque** : l'attestation est un fait déclaré, pas une analyse statique exécutée à froid ; elle doit être relue à chaque modification. Le compteur ne détecte pas une API interdite qui apparaîtrait dans une dépendance inlinée, mais le module n'a aucune dépendance inlinée.
- **Effort** : S.
- **Vérification** : recherche textuelle sur `E087.js` — zéro `console.`, `fetch`, `XMLHttpRequest`, `Math.random`, `setTimeout`, `setInterval`, `requestAnimationFrame`, zéro assemblage de balises ; `data-e087-forbidden="0"` ; relecture `:50-59` ↔ `:188-245`.

## E087-06 — Aucune numérotation de ligne pour les preuves

- **Problème / preuve** : le thème E087 porte précisément sur les preuves avec numéros de ligne, or la vue ne fournit aucun ancrage de ce type ; le modèle E049 ne cite que des références externes dans son rapport (`E049.md:23-28`), jamais dans le DOM. Sans liste numérotée, une preuve ne peut être reliée à sa ligne de code.
- **Solution** : `E087.js:61-74` définit `PREUVES`, dix objets `{ chantier, ligne, libelle }` dont la référence `E087.js:L…` est relue après écriture ; `:234-245` construit une `<ol>` (`#chronology-v2-e087-proofs`, `:323-326`) où chaque `<li>` porte son rang via `make('span','v2e087-num', …)` (`:238`) et sa référence via `make('span','v2e087-ref', …)` (`:239`). - **Impact** : chaque chantier est désormais adressable par son numéro de ligne réel ; la preuve est lisible même sans stylesheet, puisque le texte et l'ordre sont portés par le DOM.
- **Risque** : les références `L…` sont figées dans la chaîne `PREUVES` : toute insertion de lignes au-dessus impose de les relire (procédure consignée en `:61-62`). Le rang affiché (`1.`) est l'ordre de la liste, pas le numéro de ligne — les deux sont distincts et complémentaires.
- **Effort** : M.
- **Vérification** : relecture des dix références `E087.js:L…` (`:64-73`) ↔ lignes réelles `48, 52, 63, 124, 153, 160, 178, 216, 247, 298` ; harnais — `<ol>` de dix `<li>`, chacun avec un `.v2e087-num` et un `.v2e087-ref` ; zéro assemblage de balises.

## E087-09 — Lisibilité des preuves : mouvement réduit et couleurs forcées

- **Problème / preuve** : `styles.css:342-344` neutralise globalement les animations (relevé `E049.md:95`) et `ctx.reducedMotion()` est fourni par `registry.js:33-36`, mais la vue n'expose aucun état de préférence. Les preuves, si elles étaient dockées sur un mouvement ou une teinte, deviendraient illisibles en `prefers-reduced-motion` ou en `forced-colors`.
- **Solution** : `E087.js:124-145` neutralise défensivement tout mouvement hérité (`:125-131`) et impose un repli `forced-colors` (`:134-145`) fondé sur le texte et la bordure, jamais sur la seule couleur dorée. `:343` lit `ctx.reducedMotion()`, `:217-219` affiche l'état dans `#chronology-v2-e087-a11y` et `:227` publie `data-e087-reduced`. Le bouton `:306-312` a `min-height:36px` (`:93`) et un `:focus-visible` à 2 px (`:98`).
- **Impact** : les preuves restent lisibles en mouvement réduit, en contraste forcé et au clavier, sans qu'aucune animation ne soit créée par le greffon.
- **Risque** : le repli `transition: none !important` (`:128`) neutralise un héritage éventuel, il n'introduit aucun mouvement ; le compteur d'API interdites (`:58`) reste à zéro. En `forced-colors`, la bordure gauche devient `CanvasText`, donc le texte prime sur la teinte.
- **Effort** : M.
- **Vérification** : émuler `prefers-reduced-motion: reduce` → `data-e087-reduced="1"` et libellé « oui » ; émuler `forced-colors: active` → les preuves restent lisibles en `CanvasText` ; capture 390×844 → le tableau et la liste ne débordent pas (repli `:120-123`).

## E087-10 — Idempotence multi-rendus non prouvée

- **Problème / preuve** : la coque détruit le stage avant chaque rendu (`E049.md:41`, `shell.js:533`) et `runEnhancements` rejoue tous les greffons (`registry.js:39-42`) ; le modèle E049 souligne que le registre ne protège ni les nœuds ni les écouteurs (`E049.md:104`). Sans garde, un panneau, un écouteur ou un ID se dupliquent à chaque navigation.
- **Solution** : `E087.js:175-186` fournit `ensureNode` avec garde d'existence et déplacement dans le parent courant ; `:337` utilise `replaceChildren` pour détacher les nœuds de la rendu précédente ; `:269-286` installe un seul écouteur `click` sous garde `toggleBound` ; `:166` et `:220` maintiennent un compteur `installs` affiché dans `#chronology-v2-e087-renders` et publié en `data-e087-renders` (`:228`). `:350` enregistre un seul greffon.
- **Impact** : aucun doublon de panneau, d'IDs ou de feuille de style après navigation aller-retour ; aucune fuite d'écouteur sur une longue session, et le nombre de rendus devient une preuve visible.
- **Risque** : un nœud retrouvé dans un ancien parent détaché est déplacé, jamais cloné ; son état est réécrit à chaque `paint()` (`:208-230`), donc jamais périmé. Le registre neutraliserait silencieusement une erreur : `node --check` et les gardes d'existence sont la première ligne de défense.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E087.js` → PASS ; relecture — un seul `register` (`:350`), un seul `ctx.css` (`:293`), un seul `addEventListener` (`:273`), douze IDs préfixés (`:41-44`) ; rejeu rendu → navigation → rendu : un seul `#chronology-v2-e087-panel`, un seul `<style id="chronology-v2-e087">`, `data-e087-renders` incrémenté.

## Blocages / limites inter-domaines

- Le panneau est purement descriptif et calculateur de faits locaux : il ne peut pas modifier la vue (`src/views/chronology.js`), le routeur, la coque, `styles.css` ni le registre (`registry.js`) — tous fichiers non possédés. Il ne corrige pas les 8 px de `chronology.js:39`, signalés en `E049.md:95`.
- Les faits structuraux (`CONTRAT` `:48`, `INTERDITS` `:52-59`, références `L…` `:64-73`, étiquette `PASS` `:216`) sont déclarés et vérifiés par relecture, pas analysés statiquement à l'exécution : une édition du module impose de relire ces lignes. Le module n'a ni dépendance inlinée ni sous-processus pour éviter toute analyse coûteuse ou réseau.
- Les métriques CSS (`:153-157`) comptent des occurrences textuelles dans la chaîne `CSS` : elles mesurent la source, pas l'application effective des règles par le navigateur.
- Le tableau de traçabilité (`:247-267`) dérive l'effet DOM du suffixe du chantier (`:261`) : il donne le genre d'identifiant, pas un sélecteur complet — le détail exact est dans le présent rapport.
- L'état affiché (compteurs, préférence de mouvement, nombre de rendus) est volatile et recalculé à chaque rendu, comme le prescrit le contrat de greffon V2 ; la coque reste seule maîtresse du cycle de vie du stage.
