## E025-01 — Bloc « Sources » dédié et permanent dans la fiche

- **Problème / preuve** : le thème (`themes.json:28`) impose un bloc de sources dans la fiche, mais le contrat de greffon (`E025.js:10-11`) ne fournit aucun composant « sources » prêt à l'emploi : seuls `css` et `el` sont disponibles. Sans greffon dédié, le détail peut afficher son texte sans jamais réserver de place aux sources.
- **Solution** : `E025.js:24` déclare l'ID `chronology-v2-e025-sources` ; `:209-212` crée le `<section>` et le greffe dans `ctx.layout`, avec `role="region"` et `aria-labelledby` ; `:214-215` pose le titre `<h2>` « Sources du repère » et `:216-217` un préambule qui borne le périmètre. Le style de contour est en `:47-54`.
- **Impact** : le bloc existe dans toutes les situations, y compris quand le repère n'a aucune source : la question « d'où vient ce point ? » a toujours un endroit dédié.
- **Risque** : le panneau allonge la colonne de détail. C'est un compromis assumé face à un bloc absolu qui masquerait la fiche.
- **Effort** : S.
- **Vérification** : après rendu, un seul `section#chronology-v2-e025-sources[role="region"]` avec un `<h2>` associé par `aria-labelledby` ; relecture de `E025.js:209-217`.

## E025-02 — Liste sémantique des sources au lieu d'un texte aplati

- **Problème / preuve** : le contrat (`E025.js:10-11`) ne contraint aucune structure de restitution. Des sources concaténées dans un paragraphe ne sont ni dénombrables ni parcourables par les technologies d'assistance, alors que le thème porte précisément sur les sources.
- **Solution** : `E025.js:35-41` définit un sélecteur tolérant (`[data-e025-source]`, `[data-source-id]`, `[data-source-url]`, `.chronology-source`, `.source-entry`) ; `:154-173` collecte les nœuds en excluant le panneau (`:158`) pour ne jamais se relire ; `:218-219` crée le `<ul id="chronology-v2-e025-list">` ; `:178-181` fabrique un `<li>` par source ; `:237` peuple la liste avec `replaceChildren` (jamais `innerHTML`).
- **Impact** : chaque source devient un élément de liste distinct, annoncé et compté ; le nombre d'entrées est directement lisible dans le DOM.
- **Risque** : le sélecteur est volontairement large pour rester compatible avec les conventions de la vue ; un nœud tiers portant `data-source-id` serait inclus. Le filtrage par `panel.contains()` (`E025.js:158`) protège uniquement contre l'auto-référence.
- **Effort** : M.
- **Vérification** : avec deux nœuds `data-source-id`, `#chronology-v2-e025-list` contient exactement deux `<li>` ; sans nœud, la liste est vide et masquée (`E025.js:238`).

## E025-03 — Identifiant de source stable, visible et distinct

- **Problème / preuve** : une source sans identifiant ne peut être désignée de façon stable d'un rendu à l'autre ; le contrat (`E025.js:10-11`) n'expose aucun identifiant de source. Le modèle de qualité distingue par ailleurs la poignée de la citation (`E049.js:12-15` pour la séparation des responsabilités).
- **Solution** : `E025.js:159` lit `data-e025-source` / `data-source-id` / `data-source`, `:165` en extrait l'identifiant, `:194` l'affiche dans un `<code class="e025-id">` ; `:181` ajoute `data-e025-index` ; le style distinctif est en `:74-77`.
- **Impact** : l'identifiant est visible, copiable et stable, sans ouvrir de lien ni quitter la fiche.
- **Risque** : la valeur `omise` est réservée à l'état d'omission (`E025.js:161`, `:165`) et n'est donc pas affichée comme identifiant. L'usage plein de l'identifiant comme référence de citation relève de E026 (voir « Blocages »).
- **Effort** : S.
- **Vérification** : un nœud `data-source-id="SRC-12"` produit `<code class="e025-id">SRC-12</code>` (`E025.js:165`, `:194`) ; `data-e025-source="omise"` ne produit aucun `<code>`.

## E025-04 — Repli « omission justifiée » quand aucune source n'est rattachée

- **Problème / preuve** : le thème (`themes.json:28`) exige un *repli*. Sans collecte de source, le bloc de l'E025-01 resterait vide : le vide serait alors pris pour une absence d'information plutôt que pour une omission assumée.
- **Solution** : `E025.js:220-221` réserve le paragraphe `#chronology-v2-e025-fallback` ; `:238-239` bascule la visibilité liste/repli selon le nombre de sources ; `:240-247` écrit, uniquement quand la liste est vide, le texte « Aucune source n'est rattachée à ce repère dans le DOM. Omission justifiée : … » et ajoute le badge « OMISSE » ; `:267` publie `data-e025-state="omise"` ; le style du repli est en `:87-92`.
- **Impact** : zéro source n'est plus jamais un blanc : l'état est nommé, justifié et mesurable.
- **Risque** : le texte de repli décrit une observation sur le DOM, pas une affirmation historique ; il ne prétend pas que la source n'existe pas dans la réalité, seulement qu'elle n'est pas transmise à la fiche.
- **Effort** : M.
- **Vérification** : sans nœud source, `fallback.hidden === false`, `list.hidden === true` et `data-e025-state="omise"` (`E025.js:238-240`, `:267`) ; avec une source, l'inverse.

## E025-05 — Motif d'omission affiché en texte distinct

- **Problème / preuve** : une omission doit porter son motif ; le registre n'offre pas de canal d'annonce (`E025.js:12-13`, modèle `E049.js:12-15`) et un motif laissé dans un attribut `data-*` resterait invisible pour la personne qui lit la fiche.
- **Solution** : `E025.js:162` lit `data-omission-reason` / `data-e025-reason` ; `:198` l'affiche dans un `<span class="e025-reason">` par entrée omise ; `:222-223` réserve le paragraphe `#chronology-v2-e025-reason` ; `:250-257` construit la phrase « Motif d'omission — … », y compris dans le cas sans source ; le style est en `:83-86`.
- **Impact** : le pourquoi de l'omission est lisible en permanence, même quand aucune source n'est présente.
- **Risque** : E025 affiche le motif en paragraphe, pas en citation : le traitement en `<blockquote>` et l'appareil de citation sont la responsabilité de E026 (voir « Blocages »).
- **Effort** : M.
- **Vérification** : un nœud `data-source-kind="omise" data-omission-reason="consultation indisponible"` produit le `<span class="e025-reason">` (`:198`) et la phrase « Motif d'omission — source 1 : consultation indisponible. » (`:250-254`).

## E025-06 — Lien de source sortant sécurisé, sans réseau

- **Problème / preuve** : une URL de source doit pouvoir être suivie sans exposer la fenêtre d'origine ; or le module interdit tout réseau (`E025.js:17-18`) : aucun `fetch`, aucune validation à distance, aucun chargement d'icône.
- **Solution** : `E025.js:160` lit `data-source-url` / `data-href` ; `:185-189` crée un `<a class="e025-link">` avec `href`, `target="_blank"` et `rel="noopener noreferrer"` via `setAttr` (`:140-142`), sinon un `<span class="e025-label">` (`:191`) ; `:97-99` donne un `:focus-visible` à 2 px ; `:263` documente la relation dans le bloc de contrôle.
- **Impact** : la source est consultable en toute sécurité, l'activation reste native et la fenêtre parente n'est pas exposée.
- **Risque** : l'URL est recopiée telle quelle depuis l'attribut ; aucune normalisation n'est tentée (ce qui évite tout traitement réseau), une URL mal formée reste donc la responsabilité de la donnée source.
- **Effort** : S.
- **Vérification** : relecture — zéro `fetch` / `XMLHttpRequest` / `url(http` ; un nœud `data-source-url` donne `<a target="_blank" rel="noopener noreferrer">` (`E025.js:185-189`).

## E025-07 — Repère d'omission non coloriel (badge texte + forme)

- **Problème / preuve** : si l'omission n'était signalée que par une teinte, elle disparaîtrait en `forced-colors` ou pour une personne daltonienne. Le commentaire de conception `E025.js:43-45` pose explicitement la règle « texte ET forme ».
- **Solution** : le badge textuel « OMISSE » est posé en `:197` (entrée omise) et `:243` (repli) ; la bordure en pointillé est portée par `:82` pour l'entrée et `:87-90` pour le repli ; le style du badge est en `:78-81` ; l'attribut `data-e025-kind="omise"` (`:180`) sert de crochet CSS.
- **Impact** : l'état d'omission reste identifiable sans aucune perception des couleurs, y compris en contraste forcé (`:107-116`).
- **Risque** : le libellé « OMISSE » est court par choix ; il est complété par le motif (E025-05) et par le compteur (E025-09), qui portent le sens complet.
- **Effort** : S.
- **Vérification** : émuler `forced-colors: active` — le badge et la bordure pointillée restent présents (`E025.js:107-116`) ; relecture — aucune information dans le CSS portée par la seule couleur.

## E025-08 — Contraste, focus, mobile et mouvement réduit du bloc

- **Problème / preuve** : le helper `ctx.reducedMotion()` est fourni (`E025.js:10-11`) mais le contrat ne garantit ni contraste des libellés ni cible tactile : sans dispositions propres, un lien de source peut rester sous 44 px en 390×844 et les transitions peuvent ignorer la préférence.
- **Solution** : `E025.js:71-73` fixe des couleurs à contraste élevé avec replis ; `:97-99` renforce le focus ; `:100-103` empile les entrées et porte les liens à `min-height:44px` sous 620 px ; `:104-106` neutralise transitions et animations en `prefers-reduced-motion` ; `:107-116` fournit un repli `forced-colors` ; `:231` lit `ctx.reducedMotion()`, `:268` le publie dans `data-e025-reduced`, `:263` le répète en texte.
- **Impact** : bloc lisible et actionnable au doigt sur mobile, sans mouvement parasite et sans perte d'information en contraste forcé.
- **Risque** : les valeurs de couleur de repli sont des approximations des variables de thème ; si la coque redéfinit ses variables, le repli reste lisible mais peut différer légèrement de la charte.
- **Effort** : M.
- **Vérification** : émuler `prefers-reduced-motion: reduce` → `data-e025-reduced="1"` et libellé « oui » (`:231`, `:263`, `:268`) ; capture 390×844 → liens ≥ 44 px (`:100-103`) ; aucun `transition` non neutre (`:104-106`).

## E025-09 — Récapitulatif chiffré dérivé du DOM

- **Problème / preuve** : le contrat ne fournit aucun chiffre (`E025.js:10-13`) ; sans mesure, le repli « omission justifiée » n'est pas falsifiable — on ne peut pas vérifier combien de sources sont renseignées contre combien d'omissions.
- **Solution** : `E025.js:233-234` sépare `present` et `omitted` depuis les nœuds collectés ; `:224-225` crée le paragraphe `#chronology-v2-e025-count` ; `:260` écrit « Sources renseignées : N · omissions justifiées : M · total : N+M. » ; `:265-266` publie `data-e025-sources` et `data-e025-omitted` ; `:93-96` applique des chiffres tabulaires.
- **Impact** : trois grandeurs chiffrées, recalculées à chaque rendu depuis le DOM, rendent l'état de la fiche vérifiable d'un coup d'œil.
- **Risque** : les compteurs décrivent les nœuds portant les attributs reconnus, pas l'exhaustivité réelle des archives ; une source non marquée dans le DOM échappe au décompte (voir « Blocages »).
- **Effort** : S.
- **Vérification** : avec 2 sources renseignées et 1 omission, le libellé donne « 2 · 1 · 3 » et les attributs `data-e025-sources="2"`, `data-e025-omitted="1"` (`E025.js:260`, `:265-266`).

## E025-10 — Idempotence multi-rendus, IDs uniques et gardes d'existence

- **Problème / preuve** : le registre rejoue les greffons à chaque rendu (modèle `E049.js:102-104`) et la coque reconstruit le stage ; sans garde, le panneau se duplique et les compteurs se réinitialisent. Le squelette impose un seul `register` et un seul `ctx.css` (contrat rappelé en `E025.js:15-17`).
- **Solution** : `E025.js:121-132` fournit `ensureNode()` avec garde d'existence et déplacement dans le parent courant ; `:23` et `:207` imposent un seul `CSS_ID` / un seul `ctx.css` ; `:23-30` déclarent les huit IDs tous préfixés `chronology-v2-e025-` ; `:119` et `:206` maintiennent `renderCount`, publié en `:269` et `:263` ; `:229`, `:237`, `:241-246` utilisent `replaceChildren` ; `:136-138` déduplique les écritures ; `:272` est l'unique `register`.
- **Impact** : aucun doublon de panneau, de liste ou de feuille de style après navigation aller-retour ; l'état reste cohérent et auditable via `data-e025-renders`.
- **Risque** : un nœud retrouvé dans un ancien parent détaché est déplacé, jamais cloné ; ses attributs `data-e025-*` sont réécrits à chaque rendu (`:265-269`), donc jamais périmés. Le registre neutraliserait silencieusement une erreur : `node --check` est la première ligne de défense.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E025.js` → PASS ; relecture — un seul `register` (`:272`), un seul `ctx.css` (`:207`), huit IDs préfixés (`:23-30`), zéro `innerHTML` ; rejeu rendu → navigation → rendu : un seul panneau et un seul `<style id="chronology-v2-e025">`.

## Blocages / limites inter-domaines

- E025 se limite au bloc « sources » et à son repli. La mise en citation à part entière (bloc `<blockquote>`, attribution complète) est confiée à E026 (« justification affichée en citation », `themes.json:29`) ; E025 fournit les identifiants et les motifs comme poignées, sans empiéter sur ce format.
- L'identifiant d'omission explicite au niveau des données est traité par F056 (`themes.json:59`) ; la lentille ne fait que le relayer lorsqu'il est présent dans le DOM (`data-omission-reason`, `E025.js:162`) et ne fabrique pas d'identifiant nouveau.
- Le décompte de E025-09 ne voit que les nœuds portant les attributs du sélecteur `E025.js:35-41`. Une source qui ne serait pas marquée dans le DOM échappe à la mesure : la couverture binaire relève de F060 et de la vue elle-même, fichiers non possédés.
- Aucune région live n'est ajoutée : l'état du bloc est visible mais non annoncé spontanément, conformément au contrat sans `say()` (`E025.js:12-13`). Les annonces restent portées par les régions existantes de la vue et de la coque.
- Le compteur `renderCount` (`E025.js:119`, `:206`) est volatile au sens du module : il surviv aux rendus dans la session mais se réinitialise au rechargement complet de la page.
