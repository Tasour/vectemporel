## E050-01 — Échelle typographique des 8–9 px : unités relatives dans le greffon

- **Problème / preuve** : la vue diffuse de très petites tailles en pixels : `chronology.js:39` (`font-size:8px`), `:45` (`:8px`), `:56` (`:9px`), `:64` (`:8px`), `:66` (`:8px`), `:59` (`:9px`). Un zoom texte navigateur à 200 % ne peut rattraper des valeurs aussi basses que si elles sont exprimées en pixels ; le contraste typographique s'effondre (8 px → 16 px théoriques, sous la barre de lisibilité des 12–16 px attendus).
- **Solution** : `E050.js:43` fixe `font-size: 0.95rem` sur le panneau, `:49` le titre à `1.25rem`, `:56` la zone de démonstration à `calc(1rem * var(--e050-grow))`, `:101` la métrique à `0.85rem`. Le facteur est porté par `--e050-grow` (`:39`, doublé en `:46`) : aucune taille de texte du greffon n'est en `px` fixe. La ligne d'état `E050.js:166` affiche le facteur courant.
- **Impact** : le panneau E050 reste lisible et proportionné quand le navigateur zoom le texte, sans exiger de modifier les feuilles de la passe 1.
- **Risque** : le zoom du navigateur ne s'applique qu'au contenu du greffon ; les 8 px de `chronology.js` restent tels quels. La lentille ne corrige pas la vue, elle démontre et documente le comportement attendu (cf. blocages).
- **Effort** : M.
- **Vérification** : relecture `E050.js:43, 49, 56, 101` — zéro `font-size` en `px` dans le greffon ; à 200 %, `#chronology-v2-e050-demo` calcule bien 2 rem.

## E050-02 — Aucun moyen de simuler le zoom 200 % dans la vue

- **Problème / preuve** : `chronology.js:540-541` appelle les deux registres à chaque rendu sans exposer de commande de zoom ; `styles.css:102` pose `.shell-stage { overflow: hidden }`, donc tout débordement induit par un agrandissement est masqué plutôt que géré. Aucun contrôle ne permet de vérifier sur place le comportement à 200 %.
- **Solution** : `E050.js:239-240` crée un `<button type="button">` natif (`#chronology-v2-e050-zoom`) ; `:212-215` bascule `zoomLevel` entre 100 et 200, `:195-210` applique le facteur via `data-e050-zoom` (`:199`) et la variable CSS (`:46`). L'état module `zoomLevel` (`:135`) survit aux rendus. L'effet observable est immédiat : le texte de `#chronology-v2-e050-demo` double (`:56`) et l'attribut change.
- **Impact** : la conformité « zoom 200 % » devient vérifiable par un simple clic ou par Tab + Entrée/Espace (activation native, aucun gestionnaire de touche ajouté).
- **Risque** : il s'agit d'une simulation locales au panneau, pas d'un zoom pilotant le navigateur ; la mesure n'est pas une garantie sur l'ensemble de la vue. Le libellé `E050.js:235` le précise explicitement.
- **Effort** : M.
- **Vérification** : harnais — clic / Tab+Entrée sur `#chronology-v2-e050-zoom` → `panel.dataset.e050Zoom` passe de `"100"` à `"200"`, le texte double, puis revient à `"100"` ; aucun `keydown` dans le module.

## E050-03 — Changement de zoom silencieux : annonce visible dédupliquée

- **Problème / preuve** : le registre V2 n'expose pas `say()` (`v2/registry.js:28-37`) ; la vue possède déjà sa propre région `#nav-c2a-live` (`chronology.js:119-138`) et le routeur `#nav-t2-live`. Ajouter une quatrième région live, ou écrire à chaque bascule dans une région existante, produirait des annonces redondantes dans une vue déjà bavarde.
- **Solution** : `E050.js:205-207` écrit l'annonce dans un `<p>` visible ordinaire (`#chronology-v2-e050-announce`, défini `:242`, stylé `:67`), sans `role="status"` ni `aria-live`. La fonction `write()` (`:156-158`) ne touche au texte que s'il diffère. Le commentaire d'en-tête `:13-14` consigne le choix.
- **Impact** : l'état du zoom est lisible par les technologies d'assistance lors de la navigation dans le panneau, sans bavardage spontané ni compétition entre régions live.
- **Risque** : le changement n'est pas annoncé de façon proactive ; c'est un choix délibéré, cohérent avec le contrat de greffon V2 qui ne fournit pas de canal `say()`.
- **Effort** : S.
- **Vérification** : relecture — zéro `aria-live`, zéro `role="status"`, zéro référence à `nav-c2a-live` ou `nav-t2-live` dans `E050.js` ; deux bascules sans changement ne modifient aucun `textContent` (`:157`).

## E050-04 — Mots longs : `overflow-wrap` pour éviter le débordement horizontal

- **Problème / preuve** : `styles.css:102` masque le débordement du stage (`.shell-stage { overflow: hidden }`) et `styles.css:208` fait de même sur `.event-card` : un mot long agrandi à 200 % risque d'être coupé sans que l'utilisateur puisse le lire, puisque aucun retour à la ligne forcé n'est prévu.
- **Solution** : `E050.js:69-71` impose `overflow-wrap: anywhere` et `word-break: break-word` sur `.e050-wrap`, hérités du panneau (`:44`). La chaîne volontairement non fragmentable `#chronology-v2-e050-wrap` (`:219`, posée en `:244`) sert de cas d'école : à 200 %, elle se coupe à l'intérieur des mots sans pousser les bords de la boîte. L'état écrit en `:169` le confirme.
- **Impact** : démonstration falsifiable d'un texte long qui reste dans son contenant quel que soit le facteur de zoom.
- **Risque** : `overflow-wrap: anywhere` peut couper au milieu d'un mot ; c'est préférable à une troncature invisible, et le texte reste intact dans le DOM.
- **Effort** : M.
- **Vérification** : capture à 200 % — `#chronology-v2-e050-wrap` ne dépasse pas la largeur de `#chronology-v2-e050-panel` ; aucun `white-space: nowrap` sur ce nœud.

## E050-05 — `nowrap` / `text-overflow: ellipsis` : risque de troncature sous zoom

- **Problème / preuve** : la coque recourt à `white-space: nowrap` sur un libellé (`styles.css:60`) et sur le texte sr-only (`:103`, `clip`), et le globe à `text-overflow: ellipsis` (`:188`). Ces motifs, s'ils étaient repris sur le texte visible de la vue, tronqueraient le contenu dès que le zoom allonge les lignes.
- **Solution** : `E050.js:72-74` pose explicitement `white-space: normal; text-overflow: clip; overflow: visible` sur `.e050-flow` (nœud créé en `:245`). L'état associé (`:170`) l'affiche. Aucun `nowrap`, aucune ellipse, aucun `clip` sur du texte visible dans le greffon.
- **Impact** : le texte du repère se répartit sur plusieurs lignes au lieu d'être coupé, y compris quand les caractères grandissent.
- **Risque** : l'allongement des lignes augmente la hauteur du panneau ; c'est le compromis assumé face à la troncature, cohérent avec le périmètre « sans débordement ».
- **Effort** : S.
- **Vérification** : relecture — zéro `nowrap` et zéro `text-overflow: ellipsis` dans `E050.js` ; le paragraphe `.e050-flow` occupe plusieurs lignes à 200 % sans être rogné.

## E050-06 — Boîtes à largeur minimale : `min-width: 0` sur les enfants flexibles

- **Problème / preuve** : `styles.css:194` fixe la colonne latérale à `380px` et `styles.css:205` la grille de cartes à `minmax(190px,1fr)` ; en flex/grid, la taille minimale automatique des enfants peut empêcher la compression et forcer un débordement horizontal quand le texte grandit. `chronology.js:43` tente `min-width:0` sur les `<li>` d'ère, mais rien ne garantit les enfants internes.
- **Solution** : `E050.js:78-81` applique `flex: 1 1 8rem; min-width: 0` aux trois cellules de `.e050-flex` (créées en `:246-247`) ; `:86-89` fait de même pour `.e050-grid > span`, `:99-100` pour les libellés et états du registre, `:93` pour les lignes. L'état dédupliqué est écrit en `:171`.
- **Impact** : chaque cellule peut rétrécir sous la pression du texte agrandi ; le débordement est contenu à l'intérieur du panneau.
- **Risque** : le `min-width: 0` peut rendre une cellule très étroite ; le retour à la ligne (`wrap`, `flex-wrap`) évite la perte d'information.
- **Effort** : M.
- **Vérification** : capture 200 % — largeur totale des trois cellules ≤ largeur de `.e050-flex` ; aucun scrollbar horizontal dans le panneau.

## E050-07 — Cibles tactibles en px : hauteur en `em` qui suit le zoom

- **Problème / preuve** : `styles.css:236` fixe `min-height:38px` sur les boutons d'action et `chronology.js:55` `min-height:30px` sur les puces : ces cibles ne grandissent pas avec le zoom texte, ce qui détériore le confort d'usage (H.72) quand les caractères doublent.
- **Solution** : `E050.js:58-63` donne au bouton `#chronology-v2-e050-zoom` `min-height: 2.4em` et `padding: 0.5em 1em` : la cible s'agrandit proportionnellement au texte. L'état `:172` indique « hauteur doublée » à 200 % ; `:200` publie `data-e050-target="agrandi"`. Le focus visible est renforcé en `:64-66`.
- **Impact** : une cible tactile reste confortable et visiblement focalisable quel que soit le facteur de zoom.
- **Risque** : la hauteur `em` dépend de la police du bouton (`:62`, `1rem`) ; si la police du site change, la proportion est conservée, ce qui est souhaitable.
- **Effort** : S.
- **Vérification** : mesurer le bouton à 100 % et à 200 % — `min-height` calculé doublé ; Tab dessine l'anneau `:focus-visible` (`:64-65`) ; `aria-pressed` suit l'état (`:202`).

## E050-08 — Colonnes fixes : grille adaptative en largeurs fluides

- **Problème / preuve** : `styles.css:194` réserve `380px` à l'aside et `styles.css:205` exige `minmax(190px,1fr)` pour les cartes. À 200 %, ces planchers en pixels deviennent insuffisants et compriment le contenu ; `chronology.js:84-88` ne prévoit qu'un repli à 620 px, sans passage à une colonne sous contrainte de zoom.
- **Solution** : `E050.js:82-85` utilise `grid-template-columns: repeat(auto-fit, minmax(9rem, 1fr))` — un plancher en `rem` qui suit le zoom et laisse la grille se recomposer en colonnes (création des cellules en `:248-249`). L'état `:173` affiche `auto-fit / minmax(9rem,1fr)` et le facteur courant. Le repli mobile est documenté en `:102-105`.
- **Impact** : les trois colonnes de démonstration se réorganisent en une ou deux colonnes quand la place manque, au lieu de déborder.
- **Risque** : `auto-fit` change la disposition visuelle à 200 % ; c'est le comportement recherché, mais la lentille ne modifie pas la grille réelle de `styles.css:194` (fichier non possédé).
- **Effort** : M.
- **Vérification** : comparer les captures 100 % et 200 % — le nombre de colonnes diminue, aucune cellule ne sort du cadre ; `#chronology-v2-e050-panel` reste dans `#atlas-chrono-layout`.

## E050-09 — Zoom et contrastes : replis `forced-colors` et mouvement réduit

- **Problème / preuve** : `styles.css:106-107` neutralise globalement animations et transitions, mais le registre V2 expose `ctx.reducedMotion()` (`v2/registry.js:33-36`) sans que la vue n'affiche cet état. Un zoom forcé peut aussi rompre les couleurs de thème si aucun repli n'est prévu.
- **Solution** : `E050.js:106-108` désactive toute transition/animation du panneau en `prefers-reduced-motion`, `:109-116` fournit un repli `forced-colors: active` en `Canvas` / `CanvasText` pour les bordures, titres et cellules. `:270` lit `ctx.reducedMotion()`, `:272` publie `data-e050-reduced`, `:174` et `:189` écrivent l'état en texte visible.
- **Impact** : le panneau reste contrasté et sans mouvement parasite, y compris en mode couleurs forcées et quand le texte est agrandi.
- **Risque** : le repli `forced-colors` écrase les teintes de thème ; c'est le comportement attendu pour garantir le contraste, aucune information n'étant portée par la seule couleur.
- **Effort** : M.
- **Vérification** : émuler `prefers-reduced-motion: reduce` → `data-e050-reduced="1"` et libellé « oui » ; émuler `forced-colors: active` → bordures `CanvasText`, aucun texte illisible ; aucune animation définie dans `E050.js`.

## E050-10 — Re-render : unicité des IDs, du CSS, de l'écouteur et de l'état

- **Problème / preuve** : `chronology.js:540-541` appelle `runEnhancementsV2` à chaque rendu et `v2/registry.js:39-42` rejoue les greffons en isolant leurs erreurs ; `v2/registry.js:13-19` ne garantit que l'unicité du `<style>`. Ni les nœuds, ni l'écouteur, ni l'état de zoom ne sont protégés par le registre. `v2/index.js:50` importe `./E050.js` : le stub initial devait être remplacé sans toucher ce point d'entrée.
- **Solution** : `E050.js:145-153` fournit `ensureNode()` avec garde d'existence et déplacement dans le parent courant ; `:24` et `:226` imposent un seul `CSS_ID` / un seul `ctx.css` ; `:265-268` un seul `addEventListener('click')` sous garde `data-e050-bound` ; `:278` un seul `register('E050', install)`. Les compteurs et le niveau de zoom (`:134-135`) survivent aux rendus sans créer de nœud ; `:156-158` déduplique les écritures ; `:273-274` publie les données d'installation.
- **Impact** : aucun doublon de panneau, de bouton ou de feuille de style après navigation aller-retour ; le zoom choisi est conservé ; aucune fuite d'écouteur sur une longue session.
- **Risque** : un nœud retrouvé dans un ancien parent détaché est déplacé, jamais cloné ; ses `data-e050-*` sont réécrits à chaque rendu (`:199-200`, `:272-274`), donc jamais périmés. Le registre neutraliserait silencieusement une erreur : `node --check` et les gardes sont la première ligne de défense.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E050.js` → PASS ; relecture — un seul `register`, un seul `ctx.css`, un seul `addEventListener`, neuf IDs DOM tous préfixés `chronology-v2-e050-` plus dix lignes de registre préfixées ; rejeu rendu → navigation → rendu : un seul `#chronology-v2-e050-panel`, un seul `<style id="chronology-v2-e050">`, `zoomLevel` conservé.

## Blocages / limites inter-domaines

- Le panneau est une démonstration autonome : il ne peut pas corriger les `font-size: 8–9 px` de `chronology.js:39-66`, les colonnes fixes de `styles.css:194, 205` ni l'`overflow: hidden` de `styles.css:102` — tous fichiers non possédés (passe 1 et CSS global).
- Le bouton simule le facteur de zoom sur le panneau via une variable CSS ; il ne pilote pas le zoom du navigateur. Une validation « vue entière à 200 % » relève de l'agent maître (captures 1658×1150 et 390×844).
- Aucune région live n'est ajoutée : l'annonce de zoom est visible mais non annoncée spontanément, faute de `say()` dans le registre V2 (`v2/registry.js:28-37`).
- L'état du panneau (niveau de zoom, compteur d'installations, préférence de mouvement) est volatile au sens du contrat : il est recalculé à chaque rendu, mais `zoomLevel` et `installCount` sont conservés au niveau module pour la session.
- Le respect de `prefers-contrast` au-delà du seul `forced-colors` n'est pas traité ici : il relève de la lentille H077 dédiée.
