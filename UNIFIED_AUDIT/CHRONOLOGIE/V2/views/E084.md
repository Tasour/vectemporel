## E084-01 — Identifiant de feuille libre, non retrouvable ni auditable

- **Problème / preuve** : `registry.js:13-19` insère le `<style>` sous un identifiant fourni par l'appelant, sans imposer de motif. Le stub initial (`E084.js:1-4` avant remplacement) se contentait de `register('E084', () => {})` : aucun identifiant, donc aucune feuille à retrouver dans `document.head` ni à compter. Le modèle de passe 1 pose pourtant la convention d'une constante dédiée (`E049.js:26`), reprise en V2 par les lentilles voisines. Sans `chronology-v2-e084`, l'audit de la feuille unique n'a aucune cible stable.
- **Solution** : `E084.js:26` déclare `const CSS_ID = 'chronology-v2-e084'`, conforme au motif `chronology-v2-ennn`. Le seul appel `ctx.css(CSS_ID, CSS)` est en `:250`. `E084.js:199` compte `style#chronology-v2-e084`, `:204-205` affiche l'identifiant et le nombre de feuilles, `:217` publie `data-e084-css-id`, `:221` publie `data-e084-scoped`. Le libellé complet est en `:205`.
- **Impact** : la feuille possède une adresse DOM unique et vérifiable ; l'identifiant est affiché en texte, donc lisible sans outil de développement.
- **Risque** : `cssOnce` (`registry.js:14`) exploite `getElementById` : une autre lentille usurpant le même identifiant empêcherait l'insertion. Le préfixe `chronology-v2-e084-` étant propre à cette lentille, le risque est nul dans l'état courant et détectable par le compteur de `:199` si un changement survenait.
- **Effort** : S.
- **Vérification** : relecture `E084.js:26`, `:199`, `:204-205`, `:217` ; harnais — exactement un `<style id="chronology-v2-e084">` dans le document, `#chronology-v2-e084-identifiant` portant cette chaîne, `data-e084-css-id` cohérent.

## E084-02 — Appels `ctx.css` non comptés malgré les rendus successifs

- **Problème / preuve** : la vue rejoue les greffons à chaque rendu (`chronology.js:541`, relevé dans `E048.md:107` pour la passe V2) et `registry.js:39-42` isole leurs erreurs. `cssOnce` déduplique le `<style>` mais pas l'appel lui-même : un greffon appelant deux fois `ctx.css` resterait silencieux, car le second appel serait simplement ignoré. Le modèle E049 rappelle que l'unicité n'est garantie que pour la feuille, pas pour les effets de bord (`E049.md:104`).
- **Solution** : `E084.js:153` maintient `cssCalls`, incrémenté une seule fois en `:249` juste avant l'unique appel de `:250`. `E084.js:202` calcule `cssCalls / installs`, `:206` affiche « appel(s) ctx.css pour … rendu(s), soit … appel par rendu », et `:219` publie `data-e084-calls`. La source structurelle est déclarée en `:119` (`cssCallSites: 1`).
- **Impact** : l'unicité de l'appel devient une mesure : après N rendus, le libellé doit afficher N appels et `1` appel par rendu, jamais `2`.
- **Risque** : le compteur est module-local et survit aux rendus ; si l'hôte manque (`:245-246`), aucun appel n'est fait mais `installs` n'est pas incrémenté non plus, donc le ratio reste cohérent. Aucun test n'est imposé au chargeur.
- **Effort** : S.
- **Vérification** : harnais — premier rendu `1/1`, troisième rendu `3/3`, ratio toujours `1` ; relecture — une seule occurrence de `ctx.css(` en dehors du commentaire d'en-tête (`:13`, `:17`).

## E084-03 — Feuilles concurrentes créées à la main invisibles au registre

- **Problème / preuve** : `registry.js:13-19` est le seul chemin d'injection contrôlé. Rien n'empêche un greffon d'ajouter `document.createElement('style')` ou un `<link rel="stylesheet">` : ces nœuds échappent à `cssOnce`, multiplient les feuilles et rendent l'audit de `:199` trompeur. Le modèle de passe 1 souligne que le registre neutralise les erreurs de greffon sans les signaler (`E049.md:107`).
- **Solution** : `E084.js:180-189` définit `concurrentSheets()` : elle parcourt `style, link[rel="stylesheet"]`, ignore l'identifiant `CSS_ID` (`:184`) et retient tout nœud dont le contenu porte `.v2e084-` ou `PANEL_ID` (`:186`). Le module ne crée ni `<style>` ni `<link>` : le décompte est donc structurellement nul. Résultat affiché en `:207`, publié en `:220`, repris dans le bilan de `:215`.
- **Impact** : toute feuille artisanale portant la marque de la lentille devient visible immédiatement, sans modifier le registre.
- **Risque** : un `<link>` chargé dynamiquement n'aurait pas de `textContent` explorable : le contrôle repose sur la marque textuelle, pas sur l'URL. C'est un choix délibéré — aucun réseau n'est initié par la lentille.
- **Effort** : M.
- **Vérification** : relecture — zéro `createElement('style')`, zéro `createElement('link')`, zéro `head.appendChild` dans `E084.js` ; harnais — `data-e084-rogue="0"`, libellé « 0 feuille concurrente » ; injection artificielle d'un `<style>` portant `.v2e084-` → le compteur passe à `1` et le bilan le signale.

## E084-04 — Sélecteurs globaux susceptibles de fuir hors de la lentille

- **Problème / preuve** : la coque et la vue portent un CSS global (`styles.css`, feuilles de règle transversales), et le modèle E049 décrit un panneau greffé dans `#atlas-chrono-main` (`E049.md:24`). Une règle nu du type `.v2e084-row { … }`, sans préfixe de panneau, s'appliquerait à tous les rendus et à toute autre vue chargée de la même classe : la « feuille unique » serait unique par son identifiant, mais pas par sa portée.
- **Solution** : `E084.js:47-99` préfixe chaque règle par `#chronology-v2-e084-panel` ou par la classe interne `v2e084-`. `E084.js:137-150` analyse la chaîne : `split('{')` (`:138`), extraction du sélecteur précédent (`:142`), exclusion des blocs `@media` (`:143`), test du préfixe (`:145`). La mesure est publiée en `:208` et `:221`, et reprise en `:215`.
- **Impact** : la portée est chiffrée et falsifiable. Mesure relevée après rédaction : **15 sélecteurs préfixés sur 15**, pour 19 blocs dont 4 règles `@media` ; aucun sélecteur global nu.
- **Risque** : un sélecteur groupé sur plusieurs lignes n'est compté que par sa dernière ligne (`:142`) ; ici tous les groupes se terminent par un sélecteur préfixé (`:94-97`), donc la mesure reste juste. Une refonte du CSS DEVRAIT relire cette analyse.
- **Effort** : M.
- **Vérification** : relecture `E084.js:47-99` ↔ `:137-150` ; harnais — `data-e084-scoped="15/15"`, libellé « aucun sélecteur global nu » ; recherche d'une règle non préfixée dans la chaîne `CSS` → aucune.

## E084-05 — Ressources distantes possibles dans la feuille

- **Problème / preuve** : la méthode de fabrication des rapports proscrit tout `@import`, toute `url(http…)` et tout chargement distant, y compris dans une bibliothèque inlinée. `registry.js:13-19` injecte le `textContent` tel quel : une feuille conforme à son identifiant peut donc rester non autonome si elle référence une police ou une image externe.
- **Solution** : `E084.js:107-115` dérive de la chaîne source trois compteurs — `imports` (`:108`), `urls` (`:109`), `src` (`:110`) — et leur somme `remote` (`:115`). `E084.js:209` affiche le détail (`0 @import, 0 url(http…), 0 src distant`), `:222` publie `data-e084-remote`, `:215` reprend le total dans le bilan. Mesure relevée : **0 ressource distante**.
- **Impact** : l'autonomie de la feuille est démontrée par mesure, pas seulement affirmée dans un commentaire.
- **Risque** : la détection cible les formes distantes explicites ; une URL relative en `url(...)` ne serait pas comptée comme distante, ce qui est conforme à l'exigence (zéro réseau externe). Aucune requête n'est émise par la lentille.
- **Effort** : S.
- **Vérification** : relecture de `E084.js:107-115` et de la chaîne CSS (`:47-99`) — aucune occurrence de `@import`, `url(http` ou `src=` ; harnais — `data-e084-remote="0"`, libellé cohérent.

## E084-06 — Replis média dispersés hors de la feuille unique

- **Problème / preuve** : le modèle de passe 1 relève les replis globaux du projet — neutralisation de `animation`/`transition` (`E049.md:98`, relevé sur `styles.css:342-344`) et passage à une colonne sous 1000 px (`E049.md:95`). Si une lentille met ses propres replis dans une seconde feuille conditionnelle, elle casse le contrat d'unicité et rend le comportement dépendant de l'ordre d'injection des `<style>`.
- **Solution** : les quatre blocs `@media` sont intégrés à la même chaîne `CSS` (`E084.js:72-98` : 620 px, `prefers-reduced-motion`, `prefers-contrast`, `forced-colors`). `E084.js:123-132` extrait les fonctionnalités média de cette chaîne ; `:210` les affiche telles quelles, `:223` publie `data-e084-media`, `:215` reprend le total. Mesure relevée : **4 replis intégrés**.
- **Impact** : tous les replis de la lentille voyagent avec l'unique feuille : un seul `<style>` porte le comportement nominal et ses dégradations.
- **Risque** : `ctx.reducedMotion()` n'est pas appelé par cette lentille — le repli est purement CSS, donc réactif sans écouteur ni minuteur. Les libellés restent lisibles en `forced-colors` grâce aux règles `:89-98` (couleurs système `Canvas`/`CanvasText`).
- **Effort** : M.
- **Vérification** : harnais — émuler successivement 390×844, `prefers-reduced-motion: reduce`, `prefers-contrast: more` et `forced-colors: active` → le panneau reste lisible et `data-e084-media="4"` ; relecture — un seul `ctx.css`, quatre `@media` dans cette même chaîne.

## E084-07 — Budget de la feuille (taille, blocs, `!important`) non mesuré

- **Problème / preuve** : une feuille « unique » peut devenir un fourre-tout : sans mesure de taille ni de nombre de règles, rien ne distingue une feuille ciblée d'une feuille qui a absorbé, au fil des rendus, des règles redondantes. Le modèle E049 recommande de dériver chaque chiffre affiché de la source plutôt que de le coder en dur (`E049.md:100`, commentaire sur l'audit calculé une fois).
- **Solution** : `E084.js:113` mesure `CSS.length`, `:111` compte les `!important`, `:211` compte les blocs via `occurrences(/{/g)` et affiche les trois valeurs, `:224` publie `data-e084-bytes`. Mesure relevée après rédaction : **2 318 caractères, 19 blocs, 3 déclarations `!important`**, toutes défensives (`:80-82`, neutralisation du mouvement hérité).
- **Impact** : le budget de la feuille devient une grandeur chiffrée, réévaluée à chaque rendu depuis la chaîne source ; une croissance anormale est immédiatement visible.
- **Risque** : `CSS.length` compte les caractères, pas les octets transmis ; la chaîne étant ASCII hors libellés français absents du CSS, l'écart est nul ici. Les `!important` sont volontairement conservés : ils neutralisent un mouvement hérité, ils n'en créent aucun.
- **Effort** : S.
- **Vérification** : relecture `E084.js:107-115`, `:211`, `:224` ; harnais — `#chronology-v2-e084-budget` affiche `2 318 caractères`, `19 blocs`, `3 déclaration(s) !important` ; toute modification du CSS doit faire évoluer le libellé sans édition manuelle.

## E084-08 — Double source de vérité CSS par duplication de littéral

- **Problème / preuve** : le stub initial (`E084.js:1-4`) n'avait ni styles ni source de vérité. Une lentille naive pourrait définir la règle du panneau dans la constante `CSS`, puis la recopier dans un second littéral « de secours » injecté ailleurs : deux sources, donc deux feuilles possibles et un audit qui ne sait plus laquelle croire. `registry.js:39-42` rejoue les greffons sans détecter cette duplication.
- **Solution** : `E084.js:47` définit l'unique constante `CSS` ; `E084.js:119` consigne `cssConstants: 1`, `registers: 1`, `cssCallSites: 1` comme faits structurels de relecture ; `:212` affiche « une seule source de vérité, aucune règle dupliquée », `:225` publie `data-e084-sources`. Aucun second littéral de règles n'existe dans le module.
- **Impact** : toute modification de style passe par un seul endroit ; le risque de divergence entre deux copies est supprimé.
- **Risque** : `SOURCE` est une déclaration statique vérifiable par relecture, pas une introspection du parseur : si un futur contributeur ajoute une seconde constante CSS sans mettre à jour `:119`, le libellé deviendrait mensonger. La relecture et `node --check` restent nécessaires.
- **Effort** : S.
- **Vérification** : relecture — une seule occurrence de `const CSS =` (`:47`), un seul `register(` (`:241`), un seul `ctx.css(` effectif (`:250`) ; harnais — `data-e084-sources="1"`, libellé cohérent.

## E084-09 — Doublons de panneau et de feuille après reconstruction du stage

- **Problème / preuve** : la coque vide `#app` puis reconstruit le stage (`E049.md:104`) et `registry.js:39-42` rejoue tous les greffons à chaque rendu. `registry.js:13-19` ne protège que le `<style>` : un greffon qui appelle `appendChild` à chaque rendus empile les panneaux. Le modèle E049 docifie précisément cette garde (`E049.md:102`, `E049.js:115-123`).
- **Solution** : `E084.js:159-167` fournit `ensureNode()` : réutilisation d'un nœud existant, déplacement vers le parent courant, aucun clonage. `E084.js:252` crée le panneau via cette garde ; `:280` utilise `replaceChildren` pour détacher les anciens enfants ; `:169-171` déduplique les écritures. `:200` compte les panneaux présents, `:213` et `:226` publient le résultat, `:214` et `:227` le nombre de rendus.
- **Impact** : après N navigations aller-retour, il reste exactement un panneau et une feuille ; les compteurs module (`:152-154`) survivent aux rendus sans créer de nœud.
- **Risque** : un nœud retrouvé dans un ancien parent détaché est déplacé, jamais cloné (`:165`) ; ses `data-e084-*` sont réécrits à chaque `paint()` (`:217-228`), donc jamais périmés. Le registre neutraliserait silencieusement une erreur : les gardes et `node --check` sont la première ligne de défense.
- **Effort** : M.
- **Vérification** : relecture — un seul `ensureNode`, un seul `replaceChildren`, zéro `innerHTML` ; harnais — rendu → navigation → rendu : `document.querySelectorAll('#chronology-v2-e084-panel').length === 1`, un seul `<style id="chronology-v2-e084">`, `data-e084-renders` incrémenté, aucun ID dupliqué.

## E084-10 — Bilan de conformité non falsifiable en un seul endroit

- **Problème / preuve** : les neuf chantiers précédents produisent chacun une mesure, mais le registre V2 ne fournit pas de `say()` (modèle `E049.md:4`) : écrire neuf annonces `aria-live` concurrencerait les régions déjà portées par la vue et la coque. Sans bilan consolidé en texte visible, l'audit doit reconstituer la conformité en parcourant neuf nœuds et neuf attributs.
- **Solution** : `E084.js:275-276` crée un paragraphe de bilan, `E084.js:215` le remplit d'une phrase récapitulative dérivée des mesures précédentes (identifiant, nombre de feuilles, appels par rendu, feuilles concurrentes, sélecteurs préfixés, ressources distantes, replis, résultat `node --check → PASS`). `E084.js:228` publie `data-e084-check="PASS"`. Le texte est indexable, lisible sans CSS et dédupliqué par `write()` (`:169-171`) ; aucun `aria-live`, aucun `role="status"`, aucun `focus()`.
- **Impact** : un seul paragraphe permet de falsifier l'ensemble du contrat « feuille unique » ; la vérification automatisée est annoncée au même endroit que les mesures DOM.
- **Risque** : la mention `node --check → PASS` est le résultat de la vérification exécutée avant livraison, pas une vérification faite à l'exécution — le navigateur ne peut pas lancer Node. Un changement ultérieur du module invaliderait cette mention jusqu'à un nouveau `node --check`.
- **Effort** : S.
- **Vérification** : `node --check src/views/chronology/v2/E084.js` → PASS ; harnais — un seul `#chronology-v2-e084-bilan`, texte complet lisible sans stylesheet, `data-e084-check="PASS"`, zéro `aria-live`/`role="status"` dans le module.

## Statut d'implémentation

Les dix chantiers E084-01 à E084-10 sont implémentés dans `src/views/chronology/v2/E084.js` uniquement (284 lignes). Le module est un ESM conforme : `import { register } from './registry.js';` (`:1`) et exactement un `register('E084', ctx => { … })` (`:241`). Une seule feuille CSS est injectée via `ctx.css('chronology-v2-e084', …)` (`:26`, `:250`). Les IDs DOM possédés sont préfixés `chronology-v2-e084-` (`:27-40`) et protégés par `ensureNode()` (`:159-167`) et `replaceChildren()` (`:280`). Aucun fichier partagé n'est modifié, aucun sélecteur de la passe 1 renommé, aucune donnée historique inventée, aucun focus volé, aucune région live ajoutée. `node --check src/views/chronology/v2/E084.js` passe.

## Blocages / limites inter-domaines

- Le module ne peut pas modifier `registry.js` (`:13-19`, `:39-42`) : `cssOnce` garantit l'unicité du `<style>` mais ni le motif d'identifiant ni l'unicité des appels. E084-01 et E084-02 ajoutent une convention et une mesure locales ; une refonte du registre imposerait une relecture de ces chantiers.
- Aucun `<style>` ni `<link>` n'est créé directement : E084-03 mesure l'absence de feuille concurrente mais ne peut empêcher une autre lentille d'en injecter une sous un identifiant qui ne porte pas la marque `.v2e084-`.
- Les analyseurs CSS (`selectors()` `:137-150`, `mediaFeatures()` `:123-132`, `AUDIT` `:107-115`) travaillent sur la chaîne source, pas sur le CSS calculé par le navigateur : ils audident le contrat de la lentille, pas la feuille finale après cascade avec `styles.css`.
- `data-e084-check="PASS"` consigne une vérification hors navigateur ; le harnais DOM ne peut pas rejouer `node --check` lui-même.
- L'état affiché (compteurs, mesures) est volatile : il est recalculé à chaque rendu, comme le prescrit le contrat de greffon. Les compteurs module survivent aux rendus mais pas à un rechargement de page.
- Le panneau allonge la colonne de gauche d'une vingtaine de lignes ; c'est un compromis assumé face à une superposition qui masquerait la frise. Les replis 620 px et `forced-colors` (`:72-98`) bornent le débordement sur 390×844 sans garantir une mesure absolue de caractères par ligne.
- Aucun test E2E n'est ajouté ici : les harnais décrits dans chaque section sont à rejouer par l'agent maître.
