## E058-01 — Nom d'époque prioritaire (anti-anachronisme)

- **Problème / preuve** : la frise rend chaque repère comme une carte (`chronology.js:385-411`, `.event-card`) dont le titre est le libellé courant du point. Or un repère historique doit afficher le nom contemporain de l'événement, pas son nom actuel : sans champ dédié, le libellé courant se substitue silencieusement au nom d'époque et produit un anachronisme. Le squelette de carte ne prévoit aucun emplacement pour ce nom distinct.
- **Solution** : `E058.js:58-59` reconnaît les clés `historicalName`, `histName`, `nomEpoque`, `nameHistorical` ; `:240-242` les lit sans invention ; `:290` écrit le marqueur `Nom d’époque : …` dans `#chronology-v2-e058-p<N>-f01`, avec état `renseigne`/`absent` (`:308-310`). Le compteur de couverture est calculé en `:364` et affiché en `:382`, publié dans `data-e058-couverture` (`:411`). Le nom courant reste lu à part en `:261` : il n'est jamais écrasé.
- **Impact** : le nom contemporain devient la donnée principale lisible, et son absence est écrite « non renseigné » plutôt que comblée par une valeur de fantaisie.
- **Risque** : si la passe V2 expose le nom d'époque sous une clé hors de la liste de `:59`, le marqueur bascule en `absent` — l'absence reste honnête, mais la couverture est sous-estimée. La liste est volontairement explicite et documentée pour une extension rapide.
- **Effort** : M.
- **Vérification** : relecture `:58-59`, `:240-242`, `:290`, `:364`, `:382`, `:411` ; harnais — une carte avec `data-historical-name` doit produire `data-e058-etat="renseigne"` sur `-f01` et incrémenter `data-e058-couverture` ; une carte sans clé doit afficher « non renseigné » sans inventer de nom.

## E058-02 — Période de validité du nom (bornes d'usage)

- **Problème / preuve** : un nom historique n'a de sens que borné dans le temps. La carte de repère (`chronology.js:385-411`, styles `styles.css:194-217`) affiche une date d'événement mais aucune période d'usage du nom : le lecteur ne peut pas distinguer un nom valable à l'instant du fait d'un nom survivant plusieurs siècles.
- **Solution** : `E058.js:60-61` reconnaît `epochFrom`/`nameFrom`/`debutNom`/`validFrom` et `epochTo`/`nameTo`/`finNom`/`validTo` ; `:243-244` les décodent ; `:252-258` dérive la borne numérique avec `numeroDans()` (`:232-236`) ; `:291` affiche `Validité du nom : <début> → <fin>` dans `-f02`, en écrivant « non renseignée » pour chaque borne manquante ; `:365` et `:383` publient le compteur.
- **Impact** : la durée d'usage du nom devient explicite et lisible sans recalcul mental, y compris quand une seule borne est connue.
- **Risque** : les bornes sont des chaînes de texte (ex. « IVᵉ s. ») ; `numeroDans()` n'en extrait qu'un nombre pour le contrôle de cohérence (E058-07) et n'interprète pas les siècles — le libellé textuel, lui, est conservé intégralement en `:291`.
- **Effort** : M.
- **Vérification** : relecture `:60-61`, `:243-244`, `:252-258`, `:291` ; harnais — une carte avec `data-epoch-from="330"` et `data-epoch-to="1453"` doit afficher les deux bornes et incrémenter `data-e058-compte` de `#chronology-v2-e058-c02` ; sans borne, le texte « non renseignée » apparaît deux fois.

## E058-03 — Variantes orthographiques sans substitution

- **Problème / preuve** : les transcriptions alternatives d'un même nom (orthographes, latinisations) sont des données distinctes du nom d'époque. Le rendu de carte unique (`chronology.js:385-411`) n'offre qu'un titre : les variantes, lorsqu'elles existent dans les données, sont soit perdues, soit fusionnées dans le libellé, ce qui brouille le nom principal.
- **Solution** : `E058.js:62` reconnaît `variantes`, `aliases`, `nameVariants`, `variantesNom` ; `:154-158` (`lireListe`) découpe la chaîne sur `|` ou `;` ; `:266` décode la liste ; `:292` affiche `Variantes orthographiques : …` dans `-f03` sans jamais remplacer `-f01` ; `:366` et `:384` tiennent le compteur dédié.
- **Impact** : les variantes deviennent consultables en parallèle du nom d'époque, chacune séparée par un séparateur explicite, sans ambiguïté sur le nom prioritaire.
- **Risque** : le séparateur `|` ou `;` est réservé ; une variante contenant ces caractères serait coupée. Le format est documenté en `:157` et reste sous le contrôle des données sources, non de la lentille.
- **Effort** : S.
- **Vérification** : relecture `:62`, `:154-158`, `:266`, `:292` ; harnais — `data-variantes="Byzantium|Byzanz"` doit produire deux entrées séparées par « · » dans `-f03` et laisser `-f01` intact.

## E058-04 — Noms concurrents maintenus (contestation)

- **Problème / preuve** : plusieurs noms peuvent coexister pour un même lieu à la même époque selon les sources. Le modèle de point `(S,R,O,T,E,D,Src,C)` porte une composante de confiance, mais la fiche de détail ne dispose d'aucun affichage dédié aux noms rivaux : le risque est de trancher silencieusement en faveur du premier nom venu, ce qui efface la contestation.
- **Solution** : `E058.js:63` reconnaît `concurrents`, `nomsConcurrents`, `rivalNames` ; `:267` décode la liste ; `:293` affiche `Noms concurrents : …` dans `-f04`, avec repli « aucun renseigné » ; `:367` et `:385` comptent les repères concernés et libellent explicitement « aucune contestation n'est tranchée par silence ».
- **Impact** : la pluralité des noms est préservée et visible ; aucun arbitrage n'est introduit par la lentille.
- **Risque** : la lentille ne juge pas la légitimité des noms concurrents — elle les affiche tels quels. Un tri ou une pondération relèverait d'une lentille de confiance (domaine E), pas d'E058.
- **Effort** : S.
- **Vérification** : relecture `:63`, `:267`, `:293`, `:367`, `:385` ; harnais — `data-concurrents="Londinium|Lundinium"` doit produire les deux noms dans `-f04`, avec `data-e058-etat="renseigne"`, sans modifier `-f01`.

## E058-05 — Nom original et traduction étiquetée

- **Problème / preuve** : le nom d'époque est souvent un terme dans une langue historique (grec, latin, arabe). La carte de repère (`chronology.js:385-411`) n'associe ni attribut `lang` ni mention de traduction : le terme original est soit romanisé sans étiquette, soit remplacé par sa traduction, ce qui perd la langue d'origine.
- **Solution** : `E058.js:64-65` reconnaît `nameLang`/`langueNom`/`originalLang` et `originalName`/`nomOriginal`/`nameOriginal` ; `:245-246` les lisent ; `:294` affiche `Nom original (<langue>) : <nom>` dans `-f05`, avec « langue non renseignée » et « non renseigné » comme replis ; `:368` exige la présence conjointe de la langue et du nom pour incrémenter le compteur, affiché en `:386`.
- **Impact** : la langue du nom devient une métadonnée explicite, et la traduction n'est jamais présentée comme le nom original.
- **Risque** : la lentille n'écrit pas d'attribut `lang` sur un nœud existant (fichier non possédé) ; elle affiche la langue en texte. La pose effective d'un `lang` sur le terme reste à la charge de la vue, comme le note la section « Blocages ».
- **Effort** : M.
- **Vérification** : relecture `:64-65`, `:245-246`, `:294`, `:368`, `:386` ; harnais — une carte avec langue et nom original doit afficher les deux dans `-f05` ; avec une seule des deux, `data-e058-etat` reste `absent` et le compteur n'augmente pas.

## E058-06 — Suite de noms datée (relais dans le temps)

- **Problème / preuve** : un lieu change de nom au fil des ères ; ces renommages successifs sont des repères à part entière. La frise aligne les ères (`chronology.js:284-305`) et les cartes (`:385-411`) mais ne relie pas le nom contemporain d'un repère à son prédécesseur et à son successeur : la chaîne des noms est implicitement rompue à chaque carte.
- **Solution** : `E058.js:66-67` reconnaît `successeurs`/`renamedTo`/`nomsSuivants`/`successorNames` et la date `renamedAt`/`dateRenommage`/`renameDate` ; `:247-248` décodent la suite ; `:295` affiche `Suite de noms : A → B (renommage : date)` dans `-f06`, sans toucher à `-f01` ; `:369` et `:387` publient le compteur de repères pourvus d'une suite datée.
- **Impact** : le relais des noms dans le temps devient lisible, avec la date de renommage lorsqu'elle est renseignée, et le nom d'époque du repère courant reste prioritaire.
- **Risque** : la suite est une donnée de la carte, pas un calcul de la lentille ; si la vue ne la fournit pas, le marqueur affiche « non renseignée ». Aucun nom n'est déduit d'une autre carte.
- **Effort** : M.
- **Vérification** : relecture `:66-67`, `:247-248`, `:295`, `:369`, `:387` ; harnais — `data-renamed-to="Constantinople|Istanbul"` et `data-renamed-at="1930"` doivent produire les deux noms reliés par une flèche et la date entre parenthèses dans `-f06`.

## E058-07 — Cohérence nom ↔ ère (contrôle d'époque)

- **Problème / preuve** : les ères sont des bandes distinctes (`chronology.js:284-305`, `.era-band`) et les repères des cartes (`:385-411`). Rien ne vérifie que la période de validité d'un nom (E058-02) contient bien l'année du repère : un nom médiéval peut être affiché sur un repère antique sans qu'aucun signal ne le trahisse.
- **Solution** : `E058.js:53-55` définit les sélecteurs de repères, de titres et d'ères ; `:208-217` remonte à la bande d'ère via `closest()` et lit son étiquette ; `:219-230` (`anneeDe`) cherche une année dans le dataset du repère ou de ses ancêtres ; `:232-236` (`numeroDans`) extrait les bornes ; `:252-258` compare et produit `coherente`, `incoherente` ou `indeterminee` ; `:296` affiche le résultat dans `-f07` avec le nom de l'ère ; `:370-372`, `:388` et `:399-403` publient les trois comptes (`data-e058-coherents`, `-incoherents`, `-indetermines`).
- **Impact** : une incohérence temporelle devient falsifiable et chiffrée, sans modifier les bandes ni les cartes de la vue.
- **Risque** : sans année exploitable ni bornes numériques, le contrôle est « indéterminé » et non « cohérent » — un choix délibéré pour ne pas prétendre à une vérification impossible (`:388`). Les siècles romains ne sont pas convertis : seule la borne textuelle est conservée.
- **Effort** : M.
- **Vérification** : relecture `:53-55`, `:208-236`, `:252-258`, `:296`, `:370-372`, `:399-403` ; harnais — année 1200 avec bornes 1000/1300 doit donner `coherente` ; année 900 doit donner `incoherente` ; absence d'année doit donner `indéterminée`.

## E058-08 — Forme courte et forme longue conservées

- **Problème / preuve** : les titres de cartes (`chronology.js:385-411`) sont parfois des sigles ou des formes abrégées. Sans forme longue associée, le lecteur ne peut pas résoudre l'abréviation ; et la remplacer par sa forme longue ferait perdre la forme effectivement en usage à l'époque.
- **Solution** : `E058.js:68` reconnaît `longForm`/`fullName`/`formeLongue` ; `:273` lit la valeur ; `:297` affiche `Forme longue conservée : …` dans `-f08`, avec « non renseignée » en repli ; `:373` et `:389` tiennent le compteur dédié. La forme courte, lue en `:261`, n'est jamais modifiée.
- **Impact** : la forme courte et son développement coexistent, chacun identifiable, sans écrasement de la forme d'époque.
- **Risque** : la lentille ne pose pas d'élément `<abbr title>` sur le titre existant (fichier non possédé) : le développement est affiché en texte dans le marqueur. La sémantique `<abbr>` relève de la vue.
- **Effort** : S.
- **Vérification** : relecture `:68`, `:261`, `:273`, `:297`, `:373`, `:389` ; harnais — `data-long-form="Republic of Venice"` doit apparaître dans `-f08` tandis que le titre de la carte reste inchangé.

## E058-09 — Provenance du nom avec repli d'omission

- **Problème / preuve** : le nom d'époque est une affirmation historique qui doit être sourcée. La vue possède un modèle de point avec composante source (`Src`) et une région live hors `#app` (`chronology.js:119-138`), mais aucun emplacement ne montre la provenance du nom lui-même ; une absence de source se traduit par un silence, ce qui est précisément le défaut dénoncé pour les omissions.
- **Solution** : `E058.js:69-70` reconnaît `nameSource`/`sourceNom`/`sourceName` et `nameOmission`/`omissionJustifiee`/`omissionNom` ; `:249-250` les lisent ; `:298` affiche la source dans `-f09`, sinon l'omission justifiée, sinon « Source du nom : non renseignée » ; `:374-375`, `:390` et `:404-407` publient `data-e058-sources` et `data-e058-omissions`. Aucune région live n'est écrite.
- **Impact** : toute absence devient un fait explicite et distinct d'une source fournie ; le lecteur voit la différence entre « sourcé », « omission justifiée » et « non renseigné ».
- **Risque** : la lentille ne juge pas la qualité de la source ; elle l'affiche. Une source invalide serait affichée telle quelle — le contrôle qualité relève du domaine des sources, pas d'E058.
- **Effort** : M.
- **Vérification** : relecture `:69-70`, `:249-250`, `:298`, `:374-375`, `:404-407` ; harnais — une carte avec `data-name-source` incrémente `data-e058-sources` ; une carte avec `data-name-omission` incrémente `data-e058-omissions` et affiche « Omission justifiée » dans `-f09`.

## E058-10 — Bilan de couverture des noms d'époque

- **Problème / preuve** : le rendu est rejoué à chaque navigation (`chronology.js:539`, `registry.js:39-42`) et le registre ne garantit que l'unicité de la feuille de style (`registry.js:13-19`). Aucun indicateur agrégé ne dit combien de repères portent effectivement un nom d'époque : le lecteur ne peut pas mesurer la couverture sémantique de la frise, ni constater qu'un filtrage l'a fait varier.
- **Solution** : `E058.js:354-359` initialise les compteurs ; `:361-376` les incrémente en parcourant les points ; `:378-380` calcule `couverture`, `total` et `pourcentage` ; `:391` rédige le bilan « Couverture des noms d’époque : x/y repères, soit n % » ; `:394-408` écrit chaque section et ses `data-e058-*` ; `:410-414` publie `data-e058-points`, `-couverture`, `-pourcentage`, `-reduit`, `-installations`. L'agrégat est dérivé du DOM, jamais codé en dur.
- **Impact** : la couverture devient une mesure chiffrée, stable entre rendus et réévaluée à chaque installation, qui rend visibles les régressions de données.
- **Risque** : le pourcentage est arrondi à l'entier le plus proche (`:380`) ; avec peu de repères, il peut être grossier. Le couple `couverture/total` reste publié en `data-*` pour un contrôle exact.
- **Effort** : M.
- **Vérification** : relecture `:354-380`, `:391`, `:394-414` ; harnais — 10 repères dont 3 pourvus d'un nom d'époque doivent donner `data-e058-points="10"`, `data-e058-couverture="3"`, `data-e058-pourcentage="30"` ; navigation aller-retour → une seule section `#chronology-v2-e058-c10` et compteurs cohérents.

## Blocages / limites inter-domaines

- La vue et son CSS globaux (`src/views/chronology.js`, `styles.css`) ne sont pas possédés : la lentille ne peut ni poser d'attribut `lang` sur le terme original (E058-05), ni insérer d'élément `<abbr title>` sur le titre court (E058-08), ni réordonner les cartes pour matérialiser la suite des noms (E058-06). Elle se limite à des marqueurs textuels adjacents.
- Le registre (`registry.js:13-19`) ne garantit que l'unicité du `<style>` ; l'unicité des nœuds repose sur `assurerNoeud` (`:162-170`) et sur le fait que la coque reconstruit le stage. Un nœud retrouvé dans un parent détaché est déplacé, jamais cloné.
- Les données de noms (clés de `CLES`, `:58-71`) doivent être exposées en `data-*` par la passe V2. Si une clé change de nom, seul le tableau `:58-71` est à mettre à jour ; la lentille ne devine pas les clés et n'invente pas de valeurs de remplacement.
- Le contrôle de cohérence (E058-07) dépend d'années ou de bornes numériques exploitables ; sans elles, il affiche « indéterminée » plutôt qu'un résultat positif supposé.
- Aucun écouteur d'événement n'est installé : le panneau reflète l'état du DOM à chaque appel d'installation. Un changement de filtre sans re-render complet n'est pas détecté par E058 — l'actualisation relève du cycle de rendu de la vue (domaine G/performance).
- L'état du panneau (compteurs, préférence de mouvement) est volatile et recalculé à chaque rendu, comme le prescrit le contrat de greffon.
