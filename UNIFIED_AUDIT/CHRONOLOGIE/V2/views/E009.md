## E009-01 — Infobulle native réduite à une plage d'années, sans structure

- **Problème / preuve** : `chronology.js:285-298` construit chaque ère comme un `<button>` portant deux `<span>` (nom, plage) ; le seul mécanisme d'infobulle est `band.title = …` (`chronology.js:293`). Le bloc de navigation (`chronology.js:278-308`) ne contient aucun nœud `role="tooltip"` : l'information est une ligne de texte brut, non structurée, non annonçable, dont l'apparence dépend du navigateur.
- **Solution** : `E009.js:19-25` réserve les identifiants préfixés ; `:30-52` définit la feuille de l'infobulle ; `:297-301` crée un unique `#chronology-v2-e009-tip` avec `role="tooltip"` et `aria-hidden="true"` ; `:303-307` lui donne quatre enfants en texte (`strong` nom, plage, compte, état) créés par `ctx.el` ; `:204-217` pilote l'affichage. Le panneau d'état non modal est greffé en `:309-317`.
- **Impact** : l'infobulle devient un composant lisible, structuré et observable, sans modifier le balisage de la frise.
- **Risque** : `position:fixed` dans un `stage` reconstruit à chaque rendu (`chronology.js:539`) — la garde `ensureNode` (`E009.js:95-106`) évite tout nœud orphelin. Le `z-index:40` (`:33`) reste sous les modales de la coque, non possédée ici.
- **Effort** : M.
- **Vérification** : un seul nœud `role="tooltip"`, quatre enfants textuels, `aria-hidden` qui bascule entre `true` et `false` ; aucun `role="dialog"`, aucun `<div>` superposé couvrant la frise.

## E009-02 — Aucune grandeur chiffrée : le compte de repères reste hors infobulle

- **Problème / preuve** : `chronology.js:293` ne compose le `title` qu'avec `formatYear(start) → formatYear(end)` (`chronology.js:27-29`). Le compte de repères par ère n'est calculé que dans l'annonce vocale du clic (`chronology.js:302`) et dans le `status` global (`chronology.js:255-256`) : il est absent de l'infobulle, donc invisible au survol.
- **Solution** : `E009.js:108-113` réplique la règle de formatage des années sans aucune date codée en dur ; `:138-148` dérive le compte du DOM rendu en filtrant `#atlas-chrono-events > li` sur `data-era-id` (`chronology.js:378-382`) ; `:150-168` `fillTip()` écrit nom, amplitude, compte et état, et publie `data-e009-start`, `data-e009-end`, `data-e009-count` sur l'infobulle.
- **Impact** : trois grandeurs vérifiables sont désormais visibles en une seule infobulle ; la mesure est recalculée depuis le DOM, pas recopiée du store.
- **Risque** : le compte est un instantané du filtre courant (`chronology.js:376-382`) : il varie avec la recherche et doit être lu comme « repères affichés de l'ère », hypothèse explicite dans le libellé `:161`.
- **Effort** : M.
- **Vérification** : survol d'une bande → texte `« N repère(s) dans cette ère »` ; `data-e009-count` égal au nombre de `li[data-era-id]` correspondants ; aucune année littérale dans le module.

## E009-03 — Double infobulle : le `title` natif concurrent n'est pas neutralisé

- **Problème / preuve** : `chronology.js:293` pose systématiquement `band.title`. Ajouter une infobulle DOM sans neutraliser cet attribut produirait deux infobulles simultanées (native puis riche), avec des contenus divergents ; le `title` natif est en outre mal restitué par les lecteurs d'écran.
- **Solution** : `E009.js:121-136` `neutralizeTitles()` lit l'ancien `title`, le conserve dans `data-e009-native-title`, vide l'attribut (`:132`) et marque la bande `data-e009-title-off="1"` (`:133`) ; le CSS `:52` transforme le curseur en `help` pour signaler la présence de l'infobulle. Le compte de neutralisations est affiché dans le panneau (`:196`).
- **Impact** : une seule infobulle, riche et accessible ; l'information d'origine n'est pas perdue puisqu'elle reste dans le dataset.
- **Risque** : vider un attribut de la vue modifie un nœud non possédé ; relecture de `chronology.js:285-305` : aucun sélecteur de test ni logique de clic ne dépend de `band.title`.
- **Effort** : S.
- **Vérification** : sur chaque bande, `getAttribute('title') === ''` et `data-e009-native-title` contient l'ancienne plage ; au survol, un seul encadré visible.

## E009-04 — Survol muet : aucun déclencheur pointeur maîtrisé

- **Problème / preuve** : `chronology.js:299-303` n'attache qu'un écouteur `click` à la bande. Le survol ne déclenche que l'infobulle native du navigateur : aucun délai, aucun compte, aucune possibilité de borne ou de repli.
- **Solution** : `E009.js:249-258` `onOver()` et `:260-269` `onOut()` sont délégués sur `document` une seule fois (`:341-347`) et résolvent la bande via `closest()` (`:241-247`) ; `:232-239` `sync()` donne la priorité au focus ; `:213` publie `data-e009-source="survol"`. Aucun `setTimeout` : ouverture immédiate, latence nulle.
- **Impact** : l'infobulle apparaît au survol avec un coût constant, sans timer ni boucle d'animation.
- **Risque** : `pointerout` vers un enfant de la même bande est filtré par `band.contains(next)` (`:265-266`) pour éviter un clignotement ; un focus encore posé sur une bande garde la priorité sur le survol, comportement assumé.
- **Effort** : M.
- **Vérification** : `pointerover` sur `.era-band` → `data-e009-visible="1"` et compteur de survol incrémenté dans le panneau (`:199`) ; `pointerout` hors bande → `data-e009-visible="0"`.

## E009-05 — Aucun équivalent clavier ni description associée à la bande

- **Problème / preuve** : chaque bande est un `<button>` (`chronology.js:285-286`), donc focalisable au Tab, mais `:291-298` ne pose aucun `aria-describedby` : l'infobulle native ne s'affiche pas au clavier et le lecteur d'écran n'a accès qu'au nom et à la plage déjà dans les `<span>`.
- **Solution** : `E009.js:271-290` écoute `focusin`/`focusout` en délégation ; `:202-217` `show()` pose `aria-describedby=TIP_ID` sur la bande active et le retire de la précédente (`:209-210`) ; `:219-230` `hide()` nettoie l'attribut à la sortie. L'infobulle porte `role="tooltip"` (`:298`) et `aria-hidden="false"` uniquement pendant l'affichage (`:215`), jamais `aria-live`.
- **Impact** : Tab sur une bande affiche exactement la même infobulle que le survol, sans déplacer le focus ni intercepter une touche.
- **Risque** : l'infobulle est `aria-hidden` hors focus : un lecteur d'écran ne la lit que pendant la focalisation, choix délibéré pour ne pas ajouter de bavardage (cf. E041). Aucun `focus()`, aucun `preventDefault`, aucun `keydown` dans le module.
- **Effort** : M.
- **Vérification** : Tab sur une bande → `aria-describedby="chronology-v2-e009-tip"` et `data-e009-source="focus"` ; Tab sur la bande suivante → l'ancien `aria-describedby` a disparu ; Échap reste géré par le routeur.

## E009-06 — Position non maîtrisée, risque de débordement à 390 px

- **Problème / preuve** : le `title` natif est positionné par le navigateur (`chronology.js:293`). La frise, elle, passe à `flex:1 1 45%` sous 620 px (`chronology.js:85`) avec des bandes en `flex-direction:column` (`:44`) : aucune règle de la vue ne borne une infobulle, qui peut sortir de l'écran sur une bande de bord.
- **Solution** : `E009.js:170-191` `place()` calcule la position depuis `getBoundingClientRect()`, borne `left` à 8 px des bords et replie l'infobulle sous la bande quand la place manque au-dessus ; `:32-38` pose `position:fixed` et `max-width:min(320px, calc(100vw - 16px))`, `:66-68` renforce le plafond à 620 px ; `:189-190` publie `data-e009-placement` et `data-e009-clamped`.
- **Impact** : aucune infobulle hors viewport, y compris en 390×844 et en paysage étroit ; le mode de repli est mesurable.
- **Risque** : `offsetWidth`/`offsetHeight` valent 0 au tout premier affichage : un repli explicite de 260×80 px est prévu en `:176-177` ; le bornage n'est donc qu'approximatif sur cette unique frame.
- **Effort** : M.
- **Vérification** : en 390×844, survol d'une bande de bord → `data-e009-clamped="1"`, `left` dans `[8, vw - tipW - 8]`, `top ≥ 8` ; aucune barre de défilement horizontale ajoutée.

## E009-07 — Risque de modale ou de piège de focus sur une infobulle naïve

- **Problème / preuve** : `chronology.js:278-308` ne définit aucun modèle d'infobulle. Une implémentation courante (calque plein écran + `focus()` + `role="dialog"`) bloquerait la frise, volerait le focus et casserait la restauration `applyFocusIntent()` (`chronology.js:542`).
- **Solution** : `E009.js:31-40` impose `display:none` par défaut, `pointer-events:none`, aucun `tabindex`, aucun `role="dialog"`, et `data-e009-modal="0"` (`:300`) ; le panneau d'état reste un bloc en flux (`:54-64`, `:309`). Le module ne contient aucun appel à `focus()` et aucun gestionnaire de touche.
- **Impact** : l'infobulle ne reçoit ni clic ni focus ; Tab continue de traverser les bandes et les cartes exactement comme avant.
- **Risque** : le `z-index:40` (`:33`) place l'infobulle sous les modales de la coque, fichier non possédé : à rejouer avec l'aide modale ouverte.
- **Effort** : S.
- **Vérification** : `getComputedStyle(tip).pointerEvents === 'none'` ; zéro `tabindex` sur le tooltip ; Tab ne s'arrête jamais sur lui ; relecture — zéro `.focus(` et zéro `addEventListener('keydown'` dans `E009.js`.

## E009-08 — Mouvement réduit non appliqué à une infobulle

- **Problème / preuve** : `chronology.js:90-91` neutralise les transitions de `.era-band, .event-card, .atlas-chrono-tag` uniquement ; aucune règle de la vue ne couvrirait une infobulle ajoutée par une lentille. Le registre V2 fournit `ctx.reducedMotion()` (`registry.js:33-36`) mais la vue n'expose aucun état de préférence.
- **Solution** : `E009.js:69-71` impose `transition:none !important` et `animation:none !important` sur l'infobulle en `prefers-reduced-motion` ; `:321-323` lit `ctx.reducedMotion()` et publie `data-e009-reduced` sur l'infobulle et le panneau, répété en texte via `:199`. Aucune animation n'est créée : l'affichage est instantané dans tous les cas.
- **Impact** : aucun mouvement parasite, préférence système observable sans écouteur média supplémentaire.
- **Risque** : `ctx.reducedMotion()` est la source vivante (pas d'abonnement à `change`) : la valeur est rafraîchie à chaque rendu, comme pour E049 ; un changement de préférence sans rendu n'est pas capté.
- **Effort** : S.
- **Vérification** : émuler `prefers-reduced-motion: reduce` → `data-e009-reduced="1"` et libellé « mouvement réduit : oui » ; aucune propriété `transition`/`animation` non neutralisée dans la feuille E009.

## E009-09 — État « ère courante » porté par la seule couleur

- **Problème / preuve** : `chronology.js:46` distingue l'ère courante par `border-color:var(--gold)` et `box-shadow:inset 0 -2px var(--era)` : en `forced-colors` ou dans une infobulle, rien ne dit textuellement que l'ère consultée est la courante.
- **Solution** : `E009.js:162` écrit « Ère courante » ou « Ère consultable » dans un `<span>` dédié (`:306`) ; `:167` publie `data-e009-current`, `:48-51` ajoute une étoile décorative via `::before` ; `:72-78` fournit un repli `forced-colors` en `Canvas`/`CanvasText` pour l'infobulle et ses quatre textes.
- **Impact** : double codage texte + forme, contraste préservé, état compréhensible sans couleur.
- **Risque** : l'étoile issue de `content` est purement décorative : l'information reste portée par le texte, donc intacte si les pseudo-éléments sont ignorés. Le repli `forced-colors` n'est validé que par relecture, sans émulation matérielle ici.
- **Effort** : S.
- **Vérification** : focaliser l'ère portant `aria-current="true"` → texte « Ère courante », `data-e009-current="1"` ; émuler `forced-colors: active` → bordure `CanvasText`, fond `Canvas`, texte lisible.

## E009-10 — Re-render : doublons d'IDs, de CSS et d'écouteurs

- **Problème / preuve** : `chronology.js:539-541` reconstruit le `stage` puis rejoue les greffons V2 à chaque rendu. `registry.js:13-19` ne garantit que l'unicité du `<style>` : ni les nœuds ni les écouteurs de la lentille ne sont protégés ; `index.js:9` importe le module une seule fois, mais `apply()` est rejoué.
- **Solution** : `E009.js:95-106` fournit `ensureNode()` avec garde d'existence et déplacement dans le parent courant ; `:19` et `:295` imposent un seul `CSS_ID` / un seul `ctx.css` ; `:341-347` posent quatre écouteurs délégués sous la garde `bound` ; `:89-93` dédupliquent les écritures ; `:350` déclare un seul `register('E009', install)`. Le compteur `renders` (`:83`, `:294`) est publié dans `data-e009-renders` (`:324`) et dans le panneau (`:199`).
- **Impact** : aucun doublon d'infobulle, de panneau ou de feuille de style après navigation aller-retour ; aucune fuite d'écouteur sur une longue session.
- **Risque** : `registry.js:39-42` neutralise silencieusement une lentille défaillante : `node --check` et les gardes d'existence sont la première ligne de défense. La garde `bound` n'est jamais réinitialisée — choix délibéré pour une délégation documentaire unique par session.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/v2/E009.js` → PASS ; rendu → navigation → rendu → un seul `#chronology-v2-e009-tip`, un seul `#chronology-v2-e009-panel`, un seul `<style id="chronology-v2-e009">`, compteur de rendus à 2.

## Blocages / limites inter-domaines

- Le balisage des bandes, le `title` natif, `navSay()` et le `status` appartiennent à `chronology.js` (`:285-305`, `:255-256`, `:302`) : la lentille les lit et neutralise l'attribut `title`, mais ne peut ni les remplacer ni corriger leur formulation.
- Le routeur clavier et Échap restent hors de portée : aucune touche n'est interceptée, aucune modale n'est créée ; la fermeture de l'infobulle suit uniquement la perte de survol/focus.
- `z-index:40` (`E009.js:33`) sous les modales de la coque : le comportement avec l'aide modale ouverte doit être rejoué par l'agent maître.
- Le compte de repères est un instantané du filtre courant (`chronology.js:376-382`) : il reflète les repères affichés, pas la couverture totale du pays.
- Aucune région live n'est ajoutée (E041) : l'infobulle n'est annoncée que pendant la focalisation de la bande, via `aria-describedby`.
- `ctx.reducedMotion()` n'est pas abonné aux changements de préférence : l'état est rafraîchi à chaque rendu, comme dans le modèle E049.
