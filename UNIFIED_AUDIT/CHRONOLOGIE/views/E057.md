# E057 — Infobulles et descriptions détaillées des événements (vue chronologie)

Lentille : E057. Fichier possédé : `src/views/chronology/E057.js`.
Lectures seules : `src/views/chronology.js`, `src/views/chronology/registry.js`, `src/views/chronology/index.js`, `styles.css` et le modèle `UNIFIED_AUDIT/MONDE/views/M07-raf-pause.md`.
Aucun fichier partagé modifié, aucun réseau, aucun aléa, aucune journalisation, aucun timer ni boucle d'animation propre au greffon. Les dix chantiers ci-dessous sont ceux du fichier E057.js seul. Tout le texte affiché est tiré du DOM réel de la chronologie : aucune donnée historique n'est fabriquée.

## E057-01 — Périmètre strict de lecture seule et invariants du greffon

- **Problème / preuve** : `renderChronology()` importe le store et la coque (chronology.js:6-7) puis confie un contexte construit par `runEnhancements({ viewId: 'chronology', stage, layout })` (chronology.js:539, registry.js:28-37). Un greffon qui importerait `chronology.js` créerait un second propriétaire du rendu. Le style de base est injecté dans un `stage` reconstruit (chronology.js:30-32, 210).
- **Solution** : un seul import (`E057.js:1`), un seul `register('E057', install)` (E057.js:362), un seul appel `ctx.css(CSS_ID, CSS)` (E057.js:337) avec `CSS_ID = 'chronology-e057'` (E057.js:13) et un bloc CSS unique (E057.js:22-52). Les identifiants créés sont tous préfixés `e057` (E057.js:14-18) et protégés par des gardes d'existence.
- **Impact** : aucune dépendance réseau, aucune écriture hors des nœuds possédés, comportement stable en rendu répété.
- **Risque** : un futur ajout d'appel réseau, d'aléa ou de journalisation casserait l'invariant ; la règle est énoncée en tête de fichier (E057.js:3-11) et vérifiable statiquement.
- **Effort** : faible — garde-fou de régression.
- **Vérification** : `node --check src/views/chronology/E057.js` → OK ; `grep -nE 'console\.|fetch|XMLHttpRequest|Math\.random|requestAnimationFrame|setTimeout|setInterval|IntersectionObserver' E057.js` → 0 ligne ; `grep -c 'ctx.css('` → 1 ; `grep -c "register('E057'"` → 1.

## E057-02 — Infobulle unique et survie aux reconstructions du DOM

- **Problème / preuve** : le `stage` est reconstruit à chaque rendu (chronology.js:30-31, 210, 538). Une infobulle greffée sur `stage` ou sur `layout` serait détruite et recréée à chaque changement d'ère ou de filtre.
- **Solution** : `ensureTooltip()` (E057.js:80-91) crée un unique nœud `#e057-tooltip` dans `<body>`, hors du `stage`, avec `getElementById` comme garde. Le nœud porte `role="tooltip"` et l'attribut `hidden` — jamais `aria-hidden`, afin qu'une référence `aria-describedby` puisse réellement l'annoncer.
- **Impact** : une seule infobulle dans le document, persistante, immédiatement réutilisable après un rendu.
- **Risque** : un nœud détaché portant le même identifiant ne serait pas retrouvé par `getElementById` ; le greffon en crée alors un neuf sans doublon dans le document connecté.
- **Effort** : faible.
- **Vérification** : après trois sélections d'ères, `document.querySelectorAll('#e057-tooltip').length === 1` et le nœud reste `isConnected`.

## E057-03 — Déclenchement délégué, souris et clavier

- **Problème / preuve** : les cartes de repères sont recréées à chaque rendu (chronology.js:375-412) avec leur propre écouteur de clic (chronology.js:406-409) et une intention de focus (chronology.js:407). Attacher un écouteur d'infobulle directement sur chaque carte le perdrait au rendu suivant ou le dupliquerait.
- **Solution** : `ensureHooks()` (E057.js:210-216) enregistre une seule fois, sous la garde `hooksInstalled` (E057.js:64), quatre écouteurs délégués sur le document : `mouseover`, `mouseout`, `focusin`, `focusout`. `hoverable()` (E057.js:93-97) filtre sur `.event-card` ou `.e057-point` dans `.chronology-layout`, et ignore les mouvement internes via `relatedTarget` (E057.js:188-191, 195-198).
- **Impact** : même infobulle au survol et au focus ; équivalence clavier complète, sans réabonnement.
- **Risque** : un enregistrement réalisé à chaque `install()` provoquerait quatre handlers supplémentaires par rendu ; la garde module l'interdit.
- **Effort** : moyen — délégation et contrôle de filiation.
- **Vérification** : Tab jusqu'à une carte → infobulle visible ; sortie au clavier puis à la souris → infobulle masquée ; aucun doublon d'annonce après trois rendus.

## E057-04 — Contenu réel de l'infobulle et description associée à la carte

- **Problème / preuve** : la carte porte le millésime (chronology.js:392), le titre (chronology.js:393), le sous-titre (chronology.js:394) et son `<li>` porte `eventId`, `year`, `eraId`, `importance`, `tags` (chronology.js:378-383). Elle annonce seulement `aria-controls` vers la fiche (chronology.js:389) : aucun texte de synthèse ne lui est associé.
- **Solution** : `cardData()` (E057.js:101-112) lit ces champs sans inventer ; `tooltipLines()` (E057.js:120-133) compose « millésime — titre — sous-titre » puis « Ère / Importance / Thèmes » ; `showTip()` pose `aria-describedby="e057-tooltip"` sur la carte (E057.js:168) et `hideTip()` le retire uniquement si la valeur lui appartient (E057.js:150-152).
- **Impact** : la synthèse du repère est vocalisée au focus, avec les seules valeurs présentes dans la page.
- **Risque** : un champ absent (recherche filtrée, ère sans libellé) est neutralisé par des replis textuels explicites (E057.js:132) plutôt que par une valeur fabriquée.
- **Effort** : faible.
- **Vérification** : focaliser une carte → `getAttribute('aria-describedby') === 'e057-tooltip'` ; le texte de l'infobulle contient exactement l'année, le titre et les thèmes affichés sur la carte.

## E057-05 — Description détaillée en texte long, visible et indexable

- **Problème / preuve** : la fiche (chronology.js:221-223) contient le résumé (chronology.js:439), les points (chronology.js:461-504) et les sources (chronology.js:489-499), mais aucun texte long continu qui relie ces éléments ; le titre des points est un simple `h3` (chronology.js:462-464).
- **Solution** : `ensureDetail()` et `fillDetail()` (E057.js:230-296) ajoutent un `<details id="e057-detail">` natif dans l'aside, avec `<summary>` (E057.js:284), le résumé en `<p>` (E057.js:239-240), la liste intégrale des points (E057.js:242-257) et leurs sources. Le contenu n'est ni dans un `aria-hidden`, ni généré par une infobulle : il reste dans le DOM et dans le texte visible.
- **Impact** : description détaillée lisible à l'écran, parcourable et indexable ; ouverture/fermeture natives au clavier, sans JavaScript pour le mécanisme `<details>`.
- **Risque** : l'aside étant reconstruit, un ancien `#e057-detail` détaché pourrait être réutilisé à tort ; le contrôle `isConnected` et le déplacement vers le nouvel aside (E057.js:279-288) écartent ce risque, et une clé `data-e057-key` (E057.js:223-228, 292) ne régénère le texte que quand le repère change.
- **Effort** : moyen — assemblage du texte long et garde multi-rendus.
- **Vérification** : ouvrir le résumé → un `<li>` par point, avec son texte intégral et ses sources ; `document.querySelectorAll('#e057-detail').length === 1` après trois rendus.

## E057-06 — Positionnement borné et infobulle non interactive

- **Problème / preuve** : la grille de la chronologie place un aside de 380 px en colonne avec débordement propre (styles.css:193-196). Une infobulle positionnée en flux ou en absolu dans la carte serait tronquée par `overflow` et masquerait le contenu voisin.
- **Solution** : `showTip()` (E057.js:159-184) place l'infobulle en `position: fixed`, la Centre horizontalement sur la cible, bascule sous la cible si la place manque au-dessus, et borne les deux axes à 8 px de la fenêtre. Le CSS (E057.js:23-29) impose `pointer-events: none` et une largeur maximale responsive.
- **Impact** : aucun chevauchement ni débordement ; le clic sur la carte continue d'appartenir à `selectEvent()` (chronology.js:406-409).
- **Risque** : sur une fenêtre très étroite, l'infobulle pourrait dépasser ; les bornes et la règle `@media (max-width:620px)` (E057.js:47-49) maintiennent le nœud dans le viewport.
- **Effort** : moyen — calcul de position sans timer.
- **Vérification** : rendus 1658×1150 et 390×844 — l'infobulle reste entièrement visible ; un clic sur la carte sous infobulle sélectionne bien le repère.

## E057-07 — Points parcourables au clavier et infobulle de point

- **Problème / preuve** : chaque point est un `<li id="point-…">` (chronology.js:475) avec nature et confiance (chronology.js:477-478), un en-tête (chronology.js:480-486), son texte (chronology.js:487) et ses sources (chronology.js:489-499). Ces éléments ne sont pas focalisables : le lecteur d'écran ne peut pas les parcourir un à un au Tab.
- **Solution** : `enhancePoints()` (E057.js:301-314) ajoute `tabindex="0"` sous garde `hasAttribute`, classe `.e057-point` et un `aria-label` unique préfixé par le rang ; `pointData()` (E057.js:114-118) et `tooltipLines()` (E057.js:134-142) produisent l'infobulle de point depuis l'en-tête et le texte réels.
- **Impact** : chaque point devient une étape de tabulation avec un libellé distinct ; sa description courte est affichée au focus, le texte intégral restant dans le `<p>` visible.
- **Risque** : `shorten()` (E057.js:72-75) limite l'`aria-label` à 420 caractères pour rester lisible ; aucune information n'est perdue puisque le texte complet demeure dans le paragraphe et dans la description détaillée.
- **Effort** : faible.
- **Vérification** : Tab sur un point → `tabindex="0"`, `aria-label` commençant par son rang, infobulle contenant le texte du point ; deux points distincts ont deux libellés distincts.

## E057-08 — Readout accessible et attributs d'audit

- **Problème / preuve** : la barre de statut de la vue est un texte simple, volontairement sans `role="status"` (chronology.js:244-256) ; les annonces passent par la région locale `#nav-c2a-live` (chronology.js:119-138). Une mesure de couverture de la description détaillée n'existe pas.
- **Solution** : `fillDetail()` crée un nœud `#e057-readout` avec `role="status"`, `aria-live="polite"` et `aria-atomic="true"` (E057.js:259-269) qui annonce « Description détaillée : N point(s), M source(s) citée(s)… ». Les comptes sont aussi exposés en attributs `data-e057-points` et `data-e057-sources` (E057.js:270-271). Une ligne d'aide visible `#e057-hint` (E057.js:316-325) rend l'infobulle découvrable.
- **Impact** : mesure chiffrée annoncée à l'ouverture, cibles d'audit stables, aucune information portée par la seule couleur.
- **Risque** : double annonce avec la région de la coque — le readout ne parle que de la description détaillée et ne touche jamais au fil de navigation ni au statut de filtrage.
- **Effort** : faible.
- **Vérification** : ouvrir `<details>` → le readout affiche les comptes réels ; un repère à 3 points et 2 sources donne « 3 point(s), 2 source(s) citée(s) », et les attributs `data-e057-*` valent `3` et `2`.

## E057-09 — Mouvement réduit et absence de timer ou de boucle propre

- **Problème / preuve** : `styles.css:342-344` neutralise déjà animations et transitions en préférence de mouvement réduit ; `registry.js:33-36` expose `reducedMotion()` dans le contexte. Une infobulle animée par le greffon contournerait cette règle.
- **Solution** : `prefersReduced` est relu à chaque `install()` (E057.js:335) et pilote la classe `.e057-reduced` (E057.js:90) ; le CSS prévoit `transition: none` pour cette classe (E057.js:31) et un media query dédié (E057.js:50-52). Aucun timer, aucune boucle d'animation, aucune requête réseau, aucun aléa, aucune journalisation dans le module.
- **Impact** : aucune animation parasite ; cohérence totale avec le réglage système et avec le budget de performance de la vue.
- **Risque** : si le contexte ne fournit pas `reducedMotion`, le repli local (E057.js:63) et le media query CSS maintiennent la propriété.
- **Effort** : faible.
- **Vérification** : activer « réduire les animations » → `transition` calculée sur `#e057-tooltip` vaut `none` ; le grep des interdits de E057-01 reste à 0 ligne.

## E057-10 — Idempotence multi-rendus et restauration du focus

- **Problème / preuve** : `runEnhancements()` est appelé à la fin de chaque rendu (chronology.js:539), le `stage` est reconstruit (chronology.js:210, 538) et le focus est restauré explicitement (chronology.js:197-205, 540). Le greffon doit donc être réentrant sans accumuler d'état.
- **Solution** : gardes d'existence sur l'infobulle (E057.js:81), le panneau (E057.js:279-281) et l'aide (E057.js:318) ; clé de contenu (E057.js:288) ; contrôle du propriétaire de l'infobulle (E057.js:351-355) ; si une carte garde le focus après reconstruction, son contenu est régénéré depuis le DOM courant (E057.js:357-359).
- **Impact** : aucun doublon, aucun texte périmé, aucune infobulle orpheline après changement d'ère, de filtre ou de vue.
- **Risque** : l'infobulle vit dans `<body>` et pourrait survivre à un changement de vue ; le contrôle d'existence de `#event-btn-{id}` (E057.js:352-354) la masque dès que la carte propriétaire disparaît.
- **Effort** : moyen — logique de gardes et de rafraîchissement.
- **Vérification** : enchaîner trois rendus → exactement un `#e057-tooltip`, un `#e057-detail`, un `#e057-hint` ; focaliser une carte,re-rendre, puis vérifier que l'infobulle affiche toujours le repère courant.

## Statut d'implémentation

Les 10 chantiers E057-01 à E057-10 sont implémentés dans `src/views/chronology/E057.js`. Seuls deux fichiers ont été touchés : ce module et le présent rapport. CSS injecté une seule fois via `ctx.css('chronology-e057', …)` ; un seul `register('E057', install)` ; identifiants `#e057-tooltip`, `#e057-detail`, `#e057-detail-body`, `#e057-readout`, `#e057-hint` tous préfixés et protégés par des gardes d'existence. Quatre écouteurs délégués enregistrés une seule fois, zéro timer, zéro boucle d'animation propre, zéro appel réseau, zéro aléa, zéro journalisation. `node --check src/views/chronology/E057.js` passe. Langue : français partout.

## Blocages

- Aucun blocage fonctionnel.
- Limite assumée : E057 ne possède pas `chronology.js` et ne peut donc pas poser un `aria-describedby` statique ni modifier la structure de base. L'infobulle reste complémentaire : le résumé, les points et les sources de `chronology.js:439-504` demeurent lisibles sans le greffon.
- Le `<details>` de la description détaillée est créé par JavaScript. Si JavaScript est désactivé, ce panneau n'existe pas, mais les textes longs de base restent accessibles dans la fiche ; aucun contournement risqué n'est introduit.
