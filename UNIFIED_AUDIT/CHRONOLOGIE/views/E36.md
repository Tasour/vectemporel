# E36 — Erreurs et signaux de défaillance de la vue Chronologie

Module : `src/views/chronology/E036.js`.
Rapport : `UNIFIED_AUDIT/CHRONOLOGIE/views/E36.md`.
Contrat : `register('E36', ctx => { … })` ; CSS unique `ctx.css('chronology-e36', …)`.

Sources auditées : `src/views/chronology/registry.js`, `src/views/chronology.js`,
`src/views/_diagnostics.js`, `src/domain/store.js`, `src/data/dataset.js`.

Lentille méta : elle ne dessine aucun repère, n'écrit aucun état partagé et n'ajoute
ni canvas ni boucle rAF. Elle lit dix signaux d'erreur déjà présents dans le
système et les expose dans un panneau texte relu à chaque rendu de la vue, dans
le tiroir « Diagnostics · 100 ». Zéro réseau, zéro aléa, zéro écriture de journal.

## Chantiers

### E36-01 — Erreurs de greffons neutralisées par le registre
- **Preuve** : `registry.js:39-42` enveloppe chaque `apply()` dans un `try/catch` et pousse `{ id, message }` dans `diagnostics` ; `viewDiagnostics()` (`registry.js:46-48`) expose la liste. Une lentille défaillante est donc invisible en interface.
- **Solution** : `readPluginErrors()` (`E036.js:127-139`) lit `viewDiagnostics()`, trie les identifiants et publie `pluginErrors.total`, `pluginErrors.e36` et les huit premiers `ids`. Aucun message libre n'est dupliqué.
- **Impact** : les erreurs absorbées deviennent mesurables depuis l'API publique de la lentille, sans toucher au registre.
- **Risque** : le compteur agrège toutes les lentilles de la vue ; `pluginErrors.e36` distingue explicitement le cas de E36 elle-même.
- **Effort** : S.
- **Vérification** : `window.VECTEMPOREL_E36.snapshot().pluginErrors.total` vaut 0 sur un registre sain ; forcer une lentille à lever donne un identifiant supplémentaire.

### E36-02 — Écritures refusées par la porte unique du store
- **Preuve** : `set()` (`store.js:216-253`) incrémente `state.rejectedWrites` (`store.js:248`) pour chaque clé inconnue ou valeur invalide ; `getSnapshot()` (`store.js:428-430`) expose le compteur, mais aucune vue ne le lit.
- **Solution** : `readRejectedWrites()` (`E036.js:141-154`) relève le total et calcule le delta depuis la lecture précédente. Le delta est calculé une seule fois par relecture, jamais dans `snapshot()`, qui reste une lecture pure.
- **Impact** : une tentative d'écriture corrompue cesse d'être silencieuse.
- **Risque** : le compteur est cumulatif depuis l'amorçage de l'application ; le delta isolé précisément la période écoulée entre deux lectures.
- **Effort** : S.
- **Vérification** : deux appels sans interaction donnent `delta === 0` ; une écriture `set({ inconnu: 1 })` fait croître `total` d'une unité.

### E36-03 — Invariants du store en échec
- **Preuve** : `getDiagnostics()` (`store.js:517-542`) renvoie neuf contrôles booléens plus `allCoherent` ; aucun consommateur ne les affiche.
- **Solution** : `readCoherence()` (`E036.js:156-167`) filtre les clés fausses, les trie et expose `coherence.all` et `coherence.failed` ; un diagnostic indisponible est lui-même signalé comme échec.
- **Impact** : l'état de cohérence de la sélection devient lisible au même endroit que les autres signaux.
- **Risque** : seuls les noms de contrôles sont conservés ; aucune valeur d'état sensible n'est recopiée dans le panneau.
- **Effort** : S.
- **Vérification** : `snapshot().coherence.all === true` et `failed === []` sur l'état nominal.

### E36-04 — Indices de sélection hors bornes
- **Preuve** : `INDEX_MODES` (`store.js:28-30`) borne ère, repère et lieu ; `getBounds()` (`store.js:506-514`) expose `index` et `total` pour quatre collections. Un décalage resterait invisible sans lecture croisée.
- **Solution** : `readBounds()` (`E036.js:169-188`) compare les quatre paires et n'émet un signal que si `total > 0` et `index > total - 1` (ou index négatif).
- **Impact** : une sélection orpheline est détectée avant de produire un panneau vide.
- **Risque** : aucune collection vide n'est comptée comme erreur : c'est le rôle des états vides (E36-08).
- **Effort** : S.
- **Vérification** : `snapshot().bounds.bad === []` sur les dix pays du jeu généré.

### E36-05 — Liens profonds invalides
- **Preuve** : `parseDeepLink()` (`store.js:566-609`) renvoie `null` pour une vue, une ère ou un périmètre inconnu ; `hydrateFromHash()` (`store.js:611-631`) ignore alors silencieusement l'URL.
- **Solution** : `readLinks()` (`E036.js:190-214`) évalue le hash courant et une batterie figée de huit cas (`LINK_CASES`, `E036.js:41-50`) dont quatre refus attendus. `links.current` vaut `absent`, `valide` ou `invalide` ; `links.failures` compte les écarts.
- **Impact** : la robustesse du deep link devient vérifiable sans modifier le hash ni naviguer.
- **Risque** : la batterie est déterministe et ne dépend d'aucune donnée du jeu ; un hash `#` seul est classé `absent`, pas `invalide`.
- **Effort** : S.
- **Vérification** : `snapshot().links` donne `tested: 8`, `failures: 0` ; placer `#v=inconnu` dans la barre d'adresse fait passer `current` à `invalide`.

### E36-06 — Sources non résolues dans le panneau de repère
- **Preuve** : `chronology.js:489-500` résout chaque `data-source-id` vers `country.sources[].title` et affiche l'identifiant brut en repli. Le repli est prévu, mais non compté.
- **Solution** : `readSources()` (`E036.js:216-236`) construit l'ensemble des identifiants connus depuis `currentCountry()` et compare les `[data-source-id]` présents dans le stage ; les identifiants non résolus sont listés (huit au maximum).
- **Impact** : une source manquante dans le registre local devient visible sans inventer de citation ni ajouter de lien externe.
- **Risque** : la lecture est bornée au repère courant, donc au contenu réellement rendu ; elle ne parcourt pas les 229 repères.
- **Effort** : S.
- **Vérification** : `snapshot().sources.unresolved === []` sur un repère dont les sources sont enregistrées ; `scanned` suit exactement le nombre de `<li data-source-id>` du DOM.

### E36-07 — Images du repère manquantes ou sans alternative
- **Preuve** : `chronology.js:397-398` et `434-435` posent `img.src` et `img.alt` depuis le jeu de données ; une image absente ou une alternative vide ne produit aucun message.
- **Solution** : `readImages()` (`E036.js:238-253`) parcourt les `<img>` du stage en une passe et relève `noAlt` (attribut absent ou vide) et `broken` (`complete` vrai et `naturalWidth === 0`).
- **Impact** : la dégradation visuelle est chiffrée sans déclencher de requête ni de boucle d'attente.
- **Risque** : une image encore en cours de chargement n'est pas comptée comme cassée ; la commande « Relire les signaux » permet une seconde lecture après charge.
- **Effort** : S.
- **Vérification** : `snapshot().images` donne `broken: 0` et `noAlt: 0` sur les repères illustrés du jeu local.

### E36-08 — États vides et région d'annonce
- **Preuve** : `chronology.js:359`, `470`, `530` et `533` créent quatre états vides identifiés ; `ensureNavLive()` (`chronology.js:121-138`) crée `#nav-c2a-live` dans `<body>` avec `role="status"` et `aria-live="polite"`.
- **Solution** : `readEmpty()` (`E036.js:255-264`) teste la présence des quatre identifiants dans le stage et vérifie les deux attributs de la région live au document.
- **Impact** : un état vide non annonçable ou une région live absente devient un signal explicite.
- **Risque** : la région live ayant été retirée du stage pour survivre au `innerHTML` de la coque, elle est volontairement cherchée au niveau du document.
- **Effort** : S.
- **Vérification** : en état nominal, `states === []` et `liveOk === true` ; forcer un filtre sans résultat ajoute `nav-c2a-empty-filter` à `states`.

### E36-09 — Focus perdu après reconstruction du DOM
- **Preuve** : `shell.js` reconstruit tout le stage à chaque émission ; `focusIntent` (`chronology.js:17`, `199-205`, `540`) restaure explicitement la cible voulue, mais une cible introuvable retombe sur `<body>` sans signal.
- **Solution** : un unique écouteur `focusin` (`bindFocus()`, `E036.js:266-274`) mémorise le dernier identifiant focalisé ; `readFocus()` (`E036.js:276-285`) détecte une seule fois sa disparition. Le greffon restaure en outre le focus de ses propres boutons après chaque rendu (`E036.js:515-518`).
- **Impact** : la perte de focus est mesurée sans ajouter d'écouteur clavier ni concurrencer le routeur unique.
- **Risque** : un changement de vue légitime peut aussi faire disparaître la cible ; le signal est documenté comme une mesure, pas comme une faute imputable à la seule vue.
- **Effort** : M.
- **Vérification** : après un clic sur une carte, `focus.lastId` porte `event-btn-…` et `lost === false`.

### E36-10 — Identifiants dupliqués dans la vue
- **Preuve** : les cent lentilles injectent chacune leurs propres nœuds dans un stage reconstruit ; `_diagnostics.js` ne vérifie l'unicité que par le motif d'identifiant, pas par doublon réel.
- **Solution** : `readIds()` (`E036.js:287-300`) parcourt les `[id]` du stage, compte les occurrences et liste les identifiants vus deux fois (triés, huit au maximum). Les identifiants de E36 sont préfixés `e36-` et réutilisés par `getElementById`, jamais recréés.
- **Impact** : une collision entre lentilles devient détectable, y compris celles ajoutées après E36.
- **Risque** : le balayage est limité au stage : les régions live volontairement placées dans `<body>` sont hors périmètre et couvertes par E36-08.
- **Effort** : S.
- **Vérification** : `snapshot().ids.duplicates === []` après dix rendus consécutifs ; `document.querySelectorAll('#e36-panel').length === 1`.

## Blocages hors de mon fichier

- **A (`registry.js`)** : `register()` accepte des identifiants dupliqués ; E36 se contente de mesurer `viewDiagnostics()`, la correction d'unicité appartient au maître.
- **B (`store.js`)** : `rejectedWrites`, `getDiagnostics()`, `getBounds()` et `parseDeepLink()` existent déjà ; la lentille n'a modifié aucune de ces définitions.
- **C (`shell.js`)** : la reconstruction complète du DOM rend la mesure de focus (E36-09) intrinsèquement sensible aux changements de vue ; le greffon ne restaure que ses propres contrôles.
