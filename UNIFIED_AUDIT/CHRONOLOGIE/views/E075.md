# E075 — Indicateurs de chargement et d'état des données

Lentille : E075. Fichier possédé : `src/views/chronology/E075.js`.
Lectures seules : `src/views/chronology.js`, `src/views/chronology/registry.js`,
`src/views/chronology/index.js`, `styles.css`,
`UNIFIED_AUDIT/MONDE/views/M07-raf-pause.md`,
`UNIFIED_AUDIT/CHRONOLOGIE/views/E01.md`.
Aucun fichier partagé modifié, aucun réseau, aucun `Math.random`, aucun
`console.*`, aucun timer, aucune boucle `requestAnimationFrame` propre au greffon.
Français partout.

La vue est **entièrement locale et synchrone** : `renderChronology` reçoit un
pays du store (`chronology.js:6`, `:207-209`) et appelle `runEnhancements` une
fois le DOM construit (`chronology.js:539`). Il n'y a donc aucun téléchargement
à surveiller. La lentille ne simule pas de chargement : elle expose l'**état
réel des données** déjà présentes, dérivé du DOM rendu.

## E075-01 — Aucun indicateur de disponibilité des données

- **Problème / preuve** : `chronology.js:244-256` affiche une bande de statut
  mêlant ère, comptages et rang global, mais aucun libellé synthétique ne dit
  si les données sont *prêtes*, *filtrées*, *vides* ou *absentes*. Le retour
  anticipé `if (!country) return` (`chronology.js:208-209`) et les quatre états
  vides (`:353-374`, `:468-472`, `:527-535`) restent sans étiquette d'ensemble.
- **Solution** : une puce textuelle `#e075-datastate [data-e075-role="state"]`
  insérée juste après la bande de statut porte « Données prêtes », « Vue
  filtrée », « Aucun résultat » ou « Sans données », calculée dans `collect()`
  depuis le nombre de bandes, de repères et de points. Le texte prime ; la
  couleur (`--gold` / `--blue` / `--red`) n'est qu'un renfort.
- **Impact** : l'état des données est lisible en un coup d'œil, sans ambiguïté,
  y compris pour un lecteur d'écran ou sur affichage dégradé.
- **Risque** : la puce pourrait contredire la bande de statut si elle était
  calculée à partir d'une source distincte ; elle dérive du **même DOM** que
  cette bande et est recalculée à chaque rendu, donc elle reste cohérente.
- **Effort** : S.
- **Vérification** : `#e075-datastate` contient une seule puce ; son texte est
  l'une des quatre valeurs ci-dessus et `data-e075-state` du conteneur porte la
  même valeur (E075-08). Aucun `role="status"` ajouté (voir E075-10).

## E075-02 — Inventaire des données non synthétisé

- **Problème / preuve** : les quantités existent mais sont éparpillées : ères
  dans `chronology.js:282-305`, repères dans la bande (`:254-255`) et le
  compteur `3 / 57 repères` (`:344`), points dans le titre de section
  (`:462-464`), sources dans les listes de provenance (`:489-500`). Aucune vue
  ne les rassemble.
- **Solution** : `collect()` dénombre les `.era-band`, les `li[data-event-id]`,
  les `.point` et les `li[data-source-id]` distincts ; `paintBar()` écrit une
  ligne `[data-e075-role="inventory"]` du type « 7 ère(s) · 12/57 repère(s)
  affiché(s) · 84 point(s) · 31 source(s) », en chiffres tabulaires.
- **Impact** : le volume documenté est auditable d'un seul regard et les
  proportions (affiché / total) deviennent explicites.
- **Risque** : le total de repères n'est pas lisible dans le DOM filtré ;
  `collect()` le reprend par expression régulière sur `.atlas-chrono-count`
  (`chronology.js:344`), avec repli sur le nombre affiché si le compteur est
  absent — jamais une valeur inventée.
- **Effort** : M.
- **Vérification** : la ligne d'inventaire affiche quatre nombres entiers ;
  ils égalent les `querySelectorAll` des sélecteurs ci-dessus sur le même DOM.
  Aucun appel réseau, aucun `Math.random`.

## E075-03 — État de filtrage implicite

- **Problème / preuve** : le filtre local (`local.query`, `local.tag` —
  `chronology.js:16`, `:178-188`) modifie la recherche (`:312-325`), les puces
  de thèmes (`:328-343`, `:442-459`) et le compteur (`:344`) ; l'utilisateur
  doit reconstituer lui-même qu'il est dans un périmètre réduit.
- **Solution** : `collect()` détecte une recherche non vide ou une puce
  `aria-pressed="true"` ; la ligne `[data-e075-role="filter"]` annonce
  « Filtre actif : N repère(s) sur M dans le périmètre de recherche » ou
  « Aucun filtre actif : … ». L'état `filtree` alimente aussi la puce E075-01
  et le miroir E075-08.
- **Impact** : distinction nette entre vue complète et vue réduite, sans
  modifier le store partagé ni le comportement des filtres existants.
- **Risque** : les puces de thèmes utilisent déjà `aria-pressed`
  (`chronology.js:334`, `:449`) pour un choix unique ; la lentille se contente
  de **lire** cet attribut, elle n'en ajoute aucun et n'introduit donc pas de
  sémantique de bascule erronée.
- **Effort** : S.
- **Vérification** : taper dans `#atlas-chrono-search` puis re-rendre →
  `data-e075-state="filtree"` et la ligne de filtre nomme le périmètre ;
  réinitialiser → retour à `prete` (ou `vide` si aucun résultat).

## E075-04 — Panneaux vides sans état nommé

- **Problème / preuve** : quatre panneaux distincts sont produits — filtre sans
  résultat (`nav-c2a-empty-filter`, `chronology.js:356-371`), ère sans repère
  (`nav-c2a-empty-era`, `:356-359`), repère sans point
  (`nav-c2a-empty-points`, `:468-471`) et absence de sélection
  (`nav-c2a-empty-event`, `:529-534`). Leurs textes diffèrent mais aucun ne
  porte d'étiquette d'état homogène.
- **Solution** : `labelEmptyStates()` insère en tête de chaque
  `.atlas-chrono-empty` un span `.e075-empty-label` dont le texte est choisi
  par l'id réel du panneau (`EMPTY_LABELS`), avec repli générique. Garde
  anti-doublon par requête de la classe.
- **Impact** : les trois situations « rien à afficher » sont distinguables,
  y compris quand la couleur et la taille ne suffisent pas.
- **Risque** : l'étiquette est insérée avant le premier enfant, donc avant le
  bouton « Réinitialiser le filtre » (`chronology.js:361-370`), sans le
  déplacer ni modifier son gestionnaire. Le texte du panneau d'origine est
  conservé intégralement.
- **Effort** : S.
- **Vérification** : chaque panneau vide contient exactement une étiquette ;
  les quatre libellés sont distincts et le bouton de réinitialisation reste
  présent et cliquable dans le panneau filtre.

## E075-05 — Provenance des points non signalée en résumé

- **Problème / preuve** : chaque point résout ses sources titrées dans
  `chronology.js:489-500` (avec recherche dans `country.sources`, `:492-497`),
  mais l'en-tête de point (`:480-485`) ne porte que rang, type et confiance.
  Un point non sourcé et un point sourcé se ressemblent.
- **Solution** : `annotatePoints()` ajoute dans `.point-head` un badge
  « Provenance : sourcé » ou « Provenance : non sourcé », calculé depuis la
  présence réelle d'un `li` dans `.point-sources`. `paintBar()` affiche
  l'agrégat « N point(s) sourcé(s) sur M · S source(s) distincte(s) » et le
  miroir `data-e075-sourced`.
- **Impact** : la qualité de provenance devient un indicateur d'état de données
  explicite, sans inventer de source ni de degré de confiance.
- **Risque** : l'absence de source est un fait, pas un jugement : le badge dit
  « non sourcé », jamais « faux » ni « invalide ». La couleur verte/or n'est
  qu'un renfort du texte, conformément à la règle « aucune info portée par la
  seule couleur ».
- **Effort** : S.
- **Vérification** : un point avec sources porte `data-prov="ok"`, un point
  sans sources `data-prov="none"` ; le total de la barre correspond au nombre
  de `.point` contenant au moins un `li[data-source-id]`.

## E075-06 — Nature et fraîcheur des données non déclarées

- **Problème / preuve** : l'en-tête de la vue affirme « Aucune donnée n'est
  inventée » (`chronology.js:3`) et les points portent `data-confidence`
  (`:478`), mais rien dans l'interface ne rappelle que les données sont locales,
  vérifiées et chargées sans réseau. Un utilisateur peut croire à un contenu
  distant en attente.
- **Solution** : la ligne `[data-e075-role="origin"]` de la barre énonce
  « Données locales vérifiées, prêtes sans appel réseau : aucun chargement en
  cours ni indicateur simulé. » Elle est statique, dérivée du contrat de la
  vue, et ne prétend à aucune date de fraîcheur non documentée.
- **Impact** : l'utilisateur sait immédiatement à quel type de données il a
  affaire ; aucune attente d'actualisation n'est induite.
- **Risque** : affirmer une « fraîcheur » chiffrée serait trompeur (aucune date
  de publication n'est exposée par `chronology.js`) : la mention se limite à
  la nature locale et vérifiée, jamais à un âge des données.
- **Effort** : S.
- **Vérification** : la ligne est présente dans la barre ; `grep` sur le module
  ne renvoie aucun `fetch`, `XMLHttpRequest`, `src` distant, `@import` ni
  `url(http`.

## E075-07 — Tentation du faux indicateur de chargement

- **Problème / preuve** : la vue n'a aucun état asynchrone : `renderChronology`
  construit tout le DOM avant `runEnhancements` (`chronology.js:537-540`). Un
  « spinner » ou une barre de progression animée serait donc une fiction,
  coûterait une boucle rAF ou un timer et induirait l'utilisateur en erreur.
- **Solution** : la barre E075 est entièrement statique. Le CSS ne définit
  aucune `@keyframes`, aucun `requestAnimationFrame`, aucun `setInterval`,
  aucun `setTimeout` ; la seule transition est un fondu de couleur de la puce
  (E075-10), neutralisé en mouvement réduit. Le module est purement réactif :
  recalcul au rendu et au clic sur le bouton E075-09.
- **Impact** : zéro boucle parasite, zéro réveil CPU, cohérence avec le
  fonctionnement synchrone de la vue.
- **Risque** : un futur ajout d'animation « de chargement » casserait cette
  propriété ; la règle est explicite en tête de fichier et vérifiable
  statiquement.
- **Effort** : S.
- **Vérification** : `grep -nE 'requestAnimationFrame|setInterval|setTimeout|@keyframes' src/views/chronology/E075.js` → 0 ligne ; la barre apparaît déjà remplie au premier rendu, sans phase intermédiaire.

## E075-08 — État non auditable depuis le conteneur

- **Problème / preuve** : `.chronology-layout` ne porte que `data-country-id`
  et `data-view="chronology"` (`chronology.js:214-217`). Un test E2E ou un
  audit ne peut pas lire l'état des données sans reconstruire les compteurs.
- **Solution** : `paintBar()` maintient sur le conteneur
  `data-e075-state` (`prete` | `filtree` | `vide` | `sans-donnees`) et
  `data-e075-eras`, `data-e075-events`, `data-e075-points`, `data-e075-sourced`,
  recalculés à chaque passage. Miroir dérivé, jamais une seconde source de
  vérité.
- **Impact** : état observable de façon déclarative, sans instrumentation de
  la vue et sans modifier ses attributs existants.
- **Risque** : un marqueur périmé si le DOM changeait sans re-rendu ; le
  recalcul a lieu à chaque appel de la lentille et à chaque clic sur
  « Recalculer l'état », donc le miroir suit toujours le DOM.
- **Effort** : S.
- **Vérification** : après changement d'ère (re-rendu complet par `set()`),
  les cinq attributs `data-e075-*` reflètent le nouveau DOM ; aucune info n'est
  portée par la seule couleur (le texte de la puce reste la source primaire).

## E075-09 — Aucun moyen de recalculer l'état localement

- **Problème / preuve** : les changements d'état passent par `set({}, 'chrono-filter')`
  (`chronology.js:323`, `:339`, `:367`) qui reconstruit la vue. Hors de ces
  actions, aucun contrôle ne permet de relire l'état affiché — et un
  « Actualiser » réseau serait interdit par le contrat de la vague.
- **Solution** : bouton `#e075-refresh` (« Recalculer l’état des données »,
  ≥ 36 px, focus visible, `aria-controls="e075-datastate"`) inséré dans la
  barre. Son gestionnaire appelle `paintBar()`, qui relit le DOM et réécrit
  textes et miroir : aucun `set()`, aucune reconstruction, aucun réseau.
- **Impact** : recalcul immédiat et honnête ; le focus reste sur le bouton
  puisque le DOM n'est pas reconstruit.
- **Risque** : un clic sur une barre déjà à jour réécrit les mêmes valeurs —
  opération idempotente et sans effet visible, préférable à une actualisation
  fictive. La garde par identifiant empêche la duplication du bouton.
- **Effort** : S.
- **Vérification** : cliquer sur `#e075-refresh` ne déclenche aucun appel
  réseau ni re-rendu de la coque ; `data-e075-state` et les compteurs restent
  identiques si le DOM n'a pas changé, et se corrigent si le DOM a changé.

## E075-10 — Accessibilité et mouvement réduit

- **Problème / preuve** : la vue possède déjà une région live **unique** hors
  de `#app` (`#nav-c2a-live`, `chronology.js:119-138`, `:212`) et une bande de
  statut volontairement **sans** `role=status` (`:244-246`). Ajouter une
  seconde région `aria-live` dans la lentille provoquerait des annonces
  redondantes. Par ailleurs, `ctx.reducedMotion()` est fourni par
  `registry.js:33-36` et la vue a sa propre media query (`:89-91`) qui ne couvre
  pas les nœuds d'une lentille.
- **Solution** : la barre est une `<section aria-label="État des données de la
  chronologie">` en texte visible, **sans** `role="status"` ni `aria-live` :
  elle n'ajoute aucune région live. Double couplage au mouvement réduit —
  media query `@media (prefers-reduced-motion:reduce)` et drapeau explicite
  `data-e075-reduced="1"` posé via `ctx.reducedMotion()` — qui annule la
  transition de la puce. Bouton ≥ 36 px avec `:focus-visible`, libellés
  textuels pour tous les états.
- **Impact** : aucune annonce parasite, respect de la préférence de mouvement,
  informations d'état jamais confiées à la seule couleur.
- **Risque** : la puce n'étant pas live, un changement d'état n'est pas
  annoncé ; c'est le comportement voulu (C2-06), l'état restant lisible dans la
  bande de statut et la barre, et les annonces de filtrage continuant de passer
  par `#nav-c2a-live`.
- **Effort** : S.
- **Vérification** : `document.querySelectorAll('[aria-live]')` ne gagne
  aucune entrée ; avec `prefers-reduced-motion: reduce`,
  `getComputedStyle(chip).transitionDuration` vaut `0s` et le conteneur porte
  `data-e075-reduced="1"` ; sans la préférence, l'attribut est absent.

## Statut d'implémentation

Les 10 chantiers E075-01 à E075-10 sont implémentés dans
`src/views/chronology/E075.js` (un seul fichier de lentille). Aucun fichier
interdit modifié — en particulier `registry.js`, `index.js`, `SYNTHESE.md`,
`README.md` et les autres modules E0xx n'ont pas été touchés. `index.js:76`
importe déjà `E075.js`, donc aucune modification d'intégration n'est requise.

### Contrat respecté

- `import { register } from './registry.js'` ; un seul appel
  `register('E075', ctx => { … })`. `ctx = { viewId, stage, layout, css, el,
  reducedMotion }` est consommé sans import additionnel.
- CSS injecté **une seule fois** via `ctx.css('chronology-e075', …)`, ciblé
  par la classe `.chronology-e075` posée sur `.chronology-layout`.
- Deux identifiants créés, tous préfixés `e075` et protégés par garde
  d'existence : `e075-datastate` (barre) et `e075-refresh` (bouton). Les badges
  et étiquettes utilisent des classes avec garde anti-doublon.
- Zéro `console.*`, zéro `fetch`/XHR/`src` distant/`@import`/`url(http…)`,
  zéro `Math.random`, zéro timer, zéro boucle `requestAnimationFrame` propre.
- Français partout, y compris les libellés, les étiquettes et les commentaires.
- Aucun sélecteur de test existant renommé (`#atlas-chrono-*`, `.event-card`,
  `.era-band`, `.point`, `.nav-c2-*`).

### Vérifications exécutées

- `node --check src/views/chronology/E075.js` : **OK**.
- Relecture des sélecteurs ciblés face au DOM construit par
  `chronology.js:207-541` : **cohérent** (`#atlas-chrono-status` en `:248`,
  `#atlas-chrono-tools` non requis, `.point-head` en `:480`, `.atlas-chrono-count`
  en `:344`, panneaux vides en `:356-371`, `:468-471`, `:529-534`).
- Les suites E2E/verify complètes sont rejouées à froid par l'agent maître,
  conformément au contrat de la vague.

## Blocages

- **Aucun bloquant fonctionnel.**
- E075-06 est déclaratif par construction : `chronology.js` n'expose aucune
  date de publication ni statut réseau, donc la lentille ne peut pas afficher
  de « fraîcheur » chiffrée sans inventer de donnée — elle se limite à la
  nature locale et vérifiée.
- E075-07 est une propriété d'absence (aucun faux chargement) : elle est
  vérifiée statiquement et ne peut pas être « activée » par un réglage.
- Le bouton E075-09 ne peut pas déclencher de re-rendu de la coque sans
  `set()` : il recalcule depuis le DOM, ce qui est le comportement attendu
  pour un indicateur d'état local.
