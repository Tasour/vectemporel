# E097 — Export et copie du contenu de la frise, formats texte

> Lentille **E097**, vague « CHRONOLOGIE » (domaine : sortie / portabilité du contenu).
> Fichier possédé : `src/views/chronology/E097.js`.
> Lectures seules : `src/views/chronology.js`, `src/views/chronology/registry.js`,
> `src/views/chronology/index.js`, `styles.css`.
> Modèle de rapport suivi : `UNIFIED_AUDIT/MONDE/views/M07.md` (chemin réel :
> `M07-raf-pause.md`) et `M01-ombres-eclairage.md`.
> 10 chantiers **E097-01..E097-10, tous implémentés** dans le module.
> Zéro réseau, zéro `Math.random`, zéro `console.*`, zéro timer, aucune boucle
> `requestAnimationFrame`, aucun fichier partagé modifié, aucune donnée inventée.

Cette lentille est **utilitaire et observatoire** : elle n'expose pas un jeu de
données parallèle. Elle lit ce que la vue a réellement rendu dans le DOM et le
restitue sous quatre formats texte, avec copie et téléchargement local. Tout ce
qu'elle affiche est vérifiable contre la frise à l'écran ; rien n'est réparé,
aucun champ n'est déduit d'un tag ou d'une co-occurrence.

## E097-01 — Aucune sortie de la frise : panneau d'export unique et adressable

- **Problème / preuve** : `chronology.js:207-215` construit la vue (`main` + `aside`)
  puis appelle `chronology.js:539` `runEnhancements({ viewId: 'chronology', stage, layout })`.
  Le DOM ne contient aucun contrôle d'export : la recherche (`:310-345`) et les
  filtres (`:329-343`) sont locaux à la session et disparaissent au re-render. Une
  lentille qui injecterait plusieurs panneaux à chaque rendu produirait des IDs
  dupliqués (le registre réapplique les greffons à chaque rendu,
  `registry.js:39-42`).
- **Solution** : un unique panneau `#e097-export-panel` (section `aria-labelledby`
  sur `#e097-export-title`), construit par `buildPanel()` (`E097.js:310-377`) et
  réutilisé par ID (`ensurePanel()`, `:365-377`). Le titre est un `h2`, la lede un
  `p`, le readout `#e097-readout` porte `role="status" aria-live="polite"
  aria-atomic="true"`. Feuille unique `ctx.css('chronology-e097', …)`
  (`E097.js:26-48`, appel `:511`), calquée sur le garde-fou de
  `chronology.js:32-34` (`if (document.getElementById(STYLE_ID)) return;`).
  Tous les IDs créés sont préfixés `e097` et se terminent par un suffixe non
  numérique : le panneau n'est pas confondu avec un panneau de diagnostic.
- **Impact** : une sortie adressable et stable, sans toucher à `styles.css` ni aux
  sélecteurs existants (`#atlas-chrono-*`, `.event-card`, `.era-band`, `.point`).
- **Risque** : le panneau est ajouté à `ctx.layout`, donc reconstruit avec la
  coque. La garde par `document.getElementById(PANEL_ID)` et le déplacement via
  `appendChild` vers le layout courant (`E097.js:368-370`) évitent la duplication ;
  si un panneau hérité d'un ancien layout reste connecté, il est réemployé et ses
  écouteurs ne sont réattachés que sous garde `data-e097-wired` (`:372-376`).
- **Effort** : M.
- **Vérification** : après dix changements d'ère, un seul `#e097-export-panel`,
  un seul `<style id="chronology-e097">`, un seul `#e097-readout` dans le
  document. `node --check src/views/chronology/E097.js` : OK.

## E097-02 — Source unique : le DOM rendu, jamais le dataset ni une copie figée

- **Problème / preuve** : `ctx` ne transmet que `viewId`, `stage` et `layout`
  (`chronology.js:539`) ; aucun pays, aucun jeu de données n'est exposé. Importer
  `DATASET` ou figer une copie au premier rendu produirait une seconde source de
  vérité, périmée dès que l'utilisateur change d'ère (`:298-305`) ou filtre
  (`:320-325`). Le pays n'est disponible que via `layout.dataset.countryId`
  (`:215`).
- **Solution** : `collect(stage)` (`E097.js:129-139`) lit exclusivement le DOM via
  `querySelectorAll` : le titre `#atlas-chrono-title` (`:227-229`) pour le nom du
  pays, `#atlas-chrono-events > li[data-event-id]` (`:377-383`) pour les repères,
  et `.points > li.point` (`:473-478`) pour les points. Aucun chiffre ni libellé
  historique n'est codé en dur ; le panneau lui-même ne correspond à aucun
  sélecteur lu, donc un second passage ne se comptabilise pas.
- **Impact** : l'export reflète exactement ce que l'indexeur et le lecteur voient,
  avec zéro effet de bord sur le store (`set({}, 'chrono-filter')`, `:323`).
- **Risque** : seuls les nœuds actuellement rendus sont exportables — les points
  n'existent que dans l'aside du repère courant (`:466-504`) et une ère non
  affichée n'a pas de cartes dans la liste (`:235`, `:348-414`). Le rapport
  l'indique explicitement ; la lentille ne prétend pas couvrir les 901 points du
  jeu.
- **Effort** : S.
- **Vérification** : changer de filtre puis régénérer l'aperçu modifie le nombre
  de repères sans modification du module ; les nœuds de la vue restent intacts.

## E097-03 — Un seul format imposé : quatre formats texte en choix unique

- **Problème / preuve** : la vue n'offre aucune sortie : le texte visible est
  réparti entre `.event-year`, `<strong>`, `.event-subtitle`, `.aside-summary` et
  `.point p` (`:392-394`, `:439`, `:487`). Un export utile doit choisir une
  grammaire de sortie ; imposer un seul format obligerait à rééditer à la main.
- **Solution** : quatre formats déclarés dans `FORMATS` (`E097.js:12-19`) : texte
  brut (`buildPlain`, `:183-204`), Markdown (`:205-230`), CSV à séparateur `;`
  et TSV à tabulations (`:231-272`, dispatch `compose()`, `:273-281`). Le choix
  est un `radiogroup` natif (fieldset + legend + `input[type=radio]`,
  `radioGroup()`, `:288-308`) : `aria-pressed` est réservé aux bascules
  indépendantes, pas à un choix unique. L'état est mémorisé dans `settings`
  (`:50`) et resynchronisé sur les boutons à chaque rendu.
- **Impact** : l'utilisateur emporte le même contenu sous une forme adaptée à un
  éditeur, à un tableur ou à un dépôt, sans conversion externe.
- **Risque** : `textContent` des points est aplati en une ligne (`clean()`,
  `:66-68`) : les retours à la ligne internes d'un point seraient perdus. La
  source elle-même est déjà du texte plat produit par `el('p', '', point.text)`
  (`chronology.js:487`), donc l'aplatissement est sans perte sur le jeu courant.
- **Effort** : M.
- **Vérification** : parcourir les quatre radios → l'aperçu change de grammaire
  et `#e097-preview` contient successivement « CHRONOLOGIE · », « # Chronologie · »,
  une ligne CSV avec BOM, puis des tabulations ; `data-e097-format` suit la
  valeur choisie.

## E097-04 — Périmètre ambigu : trois portées explicites et désambiguïsées

- **Problème / preuve** : `filterEvents()` (`chronology.js:178-188`) étend le
  périmètre à tout le pays dès qu'une recherche ou un tag est actif, tandis que
  la bande de statut distingue «Ère N/M» de «Recherche dans les N repères»
  (`:247-256`). Un export sans portée explicite mélangerait ces deux régimes et
  rendrait le résultat impossible à interpréter.
- **Solution** : trois portées dans `SCOPES` (`E097.js:20-24`) : « Repères
  affichés » (tous les `li[data-event-id]` du DOM), « Ère courante » (filtrage
  sur `data-era-id` de `.era-band[aria-current="true"]`, `:141-151`) et « Repère
  sélectionné (fiche détaillée) » (carte portant `aria-current="true"`, posée à
  `chronology.js:390`). `scopeLabel()` (`:153-163`) écrit la portée en toutes
  lettres dans l'en-tête de l'export et dans le readout.
- **Impact** : un même clic produit trois documents distincts et auto-décrits ;
  la portée est auditable via `data-e097-scope`.
- **Risque** : en portée « Ère courante » sous filtre actif, seuls les repères
  *rendus* de cette ère sont exportés — pas ceux de l'ère masqués par le filtre.
  C'est le comportement honnête d'une lentille qui lit le DOM ; le libellé
  « Ère courante » ne promet pas l'exhaustivité du pays.
- **Effort** : M.
- **Vérification** : sélectionner un repère puis choisir « Repère sélectionné » →
  une seule carte, le résumé `.aside-summary` et les points de l'aside apparaissent
  ; repasser à « Repères affichés » → le compteur `data-e097-events` reprend le
  nombre de cartes de la liste.

## E097-05 — Aperçu invisible : texte réel, compteurs et état auditable

- **Problème / preuve** : le rapport d'audit exige que l'information ne soit pas
  portée par le seul JS ni par la seule couleur. Un bouton « Exporter » sans
  aperçu ne permet de vérifier ni le contenu ni la taille avant copie.
- **Solution** : un `<pre id="e097-preview">` (`:334-337`) dont `textContent` est
  remplacé à chaque `refreshPreview()` (`:379-394`) par le texte réellement
  produit. Un `<p id="e097-count">` (`:339-341`) affiche
  « N repère(s) · C caractère(s) · L ligne(s) ». Le miroir DOM
  `data-e097-chars` / `data-e097-lines` / `data-e097-events` (`:388-390`) rend
  ces mesures vérifiables sans lire le texte à l'écran. Le readout annonce la
  regeneration sur changement de format ou de portée (`:406`).
- **Impact** : l'export est lisible, mesurable et falsifiable avant tout clic ;
  aucune information n'est uniquement visuelle.
- **Risque** : l'aperçu est tronqué visuellement par `max-height:230px` avec
  défilement (CSS `:41`) ; le texte complet reste dans le nœud et dans `lastText`,
  donc la copie n'est jamais tronquée.
- **Effort** : M.
- **Vérification** : comparer `lastText.length` et le texte du `<pre>` ; sous
  390×844, l'aperçu défile sans casser la largeur du panneau (média query CSS).

## E097-06 — Copie absente : presse-papiers avec repli visible, zéro API dépréciée

- **Problème / preuve** : la vue possède une région live locale `#nav-c2a-live`
  (`chronology.js:119-138`) mais aucun mécanisme de copie. En contexte `file://`
  ou non sécurisé, `navigator.clipboard` est absent : un appel direct échouerait
  silencieusement.
- **Solution** : `copyText()` (`E097.js:423-450`) teste
  `navigator.clipboard.writeText`, gère la promesse (succès → compteur
  `data-e097-copies` + annonce ; échec → `revealFallback()`), et ne recourt jamais
  à `document.execCommand`. Le repli (`:411-421`) rend `#e097-fallback` visible,
  y place le texte, le focalise et le sélectionne, puis annonce « copiez-le avec
  Ctrl+C ». Chaque action est annoncée une fois dans le readout unique.
- **Impact** : copie fonctionnelle sur navigateur moderne et dégradation propre
  ailleurs, sans API dépréciée ni sortie de débogage.
- **Risque** : `writeText` peut rejeter après une attente asynchrone ; le repli
  est appelé dans le callback d'erreur (`:440`). Le compteur n'est incrémenté
  que sur succès avéré, donc le readout ne ment pas.
- **Effort** : M.
- **Vérification** : clic sur « Copier le texte » → le readout porte « Texte copié
  dans le presse-papiers. » et `data-e097-copies` vaut 1 ; simulation d'un
  `clipboard` absent → le textarea est visible, sélectionné, et
  `data-e097-fallbacks` vaut 1.

## E097-07 — Aucun fichier emportable : téléchargement local Blob, sans réseau

- **Problème / preuve** : `chronology.js:1-5` pose « Aucune donnée n'est inventée »
  et le greffon ne dispose d'aucun point de terminaison : toute tentative de
  `fetch` violerait le contrat de la vague et le fonctionnement hors ligne.
- **Solution** : `downloadText()` (`E097.js:460-490`) construit un
  `new Blob([lastText], { type: 'text/plain;charset=utf-8' })`, un URL local
  `URL.createObjectURL`, une ancre temporaire avec `download` et un `click()`,
  puis retire l'ancre et libère l'URL via `queueMicrotask` (`:483-486`) — aucun
  timer, aucune boucle rAF. Le nom de fichier est déterministe
  (`safeFileName()`, `:452-458`) : pays lu dans le DOM, portée, format, accent
  retirés par normalisation NFD, aucun `Math.random`.
- **Impact** : un fichier `.txt` réel emportable, sans serveur ni dépendance, avec
  encodage UTF-8 explicite.
- **Risque** : l'URL `blob:` est libérée en micro-tâche ; si un navigateur la
  libérait trop tôt, le repli `catch` (`:487-490`) révèle le textarea au lieu de
  perdre le contenu. Aucun `href` distant n'est introduit.
- **Effort** : M.
- **Vérification** : le téléchargement produit `chronologie-france-affiches-brut.txt`
  (nom calculé) ; `data-e097-downloads` s'incrémente d'une unité par clic ;
  `grep -E 'fetch|XMLHttpRequest|https?://' E097.js` ne renvoie aucune ligne
  active.

## E097-08 — Champs tabulaires non échappés : CSV et TSV déterministes

- **Problème / preuve** : les repères exposent `data-year`, `data-era-id`,
  `data-importance` et `data-tags` (`chronology.js:378-383`) et l'année visible
  est produite par `formatYear()` (`:26-28`, posée dans `.event-year` à `:392`).
   Une concaténation naïve casserait le tableur dès qu'un titre contient un
  guillemet, un point-virgule ou un accent.
- **Solution** : `tableRows()` (`E097.js:231-259`) produit un en-tête unique de
  dix colonnes et une ligne par repère ; `escapeField()` (`:260-265`) double les
  guillemets et aplatit retours à la ligne et tabulations. Le CSV utilise `;`
  avec BOM UTF-8 (`:266-272`), le TSV des tabulations sans BOM. L'année exportée
  est le millésime *visible* (déjà au format français), l'année brute restant
  dans sa colonne propre.
- **Impact** : fichiers directement ouvrables dans un tableur francophone, avec
  séparateur et encodage explicites et reproductibles.
- **Risque** : le BOM est un caractère invisible en tête de fichier ; il facilite
  l'import Excel mais peut surprendre un lecteur brut. Il est documenté ici et
  n'affecte ni le texte brut ni le Markdown ni le TSV.
- **Effort** : M.
- **Vérification** : un point dont le texte contient `"` et `;` donne deux
  guillemets dans la cellule CSV ; le nombre de colonnes est constant sur toutes
  les lignes ; le TSV ne contient aucun `;` comme délimiteur.

## E097-09 — Risque d'invention : confiance, sources et thèmes restitués tels quels

- **Problème / preuve** : les points portent `data-kind` et `data-confidence`
  (`chronology.js:475-478`), leur texte est un `p` réel (`:487`) et leurs sources
  des `li[data-source-id]` dont le libellé est `${sourceId} — ${source.title}`
  quand la source est résolue (`:489-499`). Les thèmes sont des chips construits
  à partir de `event.tags` (`:441-459`). Déduire une « relation » d'un tag partagé
  ou traduire `disputé`/`disputed` serait une donnée inventée.
- **Solution** : `readDetail()` (`E097.js:110-127`) et `readEvents()` (`:90-108`)
  copient ces valeurs telles quelles ; `pointLines()` (`:171-181`) préfixe chaque
  point de sa confiance et de son genre *extraits du DOM*, et `tableRows()`
  (`:231-259`) ajoute les sources distinctes sans les résoudre ni les normaliser.
  Aucun champ `data-influence`, `data-caused-by` ni `data-related` n'est créé.
- **Impact** : la sortie est une transcription fidèle, réversible et non
  interprétative de la fiche du repère.
- **Risque** : les sources sont exportées avec leur libellé visible, donc un
  identifiant non résolu reste un identifiant brut (comportement de
  `chronology.js:490-496`). La lentille ne tente pas de le réparer.
- **Effort** : S.
- **Vérification** : en portée « Repère sélectionné », chaque ligne de point du
  `<pre>` contient exactement une valeur `data-confidence` observée ; aucun
  libellé de confiance n'est écrit littéralement dans `E097.js` ; zéro `href`
  ajouté.

## E097-10 — Idempotence, mouvement réduit, propreté du greffon

- **Problème / preuve** : `registry.js:39-42` rejoue chaque greffon à chaque rendu
  et neutralise silencieusement une lentille défaillante (`:40-41`).
  `chronology.js:89-91` neutralise les transitions en mouvement réduit, mais une
  feuille injectée par un greffon doit le prévoir elle-même. `ctx.reducedMotion()`
  est fourni (`registry.js:33-36`).
- **Solution** : reconstructeur sans état du DOM — `ensurePanel()` (`:365-377`)
  réutilise le panneau par ID, le déplace dans le layout courant et n'attache les
  deux écouteurs délégués que sous garde `data-e097-wired`. Un seul
  `ctx.css('chronology-e097', …)` (`:511`). La feuille contient une media query
  `prefers-reduced-motion` (`:47`) et le module pose
  `data-e097-reduced` depuis `ctx.reducedMotion()` (`:377`). Aucun `fetch`/XHR,
  aucun `Math.random`, aucun `console.*`, aucun `requestAnimationFrame`, aucun
  `setTimeout`/`setInterval`.
- **Impact** : lentille silencieuse, déterministe, sans fuite de nœuds ni coût
  GPU, cohérente avec la préférence de mouvement du système.
- **Risque** : `queueMicrotask` est utilisé pour libérer l'URL Blob (`:484`) ; ce
  n'est ni un timer ni une boucle d'animation, et un repli synchrone existe si
  l'API est absente. Le compteur de copies est incrémenté côté promesse, donc
  une navigation immédiate après le clic peut ne pas l'afficher — le texte est
  déjà copié.
- **Effort** : S.
- **Vérification** : `node --check src/views/chronology/E097.js` : **OK** ; dix
  appels successifs au greffon → un seul panneau et une seule feuille ; sous
  mouvement réduit, `data-e097-reduced="1"` et transitions à `0s` ;
  `grep -nE 'console\.|fetch\(|Math\.random|requestAnimationFrame|setTimeout|setInterval'
  E097.js` → seules les lignes de commentaire d'en-tête.

## Statut d'implémentation

Les 10 chantiers sont implémentés dans `src/views/chronology/E097.js` (un seul
fichier de lentille). Aucun fichier interdit modifié : `registry.js`, `index.js`,
`SYNTHESE.md`, `README.md` et les autres `E0xx` sont intacts.

### Intégration

- `register('E097', ctx => { … })` (`E097.js:501-515`) est exporté vers
  `./registry.js`. `index.js:98` importe déjà `./E097.js`, donc la lentille est
  active dans l'arbre courant sans modification de `index.js`.
- `ctx` est utilisé conformément au contrat : `ctx.layout`, `ctx.stage`,
  `ctx.el` (avec repli local), `ctx.css('chronology-e097', …)` et
  `ctx.reducedMotion()`.
- Le CSS est injecté une seule fois via `ctx.css` (`E097.js:26-48`, `:511`).
  Les identifiants créés sont tous préfixés `e097` : `e097-export-panel`,
  `e097-export-title`, `e097-export-lede`, `e097-format-*`, `e097-scope-*`,
  `e097-copy-btn`, `e097-download-btn`, `e097-preview`, `e097-count`,
  `e097-readout`, `e097-fallback`.

### Contrat respecté

- **Lecture seule** : aucun nœud de la vue n'est modifié ; le panneau est le seul
  ajout au DOM, réutilisé puis déplacé à chaque rendu.
- **Zéro réseau / zéro aléa / zéro journalisation** : aucun `fetch`/XHR/`src`
  distant/`@import`, aucun `Math.random`, aucun `console.*`. Le téléchargement
  passe par un URL `blob:` local.
- **Accessibilité** : une seule région live (readout), titre `h2` relié par
  `aria-labelledby`, `radiogroup` natifs pour les choix uniques, boutons de
  36 px minimum avec focus visible, `aria-label` sur l'aperçu et le textarea de
  repli, aucune information portée par la seule couleur, mouvement réduit couvert.
- **Idempotence** : garde par ID sur le panneau et la feuille, écouteurs délégués
  attachés une seule fois, aucun timer ni boucle rAF.

### Vérifications exécutées

- `node --check src/views/chronology/E097.js` : **OK**.
- Relecture des sélecteurs face au DOM construit par `chronology.js:207-541` :
  **cohérent** (titre, bandes, cartes, points, sources, thèmes et `layout.dataset`
  tous présents).
- Contrôle statique des interdits : seules les mentions en commentaire
  d'en-tête contiennent `Math.random`, `console.*` et `requestAnimationFrame` ;
  aucune instruction active.
- Les suites `npm run verify` / E2E sont rejouées à froid par l'agent maître,
  conformément au contrat de la vague.

## Blocages

- Aucun bloquant fonctionnel.
- **Portée au rendu courant** (E097-02, E097-04) : l'export ne contient que les
  repères et les points effectivement présents dans le DOM. Emporter les 901
  points du jeu demanderait un accès au dataset que `ctx` ne fournit pas ; la
  lentille refuse de reconstituer une donnée absente.
- **Presse-papiers** (E097-06) : en contexte non sécurisé, l'API standard est
  indisponible ; le repli par sélection de textarea est le comportement prévu,
  pas un défaut. Aucune API dépréciée n'est utilisée pour contourner la limite.
- **Formats tabulaires** (E097-08) : les colonnes « Résumé », « Points » et
  « Sources » ne sont renseignées qu'en portée « Repère sélectionné », seul cas
  où la fiche détaillée est dans le DOM. Le schéma reste identique dans les quatre
  formats pour éviter un nombre de colonnes instable.
