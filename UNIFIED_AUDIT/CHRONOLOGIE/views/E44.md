## E044-01 — Liste de sources sans intitulé, réduite à une flèche de 8 px

- **Problème / preuve** : `src/views/chronology.js:68-72` définit `.point-sources`
  en `font-size:8px` avec un simple `li::before { content:'↳ ' }` : la nature de
  la liste n'est jamais énoncée en texte. `src/views/chronology.js:489-500` crée
  le `<ul class="point-sources">` sans titre, sans `aria-label` et sans légende.
  Une puce décorative est le seul indice que ces lignes sont des références.
- **Solution** : insertion d'une légende réelle `.e044-source-caption`
  (« Provenance — N référence(s) déclarée(s) ») avant la liste, et posée d'un
  `aria-label` « Sources du point X sur Y » sur le `<ul>` déjà produit par la
  vue. La flèche d'origine n'est pas retirée : l'ajout est strictement additif.
- **Impact** : la provenance devient explicite à la lecture visuelle comme à la
  lecture d'écran, sans toucher au texte des points.
- **Risque** : la légende est insérée avec `insertBefore(caption, list)` ; si un
  autre greffon déplace la liste, la légende peut s'en éloigner. La garde
  `aside.dataset.e044Applied` empêche une seconde insertion sur le même DOM.
- **Effort** : S.
- **Vérification** : chaque point pourvu de sources contient un
  `.e044-source-caption` dont le texte contient « Provenance » ; le `<ul>`
  porte un `aria-label` numéroté ; une seule légende par point après 20 rendus.

## E044-02 — Auteurs et année relégués dans un attribut `title`

- **Problème / preuve** : `src/views/chronology.js:496` stocke
  `[source.authors, source.year].filter(Boolean).join(' · ')` uniquement dans
  `line.title`. Cette information n'est accessible qu'au survol, n'est pas
  indexable comme texte et n'est pas joignable au clavier.
- **Solution** : `splitTooltip()` relève les deux champs de l'attribut réel, et
  `metaLabel()` les réécrit dans un `<span class="e044-src-meta">` visible.
  Quand les deux valeurs existent, le texte est « auteurs · année » ; sinon
  « Auteurs : … » ou « Année : … ». L'attribut `title` d'origine est conservé.
- **Impact** : la citation devient lisible sans survol, y compris en 390×844.
- **Risque** : l'attribut ne distingue pas un auteur seul d'une année seule ;
  l'heuristique `/^\d{4}$/` traite une valeur à quatre chiffres comme une année.
  Aucune valeur n'est inventée quand `title` est vide : aucun nœud n'est créé.
- **Effort** : M.
- **Vérification** : le texte visible contient les mêmes chaînes que le `title`
  source ; le `title` reste inchangé ; aucun `<span>` de métadonnée quand
  l'attribut est absent.

## E044-03 — Une référence non résolue se donne l'apparence d'une citation

- **Problème / preuve** : `src/views/chronology.js:492-494` fait
  `country.sources.find(...)` puis
  `label = source && source.title ? \`${sourceId} — ${source.title}\` : sourceId`.
  Quand l'identifiant n'est pas résolu, la ligne affiche l'identifiant brut et
  reste visuellement identique à une référence valide.
- **Solution** : `readSources()` marque `unresolved` l'absence du séparateur
  `—` dans le texte réel. La ligne reçoit `data-e044-unresolved="1"` et un
  badge textuel « référence non résolue » (aucune information portée par la
  seule couleur). Le registre agrège le même marqueur.
- **Impact** : la provenance cesse de survendre une source introuvable.
- **Risque** : une entrée de `country.sources` sans `title` suivrait le même
  chemin de repli (`src/views/chronology.js:493`) ; le badge signale alors
  exactement ce que la vue sait afficher, sans accuser d'erreur de données.
- **Effort** : S.
- **Vérification** : une ligne sans `—` porte le badge ; le compteur du résumé
  compte les références *distinctes* non résolues, pas les occurrences.

## E044-04 — Références non adressables depuis le texte du point

- **Problème / preuve** : `src/views/chronology.js:494-495` pose seulement
  `dataset.sourceId` sur le `<li>` : aucun `id`, aucune ancre. Le paragraphe du
  point (`src/views/chronology.js:487`) ne renvoie pas non plus à ses sources.
- **Solution** : chaque ligne reçoit un `id` unique `e044-src-…` via `makeId()`
  (garde `document.getElementById`). Une ligne `.e044-ref-markers` insérée
  avant la légende propose un lien de fragment local `[1]`, `[2]`, … vers ces
  identifiants, avec un `aria-label` unique incluant l'identifiant et le titre.
- **Impact** : navigation directe entre l'énoncé du point et sa référence,
  sans réseau : les `href` sont des fragments `#…` du même document.
- **Risque** : les cibles sont recréées à chaque rendu complet ; les ancres sont
  recalculées dans le même passage, donc jamais périmées à l'intérieur d'un rendu.
- **Effort** : M.
- **Vérification** : chaque `[n]` possède un `href="#e044-src-…"` résolvable ;
  aucun `href` externe ; les identifiants uniques même avec deux points citant
  la même source.

## E044-05 — Aucune vue agrégée « quelles références appuient quels points »

- **Problème / preuve** : `src/views/chronology.js:461-504` énumère les points
  puis, pour chacun, ses sources, mais ne produit aucun registre : rien ne dit
  qu'une même référence appuie plusieurs points. Les identifiants de points
  existent pourtant (`src/views/chronology.js:475`).
- **Solution** : panneau `#e044-provenance-panel` avec un
  `<ol id="e044-register">` regroupant les identifiants distincts, leur titre,
  leurs métadonnées et des renvois « Cite point 1, point 3 » vers les ancres de
  points. Bascule `#e044-register-toggle` (`aria-expanded`, `aria-controls`) et
  annonce dans `#e044-announce` uniquement sur clic explicite.
- **Impact** : la provenance devient une carte lisible, pas une somme de listes.
- **Risque** : deux occurrences d'un même identifiant avec des titres divergents
  sont regroupées sur le premier titre rencontré ; aucun titre n'est fusionné
  ni réécrit. Le registre reste masqué par défaut pour ne pas noyer la fiche.
- **Effort** : M.
- **Vérification** : un seul registre ; la bascule alterne `hidden` et
  `aria-expanded` ; le live region reste vide tant qu'il n'y a pas de clic.

## E044-06 — Aucune mesure de couverture de la provenance

- **Problème / preuve** : `src/views/chronology.js:462` n'affiche que
  « Points du repère (N) ». Les chemins sans sources
  (`src/views/chronology.js:468-472` pour les points vides, `:489` pour
  l'absence de `point.sources`) ne sont pas comptés comme tels.
- **Solution** : `#e044-provenance-summary` affiche
  « N points · A avec source · B sans source · M références distinctes · U non
  résolues ». Chaque point reçoit `data-e044-sources`, et un point sans source
  reçoit la mention explicite « Aucune source déclarée pour ce point. ». Une
  note `#e044-provenance-note` rappelle que seules les références déclarées
  sont comptées.
- **Impact** : mesure chiffrée et vérifiable de la couverture documentaire du
  repère, sans inventer de données.
- **Risque** : « références distinctes » et « non résolues » sont calculés sur
  le registre dédupliqué, tandis que « avec source » compte les points : les
  unités sont explicites dans le libellé pour éviter toute lecture trompeuse.
- **Effort** : S.
- **Vérification** : la somme « avec source + sans source » égale le nombre de
  `.point` ; le nombre distinct égale le nombre de `<li>` du registre.

## E044-07 — Citations répétées d'une même référence dans un point

- **Problème / preuve** : `src/views/chronology.js:491-498` parcourt
  `point.sources` avec un `forEach` sans déduplication : le même `sourceId`
  peut produire plusieurs lignes indistinguables, toutes portant le même
  `dataset.sourceId` (`:495`).
- **Solution** : une `Map` locale par point compte les occurrences. La ligne
  répétée reçoit `data-e044-repeat="N"` et la mention « citée N× » ; aucune
  ligne n'est supprimée. Le registre n'ajoute le point qu'une seule fois à la
  liste des renvois.
- **Impact** : la répétition devient une information lisible au lieu d'un
  doublon suspect.
- **Risque** : une double citation peut être volontaire (pages ou passages
  différents d'un même ouvrage) : le module ne tranche pas, il documente.
- **Effort** : S.
- **Vérification** : deux occurrences identiques dans un point → une mention
  « citée 2× » ; le registre affiche ce point une seule fois.

## E044-08 — Densité mobile et mouvement réduit non couplés

- **Problème / preuve** : `src/views/chronology.js:70` fixe 8 px pour les
  sources ; `:83-88` ne réorganise que les bandes et outils sous 620 px ;
  `:89-91` neutralise les transitions au niveau de la vue, mais aucun greffon
  ne publie d'état de préférence. L'aside est étroite
  (`styles.css:194-196`, colonne de 380 px).
- **Solution** : bloc CSS unique injecté par `ctx.css('chronology-e044', …)` :
  corps 11 px, `overflow-wrap:anywhere`, `min-height:36px` pour la bascule et
  24 px pour les liens, `@media (max-width:620px)` sur le panneau, et garde
  `[data-e044-reduced="0"]` remplie depuis `ctx.reducedMotion()` plus un
  `@media (prefers-reduced-motion:reduce)` de sécurité. `styles.css` n'est pas
  modifié.
- **Impact** : références lisibles sur mobile, sans débordement dans la colonne
  de droite, et aucune transition sous préférence de mouvement réduit.
- **Risque** : l'augmentation de taille allonge la fiche ; le registre reste
  replié par défaut et le panneau est inséré avant `.aside-actions` pour ne pas
  repousser la navigation en bas de liste.
- **Effort** : M.
- **Vérification** : un seul `<style id="chronology-e044">` ; aucune règle
  modifiée dans `styles.css` ; `data-e044-reduced` cohérent avec
  `matchMedia('(prefers-reduced-motion: reduce)')` ; relecture en 1658×1150 et
  390×844.

## E044-09 — Équivalence clavier et lecteur d'écran incomplète

- **Problème / preuve** : `src/views/chronology.js:480-486` affiche le rang
  « Point 1 / N » dans un `<span>` décoratif sans lien avec les références, et
  `:490` crée une liste non étiquetée. Le dispositif d'origine repose sur le
  `title` au survol (`:496`), donc sur la souris.
- **Solution** : liens de fragment nativement focusables, `:focus-visible`
  contrasté, `aria-label` distinct par lien, `aria-controls`/`aria-expanded`
  sur la bascule, `role="status" aria-live="polite"` sur `#e044-announce`
  seulement. Aucun `tabindex` positif, aucun piège de focus, aucune annonce sur
  survol, aucun `aria-pressed` détourné d'une commande indépendante.
- **Impact** : l'équivalent clavier de chaque référence existe réellement.
- **Risque** : région live partagée `#nav-c2a-live` de la vue
  (`src/views/chronology.js:119-138`) : le greffon ne l'utilise pas, ce qui
  évite deux annonces concurrentes ; la sienne reste vide hors action.
- **Effort** : M.
- **Vérification** : tabulation atteint les `[n]`, la bascule et les renvois
  du registre ; l'anneau de focus est visible ; `#e044-announce` ne change
  qu'au clic.

## E044-10 — Re-render : doublons d'IDs et décoration répétée

- **Problème / preuve** : `src/views/chronology.js:210-212` injecte ses styles
  dans un stage reconstruit, puis `:537-540` appelle `runEnhancements` à chaque
  rendu. `src/views/chronology/registry.js:13-19` ne protège que le `<style>`
  via `cssOnce` : nœuds et écouteurs restent à la charge du greffon.
- **Solution** : identifiants fixes préfixés `e044` pour le panneau, son titre,
  le registre, le résumé, la note, la bascule et l'annonce ; identifiants
  d'ancres générés par `makeId()` avec `usedIds` réinitialisé à chaque passage
  et garde `document.getElementById`. Helper `place()` qui réutilise ou déplace
  un nœud existant, garde `aside.dataset.e044Applied` contre une double
  décoration et `toggle.dataset.e044Bound` contre un double écouteur.
- **Impact** : aucun ID dupliqué, aucun écouteur empilé sur une longue session,
  y compris si `runEnhancements()` est rejoué sans reconstruction du stage.
- **Risque** : un nœud encore rattaché à un ancien stage connecté serait déplacé
  par `place()` ; le contrôle `parentNode !== parent` assure le déplacement
  sans duplication. Un renommage d'ID dans une autre lentille ne peut pas
  entrer en collision avec le préfixe `e044`.
- **Effort** : M.
- **Vérification** : 20 cycles de changement de repère → un seul
  `#e044-provenance-panel`, un seul `#e044-register`, un seul
  `<style id="chronology-e044">`, une seule légende par point ;
  `node --check src/views/chronology/E044.js` passe.

## Statut d'implémentation

Les 10 chantiers sont implémentés dans `src/views/chronology/E044.js`.
Enregistrement unique via `register('E044', …)` (`src/views/chronology/index.js:45`
importe bien le module), CSS unique via `ctx.css('chronology-e044', STYLES)`,
tous les identifiants créés commencent par `e044` et sont protégés par garde
d'existence. Le greffon ne lit que le DOM produit par la vue et le contexte
`{ viewId, stage, layout, css, el, reducedMotion }` décrit dans
`src/views/chronology/registry.js:28-43`. Il n'exécute aucun réseau, aucun
`Math.random`, aucun `console.*`, aucun timer ni `requestAnimationFrame`.
`node --check src/views/chronology/E044.js` : **OK**.

## Blocages

- Aucun blocage fonctionnel.
- `src/views/chronology.js:492-494` ne conserve dans le DOM ni les auteurs ni
  l'année sous forme de texte : E044-02 ne peut que relire l'attribut `title`.
  Une correction structurelle (texte visible produit par la vue elle-même)
  nécessiterait de modifier `chronology.js`, fichier en lecture seule ici ; le
  greffon se contente de rendre visible ce qui est déjà disponible.
- `src/views/chronology.js:489-500` ne distingue pas les références par type
  (primaire/secondaire) ni par page : le registre n'invente aucune typologie et
  signale seulement les références non résolues et les répétitions observables.
