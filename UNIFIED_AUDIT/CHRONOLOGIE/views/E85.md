# E085 — Compteurs et statistiques de la frise, mesures chiffrées

Lentille CHRONOLOGIE E085 — domaine : mesures chiffrées et statistiques de la frise.
Fichier possédé : `src/views/chronology/E085.js`. Lectures seules :
`src/views/chronology.js`, `src/views/chronology/registry.js`,
`src/views/chronology/index.js`, `UNIFIED_AUDIT/MONDE/views/M07.md`,
`UNIFIED_AUDIT/MONDE/views/M01.md`, `styles.css`. Aucun autre fichier modifié.

Contrat : `register('E085', ctx => { … })` avec
`ctx = { viewId, stage, layout, css(id,rules), el(tag,cls,text), reducedMotion() }`.
Le panneau `#e085-panel` est inséré dans `.chronology-main`, juste après la bande
de statut existante. La feuille est injectée une seule fois par
`ctx.css('chronology-e085', …)`. Zéro réseau, zéro aléa, zéro journalisation,
aucune boucle `requestAnimationFrame` propre, aucune donnée historique inventée.

Thème : **rendre la frise mesurable**. Toutes les grandeurs sont recalculées
depuis le DOM rendu (ères, repères visibles, millésimes, points du repère
courant). Les seuils ou conventions d'affichage (siècles, choix de la
référence, arrondi des pourcentages) sont des conventions d'interface, jamais
présentées comme des faits historiques.

## E085-01 — Aucune statistique agrégée de la frise dans le rendu

- **Problème / preuve** : `src/views/chronology.js:247-256` construit la bande de
  statut avec `Ère k/N`, le rang global et un compteur de repères affichés ;
  `src/views/chronology.js:344` ajoute seulement `N / M repères` dans la barre
  d'outils. La lede de `src/views/chronology.js:230` reste qualitative. Aucun
  agrégat n'expose les ères, les années, les points ni les références citées.
- **Solution** : `<section id="e085-panel" role="group">` inséré après
  `#atlas-chrono-status` (repli sur `#atlas-chrono-tools`, puis sur le `main`),
  contenant une liste de définitions `<dl>` de huit lignes : repères affichés,
  ères rendues, étendue temporelle, répartition par ère, densité par siècle,
  importances déclarées, provenance du repère courant et comparaison à la
  référence.
- **Impact** : la vue passe d'un compteur isolé à un jeu de mesures cohérent,
  toutes dérivées du même rendu.
- **Risque** : l'ancrage dépend de la présence de `#atlas-chrono-status` ; le
  repli en cascade garantit que le panneau reste dans le `main` même si une
  autre lentille retire la bande de statut.
- **Effort** : M.
- **Vérification** : le panneau contient exactement huit paires `<dt>/<dd>` ;
  aucun chiffre n'est écrit littéralement dans le module.

## E085-02 — Étendue temporelle non mesurée

- **Problème / preuve** : `src/views/chronology.js:380` pose
  `li.dataset.year = String(item.year)`, mais aucun texte ne donne le minimum,
  le maximum ou l'amplitude. `src/views/chronology.js:252` n'affiche que
  l'intervalle de l'ère courante, pas celui des repères réellement visibles.
- **Solution** : `collect()` lit `data-year` des repères non masqués, calcule
  `min`, `max` et `span = max − min`, puis imprime « de A à B, soit N années
  couvertes » avec le formateur `formatYear()` qui gère les années avant
  J.-C. négatives.
- **Impact** : première grandeur chiffrée traçable, calculée depuis les seuls
  millésimes présents dans le DOM.
- **Risque** : une année avant J.-C. étant négative, l'amplitude arithmétique
  traverse le zéro ; le libellé « années couvertes » est volontairement
  descriptif et ne prétend pas être une durée historique. Sans année lisible,
  la ligne affiche « aucune année renseignée ».
- **Effort** : S.
- **Vérification** : comparer l'affichage avec `Math.min`/`Math.max` des
  `data-year` des `<li data-event-id>` visibles.

## E085-03 — Répartition des repères par ère non chiffrée

- **Problème / preuve** : `src/views/chronology.js:282-305` crée une bande par
  ère et pose `data-era-id` (`:286`) ainsi que `data-start`/`data-end`
  (`:288-289`) ; le compte de repères d'une ère n'est annoncé que
  vocalement au clic (`:301`), jamais affiché de façon permanente.
- **Solution** : chaque bande est appariée aux repères partageant son
  `data-era-id`. Une barre proportionnelle accompagne le nom et le compte
  réel ; le remplissage porte `aria-hidden="true"` et le chiffre reste en texte.
- **Impact** : la charge de chaque ère devient lisible sans clic ni annonce
  sonore, et le total des counts égale le nombre de repères affichés.
- **Risque** : le nom d'ère est lu dans le premier `<span>` de la bande ; si
  une autre lentille y insère un badge, le repli « Ère sans nom » évite un
  libellé trompeur. Les repères masqués par un filtre sont exclus du compte.
- **Effort** : M.
- **Vérification** : la somme des valeurs des barres égale le compteur
  « Repères affichés ».

## E085-04 — Densité par siècle absente

- **Problème / preuve** : `src/views/chronology.js:380-383` expose `data-year`
  et `data-importance`, mais ne regroupe jamais les repères par période ;
  `styles.css:205` étire la grille en `minmax(190px,1fr)`, si bien que la
  densité visuelle varie avec la largeur sans retour chiffré.
- **Solution** : `centuryLabel()` regroupe les millésimes par siècle
  (`Math.ceil(année / 100)`), trie les groupes par effectif décroissant puis
  par libellé en français, et affiche les six premiers avec la mention
  « + N autre(s) siècle(s) » pour le solde réel.
- **Impact** : une répartition temporelle déterministe remplace l'impression
  subjective de « beaucoup de repères à telle époque ».
- **Risque** : le découpage en siècles est une convention d'interface, pas une
  périodisation historique ; il est documenté comme tel. Le tri totalement
  déterministe exclut toute source d'aléa.
- **Effort** : M.
- **Vérification** : la somme des effectifs de siècles égale le nombre
  d'années exploitées ; aucun écart entre deux rendus identiques.

## E085-05 — Importances déclarées non décomptées

- **Problème / preuve** : `src/views/chronology.js:382` écrit
  `li.dataset.importance = String(item.importance)` ; cette donnée n'est
  jamais restituée en texte, alors que `src/views/chronology.js:483` affiche
  bien le type de point tel quel.
- **Solution** : `tally(events, 'importance')` décompte les seules valeurs
  présentes, les imprime verbatim, sans traduction ni fusion, dans un ordre
  déterministe (effectif décroissant, puis `localeCompare('fr')`). État vide :
  « non renseignée ».
- **Impact** : la distribution des importances devient mesurable sans créer de
  catégorie interprétative.
- **Risque** : un vocabulaire hétérogène reste hétérogène ; aucune valeur n'est
  normalisée artificiellement en « haut/moyen/bas ».
- **Effort** : S.
- **Vérification** : la ligne « Importances déclarées » égale le décompte
  direct des `data-importance` des repères visibles.

## E085-06 — Couverture documentaire du repère courant non chiffrée

- **Problème / preuve** : `src/views/chronology.js:466-504` construit les
  points de l'aside et `:489-500` leurs sources, avec `data-source-id` posé en
  `:495`. `src/views/chronology.js:462` n'affiche que
  `Points du repère (N)` : le taux de points sourcés reste à calculer à la main.
- **Solution** : la ligne « Provenance du repère courant » affiche
  `s/P point(s) sourcé(s) (X %), R référence(s) citée(s)`, avec `s` = points
  contenant au moins un `[data-source-id]`, `P` = points de l'aside et
  `R` = total des `data-source-id`.
- **Impact** : deuxième grandeur chiffrée, ramenée à une référence interne
  (le total des points du repère), donc directement falsifiable.
- **Risque** : l'état sans repère (`src/views/chronology.js:527-535`) donne
  `0/0` et `0 référence` ; c'est exact, pas une erreur de calcul. Le pourcentage
  est protégé contre la division par zéro.
- **Effort** : S.
- **Vérification** : relecture — `s`, `P` et `R` correspondent aux nœuds de
  `#atlas-chrono-aside .points` ; aucun lien externe n'est introduit.

## E085-07 — Aucune mesure comparée à une référence

- **Problème / preuve** : `src/views/chronology.js:254-255` et `:344`
  n'affichent que des compteurs bruts et des rangs ; aucune mesure n'est
  rapportée à une grandeur de référence.
- **Solution** : `collect()` dérive trois références des seuls comptes par ère —
  moyenne, médiane et maximum — et `comparison()` imprime une phrase du type
  « Référence : moyenne = M repère(s) par ère. L'ère la plus dense (X) en compte
  N, soit R× la référence ; la moins dense (Y) en compte P. »
- **Impact** : la vue satisfait l'exigence de mesures chiffrées dont une est
  comparée à une référence, sans inventer de donnée ni de seuil historique.
- **Risque** : si la référence vaut zéro, aucun ratio n'est affirmé et un
  message explicite le dit ; la médiane d'un nombre pair d'ères est une
  moyenne des deux valeurs centrales, formulée comme convention statistique.
- **Effort** : M.
- **Vérification** : recalculer moyenne, médiane, maximum et ratio depuis les
  `data-era-id` des repères visibles ; le texte contient toujours la référence
  et son libellé.

## E085-08 — Choix unique de la référence mal modélisé

- **Problème / preuve** : `src/views/chronology.js:330-341` utilise
  `aria-pressed` pour des thèmes qui sont des bascules indépendantes ; réemployer
  cet attribut pour un choix à trois options induirait le lecteur d'écran en
  erreur.
- **Solution** : un `<fieldset>` avec `<legend id="e085-ref-legend">`, un
  conteneur `role="radiogroup"` relié par `aria-labelledby`, et trois boutons
  radio natifs `name="e085-reference"` d'identifiants `e085-ref-moyenne`,
  `e085-ref-mediane`, `e085-ref-maximum`. Le changement met à jour la variable
  de module `reference` et repeint le panneau.
- **Impact** : le caractère exclusif du choix est porté par la sémantique
  native, sans détournement de `aria-pressed` ni de `aria-current`.
- **Risque** : les radios mesurent 14 px, mais chaque `<label>` a une hauteur
  minimale de 24 px et `:focus-within` dessine un contour visible. Les
  écouteurs sont recréés avec les nœuds à chaque `replaceChildren()`, donc
  jamais accumulés.
- **Effort** : S.
- **Vérification** : sélectionner chaque option → `data-e085-reference` suit la
  valeur choisie, le texte de comparaison change, une seule case est cochée.

## E085-09 — Accessibilité des mesures : texte, pas couleur, pas de live concurrent

- **Problème / preuve** : `src/views/chronology.js:119-138` possède déjà la
  région `#nav-c2a-live` (`role="status"`, `aria-live="polite"`) ; ajouter une
  seconde région provoquerait des annonces redondantes.
  `src/views/chronology.js:227` porte l'unique `h1` de la vue.
- **Solution** : le panneau porte `role="group"` et un `aria-label` stable, les
  mesures utilisent une `<dl>` sémantique, les valeurs sont écrites en texte,
  les barres décoratives sont `aria-hidden`, et aucun `role="status"` ni
  `aria-live` n'est ajouté. Aucun titre n'est créé. L'état de la préférence est
  exposé par `data-e085-reduced` via `ctx.reducedMotion()`.
- **Impact** : information lisible au clavier comme à la lecture d'écran, sans
  doublage vocal ni perturbation de la hiérarchie de titres.
- **Risque** : le panneau est statique — ses chiffres sont lus lors de la
  navigation, non annoncés automatiquement ; c'est le comportement voulu. Les
  sélecteurs de test (`.event-card`, `#atlas-chrono-events`,
  `#atlas-chrono-tools`, `.era-band`) ne sont pas modifiés.
- **Effort** : S.
- **Vérification** : relecture — aucun `aria-live` dans le module, un seul `h1`
  dans la vue, chaque barre apparie un chiffre textuel.

## E085-10 — Idempotence, re-render et budget

- **Problème / preuve** : `src/views/chronology.js:539` relance
  `runEnhancements` à chaque rendu ; `src/views/chronology/registry.js:13-19`
  n'injecte le CSS qu'une fois (`:14`) mais `:28-44` rejoue toutes les lentilles
  (`:39-43`) sans purger leurs effets de bord.
- **Solution** : un seul `ctx.css('chronology-e085', …)` ; garde d'existence sur
  `PANEL_ID = 'e085-panel'` ; repaint intégral par `replaceChildren()` ; aucun
  écouteur sur un nœud persistant, aucune référence DOM conservée dans le
  module (seul le choix `reference` y vit). Aucun appel réseau, aucun
  `Math.random`, aucune journalisation, aucune boucle rAF ; deux règles média
  (`max-width:620px`, `prefers-reduced-motion`).
- **Impact** : exactement un panneau et une feuille de style par rendu, sans
  fuite d'écouteur ni dérive du budget.
- **Risque** : le choix de référence survit aux rendus parce qu'il est stocké
  dans la lentille ; c'est délibéré, documenté ici, et resynchronisé dans le
  DOM (bouton coché + `data-e085-reference`). Aucun autre fichier n'est touché.
- **Effort** : M.
- **Vérification** : rendre la vue dix fois → un seul `#e085-panel` et un seul
  `<style id="chronology-e085">` ; `node --check` PASS ; balayage statique sans
  motif réseau, aléa, journalisation ni animation propre.

## Blocages documentés

1. **Ancrage dépendant du DOM voisin** (`src/views/chronology.js:247-256`) : si
   une autre lentille supprime `#atlas-chrono-status`, le panneau est inséré
   après `#atlas-chrono-tools`, sinon en tête du `.chronology-main`. Aucune
   modification de `chronology.js` n'est nécessaire ni autorisée.
2. **Nom d'ère lu dans le premier `<span>`** (`src/views/chronology.js:294`) :
   une lentille qui préfixerait un badge dans la bande pourrait polluer le
   libellé ; le repli « Ère sans nom » évite une affirmation fausse.
3. **Périmètre des points** (`src/views/chronology.js:466-504`) : l'aside ne
   contient que les points du repère courant. La couverture documentaire est
   donc calculée sur ce repère, jamais extrapolée aux autres ; c'est une limite
   explicite, écrite dans le panneau.
4. **Intégration** : conformément au contrat de la vague, le module est
   autonome ; c'est l'agent maître qui assure le câblage final et rejoue les
   suites E2E.
