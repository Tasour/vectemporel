# E087 — Contraste élevé, mode accessibilité et surcharge de thème (vue Chronologie)

Lentille : E087. Fichier possédé : `src/views/chronology/E087.js`. Lectures seules : `src/views/chronology.js`, `src/views/chronology/registry.js`, `src/views/chronology/index.js`, `UNIFIED_AUDIT/MONDE/views/M07.md`, `UNIFIED_AUDIT/MONDE/views/M01.md`, `styles.css`. Aucun fichier partagé modifié (registre, index, `SYNTHESE.md`, `README.md` et les autres `E0xx` intactes). Zéro réseau, zéro `Math.random`, zéro `console.*`, aucune boucle d'animation propre, aucun minuteur. CSS injecté une seule fois via `ctx.css('chronology-e087', …)` (registry.js:13-19). ## E087-01 — Aucun point d'entrée de thème dans la vue Chronologie

- **Problème / preuve** : `src/views/chronology.js:277-345` construit la navigation d'ères, la recherche et les étiquettes, mais aucun contrôle de thème ni d'accessibilité n'est prévu ; le bloc de style de la vue est figé à `src/views/chronology.js:36-91` et réinjecté dans le `stage` à chaque rendu (`src/views/chronology.js:32-33`, `:92`). La coque reconstruisant tout le DOM (`src/views/chronology.js:30-31`), un panneau ajouté naïvement serait soit perdu, soit dupliqué.
- **Solution** : panneau `#e087-panel` inséré après la bande de statut `#atlas-chrono-status` (`src/views/chronology.js:247-256`) via une garde d'existence `getElementById` : réutilisé s'il est encore connecté, recréé et déplacé dans le `#atlas-chrono-main` courant sinon. Un seul `ctx.css('chronology-e087', …)`, une seule classe `.chronology-e087` posée sur le layout (`src/views/chronology.js:214`).
- **Impact** : la surcharge de thème devient actionnable depuis la vue elle-même, sans éditer `styles.css` ni le style inline de `chronology.js`.
- **Risque** : le style de la vue étant injecté *après* la feuille du greffon dans l'ordre du document, les règles de composants E087 utilisent `!important` ; les surcharges de jetons sur `<html>` n'en ont pas besoin (sélecteur d'attribut plus spécifique que `:root`, `styles.css:2`).
- **Effort** : M.
- **Vérification** : après 20 cycles de rendu, un seul `style#chronology-e087` dans `<head>` et un seul `#e087-panel` dans `#atlas-chrono-main` ; `node --check src/views/chronology/E087.js` sans erreur.

## E087-02 — Mode accessibilité : bascule indépendante à état miroir

- **Problème / preuve** : `src/views/chronology.js:334-335` et `:449` réservent `aria-pressed` à des commandes indépendantes (étiquettes), tandis que les choix uniques passent par `aria-current` (`:290`, `:390`) ; aucun mécanisme ne permet de forcer un contraste maximal indépendamment de la préférence système. `registry.js:28-37` fournit `ctx` sans région live dédiée : la vue possède déjà `#nav-c2a-live` (`src/views/chronology.js:119-138`) et `#atlas-chrono-status` (`:247-256`).
- **Solution** : bouton `#e087-access-toggle` avec `aria-pressed`, état module `S.access` survivant aux reconstructions du DOM, miroir `data-e087-access` sur `<html>` et sur le layout, libellé et `aria-pressed` resynchronisés à chaque application. Le retour se fait par l'état visible et le texte du readout, sans nouvelle région live bavarde.
- **Impact** : bascule accessible au clavier et aux lecteurs d'écran, qui force la palette « contraste élevé » sans détruire le thème explicitement choisi.
- **Risque** : l'état module persiste entre deux pays ; c'est souhaitable pour une préférence d'accessibilité, mais il doit être réécrit sur le layout à chaque rendu ( fait dans `applyState()` ), sinon un layout neuf perdrait le marqueur.
- **Effort** : M.
- **Vérification** : clic → `aria-pressed="true"`, `data-e087-access="1"` sur `<html>` et sur `.chronology-layout`, libellé « Mode accessibilité : activé » ; changement de pays → état conservé et marqueurs réécrits.

## E087-03 — Choix de thème : radiogroup, pas une bascule

- **Problème / preuve** : `src/views/chronology.js:282-305` illustre le choix unique d'ère par `aria-current="true"` (`:290`) et `:390` fait de même pour le repère courant : utiliser trois `aria-pressed` pour les thèmes enfreindrait la règle « choix unique = radiogroup ». Le registre n'impose aucun motif de ce type (`registry.js:21-26`).
- **Solution** : `<fieldset role="radiogroup">` intitulé « Thème de la vue Chronologie » avec trois `input[type=radio]` (`#e087-theme-auto`, `-hc`, `-mono`) et `<label>` associés, `name="e087-theme"` unique, `checked` piloté par `S.theme`. Priorité documentée : bascule accessibilité > choix explicite > préférence système > défaut.
- **Impact** : sémantique de choix unique correcte, navigation flèches native du navigateur, aucune ambiguïté avec les `aria-pressed` des étiquettes existantes.
- **Risque** : le `fieldset` porte à la fois sa sémantique native et `role="radiogroup"` ; les navigateurs anciens ignorent le rôle mais conservent le groupement. Aucun piège de focus ajouté.
- **Effort** : S.
- **Vérification** : `role="radiogroup"` présent, exactement un `input:checked`, `aria-pressed` absent du groupe ; changer de thème met à jour `data-e087-theme` sans toucher à `data-e087-access`.

## E087-04 — Palette « contraste élevé » par surcharge des jetons

- **Problème / preuve** : `styles.css:2-20` définit des jetons à faible séparation : `--line: rgba(255,255,255,.1)` (`:6`), `--muted-2: #8c8d91` sur `--bg: #070a0e` (`:3`, `:11`) soit seulement 5,98:1, sous le seuil AAA de 7:1. `src/views/chronology.js:38-39, :44, :58, :63-64` exploitent précisément ces jetons atténués pour les textes secondaires.
- **Solution** : `html[data-e087-theme="hc"]` redéfinit `--bg`, `--surface`, `--surface-2`, `--line`, `--line-strong`, `--ink`, `--ink-soft`, `--muted`, `--muted-2`, `--gold`, `--gold-bright` (plus `--blue`, `--violet`, `--red`). Valeurs calculées : texte/fond 21,0:1, accent/fond 14,87:1, secondaire/surface 16,83:1, bordure/fond 21,0:1 — au-dessus des références 4,5:1, 3:1 et 7:1. Le readout recalcule ces rapports depuis `getComputedStyle(document.documentElement)` à chaque application.
- **Impact** : surcharge de thème globale, héritée par toute l'application, qui élève le contraste sans modifier une seule règle de `styles.css`.
- **Risque** : les variables étant portées par `<html>`, la palette affecte aussi les autres vues ; c'est un choix délibéré de mode accessibilité persistant, documenté. Les règles de composants restent, elles, scoped sous `.chronology-e087`.
- **Effort** : M.
- **Vérification** : avec le thème `hc`, `getComputedStyle(document.documentElement).getPropertyValue('--bg')` vaut `#000000` ; le readout affiche « texte/fond 21,0 : 1 (référence AA 4,5:1) » ; aucune valeur n'est écrite en dur dans le readout.

## E087-05 — Palette « monochrome » : le sens par la forme

- **Problème / preuve** : `styles.css:231-234` distingue `point-kind.is-audit`, `.is-figure`, `.is-lieu` uniquement par la couleur (`--gold`, `--gold-bright`, `--blue`), et `src/views/chronology.js:483-484` pose ces classes sur chaque point. En mode à contraste élevé, ces teintes rapprochées deviennent indiscernables.
- **Solution** : `html[data-e087-theme="mono"]` force toutes les couleurs en niveaux de gris (accent inclus), renforce `font-weight` des titres de cartes et ajoute un `outline: 3px double` sur les états courants ; la bordure gauche des bandes passe en blanc plein, annulant le `--era` inline posé à `src/views/chronology.js:293`.
- **Impact** : aucune information n'est portée par la seule couleur, même avec une palette strictement monocrome.
- **Risque** : le `--era` reste dans le DOM (donnée d'ère réelle, `src/views/chronology.js:293`) ; seule sa traduction visuelle est neutralisée, pas la donnée. Le double outline est compensé par `outline-offset:-6px` pour ne pas rogner les cartes (`styles.css:208`).
- **Effort** : M.
- **Vérification** : en thème `mono`, `--gold`, `--blue`, `--violet` et `--red` calculés valent `#ffffff` ; les bandes courantes gardent un anneau visible en niveaux de gris ; les libellés de type de point restent lisibles.

## E087-06 — Préférences système : un seul écouteur par requête

- **Problème / preuve** : `src/views/chronology.js:89-91` ne contient qu'une média query CSS `prefers-reduced-motion`, sans pilote JS ; `registry.js:33-36` propose `ctx.reducedMotion()` mais aucune préférence de contraste. `runEnhancements()` rejoue les greffons à chaque rendu (`src/views/chronology.js:539`, `registry.js:39-42`) : un écouteur ajouté sans garde s'accumulerait.
- **Solution** : lecture initiale de `(prefers-contrast: more)` et `(forced-colors: active)`, puis enregistrement module-level unique sous garde `S.mediaWatched`, avec repli `addListener`. Un miroir CSS `@media (prefers-contrast: more)` et `@media (forced-colors: active)` reste actif si le JS de lentille est neutralisé. État exposé via `data-e087-more-contrast` et `data-e087-forced`.
- **Impact** : le thème « Auto » suit réellement le système, avec un fail-safe visuel sans JavaScript.
- **Risque** : un `matchMedia` indisponible est neutralisé par `try/catch` ; les choix explicites restent alors seuls actifs, ce qui est le comportement de repli attendu.
- **Effort** : M.
- **Vérification** : émuler `prefers-contrast: more` → `data-e087-more-contrast="1"` et `data-e087-theme="hc"` en thème Auto ; trois rendus successifs n'ajoutent aucun écouteur (un seul jeu module-level).

## E087-07 — Neutralisation des décorations à faible contraste

- **Problème / preuve** : `styles.css:201` colore les bandes par `color-mix(in srgb, var(--era) 12%, #0b0f15)` et `styles.css:204, :213` ajoutent des ombres translucides ; ces fonds de 12 % d'accent sont précisément ceux qui font chuter le contraste des textes posés dessus (`src/views/chronology.js:294-297`).
- **Solution** : sous `hc` et `mono`, fonds d'aplats `var(--surface-2)`, bordures pleines de 2 px, accent conservé en bordure gauche de 4 px, `box-shadow` et `text-shadow` supprimés sur bandes et cartes, sauf anneau d'état `inset 0 0 0 2px var(--gold-bright)`. Le bloc d'orientation `.nav-c2-orientation` (`src/views/chronology.js:260-275`) subit le même traitement.
- **Impact** : contraste effectif prévisible, indépendant de la couleur d'ère, sans perdre l'indice d'appartenance à une ère.
- **Risque** : `box-shadow` supprimé sur l'état courant pourrait faire disparaître la sélection ; l'anneau `inset` la remplace explicitement, et un `outline` double est ajouté en monochrome.
- **Effort** : M.
- **Vérification** : `getComputedStyle(bande).backgroundColor` est opaque et `boxShadow` ne contient plus de `rgba(230, 185, 111` ; la bande courante conserve un liseré doré visible en 1658×1150 et 390×844.

## E087-08 — Hiérarchie typographique renforcée

- **Problème / preuve** : huit textes de la vue sont définis en 8 ou 9 px : `src/views/chronology.js:38` (`.atlas-chrono-hint`), `:39` (statut), `:44` (période), `:58` (compteur), `:63-64` (ère de carte, thèmes), `:215` (année), `:217` (sous-titre), et `styles.css:219, :223, :230` (kickers, crédit, badges de point à 7 px). Ces tailles sont lisibles en mode standard mais fragiles en surcharge.
- **Solution** : sous `hc` et `mono`, la liste complète de ces sélecteurs passe à `font-size:11px`, `font-weight:600`, `line-height:1.5`, `color:var(--ink) !important`. Le `!important` est rendu nécessaire par la réinjection du style de la vue dans le `stage` à chaque rendu (`src/views/chronology.js:32-33, :92`).
- **Impact** : hiérarchie préservée et seuil de lisibilité relevé sur les textes secondaires, sans modifier `chronology.js`.
- **Risque** : l'augmentation de taille peut provoquer des retours à la ligne dans les cartes (`min-height:150px`, `styles.css:206`) ; `line-height:1.5` et `overflow-wrap` hérité évitent le débordement, à relecture visuelle sous 620 px.
- **Effort** : S.
- **Vérification** : `getComputedStyle(document.querySelector('.atlas-chrono-hint')).fontSize` vaut `11px` en surcharge ; le style calculé retombe à `8px` quand le thème redevient standard.

## E087-09 — Focus et cibles tactiles sous contrainte de thème

- **Problème / preuve** : `styles.css:33-36` pose un anneau de 2 px, mais `styles.css:208` met `overflow:hidden` sur `.event-card` : l'anneau peut être découpé. `src/views/chronology.js:77-80` crée un bouton de réinitialisation à `min-height:32px`, sous le seuil 36 px, et `src/views/chronology.js:54` donne 30 px aux étiquettes.
- **Solution** : `outline:3px solid var(--gold-bright)` avec `box-shadow:inset 0 0 0 2px` sur cartes, bandes, boutons et champs ; `min-height:44px !important` sur les petites cibles en surcharge ; sous `forced-colors`, l'anneau utilise la couleur système `Highlight`. L'état reste annoncé par `aria-current`/`aria-pressed`, pas par l'anneau seul.
- **Impact** : focus visible même sur fond surchargé et en couleurs forcées, cibles conformes au toucher.
- **Risque** : `box-shadow: inset` sur un bouton déjà pourvu d'un `border` de 2 px réduit légèrement la zone de texte ; `outline-offset:2px` compense à l'extérieur pour les éléments non rognés.
- **Effort** : S.
- **Vérification** : tabulation sur une carte active → anneau interne visible malgré `overflow:hidden` ; `getComputedStyle(reset).minHeight` vaut `44px` en mode accessibilité ; aucun `outline` porté par la seule couleur.

## E087-10 — Idempotence, gardes d'existence et sobriété d'exécution

- **Problème / preuve** : `src/views/chronology.js:537-541` appelle `runEnhancements` puis `applyFocusIntent` à chaque rendu, tandis que `registry.js:13-19` ne garantit que l'unicité du `<style>` ; ni les nœuds ni les écouteurs ne sont protégés par le registre. Le re-render peut laisser des IDs dupliqués ou voler le focus.
- **Solution** : tous les IDs sont préfixés `e087-` et résolus par `getElementById` à chaque application ; les écouteurs de contrôles portent une garde par nœud (`data-e087-bound`), les écouteurs de médias une garde module (`S.mediaWatched`) ; `S.layout` est vérifié avec `isConnected` avant écriture. Aucune boucle d'animation, aucun minuteur, aucune requête réseau, aucune fonction d'aléa, aucune trace de débogage, un seul `register('E087', …)`.
- **Impact** : longue session sans doublon d'ID, sans fuite d'écouteur et sans erreur de focus ; conformité au contrat du sous-agent.
- **Risque** : le layout survivant peut conserver un `dataset` périmé ; `applyState()` réécrit systématiquement `data-e087-theme`, `data-e087-access` et `data-e087-reduced`, ce qui neutralise ce risque. Le registre neutralise silencieusement une lentille défaillante (`registry.js:39-42`) : la garde d'existence reste nécessaire pour les nœuds déplacés.
- **Effort** : M.
- **Vérification** : `node --check src/views/chronology/E087.js` ; `grep -nE 'console\.|fetch\(|Math\.random|requestAnimationFrame|setInterval|setTimeout' src/views/chronology/E087.js` → 0 ligne ; 20 cycles retour monde → chronologie → un seul `#e087-panel`, un seul `<style id="chronology-e087">`, thème et bascule conservés.

Les 10 chantiers sont implémentés dans `src/views/chronology/E087.js`. Aucun fichier interdit modifié. CSS injecté une seule fois via `ctx.css('chronology-e087', …)` ; identifiants `#e087-panel`, `#e087-access-toggle`, `#e087-theme-group`, `#e087-theme-auto`, `#e087-theme-hc`, `#e087-theme-mono`, `#e087-readout`, `#e087-note`, `#e087-title` tous préfixés et protégés par garde d'existence. Un seul `register('E087', …)`, un seul jeu d'écouteurs de médias module-level, aucun `console.*`, aucun appel réseau, aucune graine aléatoire, aucune boucle d'animation propre, aucun minuteur. `node --check src/views/chronology/E087.js` : syntaxe valide.

## Blocages

- Aucun bloquant fonctionnel.
- Complémentarité avec E010 (`contraste & lisibilité`) : E010 colorie directement certains textes et bordures via `html[data-e10-contrast="high"] … !important` ; si les deux lentilles sont actives simultanément, ces règles peuvent l'emporter localement sur la typographie d'E087. Les deux attributs sont indépendants (`data-e10-*` vs `data-e087-*`) et aucun conflit d'ID n'existe ; l'arbitre reste le maître des lentilles si un rendu unique est souhaité.
- La palette surchargeant les jetons `--*` sur `<html>`, son effet dépasse la seule vue Chronologie : c'est le prix d'un mode accessibilité persistant. Si le maître souhaite une portée strictement locale, il faudra déplacer les définitions de palette sous `.chronology-e087` — modification réservée à une décision d'architecture, pas à cette lentille.
- E087-04 et E087-06 sont des mesures calculées à la demande depuis `getComputedStyle` ; elles ne instrumentent ni le navigateur ni le moteur et ne peuvent donc pas détecter un défaut de rendu GPU (hors périmètre de la vue Chronologie).
