# E055 — Titres sémantiques, regroupement par époque et structure de document

Lentille : E055. Fichier possédé : `src/views/chronology/E055.js`.
Lectures seules : `src/views/chronology.js`, `src/views/chronology/registry.js`, `src/views/chronology/index.js`, `UNIFIED_AUDIT/MONDE/views/M07.md`, `UNIFIED_AUDIT/MONDE/views/M01.md`, `styles.css`.
Thème : titres sémantiques, regroupement par époque, structure de document. 10 chantiers, **les 10 implémentés** dans le module.
Zéro réseau, zéro `Math.random`, zéro `console.*`, aucune boucle `requestAnimationFrame` propre. Un seul `register('E055', …)`, un seul `ctx.css('chronology-e055', …)`.

## E055-01 — Aucun repère `<main>` dans la vue

- **Problème / preuve** : `src/views/chronology.js:218` crée `<section class="chronology-main">` avec `aria-labelledby="atlas-chrono-title"` (`:220`), mais ni `<main>` ni `role="main"` : la zone principale n'est pas un landmark pour les lecteurs d'écran. Le commentaire de `:30-31` rappelle que la coque reconstruit le `stage` à chaque rendu.
- **Solution** : poser `role="main"` sur `#atlas-chrono-main` **uniquement si** `document.querySelector('main, [role="main"]')` ne trouve rien, puis écrire `layout.dataset.e055Main`. Le miroir d'état rend le résultat auditable sans instrumentation.
- **Impact** : un seul landmark principal, annonçable par navigation de landmarks, sans modifier `chronology.js`.
- **Risque** : ajouter un second `<main>` si une autre lentille en pose un ; la garde d'existence sur le document écarte ce risque, et le drapeau `data-e055-main="0"` signale alors que la vue s'appuie sur le landmark existant.
- **Effort** : S.
- **Vérification** : `document.querySelectorAll('main, [role="main"]').length === 1` et `layout.dataset.e055Main === '1'` après trois rendus successifs.

## E055-02 — Titres de repères invisibles à la navigation par titres

- **Problème / preuve** : `src/views/chronology.js:393` met le titre de chaque carte dans un `<strong>` nu, tandis que la fiche utilise un `<h2>` (`:423`) et la liste des points un `<h3>` (`:462`). Le titre d'un repère dans la liste n'est donc pas un titre sémantique : la navigation par titres saute les repères.
- **Solution** : promouvoir chaque `<strong>` direct d'une `.event-card` en `role="heading" aria-level="3"`, avec garde `!hasAttribute('role')`. Cibles : `li[data-event-id] > .event-card > strong` (`:378-393`).
- **Impact** : la liste devient parcourable par titres, au même niveau que le titre de la fiche une fois aligné par E055-08.
- **Risque** : un `<strong>` déjà promu par une autre lentille est laissé intact ; le style `.event-card > strong[role="heading"]{display:block}` évite tout changement de mise en page.
- **Effort** : S.
- **Vérification** : autant de `.event-card > strong[role="heading"][aria-level="3"]` que de cartes ; aucun titre supplémentaire dans la hiérarchie après re-render.

## E055-03 — Aucun titre d'ère dans le document

- **Problème / preuve** : les ères n'existent que comme boutons dans `<nav id="atlas-chrono-eras">` (`src/views/chronology.js:278-307`, bandes construites en `:284-297`) : le nom est un `<span>` (`:295`) et la plage un `<span class="atlas-chrono-era-range">` (`:296`). Aucun titre d'ère n'est donc traversable dans le plan du document.
- **Solution** : construire un sommaire `<nav id="e055-era-outline" aria-label="Sommaire des ères documentées">` inséré juste avant `#atlas-chrono-tools`, avec un `<h2 class="e055-outline-title">` par ère. Le nom est lu sur `band.firstElementChild` (`:295`) et l'ordinal sur la position de la bande.
- **Impact** : le regroupement par époque devient une structure de document navigable, en plus des boutons de filtrage.
- **Risque** : deux `<nav>` étiquetés coexistent ; chacun porte un `aria-label` distinct, ce qui est conforme. L'insertion utilise `insertBefore` avec ancre pour rester stable à chaque rendu.
- **Effort** : M.
- **Vérification** : un seul `#e055-era-outline`, autant de `<h2>` d'ère que de `.era-band`, après trois rendus.

## E055-04 — Plage chronologique non exprimée en texte dans le sommaire

- **Problème / preuve** : la plage est stockée dans `data-start` / `data-end` (`src/views/chronology.js:288-289`) et seulement affichée dans le `title` de la bande (`:292`) ou le `<span>` de la bande (`:296`). Ces données ne sont pas dans le plan de lecture du sommaire.
- **Solution** : formater `data-start` / `data-end` en texte visible dans le sommaire via `formatYear` (reproduction de `formatYear`, `src/views/chronology.js:26-28` : `N av. J.-C.` pour les valeurs négatives), dans `#e055-outline-range-<id>`.
- **Impact** : la datation est lisible et indexable dans le sommaire, sans dépendre d'une infobulle.
- **Risque** : une valeur absente donnerait `NaN` ; `formatYear` renvoie `?` pour toute valeur non finie, jamais un chiffre trompeur.
- **Effort** : S.
- **Vérification** : le texte du sommaire contient `→` et, pour une ère avant J.-C., `av. J.-C.` ; aucune chaîne `NaN`.

## E055-05 — Compte de repères par ère absent de la structure

- **Problème / preuve** : le compte global est dans la bande de statut (`src/views/chronology.js:249-255`), mais aucun compte par ère n'est rattaché au regroupement. Sous filtre, la liste est plate (`:348-414`) et l'appartenance à une ère n'est portée que par un `<span>` sur la carte (`:403-405`).
- **Solution** : calculer le nombre de `<li data-era-id>` de `#atlas-chrono-events` par ère, l'afficher dans `#e055-outline-count-<id>` et le doubler d'un `aria-label` explicite « N repères dans cette ère ». Le même compte est repris dans chaque en-tête de groupe (E055-07).
- **Impact** : le poids de chaque ère est audible et visible au même endroit que son titre.
- **Risque** : le compte est recalculé à chaque rendu depuis le DOM ; aucune donnée du store n'est dupliquée, donc pas de dérive possible.
- **Effort** : S.
- **Vérification** : la somme des comptes du sommaire égale le nombre de `li[data-event-id]` ; le `aria-label` correspond au texte affiché.

## E055-06 — Ère courante non marquée dans le sommaire

- **Problème / preuve** : la bande active porte `aria-current="true"` (`src/views/chronology.js:290`) et la classe `is-active` (`:284`), mais le fil de situation C2 (`:260-275`) s'arrête au repère courant : le sommaire n'existe pas, donc rien ne signale l'ère courante dans le plan du document.
- **Solution** : recopier l'état `aria-current` de la bande vers l'`<li>` du sommaire et vers son `<h2>`, en retirant l'attribut des autres entrées. Le style `.e055-outline-item[aria-current="true"] .e055-outline-title` distingue l'ère active sans porter l'information par la seule couleur (le mot « Ère N » et le `aria-current` restent dans le texte).
- **Impact** : situation courante cohérente entre la navigation d'ères, le sommaire et le fil C2.
- **Risque** : deux ères actives simultanément ; la boucle applique explicitement `removeAttribute` sur toutes les entrées non courantes, ce qui garantit l'unicité.
- **Effort** : S.
- **Vérification** : exactement un `aria-current="true"` dans `#e055-era-outline`, aligné sur la bande active.

## E055-07 — Liste plate sous filtre : regroupement par èpoque perdu

- **Problème / preuve** : sans filtre, `scopeEvents` vaut `eraEvents` (`src/views/chronology.js:178-188`) et la liste est déjà ère par ère. Sous filtre, `scopeEvents` devient `country.events` (`:181`) : tous les repères du pays sont affichés dans un seul `<ol>` (`:348-414`) et l'ère n'est qu'un `<span class="atlas-chrono-card-era">` (`:402-405`). Le regroupement structurel est donc perdu exactement quand il est le plus utile.
- **Solution** : avant chaque série continue de `li[data-era-id]`, insérer `<li class="e055-era-head" role="presentation">` contenant un `<h2 id="e055-group-title-N">` « Ère N · nom (plage) · K repère(s) ». Garde `list.dataset.e055Grouped !== '1'` et identifiants numérotés par série (`e055-group-N`), ce qui évite les doublons même si une ère réapparaît après une autre.
- **Impact** : le regroupement par époque est restauré dans le document, y compris en recherche multière, sans réordonner les repères ni toucher à `state.eventIndex`.
- **Risque** : `src/views/chronology.js:60` impose `.event-list.atlas-chrono-events > li { display:flex }` ; la règle `.e055-era-head{display:block!important}` neutralise cette contrainte localement. `role="presentation"` empêche le faux item de liste de fausser le décompte des repères.
- **Effort** : M.
- **Vérification** : en filtrant sur un thème présent dans plusieurs ères, un en-tête par série ; nombre d'en-têtes égal à `data-e055-groups` ; aucun `id` dupliqué.

## E055-08 — Hiérarchie de titres discontinue entre liste et fiche

- **Problème / preuve** : le document enchaîne `<h1>` (`:227`), `<h2>` du repère dans la fiche (`:423`) et `<h3>` des points (`:462`), mais les titres de la liste sont des `<strong>` non titres (`:393`). La hiérarchie saute donc du `<h1>` au `<h2>` de la fiche sans titres de repère intermédiaires dans le `<main>`.
- **Solution** : retenir le plan h1 (vue) → h2 (ère, E055-03/07) → h3 (repère, E055-02 + `aria-level="3"` sur `#atlas-chrono-event-title`) → h4 (points, `aria-level="4"` sur `#atlas-chrono-points-title`). Les `aria-level` ne sont posés que si absents, sur les balises natives d'origine.
- **Impact** : plan de document continu et prévisible, quel que soit le nombre d'ères ou de repères.
- **Risque** : `aria-level` sur une balise `<h2>`/`<h3>` native est autorisé et écrase le niveau implicite ; la garde évite de contrarier une autre lentille qui aurait déjà normalisé ces titres.
- **Effort** : S.
- **Vérification** : parcours des titres : un seul niveau 1, puis des niveaux 2/3/4 ; `#atlas-chrono-event-title` à 3 et `#atlas-chrono-points-title` à 4.

## E055-09 — Landmark principal non décrit par la bande de statut

- **Problème / preuve** : `#atlas-chrono-main` porte seulement `aria-labelledby="atlas-chrono-title"` (`src/views/chronology.js:220`) ; la bande de statut visible `#atlas-chrono-status` (`:247-256`), qui donne ère courante et nombre de repères, n'y est pas rattachée. Un lecteur d'écran entrant dans le landmark n'entend que le titre, pas le contexte de Navigation.
- **Solution** : ajouter `atlas-chrono-status` aux jetons de `aria-describedby` du `<main>`, en préservant tout jeton existant (découpage par espaces, garde `includes`).
- **Impact** : le contexte de situation est annoncé à l'entrée du landmark, sans nouvelle région live et sans doubler `#nav-c2a-live` (`:121-138`).
- **Risque** : écraser un `aria-describedby` posé par une autre lentille ; le découpage en jetons et l'ajout incrémental écartent ce risque. Le texte de statut reste un `<p>` sans `role="status"` (`:244-246`), donc aucune annonce parasite.
- **Effort** : S.
- **Vérification** : `aria-describedby` du landmark contient `atlas-chrono-status` une seule fois, avec tout autre identifiant préexistant conservé.

## E055-10 — Re-render : doublons d'identifiants et état non auditable

- **Problème / preuve** : `runEnhancements` est rejoué à chaque rendu (`src/views/chronology.js:539`) et `cssOnce` ne protège que le `<style>` (`src/views/chronology/registry.js:13-19`) : ni les nœuds ni leurs identifiants ne sont garantis uniques. La coque reconstruisant le `stage` (`:30-31`), une lentille qui réinsère ses nœuds sans garde produirait des doublons.
- **Solution** : helper `ensureNode` qui réutilise le nœud existant, le déplace dans le bon parent et ne recrée que si la balise diffère ; tous les identifiants créés sont préfixés `e055-` et une passe finale `document.querySelectorAll('[id^="e055-"]')` supprime les doublons. Miroir d'audit : `data-e055-main`, `data-e055-outline`, `data-e055-cards`, `data-e055-groups`, `data-e055-reduced` (lu via `ctx.reducedMotion()`), et CSS unique `#chronology-e055`.
- **Impact** : aucune erreur de doublon d'ID sur une longue session, état de la lentille lisible par un test E2E, mouvement réduit exposé dans le DOM.
- **Risque** : la passe de déduplication pourrait retirer un nœud frais si un ancien node persistait plus haut dans l'ordre du document ; la coque remplaçant le `stage`, aucun ancien nœud ne subsiste, et `ensureNode` garantit l'unicité avant cette passe.
- **Effort** : M.
- **Vérification** : 20 cycles de changement de pays/ère → un seul `#e055-era-outline`, un seul `<style id="chronology-e055">`, aucun `id` `e055-` dupliqué ; `node --check src/views/chronology/E055.js` passe.

## Statut d'implémentation

Les 10 chantiers sont implémentés dans `src/views/chronology/E055.js`. Aucun fichier interdit modifié. Un seul `register('E055', ctx => {…})`, un seul `ctx.css('chronology-e055', …)`, tous les identifiants créés préfixés `e055-` avec gardes d'existence (`ensureNode`, passe de déduplication finale). Zéro `console.*`, zéro `fetch`/réseau, zéro `Math.random`, zéro boucle `requestAnimationFrame`. Toutes les valeurs affichées (noms, plages, comptes, ère courante) sont dérivées du DOM produit par `chronology.js` : aucune donnée inventée. `node --check src/views/chronology/E055.js` exécuté avec succès.

## Blocages

- Aucun bloquant fonctionnel.
- E055-02 et E055-08 restent des normalisations ARIA : le plan idéal utiliserait des balises `<h2>`/`<h3>` natives dans `src/views/chronology.js` (`:393`, `:423`, `:462`), fichier non possédé. La lentille ne modifie pas ces balises, elle pose uniquement `role`/`aria-level` de façon idempotente.
- E055-07 n'altère pas l'ordre des repères ni `state.eventIndex` : le regroupement est obtenu par insertion d'en-têtes `role="presentation"`, pas par réordonnancement du `<ol>` (`:348-414`).
- La coque reconstruisant le `stage` à chaque rendu (`:30-31`), l'état des bascules propres à E055 n'est pas persisté au-delà du rendu : les drapeaux `data-e055-*` sont recalculés à chaque application, ce qui est le comportement voulu.
