# E070 — État vide : quand la carte n’a aucun lieu à montrer (vue GEOGRAPHIE)

Lentille **E070** de la vue **Géographie** : `src/views/geography/E070.js`, greffon enregistré par `register('E070', ctx => {…})`. Dix chantiers **E070-01 à E070-10**, tous réellement implémentés — aucun stub. Le thème est l’**état vide** : la situation où une recherche, un filtre ou l’absence de données ne laisse aucun lieu à afficher. La coque produit déjà deux états vides (`ATLAS-GEO-01` et `C3-07` dans `geography.js`) ; cette lentille n’y substitue rien, elle ajoute un **laboratoire pédagogique** qui rend le phénomène mesurable et discutable sur un jeu témoin déterministe de huit lieux.

Pièces lues : `src/views/geography/E070.js` (stub initial), `src/views/geography/registry.js` (contrat `register`/`cssOnce`/`el`, `ctx` enrichi de `css`, `el`, `reducedMotion()`), `src/views/geography/index.js`, `src/views/geography.js` (coque : `.geo-map`, `.geo-panel`, `runEnhancements`, états vides existants), `src/views/geography/E011.js` (lentille de référence pour la structure et la boucle rAF), `UNIFIED_AUDIT/GEOGRAPHIE/views/E011.md` et `E057.md` (formats de rapport).

**Thèse.** Un état vide n’est pas une absence d’interface : c’est un message à concevoir. Il doit dire **pourquoi** il est vide (données absentes ou filtres trop stricts), donner le **dénominateur**, proposer une **sortie**, et rester **annonçable** aux technologies d’assistance. Le laboratoire rend ces quatre exigences observables sans jamais prétendre représenter les données réelles de l’atlas.

## Fiche de vérité (trois faits sourcés)

1. On distingue un **vide structurel** (le jeu ne contient aucun lieu) d’un **vide accidentel** (des lieux existent mais aucun ne passe le filtre) : la cause n’est pas la même, donc la réponse ne l’est pas non plus.
2. Un état vide utile affiche un **dénominateur** — « 0 lieu affiché sur N » — et une **couverture** en pourcentage, avec une référence explicite (le jeu complet, soit 100 %).
3. La **distance de relaxation** est le plus petit nombre de critères à assouplir pour retrouver au moins un résultat ; elle se calcule par balayage exhaustif des sous-ensembles de critères, sans heuristique aléatoire.

## E070-01 — Vide structurel contre vide accidentel

- **Preuve** : `E070.js:44-55` (jeu témoin), `E070.js:98-109` (`listeActive`, `classerVide`).
- **Solution** : une case à cocher « Simuler un jeu sans aucun lieu » force un jeu vide ; sinon le jeu de huit lieux est filtré. `classerVide()` renvoie `structurel`, `accidentel` ou `non-vide` selon l’origine réelle du vide.
- **Impact** : deux situations qui se ressemblent à l’écran produisent désormais deux diagnostics distincts et deux messages distincts.
- **Effort** : S.
- **Vérification** : cocher la simulation affiche « vide structurel » et désactive les pistes ; la décocher restaure le jeu témoin.

## E070-02 — Dénominateur zéro et couverture chiffrée

- **Preuve** : `E070.js:536-558` (`updateReadout`).
- **Solution** : le `.readout` annonce « N lieu(x) affiché(s) sur total », le pourcentage de couverture calculé depuis le jeu témoin, et la référence « 8 lieux, 100 % ». Les grandeurs sont mises en évidence par des `<strong>`.
- **Impact** : un zéro isolé devient une mesure : l’utilisateur voit ce qu’il perd et par rapport à quoi.
- **Effort** : S.
- **Vérification** : avec un filtre qui ne laisse rien passer, le message affiche « 0 lieu(x) affiché(s) sur 8 · couverture 0 % », puis la référence 100 %.

## E070-03 — Message de cause adjoint à l’état vide

- **Preuve** : `E070.js:536-558` (`updateReadout`, énumération des critères actifs), `E070.js:231-245` (`faitsStatiques`).
- **Solution** : le message reprend les critères réellement actifs (recherche, région, époque) au lieu d’un texte générique ; les paragraphes statiques expliquent pourquoi un vide peut être structurel ou accidentel.
- **Impact** : l’utilisateur comprend la cause avant de chercher une solution ; le texte reste lisible sans animation.
- **Effort** : S.
- **Vérification** : changer la recherche met à jour la chaîne « Critères : recherche « … », région …, époque … » dans le statut.

## E070-04 — Sortie de l’impasse : réinitialisation en un geste

- **Preuve** : `E070.js:683-740` (bouton `#geography-e070-reset`, touche `Home` du canvas).
- **Solution** : un bouton « Réinitialiser tous les filtres » remet recherche, région, époque et simulation au neutre ; l’équivalent clavier `Home` fait la même chose depuis le canvas.
- **Impact** : aucun état sans issue ; la récupération est disponible à la souris comme au clavier.
- **Effort** : S.
- **Vérification** : après une recherche infructueuse, un clic sur le bouton ou `Home` ramène les 8 lieux et la mention « résultats affichés ».

## E070-05 — Pistes de rattrapage dérivées du jeu

- **Preuve** : `E070.js:129-148` (`pistes`), `E070.js:559-594` (`renderSuggestions`), `E070.js:718-727` (application d’une piste).
- **Solution** : chaque assouplissement possible (effacer la recherche, toutes les régions, une autre région, toutes les époques, une autre époque) est évalué sur le jeu ; seules les pistes donnant au moins un résultat sont gardées, triées par nombre de résultats décroissant, puis limitées à trois.
- **Impact** : la suggestion n’est pas décorative : son libellé annonce le nombre de lieux qu’elle rendrait visibles.
- **Effort** : M.
- **Vérification** : avec la recherche « zzz », les pistes proposent « Effacer la recherche … → 8 lieu(s) » ; cliquer applique réellement le filtre et recalcule l’affichage.

## E070-06 — Distance de relaxation calculée

- **Preuve** : `E070.js:111-127` (`relaxationMin`), `E070.js:536-558` (annonce dans le `.readout`).
- **Solution** : les trois critères sont neutralisés un à un puis par paires (masques de 0 à 7) ; le premier sous-ensemble qui redonne au moins un lieu fixe le nombre minimal de critères à assouplir.
- **Impact** : une grandeur chiffrée supplémentaire, distincte du dénominateur, qui mesure la « proximité » d’un résultat.
- **Effort** : M.
- **Vérification** : une recherche impossible combinée à une région et une époque incompatibles affiche une distance de 2 ou 3 critères ; le valeur est stable d’un rendu à l’autre.

## E070-07 — Illustration schématique déterministe et animation unique

- **Preuve** : `E070.js:446-533` (`drawLab`), `E070.js:615-643` (`stopLoop`, `startLoop`, `tick`).
- **Solution** : un seul canvas dessine un cadre en tirets, un squelette de lignes de résultats absents, une loupe ou des pastilles selon l’état ; le halo de la loupe dépend de `S.phase`, fonction déterministe du temps écoulé. Le DPR est borné à 2 et un seul canvas est dessiné par frame.
- **Impact** : l’illustration n’est jamais une image distant ni une donnée inventée ; elle reste reproductible.
- **Effort** : M.
- **Vérification** : un second appel du greffon ne crée pas de seconde boucle (`S.rafId` garde une seule boucle active) ; le bouton « Animer la loupe » la démarre et l’arrête.

## E070-08 — Annonce accessible, focus et équivalent clavier

- **Preuve** : `E070.js:302-443` (`ensurePanel`), `E070.js:613-667` (pause, `matchMedia`), `E070.js:727-737` (clavier canvas).
- **Solution** : `.readout` porte `role=status` et `aria-live=polite` ; le canvas a `tabindex=0`, `role=img`, un `aria-label` unique et un `aria-describedby` ; les flèches changent région et époque, `Home` réinitialise, tous les boutons mesurent au moins 36 à 44 px et disposent d’un `:focus-visible`.
- **Impact** : le message d’état vide est perçu sans voir le canvas, et toutes les actions sont réalisables au clavier.
- **Effort** : M.
- **Vérification** : la navigation au clavier depuis le canvas modifie réellement les filtres ; `visibilitychange` arrête la boucle et `prefers-reduced-motion` fige le mouvement.

## E070-09 — Repère non coloré

- **Preuve** : `E070.js:152-229` (CSS : cadre en tirets, `:focus-visible`), `E070.js:446-533` (loupe, pastilles cerclées), `E070.js:400-402` (légende).
- **Solution** : le vide est signalé par un cadre en tirets, une icône de loupe et un message écrit ; les résultats sont des points pleins cerclés. La légende explicite dit que le message écrit reste la source du sens.
- **Impact** : aucune information essentielle ne repose sur la seule couleur ; le contraste et la forme suffisent.
- **Effort** : S.
- **Vérification** : en niveaux de gris, le cadre en tirets et la loupe restent identifiables ; la légende est présente dans le DOM, pas seulement dans le canvas.

## E070-10 — Texte indexable, tableau comparatif et badge d’honnêteté

- **Preuve** : `E070.js:231-299` (`faitsStatiques`, `tableauStatique`, `lexiqueStatique`), `E070.js:671-680` (`addMapBadge`).
- **Solution** : trois faits en `<p>`, un `<table>` avec `<caption>` et portées `scope` (situation, cause, rattrapage), une liste de définitions pour le vocabulaire, et un badge posé sur `.geo-map` précisant que le laboratoire repose sur un jeu témoin de huit lieux sans lien avec les filtres réels de l’atlas.
- **Impact** : le contenu pédagogique est lisible et indexable sans animation ; la vue de base n’est ni masquée ni remplacée ; l’utilisateur n’est pas induit en erreur sur l’origine des lieux.
- **Effort** : M.
- **Vérification** : le panneau est inséré en tête de `.geo-panel` avec un `aria-labelledby` valide ; aucun identifiant ne commence hors préfixe `geography-e070-` ; le badge est idempotent (un seul `#geography-e070-badge`).
