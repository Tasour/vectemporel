# E010 — Données, traçabilité et provenance

> Lentille **E010**, vague « RÉCIT ». **Statut : 10/10 chantiers implémentés** (E010-01 à E010-10), tous dans le seul fichier possédé `src/views/recit/E010.js`. Lectures seules : `src/views/recit/registry.js`, `src/views/recit/index.js`, `src/views/recit.js`, `src/data/dataset.js`, `src/views/_diagnostics.js`. Un seul `register('E010', …)`, une seule feuille de style `recit-e010`, ids DOM préfixés `e010-`, zéro console/réseau/aléa, aucun fichier partagé modifié.

Contexte de données vérifié sur `src/data/dataset.js` : **901 points** dans les événements, **314 avec au moins une référence**, **587 sans source** ; types `récit` 587, `figure` 171, `lieu` 108, `audit` 35 ; certitudes `vérifié` 866, `certain` 21, `probable` 4, `disputed` 10. Ces chiffres ne sont pas codés en dur dans la lentille : ils sont recalculés une seule fois au chargement du module dans `STATS` (`E010.js:19-57`) par parcours déterministe de `DATASET.countries[].events[].points[]`, avec un objet de repli vide si la forme du jeu change. Aucun appel réseau, aucune valeur aléatoire.

## E010-01

**Chantier — Fiche de provenance du point courant.**

- **Problème** : la vue Récit disperse les signaux de provenance du point affiché entre le kicker `.view-kicker` (`recit.js:277`), la pastille `.recit-conf` (`:288`), l'item `.recit-thread-item.is-current` (`:372-384`) et le bloc `.recit-trace` / `.recit-sources` (`:406-413`). Aucun emplacement ne les rassemble : le lecteur doit reconstituer lui-même l'identité du point.
- **Solution** : `E010.js:194-214` crée `<section id="e010-fiche" class="recit-e010-fiche">` (avec `aria-labelledby="e010-fiche-title"`) contenant un `<dl class="recit-e010-dl">` de quatre paires `<dt>/<dd>` : **Rang** (texte du kicker), **Type** (`dataset.kind` de l'item courant), **Certitude** (texte de la pastille + son `title`, c'est-à-dire la glose d'audit), **Références** (texte du `<summary>` de traçabilité, ou « Aucun identifiant attaché »). La fiche est insérée juste après le bloc de traçabilité via `apres(ancre, …)` ; `replaceChildren()` la rend idempotente.
- **Impact** : provenance du point lisible d'un seul coup d'œil, sous forme de liste de définitions sémantique et annonçable, sans déplacer ni réécrire le contenu d'origine.
- **Risque** : si un signal manque (aucun item courant, aucune pastille), la fiche affiche « Non déterminé » plutôt que de lever une erreur ; le champ n'est jamais laissé vide. Le `title` de la pastille est une information d'audit réelle, pas une invention.
- **Vérification** : une seule `.recit-e010-fiche` dans le DOM, avec quatre `<dt>` ; son texte contient le même rang que le kicker et le même type que l'item courant ; aucun appel réseau.

## E010-02

**Chantier — Signal textuel explicite de présence ou d'absence de source.**

- **Problème** : le point sans source n'est signalé que par le paragraphe gris `.recit-sources` (`recit.js:412`) ; l'absence de référence n'est pas nommée comme un état de donnée, et le point avec source n'a aucun marqueur positif symétrique. Sur 901 points, 587 sont concernés par l'omission.
- **Solution** : `E010.js:216-231` ajoute, selon le cas, `<p id="e010-absence" class="recit-e010-absence">∅ Provenance non renseignée : l’absence de référence est un état de la donnée, pas une erreur de rendu.</p>` après `.recit-sources`, ou `<p id="e010-presence" class="recit-e010-presence">✓ Provenance renseignée…</p>` après `.recit-trace`. Les symboles `∅` et `✓` sont doublés par un texte explicite : aucune information n'est portée par la seule couleur.
- **Impact** : l'omission devient une donnée lisible et assumée ; le marqueur positif rend la présence de référence vérifiable au même endroit.
- **Risque** : les deux marqueurs sont mutuellement exclusifs (branchement sur la présence de `.recit-sources`) ; si le DOM change de forme, aucun marqueur n'est ajouté plutôt qu'un marqueur faux. Le paragraphe d'origine reste intact (ajout frère, non destructif).
- **Vérification** : sur un point sans source, un seul `#e010-absence` et aucun `#e010-presence` ; sur un point avec source, l'inverse ; le texte de `.recit-sources` est inchangé.

## E010-03

**Chantier — Identifiants de source en puces sémantiques.**

- **Problème** : `recit.js:409` affiche les identifiants dans un paragraphe unique (« Identifiants : SRC-001, SRC-015. … »). La liste est plate, non navigable, et les codes `SRC-…` ne sont pas individualisables pour un lecteur d'écran.
- **Solution** : `E010.js:233-251` lit le texte de `.recit-trace` et en extrait les codes par l'expression `/SRC[- ][0-9]+/gi`, les déduplique avec un `Set`, puis construit `<ul id="e010-source-list" class="recit-e010-sources" aria-label="Identifiants de source du point courant">` avec un `<li class="recit-e010-chip">` par identifiant. Le paragraphe d'origine n'est pas modifié ; la liste est ajoutée dans le `<details>` et reconstruite par `replaceChildren()`.
- **Impact** : chaque référence devient un élément de liste distinct, annoncé et comptable ; la traçabilité du point courant est scannable visuellement.
- **Risque** : aucun lien n'est créé (les ressources sont locales, `recit.js:409` le précise déjà) — les puces ne sont pas des liens trompeurs. Si aucun code n'est trouvé malgré un bloc de traçabilité, une puce « Référence locale » neutre est affichée ; la lentille n'invente jamais d'identifiant.
- **Vérification** : le nombre de `<li>` correspond au nombre de codes distincts présents dans le texte du `<details>` ; chaque `<li>` commence par `SRC-` ; aucun `href` n'est introduit.

## E010-04

**Chantier — Tableau de bord des données du jeu complet.**

- **Problème** : la vue ne donne aucune échelle chiffrée : le « 1 point à la fois » masque le fait que le jeu contient 901 points et que 587 d'entre eux n'ont pas de référence. Le visiteur ne peut pas situer le point courant dans un ensemble.
- **Solution** : `E010.js:253-272` crée `<section id="e010-dashboard" class="recit-e010-panel">` avec un tableau `<table class="recit-e010-table">` muni d'un `<caption>`, d'en-têtes `scope="col"` et de lignes `scope="row"` : Points du jeu (901), Avec référence (314), Sans référence (587), Couverture (`pourcentage(314, 901)` = 35 %). Toutes les valeurs proviennent de `STATS` ; `pourcentage()` (`E010.js:66`) utilise `Math.round`, jamais d'aléa.
- **Impact** : le rapport entre données documentées et données non documentées devient explicite et mesurable, avec un pourcentage calculé depuis sa formule.
- **Risque** : le pourcentage est arrondi à l'unité et signalé par le signe `%` ; aucune information n'est portée par la couleur. Si le jeu de données évolue, les chiffres suivent automatiquement au prochain chargement — aucune valeur figée dans le document.
- **Vérification** : la somme « avec » + « sans » vaut « total » ; le pourcentage calculé vaut `round(314/901×100)` = 35 ; le tableau possède bien un `<caption>` et des `th[scope]`.

## E010-05

**Chantier — Répartition par type de point et par degré de certitude.**

- **Problème** : les légendes de `recit.js:442-447` décrivent les quatre types et les quatre degrés de certitude, mais n'en donnent jamais la distribution. Le poids réel de chaque catégorie (par exemple 866 points `vérifié` contre 10 `disputed`) reste invisible.
- **Solution** : `E010.js:274-300` ajoute `<section id="e010-distribution" class="recit-e010-panel">` avec deux groupes de listes `<ul class="recit-e010-dist">` : « Types de points » (`récit`, `figure`, `lieu`, `audit`) et « Degrés de certitude » (`vérifié`, `certain`, `probable`, `disputed`), chacun avec son compte issu de `STATS.byKind` / `STATS.byConfidence`. L'ordre est stabilisé par `ordered(map, ordre)` (`E010.js:60-64`) ; toute catégorie inattendue est ajoutée en fin dans l'ordre alphabétique. Chaque `<li>` porte un libellé texte et une valeur chiffrée en `tabular-nums`.
- **Impact** : la composition du jeu devient lisible, y compris la rareté des mentions `disputed` ou `probable` : un lecteur peut juger de la fiabilité globale sans ouvrir chaque point.
- **Risque** : les libellés sont ceux du jeu (`disputed` conservé tel quel, traduit « contesté » uniquement dans la légende existante) — la lentille ne réécrit aucune mention d'audit. Aucun seuil, aucune couleur, aucun graphique dépendant d'une bibliothèque.
- **Vérification** : huit `<li>` au total (4 types + 4 certitudes) avec les comptes 587/171/108/35 et 866/21/4/10 ; la somme de chaque groupe vaut 901 ; les valeurs sont en chiffres à largeur fixe.

## E010-06

**Chantier — Signature de traçabilité du fil du repère.**

- **Problème** : le fil `.recit-thread` (`recit.js:363-403`) porte sur chaque bouton les attributs `data-kind` et `data-confidence` (`:378-379`), mais aucun récapitulatif local : impossible de voir, pour le repère affiché, combien de points relèvent de chaque type ou de chaque certitude après filtrage.
- **Solution** : `E010.js:302-318` parcourt `.recit-thread-item`, agrège `dataset.kind` et `dataset.confidence` dans deux objets, puis ajoute `<p id="e010-thread-stats" class="recit-e010-thread-stats">` en fin de `.recit-thread` avec une phrase du type « Fil du repère · N point(s) affiché(s) · types : … · certitudes : … ». Le tri réutilise `ordered()` ; l'insertion se fait dans le `<nav>` du fil, jamais dans la liste des points.
- **Impact** : la signature du repère courant est dérivée du DOM réellement affiché : elle suit les filtres C3 sans recalcul externe et sans duplication des données.
- **Risque** : si le fil est vide, la phrase affiche « aucun / aucune » plutôt qu'une division par zéro ; la ligne est séparée par un filet et reste du texte intégralement lisible. Aucun `aria-pressed` n'est détourné : la ligne est informative, pas une commande.
- **Vérification** : la somme des comptes de la signature vaut le nombre de `.recit-thread-item` ; après un filtre, la signature se met à jour au rendu suivant ; aucun identifiant de point n'est ajouté.

## E010-07

**Chantier — Glossaire des données et de la traçabilité.**

- **Problème** : les termes « source », « identifiant SRC », « omission de source » ou « couverture » sont employés par la vue et par la lentille sans définition locale ; le lecteur doit quitter la vue pour les comprendre.
- **Solution** : `E010.js:320-338` crée `<details id="e010-glossary" class="recit-e010-glossary">` replié par défaut, avec un `<summary>` (« Glossaire des données et de la traçabilité ») et un `<dl class="recit-e010-dl">` de sept définitions : Point, Type, Certitude, Source, Identifiant SRC, Omission de source, Couverture. Le `<details>` est nativement accessible et clavier ; `replaceChildren()` garantit l'idempotence.
- **Impact** : le vocabulaire de la donnée est défini au premier usage dans la vue, sans modifier la légende existante de `recit.js` et sans texte caché aux lecteurs d'écran (le contenu d'un `<details>` fermé reste dans le DOM).
- **Risque** : le glossaire est replié pour ne pas allonger la vue ; son contenu reste néanmoins indexable et révélable au clavier. Aucune définition n'ajoute de fait historique : elles décrivent toutes le modèle de données local.
- **Vérification** : un seul `#e010-glossary`, sept paires `<dt>/<dd>`, `open` absent au rendu initial ; l'ouverture au clavier révèle les définitions sans appel réseau.

## E010-08

**Chantier — Méta-provenance : identité et origine du jeu de données.**

- **Problème** : la vue affiche l'image d'un repère et ses crédits (`recit.js:263-264`), mais jamais l'origine du jeu de données lui-même (version, date de génération, mode de constitution, présence ou non de liens externes). La provenance de la donnée est pourtant la première question d'un audit.
- **Solution** : `E010.js:340-351` lit `DATASET.meta` via `STATS.meta` et remplit `<p id="e010-dataset-meta" class="recit-e010-dataset">` avec une phrase calculée : nom, version, date de génération, origine (« audits locaux + data.js curaté ») et mention « aucun lien externe » lorsque `externalLinks === false`. Les champs absents sont simplement omis (`filter(Boolean)`).
- **Impact** : chaque point du récit est désormais rattaché à une source de données datée et identifiée, traçable jusqu'à son mode de fabrication — sans changer une seule donnée historique.
- **Risque** : l'absence d'un champ `meta` donne une phrase réduite mais jamais une valeur inventée ; la mention « aucun lien externe » est conditionnée au champ réel du jeu, pas supposée. Aucun `href`, aucun `src` distant.
- **Vérification** : la phrase contient la version `0.1.0`, la date `2026-11-18` et l'origine du `meta` actuel ; si `externalLinks` passe à `true`, la mention disparaît au rendu suivant.

## E010-09

**Chantier — Vérificateur de chaîne de traçabilité (contrôle rejouable).**

- **Problème** : la traçabilité est affichée mais jamais vérifiée : rien ne dit si le point courant porte effectivement les quatre maillons attendus (rang, type, certitude, référence), ni comment les contrôler soi-même.
- **Solution** : `E010.js:353-393` ajoute `<section id="e010-verif" class="recit-e010-verif">` avec un titre, une consigne, un bouton `type="button"` `#e010-verif-button` (« Vérifier la chaîne », 36 px, focus visible) et un `<p id="e010-verif-readout" class="recit-e010-readout" role="status" aria-live="polite">`. Au clic, le contrôle relit le **DOM affiché** (`.view-kicker`, `.recit-conf`, `.recit-thread-item.is-current`, `.recit-trace`), construit la liste « rang/type/certitude/référence : présent ou absent », déduit « chaîne complète/incomplète » et l'écrit dans le readout. L'écouteur est installé une seule fois (`dataset.e010Bound`) ; le résultat est aussi porté par `data-e010-chain` pour le style, jamais par la couleur seule.
- **Impact** : l'utilisateur dispose d'un contrôle falsifiable et sans réseau : il peut constater qu'un point sans source donne « chaîne incomplète — référence : absent », puis naviguer vers un point sourcé pour obtenir « complète ».
- **Risque** : le readout n'est mis à jour que sur action explicite (aucun bavardage au rendu) et remis à l'état neutre à chaque rendu (`E010.js:404-407`), donc aucun résultat périmé n'est affiché après un changement de point. Aucun `aria-pressed` : c'est une commande ponctuelle, pas une bascule.
- **Vérification** : un clic sur un point sans source affiche « chaîne incomplète » et `data-e010-chain="incomplet"` ; sur un point avec source, « chaîne complète » ; le texte du readout mentionne les quatre maillons ; aucun appel réseau.

## E010-10

**Chantier — Robustesse, mouvement réduit et accessibilité des panneaux ajoutés.**

- **Problème** : dix panneaux injectés dans une vue reconstruite à chaque changement d'état (`recit.js:451` appelle `runEnhancements` après chaque rendu) doivent rester idempotents, accessibles, et ne pas introduire de mouvement ni de nœuds masqués par le tiroir de diagnostics (`_diagnostics.js:72` repère les identifiants correspondant au motif `e…`/`-e…`).
- **Solution** : `E010.js:135-150` centralise `getOrCreate()` (ids uniques, garde anti-doublon, `appendChild` dans un `try` sans `throw`) ; tous les nœuds porteurs d'un id sont déposés dans `.recit-body` ou ses enfants, jamais directement dans `stage`/`layout`, donc `_diagnostics.js:74` ne les marque pas `data-recit-diagnostic` et ils restent visibles. `E010.js:395-403` interroge `ctx.reducedMotion()` et pose/retire `data-e010-reduced="1"` sur le conteneur, en complément de la media query CSS (`E010.js:119-120`). Le CSS donne des cibles tactiles ≥ 36 px, un `:focus-visible` sur le bouton et le `<summary>`, et annule toute transition sous mouvement réduit. Les gardes d'existence (`if (!stage || !layout …) return`, `if (!corps) return`) garantissent qu'aucun rendu n'est cassé.
- **Impact** : la lentille survit aux re-renders, respecte `prefers-reduced-motion`, reste lisible sans CSS et ne perturbe ni le routeur clavier ni le tiroir de diagnostics.
- **Risque** : le repli sur `document` supposerait un environnement DOM ; le registre n'appelant la lentille que dans le navigateur, c'est sans conséquence. L'état du vérificateur est réinitialisé à chaque rendu : c'est voulu pour éviter un résultat faux après navigation. Aucun fichier partagé n'est modifié.
- **Vérification** : après trois changements de point, un seul exemplaire de chaque id dans le DOM ; avec `prefers-reduced-motion: reduce`, aucun `transitionDuration` sur `.recit-e010-btn` et `data-e010-reduced="1"` présent ; sans la préférence, l'attribut absent ; les nœuds ne portent pas `data-recit-diagnostic`.
