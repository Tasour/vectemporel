# E057 — Contraste et perception

Statut : **10/10 chantiers implémentés** (E057-01 … E057-10). Module :
`src/views/recit/E057.js`. Contrat `register('E057', ctx => { … })` avec
`ctx = { stage, layout, css, el, reducedMotion }`, un seul appel
`css('recit-e057', …)` regroupant toutes les règles, ids DOM préfixés `e057-`,
classes créées préfixées `recit-e057-`, attributs réservés `data-e057-*`.

Pièces lues pour le diagnostic : `src/views/recit.js` (structure
`.recit-layout/.recit-media/.recit-body/.recit-progress/.recit-timing/.recit-conf/.recit-actions`,
`#recit-point-title`, `#atlas-recit-live`, variables de thème `--gold`,
`--muted`, `--line`, `--ink`), `src/views/recit/registry.js` (`register`,
`cssOnce`, `el`, `runEnhancements`), `src/views/recit/index.js` (import de
`E057.js`), `src/views/_diagnostics.js` (marquage `e\d\d`), `UNIFIED_AUDIT/RECIT/README.md`.
Jeu de données : 901 points, `kind ∈ {récit, figure, lieu, audit}`,
`confidence ∈ {vérifié, certain, probable, disputed}`, 587 points sans source.

Aucune donnée historique n'est ajoutée. Les deux seules valeurs chiffrées
affichées sont **recalculées** : le ratio WCAG est calculé en JavaScript depuis
les couleurs de référence du thème lues dans la CSS existante (or `#e6b96f` =
`rgba(230,185,111)`, fond `#080b12` = `rgba(8,11,18)`, secondaire `#9aa6b8`) ;
le pourcentage de progression est dérivé de « Étape X / Y » déjà rendu par la
vue. Enrichissement strictement additif : aucun texte n'est remplacé ni
supprimé, aucun gestionnaire existant n'est ré-attribué, aucun attribut
préexistant n'est écrasé. Sans JavaScript, la vue Récit reste intégralement
lisible et utilisable.

## E057-01

- **Problème.** Les textes tertiaires et les bordures de la vue reposent sur
  des couleurs atténuées et des opacités faibles (`--muted-2`, `opacity:.35` à
  `.78`) : le contraste est insuffisant pour les lecteurs en environnement
  lumineux ou à basse vision, et il n'existe aucun réglage local pour le
  renforcer.
- **Solution.** Une bascule `#e057-contraste` (« Contraste : standard /
  renforcé », `aria-pressed`, `data-fk`) est insérée en tête de `.recit-actions`
  via `ajouterBouton`. Elle ajoute/retire `recit-e057-contraste` sur la racine
  `recit-e057-root`. La règle CSS associée porte le titre, le chapeau et la
  légende à `#f4f1ea`, les métadonnées à `#e8e3d6`, remonte les items du fil à
  `opacity:1`, renforce les bordures (or clair `#ffe6b0`) et le fond de la
  barre de progression. L'état est mémorisé dans `prefs.contraste` et
  réappliqué à chaque rendu. Si `prefers-contrast: more` est détecté au premier
  rendu, le mode est activé d'office (voir E057-10).
- **Impact.** Un réglage global, réversible et persistant qui augmente
  sensiblement le contraste perçu de toute la vue sans modifier une seule
  donnée ni un seul libellé d'origine.
- **Risque.** Un contraste maximal peut éblouir en environnement sombre : la
  bascule est désactivable d'un clic et l'état par défaut reste le thème
  d'origine. Le bouton est inséré dans `.recit-actions` (parent imbriqué), donc
  jamais marqué ni masqué par le mode diagnostics.
- **Vérification.** Au clic, `aria-pressed` suit `prefs.contraste`, la classe
  `recit-e057-contraste` apparaît sur `.recit-e057-root`, et un changement de
  point conserve le réglage. Un seul `#e057-contraste` par rendu (garde
  `document.getElementById`).

## E057-02

- **Problème.** Aucune mesure de lisibilité n'était exposée : le lecteur ne
  pouvait pas savoir si le contraste du texte atteignait le seuil d'accessibilité
  WCAG AA (4,5:1).
- **Solution.** Une fonction WCAG pure calcule la luminance relative
  (`0,2126 R + 0,7152 V + 0,0722 B` après linéarisation sRGB) puis le ratio
  `(L_clair + 0,05) / (L_sombre + 0,05)`. Le résultat, arrondi à une décimale
  avec virgule française, est affiché dans un paragraphe `#e057-ratio`
  (« Contraste estimé (thème) : texte principal 10,8:1, texte secondaire
  8,0:1 · seuil AA 4,5:1 respecté. ») inséré après `.recit-meta`, avec repli sur
  `.recit-progress` puis sur `.recit-body`.
- **Impact.** Deux grandeurs chiffrées et vérifiables, calculées depuis les
  couleurs réelles du thème, donnent un repère perceptif explicite ; les deux
  dépassent même le seuil AAA de 7:1.
- **Risque.** Les couleurs sont des références documentées du thème, pas une
  mesure du rendu effectif d'un pixel : le libellé dit explicitement
  « estimé (thème) ». Si le thème change, le calcul se recalcule automatiquement
  depuis les trois constantes. Aucune région live supplémentaire n'est créée
  (paragraphe ordinaire, pas `role=status`).
- **Vérification.** Le ratio « or/fond » vaut bien **10,8:1** et
  « secondaire/fond » **8,0:1** (recalculé en Node) ; `#e057-ratio` est unique
  et son texte est inchangé par les autres chantiers.

## E057-03

- **Problème.** Le degré de certitude était porté par un symbole et une
  couleur ; pour une personne daltonienne ou sur un écran mal calibré, les
  quatre niveaux (`vérifié`, `certain`, `probable`, `disputed`) restaient
  difficiles à distinguer rapidement.
- **Solution.** `chantier03` pose `recit-e057-conf` sur `.recit-conf` et calcule
  un rang (4 → 0) depuis le libellé réel. Il écrit `data-e057-rang` et
  `data-e057-niveau` (« confirmé », « établi », « moyen », « incertain », « — »).
  La CSS applique un **motif de bordure distinct** par rang (plein / plein /
  tireté / pointillé / double) et affiche le mot via `::after`
  (`content:' · ' attr(data-e057-niveau)`).
- **Impact.** Double encodage redondant — forme + texte — conforme au principe
  « jamais la seule couleur » : la certitude est perceptible même en niveaux
  de gris.
- **Risque.** Un libellé inconnu donne rang 0 et le mot « — » : aucune mention
  n'est inventée, le texte d'origine de la pastille reste intact. Le `title`
  existant n'est pas modifié.
- **Vérification.** Pour « vérifié » : `data-e057-rang="4"`,
  `data-e057-niveau="confirmé"`, bordure pleine. Pour « contesté » : rang `1`,
  « incertain », bordure pointillée.

## E057-04

- **Problème.** Le contour de focus existant (2 px,`var(--gold-bright)`) est
  fin et peut se confondre avec les accents dorés de l'interface, en
  particulier sur les items du fil et les filtres.
- **Solution.** Le bloc CSS unique surcharge `:focus-visible` de tous les
  contrôles interactifs de la vue (boutons d'action, bascules E057, recherche,
  filtres, réinitialisation, items du fil, résumé de traçabilité) avec
  `outline:3px solid #ffe6b0; outline-offset:2px` et un liseré noir
  `box-shadow:0 0 0 1px #080b12` qui sépare le contour du fond.
- **Impact.** Le focus clavier devient un signal perceptif fort et incurable
  par la couleur seule, y compris sur fond clair ou texturé.
- **Risque.** Le sélecteur est porté par `.recit-e057-root`, donc sans effet
  hors de la vue Récit ; la spécificité (3 classes) garantit la prévalence sur
  la règle 2 px d'origine. Aucun `tabindex` ni gestionnaire n'est touché.
- **Vérification.** Tab sur « Point suivant » : `getComputedStyle` renvoie un
  `outline-width` de 3 px et la couleur `#ffe6b0` ; le focus reste visible sur
  `.recit-thread-item` et `.recit-trace summary`.

## E057-05

- **Problème.** Le titre du point était un texte posé directement sur le fond :
  la séparation figure/fond était faible, surtout quand le titre est long et
  s'étale sur plusieurs lignes.
- **Solution.** Le `h1#recit-point-title` reçoit `recit-e057-titre` et le
  surtitre `.view-kicker` reçoit `recit-e057-kicker`. La CSS dessine un bandeau
  dégradé or translucide derrière le titre
  (`linear-gradient(90deg, rgba(230,185,111,.10), transparent 70%)`) et remonte
  le surtitre à `var(--e057-or)`. **Aucun padding ni bordure n'est modifié** :
  le bandeau est un simple fond en dégradé, sans conflit avec la pastille
  ordinale ou le filet qu'une autre lentille pourrait poser.
- **Impact.** Le point courant se détache nettement du reste du corps : la
  hiérarchie perceptive « ici » est renforcée avant toute lecture.
- **Risque.** Le dégradé est purement décoratif et translucide : il ne masque
  aucun texte et ne change pas le flux. En mode contraste renforcé, le bandeau
  est accentué (`.18`) sans devenir opaque.
- **Vérification.** `background-image` du `h1` contient le dégradé ; le texte
  du titre, son `tabindex="-1"` et son identifiant `recit-point-title` sont
  inchangés.

## E057-06

- **Problème.** Les commandes désactivées (début de séquence, fin de séquence,
  filtres sans résultat) étaient uniquement signalées par `opacity:.35` : une
  différence de luminance faible, difficile à percevoir et ambiguë avec un
  simple texte atténué.
- **Solution.** La CSS applique aux `button[disabled]` de `.recit-actions`,
  aux `.c3a-filter[disabled]` et aux `.recit-thread-item[disabled]` une
  opacité relevée à `.55`, une **bordure tiretée** et un hachage diagonal
  (`repeating-linear-gradient(135deg, rgba(255,255,255,.05) 0 4px, transparent 4px 8px)`).
  L'état est donc encodé par texture + forme + contraste.
- **Impact.** Un contrôle indisponible est reconnu immédiatement, sans essai,
  y compris en vision réduite ou en niveaux de gris.
- **Risque.** Le hachage reste très léger (5 % de blanc) et n'altère pas la
  lisibilité du libellé. Aucun attribut `disabled` ni `aria-disabled` n'est
  ajouté ou retiré : l'état fonctionnel d'origine est préservé.
- **Vérification.** Sur le premier point, « Point précédent » porte
  `disabled` et affiche une bordure tiretée + hachage ; cliquer ne déclenche
  aucune navigation supplémentaire.

## E057-07

- **Problème.** La barre `.recit-progress` encodait la progression par une
  seule largeur de remplissage : indice purement visuel, sans texture ni valeur
  chiffrée lisible à côté de la barre (3 px de haut).
- **Solution.** `chantier07` marque la barre `recit-e057-progress` (fond
  remonté à `rgba(255,255,255,.16)` + liseré, remplissage haché à 45°) et lit
  « Étape X / Y » via `lireEtape`. Il calcule `pct = round(X/Y*100)`, borné 0–100,
  l'écrit dans `data-e057-pct` sur la barre, et insère un paragraphe
  `#e057-pct` : « Progression du repère : 30 % (point 3 sur 10). » juste après
  la barre, avec repli sur `.recit-body`.
- **Impact.** La progression est doublement perceptible — texture sur la barre
  et pourcentage chiffré en texte — et le chiffre est recalculé depuis la vue,
  jamais mémorisé.
- **Risque.** Si le kicker change de format, `lireEtape` renvoie `null` et
  aucun paragraphe n'est créé (garde d'existence). La division est protégée
  contre `Y = 0` et les valeurs non finies. Le paragraphe est inséré dans
  `.recit-body`, jamais directement sous `layout`/`stage`/`body`.
- **Vérification.** Pour 3 points sur 10, `data-e057-pct="30"` et le texte de
  `#e057-pct` affiche « 30 % (point 3 sur 10) » ; un seul `#e057-pct` par rendu.

## E057-08

- **Problème.** La légende de l'image (`.media-caption`), son crédit
  (`.recit-media-credit`) et les identifiants de traçabilité
  (`.recit-trace`, `.recit-sources`) étaient en texte gris fin sur image ou sur
  fond sombre, donc peu contrastés ; les 587 points sans source étaient
  signalés par un texte encore plus ténu.
- **Solution.** `chantier08` marque `.media-caption` et `.recit-media-credit`
  `recit-e057-legende-image` (couleur `#f0e9da` + double ombre portée noire pour
  garantir le contraste sur cliché clair), marque `.recit-trace` et
  `.recit-sources` `recit-e057-trace`/`recit-e057-sources` (couleur `--muted`,
  `opacity:1`), et ajoute un chevron `▸` en `::before` du résumé. Si une image
  existe, `data-e057-image="presente"` est posé dessus ; le nombre de
  références est lu dans le résumé via regex et stocké dans
  `data-e057-nb-sources`.
- **Impact.** Crédit, licence, légende et traçabilité deviennent lisibles d'un
  coup d'œil, y compris sur une image claire, sans déplacer ni réécrire ces
  textes.
- **Risque.** L'image et son `alt` ne sont jamais modifiés (seul un attribut de
  données est ajouté). Le `<details>` reste replié et ses identifiants restent
  dans le DOM, exactement comme dans la vue d'origine.
- **Vérification.** Sur un point sourcé, `#e057-nb-sources` reflète le nombre
  du résumé ; sur un point sans source, le message d'origine reste visible avec
  `opacity:1` ; aucune image n'est supprimée.

## E057-09

- **Problème.** Le confort de lecture ne jouait que sur la taille de police :
  l'interlignage, l'espacement des lettres et des mots restaient denses, ce qui
  nuit à la perception du rythme de lecture et à la dyslexie.
- **Solution.** Une seconde bascule `#e057-espacement` (« Espacement : normal /
  large », `aria-pressed`, `data-fk`) ajoute/retire `recit-e057-espacement` sur
  `.recit-e057-corps` (le `.recit-body` marqué en tête de chantier). La règle
  porte `line-height:1.85`, `letter-spacing:.035em` et `word-spacing:.16em` sur
  le chapeau, le titre et les paragraphes de légende. L'état vit dans
  `prefs.espacement` et survit aux reconstructions du DOM.
- **Impact.** Le lecteur ajuste lui-même l'aération du texte, de façon
  indépendante de la taille de police (E006) et du contraste (E057-01).
- **Risque.** Un espacement large allonge le défilement ; il est réversible et
  ne s'applique qu'aux blocs de texte nommés, jamais aux boutons ni aux champs.
  Si `.recit-body` est absent, aucune bascule n'est créée.
- **Vérification.** Au clic, `aria-pressed` suit `prefs.espacement`, la classe
  apparaît sur `.recit-e057-corps`, et `getComputedStyle` du chapeau renvoie
  `line-height` ≈ 1,85 ; un changement de point conserve le réglage.

## E057-10

- **Problème.** Les utilisateurs ayant activé « contraste renforcé » au niveau
  du système d'exploitation n'étaient pas détectés, et les transitions de
  couleur du mode contraste pouvaient gêner ceux qui préfèrent un mouvement
  réduit.
- **Solution.** `detecterContrasteSysteme()` interroge
  `window.matchMedia('(prefers-contrast: more)')` dans un `try/catch` : au
  premier rendu, un résultat positif active le mode contraste et pose
  `data-e057-systeme="renforce"` sur la racine (sinon `"standard"`). Le bloc CSS
  unique contient en outre une règle native `@media (prefers-contrast: more)`
  qui applique le contraste accru **même sans JavaScript**. La chaîne de
  transition n'est ajoutée au CSS que si `reducedMotion()` est faux ; sinon une
  règle `@media (prefers-reduced-motion: reduce)` neutralise toute transition
  et animation de la racine.
- **Impact.** La préférence système est honorée automatiquement et la lentille
  reste accessible sans JS ; les transitions ne s'activent que pour les
  utilisateurs qui les acceptent.
- **Risque.** `matchMedia` est gardé contre son absence (anciens navigateurs,
  SSR) et retombe sur `false`. La préférence système ne verrouille pas la
  bascule : l'utilisateur peut toujours revenir au thème standard.
- **Vérification.** Avec `prefers-contrast: more`, la racine porte
  `data-e057-systeme="renforce"` et `#e057-contraste` est `aria-pressed=true` ;
  avec `prefers-reduced-motion: reduce`, aucune règle `transition` n'est
  injectée et `getComputedStyle(...).transitionDuration` vaut `0s`.

## Vérifications

- `node --check src/views/recit/E057.js` → **OK** (aucune sortie, code 0).
- Un seul `register('E057', …)` (`grep -c` → 1) et un seul appel
  `css(CSS_ID, …)` (`grep -c` → 1) regroupant toutes les règles sous l'identifiant
  de feuille `recit-e057`, garanti idempotent par `cssOnce`.
- **Zéro réseau** : aucun `fetch`, `XMLHttpRequest`, `src` distant, `@import`
  ni `url(http…)` ; **zéro `console.*`** ; **zéro `Math.random()`** ; aucun timer,
  aucune animation pilotée par JavaScript (recherche textuelle : aucune
  occurrence).
- **Identifiants uniques et préfixés** : `e057-contraste`, `e057-espacement`,
  `e057-ratio`, `e057-pct`, chacun protégé par `document.getElementById` avant
  création et inséré dans un parent imbriqué (`.recit-actions`, `.recit-body`)
  afin d'échapper au masquage des diagnostics. Toutes les classes créées sont
  préfixées `recit-e057-` ; les attributs `data-e057-*` sont réservés à la
  lentille.
- **Gardes d'existence** : chaque chantier est isolé par `securiser()`
  (try/catch), toute lecture DOM est nulle-tolérante, et l'absence d'un repère
  conduit à un simple « ne rien faire », jamais à une exception. Le rendu de
  la vue n'est jamais interrompu.
- **Enrichissement non destructif** : aucun texte existant n'est remplacé ni
  supprimé, aucun `disabled`/`aria-pressed`/gestionnaire d'origine n'est
  modifié ; sans JavaScript, la vue Récit demeure lisible et utilisable.
- **Aucun fichier partagé modifié** (`registry.js`, `index.js`, `recit.js`,
  `styles.css`, README, SYNTHESE) : seuls `src/views/recit/E057.js` et le
  présent rapport ont été écrits.
